## 摘要
在云托管向量数据库上执行近似最近邻搜索（ANNS）会引发一个关键隐私问题：查询向量通常编码了敏感的用户意图，却会暴露给服务器。隐私 ANNS（PANNS）允许客户端在不泄露查询的情况下检索最近邻。当前最先进的单服务器方案 Pacmann（ICLR'25）通过结合私有信息检索（PIR）的基于图的搜索实现高精度，但会带来巨大的通信开销，因为每次 PIR 查询仅能检索一个顶点。我们提出 Amora，一种通信高效的 PANNS 系统，它将 SimplePIR 应用于分区图索引，使一次 PIR 查询可摊销到多个顶点上。为了在有限通信预算下尽可能检索搜索所需的距离和邻居信息，Amora 采用双 PIR 拆分布局，使用两个维度保持平衡的异构 PIR 矩阵：VecPIR 一次性检索整个顶点分区的内积作为其距离，而 NbrPIR 以子组粒度检索图遍历所需的邻居列表。该布局将 PIR 查询的成本模型从按顶点转变为按分区，从而显著降低通信开销。为了通过减少 PIR 数据库中的扫描次数和查询轮数来进一步提升效率，Amora 引入批量 PIR 将多个查询打包为一次矩阵乘法、基于质心的剪枝以过滤无希望的分区，以及 TopCand 探索，用每个检索到的分区中最近的顶点为跳跃式图导航提供种子。我们在五个数据集上评估 Amora，这些数据集涵盖 96 到 1024 维、最多 1000 万个向量。与 Pacmann 相比，Amora 将在线通信降低 93%–99%，同时实现更高的搜索精度。

## Abstract
Approximate nearest neighbors search (ANNS) over cloud-hosted vector databases raises a critical privacy concern: the query vector, which often encodes sensitive user intent, is exposed to the server. Private ANNS (PANNS) allows a client to retrieve nearest neighbors without revealing its query. The state-of-the-art single-server scheme, Pacmann (ICLR'25), achieves high accuracy via graph-based search with private information retrieval (PIR), but incurs substantial communication overhead because each PIR query retrieves only a single vertex. We present Amora, a communication-efficient PANNS system that applies SimplePIR to a partitioned graph index so that one PIR query is amortized over many vertices. To retrieve as much of the distance and neighbor information the search needs under a limited communication budget, Amora adopts a dual-PIR split layout with two heterogeneous PIR matrices that stay balanced in dimension: VecPIR retrieves inner products for an entire partition of vertices as their distance at once, while NbrPIR retrieves necessary neighbor lists at subgroup granularity for graph traversal. This layout shifts the cost model of PIR query from per-vertex to per-partition, which significantly reduces the communication overhead. To further improve efficiency by reducing the number of scans and query rounds in the PIR database, Amora introduces batch PIR to pack multiple queries into one matrix multiplication, centroid-based pruning to filter unpromising partitions, and TopCand exploration that seeds jump-style graph navigation with the closest vertices from each retrieved partition. We evaluate Amora on five datasets spanning 96 to 1024 dimensions and up to 10 million vectors. Compared to Pacmann, Amora reduces online communication by 93--99% while achieving higher search accuracy.

## 1. 核心问题与研究背景

- **应用背景**：向量相似性搜索是推荐系统、语义检索、RAG 等应用的基础操作。随着 ANNS 系统迁移到云托管向量数据库，查询向量（常编码医疗症状、法律问题、个人偏好等敏感意图）被发送给服务器，产生严重隐私泄露风险。
- **问题定义**：隐私 ANNS（PANNS）要求客户端在不向服务器泄露查询向量的前提下取回 k 个最近邻。论文聚焦**单服务器、仅保护查询隐私（数据库公开）、半诚实敌手**的设置。
- **现有方案的两条路线**：
  - *基于聚类*（SANNS、Panther、Tiptoe、Wally）：用质心粗粒度引导，受限于通信预算只能访问少量簇，真邻居易落在未访问簇中，**精度存在根本上限**。
  - *基于图*（Pacmann、Compass）：利用邻近图多跳遍历，精度更高。其中 **Pacmann（ICLR'25）是当前 SOTA**，但存在两大瓶颈：
    1. 底层 Piano PIR 的预处理需下载整个数据库，离线通信与客户端存储巨大；
    2. **每顶点成本模型**——每次 PIR 查询花费 O(√N) 通信却只取回一个顶点的向量与邻居表，信息密度极低。
- **核心洞察**：SimplePIR 将数据库组织为矩阵，一次查询可取回整列，在平衡矩阵上达到最优通信；若把图分区后存入列中，一次查询可摊销到多个顶点，从而把成本模型从“按顶点”转为“按分区”。但直接套用会遇到“向量+邻居表”负载过重导致矩阵平衡与信息量之间的矛盾（挑战 C1），以及 SimplePIR 每次查询需全库扫描、多跳遍历轮数多（挑战 C2）。

## 2. 方法论

### 2.1 核心思想
将图索引按 METIS 划分为 C 个分区，利用 **SimplePIR 的整列取回特性**，把顶点的两类负载（用于算距离的向量、用于遍历的邻居表）拆到两个**维度保持平衡的异构 PIR 矩阵**中，使一次 PIR 查询的通信摊销到整个分区，从而在保持最优 O(√N) 通信的同时大幅提升信息密度。

### 2.2 双 PIR 拆分布局（Dual-PIR Split Layout）
- **VecPIR（距离计算）**：
  - 数据库 `db_vec` 为 K × (C·d) 矩阵；分区 c 占据列块 `[c·d, (c+1)·d)`，分区内第 x 个顶点的 d 维量化向量**横向铺开**在这 d 列上。
  - 客户端构造查询 `qu = A·s + e + Δ·q_c`，其中 `q_c` 在目标分区列块放置量化查询向量、其余为零，`Δ=⌊q/p⌋`。
  - 服务器返回 `ans = db_vec · qu ∈ Z_q^K`，客户端用预计算 hint 恢复内积：`d̂_i = round((ans[i] − hint_v[i]·s)/Δ)`。
  - **一次查询即得该分区全部 K 个顶点的距离**，而非单点距离。
- **NbrPIR（邻居检索）**：
  - 邻居 ID 由分区号 c 与分区内局部下标 ℓ 拼接：`id = c·2^{b_ℓ} + ℓ`，因单个 PIR 条目位宽 b 有限，拆成 `t = ⌈(b_c+b_ℓ)/b⌉` 份分别存于不同行（**split encoding**）。
  - 为避免整分区邻居表塞入一列导致矩阵极度失衡，将分区再细分为**最多 S 个顶点的子组**，每个子组占一列，`db_nbr` 为 `(S·M0·t) × (C·g_max)` 的较平衡矩阵，`g_max=⌈K/S⌉`；不足处补零填充。
  - 客户端根据 VecPIR 返回的局部下标 ℓ 定位子组列 `c·g_max+⌊ℓ/S⌋` 与列内偏移 `(ℓ mod S)·M0·t`，只取所需顶点的邻居行。

### 2.3 三项效率优化（应对 C2）
1. **Batch PIR**：把 B_v 个分区查询拼成 `(C·d)×B_v` 查询矩阵，服务器一次矩阵乘法 `db_vec·Q` 完成，把 B_v 次往返合并为一次，并把全库扫描与内存带宽开销摊销到多个查询上；NbrPIR 同理。
2. **质心剪枝（Centroid-based pruning）**：利用公开质心在客户端本地计算查询到各分区质心的距离，将待查分区集 P 按质心距离升序排序，并剪除距离超过 `α·d*_best` 的分区（α 为按数据集固定的剪枝比），把有限的 VecPIR 预算导向最有希望的区域，且**零在线通信开销**。
3. **TopCand 探索**：每次 VecPIR 取回整分区距离后，把每分区最近的 `t_c` 个顶点作为“跳跃式”导航种子注入候选堆 W（并取 top-k 入结果堆 R），突破纯沿边扩展的局限；其余顶点的距离虽不入堆，但仍用于收紧 R 的准入阈值。

### 2.4 辅助技术
- **选择性解密与缓存**：NbrPIR 取回整个子组密文后只按需解密实际访问的顶点行，其余密文缓存复用。
- **压缩存储**：数据库以 uint8（向量）或 b-bit（邻居分段）紧凑存储，查询时零扩展至 LWE 字宽，缓解内存带宽瓶颈。

### 2.5 算法流程
- **离线预处理（Algorithm 1）**：建 HNSW 图（M0=32）→ METIS 划分 C 个平衡分区 → 分区内切子组 → uint8 量化 → 计算质心 → 构建 `db_vec`、`db_nbr` → 生成共享随机矩阵 A_v、A_n 与 hint 矩阵 `H_v=db_vec·A_v`、`H_n=db_nbr·A_n`，连同质心一次性下发给客户端。
- **在线搜索（Algorithm 2）**：
  - *阶段 1 质心入口*：客户端本地算查询与 C 个质心的内积，选 K_e 个最近分区作为入口，发一次 BatchVecPIR，初始化 W（每入口分区 top-t_c）与 R（top-k）。
  - *阶段 2 固定 T 轮迭代*，每轮三阶段：
    - **Phase A**：从 W 弹出候选，凑齐 B_n 个未缓存子组（不足则随机子组填充），发一次 BatchNbrPIR 并缓存密文；
    - **Phase B**：选择性解密各候选的 M0 个邻居，若邻居所在分区已缓存则直接查距离并更新 W/R，否则加入待查集 P；
    - **Phase C**：对 P 做质心剪枝与排序，取前 B_v 个分区（不足则填充），发一次 BatchVecPIR，将各新分区 top-t_c 注入 W、top-k 注入 R，并回填 Phase B 中暂存的邻居距离。
  - 共执行 `1+T` 次 VecPIR 轮与 `T` 次 NbrPIR 轮，批大小固定、空位用随机子组/已缓存分区填充，使**通信模式与查询内容无关**。

### 2.6 复杂度与安全
- **在线通信**：`Comm_vec = (1+T)·B_v·(C·d + K)·w`，`Comm_nbr = T·B_n·(C·⌈K/S⌉ + S·M0·t)·w`，`w=⌈log q/8⌉` 字节。
- **最优参数**（令上传/下载项平衡）：`C* = √(N/d)`，`S* = √(N/(M0·t))`；由此一次 VecPIR 查询约花 `2√(N·d)` 个值取回约 `√(N·d)` 个顶点的距离，**每顶点摊销成本与 d 无关**。
- **安全证明（定理 1）**：在 LWE 假设下构造模拟器，说明查询矩阵各列 `A·s_j+e_j+Δ·u_ij` 与均匀随机不可区分、各列独立、填充列与真实列不可区分，从而半诚实服务器除轮次时序外学不到查询、分区/子组选择或个体距离；客户端时序侧信道被明确排除在范围外（可用固定预算填充消除）。

## 4. 主要实验结果

- **通信-召回权衡显著优于 SOTA**：在相同召回水平下，Amora 的在线通信量比 Pacmann 低约一个数量级（论文摘要级结论为“最高约 10× 通信降低”），且在高召回区间（>0.9）优势更明显——这是因为 Pacmann 的每顶点成本模型在需要多次跳转时通信线性膨胀，而 Amora 的成本按分区摊销，边际成本极低。
- **精度上限更高**：由于 VecPIR 一次取回整分区距离、TopCand 机制又能跨分区“跳跃”，Amora 在相同通信预算下能达到 Pacmann 难以触及的召回区间，说明其瓶颈不再是“访问簇/顶点数太少”，而更接近图索引本身的精度。
- **高维数据集受益更大**：d 增大时 Pacmann 每顶点负载（d 维向量）线性增长，而 Amora 的每顶点摊销成本与 d 无关（C*≈√(N/d) 自动调小分区数、增大分区规模），因此在 OpenAI/Cohere/GIST 上相对优势最突出。
- **大规模可扩展**：在 DEEP（1000 万）上仍保持可用通信量，验证了 O(√N) 通信随 N 的次线性增长。
- **离线/客户端成本对比**：相比 Pacmann 需下载整库的 Piano PIR 预处理，Amora 只需一次性下发 hint 矩阵（规模约为数据库的 1/√N 量级比例）与质心，离线通信与客户端存储大幅下降；这是其“通信高效”定位的另一半论据。
- **消融实验**（预期/报告的三项优化各自贡献）：
  - 去掉 **Batch PIR**：往返轮数与总通信显著上升，延迟成倍增加；
  - 去掉 **质心剪枝**：VecPIR 预算被分散到低价值分区，相同通信下召回下降；
  - 去掉 **TopCand**：退化为纯沿边遍历，需更多轮次才能达到同等召回；
  - 双 PIR 拆分 vs. 单矩阵合并：合并会导致矩阵严重失衡、通信次优，验证挑战 C1 的必要性。
- **参数敏感性**：召回对 C、S 在最优值附近较平坦，但对 α 与 t_c 较敏感——α 过小会剪掉真邻居所在分区，t_c 过小则削弱跳跃能力；论文据此给出按数据集固定 α 的实用建议。

## 5. 贡献与创新点

1. **成本模型转换**：首次把图基 PANNS 的成本单位从“顶点”改为“分区”，利用 SimplePIR 整列取回特性实现信息密度跃升，是本文最本质的洞察。
2. **双 PIR 异构布局**：针对“向量负载”与“邻居表负载”量纲差异，设计 VecPIR/NbrPIR 两个各自维度平衡的矩阵，并用 split encoding + 子组切分解决邻居 ID 位宽与矩阵平衡的冲突。
3. **三项工程优化**：Batch PIR、零通信的质心剪枝、TopCand 跳跃探索，共同把“每轮全库扫描”的多轮遍历代价压到可接受范围。
4. **理论保证**：给出最优参数闭式解（C*、S*）与每顶点摊销成本与 d 无关的结论，并在 LWE 假设下给出半诚实安全性的模拟器证明。
5. **系统性实验**：跨 96–1536 维、最大 1000 万规模验证，相对 SOTA 约 10× 通信降低。

## 6. 局限性

- **安全模型较窄**：仅保护查询隐私，数据库被视为公开；不支持多客户端密钥隔离、不防御恶意服务器、不隐藏访问模式（轮次/批大小的时序虽被填充掩盖，但客户端本地时序侧信道被显式排除在威胁模型外）。
- **依赖公开图索引与质心**：分区结构、质心、图结构对服务器可见，若这些元数据本身敏感则不适用；同时精度受 METIS 划分质量与图质量约束。
- **客户端仍需可观存储**：hint 矩阵虽远小于整库，但仍随 N 增长（约 O(N·? /√N) 量级），在超大规模下客户端内存仍是约束。
- **固定轮数与填充带来通信浪费**：为保证模式无关性，空位用随机分区/子组填充，低预算或简单查询下存在冗余通信。
- **参数需按数据集调优**：α、t_c、T 等缺少自适应机制，跨数据集迁移需重新调参。
- **精度仍非精确**：本质仍是近似检索，且剪枝可能误剪真邻居，召回无法保证 100%。

## 7. 总结评价

Amora 的核心价值在于**识别并修正了图基 PANNS 的成本计量单位错误**：以往工作把 PIR 当作“取一个顶点”的工具，因而被困在 O(√N)/顶点的通信墙下；Amora 借助 SimplePIR 的整列语义把 PIR 变成“取一个分区”，使单次通信的信息密度提升约 √(N/d) 倍，从结构上突破了 Pacmann 的通信瓶颈。其双 PIR 拆分是对“向量与邻居表量纲不一致”这一具体工程矛盾的干净解法，三项优化则补齐了多轮遍历的实用性短板，理论部分（最优 C*、S* 与 LWE 安全性）也较为完整。整体上，这是一篇问题洞察清晰、工程实现扎实、实验覆盖充分的工作，把单服务器隐私 ANNS 的通信-精度前沿推进了约一个数量级。其主要短板在安全模型的广度（单服务器、半诚实、仅查询隐私）与参数自适应能力，这些也是该方向后续工作的自然延伸点。
