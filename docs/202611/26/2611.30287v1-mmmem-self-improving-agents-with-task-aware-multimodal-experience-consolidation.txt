## Abstract 

AI agents accumulate conversations, images, and docu-ments through long-term interactions with users. Answering later questions often requires connecting evidence across these records, yet the resulting understanding is rarely re-tained, allowing mistakes to recur on related questions. Ex-isting multimodal memory methods largely focus on storing and retrieving records, with limited mechanisms for learn-ing from completed tasks and consolidating task-specific experience. We therefore propose MMMem , a task-aware multimodal memory framework that extracts and consoli-dates experience from completed tasks through four com-plementary strategies. First, source-linked multi-view mem-ory organizes original text, images, and rendered pages alongside generated scene images that combine clues across records for retrieval. Second, source-generated tasks sup-port knowledge alignment at two levels: warm-up consol-idates source knowledge into task-relevant experiences in external memory, while self-training adapts the model’s para-metric knowledge to task demands. Third, the same vision-language model distills completed tasks into experiences that record the task context, conclusion, and supporting source links. Finally, task-aware retrieval recalls source views and relevant experiences for answering and verification, while source-supported reuse guides long-term retention. Across three memory benchmarks and two vision-language read-ers, MMMem outperforms eight baselines. With Qwen3.5-9B, MMMem achieves relative gains of 36.9%, 17.6%, and 15.2% over the best-performing baselines on LoCoMo, Mem-Gallery, and LooGLE v2, respectively. Ablations show con-sistent gains from training and memory warm-up, while case studies illustrate how individual components work in prac-tice. 

## 1. Introduction 

AI assistants that support users over time accumulate con-versations, photographs, and documents across interactions. Later requests may depend on information spread across these records, requiring the assistant to connect complemen-tary cues from different modalities. For example, identifying an item in a photograph may require connecting its visual appearance with a name mentioned in an earlier conversation. The agent must determine which records belong together, what they jointly establish, and where each conclusion comes from. These connections emerge during task solving, but a memory that stores only the original records leaves this understanding to be reconstructed for later questions, and the agent may repeat the same mistakes on related questions (Fig. 1a). Preserving this understanding together with its supporting sources would allow completed tasks to improve how memory is organized and used. The current task determines which evidence to prioritize and which earlier conclusions are relevant. An identity ques-tion may rely on names in a dialogue, whereas a question about appearance may require visual details. An entity label stored without its task context and visual grounding can be wrongly transferred to another image when questions are similar. We therefore use tasks as the organizing unit of mul-timodal memory. Each resulting experience records the task context, conclusion, and supporting source links, making explicit what was learned and which evidence supports it. Existing memory methods retrieve relevant context [1, 12, 24] and organize evolving records [4, 25], while vi-sual memory methods [13, 19] and experience-based agents [16, 20, 22, 31] extend how histories are represented and reused. These approaches offer complementary capabilities; the challenge is to coordinate knowledge consolidation in ex-ternal memory with parametric adaptation, allowing agents to learn from multimodal experience across tasks. ## 2. Related Work 

Multimodal Memory. Multimodal memory aims to pre-serve information across text, images, and document layouts for later use. Building on retrieval-augmented generation [12], existing methods retrieve document images directly [5, 27] or render interaction histories into images to recover or emphasize relevant evidence [13, 19]. Beyond representa-tion, recent work studies how retrieved evidence is delivered to the model, preserving its modality, identity, and timing [11] or selecting among textual, visual, and dual-channel representations [6]. MMMem links original records and 2generated views through source identifiers, allowing task-relevant evidence to be combined across representations and traced back to its sources. 

Memory Editing. As interactions accumulate, memory systems must update what they retain. Existing methods extract and maintain facts from conversations [4] or orga-nize memory notes through links that evolve with new in-formation [25]. Task execution provides another source of memory: verbal reflections and insights can be retained for later decisions [20, 31], while execution trajectories can be distilled into reusable workflows and reasoning strategies [16, 22]. MMMem records multimodal question-answering experiences as tasks, conclusions, and supporting source links. These experiences are immediately retrievable, while later reuse supported by source evidence guides long-term retention. The supplementary material compares their mem-ory content, retrieval and reading mechanisms, updates, and trained components. 

Parametric Memory. Parametric memory complements external storage by encoding knowledge in model weights [17]. Recent approaches consolidate short-term knowledge through distillation [2] or incorporate interaction experience through online updates and experience distillation [18, 26]. Others coordinate episodic storage with the gradual consoli-dation of recurring patterns into parameters [23]. Parameter learning also improves how models use external evidence, from deciding when to retrieve and assessing answers [1] to identifying relevant information amid distractors [30]. MM-Mem trains a shared model for evidence-based answering and experience consolidation, connecting parameter learning with the use and construction of external memory. 

Self-Improvement. The effectiveness of parameter adap-tation depends on the training signals available to the model. Self-improvement methods construct these signals from gen-erated outputs and feedback. Some methods improve solu-tions to existing tasks by training on rationales that yield correct answers [28] or combining generated samples with offline reinforcement learning [7]. In vision-language learn-ing, verified programmatic reasoning can provide supervi-sion for model training [10]. Another line of work gener-ates question-answer pairs from knowledge sources through multi-grained self-annotation and iteratively adapts models through self-verification [29]. MMMem uses tasks gener-ated from source materials for memory warm-up and self-training, accumulating external experiences with fixed model parameters and training the shared model for answering and experience writing on separate training sources. 

## 3. Method 

MMMem combines complementary views of multimodal records with experiences distilled from completed tasks. Tasks generated from source material support memory warm-up with fixed model parameters and self-training on separate training sources. For each question, a vision-language model answers using retrieved evidence and relevant experience, then writes a new experience in a second call. We describe these three components in turn (Fig. 2): multimodal mem-ory (Section 3.1), self-improving training (Section 3.2), and task-aware online editing (Section 3.3). 

3.1. Multimodal Memory 

MMMem organizes records with persistent source IDs into local and cross-record memory nodes (Fig. 2a). Consecutive turns within a session form segment nodes, and a session node links these segments. Entity nodes collect records shar-ing a recurring capitalized name across sessions; a single timeline node gathers records containing temporal expres-sions within a memory unit. A record therefore belongs to one segment and can also contribute to entity or timeline nodes. These groupings provide local context and access to information distributed across interactions. Node contents are exposed through original text and im-ages, page images with OCR text, and optional generated scenes. Scene generation initially targets entity and timeline nodes; later usage can trigger generation for additional nodes. The model reads all records associated with the node and selects the facts to depict in one scene. The selected facts retain explicit source IDs and are sum-marized into a scene description for image generation. Fact IDs are checked against the node’s records, and a read-back check compares the generated image’s people and setting with its specification. Generated views retain the provenance of the cited facts. All image views are indexed for visual retrieval, so a match to an original, page, or generated image can retrieve its node. The answering model then receives the selected node’s text and original images. Citations follow the retained source IDs back to the records, preserving the connection between the representation used for retrieval and the evidence used for answering.

Warm-up aligns external memory with task requirements by consolidating source knowledge into retriev-able experiences. Self-training provides internal alignment by adapting the model’s parametric knowledge for evidence-based answering and experience consolidation. The generation prompts cover single-record facts, tem-poral and multi-record reasoning, and questions whose an-swers are absent from the records. Alongside independent questions, related sequences revisit the same fact through paraphrases, request different information from the same sources, or introduce a nearby unsupported query. This gives generated tasks a role in both initial learning and subsequent experience reuse. 

Warm-Up. Before user queries arrive, MMMem runs generated questions through the answering and experience-writing procedure in Section 3.3. The model receives the generated question, any answer options, and retrieved source evidence, then produces its own answer. The model pa-rameters remain fixed, while the resulting experiences enter the staging area and are immediately retrievable. This cre-ates an initial set of task-relevant conclusions and evidence associations for later questions. 

Self-Training. Offline self-training uses source-generated tasks from five benchmark domains, with training units dis-joint from evaluation units. The MiniCPM recipe includes 54 image-based QA examples generated by Qwen3.5-9B. Tasks generated from these sources yield two supervision tar-gets: answers with supporting evidence, and experience sum-maries containing the task context, conclusion, and source links. The two objectives train a shared vision-language model by updating its LoRA parameters θ [9], with the back-bone weights fixed. Answer examples supervise evidence use, whereas summary examples supervise the organization of task-specific knowledge into reusable experience.

3.3. Task-Aware Online Editing 

Retrieval and Answering. For a task q, MMMem re-trieves candidate views through text and visual search and reranks them to assemble evidence Vq within the source-view budget (Fig. 2c). The record preserves the relation-ship between a task’s conclusion and the particular evidence selected to support it. Both Rθ and Wθ use the same fixed pa-rameters under different prompts. On its first adoption by a later task, an experience may receive a generated image shar-ing its task description, conclusion, and source links. This derived view accompanies the experience when recalled. 

Experience Recall. New experiences are immediately re-trievable. For each task, staged experiences are ranked by question-text relevance, and the top entry occupies a ded-icated slot ˜eq outside the source-view budget. This recall route remains active in all settings. Staging makes new expe-rience available immediately while leaving its longer-term retention to be determined by subsequent use. 

Reuse-Guided Retention. An experience is credited as adopted when it reaches the reader and the answer cites at least one linked record that supports the answer. This links retention to continued usefulness on later questions and support from the original records. Rephrasings of the same question contribute at most two adoptions. Every 8 tasks, or when the 32-entry staging area is full, experiences with at least two adoptions are retained and indexed with ordinary memory nodes. At each check, staged experiences with no adoption for 32 tasks expire. Promotion changes only σ,preserving the task description, conclusion, and source links. 

## 4. Experiments 

We evaluate MMMem across three memory benchmarks and two vision-language models. The experiments compare performance with existing methods and examine the contri-butions of self-training, memory organization, and individual components (Sections 4.2 and 4.3). Case studies illustrate how the mechanisms affect evidence retrieval and experience reuse (Section 4.4). 

4.1. Experimental Setup 

Benchmarks. We evaluate on held-out subsets of three benchmarks. LoCoMo [15] tests recall and reasoning over multi-session conversations; Mem-Gallery [3] tests image–dialogue associations; and LooGLE v2 [8] tests ev-idence integration across long documents. Each question accesses only its associated dialogue, scenario, or document. Evaluation-set statistics are provided in the supplementary material. 

Evaluation Metrics. We report token F1 on LoCoMo; EM, token F1, and BLEU-1 on Mem-Gallery; and the offi-cial aggregate score on LooGLE v2, including partial credit for version-control questions. Unanswerable Mem-Gallery questions expect “Not mentioned.” Failed or malformed outputs remain in the evaluation denominator. 

Readers. We use Qwen3.5-9B and MiniCPM-V 4.5 (8.7B parameters) as reader backbones. Comparisons within each reader setting share the same base backbone. MMMem is trained separately for each reader. 

Baselines. We compare eight baselines in four groups. Context baselines include Direct Answer, which uses only the question and any query image; Full Context, which sup-plies up to 32K history tokens; and Recent Context, which re-tains 3K tokens on LoCoMo and 4K on the other benchmarks. Dense RAG [12] retrieves history passages through semantic matching. Visual memory baselines, OCR-Memory [13] and MemOCR [19], provide history as rendered pages. Agent memory baselines, Mem0 [4] and A-Mem [25], organize history through factual updates and evolving linked notes, respectively. Prior memory methods incorporate training at different stages, including retrieval, reading/writing, and memory management, as summarized in the supplementary mate-rial. Our ablations compare MMMem with its counterpart without self-training and with Dense RAG using the same trained reader, separating the contributions of model adapta-tion and the memory workflow. 

Memory and Retrieval. MMMem uses source-view bud-gets of 3,000 tokens on LoCoMo and 4,000 on Mem-Gallery and LooGLE v2, with zero-shot reranking by Qwen3-Reranker-0.6B. LoCoMo and Mem-Gallery use text and visual retrieval; retrieval on LooGLE v2 is predominantly text-based. Gallery images are indexed through captions and the visual route, while query images support retrieval and are supplied to the reader. The top-ranked experience occupies a separate slot outside the source budget. Baselines do not write evaluation questions or model an-swers into memory for subsequent questions. MMMem 5processes questions in dataset order within each dialogue, scenario, or document, accumulating experiences from its own answers and cited source records. Experience memory resets between units, and each unit begins with unscored warm-up tasks generated from its own sources. Model pa-rameters remain fixed throughout warm-up and evaluation. Experience writing uses no reference answers or scoring feedback. Benchmark reference answers, annotated clues, and QA tags are excluded from retrieval. 

Self-Training. Self-training uses tasks generated from sep-arate training units of LoCoMo, Mem-Gallery, LooGLE v2, LVBench, and OVO-Bench. These units are disjoint from evaluation; LVBench and OVO-Bench contribute train-ing data only. Official training-unit question texts guide question style and abstention formatting, without their ref-erence answers. Evaluation-unit questions and answers are excluded from these procedures. The MiniCPM training set includes 54 image-based QA examples generated by Qwen3.5-9B. Each reader is trained for one epoch using attention-projection LoRA adapters and AdamW. Hyper-parameters and data-generation details are provided in the supplementary material. 

4.2. Main Results 

Overall comparison. MMMem achieves the best results on all three benchmarks with both readers (Table 1). The gains are particularly large on conversational and multi-modal memory: with Qwen3.5-9B, MMMem improves over A-Mem by 17.75 F1 on LoCoMo and 11.58 F1 on Mem-Gallery. MMMem also improves performance with MiniCPM-V 4.5, further supporting its effectiveness. 

Comparison with existing methods. Dense RAG outper-forms Full Context in all six settings. Full Context improves over Direct Answer with Qwen3.5-9B but degrades perfor-mance with MiniCPM-V 4.5, highlighting the importance of selecting evidence the reader can use. The effective-ness of memory representations also varies: MemOCR is competitive on LoCoMo but trails Dense RAG on the other benchmarks, while A-Mem’s ranking changes across readers. These patterns motivate coordinating memory organization and evidence selection with the reader’s ability to interpret the retrieved material. 

Differences across benchmarks. Gains are smaller on LooGLE v2, where questions require combining evidence across long documents within the source-view token bud-get. Each document contains about 1.5 scored questions on average, giving the reader fewer opportunities to reuse expe-rience from earlier answers. Warm-up therefore provides an important source of experience before evaluation, consistent with its larger effect on LooGLE v2 in the ablation study. 

Effect of self-training. The controls in Table 2 show com-plementary contributions from self-training and the memory workflow. Self-training improves MMMem in all six set-tings and also improves Dense RAG when the same adapted reader is used. With that reader held fixed, full MMMem further outperforms Dense RAG in every setting. These comparisons show that parameter adaptation accounts for part of the improvement, while the memory workflow sup-plies additional gains through the organization and use of task-relevant evidence and experience.

4.3. Ablation Study 

Table 2 removes components from the full MMMem. Re-moving training causes the largest drop in four of the six settings; this variant and Only Training are discussed in Sec. 4.2, and we discuss the other three components below. 

Task warm-up (“MMMem” vs . “w/o Task warm-up”). Re-moving warm-up lowers all six settings, most on LooGLE v2 (6.62 points with Qwen3.5-9B and 2.13 with MiniCPM-V 4.5). Warm-up writes experiences before the first scored question, which matters most when a unit has few ques-tions: with about 1.5 questions per LooGLE v2 document, the reader would otherwise often face an empty store. On LoCoMo and Mem-Gallery, earlier questions already write many experiences, and the drops are smaller (0.57 to 2.40). 

Experience memory (“MMMem” vs . “w/o Experience”). Removing experience memory lowers performance in all six settings. The largest drops occur on LooGLE v2 with Qwen3.5-9B (5.76 points) and MiniCPM-V 4.5 (2.47 points); on Mem-Gallery with Qwen3.5-9B, the drop is 2.09 points. Since warm-up acts by writing experiences, this variant also loses warm-up. On LooGLE v2 with Qwen, disabling experience memory performs slightly better than disabling warm-up alone. Full MMMem outperforms both variants, supporting the benefit of the complete experience pathway. 

Generated views (“MMMem” vs . “w/o Generated views”). For visual retrieval, generated views combine clues from multiple records into a shared representation (Sec. 3.1). Both readers score higher with these views on LoCoMo and Mem-Gallery, supporting their role as an additional entry point to distributed source evidence. On the text-centric LooGLE v2 benchmark, models tend to skip scene gener-ation and retrieve text directly. Overall, training and task warm-up contribute in every setting, whereas the size of the contributions of experience memory and generated views varies across benchmarks and readers. 

4.4. Case Study 

Figure 3 presents three Mem-Gallery cases with MiniCPM-V 4.5, tracing how generated views, experience reuse, and task warm-up affect retrieval and answering. For bird identification, descriptions of the target bird are spread across two records. A generated scene combines these descriptions into an image for visual matching, moving the relevant node from 10th to 2nd. Its source evidence then reaches the reader, and the answer changes from “Blue Jay” to “Lazuli Bunting.” Scene generation thus makes dispersed textual clues accessible through visual retrieval. The counting question asks how many Dunlin photos Lin Wei shared. Both runs receive the same records and photos, including an earlier image. An experience from a previous scientific-name question links “Dunlin” to Calidris alpina .With this relation available, the reader includes the earlier photo and changes the count from five to six. Experience helps connect species references within evidence already retrieved. In the dog-breed case, the source record gives both the name “Rocky” and the breed “Sussex Spaniel,” and both runs cite it. Without warm-up, the recalled experience comes from a name question and supplies “Rocky,” which the reader incorrectly returns as the breed. With warm-up, the recalled experience concerns a therapy companion and supplies the breed cue “Sussex,” leading to “Sussex Spaniel.” This case illustrates how the task context in recalled experience can guide the reader toward the relevant information in a source. Warm-up thus prepares useful task experience in advance, helping later questions draw on knowledge relevant to their needs.

Closer coordination between external consolidation and internal parameter adaptation is another direction. ## 6. Conclusion 

We introduced MMMem , a task-aware multimodal mem-ory framework that combines external experience consoli-dation with internal parameter adaptation. External consol-idation turns source knowledge and task conclusions into reusable experiences, enabling agents to retrieve, reuse, and retain task-relevant knowledge. Internal adaptation trains a shared model to answer from multimodal evidence and distill task experience, aligning its parametric knowledge with task demands. Source-generated tasks connect these processes through memory warm-up and self-training. Ex-periments across three memory benchmarks, supported by ablations and case studies, show the benefits of jointly im-proving memory organization and the model’s ability to use accumulated knowledge. 

Reproducibility statement 

The evaluation settings and self-training procedure are de-scribed in Sections 4.1 and 3.2. Reference answers and annotated clues are excluded from retrieval, and failed or malformed outputs remain in the evaluation denominator.

## B. MMMem Implementation 

B.1. Multimodal Memory Construction 

Source nodes. The memory assigns a persistent ID to each source record. Within a session, consecutive turns are packed into segments of up to six turns and 400 tokens. A final segment of fewer than three turns is merged into the previous segment when the result fits those limits. A turn longer than the token limit forms a segment of its own. Each session node points to its segments. Entity nodes group records with a shared capitalized name appearing at least twice, with speaker names and sentence-initial tokens excluded from name extraction. One timeline node per unit groups records containing temporal expressions. 

Scene views. Entity and timeline nodes are eligible for scene generation at construction. A node used by three tasks can also become eligible, including a segment node. Scene generation is capped at 48 views per unit. The specification prompt in Section C.1 receives all source records in the selected node and selects facts and their record IDs for one scene. We keep facts whose IDs belong to the node. Qwen-Image renders the scene description, and a vision-language check compares the number and genders of people and the setting with the specification. A failed specification or image 11 check is retried once. The accepted view retains the source IDs of the depicted facts. 

B.2. Self-Improving Training 

Task generation. The generator writes questions, target answers, and supporting record IDs from the supplied source records. The templates in Section C.2 cover free-answer and multiple-choice questions, including related sequences that revisit a fact or ask for new information from the same source. For basic QA generation, the prefix contains six official question texts sampled from the same domain’s training pool as style examples. The pool can include questions from the training unit being processed. Generation relies on the prompt to elicit new wording. Image-based QA is generated directly from the source records. 

Warm-up as external experience consolidation. Before the first scored question, MMMem initializes an experience store for the evaluation unit and generates unscored tasks from its source material. The style examples come from the separate training pool. For each warm-up task, the reader takes the generated question, any options, and retrieved ev-idence. A second call consolidates the reader’s prediction and source evidence into an experience available to scored questions. Task generation and these per-task answering and writing calls are part of the test-time workload. 

Warm-up question overlap. We compare warm-up and scored question texts within each unit after Unicode NFKC normalization, case folding, and whitespace collapse. On LoCoMo, 2 of 887 Qwen warm-up questions and 10 of 843 MiniCPM warm-up questions have exact matches. Both readers have zero exact matches on Mem-Gallery and LooGLE v2. Excluding the matched scored questions changes LoCoMo F1 from 65.84 to 65.82 for Qwen and from 56.40 to 56.27 for MiniCPM. 

Self-training as parameter adaptation. Offline supervi-sion is generated from training units disjoint from evaluation. The targets teach the model to answer with source IDs and to summarize a completed task as a conclusion linked to supporting records. Official training questions contribute style and abstention-format examples. For example, calibra-tion assigns Not mentioned. on a subset of Mem-Gallery training examples and Unable to answer on a subset of OVO-Bench examples. The generator supplies the target answers, while official reference answers are reserved for evaluation. MiniCPM’s training includes 54 image-based QA examples generated by Qwen3.5-9B. 

Optimization. Each backbone is adapted separately. We apply LoRA to the language model’s query, key, value, and output attention projections with rank 16, α = 32 ,and dropout 0.05. We train for one epoch using AdamW at a learning rate of 10 −4, with a microbatch of one and eight gradient accumulation steps. Loss is computed on target tokens. The Qwen and MiniCPM checkpoints used for the main experiments are JFIXQ_train_ids and 

JFIXM_train_teacher , respectively. 

B.3. Task-Aware Online Editing 

Source retrieval and reader inputs. LoCoMo and Mem-Gallery use text and visual retrieval, while retrieval on LooGLE v2 is predominantly text-based. In Mem-Gallery, historical images are indexed by both their captions and their visual representations. A query image contributes to rank fusion and is supplied to the reader. We rerank candidates with the pretrained Qwen3-Reranker-0.6B cross-encoder in a zero-shot setting and select source evidence within the token budget in Table 3. A match to a generated scene recovers the corresponding node’s source text and original images. A separate slot supplies the top-ranked staged experience by question-text relevance. 

Scored questions and experience writing. After warm-up, MMMem answers scored questions in dataset order using fixed reader and writer parameters. The answering call re-ceives the current task, retrieved evidence, and any recalled experience. The experience-writing call uses the model’s own answer and the source records it cited. Each new ex-perience stores the task context, conclusion, and supporting record IDs and becomes available to subsequent questions in the same unit. Benchmark reference answers and scoring feedback are kept separate from the reader and writer. Sec-tion C.3 gives the reader prompts, and Section C.4 gives the summary prompt. 

Reuse within an evaluation unit. An experience receives adoption credit when it reaches the reader and the answer cites a linked record that supports it. Its first adoption can trigger an associated image. Rephrasings of a question con-tribute up to two adoptions. The system checks the 32-entry staging area every eight tasks or when it fills. It promotes experiences with at least two adoptions into the source index and expires staged entries that go 32 tasks without adop-tion.
