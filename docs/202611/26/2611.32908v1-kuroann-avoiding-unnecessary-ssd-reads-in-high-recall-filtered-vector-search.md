## 摘要
我们提出KuroANN，一种面向分区索引的新型基于SSD的过滤向量搜索系统。现有解决方案为给定选择性范围内的所有查询分配相同数量的SSD读取，导致许多查询浪费I/O。KuroANN则根据通过其过滤器的向量数量（称为匹配数）为每个查询分配SSD读取。这基于我们的观察：匹配数在搜索前已知，且查询所需的SSD读取数量取决于该匹配数。KuroANN离线测量在每个匹配数下，为达到目标召回率需要探测多少个分区以及读取多少候选。运行时，查询会查找这些数值，仅对探测到的分区进行过滤，并在进一步读取不太可能有帮助时停止从SSD读取。这显著避免了不必要的SSD读取和过滤工作，在高召回率下提升了吞吐量和延迟。实验结果表明，KuroANN分别比PipeANN-Filter和Faiss最高快34.5倍和9.10倍。

## Abstract
We present KuroANN, a new on-SSD filtered vector search system for partition indexes. Existing solutions assign the same number of SSD reads to all queries within a given selectivity range, wasting I/O for many queries. KuroANN instead assigns each query's SSD reads based on the number of vectors that pass its filter, called its match count. This is based on our observation that the match count is known before the search and that the number of SSD reads a query requires depends on this match count. KuroANN measures offline how many partitions to probe and candidates to read for the target recall at each count. At runtime, a query looks up these numbers, filters only the probed partitions, and stops reading from the SSD when further reads are unlikely to help. This significantly avoids unnecessary SSD reads and filtering work, improving throughput and latency at high recall. Experimental results show that KuroANN outperforms PipeANN-Filter and Faiss by up to 34.5x and 9.10x, respectively.

## 1. 核心问题与研究动机

- **背景**：RAG、语义搜索、推荐等应用依赖十亿级向量上的近似最近邻（ANN）检索，且查询通常带有过滤谓词（如“只找标签为 dog 的照片”）。生产环境中过滤选择率（selectivity）在不同查询间可相差数个数量级，同时 SSD 上的检索仍需达到很高召回（如 0.99）。
- **两类索引在过滤下的困境**：
  - **图索引**：后过滤会读入大量不匹配向量，浪费 SSD 读；跳过不匹配向量又会切断图的连通路径，导致匹配向量不可达（Filtered-DiskANN 在选择性强的标签上召回接近 0，PipeANN-Post 召回低于 0.9）。PipeANN-Filter 用 Bloom 过滤器做推测式遍历 + 2-hop 邻居稠密化，前者带来误报读放大，后者使索引体积膨胀十倍以上。
  - **分区索引（IVF）**：过滤器不会破坏索引结构，但现有系统（Faiss、Curator、AnalyticDB-V、Pinecone 等）**对同一选择率区间或同一路由的所有查询分配相同预算**（探测分区数、重排候选池大小），或使用固定公式。由于 SSD 上每个重排候选都是一次随机 I/O，统一预算必须按“最难的查询”来设定，导致简单查询大量浪费读，吞吐可下降一个数量级。
- **第二重浪费**：现有系统对远多于实际需要的向量施加过滤，例如位图过滤会为整个数据集标记匹配项，即使查询只探测少数分区，造成额外 CPU 开销。
- **核心研究问题**：能否在 SSD 上对任意选择率的过滤器都实现高召回，同时把 SSD 读和过滤工作量都压到很低？
- **关键观察（论文的立论基础）**：分区索引中，查询的**匹配数（match count）在发出任何 SSD 读之前就已知**（由倒排列表长度得到），且匹配数能预测该查询达到高召回所需的 SSD 读数量——因为候选按内存中的 PQ 码排序，PQ 压缩误差导致的错序候选数量与匹配数相关。

## 2. 方法论

### 2.1 核心思想
用每个查询的**匹配数**作为“预算索引键”，查表得到该查询应探测多少分区、读取多少候选、以及何时停止读取；内存中的过滤只触及被探测分区内的匹配项。

### 2.2 四步流水线（❶计数 → ❷查计划 → ❸内存排序 → ❹SSD 重排）

- **位置有序倒排表（Position-ordered postings，§3.2）**
  - 所有 PQ 码按分区顺序存放于一个数组，其下标称为 **position**；每个标签维护一份按 position 排序的倒排表（posting）。
  - 倒排表长度 = 匹配数（计数无需任何 I/O）；因同一分区的 PQ 码在数组中连续，一个分区的匹配项对应倒排表中一段连续区间，**两次二分查找**即可取出被探测分区的全部匹配项，无需 per-query 位图，也无需逐条检查标签。
  - 穷举路由（scan-all-matches）按 position 顺序读取，访问是顺序的而非随机的。
  - 多标签谓词在**每个被探测分区内**求值：AND 从最稀有标签的区间开始求交，OR 归并区间并去重，结果保持 position 有序。
  - 计数：单标签取长度；OR 取长度之和（上界）；AND 在最稀有 posting 很长时**按等距采样 + 置信区间估计**（例：1M 条中采 16K，10% 命中 → 区间 93K–107K），只有当区间跨越多个计划行时才做精确求交。范围/字符串/否定/嵌套谓词同理，选择性强的范围条件用按值排序的列副本取候选。

- **按计数索引的计划（Count-indexed plan，§3.3）**
  - 计划是一张小表，每行覆盖一段计数区间，固定：路由（穷举扫描全部匹配 / 探测最近分区）、探测分区数、候选池大小、是否启用提前停止及其停止表与分位水平。
  - **离线标定（calibration）**：在若干“标定点”（calibration points）上实测两条路由的候选设置，选出**满足目标召回且最快**的设置；用“减去两个标准误”的余量抵御标定查询采样误差（例：500 条查询 × 10 邻居，0.99 目标要求实测 ≥0.993）。
  - **覆盖计数区间**：对标签 posting 随机保留 90%、80% 成员构造副本（并重算真邻居），使一个标定点覆盖三档计数，也顺带适配随机删除后的计数下降。
  - **间隙行**：相邻标定点之间因两条路由的召回随计数反向变化，取在两点的六个标定计数上都达标的最快固定设置（不提前停止）。
  - **局部计数（local count）**：若标签在最近分区内的密度显著高于全局，则按“若全局都这么密”的等效更大计数取行，用于缓解匹配项在查询附近聚集时停止过早的问题。
  - **最近质心查找**：质心多时用质心上的 HNSW 图（过滤器不会破坏它），几千个时精确扫描；构建后把不可达质心连到最近的可达质心。

- **带前瞻预取的扫描（Lookahead prefetching，§3.4）**
  - 倒排表事先给出全部未来访问位置，故可在计算当前候选时预取后续候选的 PQ 码与 ID；实现取 8 个候选的前瞻距离，并用透明大页降低 TLB 缺失。
  - 该优化只改变取数时机与页映射，**不改变结果**（候选与结果完全一致）。

- **有界 SSD 重排（Calibrated stopping，§3.5）**
  - **块对齐槽位**：每个向量存入一个块对齐槽，保证一次读只取一个向量（否则 3072B 向量背靠背打包时约一半跨 4KiB 块边界，需两次读）；由 ID 一次除法即可算出块地址。
  - **误差标定停止**：在标定查询上按池内名次区间统计“精确距离 − 估计距离”的误差，取低分位数存入**每个计数、每条路由各一张**停止表。查询时未读候选的乐观下界 = 估计值 + 该名次区间的误差分位；按估计值顺序分块读（每批 32 次读），当第 k 个精确距离 ≤ 最小未读下界时停止。
  - 作者明确说明这是**启发式而非逐查询保证**（分位数只描述单个候选，而未读集合依赖同一批估计）。

- **更新机制（§3.6）**：插入进入每个分区的 delta 段（新 PQ 码/ID/标签），删除置墓碑位，二者都实时更新计数（计划只读计数，故**无需重新标定**）；按需 merge 重写紧凑数组。当前 delta 段不存属性值，因此更新只支持标签谓词。

## 3. 实验设置

- **硬件**：商用 NVMe SSD（单盘、4KiB 块粒度），多核 CPU；测试单线程与多线程吞吐，并报告每查询 SSD 读字节数（读放大）与 CPU 时间。
- **数据集**：
  - **SIFT-1B**（128 维，10 亿向量）——大规模基准；
  - **LAION-100M / 400M**（CLIP 图像嵌入，配多种标签/属性过滤器）——真实多标签场景；
  - **YFCC-100M**（配时间、相机等属性）；
  - **YT-5M / Text-to-Image** 类较小数据集用于细粒度选择性扫描。
  - 过滤器覆盖单标签、AND/OR 多标签、范围、字符串、否定与嵌套谓词，选择率从约 10⁻⁶ 到 100%（无过滤）连续扫描。
- **基线**：Filtered-DiskANN（后过滤图）、PipeANN-Post、PipeANN-Filter（推测式遍历 + 2-hop 稠密化）、ACORN（图 + 谓词子图）、以及 IVF 系 Curator、Faiss-IVF+后过滤/位图过滤、AnalyticDB-V 风格的固定预算方案；部分实验对比 Milvus/Pinecone 类系统的默认策略。
- **指标**：Recall@10（目标 0.99 与 0.90 两档）、QPS、每查询读字节数、索引构建时间与索引体积、更新吞吐。

## 4. 主要实验结果

- **高选择率（弱过滤）**：与 PipeANN-Post / Filtered-DiskANN 持平或略优，因为此时瓶颈是图遍历而非过滤，KuroANN 的 IVF 路由 + 顺序扫描在 I/O 上仍具优势。
- **低选择率（强过滤）**：图索引类基线召回崩塌（Filtered-DiskANN 在极强标签上 Recall@10 接近 0，PipeANN-Post < 0.9），KuroANN 在 0.99 召回下仍能工作，QPS 提升达一个数量级以上；相对 PipeANN-Filter，在同等召回下吞吐高数倍，且**索引体积小一个数量级**（无 2-hop 稠密化）。
- **相对固定预算 IVF 基线**：在混合选择率工作负载（同一时刻存在易/难查询）上，KuroANN 的吞吐显著高于按最难查询设预算的系统——因为简单查询只读极少量候选；论文报告的量级为“数倍到十余倍”，且读字节数下降更明显。
- **读放大**：KuroANN 的每查询读字节数随匹配数平滑增长，且接近“仅读必要候选”的下界；位图式过滤在读字节上高出数倍（标记全库 + 无效候选读）。
- **召回稳健性**：在 0.99 目标下，实测召回在绝大多数数据集/选择率组合上满足目标；标定余量（减两个标准误）使少量查询略低于 0.99 但仍在 0.99 附近，作者将其归因于分位数停止的启发式性质。
- **更新**：delta 段 + 墓碑使插入/删除无需重建或重新标定，更新吞吐高于需要重建图的基线；merge 有短时抖动。
- **消融**：
  - 去掉位置有序倒排表 → 退化为位图过滤，CPU 与读放大上升；
  - 去掉按计数索引的计划（改用单一固定预算）→ 简单查询浪费读，整体 QPS 大幅下降；
  - 去掉标定停止 → 固定读满候选池，读放大显著上升；
  - 去掉前瞻预取 → QPS 下降（I/O 串行化），但结果不变；
  - 去掉块对齐槽位 → 读次数约翻倍（跨块读）；
  - 去掉局部计数行 → 聚集型过滤器上召回下降。

## 5. 讨论与局限

- **停止准则是启发式**：分位数误差表只刻画单个候选的误差分布，未读集合的下界并非严格置信界，因此无法给出逐查询召回保证；论文以标定余量近似控制。
- **依赖 PQ 排序质量**：匹配数能预测所需 I/O 的前提是 PQ 估计与精确距离的错序程度随匹配数可控；若 PQ 码本与该数据集分布失配，标定需重做。
- **仅支持标签/属性谓词**：delta 段不存属性值，故更新路径不支持范围/字符串谓词下的即时可见性（需 merge）。
- **标定成本**：需要为每个数据集、每种谓词类型与目标召回做离线标定；好在计划只依赖计数，数据增删不需重标定。
- **与图索引的正交性**：方法本质是“分区索引 + 预算自适应”，不排斥与图结构结合，但论文未探索。

## 6. 贡献与结论

- **问题定位**：指出过滤 ANN 在 SSD 上的核心浪费不是“过滤本身”，而是**对所有查询使用统一预算**以及**对全库施加过滤**；并给出可操作的度量（每查询读字节数）。
- **关键洞察**：分区索引中匹配数在 I/O 前已知，且能预测达标召回所需的读量——这把“查询难度估计”变成了零成本的查表问题。
- **三项技术**：位置有序倒排表（O(log n) 取分区内匹配项、顺序访问、多谓词区间运算）、按计数索引的离线标定计划（含间隙行、局部计数、覆盖式标定点构造）、以及块对齐 + 误差标定的有界重排与前瞻预取。
- **工程实现**：1.5K 行 C++ + io_uring，验证了在十亿级真实数据上同时取得 0.99 召回、低读放大与高吞吐的可行性。
- **结论**：在 SSD 过滤 ANN 中，“按查询难度分配 I/O 预算”比“改进过滤机制”带来更大收益；匹配数是廉价且有效的难度信号。
