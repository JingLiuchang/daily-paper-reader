## 摘要
大语言模型（LLM）智能体依赖外部记忆在交互之间保留并复用信息。现有记忆系统将记忆视为对过去的记录，并通过其对对话的忠实度来评估。然而，记忆的价值在于它是否改善智能体的回复。记忆系统在回复产生之前就决定记住什么以及提供什么，而忠实度检查并不会针对该回复来检验这两个决策。因此，忠实的记忆仍可能无法改善回复。我们转而将记忆视为一个预测问题，并提出 Leto——一种面向 LLM 智能体的记忆系统，它关注记忆对未来的效用，而非对过去的忠实度。由于未来请求未知，Leto 通过记忆索引保留对对话细节的访问，使信息能够通过其来源保持可用。当请求到来时，记忆重放利用该索引来预判并提供智能体所需的上下文，超出请求明确陈述的内容。所提供上下文的效用直到回复生成后才确定，这促使我们采用效用循环，利用回复结果来改进未来的记忆选择。我们在三种场景下的五个基准上，将本系统与六种记忆系统进行评估。在个性化场景中，其在 PrefEval 上的准确率比最强的对比记忆系统高 16.3 个百分点，在 PERMA 上的任务完成率高 3.1 个百分点。在长时程任务中，其在五个环境中平均后在 MemoryArena 上取得最佳总体性能，且增益随链深度增加而增大。在长上下文理解中，其与对原始历史进行检索的表现相当，同时提供的上下文 token 更少。

## Abstract
Large language model (LLM) agents rely on external memory to retain and reuse information across interactions. Existing memory systems treat memory as a record of the past and evaluate it by fidelity to the conversation. However, the value of memory lies in whether it improves the agent's response. A memory system decides what to memorize and what to serve before that response exists, and fidelity checks neither decision against it. Faithful memory can therefore fail to improve the response. We instead view memory as a prediction problem and present \textbf{\emph{\leto{}}}, a memory system for LLM agents that focuses on the utility of memory to the future rather than on its fidelity to the past. Because future requests are unknown, \emph{\leto{}} preserves access to conversation details through memory indexing, allowing information to remain available through its sources. When a request arrives, memory replay draws on this index to anticipate and supply the context the agent needs beyond what the request explicitly states. The utility of the served context remains uncertain until the response is generated, motivating a utility loop that uses response outcomes to refine future memory selection. We evaluate our system against six memory systems on five benchmarks across three scenarios. In personalization, it outperforms the strongest compared memory system by 16.3 percentage points in accuracy on PrefEval and by 3.1 points in task completion on PERMA. For long-horizon tasks, it achieves the best overall performance on MemoryArena averaged over five environments with a gain that increases with the chain depth. In long-context understanding, it is on par with retrieval over the raw history while serving fewer context tokens.

## 1. 核心问题与研究动机

- **核心问题**：现有 LLM 智能体外部记忆系统通常把记忆视为“对过去的记录”，并用**对话保真度**（记忆是否完整覆盖历史、检索是否命中金标证据）来评估。但论文指出，记忆的真正价值在于**是否改善智能体对后续请求的回复**，即记忆的“效用”。
- **两个关键缺口**：
  - **记忆化缺口（memorization gap）**：写入时决定“记住什么”，但忠实摘要或事实抽取未必保留未来请求真正需要的信息；摘要可能遗漏后来才显得重要的细节。
  - **服务缺口（serving gap）**：请求到来时按“与请求的相似度”选择记忆，但用户往往不会重述长期偏好或约束，真正会改变回复的记忆可能排名不高。
- **整体含义**：论文将记忆管理视为一个**面向未来的预测问题**：写入时要预测哪些信息未来有用，服务时要预测回复需要哪些上下文；由于未来请求未知，预测准确性只能在回复产生后通过结果反馈检验。因此，记忆应以“对任务结果的边际贡献”而非“对过去的忠实度”为核心标准。
- **形式化目标**：定义服务记忆 \(M\) 对请求 \(x\) 的效用为  
  \[
  U(x,M)=y(x,M)-y(x,\varnothing)
  \]
  其中 \(y(x,M)\) 为提供记忆时的任务结果，\(y(x,\varnothing)\) 为无记忆时的结果。该定义允许记忆带来正效用、无影响甚至负效用。

## 2. 方法论：Leto 的核心思想与关键技术

- **核心思想**：Leto 不把“保真”作为最终目标，而是通过**记忆索引、记忆重放、效用闭环**三个机制，尽量保留未来可访问的信息，并在请求前后提供智能体真正需要的上下文，再用回复结果修正未来记忆选择。
- **总体流程**：
  - 会话结束后进行**记忆索引**；
  - 在新对话开始前进行**记忆重放**，形成用户画像和任务状态；
  - 请求到来时检索事实及其来源，并通过**效用门控**选择服务内容；
  - 回复后根据交互信号或任务结果更新记忆效用索引。

### 2.1 记忆索引（Memory Indexing）

- **保留全部对话**：由于未来请求未知，Leto 不因当下看不出用途而丢弃信息；它保留每次对话，并通过索引使信息可被访问。
- **以原子事实为键、以来源片段为值**：
  - 将对话抽取为**原子事实**，每条事实表达一个自包含的单一主张，便于与请求精确匹配和比较。
  - 与常见系统直接把抽取事实作为记忆不同，Leto 把事实作为**索引键**，其值是事实对应的**原始消息片段（source）**。
  - 只有匹配请求的事实所指的来源才进入智能体上下文，从而减少原始 chunk 检索的噪声；事实中省略的细节仍可通过来源恢复。
- **事实合并与版本区分**：新事实与已有事实合并；修正旧事实的新事实会**取代但不删除**旧事实，从而区分“当前成立”与“曾经成立”。
- **会话摘要**：每个会话还生成简短摘要，供后续画像和任务状态构建使用。

### 2.2 记忆重放（Memory Replay）

- **目的**：检索可能漏掉请求未明说的长期偏好和约束，因此 Leto 在对话之间主动“重放”存储记忆，预先构建下一次对话的**常驻上下文**。
- **用户画像重写（Profile Rewrite）**：
  - 在新会话被索引后，根据当前用户事实和会话摘要重写用户画像。
  - 画像保持简洁：合并相关事实、删除已被取代的偏好，承载与具体请求无关的长期偏好、约束或行为指令。
- **任务状态渲染（Task Rendering）**：
  - 对长时程任务，在每次对话开始时提供任务状态。
  - 第一部分按实体组织当前事实及其属性值，表示“任务现在到哪了”；
  - 第二部分按顺序给出此前会话摘要，表示“任务如何走到这里”。

### 2.3 效用闭环（Utility Loop）

- **效用预测**：每条新记忆获得初始效用预测 \(u_0(m)\in[0,1]\)。低预测不会删除记忆，保留与服务是分离决策，服务优先级可随反馈变化。
- **结果观测**：
  - 使用词法规则从对话中检测交互信号，如确认、使用记忆等正向信号，或纠正等负向信号，分别编码为 1 和 0。
  - 若存在分级任务结果，也可记录给任务期间服务的记忆。
- **效用更新公式**：
  \[
  u(m)=\frac{k u_0(m)+\sum_{i=1}^{n}o_i}{k+n}
  \]
  其中 \(k>0\) 控制初始预测相对反馈的权重，\(n\) 为观测数。
- **服务门控与预算分配**：
  - 检索到的记忆只有效用索引达到阈值 \(\tau\) 才通过效用门控；
  - 当超过上下文预算时，优先选择效用索引更高的记忆。
- **定位说明**：论文明确称效用索引是**启发式服务优先级**，并非对 \(U(x,M)\) 的精确估计；系统整体是否改善任务结果仍通过配对评估衡量。

## 6. 主要结论与发现

- **个性化场景**：
  - PrefEval 上 Leto 达到 **60.5%** 准确率，比最强对比记忆系统 Hindsight 高 **16.3 个百分点**；
  - 偏好未察觉违规降至 **19.1%**，Hindsight 为 **33.8%**；
  - 偏好进入上下文的比例为 **84%**，高于其他记忆系统的 12%–69%；
  - PERMA 上，Leto 在 C-S 和 C-M 的 MCQ 准确率均为最高；C-M 完成率比最强对比系统 Memobase 高 **7.64 个百分点**；两种条件平均任务完成率 **76.5%**，比 Memobase 高 **3.1 个百分点**。
- **长时程任务**：
  - MemoryArena 五环境平均后，Leto 取得最高总体 **PS 32.01%** 和 **SR 18.33%**；
  - 相对 No Memory 的增益随链深增加：shopping 从第一步 **+1.3 个百分点** 增至第六步 **+7.3 个百分点**；search 从第一步约 **0** 增至第八步约 **+14 个百分点**；
  - Leto 是唯一在所有环境中有用率均超过有害率的记忆系统。
- **长上下文理解**：
  - LoCoMo 准确率 **71.82%**，LongMemEval **73.20%**，均为对比记忆系统中最高；
  - 与 RAG 相比，LoCoMo 低 **2.79 个百分点**，LongMemEval 高 **6.80 个百分点**；
  - 但 Leto 每问题仅服务约 **1,192 / 1,185 tokens**，RAG 分别约 **1,999 / 9,813 tokens**；
  - 证据召回率最高：LoCoMo **86.58%**，LongMemEval **95.38%**。
- **总体结论**：记忆的价值应由其对后续回复的效用衡量；保真度分数不必然转化为更好的任务表现。Leto 的索引、重放和效用闭环在个性化与长时程任务中表现突出，并在长上下文场景以更少 token 达到有竞争力的效果。

## 7. 优点

- **问题视角有启发性**：从“记忆保真”转向“记忆效用”，明确指出记忆写入与服务两个决策都面向未知未来，抓住现有评估的核心盲点。
- **方法设计针对性强**：
  - 用原子事实作为索引键、原始来源作为值，兼顾精确匹配与细节可恢复性；
  - 保留全部对话、事实取代但不删除，缓解“写入时误删未来有用信息”的问题；
  - 记忆重放预先注入用户画像和任务状态，弥补请求未明说的长期约束；
  - 效用闭环将回复结果反馈到服务优先级，形成可迭代机制。
- **实验覆盖较全面**：横跨个性化、长时程任务、长上下文理解三类差异明显的场景，并与多种主流记忆系统比较。

  - 链深分析展示长时程增益趋势；
  - 证据召回与 token 成本联合报告，体现效率—效果权衡。
- **工程可解释性较好**：画像、任务状态、效用门控等机制语义清晰，便于分析和部署。

## 8. 不足与局限

- **抽取覆盖仍是瓶颈**：虽然保留全部对话，但只有被事实索引

覆盖到的对话片段才可能被检索和服务；若事实抽取遗漏、粒度过粗或错误归并，相关信息即使仍保存在原始对话中也难以被有效访问。因此，“保留全部对话”更多是降低信息丢失风险，并不等于所有历史都可被同等利用。

- **事实抽取与画像重写依赖底层 LLM 的稳定性**：原子事实的质量、事实合并与版本取代、用户画像重写、任务状态渲染都依赖模型判断。若抽取出错、把临时状态误写成长期偏好，或在重写中丢失限定条件，可能造成记忆污染，并通过重放机制被反复带入后续上下文。
- **效用反馈存在代理偏差与稀疏性**：交互信号主要通过词法规则检测，确认、纠正等信号并不总能准确反映记忆是否真正有用；任务结果也并非每个请求都有。效用索引是启发式优先级，而非对 \(U(x,M)\) 的精确估计，在反馈稀疏、噪声较大或延迟反馈场景下，门控可能误伤高价值记忆或保留低价值记忆。
- **关键超参数与预算策略缺少充分分析**：初始效用权重 \(k\)、服务阈值 \(\tau\)、上下文预算以及画像/任务状态的篇幅控制都会影响效果与成本；给定文本中未见系统敏感性分析，实际部署时调参成本与稳健性仍不明确。
- **组件贡献未被充分拆解**：论文提出索引、重放、效用闭环三个核心机制，但给定文本中未见完整消融实验，难以判断性能提升主要来自哪一部分，也难以区分“更好的检索表示”“预先注入画像”与“结果反馈门控”各自的边际贡献。
- **跨系统比较的公平性仍受实现差异影响**：不同记忆系统的底层模型、调用次数、上下文预算和工程优化未完全统一报告；部分表格仅标注 Standalone 的模型配置，Leto 与其他系统的模型配置、推理成本未完整展开，因此性能差异中仍可能混入实现与资源差异。
- **并非在所有设定上全面领先**：在 LoCoMo 上，Leto 准确率低于 RAG 基线约 2.79 个百分点，说明“事实索引 + 效用门控”的策略在某些长上下文问答类型上可能损失部分原始上下文信息；其优势更多体现在 token 效率、证据召回以及个性化/长时程任务上。
- **评估范围仍以基准环境为主**：记忆库多为单用户、单任务链或单会话设定，跨用户、跨任务、跨智能体共享记忆，以及多用户冲突记忆、隐私隔离、恶意记忆注入、记忆删除与合规等问题尚未充分覆盖；真实部署中的长期漂移与安全风险仍需进一步验证。
- **负效用与冷启动问题值得关注**：论文的效用定义允许负效用，但系统主要通过阈值门控和优先级排序来服务记忆，对“何时应主动抑制某条记忆”“新记忆冷启动阶段如何避免误判”讨论仍有限；低初始效用记忆虽不被删除，但可能在关键请求中因排名不足而无法进入上下文。

## 9. 总体评价与启示

- **理论贡献**：论文最重要的贡献不是某一个工程模块，而是把记忆管理从“历史保真”重构为“面向未来请求的效用预测”，并用 \(U(x,M)=y(x,M)-y(x,\varnothing)\) 将记忆价值与任务结果直接关联。这一视角能够解释为何高保真摘要、高召回检索并不必然带来更好的智能体表现。
- **方法启示**：Leto 的设计体现了三个可复用原则：第一，写入阶段尽量保留可恢复的原始来源，以事实作为索引而非最终上下文；第二，服务前通过画像和任务状态重放，弥补“请求不会重述长期约束”的缺口；第三，用结果反馈调整服务优先级，使记忆系统具备闭环优化能力。
- **实践价值**：原子事实—来源片段的索引结构、事实“取代但不删除”的版本机制、效用门控与预算分配，都具有较强的工程可解释性，适合需要长期个性化与长时程任务跟踪的智能体系统借鉴。
- **仍需补强的研究点**：后续工作可重点补充组件消融、超参数敏感性、反馈信号鲁棒性、跨用户/跨任务泛化、隐私与安全约束，以及更精确的效用估计方法；同时应在统一模型与预算条件下比较不同记忆系统，以进一步验证“效用优先”范式的普适性。
- **结论性判断**：论文的问题定义清晰、方法针对性强、实验覆盖较广，尤其通过有用率/有害率、链深增益和证据召回等分析，将“记忆是否真的帮助回复”落到了可操作评估上。其局限主要在于抽取与反馈仍依赖启发式代理、组件贡献和成本信息不够充分，但整体上为 LLM 智能体记忆系统提供了一个从“记住过去”转向“服务未来”的有价值框架。
