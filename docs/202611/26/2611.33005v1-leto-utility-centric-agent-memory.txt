Abstract 

Large language model (LLM) agents rely on external memory to retain and reuse informa-tion across interactions. Existing memory sys-tems treat memory as a record of the past and evaluate it by fidelity to the conversation. How-ever, the value of memory lies in whether it im-proves the agent’s response. A memory system decides what to memorize and what to serve before that response exists, and fidelity checks neither decision against it. Faithful memory can therefore fail to improve the response. We instead view memory as a prediction problem and present Leto , a memory system for LLM agents that focuses on the utility of memory to the future rather than on its fidelity to the past. Because future requests are unknown, Leto pre-serves access to conversation details through memory indexing, allowing information to re-main available through its sources. When a request arrives, memory replay draws on this index to anticipate and supply the context the agent needs beyond what the request explic-itly states. The utility of the served context remains uncertain until the response is gen-erated, motivating a utility loop that uses re-sponse outcomes to refine future memory se-lection. We evaluate our system against six memory systems on five benchmarks across three scenarios. In personalization, it outper-forms the strongest compared memory system by 16.3 percentage points in accuracy on PrefE-val and by 3.1 points in task completion on PERMA. For long-horizon tasks, it achieves the best overall performance on MemoryArena averaged over five environments with a gain that increases with the chain depth. In long-context understanding, it is on par with retrieval over the raw history while serving fewer con-text tokens. 

1 Introduction 

An LLM agent that serves the same user or works on the same task across sessions requires memory of what earlier sessions established, such as a pref-erence the user expressed weeks ago or the state of an unfinished task. Existing memory systems ex-tract facts or generate summaries from each session, then retrieve the memory most similar to an incom-ing request and insert it into the context (Chhikara et al., 2025; Rasmussen et al., 2025; Latimer et al., 2025). Some systems additionally reflect on the stored memory in the background to form higher-level notes or user profiles (Park et al., 2023; Zhong et al., 2024; Xu et al., 2025). Both the construction and the evaluation of these systems are oriented toward the past. Their evaluation measures fidelity (i.e., how completely the memory covers the con-versation and how often the retrieved memory con-tains the gold evidence) (Maharana et al., 2024; Wu et al., 2025; Liu et al., 2026). However, fidelity to the past does not by itself yield a better response. An agent needs the relevant context in its input to produce a good response. A memory system supplies this context through two decisions: what to memorize when a conversation ends and what to serve when a request arrives. Ex-isting systems assume that fidelity at each stage preserves the context needed for future responses. This assumption leaves two gaps: 1) The mem-orization gap arises because what is memorized determines what can later be served, yet faithful memory does not necessarily preserve what a future request will require. Existing systems keep sum-maries that omit details whose relevance appears later (Wu et al., 2025; Zou et al., 2026), or extract facts judged by coverage of the conversation, not by what a future request requires (Chhikara et al., 2025; Latimer et al., 2025); 2) The serving gap arises because memory is selected by how closely it matches the request, which may not reflect what the response requires. Both gaps arise because memory decisions must anticipate the context a response will need before their effects can be evaluated. We therefore view memory as a prediction problem. At write time, the system must predict which information will matter for future requests. At serving time, it must predict which memory the response needs. The request provides evidence about these needs but does not fully specify them. The accuracy of these predictions remains unknown until the response is generated. Both should therefore be evaluated against the observed outcome, which can then be used to refine future predictions. The value of mem-ory thus lies in the response it enables, which we call its utility. Figure 1 illustrates the difference between the two criteria on one request served from the same store. Selection by fidelity serves the memory that matches the request and nothing more. The response satisfies the request as stated, yet the user cannot use the hotel it books. Selec-tion by utility also serves the memory that the user uses a wheelchair, which the request does not men-tion. The response then books a hotel the user can use. The two selections differ by a single memory, which decides the outcome. We build on this view and present Leto , a mem-ory system that manages memory by its predicted utility. To address the memorization gap, Leto pre-serves access to conversation details through mem-ory indexing so that information remains available even when its utility is not apparent at write time. To address the serving gap, memory replay draws on this index ahead of the request to anticipate the context the agent needs beyond what the request states. This context is served together with the memory retrieved for the request. The response then provides evidence of the utility of what was served, and a utility loop feeds this evidence back to refine subsequent memory selection. We evaluate Leto against six memory systems on five benchmarks spanning three scenarios: per-sonalization, long-horizon tasks, and long-context understanding. Leto achieves the best overall per-formance among the compared memory systems in all three scenarios. In personalization, it out-performs the strongest compared memory system by 16.3 percentage points in accuracy on PrefEval and by 3.1 points in task completion on PERMA. For long-horizon tasks, it achieves the best over-all performance on MemoryArena averaged over five environments. Its gain over an agent with-out memory increases with the chain depth. For long-context understanding, it is competitive with retrieval over the raw history while serving fewer context tokens. 

2 Related Work 

External memory systems build memory of past interactions and serve parts of it to later ones. They extract facts or write summaries and reconcile them as interactions accumulate (Packer et al., 2023; Chhikara et al., 2025; Zhong et al., 2024). They or-ganize the store as temporal graphs or linked notes or associative indexes (Rasmussen et al., 2025; Xu et al., 2025; Gutiérrez et al., 2024). They add ed-itable memory blocks and reflection over the store 2alongside several retrieval mechanisms (Packer et al., 2023; Park et al., 2023; Latimer et al., 2025). They are also evaluated against the past. The write side is judged by how completely and accurately memory captures the conversation, the read side by how well it ranks memory against the request. The benchmarks measure memory the same way (Wu et al., 2025; Maharana et al., 2024; Liu et al., 2026). Several lines of work move one of the two de-cisions toward the future. On what to memo-rize, some index retained text by decontextualized claims or extracted entities (Choi et al., 2021; Chen et al., 2024; Gutiérrez et al., 2024; Wu et al., 2025). Others keep what a later decision is expected to need (Zou et al., 2026). On what to serve, some place standing memory in the context or revise memory between interactions before any request arrives (Packer et al., 2023; Zhong et al., 2024). Memory-R1 (Yan et al., 2026) learns memory oper-ations from downstream task reward. None carries on the memory itself an estimate of its utility that feedback updates. Leto moves both decisions to-ward the future and maintains such an estimate for every memory. Whether memory helps is a question about outcomes. PrefEval (Zhao et al., 2025) and PERMA measure whether an earlier preference is followed and a personalized task completed. Mem-oryArena (He et al., 2026) measures progress on interdependent tasks. LoCoMo and LongMemEval measure answers to questions over long histories. Each reports a system’s level. The utility of its memory is the level’s difference from the same agent without memory on the same items, which can be negative and which no level shows. 

3 Problem Formulation 

An external memory system supports an agent across timestamped sessions by deciding what to memorize and what to serve. At write time , it de-cides what to memorize when a session ends. At 

serving time , it selects memory M from the store to place in the agent’s context when a request x ar-rives. The fidelity view judges the write decision by how completely and accurately the store represents past sessions, and judges the serving decision by how closely the served memory matches x. Both criteria can be assessed using information available at decision time, but neither establishes whether the context needed for the right response is sup-plied. The memorization gap consists of required information from past sessions that the store no longer holds. The serving gap consists of required information that the store holds but that the served memory omits. We instead define the objective by task outcomes. Let y(x, M ) ∈ { 0, 1} denote the graded task out-come for request x when memory M is supplied to the agent. We define the utility of the served memory as 

U (x, M ) = y(x, M ) − y(x, ∅), (1) where y(x, ∅) is the outcome without memory. This objective captures whether the served memory improves or hurts task performance, or leaves it unchanged. It connects both memory decisions to task performance. The write decision determines what information remains available, and the serv-ing decision determines what reaches the agent. Utility depends on both the request and how the agent uses the served memory. Relevant informa-tion may provide no benefit if it is redundant or unused, and may hurt performance if it misleads the agent. The system must therefore anticipate what the served memory contributes to the response when deciding what to serve. Future requests are unknown at write time, so memory utility must be forecast across them. During subsequent interac-tions, feedback provides proxy signals of memory utility that update the utility index for the serving decisions that follow. 

4 Methodology 

Leto manages memory through three mechanisms, memory indexing and memory replay followed by the utility loop. Figure 2 summarizes this workflow. 

4.1 Memory Indexing 

Because future requests are unknown at write time, a memory system may retain information that is never needed or discard information that is. The costs of these two errors are asymmetric. Unhelpful information costs storage, while a discarded detail degrades the performance on every later request that depends on it. Leto therefore retains every conversation and indexes it to find what a request needs.

Existing memory systems commonly serve the extracted facts them-selves as the memory. Leto instead uses each fact as a key whose value is its source, the span of adja-cent messages that the fact was extracted from. A source reaches the agent only when a fact match-ing the request points to it, so the context carries less noise than retrieval over raw chunks. Informa-tion omitted from a fact also remains accessible through its source, which preserves the original wording and qualifications. New facts are consoli-dated with the existing ones. A fact that revises an earlier one supersedes it without deleting it. The in-dex can thus distinguish what currently holds from what once held. Each session also receives a short summary. 

Serving time. When a request arrives, Leto re-trieves the relevant facts with their sources. The utility loop (Section 4.3) then decides which are served within a token budget, alongside the stand-ing context from memory replay (Section 4.2). 

4.2 Memory Replay 

Retrieval can miss relevant preferences and con-straints that a request leaves unstated. Leto there-fore replays stored memory between conversations. It re-reads what the store holds and composes the standing context that the next conversation starts with. The standing context consists of a user pro-file and a task state if a task is declared. Both are composed before any request arrives. 

Profile rewrite. Profile rewrite maintains a user profile that carries what holds for the user regard-less of the request, such as standing preferences and constraints or instructions on how to act. After new sessions are indexed, Leto rewrites the pro-file from the current facts about the user and the session summaries. The rewrite keeps the profile concise by merging related facts into one statement and leaving out superseded preferences. 

Task rendering. A later step of a long-horizon task depends on what earlier sessions established, which the request rarely restates. Task rendering supplies it as a task state at the start of every con-versation on the task. The first part of the task state shows where the task stands through its current facts, grouped by entity with each attribute and its current value. The second part shows how the task got there through summaries of its prior sessions in order. 

4.3 Utility Loop 

Whether a memory will improve a response cannot be observed at write time. Leto therefore forecasts a utility index u(m) ∈ [0 , 1] for each memory and revises it with the outcome observed each time the memory is served. This cycle forms the utility loop. 

Utility forecast. Each new memory receives an initial utility forecast u0(m) as its utility index. A low forecast does not delete the memory. The fact and its source remain in the store. Retention and serving are separate decisions, which allows serv-ing priorities to change as feedback accumulates. 

Outcome observations. The forecast is made before a memory is used, and whether the mem-4ory helps becomes evident only after it is served. 

Leto therefore observes the outcome of each served memory to obtain evidence of its utility. We use the interaction signals from Chen et al. (2026) as the observations, which are detected in the conversa-tion by lexical rules. Each signal marks a positive outcome (e.g., a confirmation or a use of the mem-ory) or a negative outcome (e.g., a correction) for a memory, encoded as 1 and 0, respectively. When a graded task outcome is available, it can also be recorded for the memory served during the task. These signals provide evidence of memory utility without directly measuring an individual memory’s contribution to the outcome.

The utility index is a heuristic serving priority, not an estimate of Equation 1. It combines observable signals to guide memory selection, while paired evaluation measures whether the system as a whole improves task outcomes. 

5 Experiments 

We evaluate Leto across three scenarios: person-alization, long-horizon tasks, and long-context un-derstanding. These scenarios differ in what infor-mation is needed from earlier interactions and how explicitly the current request identifies it. 

5.1 Experimental Setup Benchmarks. We use five benchmarks grouped into three scenarios: PERMA (Liu et al., 2026) and PrefEval (Zhao et al., 2025) for personalization ;MemoryArena (He et al., 2026) for long-horizon tasks ; and LoCoMo (Maharana et al., 2024) and LongMemEval S (Wu et al., 2025) for long-context understanding . Table 4 in Appendix A summarizes the sample counts and evaluation metrics as well as each memory store’s scope. 

Compared methods. We compare Leto with six memory systems: Mem0 (Chhikara et al., 2025), LangMem 1, Hindsight (Latimer et al., 2025), 

Letta (Packer et al., 2023), Zep (Rasmussen et al., 2025), and Memobase 2. Each system uses the con-figuration provided by the benchmark when avail-able and follows its own documented setup other-wise. We also include a RAG baseline that retains the complete history and retrieves raw conversa-tion chunks by embedding similarity to the current request (Lewis et al., 2020). We establish two further baselines: No Mem-ory supplies no memory from earlier sessions, and 

Standalone is the benchmark’s own agent given the complete history in its context. Appendix B reports the share of units each system improves and degrades against No Memory .

5.2 Scenario 1: Personalization 

Personalization requires an agent to apply informa-tion from earlier interactions even when the cur-rent request leaves it unstated. PrefEval focuses on preference following, while PERMA evaluates personalization across a user’s interaction history.

5.3 Scenario 2: Long-Horizon Tasks 

Long-horizon tasks require an agent to carry infor-mation from earlier interactions into later decisions. MemoryArena evaluates this ability through inter-dependent subtasks across shopping, travel, search, math, and physics. 

Main results. Table 2 reports progress score (PS) and success rate (SR), averaged equally across the five environments. PS measures progress within a task chain, while SR measures the proportion of completed chains. Leto achieves the highest overall PS (32.01%) and SR (18.33%) among all compared methods. It is also the only memory system whose useful rate exceeds its harmful rate in every environment (Appendix B). 

Effect of chain depth. Figure 4 shows how the gain over the No Memory baseline varies with chain position in shopping and search. Every shopping chain has six purchases, while search chains run longer. Leto ’s gain grows with position in both. In shopping it rises from 1.3 percentage points at the first purchase to 7.3 points at the sixth. In search it rises from zero at the first question to approximately 14 points at the eighth, where every other system is below 10 points and most remain close to zero. A later step depends on what earlier rounds established. Leto serves it as the task state in every later round, so its contribution grows as the chain proceeds. Letta holds the larger gain in shopping, where a later purchase depends on only a few earlier ones. In search Letta reaches 7.2 points at the eighth question, half of Leto ’s gain.

6 Conclusion 

The value of agent memory lies in the responses it enables, and fidelity to past conversations does not ensure that value. We viewed memory as a prediction problem and presented Leto , a memory system that decides what to memorize and what to serve by the utility of memory to future responses. 

Leto leads the compared memory systems in three scenarios that place different demands on memory, which suggests that utility is a general criterion for memory design. We hope this view moves memory systems from how faithfully they record the past toward how much they improve what the agent does next. As future work, we will learn utility forecasts from feedback so that memory systems better anticipate the needs of future interactions. We will also study how to attribute an outcome to an individual memory and how utility transfers across agents. 8Limitations 

Leto trades storage and write-time computation for the ability to recover what extraction did not predict would matter. Keeping every conversation beneath the fact index removes the loss of discarded de-tail, but it does not make every detail reachable: a message that no fact points to is served only when another fact’s source contains it. Extraction cov-erage therefore remains the bound on how far the memorization gap can be closed. Serving standing information before the request bridges the serving gap where a request leaves a standing constraint unstated, at the cost of context that a given request may not need. The profile and task state are gen-erated summaries that can misstate what the con-versations established. The utility index is updated from outcomes, but an outcome is shared by ev-ery memory served for that response. The signal is therefore coarse: an unnecessary memory can be rewarded and a correct one penalized. A mem-ory that is never served never earns an observation. More generally, utility is a property of the memory system together with the agent it serves. The same served memory can help one agent and not another, so what Leto learns about a memory’s utility is spe-cific to the agent and the tasks it was observed on. Finally, the approach addresses what to memorize and what to serve but not how the agent uses what it is served; an agent can still overlook useful served memory (Liu et al., 2024).

B Useful and Harmful Rates 

The difference between a system’s level and No Memory ’s on a benchmark is the balance of two outcomes on the same graded units. A unit that passes with memory and fails under No Memory 

has positive utility in Equation 1 and counts as use-ful ; the reverse is harmful ; a unit with the same result in both runs is unchanged. The useful rate minus the harmful rate is the difference in level. Table 5 gives the useful rate and Table 6 the harm-ful rate on every benchmark. These are paired observed outcomes, not attribution to an individual memory. No Memory passes few units on PrefE-val and on LoCoMo and LongMemEval, so every system’s harmful rate there is small and the useful rate alone orders the systems. Leto ’s useful rate ex-ceeds its harmful rate on every evaluated outcome. Among settings with enough No Memory successes to assess degradation, Leto has the lowest harmful rate among the memory systems on PERMA MCQ and C-M completion and on MemoryArena shop-ping and math. On PERMA MCQ, Standalone ’s harmful rate is approximately twice Leto ’s. 

C Long-Context Results by Category 

Tables 7 and 8 give the long-context results by question category. LoCoMo covers single-hop and multi-hop as well as temporal and open-domain questions; its adversarial category of questions with no answer in the conversation is excluded as in 

Mem0 ’s evaluation (Chhikara et al., 2025). The LoCoMo difference from RAG is concentrated in single-hop questions, where RAG reaches 82.05% against Leto ’s 76.69%. The largest LongMemEval advantage over Hindsight is in temporal reasoning, where Leto achieves 73.68% against 62.41%.
