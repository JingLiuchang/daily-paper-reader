## 摘要
在本技术报告中，我们介绍 Taxi——一个用于大规模调试、聚类和监控智能体的系统。Taxi 能够高效扩展到数百万个步骤，这得益于多种可扩展分析方法的结合。Taxi 主要依赖聚类来生成对步骤的分类体系，从而提供数据的结构化概览，并为工程师和自动化智能体提供完整的 SQL 访问能力，以提出复杂问题。聚类和查询最好在由编码智能体引导的混合流水线中结合使用。Taxi 还包括对 Jev 风格决策模型的实验性集成：这些模型将状态和有界问题直接映射为类型化的概率决策。当仅靠嵌入或字面查询不足时，它们可增加低成本的语义路由与评估。此外，Taxi 提供可扩展的生态系统，包括内置评估器和每日报告。为适应增长，Taxi 被设计为模块化、可修改且易于个人和团队即插即用。

## Abstract
In this technical report, we present Taxi -- a system for debugging, clustering, and monitoring agents at scale. Taxi scales to millions of steps efficiently. This is made possible by a combination of scalable analysis methods. Taxi relies primarily on clustering to generate a taxonomy over steps for a structured overview of the data, and provides full SQL access for engineers and automated agents to ask complex questions. Clustering and querying are best used together in a hybrid pipeline guided by a coding agent. Taxi also includes an experimental integration of Jev-style decision models: models that map state and bounded questions directly to typed, probabilistic decisions. They add low-cost semantic routing and evaluation where embeddings or literal queries alone are insufficient. In addition, Taxi provides an extensible ecosystem, including built-in evaluators and daily reports. To accommodate growth, Taxi is designed to be modular, hackable, and easy to plug-and-play for individuals and teams.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：现代智能体（agent）可持续运行数小时甚至数天，串联规划、工具调用与错误恢复，每次运行都留下远超“成功/失败”标签的丰富轨迹记录（trajectory）。
- **核心痛点**：智能体运行中存在大量“昂贵却隐蔽”的问题类别：
  - 从不报错的行为性 bug；
  - 智能体悄悄超出用户给定任务范围；
  - 同一多余步骤在成千上万次独立运行中反复出现；
  - 意外的工具返回结果等。
- **现有方案不足**：当前轨迹日志（trajectory logging）已是常规做法，但真正可观测性还需两件事：(a) 跨语料的行为结构化概览；(b) 允许用户对行为提出任意复杂问题。现有产品（Laminar、Docent、LangSmith Engine 等）以及用 LLM 归纳分类体系的研究流水线，都依赖语言模型逐条读取每条轨迹（或为控制成本只抽样），在生产规模下受成本、速率限制、延迟与覆盖率制约。
- **论文主张**：需要一个把**可扩展性作为一等公民**的系统，即使在生产级负载与有限资源下也不失效，同时提供对智能体行为的细粒度可见性。Taxi 即为此设计。

## 2. 方法论

### 2.1 核心思想
Taxi 是一个用于大规模调试、聚类、监控智能体的系统，其核心是**以可查询的关系型数据库为统一骨干**，在其上组合多种可扩展分析路径，并通过编码智能体（coding agent）引导的混合流水线协同工作。分析路径有三条（前两条为已确立核心，第三条为实验性）：

1. **嵌入 + 聚类**：对步骤嵌入向量做聚类，无需 LLM 调用即可生成结构化概览，可扩展到全语料每个步骤。
2. **SQL 查询与文本正则性**：大量智能体行为（工具名、错误串、参数形态）可作为纯文本被检索，SQL 与模式匹配无需 AI 即可回答大量问题（作者称之为“文本的正则性”）。
3. **Jev 式决策模型**（实验性）：将状态与有界问题直接映射为类型化、概率化决策（如选择、是/否），不生成解释文本，单次决策成本远低于通用生成模型，使语义判断可在更大范围应用。

### 2.2 三层架构
- **数据层（数据库骨干）**：轨迹（trajectory）被切分为有序步骤（step：消息、工具调用、观察），每步计算文本嵌入。数据源（data source）为团队共享语料，支持 LangSmith、Hugging Face、JSON 导出等 loader，统一 schema；可同步（sync），每次同步递增单调数据版本（data version）。项目（project）是个人视图，可自定义过滤，核心产物是**分类体系（taxonomy）**——步骤聚类的层级树，每个聚类有标签与描述，每步被分配到某聚类或留空未分配。分类体系版本化且发布后不可变，数据版本演化与分类体系演化正交解耦。
- **中间层（MCP 工具）**：几十个通过 MCP 暴露的原语工具，覆盖作用域（set_project / set_data_sources）、语料访问（execute_sql、get_tfidf_terms、sample_steps）、草稿分类体系（cluster_by_embedding、cluster_by_regex、cluster_by_jev、construct_by_jev、publish_taxonomy 等）、评估器（publish_eval、run_eval）、洞察（publish_insight、save_insight_report 等）。
- **顶层（Skills）**：短指令文档（如 taxi-agent、taxonomizer、taxi-eval、taxi-insights、slack-agent），告诉编码智能体在特定任务中该用哪些工具、按什么顺序、不要臆造什么。分析方法变化快于数据模型，因此新方法通常是新增 skill 或工具，而非重写存储或所有客户端。

### 2.3 分类体系构建（关键算法流程）
- **简单扁平聚类**：对嵌入做一次 k-means（如 k=14），再用 LLM 对每簇少量样本命名，原子发布；新步骤同步时按最近质心分配。虽简单但在生产案例中常有效，作为基线。
- **智能体式构建（taxonomizer skill）**：把每次聚类调用视为“待检验的提议”而非结果，循环为：
  1. **定向（Orient）**：SQL 看语料规模、数百个 TF-IDF 词项、原始样本；
  2. **提议（Propose）**：以匹配主题丰富度的粒度聚类（根层常见 8–30 簇），支持 parent_id 做局部聚类；
  3. **检验（Examine）**：读质心样本、边缘样本、多样样本、簇区分词项、cohesion 与 nearest_sim 指标；
  4. **修订（Revise）**：低内聚/边缘样本异质 → 拆分；高最近相似度/近重复 → 合并；主导簇过大 → 加深；空簇或覆盖近乎全部父簇的子簇 → 删除；
  5. **成组命名（Name as a set）**：先定成员再命名，读全部名称检查抽象层级一致、形式平行、对比清晰，优先行为性名称；
  6. **发布（Publish）**：原子提交为新版本，按树遍历分配所有步骤。
- **混合路由**：同一棵树中可混用三类路由机制，但同一层级的兄弟节点共享单一路由方式：
  - 嵌入簇：最近质心胜出，覆盖穷尽；
  - 正则簇：大小写不敏感的模式匹配动作文本，首个匹配兄弟胜出，覆盖可不穷尽；
  - Jev 簇：以标签+自然语言描述定义，决策模型在兄弟定义加“None of these”中做 Choice，置信度超阈值才命中。
- **实验性 Jev 构建（construct_by_jev）**：从语料中发现类别而非给定类别。严格分工——决策模型做所有决策（分配、是否变化），LLM 仅在决定变更后撰写类别。步骤按固定随机序分批流入，每批后决策模型回答“拟合？混合？重叠？未覆盖？”等是/否问题并给出概率，概率排序候选，每批只做前几个编辑；类别数不预设，由上下界（相对已见步骤份额）与决策自然涌现；层级尺寸稳定数批且最后一批未新建类别即收敛，随后对所有已读步骤重分配一次。

### 2.4 查询与作用域
- 查询前先定义作用域（scope/view）：项目（含过滤与最新分类体系）或一个/多个数据源（原始语料、无分类体系）。查询以只读 SQL 在作用域内执行，可访问 trajectories、steps，项目下还可访问 clusters 与 step-to-cluster 分配。执行通过 execute_sql 工具，限定 200 行、`SET TRANSACTION READ ONLY`。

### 2.5 生态系统
- **评估器（Evaluators）**：单份 YAML 定义，可含 scope、filter_sql、success_sql / failure_sql，或 Jev 式是/否语义判据（可 per trajectory 或 per step，可配 state SQL）。结果有 success / fail / skip / error 四种；error 与 fail 刻意区分（前者是检查本身的 bug）。failure_examples 在实时语料结果前做判别校验。可从提交日志/已关闭工单自动挖掘候选，把 bug 修复转为可观测签名。
- **洞察报告（Insight reports）**：周期性调查一个或多个数据源，YAML 定义、定时运行。三种模式：首次 bootstrap 跑上周数据；否则从上次报告覆盖的数据版本起；无新数据则立即给出 up-to-date 判定并停止。每次调查保存一份 Markdown 报告与摘要，按“会让称职审阅者多惊讶”排序，主题是智能体行为（策略、工具选择与顺序、指令遵循、浪费/重复动作、恢复、停止行为）。

## 3. 实验设计

### 3.1 主要评测场景：SastBench（附录 H）
- **数据集/场景**：SastBench 静态分析分诊基准，2,737 个静态分析发现。
- **智能体配置**：4 个智能体（Claude Sonnet 4.5、Gemini 3 Pro、Gemini 2.5 Pro、DeepSeek R1），使用同一 ReAct harness（读、grep、符号查找、漏洞模式工具，最多 20 步），判断每个发现是真阳性还是假阳性。89% 发现为假阳性。
- **规模**：10,515 次运行、87,140 个步骤，作为一个语料加载，每个智能体一个视图。
- **分析层次**（逐层展开）：
  - H.1 查询：按发现分组发现共享错误（574 个发现被四个智能体同时判错，独立错误期望约 120）；单一 PHP 仓库贡献 803 个发现、其中 265 个（46%）共享错误；工具失败画像区分各智能体；失败后的调整策略差异。
  - H.2 词汇：TF-IDF 各智能体相对其他三者的区分词项。
  - H.3 两种分类体系（两种透镜）：正则体系 29 叶（按工具→行为/参数目标/判决依据）；混合体系 36 叶（正则根+每根下 k-means，按代码主题）；按判决步骤主题分组比较准确率（前端 XSS/SRI 0.24、网络/TLS 0.27 等至第三方库 0.87、测试代码 0.88）。
  - H.4 状态机：将离散化运行读作状态机（8 行为与 29 行为两种粒度），展示各智能体特有转移；并做信息论验证（知道当前行为将下一步不确定性从约 4.2 bit 降至 3.3 bit，知道前一步最多再降 0.02）。
  - H.5 决策模型问题：对 1,546 个“vulnerable”判决提问是否展示攻击者路径（有路径正确率 18%，无路径 9%）；对 1,200 个样本在两个时点提问中途立场（中途表态 90% 即为最终判决）。两次研究共约 6,300 次决策模型调用。
  - H.6 超越分类体系：任务对调查形态的影响大于模型（同发现不同模型相似度 0.58，同模型不同发现 0.29，无关运行 0.23）；分歧模型调查方式相似度仅差 0.022。
  - H.7 异常作为聚光灯：低概率运行、失败查找后的判决、触及步数上限的运行分析。
  - H.8 用决策模型构建新分类体系：对 11,760 个采样步骤评分（<5 分钟），对最高分 594 步构建 28 个类别、四大类族，统计各智能体每千步本地错误率；构建约 8 分钟。

## 6. 主要结论与发现

- **系统层面**：Taxi 可高效扩展到百万级步骤，核心贡献是**可扩展性贯穿每个设计决策**，同时不排除必要时使用更重的方法；模块化、可插拔的架构便于扩展（新分析方法通常是新增 skill/工具而非重写）。
- **SastBench 具体发现**：
  - 错误是**共享的而非各自 idiosyncratic**（574 个发现被四模型同时判错，远超独立错误期望）；
  - 单一 PHP 仓库贡献近半共享错误，提示基准标签可能有问题；
  - 各智能体有可辨识的**工具失败画像**与失败后调整策略；
  - 不同智能体有可辨识的**词汇风格**；
  - 某些主题（前端 XSS/SRI、网络/TLS）对所有智能体都难（准确率约 1/4），第三方/非生产代码几乎总能判对；
  - 离散化运行可读作**状态机**，各智能体有特有循环与转移；
  - 决策模型可低成本回答语义两极问题：展示攻击者路径的“vulnerable”判决正确率 18% vs 无路径 9%；中途表态 90% 即为最终判决；
  - **任务对调查形态的影响大于模型**；模型分歧主要源于判断而非调查过程；
  - 异常运行指向可修复的具体问题（如符号查找工具、步数上限）。
- **生产案例结论**：聚类（而非结果标签）能揭示单条轨迹看不出的系统性软失败（坏正则、范围违规、冗余查找、缺失依赖、过期凭证）。

## 7. 优点
