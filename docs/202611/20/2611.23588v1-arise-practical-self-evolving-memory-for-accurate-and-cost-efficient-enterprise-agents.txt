Abstract 

Enterprise LLM agents operate in dynamic en-vironments where foundation models evolve rapidly, workflows update frequently, and de-ployments need to satisfy accuracy and cost requirements. We propose ARISE ( Agent 

Refinement through Iterative Self-Evaluation), a practical memory architecture in which the agent’s memory evolves from its own fail-ures without updating model weights, tools, or workflow logic. ARISE uses the model itself or a teacher model to attribute the failures and propose corrections. Then, ARISE keeps the corrections as retrievable micro memory, con-solidates them into macro rules, and accepts a rule update only if held-out accuracy rises. Across 14 enterprise-workflow domains from SOP-Bench and τ 2-bench using 5 models, ARISE-Teacher, which uses Claude Opus 4.6 for attribution and consolidation, gains 10.9 pp over the baseline on SOP-Bench and 5.8 pp on 

τ 2-bench. ARISE-Teacher also outperforms GEPA by 4.5 pp on τ 2-bench and 1.4 pp on SOP-Bench. With the deployment model as its own attributor, ARISE-Self still gains 10.0 pp on SOP-Bench. 1 Introduction 

Enterprise agents run on rapidly evolving LLMs, with new state-of-the-art models appearing monthly. Standard operating procedures (SOPs) and policies change, requiring corresponding updates to agents. Model and workflow changes occur independently, requiring teams to revalidate agents rather than rely on a one-time prompt up-date. Rebuilding agents for these changes requires development and maintenance effort. Each task has a cost budget, so longer prompts incur cost on every request. Existing methods improve agents from experience through reflection (Shinn et al., 2023), insight extraction (Zhao et al., 2024), or prompt and context evolution (Agrawal et al., 2026; Zhang et al., 2026). Model training (Sri-vastava et al., 2025) additionally requires access to model weights. Many enterprise workflows expose verifiable post-task outcomes, such as whether a customer request reaches its intended system state or an SOP execution returns the correct decision. ARISE is a practical memory architecture that self-evolves while model weights, tools, and work-flow logic remain fixed (Figure 2). The offline loop uses task traces, agent outputs, and post-task feedback to diagnose failures. It collects failed training tasks with their expected outputs or diag-nostic feedback, asks an attributor to write scoped corrections, stores them as micro memory, and consolidates them into at most K macro rules. A held-out validation gate accepts a rule update only when accuracy improves. At inference, the agent receives the macro rules and the most simi-lar corrections. A stronger LLM can serve as the teacher, while the deployment model can perform attribution and consolidation itself; the latter set-ting gains 10.0 pp on SOP-Bench. Our contributions are threefold. 2 Related Work 

Agent memory and procedural knowledge. 

Agent memory systems preserve information across interactions so later decisions can reuse past context. The Generative Agents architecture (Park et al., 2023) stores observations, reflections and plans in a memory stream. MemGPT (Packer et al., 2023) manages memory across context and external storage. Mem0 (Chhikara et al., 2025) and A-MEM (Xu et al., 2025) organize long-term memories for later retrieval. Voyager (Wang et al., 2024) accumulates executable skills from interac-tion, while MemoryBank (Zhong et al., 2024) pre-serves long-term user experiences. Beyond persis-tent storage, procedural memory extracts reusable guidance about how an agent should act from prior trajectories. Reflexion (Shinn et al., 2023), eval-uated in our experiments, turns feedback from failed episodes into verbal reflections reused in later trials. ExpeL (Zhao et al., 2024) extracts reusable insights from collected experiences and applies them to future tasks. RICP (Sun et al., 2024) derives principles from past mistakes, while AutoGuide (Fu et al., 2024) generates context-aware guidelines and AWM (Wang et al., 2025) in-duces reusable workflows. Recent systems include Memp (Fang et al., 2026) for fine-grained and script-like procedures, ReasoningBank (Ouyang et al., 2026) for strategies from successful and failed experiences, ReMe (Cao et al., 2026) for adaptive reuse and refinement, and MNL (Su et al., 2026) for performance-gated failure mem-ory. ARISE focuses on an operational combina-tion of retrievable corrections from individual fail-ures, a separately bounded rule set, and a valida-tion gate for rule updates while model weights, tools, and workflow logic remain fixed. 

Automated prompt engineering. Prompt engi-neering adapts an LLM by improving the instruc-tions or context supplied at inference. APE (Zhou et al., 2023) generates candidate instructions from demonstrations and selects them using task scores. OPRO (Yang et al., 2024) gives an LLM previous solutions and their scores, then itera-tively proposes new instructions. DSPy (Khat-tab et al., 2024) represents multi-stage LM work-flows as programs that can be compiled and optimized. MIPRO (Opsahl-Ong et al., 2024) jointly searches over instructions and demon-strations using Bayesian optimization. Af-ter training, if both stores are nonempty, the micro gate screens retrieval by comparing macro only ac-curacy on the full validation set with macro plus micro accuracy on a fixed subset. Because the scores use different task sets, the gate does not iso-late the effect of micro retrieval. Accuracy is the only acceptance criterion. 

3.5 Retrieval at Inference 

Macro rules are injected into every prompt. If the micro gate passed, the task input is embedded and up to k corrections whose cosine similarity ex-ceeds threshold θ form M(x) in Eq. 1. The in-jected context is bounded at K rules and k correc-tions.

4.4 Component Analysis and Cost Efficiency Serving cost. Cost includes model token charges but excludes embedding, storage and retrieval. ARISE adds about 1,340 characters of memory per SOP-Bench task. With ARISE-Teacher, agents nevertheless make 4.0% fewer model calls over the 14 domains and write 4.9% fewer output tokens on SOP-Bench and 6.4% fewer on τ , corresponding to a 5.2% reduction over the 14 domains. ARISE-Teacher’s per-task inference cost changes by −1.0% over the 14 domains (Table 2). Fewer calls and shorter outputs offset the added memory context, keeping same model inference cost near the baseline while improving average accuracy across both benchmarks and five models. 4.5 Case Studies 

Figure 7 shows one test case per memory level, be-fore and after adaptation. 

Case 1: micro memory. The SOP imputes miss-ing scores unless more than two are missing. The labels give Unable to Decide already for two. No macro rule covers this, and only training task 111 has two missing scores. Its correction is retrieved for all four test tasks with two missing scores, though each misses a different pair. These go from 0 to 4 correct, and all five baselines miss them. The nine tasks with one missing score also re-trieve it, and none is answered Unable to Decide .Three other runs learn a similar correction and get three or four right. 

Case 2: macro memory. The SOP concludes a case for an ineligible account but names no sta-tus. The labels use FAILED . On nine such test tasks, the five baselines answer 23 of 45 correctly, mostly erring with PENDING_ACTION . The consol-idated rule names the account states. With macro rules only, this run answers all nine, and the 15 ARISE-Teacher runs answer 130 of 135. Task 152 has a lifted suspension, and this run still esca-lates it correctly. 5 Guidance for Enterprise Deployment 

What drives the gains. Consolidated rules pro-vide most of the gain. Retrieved corrections add 0.7 pp and supply source material for rule learning. ARISE-Self retains a 10.0 pp gain, so the same model can attribute and consolidate. The teacher adds 0.9 pp on SOP-Bench and 3.2 pp on τ , which suggests more value in workflows that span con-versational turns and tools. 

Choosing the attributor. Self-attribution needs no extra model and keeps most of the SOP-Bench gain. A teacher helps most on multi-turn tasks. 

Validation behavior. The gate keeps the current rules by default and accepted no update in 32% of SOP-Bench training runs. Accepted rule sets hold 3.4 rules on average (Figure 7 shows one). The gate checks validation accuracy only; safety and policy checks remain separate. 

Choosing the deployment model. With ARISE-Teacher, Sonnet 4.6 achieves higher average accu-racy than the Opus 4.6 baseline on both bench-marks, at 33% and 39% lower inference cost per task, respectively (Table 10). Haiku 4.5 also exceeds the Sonnet 4.6 baseline on SOP-Bench. A cheaper model with memory can thus beat a stronger model without it. 

Maintenance. When a procedure or deployment model changes, an ARISE rerun rebuilds the mem-ories, and the tools and base prompt stay un-changed. For Haiku 4.5 on SOP-Bench, a rerun costs an estimated $6.76, against $21,052 for serv-ing 1M tasks. 

6 Conclusion 

ARISE is a practical memory architecture for ac-curate and cost-efficient enterprise agents. It turns failed tasks into scoped corrections and a compact set of macro rules, accepting rule updates only when they pass a held-out validation gate. ARISE-Teacher improves over the baseline by 10.9 pp on SOP-Bench and 5.8 pp on τ and reduces model calls by 4.0% on average. With ARISE-Teacher, Sonnet 4.6 beats the Opus 4.6 baseline on both benchmarks at 33% and 39% lower cost per task. Without a stronger model, ARISE-Self improves every model, including small and open-weight models, with an overall gain of 8.4 pp, within 1.4 pp of ARISE-Teacher. We hope ARISE helps enterprise agents adapt as their models and proce-dures evolve. 8Limitations 

To make ARISE easy to adapt to enterprise agents, we design it to update the injected context through two memory levels, with a compact set of macro rules that an operator can review before release. This design keeps the deployed model and its tools unchanged, so the same loop applies to closed-source models and to new model releases. Future work can explore richer memory structures, such as graph-based memory or more memory levels, and extend the loop to other parts of the agent har-ness, such as its tools, tool descriptions and work-flow logic. ARISE requires verifiable pass or fail outcomes, which are common in enterprise work-flows, and extending it to ambiguous tasks with-out clear outcomes is an important direction for future work. Average gains vary across domains, and some model and domain combinations regress relative to the baseline. Production use requires data governance and memory safety controls that we do not evaluate.
