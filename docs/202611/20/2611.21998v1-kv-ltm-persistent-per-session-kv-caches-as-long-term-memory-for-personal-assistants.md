## 摘要
个人助理会积累数月的对话，但当前的长期记忆栈在问题与其证据之间插入了推导或选择环节。在 LongMemEval 的系统级比较中，两个商用助理的得分远低于同一模型离线阅读历史记录的表现 [1]，这与写入和读取之间的内容损失相一致，但并不能单独证明该损失。我们提出 KV-LTM：一种记忆层级，在固定读取模型下存储每个会话的原始文本及其 KV 缓存，通过恢复已缓存会话并追加问题来作答。KV-LTM 与检索和索引互补，而非替代它们。文本是记录性记忆；缓存是无重计算的预填充加速器，并可优雅降级为文本。我们明确了设计：存储记录、由预算推导的保留策略、仅追加式读取路径，以及有界聚合。我们对其进行了分析式规模估计：在固定为 BF16 的全注意力（GQA）和潜缓存 MLA 配置下，每 token 状态占用约 31K–328K 字节（固定的 KDA+MLA 混合配置有所不同：约 8.1K 字节/token 加上固定的逐会话循环项），在声明的每天 30K token 场景下，每用户年约 0.34–3.6 TB，而原始文本约 49 MB；每次查询成本被建模为按情形条件化的传输、注意力、解码、聚合与计算。我们定义了一种评估协议，用于逻辑问答评估时无需持久缓存实现：逐会话预填充在相同模型/输入状态契约和理想算术下模拟有效的缓存复用，并设有命名实验组、受控基线和预注册的读取模型门槛；另一项独立的最小真实缓存重放测试数值等价性并测量成本轴，且不预设结果。KV-LTM 在声明的保留预算内，以存储换取避免的重新预填充计算和写入时保真度。

## Abstract
Personal assistants accumulate months of conversations, but today's long-term memory stacks put derivation or selection between a question and its evidence. In a system-level comparison on LongMemEval, two commercial assistants scored well below the same model reading the history offline [1], consistent with, but not isolating, content loss between write and read. We propose KV-LTM: a memory tier storing each session's raw text plus its KV cache under a fixed reader model, answering by restoring cached sessions and appending the question. KV-LTM is complementary to, not a replacement for, retrieval and indexing. Text is the memory of record; the cache is a recompute-free prefill accelerator, degrading gracefully to text. We specify the design: storage record, budget-derived retention, append-only read path, and bounded aggregation. We size it analytically: across pinned BF16 full-attention (GQA) and latent-cached MLA configurations, per-token state spans approximately 31K-328K bytes (the pinned KDA+MLA hybrid differs: approximately 8.1K bytes/token plus a fixed per-session recurrent term), giving approximately 0.34-3.6 TB per user-year at a declared 30K-token/day scenario, against approximately 49 MB of raw text; per-query cost is modelled as regime-conditional transfer, attention, decode, aggregation, and compute. We define an evaluation protocol needing no persistent-cache implementation for logical QA evaluation: per-session prefill emulates valid cache reuse under the same model/input-state contract and ideal arithmetic, with named arms, controlled baselines, and a preregistered reader-model gate; a separate minimal real-cache replay tests numerical equivalence and measures the cost axis, with outcomes not assumed. KV-LTM trades storage for avoided re-prefill compute and write-time fidelity, within a declared retention budget.

# KV-LTM 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：个人助理（PA）会积累数月对话（一次性说过的偏好、随口做的决定、临时给出的约束），用户事后追问“我们当时怎么定的 X”时，答案取决于系统是否仍能取回原始证据。
- **核心问题**：现有长期记忆（LTM）栈几乎都在“问题”和“证据”之间插入了**写入时推导**（提取事实、滚动摘要、时序图谱、分层摘要）或**读取时选择**（RAG/向量检索只把子集喂给读者），这两步都可能造成内容损失。
- **证据支撑（系统级、非机制隔离）**：
  - LongMemEval 97 题子集：GPT-4o 离线读全史 0.918，ChatGPT(GPT-4o) 0.577，Coze(GPT-4o) 0.330。
  - LoCoMo（Mem0 自评）：全上下文 J≈72.9，Mem0 66.9，最佳 RAG≈61。
  - 机制级证据：同一 retrieve–rerank–reason 流水线只换存储表示，逐字块比抽取工件在 LoCoMo cat1–3 高 15.9 分（43.9% vs 28.0%），LongMemEval-S 高 22.0 分（67.4% vs 45.4%）；约束探针中摘要 14.0% exact vs RAG 89.5%。
  - **反例警示**：Zep 自报 LongMemEval-S 71.2% vs 全上下文 60.2%，说明“全上下文更好”并非普适排序。
- **论文定位**：提出 L4 记忆层级 KV-LTM——按会话持久化“原始文本 + 固定读者模型下的原生 KV 状态”，读时恢复缓存并追加问题，从而**避免重复 prefill**，同时**不做写入时推导**。明确是检索/索引的补充而非替代。

## 2. 方法论

### 2.1 核心思想

- **文本是记录载体（memory of record）**：任何变体都保留原始会话文本。
- **KV 缓存是无重算的 prefill 加速器**：缓存不是唯一副本，被驱逐/失效/模型变更时可优雅降级为读文本。
- 两种互补角色：(a) 有界近期证据保真层（参考路径不需要检索索引）；(b) 作为已有检索系统的 verifier/reranker（对候选会话的缓存做全文核验与重排）。

### 2.2 精确性引理（§2.2，有边界）

- **陈述**：恢复某会话缓存并追加问题，在**理想算术**下与完整 prefill `(session ‖ question)` 数学等价。
- **成立条件**：同一完整 token 前缀（含固定指令）、同一模型权重、连续位置索引（缓存占 0..N−1，查询占 N..N+Q−1）、固定的 RoPE base/scaling/max-position、相同 attention mask、相同原生缓存状态。
- **边界**：事后量化/剪枝属另一变体；真实引擎核函数非确定，实际等价需容差回放验证；引理是**逐架构**的，不给出跨架构质量保证。

### 2.3 存储记录

- 字段：`state`（原生 KV/MLA latent + 混合层固定循环状态 + 运行时辅助状态，版本化格式）、`text`（原始文本）、`meta`（时间戳、会话 ID、模型/配置哈希）、`serialization`（角色、模板、tokenizer 版本等）、`text_digest` / `state_digest`（分离完整性哈希）。
- 原则：坏状态只能从**已验证完好**的源文本重建；源文本校验失败则恢复已知good副本或标记 unavailable，绝不静默信任损坏文本。

### 2.4 写路径

- 不变量：`state = prefill_reader(fixed_prefix ‖ serialize(text))`，在会话结束时做一次性规范 prefill（助手轮次也作为文本 token）。
- 仅在“读者即服务模型且序列化上下文完全一致”时才复用在线缓存；固定指令前缀跨会话共享（物理去重后只计一次）。

### 2.5 读路径（参考/穷举式）

1. 逐会话校验（契约 + 状态完整性）→ 恢复请求内工作副本；
2. 追加问题与查询指令（只从本会话作答、无据则弃答、带日期引用证据）；
3. 解码短的逐会话输出（“作答”与“证据”分列，弃答仍可保留部分证据）；
4. 源校验失败则恢复并复核，失败则记 unavailable 并继续；
5. 有界聚合；输出覆盖度报告（state-read n / text-fallback m / abstained a / unavailable u），无静默截断。
- 可选：查询后缀提示（检索派生的实体候选等）作为**未经验证的解释辅助**，不得当作会话内证据，重复出现不构成独立佐证。

### 2.6 聚合契约

- 输入：问题 + 带日期、可溯源证据 + 弃答标志。
- 显式界限：至多 S 条证据、每条 ≤ e token、输出 ≤ o token；溢出走预先声明的分阶段/树式聚合规则，跨实验组冻结。
- 策略：源与时效感知的有界综合；**明确否定多数投票等于真值裁决**（重复的陈旧事实不能靠频次压过有支撑的新事实）。
- 输出：带源链接的答案 | 弃答 | 追问（含回退原文）。

### 2.7 跨会话问题（joint tier）

- 逐会话读无法联合注意；由聚合器追问或问题类型触发，取 top-k_joint 会话**从文本重新 prefill** 做联合读，且须装得下读者上下文，否则弃答/追问。
- 明确说明：把独立缓存拼接是非精确的（丢失跨会话注意力，且破坏位置索引），因此联合路径走文本而非融合缓存。

### 2.8 保留、失效与回退

- 保留集 `R(N 月) ∪ L(M)`，容量不变量作用于去重并集（含状态与元数据开销），需同时满足字节与延迟预算。
- 穷举读下“最近加载”无意义，故“使用”定义为**证据使用**（被聚合器引用的支撑/部分证据，或 verifier 命中）；超预算时先缩老集合再缩近期窗口（“N 月”变为 achievable-N），溢出会话降为纯文本。
- 失效：模型/tokenizer/配置/固定前缀模板/序列化版本变更 → 后台从文本重 prefill（迁移成本计入）。
- 回退：驱逐≠删文本；RAG 回退会重新引入读取时选择暴露。

### 2.9 规模公式与解析结果

- GQA/MHA：`2 · L · H_kv · d_head · b`；MLA：`L · (d_c + d_R) · b`（假设运行时持久化压缩 latent，否则约 8.9×）；混合：`sessions × S_recurrent + tokens × b_MLA`。
- 结果（BF16）：MiniCPM3-4B 35,712；DeepSeek-V2-Lite 31,104；Qwen2.5-7B 57,344；Llama-3.1-8B 131,072；Llama-3.3-70B 327,680；DeepSeek-V3-class 70,272；Kimi-Linear b_MLA=8,064（+符号化 S_recurrent）。
- 年度存储（30K token/日）：约 0.34–3.6 TB/用户年，对应纯文本约 49 MB；8B-GQA 的 KV/文本比约 2.9×10⁴。
- 512 GB 预算下 achievable-N：8B-GQA≈4.3 月，V3-class≈8.0 月，MiniCPM3-4B≈16 月，V2-Lite≈18 月；混合模型公式化，S_recurrent≈21 MB 时约 2.5 年。
- 每查询成本：`T(q) ≈ 冷传输 + 查询注意力 + 解码 + 有界聚合 + 条件重建 + joint + prefilter + 残差模型计算 − 重叠`，并叠加一次性摄入 prefill 与模型变更迁移。
- 示例：300 会话×2000 token×131,072 B ≈ 79 GB 冷传输（5 GB/s→15.7 s）；解码 19,200 token，串行 30 tok/s→640 s，理想 300 路并行→2.1 s；整年 1.44 TB 的传输分量≈287 s。强调“解码与传输不独立”（密集注意力每生成一个 token 都要重读缓存状态）。
