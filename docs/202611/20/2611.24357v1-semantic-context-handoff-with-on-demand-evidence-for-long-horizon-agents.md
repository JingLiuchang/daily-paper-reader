## 摘要
传统长时程 LLM 智能体通常通过全历史提示进行上下文交接，保留此前所有动作—观察交互。随着执行推进，该历史不断增长，增加推理成本并可能降低准确性。现有方法通过保留紧凑结论、移除较早观察来控制这种增长，但这样做可能丢弃后续变得相关的证据。我们提出语义上下文交接（SCH），其核心抽象是状态—证据分离：紧凑的语义状态承载智能体当前的解释，而支撑性的动作—观察证据保持可单独寻址，并可在后续执行使其相关时重新进入上下文，无需单独摘要或检索模型调用。经验上，SCH 在显著降低上下文成本的同时提升了长时程智能体性能。在一项受控的 150 任务 SWE-bench 研究中，SCH 的证据恢复在 token 使用量和执行时间基本不变的情况下将 Pass@1 从 80.0% 提升至 86.9%。在完整系统比较中，SCH 达到 86.9% 的 Pass@1，同时相较按任务性能而言最强的基线使用少 43% 的 token、少 41% 的墙钟时间。跨模型和基准，SCH 相对全历史提示持续减少 token 使用，同时与所评估基线相比保持竞争力或有所提升。轨迹分析证实，SCH 是从交互历史中明显更早的部分恢复证据，而不仅仅是保留最近的上下文窗口。

## Abstract
Traditional long-horizon LLM agents often hand off context through full-history prompting, retaining all previous action--observation interactions. As execution proceeds, this history keeps growing, increasing inference cost and potentially degrading accuracy. Existing methods control this growth by preserving compact conclusions while removing earlier observations, but doing so can discard evidence that later becomes relevant. We introduce Semantic Context Handoff (SCH), whose central abstraction is state--evidence separation: a compact semantic state carries the agent's current interpretation, while supporting action--observation evidence remains separately addressable and can re-enter context when later execution makes it relevant, without separate summarization or retrieval-model calls.   Empirically, SCH improves long-horizon agent performance while substantially reducing context cost. In a controlled 150-task SWE-bench study, SCH's evidence recovery improves Pass@1 from $80.0\%$ to $86.9\%$ at essentially unchanged token use and execution time. In the complete-system comparison, SCH achieves 86.9% Pass@1 while using 43% fewer tokens and 41% less wall-clock time than the strongest baseline by task performance. Across models and benchmarks, SCH consistently reduces token use relative to full-history prompting while remaining competitive with or improving upon the evaluated baselines. Trajectory analysis confirms that SCH recovers evidence from substantially earlier parts of the interaction history rather than merely preserving a recent context window.

## 1. 核心问题与研究动机

### 1.1 背景
- 长时程（long-horizon）LLM 智能体需要与环境反复交互，并把每次「动作—观察」结果带入后续提示。
- **全历史提示（Full History）**保留了完整执行轨迹，但上下文随步数线性膨胀，推理成本急剧上升，且过长上下文会「淹没」当前相关信息（Lost in the Middle 问题）。
- **压缩/摘要式方法**（如 ReSum、ACON、PACT、CAT、MemPO）能控制增长，却引入新失效模式：**不可逆压缩**保留了结论却删除了形成结论的原始观察，当后续执行需要重新审视该结论时，证据已不可得。

### 1.2 关键洞察
- 历史证据的**有用性不由时间顺序决定**：例如软件工程智能体在第 6 步检查某文件形成根因假设，第 24 步验证失败时，第 6 步的原始观察突然变得关键。
- 因此存在**两条并存的保留需求**：
  1. 智能体的当前理解应保持紧凑、持续可见；
  2. 详细历史观察只需在后续执行使其重新相关时**可恢复（recoverable）**。
- 全历史提示同时满足两者但成本递增；不可逆压缩则以牺牲可恢复性为代价。

### 1.3 研究问题拆解
> 「哪些语义信息应持续可见？哪些历史证据应在重新相关时可被取回？」

## 2. 方法论：Semantic Context Handoff（SCH）

### 2.1 核心思想：状态—证据分离（State–Evidence Separation）
- 将「智能体对执行的可变解释」与「支撑该解释的、只追加的动作—观察证据」**拆分为两类持久对象**。
- 前者维护为紧凑**语义状态**；后者存入**证据档案**，可离开常规提示但保持可寻址（通过 provenance 链接）。
- 由**确定性控制器**（非 LLM 组件）完成状态协调、证据存储与证据选择，**无需额外的摘要模型或检索模型调用**。

### 2.2 三组件架构
| 组件 | 作用 |
|---|---|
| **语义状态 S_t** | 当前理解与工作状态（紧凑、可修订） |
| **证据档案 L_t** | 已执行动作—观察记录的只追加存储（不进常规提示） |
| **确定性控制器** | 更新状态、执行动作、选择回注证据 |

### 2.3 交接提示构造（公式流程）
每一步构造：

```
C_t = [ x, S_t, P_t, R_t ]
```
- `x`：任务/系统指令；
- `S_t`：当前语义状态；
- `P_t`：**待处理证据**（新产生、尚未被 LLM 确认的记录）；
- `R_t ⊆ L_t`：从证据档案中**恢复**的历史证据。

LLM 单次响应返回两个输出：**稀疏状态增量 Δ_t** + **下一步环境动作 a_t**。

### 2.4 语义状态的字段设计
四类信息：
1. **任务约束（constraints）**：预期稳定的需求与假设；
2. **事实（facts）与假设（hypotheses）**：前者为环境证实的信息，后者为可修订的暂定解释（标签仅组织状态，不保证语义真值）；
3. **工作项（work items）**：遵循 `open → blocked → completed` 生命周期，并支持**重开（reopen）**；
4. **任务阶段（phase）**：如信息收集、实施、验证。

**Provenance（溯源）机制**：
- `support`：状态条目直接引用的证据 ID；
- `lineage`：工作项生命周期中累积的证据 ID。
- 形式化：`support(z) ⊆ dom(L)`，即从提示中移除观察不破坏其可寻址性。

### 2.5 稀疏增量与确定性协调
- 不要求 LLM 每轮重写整个状态，仅提交 `{"delta": Δ_t, "command": a_t}`。
- 控制器计算：

```
S_{t+1} = V(S_t, Δ_t, L_t)
```
- `V` 为确定性协调函数：校验证据 ID 是否存在于 `L_t`、校验生命周期转移的结构合法性（如「完成编辑类工作」需有 edit/diff 证据，「完成验证类工作」需有 validation 证据）。
- 好处：减少冗余生成 token；防止未被修订的状态被意外改写；模型提议可被拒绝或部分恢复而不整体替换权威状态。

### 2.6 证据档案与「确认（Acknowledgement）」
- 环境执行 `a_t` 得到 `o_t` 后形成记录 `e_t = (t, a_t, o_t)`，追加进 `L_{t+1}`；**模型推理过程不存为执行证据**。
- 新记录暂留于 `P_t`；LLM 确认后（把持久含义并入状态，或判定无需持久可见）：
  - `e_i ∉ P_{t+1}`，但 `e_i ∈ L_{t+1}`。
- **关键语义：确认改变「可见性」而非「存储」**——证据离开常规提示 ≠ 证据被销毁。

### 2.7 修订感知的证据恢复（Revision-aware Recovery）
**两种修订触发信号**：
1. 控制器在新产生的环境证据中识别到**已知失败模式**，且当前存在可修订状态；
2. LLM 通过增量**显式修订**（撤回事实、重开已完成工作）。

触发后，**已完成工作的 provenance 也变为可回注**（而不仅是当前活跃状态的 provenance），使很早阶段的观察得以重返上下文。

**补充机制——确定性孤儿恢复（orphan recovery）**：
- 对无 provenance 链接的档案记录，当其**路径或检索词与当前状态重叠**时成为候选；
- 另加**近期记录**与**安全相关记录**作为兜底候选；
- 直接链接证据优先级最高。

**Algorithm 1 流程（文字版）**：
1. 收集当前相关状态条目的 support 与 lineage；
2. 从「识别到的失败证据」或「被接受的增量」检测修订；
3. 若触发修订，加入受影响**已完成工作**的 provenance；
4. 加入确定性孤儿、近期、安全相关候选；
5. 合并、排序，排除已在 `P_t` 中可见者；
6. 在配置预算内暴露最高优先级证据。

### 2.8 关键实现参数（SWE-bench 配置）
- 状态序列化上限 12,000 字符；历史回注上限 12,000 字符 + 12 条记录/轮；
- 候选配额：修订相关 6 / 近期 3 / 孤儿 4 / 安全 6；
- 防过度研究阈值：12 次源码检查动作后给出一次瞬时提示；
- 输出 16,384 token，每任务最多 100 次模型调用。

### 2.9 设计原则（与既有范式的对比）
| 范式 | 保留依据 |
|---|---|
| Full History | **存在性**（全部可见） |
| 滑动窗口 / 近期历史 | **时间近因** |
| **SCH** | **修订相关性**（默认携带语义结论，按需暴露证据） |
