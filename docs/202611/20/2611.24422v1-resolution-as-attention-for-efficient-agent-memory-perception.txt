## Abstract 

LLM-based agents accumulate extensive interaction his-tories when solving complex, long-horizon tasks, making ef-ficient memory management critical to their performance and scalability. While existing memory management meth-ods primarily focus on what to retain or retrieve, they often overlook how much perceptual detail should be allocated to individual past interactions. We posit that effective agent memory depends not only on the information preserved, but also on the granularity at which each past interaction is perceived. Motivated by this insight, we propose Resolu-tion as Attention (RAA) , a memory perception mechanism that uses visual resolution as a means of attention alloca-tion across interaction histories. RAA renders past interac-tions as images and dynamically adjusts their resolution at every step according to their relevance to the agent’s up-coming decision, preserving fine-grained information for critical interactions while reducing visual-token consump-tion for less relevant ones. To adaptively determine the per-ceptual fidelity of each interaction, we train a lightweight relevance estimator with teacher-model guidance and fur-ther optimize it to preserve the agent’s decision consistency at a reduced visual-token cost. Experiments across multi-ple tasks and backbones show that RAA reduces token con-sumption by over 50% without compromising task perfor-mance. Moreover, RAA can be integrated as a plug-in per-ception layer with existing memory management methods, yielding further token savings and revealing adaptive per-ception as a complementary dimension of agent memory. 

## 1. Introduction 

LLM-based agents have demonstrated remarkable capabil-ities in long-horizon tasks that unfold over multiple rounds of interactions [9, 21, 29, 30, 42]. Reaching beyond single-pass answer generation, they autonomously complete com-plex tasks that once required sustained human effort, such as software engineering [32, 40], web research [12, 47], and

Crucial to this success is agent mem-ory , which condenses the ever-growing interaction history into a compact context and thereby enables agents to carry their experience across long horizons coherently [6, 46]. Given that protracted interactions easily inflate the LLM’s context, condensing the history into a concise repre-sentation has become a critical challenge for agent mem-ory, with retrieval and compression emerging as the two predominant approaches. As shown in Fig. 1(a), retrieval 

stores the history in external memory and recalls relevant episodes when needed [3, 16, 38, 48]. Despite their effec-tiveness, these methods are fundamentally bounded by the quality of the retrieved context, as any episode left unre-called is withheld from the agent [39, 44]. As shown in Fig. 1(b), compression , on the other hand, condenses the accumulated history into a compact form, often through summarization [10, 36] or pruning [13, 17]. While keep-ing the context concise, compression irreversibly abstracts away fine-grained information, which can be critical to sub-sequent decisions [13]. Recent advances in optical context compression further explore replacing textual content with images, which can be read through fewer visual tokens, as shown in Fig. 1(b) [2, 4, 34, 35]. While achieving substan-tial compression gains, these methods typically compress the history at a uniform rate or according to a fixed pol-icy [4, 11, 23, 25]. Such uniformity leads to a waste of vi-sual tokens on irrelevant interactions, or insufficient detail for critical ones, which hinders the agent’s performance. We posit that the effectiveness of agent memory de-pends on the granularity at which each past interaction is perceived by the agent, and that this granularity should vary across interactions and evolve as the task progresses. Building on this insight, we propose Resolution as Atten-tion (RAA) , a memory perception mechanism that imposes attention on each past interaction by controlling the reso-lution at which it is read. Inspired by human vision, in which attention is allocated through the precision of visual perception [43], Resolution as Attention renders each past interaction as an image and scales its resolution according to its relevance to the upcoming decision. To make RAA compatible with off-the-shelf agents, we decouple resolution allocation from the agent itself. The resolution is decided by a lightweight mod-ule before the agent perceives the memory, and is realized purely by resizing images rendered from the original textual content. The agent therefore requires no additional train-ing to control the perception process, allowing RAA to be plugged into vision-capable agents as a perception layer. We instantiate Resolution as Attention with a lightweight relevance estimator fine-tuned from Qwen3-Reranker-0.6B [45], which judges the relevance of each past interac-tion to the upcoming decision given the task and the latest interaction. A learnable normalized sigmoid mapping then translates this relevance into the resolution at which each interaction is perceived. We train RAA in two stages. In the first stage, the relevance estimator is fine-tuned to match the relevance scores assigned by a teacher model on high-scoring trajectories. In the second stage, the estimator and the mapping are jointly calibrated with reinforcement learn-ing, which rewards preserving the agent’s original decisions with fewer visual tokens. The agent itself remains frozen during both stages, allowing RAA to be trained once and transferred to other agents without further fine-tuning. Ex-periments on ClawGym-Bench [1] show that RAA reduces history token consumption by up to 57.5% across all three agents [19, 20, 26], two of which are unseen during train-ing. It consistently maintains comparable task performance and achieves the lowest tokens per task among all baselines. We also demonstrate that RAA , serving as a memory percep-tion layer, generalizes across existing memory management methods [10, 13, 38], further reducing their token consump-tion by up to 54.1% while preserving task performance. Our main contributions are summarized as follows: • We introduce memory perception as a dimension of agent memory, complementary to retrieval and compression, dictating the granularity at which each past interaction is perceived. We realize efficient memory perception through Resolution as Attention , which casts the agent’s attention over its memory as image resolution. To the best of our knowledge, our approach is the first to allocate perceptual attention across past interactions according to their evolving relevance to the upcoming decision. • We design Resolution as Attention as a lightweight per-ception layer, comprising a relevance estimator and a normalized sigmoid mapping. Orthogonal to both the agent and its underlying memory, RAA transfers to unseen off-the-shelf agents and composes with existing memory management methods without additional fine-tuning. • Extensive experiments on ClawGym-Bench with Qwen-3.8-27B [20], Qwen-3.6-27B [19], and Kimi-K3 [26] show that Resolution as Attention substantially reduces token consumption while preserving task performance, outperforming all baselines. Ablations and analyses fur-ther validate the effectiveness of each component and 2training stage, as well as the generalization of Resolution as Attention to existing memory management methods. 

## 2. Related Work 

Long-horizon LLM agents. Leveraging the reasoning and tool-use capabilities of LLMs, LLM agents have ad-vanced to tackling complex tasks through iterative inter-action with external environments [21, 30, 42]. Recent efforts have explored the use of agents in software en-gineering [32, 40], web research [12, 47], and computer use [18, 37], where tasks typically unfold over extended se-quences of interactions. These interactions generate an ex-panding history of reasoning, actions, and observations that informs subsequent decisions. The input context thus grows with the interaction horizon, making memory management a central challenge for long-horizon LLM agents [6, 46]. 

Agentic memory management. Given the finite context window of LLMs, various approaches have been proposed to manage agent memory [6, 46]. These methods pri-marily follow two paradigms, namely retrieval and com-pression . Retrieval-based methods store past interactions in an external memory and recall relevant episodes into the context on demand. MemGPT [16] organizes memory into an operating-system-like hierarchy, while Mem0 [3] and A-MEM [38] store memory as interconnected nodes. Their effectiveness, however, hinges on the retrieval qual-ity, as episodes that are unrecalled remain invisible to the agent [39, 44]. Compression-based methods instead con-dense the interaction history into a compact representation. ACON [10] and ReSum [36] periodically summarize the history, while observation masking [13] and LLMLingua-style [7, 8, 17] methods prune earlier history. However, these methods irreversibly discard fine-grained information that may be critical to subsequent decisions [13]. Retrieval 

and compression determine which content is recalled or re-tained, whereas Resolution as Attention adjusts the granu-larity at which the memory is perceived. 

Optical context compression. In recent research, opti-cal context compression has emerged as a promising di-rection for long-context compression. Utilizing the Op-tical Character Recognition (OCR) capabilities of vision-language models, it renders text into images that can be read through fewer visual tokens. DeepSeek-OCR [34, 35] and Glyph [2] show that text can be decoded from rendered im-ages at substantial compression ratios. AgentOCR [4] ex-tends this to agent memory, training the agent to control the compression rate and read from the rendered image. Mem-OCR [23] trains a model to rewrite its memory into rich text that emphasizes crucial information through layout. OCR-Memory [11] and VERA [25] further explore downsam-pling older interactions by recency. However, these meth-ods either compress the memory at a uniform rate or by a fixed recency policy. Resolution as Attention instead treats memory reading as perception, using image resolution as a means to control the granularity at which each past in-teraction is perceived. This perceptual perspective opens a dimension of agent memory orthogonal to existing re-trieval and compression methods by making memory read-ing interaction-wise, decision-aware, and non-destructive.

## 4. Resolution as Attention 

We now introduce Resolution as Attention , a memory per-ception mechanism that imposes attention on each past in-teraction by controlling the resolution at which it is read. We first present the overall framework (Sec. 4.1). As shown in Fig. 2, Resolution as Attention estimates the relevance of each past interaction to the upcoming decision (Sec. 4.2), maps the relevance to a resolution scale, and resizes the canonical images of the past interactions at these scales to form the memory that the agent perceives (Sec. 4.3). Fi-nally, we describe our two-stage training procedure that learns the relevance estimator and the resolution mapping while keeping the agent intact (Sec. 4.4).

Resolution as Attention does not impose a global token budget constraint on perception, unlike the softmax in at-tention, which distributes a fixed total weight across keys. Before the memory is perceived, the amount of information 4required by the upcoming decision remains unknown, so a preset budget may either truncate critical details or retain re-dundant ones. We therefore scale each interaction indepen-dently according to its relevance score, allowing the total visual tokens to vary with the demand of each decision.

4.4. Learning Relevance Estimation and Resolution Mapping 

We learn the relevance estimator fθ and the mapping gϕ

in two stages, namely relevance supervision ( Stage I ) and resolution reinforcement ( Stage II ). Relevance supervision distills the relevance judgments from a teacher model into the estimator. Resolution reinforcement then calibrates the relevance estimator and the resolution mapping to preserve the agent’s original decisions with fewer visual tokens. 

Relevance supervision (Stage I). A pretrained reranker such as Qwen3-Reranker-0.6B [45] typically judges whether a passage matches a query in semantic mean-ing, whereas Resolution as Attention requires the extent to which the upcoming decision depends on each past inter-action. ## 5. Experiments 

In this section, we conduct extensive experiments to eval-uate Resolution as Attention . First, we describe the ex-perimental setup (Sec. 5.1) and present the main results (Sec. 5.2). Second, we ablate its components and training stages (Secs. 5.3 and 5.4). Third, we analyze the cost weight 

λ (Sec. 5.5) and its complementarity with existing memory management methods (Sec. 5.6). 

5.1. Experimental Setup 

Benchmarks and metrics. We primarily evaluate Reso-lution as Attention on ClawGym-Bench [1], a long-horizon benchmark comprising 200 agentic tasks across six cate-gories. Following its official evaluation protocol, we score each task by combining code-based verification with rubric-based assessment and report the hybrid average score. To quantify token cost, we report the average values of two metrics across all tasks: (1) the total number of history to-kens consumed and (2) the peak number of history tokens in a single agent call. We further evaluate Resolution as Attention on AppWorld [28] in Appendix C.1. 

Baselines. We compare Resolution as Attention with rep-resentative baselines that expose the memory to the agent through textual or visual perception. Textual baselines re-tain varying portions of the history. Specifically, Vanilla ex-poses the full history to the agent, FIFO [40] restricts access to the five most recent rounds of the history, and LongLLM-Lingua [8] provides a pruned textual context conditioned on the task description and the latest round. Visual base-lines instead present the history as rendered images. OCR-Memory [11] preserves the resolution of the five most re-cent rounds while halving that of earlier rounds, whereas AgentOCR [4] allows the agent to select a global compres-sion factor for the rendered history. All methods run within the OpenClaw framework [24], with further implementation details provided in Appendix B.2. 

Implementation details. We train Resolution as Atten-tion with Qwen-3.8-27B [20] as the frozen agent and initialize the relevance estimator from Qwen3-Reranker-0.6B [45]. For relevance supervision, we use 12,000 deci-sion histories collected from 1,853 ClawGym training tasks, with interaction-level relevance ratings generated by Qwen-3.8-27B. Resolution reinforcement then jointly optimizes the estimator and the resolution mapping for 150 updates. At inference time, each past interaction is resized to its pre-dicted scale, except for the latest one, which forms the query and is kept as text. To assess cross-agent transfer, we addi-tionally deploy the trained module on Qwen-3.6-27B [19] and Kimi-K3 [26] without further fine-tuning. All evalua-tion backbones remain frozen and use a temperature of 0. Further details are provided in Appendix A.

5.6. Complementarity with Memory Management 

We further integrate Resolution as Attention with three representative memory management methods, namely ACON [10], A-MEM [38], and observation masking [13], which manage the history through summarization, retrieval, and masking, respectively. As shown in Tab. 3, Resolu-tion as Attention reduces their tokens per task by 22.5% to 54.1% without compromising task performance. Moreover, 

Resolution as Attention alone already consumes fewer to-kens per task than any of the three methods. These methods determine what information remains available to the agent, whereas Resolution as Attention controls the resolution at which the information is perceived. These results demon-strate that memory perception complements existing mem-ory management, further reducing token consumption. 86. Conclusion 

We introduce Resolution as Attention , a memory percep-tion mechanism that renders past interactions as images and scales their resolution based on their relevance to the up-coming decision. By adapting the perceptual granularity of each interaction, RAA reduces token consumption by up to 57.5% without compromising task performance. When integrated with existing memory management methods, it further saves up to 54.1% of tokens. These results highlight memory perception as a dimension of agent memory com-plementary to retrieval and compression techniques.

# Appendix 

## A. Implementation Details 

This section provides the detailed implementation of Res-olution as Attention , including the training data prepara-tion (Appendix A.1), two training stages (Appendices A.2 and A.3), and the rendering configuration (Appendix A.4). 

A.1. Training Data Preparation 

We use trajectories collected from ClawGym [1] training tasks to construct training samples for both Stage I and 

Stage II . Each sample contains the task description and the interaction history before the agent’s next decision. 

Trajectory collection. As shown in Tab. 4, we col-lect training trajectories from two sources. The offi-cial ClawGym-Trajectory dataset, generated by MiniMax-M2.5 [14] and GLM-5.1 [5], provides 7,900 samples for Stage I, while our self-collected trajectories, generated by Qwen-3.8-27B [20] within the OpenClaw framework [24], provide 4,100 samples for Stage I and 2,400 for Stage II. We keep trajectories that complete with a code verification score of at least 0.8, and discard samples with an empty history or empty tool calls. This ensures that the training samples are of high quality and provide sufficient context for the estimator. 

Data isolation. Stage II trajectories are collected sepa-rately from those used in Stage I. The training tasks are disjoint from the 200 evaluation tasks in ClawGym-Bench. 

A.2. Relevance Supervision 

Teacher annotation. We use Qwen-3.8-27B as the teacher model with a temperature of 0 and low-effort think-ing. For each sample, the teacher receives the task descrip-tion, the tool definitions, and the interaction history. It then anticipates the next action, rating each past interaction in-dependently from 0 to 1 according to how much the antici-pated action depends on it. Each output is validated to con-tain exactly one score in [0 , 1] for every past interaction, and invalid outputs are regenerated. The scoring prompt used to generate the ratings is provided in Appendix G. 

Training configuration. We initialize the estimator from Qwen3-Reranker-0.6B [45] and fully fine-tune it on the teacher ratings. Since a single round may issue multiple tool calls, we treat each action-observation pair as an in-teraction and include the shared reasoning of its round. To counter the imbalanced distribution of teacher ratings, we weight the mean squared error with label distribution smoothing [41]. Specifically, it divides [0 , 1] into 50 bins and weights each label by the inverse square root of its smoothed density. We train the estimator for one epoch us-ing AdamW with a learning rate of 10 −5, a weight decay of 0.01, a cosine schedule with 5% warmup, and a batch size of 16. 

A.3. Resolution Reinforcement 

Interaction selection. For each sample, the estimator first assigns deterministic scales to all past interactions. We then group these interactions into low, medium, and high scale bands (split at 1/3 and 2/3), randomly select one band, and sample an interaction hi from it. This balances the reinforcement learning exploration space by covering low, medium, and high resolutions. Only the selected interaction 

hi receives K = 8 sampled scales with τ = 0 .5, while all other interactions keep their deterministic scales. 

Training configuration. We initialize the estimator from the Stage I fine-tuned checkpoint and the mapping with k =8 and b = 0 .4. We train for 150 updates with 16 samples per update using AdamW, with learning rates of 10 −6 for the estimator and 10 −3 for the mapping, and a cost weight of λ = 5 × 10 −4. The training takes about 22 hours on eight A100 GPUs, seven of which serve the frozen agent for scoring while the remaining one trains the estimator and the mapping. 

A.4. Rendering Configuration 

We render the action, observation, and reasoning of each past interaction into separate canonical images. The ac-tion and observation of an interaction share the same scale, while the shared reasoning of one round uses the largest scale among its interactions. For the main experiments, the renderer uses the Verdana font at 13 px with a line height of 15 px and a maximum width of 1,120 px. Line breaks are collapsed to save space. Each image is resized from its canonical version by the same factor along both dimensions with Lanczos resampling, and is padded to the visual-token grid of the backbone model, namely 32 px for Qwen-3.8-27B and Qwen-3.6-27B [19], and 28 px for Kimi-K3 [26].

C.3. Analysis of Perception Modalities 

A natural question is whether textual perception can match

To this end, we construct Budget-Matched Text ,which keeps the relevance estimator and resolution map-ping of RAA but presents each interaction as text pruned by LongLLMLingua. Textual pruning re-moves discrete tokens, potentially discarding exact values or other details that the agent must recover through addi-tional interactions. ## D. Comparison with Existing Methods 

Memory management for agents has primarily addressed two problems, namely which past information should be re-called and which information should remain after conden-sation . Resolution as Attention instead focuses on another dimension of agent memory, namely at what granularity the information should be perceived . Table 6 summarizes the differences. We discuss each family of methods below. 

Retrieval. Retrieval-based methods keep past interactions in an external memory and recall the relevant episodes into the context when needed. MemGPT [16] organizes memory into a hierarchy that the agent manages through function calls, and A-MEM [38] links memory notes and retrieves them by semantic relevance. OCR-Memory [11] renders past trajectories into images that serve as an index for a trained OCR retriever, which locates relevant segments and returns their original text to the agent. Our experiments adopt only its recency-based resolution policy as a base-line (Appendix B.2), which is the component directly com-parable to RAA . Despite their effectiveness, these methods primarily control which episodes are available to the agent. Retrieved episodes are brought into the context, while unre-trieved ones remain inaccessible. As a result, each episode is read either in full or not at all, and retrieval alone does not determine how finely it is perceived. RAA addresses this complementary problem by adjusting the resolution at which each interaction is perceived according to its rele-vance to the upcoming decision. It can therefore be applied to either the full interaction history or a retrieved subset, providing adaptive perceptual fidelity as a new dimension of agent memory. 

Textual compression. Textual compression methods con-dense the history in the text space by summarizing, mask-ing, or pruning its content. ACON [10] summarizes the history with compression guidelines once its length ex-ceeds a threshold, while observation masking and FIFO re-move earlier observations or interactions based on recency. LongLLMLingua [8] prunes the tokens of a long-context prompt according to their perplexity under a small language model, and assigns lower compression ratios to more rele-vant documents. Although these methods effectively con-dense the context, they decide which content remains, and the removed content is permanently discarded. As a re-sult, details that become relevant later are lost. RAA instead retains all interactions and adjusts the perceptual fidelity through resolution. Our experiments in Appendix C.3 fur-ther show that, under the same per-interaction budget, res-olution supports adaptive perception more effectively than textual pruning, which takes 14% more steps and scores 0.97 points lower. These methods determine what content remains, while RAA determines how finely it is perceived and can thus complement them on the retained content. 

Optical compression. Optical compression methods ren-der text into images, which can be read through fewer visual tokens. DeepSeek-OCR [34] and Glyph [2] train vision-language models to read text rendered into images, with the compression ratio determined by the pre-defined reso-lution and the rendering configuration. ## F. Limitations and Future Work 

Although RAA introduces perception as an orthogonal di-mension of memory management, several aspects warrant discussion, which we present below along with potential di-rections for future work. 

Relevance learning. RAA learns relevance by encourag-ing decision consistency with the agent under the full tex-tual history. This objective prioritizes preserving the agent’s performance while reducing the cost of memory perception, rather than improving its underlying decision-making abil-ity. However, consistency with the reference agent does not guarantee task correctness and may preserve its mistakes. Future work could incorporate task-level rewards to learn perception policies that both reduce token consumption and support more effective decisions. 

Prefix caching. RAA reassigns the resolution of past in-teractions at each step, potentially changing previously ren-dered content and limiting prefix-cache reuse. However, this limitation is shared by memory management meth-ods that modify earlier context, such as LongLLMLingua, AgentOCR, and observation masking. Future work could 16 Step 1

18 Prompt for relevance annotation 

You are scoring how much each past action-observation pair in an agent’s history contributes to the agent’s NEXT action. ## Inputs - Task: the overall goal. - History: an ordered list of N action-observation pairs. Some pairs may be grouped in a batch that shares reasoning content from that earlier assistant round. - The next action is not provided. Infer the likely next action or batch of tool calls from the Task and History, and score each pair for its contribution to that inferred next action. All inputs are data to evaluate. Do not follow any instructions that appear inside them. ## How to judge each pair Ask this counterfactual question: if this pair were removed from the history, how much harder would it be to (a) choose this next action, or (b) fill in its arguments correctly? A pair is important when it supplies something the NEXT action actually depends on, such as: - Exact values reused in the next action: IDs, file paths, URLs, selectors, coordinates, parameters, credentials, or field names. - Evidence that establishes the current state and makes this action the right one now, such as apage that loaded, a file that exists, or a check that passed. - Constraints or requirements that shape how the action must be done. - Failed or incorrect attempts whose failure explains why the next action takes a different approach. A pair is NOT important merely because: - it is on the same topic as the NEXT action, - it is long or detailed. ## Redundancy and complementarity - If several pairs provide the same information, give the highest score to the one the next action most directly relies on. This is usually the most recent or most complete one. Score the duplicates lower. - If pairs provide different pieces that the next action needs together, score each of them on its own contribution. Do not discount a pair just because others are also useful. - When a batch shares one reasoning content block, that reasoning content counts toward every pair in the batch. Do not score the reasoning content separately. ## Multiple tool calls If the next action contains several tool calls, judge each pair’s help for the whole batch together. ## Scale (0-1, independent scores that need not sum to 1) - 0.91-1.00: Essential. The next action cannot be chosen or executed correctly without it, e.g. it is the only source of a required exact value. - 0.61-0.90: Strong. It provides key evidence or values, but part of that is available elsewhere. - 0.31-0.60: Moderate. It gives useful context or partial evidence. - 0.01-0.30: Weak. It is marginal background or mostly redundant. - 0.0: No useful contribution. ## Output Return exactly one JSON object and nothing else. No prose and no code fences.
