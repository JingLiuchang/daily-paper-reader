ABSTRACT
Efficient benchmarking estimates a system’s full benchmark performance from a
small number of task executions. Standard approaches rely solely on the binary
correctness of executions from a collection of already-evaluated reference sys-
tems. An agentic system, however, produces a rich trace for each execution that
can reveal substantially more about its capabilities. Leveraging this information
requires useful trace representations. We propose representing a trace by extract-
ing a structured summary of it with an LLM and embedding the summary with
a standard text encoder. These representations preserve correctness- and task-
related signal while minimizing the presence of system identity-, model family-,
and harness-related signals that dominate raw trace embeddings. Given this rep-
resentation for each task execution from all reference systems, we construct low-
dimensional representations of the systems and predict a new system’s score from
its position among the reference systems. On SWE-bench Verified and Terminal-
Bench 2.0, augmenting an item-response model with this geometry-based predic-
tion reduces mean absolute error from 0.13 to 0.08 (Wilcoxon p < 10−4) and
from 0.14 to 0.12 (Wilcoxon p < 10−3), respectively, when provided a single
random executed task. Further, given access to the full set of reference systems,
our approach dominates baselines for any given number of executed tasks on both
benchmarks.

INTRODUCTION
Generative model use is increasingly agentic: systems plan, invoke tools, observe intermediate re-
sults, and iterate over long horizons to complete complex tasks (Yang et al., 2024; Wang et al.,
2025). As agentic capabilities increase, so does the range of settings in which a given system might
be deployed – and, with it, the number of benchmarks on which the system must be evaluated before
it can be trusted with consequential work (Kapoor et al., 2026). Agentic evaluation, however, is
expensive. Each task execution requires a properly sandboxed environment and routinely consumes
hundreds of thousands of tokens (Jimenez et al., 2024; Merrill et al., 2026). Full evaluation on a
benchmark can regularly exceed $2,000 (Kapoor et al., 2026). Given this cost, efficient evaluation
is necessary to improve the evaluation coverage of an agentic system.
Task-efficient evaluation methods address this problem by finding structure in item-level informa-
tion available from previously evaluated reference systems to mitigate the cost of evaluating a new
system. Some task-efficient evaluation methods require only the item-level scores from reference
systems (Maia Polo et al., 2024; Vivek et al., 2024; Kipnis et al., 2025; Bowyer et al., 2026). Others
leverage information in cached artifacts, such as natural language responses (Acharyya et al., 2024;
Helm et al., 2025) or residual streams (Duderstadt et al., 2023), to measure the similarity of sys-
tems on a set of tasks. Agentic workflows often produce artifacts when executing a task – file diffs,
tool calls, intermediate plans, and error messages – recorded together in an execution trace that can
be used to this effect. Existing methods for using cached artifacts rely on off-the-shelf embedding
functions that typically capture system or model idiosyncrasies (Sun et al., 2025) better than trace
functionality. Along these lines, we make two primary contributions:
1. trubric trace representations. We introduce trubric (trace rubric): a trace represen-
tation constructed by extracting a task-specific structured summary of a trace with an LLM and

RELATED WORK
Representing agentic traces.
The standard tools for embedding model artifacts are text encoders
trained on sentence-level semantic similarity (Reimers & Gurevych, 2019; Su et al., 2023; Nussbaum
& Duderstadt, 2025). Agentic traces, however, implicitly or explicitly encode system metadata that
may not be relevant for downstream tasks (Sun et al., 2025; Oderinwale, 2026) and are therefore
not necessarily encoded well by semantic embedding models. Instead, traces have primarily been
studied through taxonomies of failure modes and actions (Cemri et al., 2025; Shu et al., 2026) and
LLM judges (Zhuge et al., 2025; Mehtiyev & Assunc¸˜ao, 2026). Parallel work uses LLMs to adapt
outputs to be more naturally compared via their semantics (Ravfogel et al., 2024; Peng et al., 2024;
Benara et al., 2024). trubric applies this to agentic traces by embedding a task-specific structured
summary of each trace.
2


Efficient benchmarking.
Task-efficient benchmarking estimates a system’s full benchmark score
from a small number of executions. The dominant paradigm for efficient benchmarking centers
around item response theory (IRT) (Birnbaum, 1968), where a target system’s score is estimated
with m ≤M item-level scores by assigning a latent ability based on the relationship between a
task’s difficulty and discriminability (Maia Polo et al., 2024; Kipnis et al., 2025). Extensions of
IRT select informative or adaptive task subsets (Vivek et al., 2024; Truong et al., 2025). A comple-
mentary paradigm represents the systems themselves, either from their score profiles (Ruan et al.,
2024; Zhuang et al., 2025) or from the artifacts they produce while executing a task (Duderstadt
et al., 2023; Acharyya et al., 2024; Helm et al., 2025). For example, the Product Kernel Perspective
Space (PKPS) (Helm et al., 2026a) represents language models as Euclidean objects obtained via
multidimensional scaling of the distances between their embedded responses. Helm et al. (2026b)
regress benchmark scores on similar representations and prove that the estimate is task-efficient rel-
ative to the sample score. trubric enables extending geometry-based methods to agentic systems
by providing an effective trace encoding. We show that these two approaches – score-based IRT
and trace-based PKPS – can be combined to outperform either constituent for any given number of
executed tasks when the full set of reference systems is available.

EXPERIMENTS
We next introduce the datasets we use to evaluate the trace embeddings and the trace-based ge-
ometries for efficient evaluation, describe the trace embedding analysis and three different agent
evaluation protocols, and describe baselines. We then evaluate trubric-based estimators against
baselines across benchmarks, evaluation protocols, task budgets, and design choices.

1. SWE-bench Verified (Jimenez et al., 2024; OpenAI, 2024) consists of 500 human-validated

sions from 119 unique systems. We consider the 107 systems with complete public trace archives
and per-task outcomes. We downsampled to M = 100 tasks (Appendix C). We let yi be the official
resolve rate over all 500 tasks. The full list of systems and tasks is included in Appendix C.

Trace embedding evaluation.
To quantify what a trace representation encodes, we train balanced
linear classifiers to predict each of the five attributes of Section 3.1 for a held-out trace from its
embedding. Classifiers for the system-level attributes (iii)–(v) are evaluated on held-out tasks. Clas-
sifiers for (i) and (ii) are evaluated on held-out groups of systems. We evaluate trace representations
using the cached SWE-bench Verified traces and report balanced accuracy for each attribute. Higher
accuracy is preferred for attributes (i) and (ii). Near chance accuracy is preferred for attributes
(iii)–(v). Detailed descriptions of the classification tasks are provided in Appendix A.2.
Trace embedding baselines.
We compare trubric embeddings to two baseline representations:
raw trace, which uses g to embed the start and end of each trace, and generic, which follows the
two-stage construction of Section 3.1 with fixed field descriptions in place of a task-specific rubric.
Unless otherwise stated, both the generic and trubric representations use K = 6 fields, with
DeepSeek-V4-Flash (DeepSeek-AI, 2026) as both the rubric generator and summarizer. For the em-
bedding function g, we consider seven text encoders: text-embedding-3-small (Neelakan-
tan et al., 2022), nomic-embed-text-v1.5 (Nussbaum et al., 2025), bge-large-en-v1.5
(Xiao et al., 2024), gte-large (Li et al., 2023), e5-large-v2 (Wang et al., 2022),
all-mpnet-base-v2, and all-MiniLM-L6-v2 (Reimers & Gurevych, 2019). These en-
coders span open- and closed-source models, multiple architectures and training procedures, and
embedding dimension sizes. The prompts and fixed field descriptions are provided in Appendix A.3.

Efficient benchmarking baselines.
We compare trubric-based predictions against five base-
lines: the population mean (the mean benchmark score of the reference systems), the sample score
(the mean of the target’s m observed trace-level scores), raw trace (the PKPS pipeline applied to the
raw-trace embeddings), generic (the PKPS pipeline applied to the generic rubric embeddings), and
two-parameter IRT. We also consider the convex combination ˆyα = α ˆyIRT + (1 −α) ˆygeom, with
α ∈[0, 1] selected via cross-validation. We refer to the convex combination as IRT + trubric.
For trubric, raw trace, and generic, the regressor and its hyperparameters are selected per task
draw via cross-validation on the reference systems. Implementation details for all estimators, in-
cluding a technical description of IRT, are provided in Appendix B.
Task selection methods.
For each task budget m, we consider two methods for selecting the
target’s m executed tasks. Random selection draws the m tasks uniformly. Reported results average
over 50 randomly sampled task subsets. Adaptive selection chooses tasks greedily using the fitted
item-response model. In particular at each step, the task with the highest expected Fisher information
under the current ability posterior is executed and the posterior is updated (Appendix B).

Trace geometry supports task-efficient benchmark prediction.
Table 1 and Figure 3 show that
trubric-based geometry predicts full benchmark performance more accurately than the sample
score for small task budgets (m ≤10) and the population mean for all budgets. The trubric-
based geometry can also outperform IRT, which exploits the correctness patterns of reference sys-
tems, at small task budgets. On SWE-bench, the geometry produces a more accurate estimate from
1 through 10 random tasks (Figure 3). On Terminal-Bench, ˆygeom outperforms IRT at one task, but
ˆyIRT is more accurate from three tasks onward. We emphasize that the geometric methods only
require the target’s trace content, and not its correctness labels, which means that these methods
are applicable in settings where grading target tasks is infeasible (e.g., due to cost, lack of exper-
tise, etc.), provided scored reference systems are available. ˆygeom can be interpreted as a high-bias,
low-variance estimate of the full benchmark score.
Combining trace geometry with IRT is best.
The trace-based predictions and correctness-based
predictions exhibit different behavior as the task budget grows: trace-based predictions are informa-
tive with very few executions, while IRT improves substantially as the number of tasks increases.
Figure 3 shows that combining their predictions improves prediction across all evaluated budgets
and benchmarks. At m = 5 on SWE-bench, IRT + trubric achieves 0.063 MAE, compared
with 0.069 for geometry alone (Wilcoxon’s p < 10−4) and 0.088 for IRT (Wilcoxon’s p < 10−12).
On Terminal-Bench – where IRT is relatively stronger – the combination achieves 0.090, compared
with 0.107 for geometry (Wilcoxon’s p < 10−3) and 0.097 for IRT (Wilcoxon’s p < 10−2). These
results suggest a complementary predictive value of execution artifacts and correctness outcomes.
The broad pattern persists across the system-, family-, and harness-exclusion protocols in Figure 3,
although the size of the improvement varies.
Performance improves with larger reference sets.
The left panel of Figure 4 shows that increas-
ing the number of reference systems generally improves both IRT and geometry-based estimators.
At m = 5 random tasks on SWE-bench, expanding from n = 20 to n = 107 reduces geometry-only
MAE from 0.086 to 0.069 and IRT + trubric MAE from 0.081 to 0.063. The contribution of
geometry depends on reference availability: given a small number of reference systems and a large
task budget, IRT can outperform geometry-only methods. The medium budget (m = 20), small-
reference-set (n = 20) regime is the one setting where IRT outperforms the convex combination.

and can further improve evaluation efficiency.
Prediction is insensitive to the choice of text encoder.

based prediction on SWE-bench to the choice of text encoder in the right panel of Figure 4. The
effect is small (at most 0.008 MAE at any fixed setting) relative to the effect of the number of target
tasks or task selection (0.081 to 0.060 from 1 to 20 random tasks; 0.063 to 0.048 for random versus
adaptive selection at m = 5) and the number of reference systems (0.086 to 0.069 at m = 5).
The trace geometry reduces the cost of reaching a given prediction error.
Figure 5 translates
the error curves into the cost of evaluating a system. For this comparison, we assume a cost of
$2 per agent execution (Jimenez et al., 2024; Merrill et al., 2026; Kapoor et al., 2026) and assume

We also evaluate methods for comparing two systems head to head. For each pair of systems whose
true benchmark scores differ by at least 0.05, we exclude both systems from the references and ask
whether an estimator correctly identifies the better system from m random executions per system

from a single task per system, compared with 79% for IRT and 69% for the sample score. By five
tasks per system, all estimators exceed 90% and the score-based estimators are competitive or better.
On Terminal-Bench, IRT is the most accurate estimator at every tested budget. Trace information
is thus most valuable for head-to-head comparisons in the lowest budget regime, where executing a
single task per system ($4 for the pair) identifies the better system in nearly nine of ten pairs.

5
DISCUSSION
We introduced trubric, a trace representation constructed by extracting a task-specific structured
summary of a trace with an LLM and embedding the summary with a standard text encoder. Across
seven text encoders, trubric embeddings preserve information about the task and the correctness
of an execution while minimizing idiosyncratic information about the system, model family, and
harness that produced it.
We then proposed using trubric embeddings to induce representations of agentic systems for
task-efficient evaluation. The resulting geometry supports accurate benchmark score prediction from
as little as a single executed task and, combined with an item-response model, is never worse than
either constituent at any task budget when the full set of reference systems is available.
The combined estimator reduces the cost of reaching an MAE below 0.10 on SWE-bench Verified
from $10–$40 to $2 per system. These results are relatively robust to the major design choices: the
text encoder, the number of rubric fields, and the task selection method. Importantly, these results
support the claim that extracting more than binary correctness from cached executions can improve
the efficiency of agentic evaluation as the number of systems and benchmarks continues to grow –
providing a route toward improved evaluation coverage for a given system.
5.1
LIMITATIONS
We evaluated trubric along the five attributes relevant to efficient evaluation. We make no claims
about the usefulness of the representation for other tasks one might consider with traces, such as
change detection (Bridgeford & Helm, 2025), online monitoring (Helm et al., 2026c), early stop-
ping (Ruan et al., 2026; Wang et al., 2026), or steering (Rahn et al., 2024). We leave the study of
trubric-like representations for these tasks to future work.
As mentioned above, we did not attempt to optimize the rubric. The rubric size experiment of
Section 4.1 demonstrates that favorable small rubrics exist. Developing validated procedures for
selecting or learning rubric fields, such as parameterizing meta-instructions, is an open problem that
we expect to have a small to medium effect on accuracy. We also note that trubric’s fields can
be reconfigured to amplify or dampen arbitrary dimensions of variation in the input data.
In our analysis we only consider DeepSeek-V4-Flash (accessed via OpenRouter) as the rubric gen-
erator and trace summarizer. We had intended to add other frontier models as part of our ablation
9


study, but a provider’s API service banned our account and accused us of attempting to distill rea-
soning traces. We include this note as a warning: summarizing traces at the scale required for
trace-based evaluation can resemble distillation to automated enforcement systems and may result
in account bans. In any case, we leave the sensitivity analysis of the two roles to future work.
Finally, we only consider highly curated, paired settings where every reference system has executed
(nearly) every task of a single benchmark. We do not consider references with sparse or disjoint task
coverage, nor signal shared across benchmarks. The PKPS formulation we use throughout supports
both – Eq. (1) is defined for unpaired task sets – and we expect less curated, larger reference
collections to further reduce evaluation cost.

A.2
LINEAR CLASSIFICATION TASKS
For each combination of text encoder and trace representation, we assemble one embedding per trace
for the executions of the 107 SWE-bench Verified systems on a fixed panel of 20 tasks (2,129 traces;
a small number of executions are missing from the public archive). Rubric-based representations
are the concatenated per-field embeddings of Section 3.1; raw-trace representations embed head and
tail slices of the rendered log as two blocks. Each block is ℓ2-normalized and blocks are weighted
equally.
Probes are linear classifiers trained with class-balanced squared loss and a ridge penalty; the penalty
is selected along a closed-form regularization path using grouped cross-validation within the training
folds. Evaluation is five-fold grouped cross-validation with seeded, size-balanced group allocation:
for the system-level attributes (iii)–(v) the groups are tasks, so probes are evaluated on tasks unseen
during training, and for (i)–(ii) the groups are model families, so probes are evaluated on systems
from families unseen during training. We report balanced accuracy averaged over folds; chance
balanced accuracy for a C-class attribute is 1/C. Figure 1 plots (accuracy −chance)/(1−chance)
for attributes (i)–(ii) and its complement for (iii)–(v), so that better-for-evaluation is always outward.
Table 2 reports the balanced accuracies underlying Figure 1.

The raw-trace and generic-rubric estimators replace the trubric representation ϕ in the pipeline
