## 摘要
多向量检索将每个查询和文档表示为嵌入集合，并通过 MaxSim（Chamfer 相似度）等细粒度集合到集合交互来计算相关性。这种表达能力相比单向量表示提升了检索质量，但也使搜索代价显著增加。现有系统主要通过代理表示或将候选生成简化为单向量搜索的过滤-重排流水线来应对这一挑战。我们研究了一个互补方向：直接在多向量数据上构建原生 IVF 风格索引。我们提出 MV-IVF，一种用于多向量检索的倒排文件索引，它构建于 MV-Lloyd 之上；MV-Lloyd 是一种新的 Lloyd 风格算法，用于在 Chamfer 目标下对点云进行聚类。我们的关键观察是：一旦点云被分配到簇，中心更新步骤就简化为对每个簇中展平后的嵌入进行标准单向量聚类。这使得能够高效构建分层 IVF 树，并在内部节点处使用中心点云。在查询时，MV-IVF 在树上执行最佳优先束搜索以识别有希望的叶簇，然后对这些叶簇中的文档进行评分。我们进一步使用低位量化、查询压缩和缓存高效的批量搜索来加速搜索。我们在 MVSIC 中实现了 MV-IVF；MVSIC 是一个优化的 C++ 库和统一的多向量检索评估框架，包含若干主要方法。在 BEIR 和 LoTTE 文本检索基准上，MV-IVF 实现了强延迟—召回权衡、最佳的批量吞吐前沿，以及良好的构建时间和索引大小表现。在 $90\%$ Recall-$10$@$10$ 下，MV-IVF 相比基线实现了最高 $8.03\times$ 的单查询延迟降低和最高 $173.5\times$ 的 QPS 提升，表明原生 IVF 风格索引对于可扩展多向量检索是实用且有效的。

## Abstract
Multi-vector retrieval represents each query and document as a set of embeddings and scores relevance via fine-grained set-to-set interactions such as MaxSim (Chamfer similarity). This expressiveness improves retrieval quality over single-vector representations, but makes search substantially more expensive. Existing systems address this challenge primarily through proxy representations or filter-and-rerank pipelines that reduce candidate generation to single-vector search. We study the complementary direction of building a native IVF-style index directly over multi-vector data.   We introduce MV-IVF, an inverted-file index for multi-vector retrieval built on MV-Lloyd, a new Lloyd-style algorithm for clustering point clouds under a Chamfer objective. Our key observation is that once point clouds are assigned to clusters, the center-update step reduces to standard single-vector clustering over the flattened embeddings in each cluster. This enables efficient construction of a hierarchical IVF tree with center point clouds at internal nodes.   At query time, MV-IVF performs best-first beam search over the tree to identify promising leaf clusters, then scores the documents in those leaves. We further accelerate search using low-bit quantization, query compression, and cache-efficient batched search. We implement MV-IVF in MVSIC, an optimized C++ library and unified evaluation framework for multi-vector retrieval that includes several major approaches. Across BEIR and LoTTE text retrieval benchmarks, MV-IVF achieves strong latency--recall tradeoffs, the best batched throughput frontiers, and favorable build-time and index-size profiles. At $90\%$ Recall-$10$@$10$, MV-IVF achieves up to $8.03\times$ lower single-query latency and up to $173.5\times$ higher QPS than the baselines, demonstrating that native IVF-style indexing is practical and effective for scalable multi-vector retrieval.

# MV-IVF 论文结构化总结

## 1. 核心问题与研究背景
- **多向量检索的表达力与代价矛盾**：ColBERT/ColPali 等模型将查询和文档表示为点云（嵌入集合），通过 MaxSim 等集合到集合交互获得更强检索质量；但单次查询—文档评分需要大量内积，搜索成本远高于单向量检索。
- **现有主流路线是“间接化”**：PLAID/WARP、SVH 通过单向量候选生成再重排；MUVERA 通过固定维编码近似 MaxSim，将问题归约为单向量 MIPS。这些方法有效，但最终 top-k 质量依赖代理表示或候选生成阶段是否保留高排名文档。
- **论文探索互补方向**：直接在多向量数据上构建原生 IVF 风格索引，使被索引对象和路由代表都保持为点云，从而更准确地保留 MaxSim 下的 top-k 邻域。
- **核心挑战**：如何对点云聚类，以及用什么代表点云将查询路由到簇。论文提出 MV-IVF 与聚类原语 MV-Lloyd 来解决这两个问题。

## 2. 方法论
### 2.1 问题形式化
- 文档集合为点云 \(P=\{P_1,\dots,P_n\}\)，查询为点云 \(Q\)。
- **MaxSim**：  
  \[
  \mathrm{MaxSim}(A,B)=\sum_{a\in A}\max_{b\in B}\langle a,b\rangle
  \]
- **Chamfer 距离**：  
  \[
  \mathrm{Ch}(A,B)=\frac{1}{|A|}\sum_{a\in A}\min_{b\in B}\|a-b\|_2
  \]
- 提出 **Chamfer \((k,s)\)-median**：寻找 \(k\) 个大小不超过 \(s\) 的中心点云 \(C_j\)，最小化  
  \[
  \sum_i \min_j \mathrm{Ch}(P_i,C_j)
  \]
  即多向量版 \(k\)-median。

### 2.2 MV-Lloyd 聚类算法
- 采用 Lloyd 风格交替迭代：
  1. **分配步**：将每个文档点云分配给 Chamfer 距离最近的中心点云。
  2. **更新步**：对每个簇重新计算大小不超过 \(s\) 的中心点云。
- **关键观察**：一旦点云分配固定，中心更新等价于对簇内所有嵌入“展平”后的加权单向量 \(s\)-median 问题。Proposition 1 表明：
  \[
  \sum_{P\in\Pi_j}\mathrm{Ch}(P,C)
  =
  \sum_{x\in\mathrm{Flatten}(\Pi_j)} w(x)\min_{c\in C}d(x,c),
  \quad w(x)=1/|P|
  \]
- 因此多向量特性主要出现在分配步，更新步可复用高效单向量聚类工具。
- 实现中采用带余弦相似度的 \(s\)-means 更新，以匹配归一化嵌入几何，作为理想 Chamfer 中心更新的实用近似。
- 算法流程：随机采样 \(k\) 个点云作为初始中心；迭代 \(T\) 次执行分配与更新；默认 5 次迭代。

### 2.3 MV-IVF 索引构建与搜索
- **构建**：递归运行 MV-Lloyd。若节点点数不超过 \(\ell_{\max}\) 则为叶节点；否则以分支因子 \(b\) 聚类，生成子节点并在内部节点存储中心点云，递归构建。形成内部节点为路由中心点云、叶节点存文档点云的分层 IVF 树。
- **查询路由**：在树上执行最佳优先束搜索，按查询与节点中心点云的 MaxSim 排序；维护大小为 `beam_size` 的内部节点束和 top-`nprobe` 叶节点列表。
- **提前终止**：当已找到 `nprobe` 个叶节点且束中最佳内部节点的 MaxSim 不优于当前最差叶节点时终止。论文明确指出这是启发式规则，不是严格上界。
- **叶内评分**：对选中的叶簇中文档点云计算 MaxSim，返回全局 top-k。

### 2.4 批量搜索与系统优化
- **批量探测生成**：根节点对所有查询共享同一组子中心，因此将根层评分组织为 many-to-many MaxSim 批量计算；更深层查询逐渐分叉，收益递减。
- **按叶分组评分**：将探测同一叶的查询分组，加载一次叶数据并对其所有查询评分，提高缓存局部性、复用内存带宽。
- **结果聚合**：各叶产生局部候选，散播到每查询缓冲区，再聚合得到最终 top-k。
- **量化**：
  - 预处理使用随机符号翻转 + 快速 Hadamard 变换旋转。
  - **Rand-1bit**：符号位量化，XOR + popcount 计算 Hamming 距离，压缩 32×。
  - **TurboQuant 4-bit**：非均匀 16 质心码本，用于树搜索。
  - **Rand-8bit**：自适应逐向量均匀量化，用于高保真重排。
- **查询压缩**：将查询嵌入分块并以块内向量和表示；比较 Ball Carving 与 Ward 凝聚聚类，默认 Ward，阈值 0.5。
- **MVSIC 框架**：统一 C++ 库与评测框架，包含 SVH、MUVERA、MV-Vamana、MV-IVF，并支持与 PLAID/FastPLAID、IGP 比较。
- **MV-Vamana**：作为原生图基线，将 Vamana 扩展到点云数据，直接在点云上建邻近图并用 MaxSim 束搜索。

## 6. 主要结论与发现
- MV-IVF 在延迟—召回和吞吐—召回前沿上表现强，尤其批量吞吐优势明显。
- 在 90% Recall-10@10 下，MV-IVF 相比基线最高实现 **8.03× 更低单查询延迟**和 **173.5× 更高 QPS**；几何平均延迟改进 1.22–1.55×，吞吐改进 2.07–4.01×。
- 单查询低延迟场景中 MV-Vamana 很有竞争力，但构建成本显著更高；MV-IVF 在构建时间和索引大小之间提供较好折中。
- 消融显示优化栈整体在 fiqa 上至少带来 17.2× 加速；MV-Lloyd 中心更新对路由质量重要，5 次迭代后收益趋缓。
- 原生 IVF 风格多向量索引是实用且有效的可扩展方案；MVSIC 提供了较全面的统一评测框架。

## 7. 优点
- **原生多向量路由**：索引对象和路由代表均为点云，避免代理表示带来的信息损失。
- **算法观察巧妙**：将中心更新归约为展平嵌入上的加权单向量聚类，复用成熟 \(k\)-means 工具。
- **系统优化完整**：树搜索、低位量化、查询压缩、批量 many-to-many MaxSim、缓存友好调度形成完整栈。
- **批量搜索有针对性**：利用 IVF 叶级共享工作，按叶分组查询，显著改善高吞吐场景的缓存与内存带宽利用。
- **评测较规范**：强调 Recall-\(K\)@\(K\) 而非仅 Recall-1，使用统一框架和参数扫描 Pareto 前沿，消融充分。

## 8. 不足与局限
- **缺乏严格理论保证**：提前终止基于启发式，中心点云不是子树得分的认证上界；MV-Lloyd 也是启发式聚类，未给出召回保证。
- **实现近似理想目标**：更新步使用余弦 \(s\)-means 近似 Chamfer 加权 \(s\)-median，可能偏离形式化目标。
- **场景覆盖有限**：主要验证文本检索和 ColBERTv2 嵌入，未系统评估图像/多模态 ColPali 等场景；外部基线仅两个数据集。
- **参数与构建成本**：索引质量依赖 \(b\)、\(\ell_{\max}\)、迭代次数和量化配置；大规模构建时间虽“实用”，但仍可能成为瓶颈。
- **公平性风险**：跨系统比较受实现成熟度、参数网格和硬件影响；未报告统计显著性、重复实验方差或能耗。
- **应用限制**：批量优势依赖查询可成批且叶访问有重叠；极低延迟、强单查询场景下图索引可能更优。
