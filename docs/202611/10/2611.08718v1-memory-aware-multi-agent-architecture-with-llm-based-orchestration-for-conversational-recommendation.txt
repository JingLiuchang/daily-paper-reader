Abstract. Conversational recommender systems often treat user ses-
sions in isolation, limiting their ability to capture how user intent evolves
over time. While large language models (LLMs) have improved semantic
understanding, they are typically used as isolated components, with-
out addressing how memory, retrieval, and decision-making should be
integrated at the system level. In this work, we propose a memory-
aware multi-agent architecture for conversational recommendation, in
which LLMs act as orchestration layers that coordinate intent refine-
ment, query construction, and interaction flow. A key design principle
is the integration of long-term memory as a first-class component, influ-
encing both routing decisions and semantic query formation. We eval-
uate the system through cross-session memory experiments, multi-turn
conversational simulations, and supervisor-driven interaction studies on
the Amazon Reviews dataset. Results show that memory-enabled inter-
actions recover up to 63% of the gap toward explicit-query scenarios
and prevent semantic degradation in extended dialogues. In addition,
supervisory orchestration increases user acceptance by +28.9 percentage
points, highlighting the importance of structured orchestration in guid-
ing interaction and output quality. We also observe an exposure bot-
tleneck between retrieved candidates and displayed recommendations.
While LLM-reranking does not improve Hit@K, it consistently enhances
semantic consistency and diversity. To capture these effects, we intro-
duce the Semantic Consistency Score (SCS), a complementary evaluation

Introduction
Conversational recommender systems aim to iteratively infer user preferences
through interaction, as intent is rarely explicit and instead evolves across dia-
logue turns. However, most existing approaches treat sessions in isolation, dis-
carding preference signals once interactions end, which prevents systems from
leveraging accumulated user context across interactions. This limits their ability
to model long-term intent and maintain coherence over extended dialogues [9,
8].
Recent advances in large language models (LLMs) have enabled new ap-
proaches to conversational recommendation, including multi-agent architectures
where components specialize in tasks such as intent understanding, retrieval,
and response generation [5]. While effective for intent interpretation, these ap-
proaches typically operate as loosely integrated components, without a unified
system-level design that governs how information flows across interaction, re-
trieval, and ranking stages [8]. As a result, there is limited understanding of how
these components interact in multi-turn and cross-session scenarios, particularly
in architectures where LLMs act as orchestration layers.
This work presents a memory-aware multi-agent architecture in which an
LLM-based supervisor coordinates interaction, integrates long-term memory into
query construction, and guides recommendation decisions across turns.
The described approach is based on a multi-agent framework in which an
LLM-based supervisor coordinates interactions, integrates long-term memory
into query construction, and guides recommendation decisions across turns. The
architecture explicitly incorporates cross-session memory as a first-class compo-
nent, enabling the system to leverage past interactions when the user’s current
intent is not clearly specified.
Our main contributions are:
– A memory-aware multi-agent architecture for conversational recommenda-
tion with LLM-based orchestration.
– An empirical analysis of the impact of orchestration and cross-session mem-
ory on recommendation effectiveness and interaction dynamics in multi-turn
settings.
– The identification of a gap between retrieval and exposure in conversational
recommendation.

Related Works
Conversational recommender systems (CRS) iteratively refine user preferences
through dialogue [9, 22]. However, most approaches operate at the session level,
without persistent memory across interactions, limiting their ability to model
long-term user intent [8].
Large Language Models (LLMs) have been increasingly adopted in recom-
mendation pipelines, for example as zero-shot rankers or conversational agents [6,
4]. While these approaches improve flexibility and semantic understanding, they
typically treat LLMs as standalone components and do not address system-level
integration with retrieval and memory.
Recent work on LLM-based agents emphasizes memory for long-term reason-
ing and adaptation, including approaches such as Generative Agents [16], Mem-
oryBank [24], and Reflexion [20]. However, these mechanisms are not directly
designed for recommendation pipelines, where memory must influence retrieval
and ranking decisions.
In parallel, LLMs have been explored as coordination layers for multi-step
reasoning and tool use [19], highlighting their potential for orchestrating com-
plex pipelines. However, prior work typically studies memory, retrieval, ranking,
or orchestration as separate mechanisms, without analyzing how cross-session
memory should act as a first-class signal that influences query construction, rout-
ing, and recommendation decisions across turns. To the best of our knowledge,
no prior work jointly investigates long-term memory, LLM-based orchestration,
and hybrid retrieval-reranking interactions at the system level for conversational
recommendation. Our work addresses this gap through a unified architecture
and a controlled empirical analysis of how these components shape multi-turn
recommendation behavior.

Architecture
3.1
System Architecture
We propose a multi-agent architecture that integrates LLM-based agents with
classical recommendation algorithms, orchestrated through a structured pipeline.

Each agent fulfills a specific role, such as intent refinement, routing, or recommen-
dation, while sharing access to memory and retrieval components. This design
enforces a clear separation of responsibilities and enables consistent behavior
across multi-turn interactions.
As illustrated in Figure 1,a Supervisor Agent acts as the central orchestra-
tor between the user and internal system components. It maintains control over
the interaction flow across stages including intent refinement, query construction,
routing, and response generation, coordinating the transition between preference
elicitation and recommendation. Memory is accessed prior to orchestration, en-
riching the user query with cross-session context before routing decisions are
made. The architecture is implemented using LangGraph, enabling explicit con-
trol over execution flow and state management across agents, consistent with
LLM-based coordination approaches [19].

3.2
User Modeling and Interaction
Supervisory Agent The Supervisor acts as the central coordination layer,
responsible for managing interaction flow and refining user queries based on
conversational and memory context. It integrates information from the current
dialogue and memory retrieval to guide downstream components.
Rather than operating as a generic router, it structures the interaction by
eliciting missing preferences and updating query representations across turns,
enabling the system to progressively align recommendations with user intent,
particularly in underspecified scenarios.
In this role, it coordinates interaction and query refinement while guiding
the behavior of downstream components. Its design is inspired by recent work
on LLM-based control and self-improvement mechanisms[19, 20].
The decision process is driven by the interaction state, retrieved candidates,
and dialogue history, allowing the system to balance preference elicitation and
recommendation generation across turns.
Conversational Agent The Conversational Agent is responsible for elicitating
user preferences through targeted follow-up questions. As shown in Figure 1, it

3.3
Recommendation Engine
The recommendation engine, whose processing flow is illustrated in Figure 1,
is implemented as a modular pipeline combining multiple retrieval and ranking
strategies. It integrates:
Semantic Retrieval Dense representations from Sentence-BERT are used
for similarity search between natural-language queries and items, as they cap-
ture semantic intent beyond lexical overlap [17]. Item embeddings are indexed
with FAISS to support efficient approximate nearest-neighbor retrieval over the
catalog [11]. We apply Maximal Marginal Relevance (MMR) to balance rele-
vance and diversity, reducing redundancy in candidates retrieved by semantic
similarity alone [2].
Collaborative Filtering We adopt Alternating Least Squares (ALS), a
well-established implicit-feedback matrix factorization method, to capture latent
user–item interaction patterns that complement textual and semantic signals [7].
Content-Based Filtering A content-based module uses TF-IDF represen-
tations extracted from textual features such as product descriptions and reviews,
providing a lexical signal complementary to dense semantic retrieval [13].
Ensemble Strategy and LLM-based Reranking Results from the re-
trieval components are combined through a weighted ensemble, allowing hetero-
geneous collaborative, lexical, and semantic signals to contribute to candidate
generation [18]. The candidate set is then refined by an LLM-based reranker,
which operates only over retrieved items and prioritizes semantic relevance and
contextual coherence rather than expanding the retrieval space [6].
3.4
Memory Orchestrator
The memory module provides cross-session context by storing and retrieving
user-related information accumulated over previous interactions. Memory is ac-
cessed prior to orchestration, allowing retrieved signals to directly influence query
construction and routing decisions.
Information is organized into structured nodes representing user preferences,
constraints, and contextual signals. Updates follow an append-only strategy,
where new nodes reference previous state for the same subject, forming a linked
sequence of states over time while maintaining a single active representation.
This design allows the system to preserve and reuse user context across in-
teractions, supporting more consistent recommendations in underspecified sce-
narios. It is conceptually aligned with recent approaches to memory-augmented
LLM systems [24, 20], where external memory is used to extend context beyond
individual interactions.

Experimental Methodology
4.1
Dataset and Preprocessing
Experiments are conducted on the Amazon Reviews 2023 Electronics dataset [15,
14], which provides both structured interaction data and rich textual content,
enabling query-driven and conversational recommendation scenarios.
To support controlled evaluation of LLM-intensive components, a subset of
the 1,000 most active users is constructed (January 2004–May 2023), yielding
19,678 unique items and 54,521 interactions (sparsity: 99.72%), with a median of
54 interactions per user. Each record includes user_id, ASIN, timestamps, rat-
ings, review text, and product metadata. Recommendation and evaluation rely
on a product-centric view, focusing on items with available product metadata.
This subset is chosen to enable controlled analysis of architectural effects
under computationally intensive settings, including multi-turn interactions and
cross-session memory. While limited in scale, it allows isolating the impact of
design choices such as orchestration and memory integration.
Experiments are conducted in a controlled environment to enable systematic
comparison of components, rather than providing absolute performance esti-
mates.
Given the limited scale of the resulting subset, results should be interpreted
mainly through relative comparisons across configurations, as statistical power
for ranking metrics such as Hit@K [21] and NDCG@K [10] is constrained and
collaborative filtering effectiveness is reduced by sparse user neighborhoods.
4.2
Offline Evaluation of the Recommendation Pipeline
We adopt a Leave-Last-3-Out protocol with temporal consistency and synthet-
ically generated queries from review text. Five models of increasing complex-
ity are evaluated: Random, Popularity, Semantic retrieval (Sentence-BERT),
Prototype (semantic + ALS + content-based), and Prototype + LLM (LLM-
based reranking). These configurations cover standard recommender system fam-
ilies, while the hybrid prototype combines ALS-based collaborative filtering with
sparse TF-IDF and dense Sentence-BERT retrieval [18, 7].
Ranking performance is measured using Hit@K and NDCG@K, with intra-
list diversity assessed through ILS@K following Ziegler et al. [26]. To complement
these metrics in terms of semantic alignment under sparse settings [12], we in-
troduce the Semantic Consistency Score (SCS), an LLM-based evaluation signal
that assesses whether recommended items are semantically consistent with the
inferred user intent.

4.3
Intent-based Conversational Evaluation
Conversational intent recovery is evaluated on 998 users with at least six inter-
actions. For each user, one interacted item is held out as the target and removed
from the history. A Claude 3 Haiku proxy user seeks the held-out item without
naming it, progressively refining the request for up to six turns. No temporal
split is enforced, as the goal is intent recovery rather than next-item prediction.
Cumulative Hit@T extends the standard Hit@K metric to multi-turn rec-
ommendation by measuring whether the target item has been retrieved at least
once up to interaction turn T. Together with MRR (Mean Reciprocal Rank) [21]
computed over the accumulated ranked lists across turns, it serves as the pri-
mary evaluation metric. Results are reported under two views: internal (target
retrieved by the pipeline) and shown (target displayed to the user).
4.4
Supervisor Evaluation
A three-tier ablation is conducted: Baseline issues recommendations from a
single-shot query; Conversational adds a supervisor capable of requesting clar-
ification; Conv. w/ Memory further activates the Memory Orchestrator to
persist preferences across turns. All tiers share the same retrieval engine and
evaluation partition.
Following established simulation practice [8, 3], a proxy user is initialized
with the category, attributes, and price of a held-out target but may not name
it, disclosing requirements organically [25]. The engine retrieves 10 items; the
top 3 are presented. An item is accepted if it matches category and features, and
its price falls within 30% of the target.
Performance is assessed along two dimensions. Recommendation quality is
captured by Hit Rate (target in top-10 retrieved), Acceptance Rate (any item
satisfying the latent-match rule), Lift (absolute acceptance gain over Baseline),
and Conversions (sessions where an initial rejection recovers to acceptance).
Dialogue efficiency is measured by Average Turns and Recommendation
Latency (mean turn at which the first ranked list is issued).

4.5
Cross Session Memory Evaluation
To evaluate the effect of cross-session long-term memory on recommendation
quality, we conducted a two-session experiment using 30 synthetic user profiles
with gradually revealed preferences. In Session 1, a multi-turn dialogue was
simulated and the extracted preferences were stored in a long-term memory
module. In Session 2, the same vague query was issued under two conditions:
Condition A (without memory) and Condition B (with memory from Session 1
restored), with all other system components fixed. Recommendation quality was
evaluated using a deterministic LLM-as-a-judge protocol [23], which performed
pairwise comparisons between conditions based on the user’s revealed preferences
and Session 1 dialogue, assigning an alignment score (0–10) per list and a winner.
We report win rate (B over A) and mean alignment score per condition.

Offline Evaluation

Discussions
6.1
Offline and Intent-based Evaluations
Popularity-based methods achieve higher Hit@K and NDCG@K but exhibit
lower semantic consistency, reflecting their sensitivity to interaction frequency
rather than user intent, a well-documented effect of popularity bias [1].
To address this, the Semantic Consistency Score (SCS) complements tradi-
tional ranking metrics by measuring alignment between recommendations and
inferred user intent. While standard metrics emphasize exact matches and in-
teraction frequency, SCS provides a semantic perspective that is particularly
relevant in conversational settings, where user preferences are often underspeci-
fied. In our experiments, this metric reveals differences across methods that are
not reflected in ranking-based evaluation alone.


12
Castro et al.
Semantic and hybrid approaches improve diversity and alignment, indicating
that representation-based retrieval better captures intent beyond historical inter-
actions [17, 5]. LLM-based reranking follows prior observations on LLM rankers
by improving semantic coherence despite limited Hit@K gains [6]. In our set-
ting, this trade-off extends to conversational recommendation, where reranking
interacts with orchestration and memory and is most appropriate when semantic
alignment and diversity justify its computational cost.
Intent-based evaluation provides additional insight into interaction dynam-
ics. Most user intent is recovered within the first turns before stabilizing. A
consistent gap between retrieval and exposure indicates that recommendation
quality depends not only on retrieval effectiveness, but also on how candidates
are filtered, ranked, and presented during interaction.
These results should be interpreted in the context of the evaluation setting,
where ground truth reflects historical behavior rather than the full space of user
preferences. As a result, optimizing for exact matches may not align with cap-
turing evolving intent, highlighting a central trade-off in conversational recom-
mendation. Given the controlled and relatively small-scale setup, performance
differences should be interpreted as indicative trends rather than statistically
robust estimates.
6.2
Conversational Orchestration
The supervisor has a clear impact on interaction quality. Introducing a clarification-
capable supervisor increases acceptance rates by up to 28.9 percentage points,
enabling structured preference elicitation under underspecified intent.
Orchestration shapes exploration across turns by iteratively refining user
preferences and updating query representations, allowing progressive alignment
with intent rather than relying on a single-step prediction. These effects are
reinforced by LLM-based reranking, which leverages accumulated conversational
context to surface relevant alternatives.
Efficiency results reveal a trade-off: successful sessions converge quickly, while
failures require longer interactions. This reflects early commitment when intent
is clear, followed by deeper exploration under ambiguity. Overall, orchestration
plays a central role in both preference elicitation and coordination of information
throughout the interaction.
6.3
Cross-Session Memory
Cross-session memory improves performance under underspecified queries, in-
creasing semantic alignment and outperforming the no-memory condition. This
aligns with prior work on memory-augmented LLM systems[24, 16], where per-
sistent memory enables more personalized and context-aware behavior across
interactions.
Its effectiveness, however, depends on how stored preferences interact with
current intent. As preferences evolve, previously stored signals may become

less informative, leading to misalignment, particularly when outdated or overly
generic signals are emphasized.
Rather than acting as a uniformly beneficial component, memory functions
as an additional signal whose impact depends on its integration with interaction
context and downstream decisions. When properly aligned, it consistently im-
proves handling of underspecified queries, reinforcing its role in conversational
recommendation.
6.4
Limitations
This work relies on a controlled evaluation setting designed to isolate architec-
tural effects. The use of a reduced dataset and simulated interactions enables sys-
tematic comparison, but limits representation of real-world variability. Simulated
users may not capture the diversity and evolution of real user intent, affecting
observed interaction dynamics. Additionally, the limited dataset scale constrains
variability in user profiles, and the magnitude of reported gains may differ under
larger and more heterogeneous populations. The results should therefore be in-
terpreted as evidence of system-level patterns rather than definitive performance
estimates. Extending evaluation to larger-scale and real-world settings remains
necessary to assess robustness and generalization.
7
Conclusion
This work presents a memory-aware multi-agent architecture for conversational
recommendation, integrating LLM-based orchestration, long-term memory, and
a hybrid retrieval pipeline. By coordinating preference elicitation, query con-
struction, and recommendation generation, the approach highlights how system-
level interactions shape conversational effectiveness.
Across offline, conversational, and cross-session evaluations, the results in-
dicate that orchestration and memory play complementary roles. Supervisory
control improves interaction under underspecified intent, while memory enhances
personalization when aligned with interaction context. A consistent gap between
retrieved and displayed items reveals an exposure bottleneck, indicating that rec-
ommendation quality depends not only on retrieval but also on how candidates
are presented.
These findings should be interpreted as evidence of system-level effects in
a controlled experimental setting, suggesting that effective conversational rec-
ommendation requires the joint design of orchestration, memory, and retrieval-
ranking components.
Future work includes the development of adaptive memory mechanisms to
address preference drift, as well as improved strategies for candidate selection
and presentation. In addition, incorporating structured profiling signals repre-
sents a promising direction for informing early-stage interaction and improving
robustness in cold-start and underspecified scenarios. Extending the evaluation
to larger-scale and real-world settings remains essential to assess robustness un-
der more diverse interaction patterns and user behaviors.
