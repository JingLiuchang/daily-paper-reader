## ABSTRACT 

Learned sparse attention, used in production models such as DeepSeek-V4 and GLM-5, lets each query attend to only k keys chosen by a lightweight indexer, but the indexer still scores every key in the prefix. At one million tokens, this selection takes more than half of prefill time. Two-stage selection over contiguous blocks, as in HiSA, reduces this cost, but its recall declines as context grows at a fixed candidate budget. We present AttentionIndex, which routes each query over an inverted-file index that groups indexer keys by similarity and refines the candidates with the native indexer score. AttentionIndex builds the index during prefill, making new keys searchable immediately, reusing previous clustering to keep maintenance cheap, and exposing each query only to clusters built from its own prefix. On GLM-5.3 and DeepSeek-V4-Flash at one million tokens, AttentionIndex delivers 1.3–1.8 × the prefill throughput of exhaustive selection, and at throughput within 5% of HiSA, it recovers 17.0 and 10.0 percentage points more of the exhaustive top-k, respectively. AttentionIndex also improves accuracy on long-context benchmarks by up to 18.4 percentage points over HiSA at the same candidate budget. 

## 1 INTRODUCTION 

Long-context inference has become a defining workload for large language models: agents (Sun et al., 2026), code assis-tants (Rando et al., 2025), and document analysis (Bai et al., 2025; Zhang et al., 2024) routinely process hundreds of thousands to millions of tokens per request (Gemini Team, 2024). At these lengths, dense attention is prohibitively ex-pensive, and production models have adopted learned sparse attention. DeepSeek Sparse Attention (DSA) (DeepSeek-AI, 2025), used by DeepSeek-V3.2, DeepSeek-V4, and GLM-5.3 (DeepSeek-AI, 2026; Z.ai, 2026), adds a lightweight learned indexer to the model’s sparse attention layers. The indexer scores the keys in the prefix, and the main atten-tion operates only on the k highest-scoring entries, which bounds its per-query cost regardless of context length. However, the indexer itself still scores every key. As a result, the computation cost of selection still grows linearly with context length per query while the cost of the attention stays constant. At one million tokens, indexer scoring and top-k selection take 53–58% of prefill time on DeepSeek-V4-Flash and GLM-5.3, more than the rest of the model combined, even with key compression and cross-layer index reuse (Section 3.1). At long context, choosing which keys to attend to has become the bottleneck of sparse attention. A natural remedy is two-stage selection: route each query to a small set of candidate keys, then apply the native indexer only to those candidates. HiSA (Xu et al., 2026) routes to contiguous blocks of keys ranked by their mean-pooled representatives. However, keys of contiguous token entries in the context need not be similar in indexer space or equally relevant to a query, so a block holding a few important keys can rank low and be discarded. As context length grows, the probability of entries relevant to a query falling into unse-lected blocks grows. In our LongBench-v2 measurements on GLM-5.3, HiSA’s recall with 8K candidate keys falls from 83.9% to 41.8% as context grows from 16K to 256K to-kens. We observe a similar decline on DeepSeek-V4-Flash with a budget of 4K compressed entries (Section 3.2). We observe that the native indexer performs exhaustive search within each selected block, so any approximation lies in which keys reside in the selected blocks. Group-ing keys by similarity rather than by their positions in the context allows the exhaustive top-k search to be applied to fewer groups that contain a higher number of promising candidates, thus reducing the selection process with limited time budget to reach higher quality top-k outcome. This is the basic idea behind inverted-file (IVF) indexes for approx-imate nearest-neighbor search (Jegou et al., 2011; Johnson et al., 2021). However, three constraints in a learned indexer environment make application of IVF more challenging. First, since pre-fill and decode generate new tokens that must be added into the candidate groups, updating the IVF index to include these new tokens must cost less than the scoring work it arXiv:2611.02508v1 [cs.AI] 2 Nov 2026 AttentionIndex: Accelerating Learned Sparse Attention 

saves. Second, in order to maintain inference causality, ev-ery query must see an IVF index built only from its own prefix, including the centroids that guide routing. Third, since the indexer score, i.e. similarity measure, is not gener-ated as a simple inner product, the score for a centroid that is the mean of the members of a cluster is a potentially poor approximate proxy for how the indexer scores its members. We present AttentionIndex, which applies the IVF principle with three novel ideas. First, it routes each query over IVF clusters of keys and refines the candidates with the native indexer score, leaving the sparse attention kernel unchanged. Second, it incrementally builds and maintains the index during prefill to limit maintenance overhead. New keys become available to subsequent queries immediately and are clustered in small batches. Periodic refits regroup the prefix while reusing the previous clustering and selectively reassessing key assignments. To preserve causality, each query uses only clusters and representatives formed from keys in its own prefix. Third, it adjusts the cluster repre-sentatives to better predict the native indexer score for its cluster members using an encoder trained offline and shared across the clusters of each layer. We implement AttentionIndex in SGLang (Zheng et al., 2024) and evaluate it on GLM-5.3 and DeepSeek-V4-Flash with contexts of up to one million tokens. At one million tokens and almost matched prefill throughput, AttentionIn-dex improves recall over HiSA by 17.0 and 10.0 percentage points on GLM-5.3 and DeepSeek-V4-Flash, respectively. Across the evaluated budgets, AttentionIndex achieves 1.3– 1.8 × the prefill throughput of exhaustive selection at the same context length. AttentionIndex also improves accuracy on long-context benchmarks by up to 18.4 percentage points over HiSA at the same candidate budget. In summary, this paper makes the following contributions: • We show that in production learned sparse attention, key selection rather than attention dominates long-context prefill, and that HiSA’s recall declines as con-text grows at a fixed candidate budget (Section 3). • We design a causal IVF index for learned indexers that is built and maintained during prefill through immedi-ate insertion and incremental refits (Section 4). • We evaluate AttentionIndex on two production models with up to one million tokens, measuring selection recall, prefill throughput, and task accuracy against exhaustive selection and HiSA (Section 6). 

## 2 BACKGROUND 

2.1 Sparse Attention 

LLM inference processes the input tokens in a prefill phase and then generates output tokens one at a time during decod-ing. Dense causal attention compares each query with every key in its prefix, so its computation cost grows quadratically with input length during prefill and linearly with context length at each decoding step. Sparse attention reduces this cost by restricting each query to a subset of key–value (KV) entries. Many sparse designs retain a few initial tokens, which act as attention sinks that receive high attention re-gardless of their content (Xiao et al., 2024). The efficiency of sparse attention depends on the cost of both selecting these entries and computing attention over them. Systems such as SampleAttention and LServe use structured sparsity to reduce attention cost (Zhu et al., 2025; Yang et al., 2025). Grouping entries into blocks can simplify selection and allow kernels to skip entire blocks. However, the fact that a group is not skipped over does not mean that all its entries should be selected for attention computation. Thus the selection process should consist of two stages: a coarse search can identify candidate groups before a fine stage selects individual tokens. We call the coarse stage 

routing , the fine stage refinement , and the maximum number of keys passed from routing to refinement the candidate budget .

2.3 Inverted-File Indexing 

Inverted-file indexing (IVF) speeds up approximate nearest-neighbor search by restricting candidate evaluation to se-lected clusters. It partitions vectors into clusters, commonly using k-means, and stores their members in inverted lists (Je-gou et al., 2011; Johnson et al., 2021). At query time, IVF ranks cluster representatives, selects a subset of clusters, and evaluates the vectors within those clusters to return the top-k candidates. The number of clusters selected, or equiv-alently the number of candidate vectors evaluated, controls the tradeoff between search cost and recall. Cluster representatives determine which clusters are selected and thus which vectors reach the final scoring stage. Even when candidates are scored exactly, a true top-k result can be missed if its cluster is not selected. Standard IVF rep-resents each cluster by its mean, which suits inner-product search: a query’s score against the mean equals the average score of the cluster’s members. The native indexer score in Equation (1) is not an inner product, so this equivalence does not hold. IVF also supports insertion by assigning new vectors to existing clusters without reclustering, and its clustering cost is typically paid once and amortized over many queries. 

## 3 MOTIVATION 

3.1 The Cost of Exhaustive Indexer Scoring 

Learned sparse attention bounds the cost of the main atten-tion computation, but not the cost of choosing which entries it attends to. In DSA, attention uses only the top-k entries for each query, yet exhaustive selection scores every available indexer key and selects the k highest scores (DeepSeek-AI, 2025). For a context of N tokens, scoring and top-k selec-tion each require O(N ) work per query and O(N 2) work across prefill, assuming fixed model dimensions and com-pression ratios, whereas attention over the selected entries requires O(k) work per query. The cost of key selection therefore grows with context length, while the per-query cost of sparse attention stays constant. This holds in both phases of inference: selection is quadratic across a prefill, and every decoding step must again score the entire prefix. Recent models reduce this overhead through compression and reuse. DeepSeek-V4-Flash compresses every four tokens into one indexed entry in its Compressed Sparse Attention (CSA) layers (DeepSeek-AI, 2026), and GLM-5.3 reuses indexer selections across multiple attention lay-ers (Z.ai, 2026), exploiting the high overlap between the selections of adjacent layers (Bai et al., 2026). On GLM-5.3, top-k selection alone takes nearly twice as long as sparse attention, so an effective remedy must shrink the input to top-k as well as the number of keys scored. AttentionIndex targets this selection cost by routing each query to a bounded set of candidate keys before applying the native indexer, so both scoring and top-k selection op-erate on these candidates rather than the full prefix. The objective is to recover the keys chosen by exhaustive selec-tion with less computation, while keeping inference-time index construction and maintenance below the savings they provide. 

3.2 Limitations of Contiguous-Block Routing 

Block-level routing reduces selection cost by scoring one representative for many keys. MoBA (Lu et al., 2026) ranks contiguous blocks using mean-pooled keys, and HiSA (Xu et al., 2026) applies the same idea to the learned indexer. It selects blocks using their summaries, then refines the keys in those blocks with the native indexer score. A fixed candidate budget bounds refinement work, but routing determines which keys refinement can recover. Table 1 shows that HiSA’s recall drops as context grows at a fixed candidate budget. On GLM-5.3, recall falls from 83.9% to 41.8% on LongBench-v2 and from 81.7% to 41.4% on RULER as context grows from 16K to 256K tokens. On DeepSeek-V4-Flash, it falls from 87.4% to 46.0% on LongBench-v2 and from 82.0% to 41.8% on RULER be-tween 32K and 256K tokens. At 256K, HiSA misses more than half of the exhaustive top-k in all four settings. At a fixed block size and candidate budget, longer contexts introduce more blocks competing for the same routing slots. This motivates grouping keys by their indexer embeddings rather than their positions. AttentionIndex clusters similar keys, allowing routing to retrieve related keys together with-out also admitting less relevant their positional neighbors. 

## 4 DESIGN 

AttentionIndex replaces exhaustive selection with routing over an inverted-file (IVF) index of indexer keys, followed by refinement with the native indexer score. Because the index grows with the requests that use it, during both prefill and decoding, two requirements shape the design: maintain-ing the index must cost less than the scoring work that it saves, and every query must see an index built only from its own prefix. The design has three parts (Figure 2): routing over similarity clusters (Section 4.1), causal and incremen-tal index maintenance (Sections 4.2 and 4.3), and learned routing representatives (Section 4.4). 

4.1 Routing over Similarity Clusters 

For each request and indexed layer, AttentionIndex keeps an IVF index over the indexer keys (Jegou et al., 2011; Johnson et al., 2021). Each cluster stores an inverted list of its member key IDs and a routing representative. A query scores every representative with the native indexer score (Equation (1)) and ranks the clusters. It then fills a candidate budget of B keys: sink keys and the not-yet-clustered keys of the open window take reserved slots, and the lists of the top-ranked clusters fill the rest, with the last list truncated if needed. Refinement scores these candidates with the native indexer score and passes the top-k keys to the unchanged sparse attention kernel. Like HiSA, AttentionIndex selects keys in two stages, but its routing units are clusters of similar keys rather than con-tiguous blocks. Because refinement scores every candidate exactly, all approximation comes from candidate selection: a key in the exhaustive top-k is missed only if it never reaches the candidate set. Grouping keys by similarity concentrates the exhaustive top-k in fewer clusters, so the same budget covers more of it (Section 6.2). Each query scores about C + B entries instead of N , where 

C is the number of clusters. With about 128 keys per cluster on GLM-5.3, routing still grows linearly with the prefix but with a far smaller constant, and refinement is bounded by 

B.

4.2 Causal Maintenance of a Growing Index 

The prefix grows with every token, so the index must change while queries use it. Rebuilding it whenever new keys arrive would erase the savings, while only adding keys to existing clusters lets clusters grow unevenly. AttentionIndex there-fore separates immediate insertion from lazy reorganization. New keys enter an open window and are included directly in the candidates of later queries, so they are searchable before they are clustered. Every W keys, AttentionIndex seals 

the window: it clusters the window’s keys with size-capped 

k-means and appends the new clusters without modifying published ones. On GLM-5.3, a seal groups W = 1 ,024 

keys into eight clusters of about 128 keys. Until the first seal, queries use exhaustive selection. Sealing keeps insertion cheap but confines each cluster to one window, so similar keys that arrive in different windows stay apart. Every R tokens ( R = 16 ,384 on GLM-5.3), a 

refit therefore regroups the entire available prefix into a new base, with more clusters as the prefix grows. The window size trades candidate slots for insertion work; the refit in-terval sets how long window boundaries persist. During decoding, which adds one key per step, new keys instead join existing clusters directly, because a typical response stays below the refit interval. Causality must hold for routing, not only for candidate IDs: a representative computed from a future key could change which clusters a query selects even if that key is later masked. Each seal or refit therefore produces a new index version whose lists, representatives, and window metadata become visible together, and a query uses a version only if every key that built it lies in the query’s prefix. Within a prefill chunk, earlier queries keep the previous version and cover newer keys through their own window. 4.3 Incremental Refits 

Two properties let a refit reuse the previous base instead of clustering from scratch: consecutive refits share almost all of their keys, and indexer keys never change once generated. AttentionIndex warm-starts each refit from the previous base’s nonempty means plus new centers sampled from recently added keys. It also keeps, for every key, its assign-ment, an upper bound on the distance to its center, and lower bounds on the distances to competing centers (Elkan, 2003; Drake & Hamerly, 2012). A refit compares all keys with the new centers, but only newly added keys and keys whose bounds no longer certify their assignment search all centers. With ∆C new centers and M keys that need a full search, the distance work is proportional to N ∆C + M C instead of N C . Each refit runs a single assignment and update pass, trading exact convergence for lower cost. A refit executes on a separate stream while the forward pass continues, and each layer publishes its new version before the first query that needs it. The new base replaces the clusters of the prefix it covers and keeps any seals made since; only sealing remains on the forward path. 

4.4 Learned Routing Representatives 

Cluster membership and routing serve different purposes. Membership uses geometric distance, which is cheap to up-date and supports the bounds above. Routing ranks clusters by the native indexer score, under which a cluster’s mean is only an approximate proxy for its members (Section 2), so scoring the mean can rank a cluster low even when it contains top-k keys. AttentionIndex therefore keeps mem-bership geometric and learns only the representatives used for routing, following Vecchiato et al. (2024). Because clusters are created and replaced within each re-quest, a separate representative cannot be optimized per cluster. Instead, a small encoder shared by all clusters of a layer predicts a correction ∆rc to the cluster mean μc

from permutation-invariant summaries of its members: their mean, the logarithm of the cluster size, and mean- and max-pooled learned features (Zaheer et al., 2017). The routing representative is rc = μc + ∆ rc. The correction is bounded and initialized to zero, so the encoder starts from ordinary IVF and leaves membership, means, and bounds unchanged. We train the encoder offline on queries and index snapshots from the frozen model, with exhaustive selection as the reference. ## 5 IMPLEMENTATION 

We integrate HiSA and AttentionIndex into SGLang as can-didate producers for the learned indexer (Zheng et al., 2024). Full DSA and both selectors share the serving stack, model weights, sparse attention kernels, and client. The selectors use Triton and TileLang kernels and read paged indexer keys directly. On GLM, routing representatives use the same FP8 page format as indexer keys, allowing routing and refinement to reuse DeepGEMM. Refits read quantized keys directly and run on separate CUDA streams, with work staggered across layers to over-lap the forward pass. Under tensor parallelism, indexer keys are replicated, while each layer has an owner rank that fits and broadcasts its index state so all ranks use the same routing geometry. Learned encoders are trained offline and loaded at server startup. Layers without a selected encoder use ordinary cluster means. We measure recall by capturing indexer operands during serving and replaying selectors under the serving schedule. Replay checks require HiSA to match its served selections and IVF to preserve the server’s mandatory candidates. Serv-ing timings include index construction and maintenance, but exclude startup and kernel compilation. Time breakdowns use PyTorch profiler traces of a prefill. Accuracy runs use greedy decoding and each benchmark’s answer extraction and metric, applied after the model’s thinking segment. 

## 6 EVALUATION 

6.1 Experimental Setup Models. We evaluate AttentionIndex on GLM-5.3 and DeepSeek-V4-Flash. We preserve their native selection sizes: 2,048 token keys per query for GLM-5.3 and 512 compressed entries for the indexed layers of DeepSeek-V4-Flash, which use a compression stride of four source tokens. 

Baselines. We compare against Full DSA, which exhaus-tively scores the causal key set using the native indexer, and HiSA (Xu et al., 2026), which selects contiguous blocks using pooled key summaries before scoring their member keys. 

Datasets. We use LongBench-v2 (Bai et al., 2025), RULER (Hsieh et al., 2024), and InfiniteBench (Zhang et al., 2024), covering code repositories, long-document question answering, in-context learning, and synthetic retrieval tasks. 

Hardware. Timing experiments use eight NVIDIA B200 GPUs with eight-way tensor parallelism and 8,192-token prefill chunks. All methods run in the same serving stack (Section 5). 

6.2 Indexer Retrieval Quality Analysis 

In this section, we measure recall as the fraction of the exhaustive native indexer’s top-k keys recovered in the fi-nal selection. All methods and budgets use the same 12 inputs per dataset and model. LongBench-v2 uses ten code-repository and two in-context learning inputs, excluding data used to train or select learned representatives and tak-ing prefixes of approximately 1M tokens. RULER uses two 512K inputs from each of six tasks, and InfiniteBench uses 12 long contexts with at most one per book. We eval-uate the final 2,048 queries of each prefix at five indexed layers spanning the model’s depth, averaging over queries and layers within each input, then across inputs. Budgets span 16K–64K candidates ( 1K = 1 ,024 ), counted as token keys on GLM and compressed C4 entries on V4. The V4 budgets therefore correspond to 64K–256K source-token equivalents. AttentionIndex achieves higher mean recall than HiSA (Fig-ure 3) on all three datasets at every evaluated budget sup-ported by both methods. For example, at a 24K budget on LongBench-v2, AttentionIndex improves recall from 67.16% to 89.70% on GLM-5.3 and from 75.88% to 90.66% on DeepSeek-V4-Flash. The smaller gains on DeepSeek-V4-Flash at larger budgets reflect the higher recall already achieved by HiSA. AttentionIndex also achieves higher recall with smaller can-didate budgets. On GLM-5.3, its 24K results exceed HiSA’s 64K results on all three datasets, using 62.5% fewer can-didate slots. On DeepSeek-V4-Flash, its 24K-entry results exceed HiSA’s 32K-entry results on all three datasets, using 25% fewer slots. Increasing the budget further improves recall for both methods. These results demonstrate that AttentionIndex uses the candidate budget more effectively, although the resulting latency benefit also depends on rout-ing and index maintenance costs. The gains are consistent with the limitations of HiSA’s contiguous-block means (Xu et al., 2026) (Section 3.2): similarity grouping preserves more reference keys within the same candidate budget.

## 7 RELATED WORK 

Sparse attention. Structured approaches keep local win-dows and attention sinks (Xiao et al., 2024) or exploit struc-tured sparsity in attention kernels (Zhu et al., 2025; Yang et al., 2025). Query-aware methods select pages of the KV cache at inference time (Tang et al., 2024), and trainable architectures learn block or token selection together with the model (Yuan et al., 2025; Lu et al., 2026; DeepSeek-AI, 2025). Routing Transformers cluster queries and keys with online k-means during training (Roy et al., 2021). At-tentionIndex does not change how a model attends: it ac-celerates the selection step of a learned sparse attention mechanism at inference time and preserves its native score. 

Accelerating learned indexers. HiSA replaces the exhaus-tive indexer scan with routing over contiguous blocks (Xu et al., 2026), the approach we compare against throughout. IndexCache reuses selections across layers (Bai et al., 2026), and kernel-level work streams indexer scores to bound mem-ory (Jaber & Jaber, 2026) or speeds up exact top-k selec-tion (Liu et al., 2026). These optimizations largely com-plement AttentionIndex’s reduction in the number of keys scored. 

Retrieval over the KV cache. RetrievalAttention builds approximate nearest-neighbor indexes over keys (Liu et al., 2025a), and RetroInfer organizes the KV cache as a vector storage engine (Chen et al., 2026). ClusterKV, Squeezed Attention, and Tactic cluster keys to select or estimate im-portant tokens (Liu et al., 2025b; Hooper et al., 2024; Zhu et al., 2026). MagicPIG samples keys with locality-sensitive hashing (Chen et al., 2025), while SAAP partitions keys and queries asymmetrically using a learned query classi-fier (Mazar´ e et al., 2025). These methods approximate dense attention, mostly during decoding, with indexes built offline or after prefill. AttentionIndex instead targets the top-k of a learned indexer and maintains its index within the forward pass, keeping routing causal as the prefix grows. 

Dynamic vector indexes and clustering. Dynamic indexes combine incremental insertion with periodic reorganiza-tion (Xu et al., 2023; Baranchuk et al., 2023). AttentionIn-dex’s seals and refits resemble buffered writes and merges in log-structured merge trees (O’Neil et al., 1996). Its refits build on bound-based k-means acceleration (Elkan, 2003; Hamerly, 2010; Drake & Hamerly, 2012; Ding et al., 2015), and its learned representatives follow a learning-to-rank for-mulation of cluster selection (Vecchiato et al., 2024). We adapt these techniques to an index that is built within a sin-gle request and publishes causal updates on the inference path. 

## 8 CONCLUSION 

Learned sparse attention reduces attention computation, but exhaustive key selection remains costly at long contexts. At-tentionIndex accelerates selection by maintaining a causal IVF index within each request and refining routed candi-dates with the native indexer score. At a matched 24K candidate budget, AttentionIndex improves recall and task accuracy over HiSA on both models, while delivering 1.3– 1.8 × the prefill throughput of exhaustive selection at one million tokens.
