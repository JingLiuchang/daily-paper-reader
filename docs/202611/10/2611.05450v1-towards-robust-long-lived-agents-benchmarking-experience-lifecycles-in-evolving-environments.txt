ABSTRACT
As agents become more capable, they are moving beyond one-off tasks toward
sustained assistance across successive user goals. Such assistance requires agents
to discover how unfamiliar environments work, reuse what they learn across tasks,
and keep that experience current as environments evolve. Existing benchmarks
increasingly study experience reuse and adaptation, but provide limited insight
into which parts of accumulated experience agents revise, retain, or lose. To ad-
dress this gap, we introduce ReScopeBench, a benchmark for the experience life-
cycle across 18 interactive environments. It distinguishes structural experience
about how an environment is organized and accessed from rule experience about
reusable principles and constraints that guide decisions across tasks. To study
how experience is acquired, reused, and revised, we propose an experience-first
construction approach. It builds task streams around shared experience and in-
troduces silent environmental changes. We evaluate task performance and track
changes in saved experience throughout each stream. Across 20 models, we find
that retained experience improves task performance, but agents struggle to keep
it current as environments change. Even when the required experience is cor-
rectly recorded, agents do not always fulfill requests successfully. These findings
identify selective maintenance and effective use as complementary challenges for
long-lived agents.

INTRODUCTION
Recent advances have strengthened agents’ ability to complete complex tasks in interactive environ-
ments (OpenAI, 2026; Anthropic, 2026; Seed, 2025b; Gonzalez-Pumariega et al., 2026; Lin et al.,
2026). This progress opens the way to sustained assistance across successive user goals. In an
initially unfamiliar environment, such assistance requires the agent to discover how resources are
organized and which rules guide its actions. When new requests depend on the same resources and
rules, agents can reuse earlier discoveries to guide their work. Continued reuse also requires keeping
this experience current when the environment changes.
To evaluate these abilities, existing benchmarks examine experience reuse across tasks and adapta-
tion to change. Memory benchmarks test retrieval and reasoning over supplied histories, with some
also assessing information updates (Maharana et al., 2024; Wu et al., 2025; Tan et al., 2025; Hu et al.,
2025). Interactive and skill-oriented benchmarks assess experience acquired through agents’ own
actions and reused or refined in later tasks (Zheng et al., 2025; He et al., 2026; Zhang et al., 2026;
Lei et al., 2026). AgingBench and EvoArena further examine memory maintenance and adaptation
as information and operating conditions change (Zhu et al., 2026; Xu et al., 2026).

However, existing evaluations do not fully show whether agents update outdated experience while
keeping the parts that remain valid after the same environmental change. Task success alone cannot
answer this question. For example, a delivery directory may move while its delivery policy stays the
same. An agent may find the new directory and complete the task but leave the old path in memory.
It may also rewrite the saved entry and lose policy details that are still valid. These cases can receive
the same task score as an update that corrects the path and keeps the policy. When queries and
task actions share a limited budget, repeated lookups leave fewer resources for completing requests.
We therefore evaluate task results together with the experience agents save. We track what agents
learn, update, retain, or lose across tasks and environmental changes. Table 1 compares existing
benchmarks and ReScopeBench along these dimensions.
To support this evaluation, we introduce ReScopeBench, a benchmark spanning 18 initially unfa-
miliar environments. We focus on two complementary types of experience that agents can acquire
in these environments. Structural experience describes how resources are organized, related, and
accessed. Rule experience captures reusable principles and constraints that guide decisions across
tasks within an environment. To study how the same experience is acquired, reused, and revised, we
propose an experience-first construction approach. We first identify structural and rule experience
that agents can discover through interaction, then build varied tasks in which agents can reuse it.
Local changes invalidate selected parts of this experience while leaving others valid. Changes are
unannounced, so agents must detect them through interaction. To examine experience maintenance
at different stages of interaction and beyond a single change, we vary change positions and include
multiple changes in some streams. Without exploration costs, agents could repeatedly rediscover
information instead of maintaining useful experience. We therefore place discovery and execution
under environment-specific resource budgets, encouraging agents to reuse valid experience and se-
lectively recheck what may have changed. We evaluate task performance with and without retained
experience and assess saved content against private references that reflect the current environment.
We evaluate 20 commercial and compact open-weight models on ReScopeBench and find that retain-
ing experience improves average task performance. Agents generally record structural experience
more completely than rule experience. When environments change, they preserve much of the valid
content but leave some outdated content uncorrected. More interaction after change does not always
coincide with more explicit attempts to update saved experience. Even when the required experi-
ence is correctly recorded, agents can still fail to fulfill requests. These findings highlight the need to
update experience without losing valid content and to use saved experience effectively to complete
tasks.
Our contributions can be summarized as follows:

RESCOPEBENCH
2.1
BENCHMARK OVERVIEW
ReScopeBench evaluates agents over task streams in initially unfamiliar interactive environments.
We use e to denote one environment, Te its stream length, and t = 1, . . . , Te the task position within
that stream. For each task, agents receive a goal and descriptions of the available tools. They use
these tools to discover resource relationships and operating rules, and can record these findings for
reuse in later tasks.
Completing varied goals requires agents to locate relevant resources and understand how to act on
them. We distinguish structural experience, which describes how resources are organized, related,
and accessed, from rule experience, which captures reusable principles and constraints that guide
decisions across tasks. For example, locating stored goods does not establish how they must be
handled. Their location can change while handling rules remain valid, or vice versa. Separating
these types lets us track their acquisition, revision after change, and retention of still-valid content.
To track how the same experience is acquired, reused, and revised across tasks, we propose an
experience-first construction approach. We first identify discoverable experience, then build var-
ied tasks that reuse it and local changes that invalidate selected parts. Changes vary in timing and
number and must be detected through interaction without explicit notice. Resource budgets limit
exhaustive rediscovery, encouraging agents to reuse earlier findings. Figure 1 summarizes the con-
struction process and lifecycle. We evaluate task performance with and without retained experience
and assess saved content against references for the current environment.
2.2
BENCHMARK CONSTRUCTION
As depicted in Figure 1(a), construction proceeds through environment preparation, experience dis-
covery, joint stream synthesis, and verification.
Environment Preparation.
We implement each environment e as a simulated application in code,
using application scenarios and public documentation to define its entities, workflows, and opera-
tions. Each simulation provides reproducible initial states and tools whose outputs reflect the current
state. Tool descriptions explain how to use the interfaces, while local resource relationships and op-
erating conditions must be discovered through interaction. Each environment specifies which tool
operations incur costs and the limits on the resources they consume.
Experience Discovery.
The selected experience must support multiple task goals and be discover-
able through the tools available to evaluated agents. We identify candidate experience by inspecting
environment code and data, then verify its discoverability through tool interactions. For each se-
lected item, we record its scope, the observations that reveal it, and the decisions and task outcomes
that depend on it. These links form a private dependency graph for constructing tasks that reuse the
experience and changes that invalidate selected parts.
To assess the saved content, we organize the selected experience within each environment e into
reference units u. Each unit groups related statements, called claims c, about resource relationships
or operating rules. Each claim has a scoring rubric specifying what the saved content must establish

Joint Stream Synthesis.
To test reuse across different goals, we use the dependency graph to
construct an ordered stream of Te tasks for environment e. The tasks share resource relationships
and operating rules but vary in their requested objects and conditions. To test selective revision, we
schedule local changes immediately before selected tasks. Their positions form the change schedule
De, with each d ∈De denoting the first task affected by a change. Each change alters selected
relationships or rules and updates their reference claims. For a given change and affected unit u, let
Nu denote the current-version claims describing information introduced or changed by that event.
Later tasks use both changed and unchanged information. Changes are detectable through tool
observations but are not announced in task instructions or boundary messages.
We complete the tasks in sequence using the tools available to agents, carrying state forward and
applying scheduled changes. These tool-call sequences serve as private reference solutions. We use
the resulting task artifacts and relevant final states to specify each task’s delivery requirements. A
private grader checks the agent’s delivered results against these requirements and accepts equivalent
valid outcomes. Appendix D.1 gives an example. We then compare the resource costs of reference
solutions, local correction after changes, and exhaustive searches over candidate resources and rules.
Budgets cover verified completion and correction costs while restricting exhaustive rediscovery.
Verification.
Starting from each environment’s initial state, we replay the reference solutions in
task order and apply the scheduled changes. We check that each solution produces the required
outputs within budget and that the grader assigns the expected score. We also test tool-call sequences
that reveal updated information and support local correction within budget. Finally, we inspect task
instructions and tool interfaces for leaked answers and unintended shortcuts. We freeze the tasks,
tools, budgets, change schedules, and graders before evaluating models’ ability to acquire, reuse,
and revise experience.

2.4
EVALUATION PROTOCOL AND METRICS
2.4.1
EVALUATION PROTOCOL
For each model–environment pair, two streams start from the same initial state with identical tasks,
tools, budgets, and change schedules. Agents are instructed to store structural experience in memory
and rule experience in skills. The with-experience condition retains these assets and retrievable
history across tasks. The without-experience condition clears them between tasks. Both conditions
permit within-task learning and start each task with a fresh conversation. Environment state persists
within each stream and can diverge as agents take different actions.
2.4.2

EXPERIMENTS
3.1
EXPERIMENTAL SETUP
We evaluate 20 models from ten families: three compact open-weight models (Qwen3.5-9B,
Qwen3.5-35B-A3B, and Qwen3.8-27B) (Team, 2025b) and 17 models offered through commer-
cial services, including models with public weights. The commercial group covers GPT (OpenAI,
2026), Claude (Anthropic, 2026), DeepSeek (DeepSeek-AI, 2026), Doubao (Seed, 2025a), Gemini
(Team, 2025a), GLM (GLM, 2026), Kimi (Team, 2026), MiMo (Xiaomi, 2026), MiniMax (Lai et al.,
2026), and Qwen3.8-Max. These reports describe the model families. Table 2 lists the versions we
evaluated.
All models use the Hermes agent harness (Nous Research, 2026) on the same 18 environments. Each
model completes one with-experience stream and one without-experience stream per environment,
following the protocol in Section 2.4. Task outcomes are scored by deterministic graders. We use
GPT-6 Astra (OpenAI, 2026) to assess saved experience against the reference rubrics. Appendix B
provides inference settings, runtime limits, and detailed execution and scoring procedures.
3.2
MAIN RESULTS
Table 2 reports the main results. We highlight three observations.
(1) One compact model approaches the commercial median in immediate updating. Qwen3.8-
27B records 29.05% of the required updates after the first affected task, close to the commercial
median of 29.75%. Its task performance with experience shows a wider gap (62.48 versus 73.44).
Both Qwen3.5 models score below 3 on each of these metrics.
(2) Rule coverage remains uneven even among strong models. Structural coverage exceeds rule
coverage for 17 of 20 models, with a mean gap of 4.79 points. This imbalance is not confined to
models with low coverage. GPT-6 Astra and GPT-6.1 Sol have structural scores above 70, yet their

rule coverage of 73.22 leads the table and exceeds its structural coverage of 71.70. Strong structural
coverage therefore does not uniformly translate into equally complete recording of rules, and the
balance between the two types remains model dependent.

ANALYSIS
We examine how experience relates to task performance, how models adapt to environmental
change, and how their tool use and experience maintenance respond.

3.3.3
HOW DO AGENTS ALLOCATE TOOL USE?
We analyze 7,040 with-experience tasks across all 20 models and 18 environments to examine in-
teraction allocation and responses to change. History tools retrieve prior records, experience tools
read or modify memory and skills, and environment tools query or act on the current state. We count
explicit calls, including failures, and exclude background review. Changes are aligned at the first
affected task. Appendix C.3.1 gives the counting and averaging procedures.
Models differ in history retrieval. In Figure 5(a), the four displayed models make similar numbers
of environment calls, ranging from 13.07 to 13.81 per task. History calls vary much more, from
0.14 for GPT-5.4 to 6.41 for GPT-5.5. Their differences in total activity therefore largely reflect
consultation of prior records, rather than more requests to the current environment.
Interaction peaks near change. A tool round comprises one assistant turn with one or more calls
and their responses. In Figure 5(b), the overall mean rises from 10.72 rounds over the three preceding
tasks to 12.70 at onset, then falls to 11.21 by the fourth affected task. All displayed models except
GPT-5.4 show a similar increase near change, indicating that the aggregate response is not shared
uniformly across models.

4
RELATED WORK
4.1
EXPERIENCE-BASED AGENT ADAPTATION
Experience-based adaptation methods differ in what they retain from interaction and how they up-
date it. Reflexion and ExpeL turn feedback and trajectories into verbal reflections or reusable in-
sights (Shinn et al., 2023; Zhao et al., 2024). Other methods retain procedures: Voyager stores
executable skills (Wang et al., 2024), while Agent Workflow Memory abstracts recurring action
sequences into reusable workflows (Wang et al., 2025). To keep guidance current, Dynamic Cheat-
sheet revises test-time memory as new evidence arrives (Suzgun et al., 2026). ReScopeBench com-
plements these methods with an evaluation of how acquired experience is reused and maintained
across tasks as local conditions change.
4.2
BENCHMARKING AGENT MEMORY AND EXPERIENCE
Benchmarks study experience under supplied histories, interactive tasks, and changing conditions.
LoCoMo, LongMemEval, and MemBench evaluate reasoning over supplied histories, with the lat-
ter two also assessing updates to remembered information (Maharana et al., 2024; Wu et al., 2025;
Tan et al., 2025). MemoryAgentBench adds incremental learning and selective forgetting (Hu et al.,
2025). Interactive benchmarks, including LifelongAgentBench and MemoryArena, evaluate expe-
rience use across tasks (Zheng et al., 2025; He et al., 2026), while skill-oriented benchmarks study
acquisition, refinement, and transfer (Zhang et al., 2026; Lei et al., 2026; Gao et al., 2026). More re-
cent benchmarks examine maintenance as information and environments change. AgingBench (Zhu
et al., 2026) studies memory degradation and revision, including agent-managed workspace scenar-
ios. EvoArena (Xu et al., 2026) evaluates evolving terminal workflows, codebases, and preferences,
and measures whether saved memory contains evidence of user preferences. In ReScopeBench,
tasks reuse discoverable structural and rule experience, and local changes make selected parts out-
dated. We assess saved content alongside task outcomes to distinguish correction of affected rela-
tionships from retention of those that remain valid.
5
CONCLUSION
This paper introduced ReScopeBench, a benchmark for studying experience acquisition, reuse, and
revision across 18 interactive environments. Its experience-first construction builds varied tasks
around shared structural and rule experience, then introduces silent changes that invalidate selected
content while leaving other content valid. Evaluations of 20 models show that retaining experience
improves task performance, but rule experience is generally recorded less completely than structural
experience. Further analyses show that agents preserve much of the still-valid content while leaving
required updates incomplete, and can fail to complete requests even when the required experience
is correctly recorded. More interaction after change does not always coincide with more explicit
attempts to update saved experience. ReScopeBench offers a testbed for developing agents that
selectively revise outdated experience and effectively apply what they retain.

EVALUATION DETAILS
B.1
EXPERIMENTAL SETUP
We evaluate the 20 models in Table 2 on the same 18 versioned environments. Each model com-
pletes 352 tasks per condition, covering 26 environmental changes. We use the maximum supported
reasoning effort where configurable. Explicit sampling settings use temperature 1 and top-p 0.95;
unsupported or omitted fields follow provider defaults. Foreground execution allows 100 agent iter-
ations per task and up to 65,536 output tokens per response. An iteration may contain multiple tool
calls. Environment-specific resource budgets apply separately.
The Hermes memory and skill interfaces are pinned to revision 345cd2b057a45. Memory and
skills are limited to 16,000 and 100,000 characters, respectively. Agents receive a memory snapshot
and skill index at task start and can retrieve full skills on demand. Four read-only history tools
retrieve completed-task records through lexical matching and pagination, with a shared limit of 30
calls per task. Structural and rule experience are classified by content, regardless of where they are
stored. No reference experience is preloaded.
Both conditions start from the same environment state and use a fresh conversation for each task.
With-experience streams retain memory, skills, and retrievable history. Without-experience streams
clear these assets while retaining their own environment state. The two states then evolve indepen-
dently through agent actions. Each model–environment pair has one stream per condition. GPT-5.5
also supported environment development. Agents can update experience during execution. Hermes
skill review can run after ten tool iterations and a completed, uninterrupted response, with a sep-
arate limit of 100 iterations and 600,000 cumulative input tokens. It uses the same model, cannot
access environment tools, and finishes before grading, so the current task’s score cannot supervise
review. Later history retrieval may include permitted outcome feedback, but never private reference
answers.
B.2
SCORING AND AGGREGATION
BP and EP average all task positions, including the initial task. DP uses the first affected task
after each change and includes adaptation within that task. SC and RC average binary claim scores
within reference units, units within each experience type, and checkpoints within each environment.
References follow the current environment version and include content not yet encountered by the
agent.
GPT-6 Astra evaluates one complete reference unit against the complete saved memory and skill cor-
pus per request, using medium reasoning effort and a 14,000-token output limit. Model-identifying
metadata is withheld. Each claim receives credit only when all applicable rubric checks pass. Equiv-
alent wording and supported deductions are accepted, while unresolved contradictions receive no
credit. We validate the structured responses and cited evidence before computing scores. These
metrics measure reference coverage rather than the precision of all saved content.
For each affected unit, UC measures coverage of the current update targets after the first affected
task. RT measures the first checkpoint at which all update targets and the unit’s previously correct,
still-valid claims are correct together. Update targets are shared across models, while the retained
set depends on pre-change credit. Both target sets remain fixed within an L-task window starting
at the first affected task and ending before the next change or at stream completion. Only units
with nonempty update targets participate. Completion at its first or last task scores 100 or 100/L,
respectively, and no completion scores zero. An empty retained set reduces the criterion to update
completion. RT records first completion, not its subsequent persistence, and reflects the opportuni-
ties provided by the task schedule.
All metrics weight environments equally. DP averages events within environments. UC and RT
average affected units within events, then events within environments. Avg. averages the seven
unrounded metrics. Longer streams and larger inventories do not receive more weight.
Supplementary analyses use Wmet and Bmet for task scores with and without experience, and Smet
and Rmet for post-task structural and rule coverage. The difference ∆met = Wmet −Bmet is
distinct from DP. Position curves keep environment membership fixed within each stream-length
