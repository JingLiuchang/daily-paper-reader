MEMOIR: A Training-Free Memory Lifecycle for Long-Horizon LLM Agents
Mayank Anand1, Subham Raj2∗, Aman Vaibhav Jha2, Sriparna Saha2
1Indian Institute of Information Technology Allahabad
2Indian Institute of Technology Patna

Abstract
Long-horizon LLM agents require memory systems that pre-
serve useful information across sessions and retrieve it when
needed. Existing systems treat these as separate problems:
memories are written prospectively with static importance
scores that are never revised after use. This creates two cou-
pled failure modes: consolidation can silently destroy evidence
that future queries require, while retrieval continues to favor
stale memories. We propose MEMOIR (Memory Evidence
via Merge-certified, Online Importance Revision), a training-
free memory lifecycle that unifies judge-gated consolidation
with retrospective attribution. Before compressing memory,
screening gates test whether answer-relevant evidence is pre-
served. After each query, attribution estimates which retrieved
memories supported the answer and updates their retrieval
priority. A UCB-style exploration bonus additionally encour-
ages retrieval of under-exposed memories, reducing the risk
that frequently retrieved memories crowd out useful but less-
seen evidence. On 1,905 deduplicated LoCoMo QA pairs, the
full retrieval stack improves evidence recall@5 by 11.92 per-
centage points over bare cosine, with confidence-gated feed-
back adding 1.50 points overall without reference answers
or reranker training; a deployment-unavailable oracle adds
1.84 points overall and 8.05 points on multi-hop. Judge-gated
merge changes the recall of text-based evidence from 58.82%
to 59.08%, reduces the active store by 1.42%, and incurs 0
observed losses in 100 independently audited merges, with
a one-sided 95% upper loss-rate bound of 2.95%. Together,
these results outline a practical deployment path: no addi-
tional LLM call on the online write path, with merge screen-
ing confined to periodic offline consolidation. The lifecycle
reduces to one principle: attribute usefulness after use, and
screen for preservation before compression. Code is available
at https://github.com/AnandMayank/MEMOIR.

Introduction
LLM agents can use tools and reason over immediate con-
text, but long-horizon agents require external memory to
reuse historical experience across sessions that exceed any
practical context window (Park et al. 2023; Wu et al. 2024).
As agents are deployed for multi-session tasks such as per-
sonal assistance, customer support, and research copiloting,

accumulated interaction history grows beyond what a single
inference call can attend to. External memory is therefore
not merely an efficiency optimization; it is a lifecycle re-
quirement: agents must decide what to keep, what to con-
solidate, what to retrieve, and how to revise those decisions
after observing outcomes.
Most existing systems handle only part of this lifecy-
cle. Write-time memory systems construct summaries, facts,
links, or graph structures when an interaction is stored. Re-
trieval systems then rank those memories using recency, rel-
evance, and static importance. Generative Agents, for ex-
ample, scores memory priority as a fixed combination of
recency, importance, and relevance (Park et al. 2023). Later
systems such as Mem0 and A-MEM add stronger extraction,
linking, or graph structure (Chhikara et al. 2025; Xu et al.
2026), but the importance signal is still largely assigned at
write time. A memory that was judged important when stored
can remain highly ranked even if later sessions show that it
is no longer useful.
This paper reframes the problem around two coupled fail-
ure modes. The first is prospective corruption: memory con-
solidation can merge, summarize, or prune items that look
redundant locally but contain evidence required by future
queries. The second is retrospective staleness: retrieval can
continue to favor memories that merely resemble the query
rather than memories that have actually helped answer prior
queries. These are not merely engineering artifacts: prospec-
tive corruption reflects the loss of answer-relevant traces
during consolidation, while retrospective staleness reflects
the absence of retrieval-induced strengthening (Roediger and
Karpicke 2006). We treat established properties of bounded-
capacity memory under delayed, sparse feedback (Tulving
1972; Craik and Lockhart 1972; Ebbinghaus 1885; Stern
2002) as convergent design constraints for a memory life-
cycle, not as claims of biological or structural isomorphism.
Treating the two failures separately is insufficient. Consolida-
tion changes the objects to which retrieval credit is attached,
while retrieval feedback reveals which objects consolidation
should protect.
We therefore propose a combined lifecycle: screen
prospectively, attribute retrospectively. Prospectively,
certificate-gated consolidation applies merge operations only
when a judge ensemble finds that answer-relevant support is
preserved. Retrospectively, we introduce TRACE (Training-

free Retrieval Attribution and Credit Estimation), with two
instantiations: TRACE-FB (feedback attribution) estimates
memory support via lexical overlap, and TRACE-CF (coun-
terfactual attribution) measures support by leave-one-out
answer change. TRACE-UCB (Upper Confidence Bound
exploration) couples these importance updates with count-
based exploration to reduce feedback-driven retrieval lock-
in. The bridge is that attribution provides online estimates of
support sets for consolidation, while accepted merges pre-
serve and transfer the credit ledger. In short, the system con-
solidates what the screening procedure accepts as redundant
and up-weights what is estimated to be useful.
This framing follows the two-phase shape of RMM,
which combines prospective memory construction with ret-
rospective reflection (Tan et al. 2025), but changes both
halves. RMM’s prospective step is heuristic summariza-
tion and its retrospective step uses an LLM citation labeler
plus a REINFORCE-trained reranker. Our direction replaces
heuristic summarization with certificate-gated consolidation
and replaces trained reranking with closed-form, training-
free attribution updates. The goal is not simply better re-
trieval, but a memory lifecycle in which compression and
credit assignment are mutually consistent.
Our contributions can be summarized as the following:
1. A combined prospective-retrospective memory lifecy-
cle unifies certificate-gated consolidation with outcome-
conditioned attribution in a training-free framework for
long-horizon agents. Its full RECALL-Q retrieval stack
improves evidence recall by 11.92 percentage points over
cosine retrieval on LoCoMo.
2. TRACE-UCB couples these with count-based explo-
ration to mitigate exposure lock-in. Confidence-gated au-
tonomous feedback improves evidence recall@5 by 1.50
percentage points over the matched no-TRACE retriever,
while reference-answer feedback reaches a 1.84-point
gain and an 8.05-point multi-hop gain.
3. Certified merge provides a conservative prospective
safety gate combining judge screening, retrieval coverage,
provenance preservation, and hard compression. Under
a fixed retrieved-token budget, it changes text-grounded
evidence recall from 58.82% to 59.08%, reduces the ac-
tive store by 1.42%, and incurs 0 observed audited losses
among 100 accepted merges.
4. A training-free architecture separates low-latency online
memory operations from asynchronous certified consol-
idation. The online write path requires no LLM call and
takes 6.8ms median latency, while lexical and counter-
factual attribution expose a configurable quality-latency
trade-off.

Related Work
2.1
Agent Memory Systems
Agent memory systems can be organized by how they store
and update long-term context (Zhou et al. 2026). Stream-
and-reflection systems such as MemoryBank maintain con-
versation as a timestamped log and periodically distill it
into higher-level reflections (Zhong et al. 2024). Hierarchi-
cal systems such as MemGPT and Letta separate bounded
in-context memory from an archival store, moving items be-
tween tiers through explicit control operations (Packer et al.
2023). Knowledge-graph systems such as Mem0 and Zep
represent memory as entities and typed relations, some-
times including temporal validity intervals for factual up-
dates (Chhikara et al. 2025; Rasmussen et al. 2025). Com-
posite systems such as A-MEM route structured memory
objects across vector and graph substrates (Xu et al. 2026).
A common cost of this write-time structure is that entity
extraction, relation inference, and summarization typically
require one or more LLM calls per write, which accumu-
lates into non-trivial latency and token cost as interaction
volume grows. Recent work such as Memanto (Abtahi et al.
2026) instead pursues LLM-free ingestion, showing that raw
conversational content can be stored without any write-path
LLM call. MEMOIR shares this training-free write-time goal
but differs in what the saved cost is used for: rather than opti-
mizing ingestion alone, MEMOIR uses the freed write-time
budget to support closed-form, retrospective importance re-
vision, so that cheap writes are paired with an evolving no-
tion of which memories remain load-bearing. These systems
improve storage and retrieval structure, but they still assign
importance, relevance, or link strength at write time rather
than revising it from retrieval outcomes.
MEMOIR’s write path deliberately shifts processing cost
from initial ingestion to retrospective usage-driven accrual —
a design trade-off informed by established cognitive memory
principles (Tulving 1972; Craik and Lockhart 1972; Roedi-
ger and Karpicke 2006; Ebbinghaus 1885; Stern 2002) as
engineering design pressures rather than biological claims.
2.2
Retrieval and Importance Scoring
The retrieval layer beneath agent memory is often a fixed
scoring function. Dense retrieval scores candidates by em-
bedding similarity; BM25 (Robertson and Walker 1994)
scores by lexical statistics; and hybrid methods such as
SPLADE and ColBERT combine lexical and semantic
matching through learned sparse expansion or late interac-
tion (Izacard et al. 2023; Formal, Piwowarski, and Clinchant
2021; Khattab and Zaharia 2020). Generative Agents add a
write-time LLM importance rating to recency and relevance,
but the importance term is static (Park et al. 2023). The
closest prior work is RMM, which introduces Retrospective
Reflection: an LLM assigns binary citation scores to retrieved
memories, and those scores train a lightweight reranker with
REINFORCE (Tan et al. 2025). RMM shares MEMOIR’s in-
tuition that generation-time attribution can improve retrieval,
but it operationalizes that intuition as a training loop. MEM-
OIR instead updates wimp as a closed-form running statistic,
requiring no reranker training and no write-path LLM call.
2.3
Long-Horizon Memory Benchmarks
We evaluate MEMOIR primarily on LoCoMo, a long-
conversation benchmark spanning up to 32 sessions per dia-
logue with single-hop, multi-hop, temporal, and adversarial
query categories (Maharana et al. 2024). We also consider
LongMemEval-S, which targets memory abilities such as


information extraction, multi-session reasoning, and knowl-
edge updates (Wu et al. 2024). These benchmarks are appro-
priate for MEMOIR because TRACE-FB requires repeated
retrieval events across sessions; single-session QA bench-
marks cannot exercise a feedback loop that accumulates im-
portance over time. The broader agent-memory evaluation
literature also motivates avoiding expensive write-time ex-
traction when coarser retention can preserve more answer-
able evidence (Zhou et al. 2026).
2.4
Retrospective Credit Assignment
MEMOIR is conceptually related to Hindsight Experience
Replay, which relabels failed trajectories with achieved goals
after the fact so that agents can extract learning signal from
outcomes not anticipated at decision time (Andrychowicz
et al. 2017). TRACE-FB applies an analogous idea to mem-
ory: rather than relabeling a trajectory goal, it revises a
memory’s importance after observing whether that memory
contributed to a successful answer. Unlike reinforcement-
learning approaches, TRACE-FB operates entirely at in-
ference time and does not require environment rollouts or
policy-gradient updates. Recent work has begun to apply
hindsight-style reasoning directly to memory-write credit
assignment: HiMPO treats each memory update as a state-
writing transition and compares the updated memory against
the prior memory under the same pre-write state, using hind-
sight relevance as a retrospective filter for policy optimization
(Yan et al. 2026). TRACE-FB targets the same underlying
question: how necessary was a given memory to a success-
ful answer, but resolves it as a closed-form running statis-
tic rather than a trained reward signal, requiring no policy-
gradient updates or reward-model training. Concurrently,
RL-aligned lifecycle controllers such as Fine-Mem (Ma et al.
2026) and Agentic Memory (Yu et al. 2026) train policies
to jointly control storage, summarization, and hard deletion.
However, learned pruning policies typically assume station-
ary distractor distributions; in open-ended multi-session di-
alogues, evidence utility is non-Markovian and restless, a
memory dormant for ten sessions may become critical for
a later multi-hop query (where utility-based hard pruning
destroys required evidence in 63.6%–83.9% of audited oper-
ations; Appendix H). Similarly, unlike reflective knowledge-
flagging frameworks (e.g., Mozilla CQ) that require on-
line LLM self-assessment calls after each session, MEM-
OIR maintains a 6.8ms zero-LLM online write path through
closed-form outcome attribution and restricts compression
to non-destructive, empirical judge-certified merges.

Proposed Methodology
3.1
Problem Formulation
Let Mt = {m1, . . . , mn} be the memory store before query
qt. Retrieval returns Rt ⊂Mt, the agent produces answer
at, and feedback yields an attribution value τt,i for each
retrieved memory. Each item stores an importance value
wimp(mi) and retrieval count ni. During a sleep phase, a
candidate cluster C ⊂Mt may be replaced by a merged item
z, or an ordered pair (mo, mn) may be proposed as an older
and newer statement of the same evolving fact. MEMOIR
optimizes two coupled objectives: improve evidence recall
through retrospective credit while allowing only judge-gated
lifecycle changes intended to preserve answerability or ex-
plicitly retire stale evidence with provenance.

3.3
Certified Temporal Supersession
Judge-gated merge removes redundancy but cannot represent
a fact that becomes obsolete. MEMOIR therefore includes an
optional SUPERSEDE operator for contradiction and tem-
poral updates. Candidate pairs are ordered by timestamp and
proposed when the newer item mn is semantically close
to the older item mo (cosine similarity at least 0.85) and
TRIAGE-α, a lightweight lexical negation and contradiction
detector, flags a conflict signal wconf. This proposal stage is
intentionally conservative: similarity alone indicates topical
overlap, whereas the conflict signal identifies pairs for which
retaining both items as concurrently valid may serve stale
evidence.
The candidate pair is evaluated by three judge framings
that test direct replacement, temporal precedence, and ad-
versarial compatibility. Each judge returns SUPERSEDES
or INDEPENDENT; the operation is accepted only when the
fraction of SUPERSEDES verdicts exceeds a separate thresh-
old τs (operating point τs = 0.6, matching the MERGE
judge threshold). Appendix B gives the prompt templates.
On acceptance, mo is marked as retired rather than physi-
cally deleted, and the newer item retains links to both source
records. This reversible representation preserves the audit
trail and permits rollback if a later query reveals that the
statements were conditionally compatible rather than contra-
dictory.
Because supersession changes the valid content rather than
compressing equivalent content, it uses discounted rather
than full credit transfer:

3.5
Closed-Loop Interaction
The lifecycle mechanisms share one invariant: an item may
retain retrieval credit only while it retains the evidence that
earned that credit. TRACE-UCB identifies frequently use-
ful memories and protects them during consolidation; an
accepted merge is intended to preserve equivalent support,
transfers the maximum credit, and redirects co-citation struc-
ture to the replacement. Under a closure-preserving merge,
a query answerable through a constituent remains answer-
able through the merged item, so transferred credit remains a
valid predictor of usefulness. An uncertified or lossy merge
can instead inherit credit for evidence it no longer contains,
corrupting the relationship between wimp and future utility.
SUPERSEDE therefore retires stale support reversibly and
transfers only discounted credit because the valid fact has
changed. Conversely, UCB continues to probe low-exposure
items, preventing lifecycle decisions from being based only
on a self-reinforcing retrieval history. An additive DIGEST
operator is implemented but evaluated separately because
it synthesizes new session facts without removing source
memories.
4
Experiments and Results
Experiments examine systems positioning (RQ1), retrospec-
tive retrieval and exploration (RQ2), attribution validity and
cost (RQ3), and consolidation safety and lifecycle consis-
tency (RQ4).
4.1
Datasets
LoCoMo contains 1,986 questions over ten evolving dia-
logues; after deduplication, 1,905 pairs are evaluated with
memory-level evidence labels. LongMemEval-S contains
500 single-query dialogues with session-level evidence. The
protocols are reported separately because only LoCoMo can
exercise repeated feedback, whereas LongMemEval-S tests
cold-start retrieval across a broader set of stores.
4.2
Experimental Setup
All experiments are conducted on LoCoMo and Long-
MemEval. The primary metric is evidence recall@5 —
the fraction of annotated supporting memories in the top
five retrieved items. The RQ1 systems comparison uses
the full benchmarks, top-15 retrieval, and five independent
runs; RQ2–RQ4 use 1,905 deduplicated LoCoMo pairs with
k = 5. Primary LoCoMo inference uses 10,000 bootstrap
resamples over the ten stores; question-level bootstrap is a
sensitivity analysis, and leave-one-store-out folds test con-
sistency. Consolidation is evaluated using fixed-budget, text-
grounded recall, active-store tokens, and an independent
model-family audit. For RQ4, ∆r = rpost −rpre is retained
as a secondary credit-ledger diagnostic. Matched baselines
use sleep interval 8 and τc = 0.6.


Sequential Evaluation Protocol. For multi-session Lo-
CoMo dialogues, queries q1, . . . , qT are processed sequen-
tially in dataset order over each shared dialogue store without
state resets between queries. Crucially, for every query qt,
top-k retrieval and Recall@5 / QA evaluation strictly pre-
cede the retrospective TRACE importance update and UCB
count increment, preventing intra-query leakage.
Baselines. We compare MEMOIR with LoCoMo-agent (Ma-
harana et al. 2024), MemoryBank (Zhong et al. 2024), Zep
(Rasmussen et al. 2025), Mem0/Mem0g (Chhikara et al.
2025), A-MEM (Xu et al. 2026), MemOS (Li et al. 2025),
and LiCoMemory (Huang et al. 2026).
4.3
RQ1: How Does MEMOIR Position Against
Established Memory Systems?
All Llama-block rows use Llama-3.1-70B-Instruct-Turbo.

4.5
RQ3: Do Attribution Signals Track Retrieval
Success Efficiently?
We evaluate online-path efficiency and the association
between attribution scores and retrieval success on one
NVIDIA RTX 3090 24GB GPU over 1,905 deduplicated
LoCoMo QA pairs. MEMOIR writes a memory in 6.8ms
P50 with no write-path LLM call, compared with ap-
proximately 110ms for write-time extraction baselines (Ta-
ble 4). Search (k = 5) and lexical TRACE feedback require
10.5ms and 6.7ms P50, respectively, while counterfactual
TRACE-CF requires 67.0ms P50. Both attribution signals
correlate significantly with evidence recall (Table 5): lex-
ical TRACE achieves r = 0.447 (95% CI [0.412, 0.481],
p < .0001), while TRACE-CF achieves r = 0.493 (95%
CI [0.458, 0.527], p < .0001). A paired bootstrap test con-
firms that TRACE-CF’s +0.046 correlation advantage is
significant (95% CI [+0.011, +0.081], p = .0128), show-
ing a stronger association with evidence-recall success than
surface-form unigram matching, at an approximately ten-
fold median feedback-latency cost (67.0ms versus 6.7ms).
To compute query-level association in Table 5, per-memory
attribution scores τt,i are mean-aggregated over the top-
k retrieved set Rt and correlated against binary query-
level evidence-recall success. Lexical TRACE-FB captures
90.7% of counterfactual TRACE-CF’s Pearson correlation
(r = 0.447 vs. r = 0.493, p = .0128) at one-tenth the me-
dian latency (6.7ms vs. 67.0ms P50) and zero LLM calls,
forming an explicit operational Pareto frontier. Periodic of-
fline consolidation, executed every eight queries, processes
multi-framing merge certificates in 2.85s P50 without block-
ing the online query path.

5
Limitations
TRACE-UCB requires repeated queries over a shared store
and cannot improve cold-start queries. Verified self-feedback
recovers most of the oracle gain but still depends on cal-
ibrated self-consistency or judge scores and may reinforce
irrelevant evidence when the model is confidently wrong.
Lexical TRACE can miss paraphrases, numbers, and short
evidence, whereas TRACE-CF incurs substantially higher la-
tency. Certified merge is an empirical safety gate rather than
a formal guarantee: unforeseen future evidence may still be
lost, and 0 losses among 100 audited merges retains a 2.95%
one-sided 95% upper bound. Its 1.42% active-store reduc-
tion is also modest and does not represent total storage sav-
ings because originals are archived for rollback. Results are
concentrated on ten LoCoMo stores, while LongMemEval
does not exercise repeated feedback. Future work should
evaluate additional evolving-store benchmarks, calibration
under distribution shift, larger human and cross-model au-
dits, matched-backbone end-to-end QA, privacy-aware ex-
ploration, calibrated certificates, and reversible pruning that
provides meaningful capacity reduction without sacrificing
provenance.
6
Conclusion
MEMOIR frames long-horizon agent memory as a cou-
pled lifecycle: screen prospectively and attribute retro-
spectively. On 1,905 LoCoMo QA pairs, the full retrieval
stack gains 11.92 points over bare cosine. TRACE with-
out UCB gains a non-significant 0.42 points; UCB with
raw autonomous feedback gains 1.13 points; confidence-
gated verified self-feedback gains 1.50 points; and or-
acle attribution gains 1.84/8.05 overall/multi-hop points,
with verified and oracle effects positive across all ten
folds. In matched Llama-3.1-70B experiments, MEMOIR
reaches 58.70%/61.20% accuracy/recall on LoCoMo and
81.20%/85.10% on LongMemEval-S at 0.2k tokens and
1.18 s latency, with a 6.8 ms LLM-free write path. Prospec-
tively, 100 empirical judge-certified merges reduce active-
store tokens by 1.42% while raising fixed-budget Rec@5
from 58.82% to 59.08%, with 0/100 audited losses (one-
sided 95% exact Clopper–Pearson upper bound ≤2.95%)
versus 18/100 for uncertified merging. Evidence remains
concentrated in ten LoCoMo stores, and real-scale SUPER-
SEDE evaluation is future work. Overall, MEMOIR reduces
the lifecycle to one closed loop: attribute usefulness after
use, and certify preservation before compression. Ethics are
detailed in the Supplementary Material.

Algorithm
Algorithm 1 summarizes the full closed-loop procedure ref-
erenced in the main paper’s Methodology section. Below we
walk through every function and symbol used in the pseu-
docode.
Online path (lines 1–6, executed per query).
• Line 1: SRQ(qt, m) is the RECALL-Q retrieval score
(dense similarity, lexical overlap, relevance, importance,
and the MMR diversity penalty, combined as in the main
paper’s Methodology); bt(m) is the UCB exploration
bonus that favors under-exposed memories. In the no-
tation of main-paper Equation 6, the deployed config-
uration sets the explicit recency coefficient to δ = 0,
so δwrec contributes zero. Temporal effects instead en-
ter through chronological active-store ordering, while
Dmmr controls redundancy rather than time. TopK se-
lects the k memories in Mt with the highest combined
score SRQ(qt, m) + bt(m), forming the retrieved set Rt.
• Line 2: LLM(qt, Rt) denotes the answer-generation call:
the backbone language model produces answer at con-
ditioned on the query and the retrieved memories. For
the deployed lexical TRACE path, this is the only online
LLM call. The optional TRACE-CF ablation performs
additional leave-one-out model-scoring calls after answer
generation.

computes
the

τt,i (via lexical overlap in the training-free default, or

• Line 7: Sleep(t) is a scheduling predicate that is true
only at periodic offline checkpoints (every eight queries
in the reported experiments), never during normal query
handling.
• Lines 8–12 (MERGE): For each candidate cluster C ⊂
Mt proposed from embedding similarity and co-citation
structure, g(C) denotes the merge generator that produces
a shorter candidate entry z. The merge is applied only if
all three gates pass: c(C, z) is the fraction of LOSSLESS
verdicts from the three-framing FaithfulnessJudge ensem-
ble (Section B); κ(C, z) is retrieval-token coverage, com-
puted after lowercasing and removing the NLTK English
stopword list with multiset token counts; and η is the
hard length ratio bounding |z| relative to the combined
length of the originals. When accepted, C is replaced
by z, provenance is preserved, z inherits the maximum
importance, and its retrieval count is nz = maxm∈C nm.
• Lines 14–18 (SUPERSEDE): For each ordered conflict
pair (mo, mn) flagged by the SUPERSEDE proposal
stage (Section B.1), SupersedeCert(mo, mn) is the frac-
tion of SUPERSEDES verdicts from the three-framing
SUPERSEDE judge ensemble (direct replacement, tem-
poral precedence, adversarial compatibility). The operat-
ing point is τs = 0.60, so at least two of the three judges
must return SUPERSEDES. When accepted, the older
item mo is retired reversibly (marked inactive rather than
deleted), the newer item mn receives discounted credit,
and its exposure count becomes nmn ←nmn + nmo.

the updated store Mt+1, ready for the next query.
This structure keeps the two lifecycle halves cleanly sep-
arated by execution context: attribution and importance up-
dates happen synchronously with every query, while con-
solidation and supersession are deferred to periodic offline
sleeps. The deployed lexical path requires no additional LLM
call on the online write or retrieval path; TRACE-CF is an
explicitly optional, higher-cost attribution ablation.
The deployed state-transfer rule prevents consolidation
from creating an artificially under-exposed replacement. Af-
ter MERGE, the replacement receives the maximum con-
stituent retrieval count, nz = maxm∈C nm. After SUPER-
SEDE, the newer item accumulates the older item’s exposure,
nmn ←nmn + nmo. Reliability pass/trial counters belong
only to the reported reliability-bonus ablation and are not
part of the deployed lexical TRACE-UCB state.

Full Prompt Templates
The merge generator receives the source entries and the fol-
lowing instructions: combine them into one shorter entry;
preserve every unique fact, entity, number, date, qualifier,
relation, and contradiction; remove only redundant phrasing;
maintain temporal order; introduce no unsupported infor-
mation; and output one concise paragraph. A candidate is
not applied merely because it is shorter. Figure 2 gives the
three FaithfulnessJudge certification prompts, and Figure 3
gives the merge-generation prompt and the three application
guards.
The certificate score is the fraction of LOSSLESS votes.
The main operating point uses τc = 0.6, retrieval-token
coverage τr = 0.45, maximum length ratio η = 0.9, and
high-credit protection threshold wimp = 0.3. For cover-
age, source and candidate text are lowercased, tokenized,
and filtered with the NLTK English stopword list. With
fC(x) and fz(x) denoting the resulting multiset counts,

SUPERSEDE proposal and execution.
Candidate pairs
are ordered by timestamp and proposed without an LLM

judge must distinguish a true update from two facts that

Only a certificate meeting τs = 0.60 retires the older item;
with three judges, this is a two-of-three rule. Retirement
is reversible: the old item is marked inactive rather than
deleted, and the record stores both identifiers, timestamps,
judge verdicts, and the replacement link. Because the content
changes, only discounted credit is transferred, wimp(mn) ←
max(wimp(mn), 0.5wimp(mo)), while historical exposure
is accumulated as nmn ←nmn + nmo.
Exploratory DIGEST.
DIGEST is an additive, session-
level synthesis operator and is not part of the evaluated
merge-only core. Its generator requests one short factual sen-
tence per line, including supported cross-entry relationships,
while forbidding invented facts, names, dates, quantities, or
relations. Unlike merge, DIGEST never removes its con-
stituents. Figure 5 gives the complete DIGEST generation
and faithfulness-certification prompts.
Uncertified whole-store baseline.
The summarize-all
comparator receives every live entry and requests a com-
pact set of notes preserving important facts, names, numbers,
dates, and relations. It has no candidate-selection stage, loss-
less certificate, retrieval-coverage gate, or length-ratio check.
The operation represents the aggressive endpoint of the com-
pression axis rather than a MEMOIR component. Because
it unions the source evidence identifiers onto a small num-
ber of surviving summaries, recall metrics based only on
identifier intersection can become artificially optimistic even
when the retrieved summaries are long or textually incom-
plete (see Table 21 for the empirical magnitude of this effect).
We therefore do not treat its raw evidence recall as proof of
answer preservation without an end-to-end QA check.

Limitations
TRACE-UCB requires repeated queries over a shared evolv-
ing store and therefore cannot improve the first query to a
fresh store. Confidence-gated self-feedback depends on cali-
brated confidence and can reinforce irrelevant evidence when
an answer is confidently wrong. Lexical TRACE can miss nu-
meric, short, and paraphrastic evidence, whereas TRACE-CF
incurs additional leave-one-out scoring latency. The factorial
table uses oracle reference feedback and does not establish
the same joint result for the deployed confidence-gated sys-
tem.
Certified merge is an empirical safety gate rather than a
formal guarantee. The primary extension observes 0 losses
among 100 audited merges, but its one-sided 95% operation-
level upper bound remains 2.95%, and operations produced
within the same store may be statistically dependent. The
1.42% reduction is an active-store saving rather than a total-
storage saving because originals are archived for rollback. Ta-
ble 17 reports the recovered |P| = 1,120 distortion denomi-
nator and policy-specific lost-probe counts. The preliminary
SUPERSEDE audit observes 0/24 invalid retirements but re-
tains an 11.73% one-sided upper bound. The credit-ledger
comparison is event-level, and its interval crosses zero; it is
therefore a secondary diagnostic rather than a system-level
safety guarantee.

Ethics Statement
Long-term agent memory can retain sensitive personal in-
formation across sessions. Deployments should use encryp-
tion, access control, retention limits, and data-minimization
policies. MEMOIR adds a specific fairness risk: if biased,
harmful, or privacy-sensitive memories repeatedly appear
in successful trajectories, retrospective importance revision
may increase their future retrieval probability. This risk is dis-
tinct from generic memory retention because it arises from
the feedback loop itself. Practical systems should combine
MEMOIR with content filters, user-controlled deletion, and
auditing of high-importance memories.
