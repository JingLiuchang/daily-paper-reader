Abstract 

With the rise of Group Agent such as Claude Tag, agents increasingly serve as digital work-ers for long-term team collaboration. These agents operate over shared contexts that con-tinuously accumulate through multi-user inter-actions. However, existing agent memory sys-tems are mainly designed for individual users and struggle to capture group-level knowledge in shared contexts, including group relation-ships and collaboratively formed knowledge. Manual memory strategies further limit adap-tation to diverse and evolving shared contexts. To this end, we propose EvoGroup (EvoG) ,a self-evolving harness for group agents that starts from a minimal six-tool cold start and adapts through interaction with shared con-text. EvoG uses confidence and task outcomes to select informative trajectories, while also eliciting self-reflections on uncertainty in low-confidence cases. The analysis agent then ex-amines selected trajectories through adaptive progressive disclosure, followed by bucketed analysis to synthesize high-level findings that guide the evolve agent in revising the Har-ness. Empirically, pass@1 on held-out split of EverMemBench improves from 71.07% to 89.58%, surpassing both self-evolving mem-ory and human-designed harnesses, including Claude Code (85.83%). To evaluate generaliza-tion, we freeze the evolved harness and evaluate it on the unseen GroupMemBench, where, with GPT-5.5, it demonstrates effective generaliza-tion and outperforms both memory baselines and human-designed harnesses. 1

This makes memory essential for agents to accurately extract and apply relevant information from long-term conversations. A Group Agent must not only understand current messages but also integrate discussion topics, key events, member roles, and group decisions from prior interactions. However, most existing agent memory systems are designed for single-user settings, organizing memory around individual experiences, prefer-ences, and interaction histories (Park et al., 2023; Zhong et al., 2024; Packer et al., 2023). In group settings, information is distributed across multiple users, topics, and reply threads, and events may be supplemented or reinterpreted by different mem-bers. These characteristics make it difficult for ex-isting memory systems to capture group dynamics and collaboratively formed knowledge (Yang et al., 2026a). In addition, existing memory systems typ-ically predefine how memory is represented, up-dated, and retrieved (Chhikara et al., 2025; Liu et al., 2026). For example, interaction histories may be stored in vector databases (Chhikara et al., 2025) or organized as knowledge graphs (Anokhin 1arXiv:2611.03868v1 [cs.CL] 2 Nov 2026 et al., 2024), with fixed mechanisms for updating outdated or conflicting information (Fang et al., 2026). When group structures, shared contexts, or task requirements change, adapting these systems often requires redesigning their memory storage or retrieval mechanisms. Such predefined designs limit the ability to adapt to different groups. To address these challenges, we propose 

EvoGroup (EvoG) , a self-evolving harness frame-work for Group Agent memory. EvoG starts from a minimal harness with only six tools and evolves through interaction. The evolution loop consists of four stages. (1) Interaction. The Group Agent uses the harness to answer queries over accumu-lated shared contexts, producing trajectories and confidence scores. For low-confidence queries, the agent additionally reflects on the reasons for its uncertainty before accessing the ground-truth. 

(2) Trajectory Selection. EvoG combines con-fidence with official evaluation to identify infor-mative trajectories, including confident-incorrect, unconfident-correct, and unconfident-incorrect. (3) Analysis. The analysis agent uses Adaptive Pro-gressive Disclosure (APD) to analyze selected tra-jectories, accessing trajectory details only when necessary. The agent also compresses detailed ra-tionales into concise rationales. To identify recur-ring issues across trajectories, the agent performs bucketed analysis by grouping rationales according to inferred query semantics and further aggregat-ing them into high-level findings. (4) Revision. 

Finally, the evolve agent uses analysis outputs to revise the Harness, producing Ht+1 for the next round of interaction. Through this loop, EvoG en-ables the harness to continuously adapt to the group and shared context. We conduct extensive experiments to evalu-ate the effectiveness of EvoG . After evolution, the pass@1 of DeepSeek-V4-Flash on held-out split of EverMemBench improves from 71.07% to 89.58%, outperforming the human-designed Har-nesses Codex (82.62%) and Claude Code (85.83%), as well as the strongest self-evolving memory base-line (55.95%). Across two additional backbone models, EvoG consistently improves pass@1 by 15.36–16.19 pp. To evaluate generalization beyond the evolution distribution, we freeze the evolved harness and apply it to GroupMemBench without further adaptation, where it continues to outper-form self-evolving memory baselines and Claude Code. We further conduct component and process-level ablations and analyze capability transitions, confidence, self-reflection, APD analysis, and har-ness revisions to better understand how EvoG 

evolves. Together with our findings and open-source release, we hope EvoG inspires future ef-forts toward more capable and adaptive Group Agents.

2.2 Confidence-Guided Trajectory Selection 

During continuous interaction, different trajecto-ries provide different evolutionary signals for self-evolution. We therefore combine the Agent’s con-fidence with official evaluation results to select in-formative trajectories. After the interaction, an official evaluator sup-plies an external correctness signal yi ∈ { 0, 1} for the answer ai. Combining yi with the confidence indicator zi = 1[ci > γ ] partitions the collected trajectories into four groups: 

DCC = {τi | zi = 1 , y i = 1 },

DCW = {τi | zi = 1 , y i = 0 },

DUC = {τi | zi = 0 , y i = 1 },

DUW = {τi | zi = 0 , y i = 0 }.

(3) The confident-and-correct subset DCC represents routine successful behavior and is not prioritized for diagnosis. EvoGroup instead selects 

Dsel = DCW ∪ D UC ∪ D UW , (4) which covers three complementary signals. Con-fident but incorrect trajectories reveal undetected reasoning failures or answer biases; unconfident but correct trajectories indicate fragile successes; and unconfident and incorrect trajectories capture failures that the Group Agent can partially recog-nize. 

2.3 Trajectory Analysis 

Agent trajectories contain numerous tool calls, ob-servations, and shared-context details, making it difficult to locate the evidence responsible for a failure. EvoGroup addresses this challenge at two levels: it first uses Adaptive Progressive Disclosure 

(APD) to inspect and attribute individual trajecto-ries on demand, and then uses bucketed analysis to aggregate recurring issues across trajectories into high-level findings. 

APD Analysis. Rather than loading an entire, po-tentially long interaction into context at once, APD initially keeps the full trajectory hidden and ex-poses only a compact structural view. The Anal-ysis Agent first locates a potentially problematic stage and then jumps to the corresponding local segment, requesting additional observations, ac-tions, tool results, or communication records only when needed. This on-demand access focuses the analysis on diagnostically relevant evidence while reducing distraction from unrelated parts of the trajectory. 2.4 Harness Revision 

To enable more comprehensive and effective har-ness revision, we organize updates into four com-plementary interfaces: representation, operation, intervention, and policy, each targeting a distinct aspect of harness behavior to support continuous self-evolution from interaction. 

Representation. This interface modifies how infor-mation is represented, organized, and linked within the Harness, without changing selection strategies. Updates include restructuring memory units, entity relations, working memory, and the context pro-vided to the underlying model. Operation. This in-terface adds or modifies executable capabilities and their implementations, such as introducing query tools or revising retrieval algorithms. It determines what the harness can execute and how each opera-tion is implemented. Intervention. This interface introduces checks, transformations, or constraints at execution boundaries, such as validating tool ar-guments before calls, normalizing returned results, and verifying outputs before returning them as fi-nal answers. Policy. This interface modifies the rules governing operation selection, timing, and ordering. Updates include adjusting prompts, skill invocation rules, retrieval parameters, search strate-gies, and operation composition and scheduling. Based on this distinction, the Evolve Agent selects the interface or interfaces that directly address each diagnosed issue. 

3 Experiments 

3.1 Setup Benchmark & Baseline Methods. We use multi-party conversation benchmarks to evaluate the memory capabilities of group-chat agents. Ev-erMemBench (Hu et al., 2026) is divided using stratified sampling, with 30% used as the held-in set for harness evolution and the remaining 70% used as the held-out set for evaluating the evolved harness. To evaluate cross-benchmark transfer, we then freeze the evolved harness and evalu-ate it on GroupMemBench (Yang et al., 2026b). We compare EvoGroup with structured-memory and self-evolving memory baselines, as well as human-designed agent Harnesses, including (1) FullContext, (2) Mem0 (Chhikara et al., 2025), (3) MemOS (Kang et al., 2025), (4) A-MEM (Xu et al., 2025), (5) MemRL (Zhang et al., 2026b), (6) Codex (OpenAI, 2025), and (7) Claude Code (Anthropic, 2025). 

Models. For the evolution iterations and frozen transfer experiments (Sections 3.2, the Group Agent, Analysis Agent, and Evolve Agent use the same base model within each run. We eval-uate three model configurations: GPT-5.5 (Ope-nAI, 2026a) with the non-thinking reasoning set-ting, DeepSeek-V4-Flash (DeepSeek-AI, 2026), and GLM-5.1 (GLM-5 Team et al., 2026). 

Metric. We evaluate task effectiveness using 

pass@1 . Each task is attempted once per eval-uation run and is considered successful if it passes the official verifier. The final score is the proportion of successfully completed tasks. Trials terminated by system-level failures, such as timeouts, crashes, or missing outputs, are counted as unsuccessful. 3.2 Main Results 

As shown in Table 1, we evaluate EvoGroup on GPT-5.5, DeepSeek-V4-Flash, and GLM-5.1. Af-ter six self-evolution iterations, EvoGroup iden-tifies the best-performing harness configuration, denoted by H∗. On the held-out dataset, com-pared with the initial configuration H0, H∗ im-proves the average pass rate by 16.2, 18.5, and 15.4 pp on the three models, respectively, demon-strating EvoGroup’s ability to consistently discover substantially better configurations. Meanwhile, EvoGroup outperforms the Structured Memory and Self-Evolving Memory baselines, as well as Claude Code and Codex, across all three backbones, except that its performance on GPT-5.5 is slightly below both Codex and Claude Code. However, since the evolution process is not limited to the number of iterations evaluated in our experiments, further it-erations may yield additional performance gains. These results demonstrate that EvoGroup consis-tently discovers substantially stronger memory harness configurations across LLM backbones with different capabilities. Generalization beyond the evolution benchmark. 

To evaluate whether the evolved harness general-izes beyond the distribution used for evolution, we freeze the harness evolved on EverMemBench and directly evaluate it on the unseen GroupMemBench without further adaptation. As shown in Table 4, on GPT-5.5, the evolved harness achieves the highest average pass rate of 63.89%, outperforming the ini-tial harness by 2.01 points and the strongest human-designed harness by 8.46 points. On DeepSeek-V4-Flash, it achieves 71.14%, remaining within 52.95 points of the initial harness and 5.37 points of Codex, while outperforming the strongest mem-ory baseline by 28.46 points. These results show that EvoG can transfer to an unseen benchmark while maintaining strong performance, although some performance degradation is observed with DeepSeek-V4-Flash. 3.3 Ablation Study Component-level ablations. We evaluate the con-tribution of each harness component by replacing one component of the initial harness with its coun-terpart from the fully evolved harness, while keep-ing all other components unchanged. We consider Prompt, Tools, Middleware, Memory, and Skills separately. As shown in Figure 3, Tools and Prompt provide the largest gains, improving accuracy by 10.90 and 7.41 pp, respectively. Middleware, Mem-ory, and Skills yield smaller gains of 1.27, 1.47, and 0.86 points. Using all evolved components achieves 89.58% accuracy, an 18.51 pp improve-ment over the initial harness at 71.07%. These results show that EvoGroup improves the harness through multiple components rather than prompt optimization alone. 

Process-level ablations. We further examine three mechanisms in the self-evolution loop us-ing DeepSeek-V4-Flash. All variants use the same cold-start harness configuration, evolution set, and token budget. As shown in Figure 4, removing tra-jectory selection increases Pass@1 from 73.33% to 74.86%, with a peak of 75.69%. Thus, analyzing all trajectories can support self-evolution, but requires more analysis time and greater token consumption. Replacing APD with full-trace analysis yields a final Pass@1 of 69.44%, below its initial score. This suggests that, in shared-context task settings, directly analyzing complete trajectories may in-troduce irrelevant information and noise, whereas APD enables the Analysis Agent to focus on di-agnostically relevant evidence and produce more effective evolution signals. Removing bucketed analysis produces the lowest final Pass@1 of 67.08%. Without cross-trajectory aggregation, individual diagnoses may miss recur-ring failure patterns, resulting in more instance-specific and less reliable harness updates.

3.6 Analysis of Self-reflection 

To assess the agreement between self-reflection and trajectory-based diagnosis, we adopt three measures: localization-agreement, cause attribution-agreement, and diagnostic-evidence consistency. Localization-agreement reaches 84.0% for DeepSeek-V4-Flash and 74.4% for GPT-5.5, suggesting that self-reflection can often identify where a problem likely occurs without examining the full trajectory. In contrast, cause attribution-agreement is 49.2% and 62.0% for the two models, while diagnostic-evidence consistency is only 7.1% and 16.8%, respectively. These results indicate that self-reflection can provide a valuable yet not fully reliable localization signal before the full trajectory is read, directing the Analysis Agent toward likely problem regions and offering a more efficient, token-saving diagnostic pathway for harness self-evolution. Nevertheless, accurately verifying the root cause with sufficient evidence still relies on full trajectory analysis. Further improving the agent’s autonomous error-localization ability could reduce this reliance and further accelerate the harness self-evolution loop. 4 Related Work 

Agent Memory. Agent memory aims to store and retrieve interaction information to support sub-sequent tasks (Park et al., 2023; Packer et al., 2023; Zhong et al., 2024). Existing methods typi-cally organize memory using predefined structures (e.g., trees or graphs), combined with mechanisms such as profiling, reflection, and semantic compres-sion (Park et al., 2023; Shinn et al., 2023; Packer et al., 2023; Chhikara et al., 2025; Xu et al., 2025; Fang et al., 2026; Liu et al., 2026). However, their memory storage and retrieval mechanisms are rel-atively fixed, making it difficult to adapt memory management to task requirements. Recent work has begun exploring self-evolving memory by opti-mizing memory operations through reinforcement learning or improving memory construction and up-dating (Yan et al., 2025; Xu et al., 2025; Liu et al., 2026). However, these methods primarily target single-user. Hu et al. (2026); Yang et al. (2026b) have begun to investigate group-chat memory and its evaluation. Unlike single-user memory, group-chat memory must integrate information distributed across speakers, sessions, and temporal states while preserving user attribution, entity relationships, and contextual dependencies. To overcome the limi-tations of single-user designs and fixed memory paradigms, we propose EvoG, which enables mem-ory mechanisms to evolve continuously based on interaction feedback. 

Agent harness. An agent harness is a framework that organizes memory, planning, tools, and ac-tion policies around a foundation model to sup-port agent-environment interaction. (Tang et al., 2026). Existing studies adapt harnesses through self-improvement, programmatic optimization, tra-jectory analysis, and code generation to improve task performance and adaptability (Lin et al., 2026; Huang et al., 2026; Chen et al., 2026; Zhou, 2026; Zhang et al., 2026a; Ning et al., 2026; Xu et al., 2026; Banu, 2026). However, most target coding, lacking efficient diagnostics for long interaction tra-jectories. In multi-user shared contexts, evidence scattered across speakers, sessions, and temporal states creates lengthy, interconnected trajectories, making full-trace analysis costly and prone to irrel-evant information. To address this challenge, we propose EvoGroup. 

5 Conclusion 

In this work, we introduce EvoGroup, a self-evolving harness for group agent memory. By treating the harness as an evolvable system and learning evolution signals in the shared context, EvoGroup enables Group Agents to autonomously 8adapt to diverse groups. Result demonstrates that EvoGroup improves efficiency while maintaining strong performance. In the future, we will explore more realistic collaborative scenarios with diverse and long-term multi-user.

C Evolution Protocol 

C.1 Trajectory Analysis and Harness Revision 

Let T = {xi}Ni=1 be the fixed evolution questions and Ht be the harness at round t. An interaction produces trajectory τ ti = Interact( Ht, x i), the Agent’s confidence pti ∈ [0 , 1] , and the judge’s answer-correctness label yti ∈ { 0, 1}. The trajec-tory records the messages, tool requests and ob-servations, memory operations, and final answer. A timeout or infrastructure exception is recorded separately from a judged incorrect answer. At confidence threshold γ = 0 .5, semantic tra-jectories are assigned to confident-correct (CC), confident-wrong (CW), unconfident-correct (UC), or unconfident-wrong (UW), where “confident” means ci > γ . Low-confidence trajectories also receive a self-reflection, used as diagnostic evi-dence without changing their official correctness label. The Analysis Agent first inspects address-able summaries and retrieves full trace segments when it needs to verify a finding. It synthesizes re-curring patterns across questions before the Evolve Agent proposes changes to the harness components: skills, prompts, middleware, tools, and memory. Each proposal includes a change manifest and its predicted repair and regression risks. The result measured at round t belongs to Ht. A candidate Ht+1 is only a proposal until it has been executed and evaluated in a subsequent round. The evolution set is used to select a checkpoint; results on a separate test set are reported independently.
