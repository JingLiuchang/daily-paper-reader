# From Benchmarks to Behaviors: A Framework for Auditing AI Agents 

# Nick Hagar October 2026 

Abstract 

Generative AI systems increasingly mediate access to information. Their behavior depends on tools, instructions, and user memories that are often difficult for researchers to observe or control. Here, I introduce TRACE (Transparent Research on Agent Contexts and Environments), a framework for systematically auditing how these components shape AI agent behavior. Built on an open-source agent harness, TRACE enables controlled manipulation of system components. It also records inputs, outputs, and task execution for downstream analysis. I demonstrate this framework through an experiment examining how user memories influ-ence source selection when agents answer questions about the 2026 U.S. midterm elections. I find that memories expressing explicit preference for a publisher increase its inclusion among the first three cited sources in a response by 33-39 percentage points. Memories identifying the user as a Republican or expressing distrust of mainstream media shift cita-tions rightward. That same media distrust memory also increases cita-tion of sources expressing misinformation or conspiracy theories by 6.3 percentage points, with substantial variation across models. These find-ings demonstrate that concise user memories can alter source selection in consequential settings, even when questions and search results remain fixed. TRACE extends algorithm auditing to agent harnesses, providing a transparent way to study agent behaviors that benchmarks or commercial interfaces may struggle to isolate. 

# 1 Introduction 

Consumer-facing generative AI (GenAI) tools like ChatGPT and Claude have permeated many tasks that were formerly the domain of search engines. Con-sumers now turn to generative AI for information about health (Wardle et al., 2025), politics (Luettgau et al., 2025), and current events (Simon et al., 2025)— in one September 2025 survey, 4% of respondents reported completely replacing Google searches with chatbot questions (On Marketing, 2025). Even for users who rely primarily on Google, features like AI Overviews introduce synthesized 1arXiv:2611.03939v1 [cs.HC] 2 Nov 2026 answers generated by large language models into conventional search results (Chapekis and Lieb, 2025). GenAI has become a consequential information intermediary. Prior work has established that information intermediaries are not neutral brokers of credible information. Across platforms, algorithm audits have docu-mented instances of imbalanced or nonrepresentative search results (Trielli and Diakopoulos, 2019; Diakopoulos et al., 2021), preferential treatment of plat-forms’ own offerings within search results (Kim and Luca, 2019), and the ap-pearance of incorrect or harmful information in response to sensitive queries (Ghezzi et al., 2020). Initial audits of GenAI search systems have started to identify similar concerns—for example, citations that do not substantiate the statements they accompany (Liu et al., 2023) or source selection driven by pub-lishers’ political leanings (Dai et al., 2025). Algorithm audits are crucial to understanding how technologies influence the information that their users receive. They are also technically challenging to conduct (Hannak et al., 2013; Robertson et al., 2018) and further complicated by several common aspects of GenAI systems. First, the probabilistic outputs of large language models (LLMs) can vary substantially across repeated invoca-tions of the same query (Manakul et al., 2023). Second, in addition to the LLM, a GenAI system’s behavior depends on its harness : the accompanying tools, in-structions, context management, and guardrails that operate in the background to shape behavior and outputs (Li et al., 2026b). Finally, memory features in GenAI systems can retain information from prior interactions and use it to personalize subsequent responses, potentially shaping the information users en-counter (Chandrasekar, 2026). These factors create compounding opportunities for variance in the kinds of information a tool surfaces, conditioned on factors that are difficult or impossible for a researcher to observe. To better understand how GenAI systems surface information, researchers require a transparent and systematic way to scrutinize their components. Here, I propose TRACE (Transparent Research on Agent Contexts and En-vironments), an evaluation framework that allows researchers to systematically inspect how the internal workings of a GenAI system impact its behavior and responses. TRACE uses Pi, an open-source and customizable harness for GenAI agents (Pi contributors, 2026d), as a transparent platform for selectively vary-ing system prompts, user memories, and tool behavior. As part of this work, I make an open-source implementation of TRACE available via the JavaScript package registry npm. 1

To demonstrate the capabilities of TRACE, I audit how user memories shape the sources six LLMs cite when answering questions about the 2026 U.S. midterm elections. Across 3,000 trials with fixed search results, memories ex-pressing a preference for a particular publisher increase its inclusion among the first three cited sources in a response by 33–39 percentage points. Memories identifying the user as a Republican or expressing distrust of mainstream media shift citations rightward. The memory expressing media distrust also increases

# 2 Background 

An increasingly consequential aspect of GenAI development is the harness , the set of tools, instructions, and other infrastructure that allows an LLM to in-teract with files and software (Li et al., 2026b). Harnesses enable agentic AI by connecting LLM outputs to actions in an external environment: An LLM in isolation generates text; a harness can interpret its requests, execute operations to read and write files, run software or web searches, and return the results to the model for subsequent decisions (Yao et al., 2023). These capabilities are surfaced in products like Claude Code and ChatGPT Work (Anthropic, n.d.a; OpenAI, n.d.b). Because agent harnesses provide an interface through which an LLM carries out complex actions, their design can substantially affect performance. Har-nesses often rely on a set of common components, such as tool interfaces, context and memory management, and code execution environments (Li et al., 2026b). The implementation of these components can vary: For example, Zhang et al. (2025b) identified at least 35 approaches to agent memory. And these variations in component design shift agent performance even when the underlying model remains fixed. SWE-agent, for example, demonstrates the effects of interface design on software engineering tasks, while Agent Workflow Memory shows how supplying reusable procedures improves web navigation (Yang et al., 2024; Wang et al., 2024). Alongside their technical implementation, the contents of agent harness components may also affect LLM behavior. Independent of harness design, prior work already establishes that LLMs exhibit social biases across a range of tasks. These include tendencies toward caricature when simulating political and marginalized groups (Cheng et al., 2023) and exhibiting political preferences in the sources they cite (Dai et al., 2025). Interacting with external systems intro-duces additional signals that can steer an LLM’s choices. When generating code, for example, LLMs demonstrate strong preferences for services from particular providers (e.g., Google and Amazon) and sometimes introduce those providers without being asked (Zhang et al., 2025a). More broadly, LLMs may fixate on one provider or disproportionately select options that appear in their context when choosing among functionally equivalent tools (Blankenstein et al., 2026). 3These patterns highlight several risks. Agents may select familiar or promi-nently presented options without evaluating how suitable they are to a task. Patterns in training data can amplify this tendency (Blankenstein et al., 2026). If recommendations or implementations by agents are concentrated on estab-lished providers, this may reinforce their advantages and make alternative ser-vices harder to discover (Zhang et al., 2025a). Such preferences may also shape the functionality and information made available to human users. Influences of this kind can appear in several key components of the agent harness. Tool descriptions present an agent with information about the actions it can take, such as searching the web, creating a file, or running a program. Agents are sensitive to the wording of these descriptions; editing them to be longer or more positive about a tool can increase the rate at which it is se-lected during a task (Blankenstein et al., 2026; Faghih et al., 2025). Similarly, when an agent looks for information, search results provide textual signals that may influence which sources it cites. Controlled experiments show that the identity of a news publisher can influence how often it gets cited, even when coverage is available from multiple outlets (Dai et al., 2025). In response to this, analogous to established search engine optimization practices, generative engine optimization seeks to increase the visibility of web content in synthesized answers (Aggarwal et al., 2024). In many agent harnesses, user memories may also influence how an agent approaches a task. Memory systems can extract and retain information from prior conversations (e.g., a person’s profession, ongoing projects, or preferences), and retrieve it in later interactions (Chhikara et al., 2025; Zhang et al., 2025b). This presents an implicit steering pathway for agent behavior: Prior work shows that both explicit prompts and user memories can increase LLM sycophancy (Jain et al., 2026). Because it is often not explicitly controlled by the user, that pathway might silently compound errors or retrieve prior interactions that are poorly suited to a new task, as studies of agent memory management have demonstrated (Xiong et al., 2025). Across these interacting components, AI agents present a wide range of op-portunities for external systems, human users, and their own prior actions to shape task outcomes. At present, systematically studying whether and how such influence manifests in agents presents several difficulties. First, effectively moni-toring agentic systems is complex, requiring both access to and interpretation of dense activity logs (Chan et al., 2024; Hugging Face, 2026). Second, even within a single task, many components may interact: An agent could use a memory about a user to formulate a web search, encounter signals in the results, and then draw on learned associations in its parametric memory to prioritize par-ticular sources. Research on memory retrieval and source selection establishes mechanisms through which these effects could arise (Zhang et al., 2025b; Dai et al., 2025). Untangling their contributions requires a way to vary individual components while controlling other aspects of execution. Finally, even getting access to these components varies depending on the deployment. Commercial products may provide memory settings, but they do not often provide complete control over or visibility into the underlying memory system (OpenAI, n.d.a; Li 4et al., 2026b). Such harnesses, then, do not provide the level of access needed for a controlled experiment. Existing efforts tackle some facets of these challenges. Benchmarks like Terminal-Bench and τ -bench offer a way to evaluate agents leveraging actual harnesses in complex environments (Merrill et al., 2026; Yao et al., 2025). Such environments support comparisons across models and implementations, with repeated trials. Recent work also broadens benchmark evaluation beyond task completion, to consider aspects like robustness, predictability, and the severity of failures (Rabanser et al., 2026). Observability tools provide more visibility into the process leading up to an agent’s final output. Frameworks like Inspect or Langfuse provide reusable components and a range of content and metadata in structured formats (UK AI Security Institute and Meridian Labs, n.d.; Lang-fuse, n.d.). These capabilities help researchers pinpoint failures and compare different approaches to executing a task. Such approaches often treat the agent as the unit of analysis, evaluating an LLM and its harness as a complete system. The influences reviewed above, however, enter through individual components that may be shaped by different parties (e.g., developers, publishers, and users). Establishing the effect that these components might have on agent behavior requires isolating them indi-vidually. Without such comparisons, a behavior cannot be attributed to the component that produced it, and harness designers have little evidence about which of their choices matter. Researchers therefore require a transparent, alterable, and reproducible ap-proach to understanding how aspects of agent design influence behavior across models and implementations. In the next section, I propose TRACE as an evaluation framework for carrying out these controlled comparisons. 

# 3 Design 

TRACE is designed to provide an evaluation framework that meets the three criteria laid out above: It provides transparency around agent behavior, allows changes to the individual components of the harness, and supports reproducible experiments. It builds on prior work in algorithm audits, in which researchers construct controlled inputs to a system (e.g., sock puppet accounts that differ in a single attribute) and measure systematic differences in outputs (Sandvig et al., 2014; Metaxa et al., 2021). Here, the provided inputs take the form of alterations to the way in which an agent is configured, and the system under study is an LLM operating inside a harness controlled by the researcher. In practical terms, TRACE is a software package for configuring and running experiments on AI agents. A researcher provides a configuration that specifies the tasks an agent will attempt, the LLM it will use, and the tools, instructions, and memories available to it. TRACE executes each task under the specified experimental conditions, runs each execution repeatedly to capture variation in LLM outputs, and saves a detailed record of the agent’s inputs, actions, and outputs. Researchers can then compare across conditions to examine how 5changes to particular harness components affect behavior. TRACE’s design draws on established approaches to agent evaluation. In-spect provides general-purpose evaluation, scoring, and logging, while the Holis-tic Agent Leaderboard (HAL) standardizes comparisons across models, scaf-folds, and benchmarks (UK AI Security Institute and Meridian Labs, n.d.; Kapoor et al., 2025). Those capabilities support systematic evaluation of agent behavior. TRACE further organizes such comparisons around interventions on individual harness components. # 3.1 Open Harness as Experimental Substrate 

TRACE is built on Pi, an open-source, MIT-licensed agent harness (Zechner, 2025; Pi contributors, 2026d). Pi is deliberately minimal, with a short system prompt and a limited set of available tools: reading, writing, and editing files, and running shell commands (Zechner, 2025). Additional functionality can be added via an extension system. Pi has also served as the underlying agent runtime of OpenClaw, a widely used AI personal assistant (Ronacher, 2026). Three properties make Pi well-suited to this purpose. First, its minimal and transparent implementation reduces the risk that opaque system components will influence agent behavior in ways that a researcher cannot observe (Zechner, 2025). Researchers can inspect the system prompts, tool descriptions, and con-text assembled by the harness. Second, Pi’s extension system provides hooks at several points in the agent loop: before the agent begins a turn, before each model call, after each LLM provider-specific request is assembled, and before it is sent (Pi contributors, 2026a). Third, it supports multiple model providers, 6so the same harness and experimental configuration can be paired with models from different developers (Pi contributors, 2026c). This decouples LLMs from the harness in a way that many commercial products do not. It also partially addresses concerns about the reproducibility of research built on proprietary models (Spirling, 2023; Palmer et al., 2024): Even with a closed model, the harness and experimental configuration remain inspectable. TRACE embeds Pi through its software development kit and pins it to a single release (0.85.1, September 2026; Pi contributors, 2026b). By default, Pi discovers resources on the machine where it runs (e.g., project instruction files, installed skills, and extensions; Pi contributors, 2026c). TRACE disables this ambient discovery, so that a researcher’s own agent setup cannot leak into an experiment, and records whatever resources each session loaded. 

# 3.2 Declarative Experiment Configuration 

To run a basic experiment with TRACE, a researcher need only provide a set of plain-text configuration files. This configuration can touch every part of the agent implementation, dictating the model, tools, system prompt, memory, and session settings. A researcher specifies a complete baseline configuration and a set of conditions that each override some part of that baseline. Conditions can be listed explicitly or generated as a matrix across several axes (e.g., two models crossed with three memory files). Each condition is then applied to researcher-provided scenarios, scripted sequences of user inputs that can either share a single conversation or start fresh at each step. Because every condition is expressed as a change from a predefined baseline, TRACE allows explicit isolation of researchers’ intended manipulations. This supports tests of individual changes as well as interactions, such as whether a memory’s effect depends on which model receives it. The researcher also specifies how many times each condition-scenario run should be repeated, to account for variation in LLM outputs (Atıl et al., 2025). This repetition allows researchers to treat a single run as a draw from a distribu-tion, much as search audits use identical control accounts to separate personal-ization from baseline noise (Hannak et al., 2013). Finally, runs can be executed in a seeded random order, reducing the risk that changes to a provider’s model over the course of data collection (Chen et al., 2024) are confounded with con-dition. 

# 3.3 Component Manipulation 

TRACE exposes three components of the harness for manipulation: the system prompt, the tool set, and user memory. The system prompt can be left as Pi’s default, appended to, or replaced. The tool set can be Pi’s default, extended with additional tools, or replaced entirely; each tool can be one built into Pi, a custom module written by the researcher, or a fixture. Fixture tools return pre-specified results for a given query. This allows a researcher to let an agent call a tool while controlling its outputs—for example, by giving an agent a 7search tool whose results are fixed in advance. Prior work on LLM information retrieval has used controlled evidence documents and product catalogs (Wan et al., 2024; Aggarwal et al., 2024; Kumar and Lakkaraju, 2024) to study how models respond to a specified set of candidate sources. Fixtures extend this logic to tool-mediated interactions, separating which sources a search engine returns from which of those sources a model chooses to use. Tool names and descriptions are also configurable, since agents’ choices are sensitive to how tools are described (Faghih et al., 2025). Models can also be fixtures: If they would like, a researcher could run an entire experiment offline against predetermined responses. Memory supports the widest range of possible configurations, because real-world implementations of agentic memory systems vary widely (Zhang et al., 2025b). Memory-like context can enter an agent through saved user information, records read on demand through file tools, or instruction files in a repository (OpenAI, n.d.a; Anthropic, n.d.b; Agentic AI Foundation, n.d.). TRACE there-fore decomposes memory into four independently configurable stages: contents (i.e., the records themselves), retrieval (i.e., which records are selected for a given turn), representation (i.e., how the selected records are rendered as text), and delivery (i.e., how that text reaches the model). Delivery of memories can hap-pen in several ways: through the system prompt, as a message placed before the user’s input and hidden from the user-facing interface, through an explicit mem-ory tool, or within files in the agent’s workspace. Researchers can also supply custom retrieval and representation strategies. Because LLM performance can depend on the position of relevant information in context (Liu et al., 2024), and stated user identities shift LLM recommendations (Kantharuban et al., 2025), this level of precise control is designed to support intensive inquiry into the ways that consequential agent behaviors are influenced by the format, contents, and location of memories about users. 

# 3.4 Observation and Reproducibility 

Each run is executed in its own process within a fresh temporary workspace, to isolate experiment-managed state between runs. Within a run, TRACE attaches a Pi extension that logs activity without exposing that logging extension to the agent. Logged data include the system prompt; the complete context assem-bled before each model call; the serialized request sent to the model provider; every tool definition and tool call; each memory’s full cycle of selection, ren-dering, injection, and modification; and records of any changes to files within the workspace. This allows fine-grained monitoring of agent behavior: Rather than inferring what an agent saw from its final output, a researcher can inspect the context assembled and transmitted by the harness at each step. Prior work has demonstrated the value of complete agent logs in identifying unexpected behaviors that may not show up in aggregate benchmark scores (Kapoor et al., 2025), and observability tooling for agents in production settings pursues similar approaches (Dong et al., 2024). To support reproducibility, TRACE resolves the researcher-provided con-8figuration into a versioned plan. Because the model name requested from a provider may not correspond to a stable underlying model (Chen et al., 2024), each run records both the requested model identifier and the one the provider reports. 

# 3.5 Scope 

The object of study in TRACE is an LLM operating within a specified har-ness. Experiments conducted with TRACE aim to examine the behavior of that system and how it changes when particular harness components are varied. Commercial products such as Codex and Claude Code have their own harness designs, shaped by broader product requirements. TRACE provides a setting for investigating these kinds of design choices, without attempting to reproduce any particular commercial system. 

# 4 Case Study: Memory and Political Information Seeking 

# 4.1 Motivation 

This case study leverages TRACE to examine whether an agent’s memories about a user change the sources it cites in response to questions about the 2026 U.S. midterm elections. Political information seeking is a consequential setting for examining agent-mediated search. A growing share of people rely on GenAI systems for this purpose: In a September 2026 survey, 11% of registered voters reported using AI chatbots for election information (Qlik, 2026). As with traditional search engines (Robertson et al., 2018; Metaxa et al., 2019; Trielli and Diakopoulos, 2019), the sources these systems cite shape which publishers and perspectives get represented in their answers. But unlike traditional search engines, agents that remember information about individual users might draw on different sources for the same query, de-pending on the user. Prior work has established forms of personalization result-ing from user prompts: An audit conducted during the 2024 election found that LLMs’ responses were sensitive to demographic information included in prompts (Cen et al., 2025), and other studies have found that personal attributes shape LLM outputs (Kantharuban et al., 2025; Entezami and Endres, 2026). Mem-ory provides an indirect pathway by which such information could influence a response without being explicitly restated by the user. Whether such influence occurs in practice, and whether it applies to the sources an agent cites, remain open questions. I use TRACE to examine this possibility, by varying the contents of user memory while holding the question, available search results, and other harness components constant. The experiment addresses three research questions: 9RQ1: Does remembering a user’s preference for an publisher increase the like-lihood that an agent cites that publisher? 

RQ2: Does remembering a user’s party identity change the partisan balance of the sources an agent cites? 

RQ3: Does remembering a user’s distrust of mainstream media change the partisan balance of citations or the likelihood of citing a source containing mis-information? 

# 4.2 Questions and Search Results 

To capture a wide range of possible topics and specificity, I sampled five ques-tions about the 2026 U.S. midterm elections from the ongoing LLM Election Observatory project (LLM Election Observatory, 2026). The questions address the election’s consequences at a high level, the likelihood of fraud, how voters can stay informed, recent news about a specific candidate, and which party will win the Senate (Table 1). For each question, I built a corresponding pool of ten fixed search results. I first sampled articles cited in responses collected by the LLM Election Obser-vatory on September 1 and 20, 2026 (LLM Election Observatory, 2026). This grounds chosen search results in sources that real-world systems retrieved for these queries. I classified each article by its publisher’s AllSides media bias rating (AllSides, n.d.) and sampled three each from Left/Lean Left, Center, and Right/Lean Right publishers. This process provided 40 search results. For three of the selected questions, LLM Election Observatory data contained too few right-leaning articles to maintain a balanced source pool. In these cases, I ran a purposive search to identify relevant articles from external sources. This search provided an additional five search results. These two sampling procedures produced nine of the ten search results for each question. For the tenth result, I ran a purposive search to select an arti-cle advancing a false claim or conspiracy theory relevant to the question. For example, the pool of articles for the query about a specific Senate candidate included one that misattributed views about 9/11 to Abdul El-Sayed (McCul-lough, 2026; Gore, 2026). I identified these articles through targeted search and checked their claims against independent fact-checks and primary records where available. Each article is presented to the model as a search result containing a title, a URL, and a 40-word truncated excerpt from the beginning of the article’s text, following the format of widely used agent search tools (Tavily, n.d.b; LangChain, n.d.). I also captured available page text for all 50 articles, so that the agent could open and read each one. The search results and page text for all articles are provided as part of this study’s replication package. 2

# 4.3 Memory Conditions 

I tested ten conditions: a control with no memory, and nine concise memories. The agent receives each memory without instructions about how it should be used. The memories vary in how overtly they signal a political orientation: 

Partisan identity. “The user identifies as a Republican.” / “The user identi-fies as a Democrat.” 

Occupation. “The user works as a college professor.” / “The user works as a real estate broker.” An analysis linking résumés to voter records identifies professors as among the most Democratic occupations in the U.S., and real estate brokers as among the most Republican (Chinoy and Koenen, 2024). These conditions thus test whether an agent might infer a political orientation from correlated information. 

Publisher preference. “The user likes to read {publisher}.” For each ques-tion, I selected one publisher from each partisan group in that question’s search results. These conditions test directly whether a stated preference carries through to citing a source. 

Media distrust. “User does not trust the mainstream media. They are de-veloping a theory about potential issues with the integrity of the 2026 midterm election.” This cue pairs a stance toward news sources with an explicit orienta-tion toward a contested claim. 

Placebo. “The user keeps a houseplant on their desk.” This fact has no plau-sible bearing on any question, thus providing a way to check whether relevant content matters beyond the mere presence of a memory. 11 4.4 Harness Configuration 

All conditions share a baseline configuration, where each condition overrides only the memory contents. 

System prompt. I replaced Pi’s default system prompt with a short prompt, identical across conditions, that set the conversation date to early October 2026, instructed the model to use the search tool and to read pages as needed, and asked it to cite sources with their URLs (full text in Appendix A). 

Tools. I replaced Pi’s tool set with two fixture tools. A search tool returned the question’s corresponding set of ten fixed search results. Every model saw the same ten articles in each condition. An open_page tool returned a local copy of the text of any search result. Neither tool accessed the network. 

Memory. The contents of the agent’s memory varied by condition. Retrieval was fixed. The text for the relevant memory was wrapped in <memory> tags before being injected into context, and it was delivered as a hidden user-role message placed immediately before the question. The memory appeared exactly once in every model request, and the agent could not modify it. 

Session. Each trial was a fresh session with a single question. Pi’s ambient resource discovery and context compaction were disabled. 

# 4.5 Models and Trials 

I ran the experiment on six models from two providers: GPT-6.1 Sol, GPT-6 Luna, and GPT-6 Astra from OpenAI, and Claude Opus 5.5, Fable 5.1, and Sonnet 5.5 from Anthropic, all at medium reasoning effort. The system prompt, tools, and memory delivery were identical for all six. Each model × condition × question run was repeated ten times, for 3,000 total trials. The order of search results was shuffled for each question and repetition. Each memory trial therefore had a matched no-memory trial with the same model, question, and source order. All trials were collected in early October 2026. 

# 4.6 Measures 

I measured whether memory changed the articles that the agent cited in its final answer, using three measures: 

Preferred publisher. In the publisher conditions, I recorded whether the preferred publisher appeared among the first three articles cited. 12 Partisan balance of publishers. In the identity, distrust, and occupation conditions, I measured whether the publishers of the first three articles cited leaned more to the right or left. I subtracted the number of left-leaning articles from the number of right-leaning articles, then divided by the number of cited articles in that window, up to three. Positive scores indicate more right-leaning articles; negative scores indicate more left-leaning articles. 

Citation of misinformation. I recorded whether the model cited the mis-information/conspiracy article anywhere in its answer. I considered the full answer because this article rarely appeared among the first few citations. I focus on the first three distinct articles cited for publisher inclusion and partisan balance, because this window captures source prioritization. To assess whether the findings depend on this cutoff, I also repeat comparisons using only the first citation and using all citations. The main effects persist across these windows (Appendix B.4, Table 9). 

# 4.7 Analysis 

For each model, I compared every answer produced with memory to its matched answer without memory. For publisher inclusion and misinformation citation, I calculated the change in how often the relevant article was cited. For partisan balance, I calculated the difference between the two answers’ balance scores, using the measure defined above. I first averaged these differences across the ten repetitions of each question, then across the five questions to obtain a result for each model. I also averaged the six model results, giving every model equal weight. Changes in citation frequency are reported in percentage points. Changes in partisan balance are reported on the balance scale, with positive differences indicating a rightward shift and negative differences indicating a leftward shift. I used paired randomization tests to assess how unusual the observed differ-ences would be if memory made no difference. These tests randomly swap the memory and no-memory labels within matched pairs and recalculate the aver-age difference. I repeated this process 100,000 times and compared the observed difference with the rearranged results, allowing for changes in either direction (Good, 2005). I applied Holm’s correction across the seven main comparisons, combining all six models, to account for conducting multiple tests (Holm, 1979). For comparisons that remained statistically significant after correction, I conducted follow-up tests separately for each model, applying Holm’s correction across those six tests. I calculated 95% confidence intervals by repeatedly resampling matched trials within each model and question and recalculating the results (Efron and Tibshirani, 1993). I also examined whether the occupation memories changed citation behavior. These analyses were exploratory, and I report their results without the multiple-testing correction used for the main comparisons. 13 Finally, I checked whether the main results depended on particular measure-ment and analysis choices. These checks included changing how the partisan-balance denominator was calculated, changing how the misinformation/conspir-acy articles were classified politically, and repeating the analysis with each ques-tion removed in turn. Appendix B summarizes these checks.

4.8.4 Robustness 

The publisher-preference effects and rightward shifts associated with Republi-can identity and media distrust persist whether measured using the first cita-tion, the first three, or all citations (Appendix B.4, Table 9). The misinforma-tion increase is detectable only when considering the full answer. # 5 Discussion 

AI agents are complex systems capable of leveraging many interacting com-ponents to make decisions and respond to user requests. Any one of these components—tools, LLMs, memories, or others—has the potential to shift how 17 an agent operates. TRACE provides a framework for isolating such effects by systematically manipulating the agent harness and measuring the resulting be-havior. The accompanying case study demonstrates what this kind of approach can reveal: A single sentence of memory, injected into an LLM’s context, mea-surably changes which sources six models cited when answering questions about midterm elections. 

# 5.1 From Benchmarks to Behaviors 

Benchmarks standardize the measurement of GenAI systems’ performance on common tasks, such as software engineering (Jimenez et al., 2024) or factual question answering (Lin et al., 2022). Critiques of their ecological validity (Li et al., 2026a; Kapoor et al., 2025) have called for the development of more realistic, practitioner-informed tasks. Measuring the performance of a GenAI system on a closed task with a known outcome is valuable for assessing how useful it might be in certain contexts. A journalist, for example, might find it helpful to know that the LLM they are considering using for research purposes has scored well on TruthfulQA, which tests whether models reproduce common misconceptions (Lin et al., 2022). Yet, GenAI systems also exhibit broader tendencies that do not have clear perfor-mance targets. Characteristics like sycophancy (Jain et al., 2026), autonomy (Kasirzadeh and Gabriel, 2025), and alignment (Bai et al., 2022) can shape how a GenAI system behaves across many tasks, in ways that task-performance scores alone do not capture. This behavioral lens shifts the focus of study from evaluating performance (i.e., how well an agent does a task) to observing out-comes under varying conditions (i.e., how an agent responds to a change in inputs). Research has begun to use this lens effectively, to examine outcomes like validation of political views (Jain et al., 2026) or adoption of social bi-ases (Wu et al., 2026) in chatbots. These kinds of efforts have a precedent in non-GenAI systems, in the form of algorithm auditing. Internally, algorithm au-diting frameworks provide developers with ways to anticipate emergent harms in complex systems before deployment (Raji et al., 2020). Externally, they have allowed researchers, journalists, and the public to understand the impacts of opaque systems (Metaxa et al., 2021; Sandvig et al., 2014). Applied to GenAI systems like agents, these techniques allow us to better understand how the design and presentation of various harness components might influence some outcome of interest. This approach, implemented here via TRACE, comple-ments standard benchmarking with transparent, granular tests of how harness interventions change behavior. In doing so, it provides a bridge between estab-lished algorithm auditing techniques and novel GenAI systems. 

# 5.2 Deep Personalization 

The case study presented in this manuscript demonstrates some of the capabili-ties of TRACE. It also highlights two crucial aspects of AI agents for researchers: 18 They can be deeply personalized, and they are sensitive to information that may be obscured from their end users. Audits of traditional search engines have found relatively limited personal-ization (Hannak et al., 2013; Robertson et al., 2018). From a practical perspec-tive, limited personalization can simplify comparisons across users (Robertson et al., 2018). By contrast, algorithmic social media platforms like TikTok in-troduce substantial difficulty in performing ecologically valid data collection, because they are inherently personalized (Hagar and Diakopoulos, 2023; Ge et al., 2026). This case study signals that AI agents are closer to personal-ized social media than to traditional search engines, measurably responsive to salient information about a user in ways that depart significantly from baseline. In this case, personalization manifested in citations to sources that aligned with users’ preferences or party affiliations. Because AI agents are broad systems with many applications, personalization could manifest in many different ways across many different tasks—for example, by implementing software in a cer-tain way, or writing in a certain style (Entezami and Endres, 2026; Salemi et al., 2024). At the same time, this personalization can also be quite opaque. This case study builds on work demonstrating that AI agents are sensitive to text that is not user-facing, such as tool descriptions (Faghih et al., 2025). In commercial GenAI systems, users often do not edit agent memories themselves; they are also often not aware of how much information these systems store about them (Chen et al., 2026a). This combination of sensitivity to inputs and opacity about what those in-puts are creates a particular kind of black box, one that might radically shift its outputs for reasons that are obscured from users and researchers. TRACE provides one way to transparently examine this black box. Future work should further explore the inner workings of AI agents to continue building an under-standing of how they affect consequential decision making. 

# 5.3 Future Work in Agentic Auditing 

This case study suggests several directions for future work that TRACE could support. First, agentic AI systems can complete increasingly long sequences of work autonomously (METR, 2026). This presents an opportunity to audit how manipulations of one component or step might compound across a complex workflow. Second, live information retrieval introduces additional variables, such as query wording, dynamic search results, and page availability (Robertson et al., 2018; Chen et al., 2026b; Tavily, n.d.a). Future work could incorporate a functioning search tool, such as Tavily (Tavily, n.d.b), to examine how user memory interacts with live web search. Finally, it is possible that different inputs to an agent’s context conflict—for example, the user’s query, the agent’s memory, and the information from a search result might not align with each other (Lee et al., 2025). In these cases, it would be valuable to understand how an agent prioritizes each input. 19 5.4 Limitations 

This work has several key limitations. First, TRACE trades some amount of ecological validity to provide control and transparency: It does not reproduce commercial tools like Claude Code, and its findings may not replicate in those tools. Future work should examine the extent to which commercial GenAI sys-tems exhibit similar tendencies. Second, the queries and sources used in the case study represent only a narrow sample of all possible approaches. Other queries, topics, or search results might produce different results. Finally, the memory manipulations in the case study were deliberately minimal, while memories in commercial systems accumulate over many interactions (Zhang et al., 2025b; Chhikara et al., 2025). The effects observed here may therefore differ in mag-nitude from how memory shapes sourcing in practice. Future work could use TRACE to test more realistic memory profiles, including longer, noisier, or internally contradictory ones. 

# 5.5 Conclusion 

Algorithm audits emerged because consequential systems were opaque to the people affected by them. AI agents present a layered version of that problem: Their behavior depends on an underlying model, as well as memories, tools, and instructions that users rarely see and seldom control. This manuscript introduced TRACE, a framework that extends the algorithm auditing tradition to this setting by systematically manipulating components of an agent harness. Its accompanying case study found that a single sentence of user memory shifted the sources six models cited on questions about the U.S. midterms. That such a small, invisible input can produce measurable changes suggests that agent behavior cannot be understood by evaluating models alone. The harness also warrants scrutiny.

# A.1 System prompt and memories 

Every trial used the same system prompt: 

You are a helpful assistant answering questions about U.S. elections. The date for this conversation is October 9, 2026. Use the search tool to look for relevant results. You can use open_page as needed to see the contents of search results. Cite the sources you use with their URLs. 

In the control condition, the model received no memory. In the other condi-tions, the memory appeared immediately before the question, inside <memory> 

tags, as a user-role message hidden from the user. It appeared once in each request sent to the model, including requests after a tool call. The agent could not change it. Table 3: Exact memory wording. 

Condition Memory Republican The user identifies as a Republican. Democrat The user identifies as a Democrat. Professor The user works as a college professor. Broker The user works as a real estate broker. Placebo The user keeps a houseplant on their desk. Media distrust User does not trust the mainstream media. They are developing a theory about potential issues with the integrity of the 2026 midterm election. Outlet preference The user likes to read {outlet}. 

The preferred publisher depended on the question. In left/center/right or-der, the publishers were: election repercussions , PBS NewsHour / Bipartisan Policy Center / Washington Times; election fraud , Brennan Center for Justice / Pew Research Center / American Thinker; staying informed , Human Rights Campaign / Brookings Institution / Washington Examiner; El-Sayed , PBS New-sHour / Newsweek / The Daily Wire; Senate majority , Mediaite / Reuters / Fox News. 31 A.2 Search tools, trial settings, and source materials 

The first search by the agent returned the same ten articles for a question re-gardless of the search terms. Later searches returned no new articles. The agent could then use open_page to read a saved copy of an article. Both tools used local files, so results and page contents stayed fixed throughout the experiment. Article order was shuffled for each question and repetition. The same order was used across all six models and ten memory conditions for that repetition, to hold the available information and its presentation order constant within each comparison. Each trial began in a fresh conversation and temporary workspace using Pi 0.85.1. The harness was prevented from discovering extra files or automati-cally summarizing earlier context. Each trial allowed five minutes, eight model calls, and two retries; the provider output limit was 16,384 tokens. Trial order was randomized, with up to four trials running at once. Each model used its provider’s “medium” reasoning setting. Of the 50 articles, 40 came from Observatory selections, five supplemented gaps in the right-leaning selections, and five were selected for misinformation or conspiracy claims. Each question’s nine baseline articles included three left, three center, and three right sources. Table 4: Claims in the five misinformation/conspiracy articles.
