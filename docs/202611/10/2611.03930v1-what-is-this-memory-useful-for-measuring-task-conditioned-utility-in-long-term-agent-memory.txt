## Abstract 

A stored experience may answer one future question and offer little help with another. We measure this task-conditioned utility rather than assigning each memory a single importance score. A task-blind writer stores a memory without seeing the later task; a frozen reader then answers that task with and without the memory, using identical filler. A cost ledger records the resources used to form, store and expose the memory. On single-call factual-recall tasks built from LongMemEval-V2 web-agent memories, the same memory helps more when it con-tains information needed for the answer. Its mean paired reward gain on these answer-bearing task pairs exceeds that on matched-control pairs by +0.33 (95% interval +0.21 to +0.46). The tested task-blind summaries and structured records yield smaller gains than Raw, including at fixed total context; a budget sweep is con-sistent with retention of answer-bearing content contributing to the difference. The bearing–control contrast remains positive in a new session with randomized memory position and under a second reader, although individual memory–task labels change. Generic retrieval performs above chance but misses most screen-defined answer-bearing memories. The factual-recall gains do not extend to the tested software-engineering and scientific-coding bench-marks, where even raw memories have no measurable effect. We provide a public, versioned Conditional Memory Utility Dataset of paired measurements and costs. The practical takeaway is to evalu-ate memory compression by the task utility it preserves alongside its costs. Task-conditioned measurements make this comparison possible; their stability must also be checked.

## 1 Introduction 

A long-horizon agent has to decide which past experiences to retain, which to retrieve for a task, and which to expose to the model that answers it. For retention, the relevant quantity is a memory’s expected effect over future tasks; for exposure, it is the effect on the task at hand. Both depend on how a memory’s effects vary across tasks: whether it helps many tasks or few, and whether a memory that helps one task can hurt another. Memory systems already score items [2, 19, 21], and prior work observes that value depends on the task [1, 9, 20]. We provide a measurement protocol that jointly holds the filler context fixed, keeps the writer blind to the later task, and records the memory’s cost beside its effect. We apply it to web-agent memory on LongMemEval-V2 [16]. The central finding is that usefulness depends on the memory–task pair and on whether the representation preserves the content needed for that task. Consider a hypothetical past page visit that shows a project’s budget. A task-blind writer stores that visit as a memory without seeing any future question. A later question asks for the budget, and the same reader answers it twice, with the same filler, once with and once without the stored memory; the reward difference is that memory’s effect on that question. Repeating the comparison for other questions and representations yields the memory’s task-conditioned profile. The controlled comparisons show that a memory gains more on tasks for which it contains answer-bearing information than on matched controls. The tested summaries and structured records gain less than Raw, including when total context is fixed. These findings make preserved task utility a concrete evaluation target for memory compression, alongside its costs: a shorter memory is useful only if it still helps the reader answer the relevant ques-tion. They also expose two practical challenges: generic retrieval misses most screen-defined answer-bearing memories, and individ-ual memory–task labels can change across measurement conditions. The aggregate bearing–control contrast remains positive across the tested sessions, positions and readers; that stability does not make each individual label stable.

## 2 Related Work 

We organize prior work by the granularity of memory-utility mea-surement and the evaluation controls it provides. Several systems are designed around the idea that a memory’s value varies across tasks. A design rationale alone does not supply what a retention policy needs: how large the per-task effect is against execution noise, how often it occurs, and what the memory costs. 

Measured, then averaged. UMEM scores a memory by a marginal-utility reward over a cosine neighborhood of 𝑁 =3 future queries under GRPO [21]. The counterfactual is real, but it is reduced to its mean, and no dispersion or negative-utility statistic is reported. Their Lemma C.1 argues that the neighborhood captures the queries that retrieve the same memory; it does not report whether the dispersion inside that population is structured, which is what we measure. 

One memory, several future tasks. EMBER’s MultiQ split tests whether one frozen memory serves 100 bundles of five questions each [9]. EvoMemEval releases per-cell labels from real execution with and without the memory on held-out tasks [1]; the labels are categorical, so they carry no effect size, and each cell runs once, so no flip separates from execution variance. Its released balance (exactly 100/100/100 by seeded down-sampling) is itself a design choice, so a rate computed on it describes the sample rather than a population. MeClear computes leave-one-out and Shapley attributions from re-execution, but over the memories available to a single query [20]. A multi-factor value model notes that task utility is among the factors its scorer leaves out [2], and Memory-R1 trains a memory manager with one task per memory [19]. 

Constraints on our design. Memory-R2 argues that once rollouts write, update or delete different memories, trajectory-level compar-isons become unfair [18]; our frozen memory set answers this in Section 3. Selective retention on clean benchmarks finds retention policies indistinguishable within Wilson 95% intervals [11], which is expected if no memory is harmful. In EvoMemEval’s released sam-ple, pooled over its three datasets, the harmful label covers 22.0% of 537 items; we did not validate these labels. A learned gate over measurements like ours could build on influence-guided context selection [5] and pre-generation decoding of tool necessity [13]; we propose none. Leave-one-out re-execution is shared with MeClear, UMEM and influence-guided selection; context attribution by abla-tion is developed further in ContextCite [3], and per-item valuation in data Shapley [6]. What we add is the measurement design around it: profiles across tasks under controlled context, formation-cost provenance, and sensitivity checks. Our instability findings also have known causes. Long-context readers are sensitive to where rel-evant text sits [10], and temperature-0 inference is not reproducible when serving kernels vary with batch composition [7]. What is new is measuring their size on the quantity a memory evaluation reports. On representation, LongMemEval’s original study already varied the granularity at which history is stored and retrieved [17]; our length control asks a narrower question, whether a representa-tion’s effect comes from what it says or from how many tokens it keeps.

Identical filler, frozen memories. Both arms place the same con-trolled filler in the reader’s context, and the with arm adds 𝑚 . The filler is 4 memory units of 1 ,500–5 ,000 tokens each, drawn from 50 trajectories disjoint from every trajectory that hosts a bearing memory, so it never contains another unit that bears on the task. The without arm is therefore not an empty-context arm. On Long-MemEval’s first version [17] the oracle context is entirely evidence, so ablating “the memory” there would delete the whole context. The memory set is written once, frozen and content-hashed before any pairing exists, and no arm writes, updates or deletes a memory. The arms differ by exactly one item from that frozen set, so the divergent-state hazard raised by Memory-R2 [18] does not arise. The position of the added memory is not neutral: moving only that position changed the answer in 8 of 12 cells of a pilot, and 10% of labels at scale (Section 6). In the main runs we hold position fixed across replicates, vary it across cells, and record it on every row (Supplement S1.2). Every contrast we report is therefore condi-tional on the recorded positions; position variance is not inside our intervals. 

The writer never sees the future task. Memory formation is a func-tion of the memory unit alone, 𝑚 = 𝑊 (𝑢 ) and never 𝑚 = 𝑊 (𝑢, 𝑡 ).Without this invariant, Δ𝑈 > 0 would only show that a model can be told an answer and copy it forward. We enforce it structurally rather than by convention: the writer takes a segment and nothing else, emits a closed field set, and has a single interpolation point. Each of these barriers carries a negative control that plants the defect and requires the check to fire (Supplement S1.1). 

## 3.2 The answer-bearing screen is an instrument, not a retriever 

To decide which (memory, task) pairs are worth executing, we use an answer-bearing screen . For each pair it reads three inputs: the memory’s text, the task’s gold answer , and the task’s evaluation specification. It never reads the question, a reward, or any model output, so the strata it defines are not selected on the outcome. A pair is answer-bearing (bearing) when the benchmark’s own scorer would mark the memory text correct against the gold answer and 

the test singles this memory out of its domain pool, firing on at most eight of the 865–1,024 units available to that task. Answer-bearing is a screening label based on answer contain-ment, not a measured positive-utility label: paired evaluation mea-sures the effect, and screen-selected pairs can still fail while pairs outside the screen can still help. Our sparsity result is a statement about how answers are distributed over memories. Because it con-sumes the gold answer, the screen cannot be deployed, and we do not propose it as a retriever. Its role is to define, with the gold answer, the answer-bearing pairs; these screen-defined labels, not exhaustive ground truth for useful memories, are what we evaluate retrieval against (Section 5.3). Every rate we report under the screen is conditional on a screened design. A screen selected on the gold answer invites a second objection: perhaps the effect is an artifact of selecting pairs with the answer in hand. We tested this with a gold-free screen, pre-registered be-fore execution: the same model as the reader (gpt-oss-120b), asked whether the memory contains the specific information the question asks about, without the gold answer. On 32 cells the gold screen 

never selected, the gold-free picks move the reader from 15 .6% correct without the memory to 50 .0% with it, while 42 matched-control pairs move from 14 .3% to 11 .9%. The contrast is +0.37, with a task-clustered 95% interval of [+ 0.05 , +0.70 ] over 44 tasks and an episode-clustered one of [+ 0.14 , +0.67 ] over 19 episodes. This answers the selection objection, not the containment one; because the judge is the reader’s own model, its picks may favor pairs that model finds easy. Its picks overlap the gold screen little (Supple-ment S1.3) yet carry an effect of similar size, so benefits also occur outside the gold screen. A second, lexical gold-free screen did not locate answer-bearing pairs (Supplement S1.3). Preprint, October 2026, Online 

## 3.3 Three representations of one experience 

All three representations derive from the same memory unit, so a downstream difference is attributable to how the segment is written rather than to which content was selected. Raw is deterministic and uses no model: the memory is the segment itself. Summary 

is one writer call per segment at pinned decoding and prompt version. Structured is one writer call that emits a validated schema (memory type, trigger, action, outcome, lesson, scope). A malformed structure is recorded as a failure and never repaired. Formation cost belongs to the representation. Raw makes zero writer calls; Summary and Structured make one each per segment. Omitting that cost flatters the model-written representations, so we charge each its own, including writes that failed after consuming a call. 

## 3.4 Noise, labels and cost 

Noise is measured, not assumed. Replicates are separate requests (0 of 5 ,198 calls served from cache), and within a session they agree on all 1,157 primary cells, so the execution floor is zero and a cell’s label (helped, unchanged or hurt) is the sign of Δ𝑈 ; the pre-registered floors and label rules are in Supplement S3. Truncated completions are re-issued, not scored. Intervals are over memories, tasks or episodes, never replicates. A memory shows a sign flip when it helps one task and hurts another. A flip rate is descriptive, not evidence of memory × task interaction: under a purely additive model Δ𝑈 = 𝜇 + 𝑎 𝑚 + 𝑏 𝑡 ,simulated over 20 trials of 200 memories × 8 tasks, flip rates range from 53.5% to 92.0% with no interaction present (Supplement S3). A flip rate also grows with the number of cells per memory, so it can only be compared across groups at matched cell counts. 

The perturbation floor. The noise that matters most here is not seed variation but the reader’s response to inserting any item: position alone changes 10% of per-cell labels (Section 6). We ran no placebo arm of length-matched irrelevant content, so per-cell labels include such perturbations. The random-task stratum bounds their size: a memory paired with a randomly selected task helps in 11 .8% of the pairs where the reader was wrong without it and hurts in 14 .5% of those where it was right. These rates are an upper bound on pure perturbation: the memories are real same-domain pages, and where they contain the answer string they help more often (15 .5% against 10 .1%). Irrelevant context can distract a reader [12] or even help it [4]. We therefore report effects as paired contrasts between strata, which reduce sensitivity to content-independent perturbation when its mean effect is comparable across the contrasted strata, and never as counts of labeled cells; without a placebo arm we do not claim to isolate every such effect. 

Pre-registered and exploratory analyses. The screened design, both gold-free screens, the length control, the second-reader study, the writer × reader factorial, the reversal rate and the variance de-composition were pre-registered; Supplement S10 lists their anchors and every deviation. All other analyses, including the three follow-up runs, are exploratory, and their intervals are not adjusted for multiplicity. Every measurement is paired with its cost in seven families, from storage to formation; utility per exposed token is reported beside utility per token charged, including the writer’s (Supplement S4.5). 

## 4 Benchmarks and Setup 

LongMemEval-V2 and the page-visit memory unit. Our primary benchmark is the small tier of LongMemEval-V2 [16], where each domain has exactly one haystack, so every memory is available to every question in its domain. A whole trajectory cannot serve as a memory: its median length is 103,886 tokens. We segment at the 

page visit , the maximal run of consecutive states that share one URL, a boundary drawn by the past agent’s own navigation. This yields 

1,889 memory units with a median of 7,261 tokens. Removing one unit removes a median 3.33% of its trajectory and 0.058% of the domain haystack, and segmentation preserves answerability for 278 of 295 deterministically scored questions (94.2%). 

Future tasks and the executed design. A future task is one ques-tion with its evaluation specification. Of 451 questions, 295 are deterministically scored; we use the benchmark’s scorer verbatim, and an LLM-judged task raises an error rather than scoring zero. Seeded pairing within domain gives a grid of 15,112 memory–task pairs. We execute a screened design over 60 memories, a floor fixed before running by a power study: 40 from the web domain and 20 from the enterprise domain (unit pools of 865 and 1 ,024), drawn from 35 source episodes. A content-blind size cap fixed before any outcome removed 11 candidate memories longer than 20 ,000 to-kens. The 60 memories are every memory bearing on two or more tasks that passed the cap (35) and 25 that bear on one, so the de-sign over-samples multi-task memories to give reversal a chance. Each memory is paired with three strata of future evaluation tasks: 

answer-bearing task pairs (bearing); matched-control task pairs ,tasks of the same family as a bearing task (static environment, dy-namic environment or procedure) on which the screen does not fire for that memory; and the random-task stratum (random), un-screened tasks drawn at random, over 218 tasks in all. All three strata contain the identical 60 memories, so contrasts are paired within memory rather than against a different set of control memo-ries. The design has 1 ,157 cells (Table 1). 

Secondary benchmarks. We also ran the protocol on SciCode [15] (reusable helper routines, 154 donor →recipient pairs) and SWE-bench Verified [8] (40 interpretable cells); there memories show no effect even in raw form, so we report them in Supplement S6. 

Execution. In the primary arms, the reader and the memory writer are both gpt-oss-120b on one serving cluster, with low reasoning effort, temperature 0 and max_tokens 512; similarity uses SFR-Embedding-Mistral. Section 5.5 changes only the reader, to gemma-4-31B-it . ## 5.3 Retrievers find answer-bearing memories, but miss most 

The screen defines which units of a domain pool are answer-bearing for each of the 75 tasks, so these screen-defined labels can score re-trievers that never see the answer (Figure 4b). Recall@10 measures recovery of these units, not of every helpful memory or the accu-racy of a complete retrieval system. Ranking the whole pool of 865 Preprint, October 2026, Online 

or 1 ,024 units by the question, dense retrieval with SFR-Embedding-Mistral ranks, on average, 0 .40 [0.31 , 0.50 ] of a task’s bearing units in its top ten (recall@10) when units are split into 512-token chunks, and 0 .35 when only a 2,000-token prefix is embedded, against about 0.01 by chance. The lexical ranker BM25 reaches 0 .21, with an area under the ROC curve (AUROC) of 0 .86. Chunked retrieval places the first bearing unit at a mean reciprocal rank of 0 .41, and chunking improves recall only modestly over prefix embedding in this com-parison. Retrieval thus locates bearing memories far above chance yet misses most of them in its top ten, which is why a deployable locator remains open. Similarity is a weaker guide to how much amemory helps: across executed cells, cosine similarity correlates with Δ𝑈 at only 𝜌 = +0.09 (Supplement S4.2).

## 5.5 The contrast keeps its direction under a second reader 

One concern is that the Raw effect is specific to one reader. We re-executed the 285 Raw bearing and control cells with a second, unrelated reader (gemma-4-31B-it) on the same memory text. The memory file, prompt, filler, every rendered request and each target position were hash-asserted against the first run, and the text re-verified byte-identical on 1 ,694 rows. Because this endpoint is not deterministic across sessions (Section 6), we ran both readers in one session and quote that measurement. The aggregate contrast keeps its direction and is larger: over 275 matched cells on 123 tasks, the second reader’s mean Δ𝑈 is higher by +0.10 [+ 0.02 , +0.17 ], and the within-memory bearing −control contrast is +0.60 (Figure 3a). Part of the gain comes from a weaker no-memory arm under the second reader ( −0.07) rather than from a better memory. 

The aggregate contrast retains its direction across the two readers, while per-pair labels show partial agreement. Over the 275 cells, the two readers’ three-way labels (helped, unchanged, hurt) agree at Cohen’s 𝜅 = 0.58. Of the 105 cells that move under either reader, both mark 55 as helped (Figure S5f). Too few cells are harmed (6 and 2) to tell whether harm labels reproduce. Whether a reader favors memories its own model wrote is tested by a pre-registered writer × reader factorial crossing both models as writers and readers. On Summary and Structured, whose utility is already near zero, the factorial excludes writer and same-family effects above 0 .038 (Supplement S5).

## 6 Discussion and Limitations 

Our measurements inform two memory-manager decisions without implementing either: what to keep after an episode and what to show at each later step. Retention would require combining task-conditioned utility profiles with an anticipated future-task distribu-tion and memory costs; our measurements characterize a defined evaluation task set, not a deployed agent’s future return. The pairing is constructed. The memories are real trajectory spans, but their pairing to tasks is a seeded rule fixed before mea-surement, so every rate describes a defined evaluation task set rather than naturally occurring future tasks. The observed harm rates should therefore not be interpreted as population rates for deployed memory systems. 

Session and position variance. Re-issuing 1 ,124 byte-identical no-memory requests a day later changed 82 rewards, so we compare only arms executed in one session. We then measured both sources, session and position, directly by re-running the headline cells in a new session with position redrawn per replicate (Section 5.2). The aggregate contrast keeps its direction. Single cells move (Figure 5a). Position alone changes 10% of labels and accounts for 11% of the variance of Δ𝑈 , and the bearing effect is weaker in the middle of the context ( +0.30) than at its ends ( +0.43; Figure 6), echoing [10]. unchanged (Figure 5a). Standardizing the published contrast over position leaves it at +0.33. 

Scope. The main results concern a single-call factual-recall reader evaluated on the web and enterprise domains of LongMemEval-V2. The experiments use one serving cluster and two reader check-points, limiting generalization to other model families and deploy-ments. The software-engineering and scientific-coding evaluations show no measurable memory effect; the positive factual-recall find-ing should not be extended to those settings. Single-item insertion cannot see redundancy or complementarity between units, which Shapley-style attribution could [20]. Our filler comes from trajecto-ries that host no bearing memory, so it never contains competing evidence; realistic retrieval would, which likely makes our bearing effect larger than a deployed system would see. Our leakage-audit rates are lower bounds (Supplement S9). Preprint, October 2026, Online 

Release and reproducibility. The Conditional Memory Utility Dataset is publicly available on Hugging Face. The frozen v0.6-length-control snapshot contains 16,816 evaluation records, with paired outcomes, costs and available text, plus schema and valida-tion code. The data card documents the included conditions, missing records and text withheld under upstream restrictions. This ver-sioned snapshot does not cover every later manuscript analysis, including the fixed-total-context experiment. Per-pair labels depend on the evaluation condition; they are observations, not uncondi-tional targets for training a memory gate. See Supplement S8 for coverage and reuse details. 

Conclusion. Evaluate memory compression by the task utility it preserves alongside its costs. On LongMemEval-V2 factual-recall tasks, answer-bearing pairs gain more than matched controls, and the tested summaries and structured records gain less than Raw even at fixed total context, consistent with reduced retention of rel-evant content. Our paired protocol makes these effects measurable without exposing the future task to the memory writer. The head-line contrast stays positive across the tested sessions, positions and readers, while individual labels remain condition-dependent. These factual-recall gains do not extend to the tested coding benchmarks.

## S1 Protocol details S1.1 Keeping the writer blind to future tasks 

Memory formation must be a function of the past episode alone, 

𝑚 = 𝑊 (𝑒 ). If the writer could see a future task, a positive Δ𝑈 

would show only that a model can be told the answer and copy it forward. We enforce this with four structural barriers rather than by convention. (1) Arity : the writer function takes a segment and nothing else. (2) A closed field set : the writer emits only the fields of its schema. (3) A metadata denylist : the weakest barrier, present to make a plumbing mistake fail loudly. (4) A single interpolation point :the prompt has one placeholder, the segment text. Each barrier carries a negative control that plants the defect and requires the check to fire. Prompt identity is derived from the prompt file’s bytes, not from a hand-maintained version constant that could report a stale version. 

## S1.2 Target position is held fixed 

The with arm holds one more item than the without arm, so some rule must place it, and that rule is not neutral. Holding the memory, question, filler, model, decoding and seed fixed and varying only the position of the target memory changes the answer in 8 of 12 probe cells. Measured at scale in the second-session run (Section S11), position changes 10% of labels. A comparison that does not con-trol position therefore measures position together with presence. We hold position fixed across replicates, vary it across cells, and record it on every row. This is also what makes the second-reader comparison (main paper, Section 5.5) a comparison of readers and not of positions. The probe is small ( 𝑛 =12), and we treat the rate as provisional. 

## S1.3 The bearing screen and both gold-free screens 

The bearing screen reads the memory text, the task’s gold answer, and the task’s evaluation specification; it never reads the question. A pair is bearing only when the benchmark’s scorer marks the memory text correct against the gold answer and the test fires on at most eight of the 865–1,024 units in the task’s domain pool. The second clause matters. An earlier, non-discriminative version of the flag fired on nearly every candidate: its rate on paired versus unpaired memories was in a ratio of 0 .995, so it said nothing about any one of them. We pre-registered two gold-free screens before execution. Each reads the memory, the question and the same-domain pool, and none of the gold answer, the reward, any model output, or the evaluation specification. We report both, because reporting only the screen that worked would select an instrument on its outcome. 

• Model-based screen. The judge is 𝑔𝑝𝑡 −𝑜𝑠𝑠 −120 𝑏 , the reader’s own model, at temperature 0, asked whether the memory contains the specific information the question asks about. On cells the gold screen never selected, its picks move the reader from 15 .6% correct without the memory to 50 .0% with it (64 rows, 32 cells); its matched control moves from 14 .3% to 11 .9% (84 rows, 42 cells). The contrast of +0.3676 has a task-clustered interval of [+ 0.05 , +0.70 ] (44 tasks), an episode-clustered one of [+ 0.14 , +0.67 ] (19 episodes), and a paired-by-memory difference of +0.49 over 24 memories. Against the gold screen it recovers 10 of 266 gold-bearing pairs (3 .8% recall), and 10 of its 42 picks are gold-bearing (23 .8%). The run is in one session, separate from the gold run. 

• Lexical screen. It returns no effect. A diagnostic independent of any utility explains why: its bearing cells fail in both arms at a rate of 0 .744, worse than unscreened random pairing, against 0 .310 for the model-based screen. A criterion whose selections are harder than a random draw has not located bearing pairs. 

## S1.4 Leakage audit 

The writer invariant excludes task-directed writing , not a naturally occurring memory that happens to contain a later answer. Such a memory is genuinely useful, and removing it would condition the cell set on the outcome. We therefore audit every cell rather than filter it. The detector reuses the benchmark’s own scorer and asks whether the rendered memory text alone would score correct against the gold answer. For bearing cells the answer is yes by construction, since that is half the bearing definition. The audit carries information for the control and random strata and for the Summary and Structured texts, where containment is not guaran-teed and can be conditioned on in analysis. It is validated by 17 controls (plants it must catch, clean cases it must not fire on, and two pinned known false negatives) and aborts if any control fails. 

## S1.5 Three kinds of zero in the cost ledger 

Raw makes zero writer calls; Summary and Structured make one each per segment. The ledger distinguishes three zeros that are routinely merged: a measured zero (Raw makes zero extraction Preprint, October 2026, Online 

calls), an absent measurement (no call was made, so the cell leaves that denominator), and an unreported field (the endpoint exposes no counter). Failed writes count: a write that failed after consuming a call still cost that call. 

## S2 Benchmark adapters and coverage 

LongMemEval-V2 haystacks. On the small tier each domain has exactly one haystack, identical across questions even as an ordered tuple, so every memory is available to every question in its domain and there is no availability confound between arms. The same test returns 222 and 211 distinct haystacks on medium , a positive control showing that it distinguishes the two cases. Trajectory lengths were measured with the benchmark’s own tokenizer over 200 trajectories and 5,095 states. 

Scorer dispatch. There are eight distinct evaluation-specification strings, not six: two phrase-match variants differ only in their sep-arator. The adapter therefore dispatches on the full string, never on the function name, and calls the benchmark’s scorer verbatim. Its phrase matcher tests gold-phrase containment , not set equality, which a name-based reimplementation gets wrong. An LLM-judged task raises an error rather than returning a default; a silent False 

would turn “cannot evaluate” into “wrong answer” for 156 of 451 questions in both arms. 

Pairing and power. Seeded deterministic pairing within domain, stratified by the benchmark’s own question-type taxonomy, gives 1,889 memories × 8 tasks = 15,112 cells, and every memory was verified to receive exactly 8. The build asserts that the same seed re-produces the grid byte-identically and that a different seed changes it, so the reproducibility check is not vacuous. That grid is the avail-able pairing, not the executed design. The floor of 60 memories was fixed before running from a recovery study on synthetic data with known planted components; the same study showed that widening the task axis helps more than adding memories. 

BEAM.. BEAM [14] was in our original plan as a multi-domain check but cannot supply the task axis: 92.6% of its cited turns are cited by exactly one question. Being CC BY-SA 4.0, it would also have to ship separately, since ShareAlike would otherwise relicense the rest of the release. 

SciCode. The memory unit is a reusable helper routine with its procedure, which transfers across problems. Against an early feasibility estimate of 8–12 pairs, the full candidate pool measured on the built adapter is 154 donor →recipient pairs (34 memories, 40 tasks), and we ran all of it. 

SWE-bench Verified. Pairing is plentiful but the measurable yield is low. ## S3 Execution configuration and statistics 

Frozen configuration. Cluster and serving configuration are part of a cell’s experimental identity, and every row records the full pinned set: reader and writer gpt-oss-120b on one cluster, low reasoning effort, temperature 0, max_tokens 512, 16 concurrent workers, SFR-Embedding-Mistral at dimension 4096, and the bench-mark’s own tokenizer. A change to any of them defines a new arm rather than additional data. Three settings were fixed by mea-surement. An empty or truncated completion raises and the cell is re-run, since scoring it as zero would push Δ𝑈 negative and manufacture harmful memories. Concurrency sits at a measured saturation ceiling, with the ladder pushed past the chosen value. Responses are cached on all twelve fields of a cell’s identity, verified by varying one field and confirming a cache miss. The embedding model’s determinism was checked directly: the cosine of identical texts is exactly 1.0. 

Noise floors. 𝐹 exec is outcome variation across seeds with every-thing else fixed, measured per benchmark with a bootstrap interval and within a single execution session. 𝐹 empty is the variation of the no-memory arm, available at no extra cost because that arm is identical for every memory paired with a task. 𝐹 judge is scorer disagreement on byte-identical outputs, from re-scoring stored gen-erations; we store full output text rather than a digest so that this re-scoring is possible. The floor is defined on the Δ𝑈 scale, since var (Δ𝑈 ) = var with + var without − 2 cov; per-arm floors are reported alongside. One hazard would fabricate the whole result: the with-out arm’s inputs are identical across memories, so a cache serving it would reuse one generation everywhere and let every Δ𝑈 clear a zero floor. That arm is re-generated per (task, replicate) rather than served from the response cache; in the screened run all 5 ,198 calls reached the endpoint, with 0 cache hits. 

Labels and flips. A cell is robust useful when CI lower > 0 and 

Δ𝑈 > 𝐹 , robust harmful when CI upper < 0 and |Δ𝑈 | > 𝐹 , and neutral otherwise, so a cell can be statistically non-zero and still neutral. A memory shows a robust sign flip only if two of its cells independently meet the useful and harmful criteria. Every flip rate carries its denominator (memories on at least two tasks) and a Wilson interval beside the naive rate, and a cell needs at least two replicates to enter one. Because replicates agree on every primary cell, a robust label reduces in practice to the sign of Δ𝑈 , and flip rates are comparable only at matched cells per memory (Section S7). 

The additive null. A flip is a property of Δ𝑈 ’s sign; interaction is a property of its variance. Under Δ𝑈 (𝑚, 𝑡 ) = 𝜇 + 𝑎 𝑚 + 𝑏 𝑡 with no interaction, a memory still helps one task and harms another whenever 𝑏 𝑡 crosses −( 𝜇 + 𝑎 𝑚 ). Simulating that null over 20 trials of 200 memories × 8 tasks gives flip rates of 53.5%–92.0% across five settings of 𝜇 and the memory and task standard deviations. A high flip rate is therefore consistent with memory value being a scalar plus a task-difficulty term. Preprint, October 2026, Online 

The variance decomposition. We pre-registered a decomposition 

Δ𝑈 (𝑚, 𝑡, 𝑠 ) = 𝜇 + 𝑎 𝑚 + 𝑏 𝑡 + ( 𝑎𝑏 )𝑚𝑡 + 𝜀 𝑠 into component variance shares against 𝐹 exec , with a method-of-moments fallback fixed in advance. We recorded the structural precondition before executing: components are identified only relative to a residual scale. It fails here because the reader is deterministic within a session, so we quote no share (Section S7). Standard errors are clustered by task throughout. 

Similarity and cost. Semantic distance is the cosine of the pinned embeddings of memory and task, banded by terciles fixed before outcomes were examined, since cosine scales are not comparable across corpora. The seven cost families are storage (memory to-kens held), retrieval (latency, tokens returned), exposure (tokens placed in the reader’s context), generation (latency, input, output and reasoning tokens), extraction (formation cost), API and com-pute , and selectivity (how much of what was retrieved was worth exposing). Exposure is recorded separately from retrieval because the gap between them is truncation loss.

## S4.5 Formation-cost sensitivity 

Formation cost per cell is the writer’s tokens divided by the reuse factor 𝑟 , the number of cells that share one written memory. Our design fixes 𝑟 = 4.86, so we recompute exposure efficiency over 𝑟 

from the same utilities and token counts (Figure S3). One Summary costs about 7 ,956 writer tokens and one Structured record about 8,141. On point estimates Summary overtakes Raw only for 𝑟 ≳ 5.5, but its utility interval spans zero at every 𝑟 , so the crossing point is not estimated with any precision. Under the sparsity we measure, a memory that bears on one task may be shown for few others, which pushes 𝑟 down and formation cost up. The relevant factor in deployment is exposures per write, not cells per memory. ## S9 Extended limitations 

Leakage rates are lower bounds. Our leakage detector reuses the benchmark’s phrase matcher, whose normalizer strips punctuation without inserting a space. A gold phrase next to a quote or an equals sign is glued to its neighbor and the match fails. Such leaks are missed, and punctuation is common in accessibility trees, so every leakage rate we report is a lower bound. A control test records the defect, so an upstream fix would be detected. The 156 LLM-judged questions cannot be audited without an inference call and are recorded as undecidable rather than clean. 69 multiple-choice questions with gold answers of one to five characters cannot be audited structurally and are never folded into a pooled rate. 

The judge floor measures decoding. 𝐹 judge is zero wherever we measured it: over 3 ,486 explicit re-scorings of 60 units in the earlier official arm, and in every stratum of the screened run. Both estima-tors carry a positive control (a planted disagreement makes them fire). A zero floor here reflects a deterministic scorer and greedy decoding, not an unambiguous rubric. The SciCode control in Sec-tion S6, which disagrees on 5 of 135 cells, is a different scorer on a different benchmark. We have no cross-session floor for any arm and presume it to be non-zero. 

Semantic type. We intended semantic memory type as a sec-ond axis, but in our representation pilot the two labeling passes agreed on 3 of 8 segments at Cohen’s 𝜅 = 0.000: the structured writer’s own pass called every segment episodic , a degenerate marginal, so we report no semantic-type breakdown. Separately, exactly one deterministically scorable errors-gotchas question exists in the benchmark and accounts for 865 of 6,920 web cells, so any per-stratum result there is a single-question result. 

Writer failures and faithfulness. The structured writer failed on 3 of 60 segments, all by exhausting the token budget mid-value rather than by malformed output, and on 0 of the 57 writes that finished. An 8-segment pilot had put the failure rate at 0 of 8 and could not have seen this, since it never reached the cap. Our faithfulness mea-sures are a screen, not a guarantee: a low score is strong evidence of a problem, a high score is weak evidence of its absence, and they do not detect recombination, omission, unsupported inference or negation. 

Unrecorded quantities. Two quantities were not recorded during the runs and cannot be recovered: how many gold-free picks contain the answer, and how the 12 position-probe cells were chosen, which is why we treat that probe as a pilot. 

Stated exclusions. 17 of the 295 deterministically scored questions have no memory unit that carries their gold answer under the segmentation answerability check, so their cells can only yield 

Δ𝑈 ≤ 0. The bearing screen, a looser containment test, fires on no unit for 15 of them (Section S11). 23 of the 1,889 units (1.2%) are their entire trajectory.

Power for harm. With 16 bearing cells able to show harm, against the random stratum’s rate of 14 .5%, the screened design detects (80% power, two-sided 𝛼 = 0.05) only a bearing harm rate of 44% or more; the null on harm is therefore weak evidence.
