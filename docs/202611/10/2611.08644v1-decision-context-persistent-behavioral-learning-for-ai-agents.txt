Abstract
LLM agents do not learn from corrections across sessions. A user fixes the same
mistake at the start of every conversation. Existing agent memory systems handle
facts (preferences, entities, conversational history [1, 2, 3]) but not procedural
knowledge [4].
We present Forge Decision Context (forge_dc), a system that captures behavioral
signals from human corrections and from self-assessed tool-call failures, compiles
them into imperative RULE directives, and injects them at the decision points where
they apply. We evaluate forge_dc alongside four predecessor approaches on
DC-Bench, a new benchmark of 71 scenarios across 9 behavioral dimensions,
built from real executed agent traces in a deterministic mocked-tool environment.
forge_dc reaches 95% compliance, up from 55% with naive retrieval, while
injecting roughly 10× fewer tokens per query.
Across the five-stage progression, the strongest systems represent behavioral mem-
ory as explicit directives and deliver it at the decision points where it applies. The
results identify representation, activation, and placement as central design choices
for persistent behavioral learning.

Introduction
LLM agents are increasingly deployed beyond question-answering: writing code, managing infras-
tructure, orchestrating multi-step workflows. Yet they are memoryless learners: every session begins
from the same blank state. Every correction must be repeated. Every hard-won behavioral insight is
lost.
Consider a security analyst correcting an agent over many sessions: “always check Identity and Access
Management (IAM) policies before network configurations,” “use –recursive when scanning S3
buckets,” “that API returns paginated results, so loop.” Within each session the agent improves as
corrections accumulate in context. But the next day every correction must be re-issued, in the same
order, with the agent making the same mistakes with the same confidence.
The problem has two dimensions. First is the loss of human corrections: explicit feedback transfer-
ring domain expertise about metrics, parameters, and strategies. Second is the loss of self-generated
patterns: signals from the agent’s own execution such as tool retries that eventually succeed,
errors that force strategy changes, and outputs the user silently regenerates. Existing prompt-
engineering practice is fundamentally lossy (most corrections never propagate to system prompts),
situational (most judgments are conditional), and ignores self-generated signals entirely. What is
needed is a system that captures situational judgments as they occur and surfaces the right judgment
at the right moment.

The agent memory landscape has grown rapidly [5, 6]. Many systems emphasize facts, such as
a meeting on Tuesday, a Python version, or a preference for dark mode. Other systems extend
memory beyond factual recall by learning user preferences from edits [7] and reusable procedures
from interaction traces [8, 9, 10]. We study how a tool-using agent can turn explicit corrections and
implicit execution signals into actor-scoped guidance, determine when that guidance applies, and
deliver it at the decision point where it can change behavior. Storing the correction “use QRR for
enterprise revenue” is trivial; knowing when, how, and whether to apply it is the hard problem.
A separate line of work learns reusable procedures, workflows, or hints from past trajectories, scored
by task success [11, 12, 13, 14]. These methods assume a reward: something outside the agent says
which trajectory was better. Deployment provides no such signal. What the agent has is the session
itself: an explicit human correction, or an implicit cue in its own execution, such as a tool call that
fails and then succeeds on retry, or an output the user silently regenerates.
This paper makes three contributions:
1. DC-Bench. A benchmark of 71 scenarios across 9 behavioral dimensions and two agent
domains, built from real traces captured by running agents in a deterministic mocked-tool
environment. Each scenario seeds corrections on one subject and tests on another, so it
measures whether a correction is applied, not whether it is recalled.
2. Forge Decision Context (forge_dc). A system that learns from human corrections and
self-assessed tool-call failures without a reward signal, compiles both into scoped, actor-
attributed RULE directives, and injects them at the decision points where they apply. It
reaches 95% compliance on DC-Bench, against 12–15% for factual-memory systems and
34–49% for procedural-memory baselines.
3. Empirical findings from a five-stage system progression. The progression reveals an
advantage for directive-form memory, a retrieval gap between formatting and content rules,
the failure of implicit signals without explicit extraction, and sensitivity to the injection
channel (Section 7).

Related Work
Agent memory systems.
Existing systems target factual memory in three families.
Graph-
structured systems (Zep/Graphiti [3], GraphMem [15]) use typed graphs with traversal-based retrieval.
LLM-as-controller systems (MemGPT/Letta [1], MemOS [16]) page tiered memory in and out via
LLM tool calls. Extraction-pipeline systems (Mem0 [2], Hindsight [17]) extract structured records
offline with an LLM, then retrieve via non-LLM hybrid search. These systems primarily optimize
factual or conversational recall; procedural memory remains comparatively underexplored [6, 18].
DC is complementary: an agent may use Mem0 for facts and DC for behavior simultaneously.
Procedural and experiential memory.
A recent line distills reusable knowledge from past trajec-
tories: AWM [11] induces workflows, Memp [12] builds step-level procedures, ACE [13] curates
a context playbook, and JEF-Hinter [14] extracts offline hints. AutoManual [8] constructs and
maintains an online rule manual, while skill-centric systems persist and revise reusable procedures:
Memento-Skills [9] grows a routed skill library, and SkillRevise [10] diagnoses and repairs skills
through re-execution. These systems primarily learn procedures that expand or repair how an agent
completes tasks. Decision Context instead learns scoped behavioral guidance that changes when and
how an agent uses capabilities it already has. It converts explicit corrections and patterns from tool-use
traces into actor- and condition-scoped directives delivered at relevant decision points. Accordingly,
skill-learning systems are generally evaluated by task success, whereas DC-Bench measures condi-
tional compliance, generalization, scope precision, and non-transfer. We adapt AWM and Memp
as baselines because their trace-to-procedure pipelines most directly match the behavioral-memory
setting.
2


Learning preferences from edits.
PRELUDE/CIPHER [7] infers context-dependent latent prefer-
ences from users’ direct edits and retrieves and aggregates those preferences to guide future generation.
It is the closest prior work on reusing naturally occurring user revisions. Our setting broadens the
feedback beyond edited text to explicit conversational corrections and tool-execution patterns, and
focuses on multi-step tool agents where a rule may need to activate between calls, be scoped to an
actor, or be suppressed to avoid negative transfer. Conversely, PRELUDE directly optimizes edit cost
in writing tasks, which DC-Bench does not measure.
Memory benchmarks.
LongMemEval [19], MABench [20], MemoryBench [4], MemBench [21],
MemoryArena [22], and LOCOMO [23] converge on four findings: (i) single-fact retrieval is largely
solved; (ii) cross-session reasoning remains difficult; (iii) conflict resolution is weak across all
systems; (iv) procedural memory is unsolved. MemoryBench [4] explicitly identifies the procedural
gap that motivates this work. DC-Bench differs by evaluating behavioral compliance (does the agent
apply the correction to an unseen subject?), using real executed agent traces with controlled tool
outputs, and covering 9 behavioral dimensions including self-assessment and multi-actor conflict. The
benchmark is intended to complement, not replace, task-success and preference-learning evaluations.
Learning from feedback and RAG.
RLHF [24] adjusts model weights at the population level
and is unsuitable for per-user behavioral adaptation. Constitutional AI [25] encodes manually
authored, universal principles; DC automates and personalizes the same idea. In-context learning [26]
requires manual example selection and does not persist across sessions. Continual learning [18] faces
catastrophic forgetting and training cost. Standard RAG [27] retrieves information once at query
start; DC retrieves behavioral guidance progressively at the decision points where it applies.

The Dimensions of Behavioral Memory
Behavioral memory must satisfy several dimensions that factual memory does not, and prior ap-
proaches address only some of them. The two signal sources (human corrections and self-generated
trace patterns) must be turned into reusable guidance and surfaced when relevant. Six challenges
define these dimensions: extracting signals from noise, generalizing without losing fidelity, retrieving
at scale, surfacing at the decision point, updating knowledge as corrections supersede one another,
and not regressing behavior the agent already gets right.
Extracting signals from noise.
Behavioral corrections arrive as natural language embedded in
conversation. “Oh, and include the USD symbol next to monetary amounts” is a correction, but it
looks like a casual remark. Trace patterns present a different challenge: not every tool error is a
behavioral failure (rate limits, empty results, and sequential narrowing all produce errors that are not
signals).
Generalizing without losing fidelity.
A correction observed against one subject must transfer to
others without dropping qualifiers. Three properties make this hard: (i) corrections chain, so the
same behavior is corrected repeatedly and only the final state matters; (ii) they are conditional, with
qualifiers (“for enterprise clients”) that must be preserved; (iii) the generalization scope is ambiguous,
since a failure on one subject may or may not generalize to others.
Retrieval at scale.
Behavioral guidance has narrow windows of relevance: the same tool with a
different source, the same metric for a different segment. Scale stresses precision: the system must
work with 5 corrections and with 500. Different categories also retrieve differently. Content-related
guidance has semantic overlap with the query; formatting guidance (“include USD next to amounts”)
does not, since “USD formatting” has no embedding similarity to “Beta Inc.”
Surfacing at the right moment.
Unlike facts, behavioral guidance must appear at the decision
point where it is actionable. Guidance about S3 scanning is irrelevant during planning and critical
during execution. Premature injection wastes context, late injection misses the decision point, and
content placed in the middle of long contexts attenuates [28].
Updating and resolving conflicts.
Corrections accumulate, change, and conflict. A later correction
supersedes an earlier one, and different actors correct the same behavior differently (one says “QRR,”

System Design
The six challenges in Section 3 map to a four-layer pipeline (Figure 1): Capture extracts behavioral
signals from agent traces; Store persists them in queryable form; Retrieve finds relevant rules for
a new query; Inject delivers them at the right moment. Five approaches implement this pipeline
with progressively more sophistication (Table 1). forge_dc, the strongest approach and the main
technical contribution, combines all of them.

Two storage models.

types (MADE, ABOUT, APPLIED, LED_TO, PRODUCED, INFORMED_BY, HAS_SUMMARY, FOLLOWED_BY)
connect actors, subjects, nodes, and evidence; forge_dc adds a ninth (FORGED_FROM) linking each
compiled rule to the trigger node that should surface it.
4.1
Four predecessor approaches
doc_naive (55%): naive RAG.
The simplest pipeline: each trace is split at tool-call boundaries
and chunked; embed, retrieve the top-k via the shared hybrid search (BM25 + cosine + RRF), and
inject as “relevant past context” in the system prompt. No annotation, no aftermath classification, no
edges, no per-tool injection. This is what happens when a team dumps logs into a vector database.
Corrections get fragmented across chunks, are mixed with conversational filler, and are injected as
raw text the agent must interpret. The 55% baseline succeeds only on simple, recent corrections that
happen to land in a retrievable chunk.

doc_chunk (63%): annotated chunks.
The motivation here is to improve retrieval by adding
annotations, and see whether the same annotations can shrink the injected context. doc_chunk
adds deterministic per-chunk annotations and aftermath classification on top of doc_naive, and
prepends a global readout of per-action correction rates to the system prompt alongside top precedents.
Storage stays flat (no graph edges). Annotation makes BM25 hits sharper and lets injection drop
conversational filler, raising compliance by 8 points (55%→63%); but without edges the system still
cannot follow correction chains, traverse actor-scoped history, or use accumulated embeddings.
hybrid_raw (70%): graph storage.
Replaces chunks with the typed-graph storage model: each
session becomes a sequence of DecisionNodes with eight edge types and both node and accumulated
embeddings. The shared hybrid search now operates over nodes, with the embedding component
combining node and accumulated similarity (0.7·node+0.3·accum). After RRF fusion, multiplicative
boosts re-rank candidates by matching subjects, actors, and corrected documents. Injection occurs at
two points: a system-prompt global readout plus top precedents, and a separate per-tool-call lookup
that matches the current tool result against stored evidence via INFORMED_BY edges. Structure alone
fixes retrieval (chains, conditional matching, long-conversation and scale scenarios), but hybrid_raw
only captures explicit human corrections. Implicit signals from the agent’s own execution, tool retries,
recurring failures, and suboptimal sequences, are never extracted. This sets up the next approach.
lucid_dc (82%): autonomous self-assessment.
Asks whether the agent can learn from its own
traces rather than human corrections. After base capture, a separate Sonnet 4 analyzer reads tool-only
data (no conversational context) and compiles recurring failures, retry-then-succeed sequences, and
suboptimal strategies into behavioral directives. Tool-only input is deliberate: when the analyzer sees
full traces, it produces rules about everything; restricting input to tool calls keeps it focused on ob-
servable patterns. Compiled rules are injected unconditionally under a MANDATORY TOOL-CALLING
RULES header, alongside the hybrid_raw retrieval. Only the self-assessment directives were fol-
lowed reliably; raw human corrections were often ignored. This observation motivated forge_dc’s
correction compiler and the “Only Rules Rule” mnemonic (Section 7).
4.2
forge_dc: correction compilation with progressive injection
forge_dc combines both behavioral signal sources through a compilation pipeline that transforms
raw corrections and trace patterns into structured, conflict-resolved, progressively injectable RULE
directives.
Pipeline.
On top of the lucid_dc capture and self-assessment: (1) Correction chains are dis-
covered by grouping per conversation_id and actor_id, then splitting at accepted aftermath
boundaries (per-actor grouping prevents cross-preference merging). (2) Compilation (Sonnet 4)
turns each chain, and the self-assessment patterns, into structured output: RULE (imperative directive),
TYPE (FORMAT or CONTENT), TRIGGER (precondition node), DROP/SKIP (noise filters), and GROUP
markers that cluster related rules. (3) Each rule is wired to its trigger node via a FORGED_FROM edge.
(4) Rulebook maintenance deduplicates, merges agreements, supersedes earlier rules from the same
actor, and flags cross-actor conflicts for runtime resolution. (5) At query time, progressive injection
delivers rules across two stages.
Precondition triggers.
For each rule the compiler answers: at which point in the trace, if the
agent had known this rule, would the mistake have been prevented? For tool-specific rules this is the
node before the failing call (so the rule fires in time to prevent the mistake). The trigger anchors the
5


FORGED_FROM edge; at query time, matching the agent’s current context against trigger embeddings
surfaces the linked rule.
Progressive injection.
Rules arrive at the model through two channels. Stage 1 (before the agent
starts) injects unconditional rules (FORMAT type, plus any rule whose trigger matches the initial query)
through the user channel as a fabricated user/assistant dialogue pair prepended to the conversation.
Stage 2+ (between tool calls) re-retrieves using the agent’s accumulated context (query plus all prior
tool calls and results) against trigger accumulated embeddings, and adds each newly triggered rule to
the system prompt for the next model call. The two channels are intentionally different (Section 7).
This stage-to-stage matching surfaces data-conditional rules at the moment the triggering data appears,
and re-injecting at the decision point mitigates the “lost in the middle” problem [28].
Conflict resolution.
When retrieval surfaces rules from the same conflict group, resolution is
three-tiered: (i) prefer the querying actor’s rule if they are a party to the conflict; (ii) otherwise pick
the majority rule by supporting corrections; (iii) if no majority, abstain. All rules are stored, and
selection happens at injection time per actor, allowing the same rule set to serve different actors
differently.
5
DC-Bench
DC-Bench evaluates behavioral recall: can the system learn from corrections and self-assessment,
then apply that learning to a novel subject? It comprises 71 scenarios across 9 behavioral dimen-
sions (Behavioral Change, Conditional Activation, Exception Handling, Generalization Boundary,
Implicit Learning, Persistence, Recall, Scope Precision, Temporal Coherence; per-scenario scores
in Appendix A), built on four principles. Each dimension contains scenarios from both a financial
analyst skill and a customer support skill, testing whether behavioral learning transfers across agent
domains.
Real agent traces with controlled tools.
Every seed is a real trace captured by running the agent
end to end. The trace records the model’s actual messages, reasoning trajectory, tool calls, tool results,
and subsequent author-provided behavioral corrections. The agent therefore determines which tools
to call, in what order, and how to react to their results. Only the external environment is controlled:
tools are mocks whose outputs are predetermined for each scenario, ensuring that every approach
encounters the same evidence while preserving natural action sequences and trace structure.
Seed-then-test on unseen subjects.
Each scenario seeds corrections for one company (Acme) and
queries about a different company (Beta), forcing behavioral generalization.
Decoupled evaluation.
Each approach captures with its own pipeline, but the test phase uses an
identical agent (same skill prompts, tools, LLM config). The only variable at test time is the injected
context, so score differences reflect retrieval and injection quality.
Scenario isolation.
Every scenario starts with a fresh memory store. Memories do not carry across
scenarios, preventing contamination from unrelated corrections and ensuring that each score reflects
only the seed trace specified for that scenario. The five repeated runs share the scenario specification
but do not inherit memory from another scenario.
Dual scoring and compliance.
A GPT-4 judge evaluates each output against a 3–8-item rubric
(positive or negative mode, weighted 1–3). The satisfied rubric weight is normalized by the applicable
total weight to produce a per-run compliance score between 0 and 100. We average the five runs
for each scenario–approach pair, then macro-average scenario scores within each dimension and
across all 71 scenarios. Programmatic checks verify deterministic constraints (tool_call_max,
source_not_called, output_contains, tool_param_check); programmatic failure forces a 0.
Each scenario–approach pair is evaluated over 5 runs.

The progression.
Each step unlocks specific failure dimensions. naive →hybrid (55 →70%):
structure. Typed LED_TO edges and accumulated embeddings resolve Persistence (21 →82%) and
Conditional Activation (53 →80%). However, hybrid provides no improvement on Implicit Learning
(10 →0%), which requires tool-trace analysis. hybrid →lucid (70 →82%): self-assessment.
Sonnet 4 over tool-only traces unlocks Implicit Learning (0 →78%), inaccessible to any correction-
only approach. lucid →forge (82 →95%): compiled, triggered delivery. Strong-model rule
compilation, per-actor conflict groups, and trigger-based progressive injection close Generalization
(67 →100%), Implicit Learning (78 →90%), Recall (89 →100%), and Conditional Activation
(84 →95%). This cumulative stage measures the combined effect of compilation, conflict resolution,
triggering, and progressive injection. The memory also never regresses the base: on every scenario
the no-injection control already passes, forge_dc still passes, while each predecessor fails at least
one (Table 5).

Cross-model validation.
We also ran the full benchmark on five additional frontier models: Sonnet
4.5, Opus 4.5, Opus 4.6, GPT-4.1, and GPT-5.5. forge_dc mean compliance stays in the 0.93 to

In-session value.
In a separate test we kept the seed conversation in the agent’s message history
at test time, on the 54 scenarios that do not hinge on a cross-session boundary by design. The raw
conversation alone reaches 69% compliance; forge_dc on top of the same in-context conversation
reaches 90%. The gap is sharpest on implicit-learning, where the raw conversation scores 0% (the
patterns come from tool-call traces, not from human corrections) and forge_dc scores above 80%.
Behavioral memory adds value within a session as well as across sessions.

Findings and Design Considerations
Each finding pairs with a design consideration for anyone building behavioral memory for an LLM
agent.
Finding 1: Directive-form memory produces a recurring compliance advantage (the “Only
Rules Rule”).
Across the system progression, agents follow compiled behavioral directives more
consistently than retrieved descriptive corrections. We call this recurring pattern the “Only Rules
Rule.” Its practical implication is that behavioral memory must be optimized for action, not retrieval
alone: representation, activation, and delivery jointly shape compliance. Consideration: evaluate
whether retrieved memory changes behavior, not only whether the correct text was retrieved.
Finding 2: FORMAT and CONTENT rules retrieve differently.
Formatting rules (“include USD”)
have no embedding similarity to the queries they apply to. Pure semantic retrieval misses them at
scale. Consideration: tag rules by type at capture and route them differently at retrieval. Embedding
similarity is the right primitive for content rules and the wrong primitive for formatting rules.
Finding 3: Data-conditional rules need to fire at the decision point.
Rules that depend on tool
data cannot be evaluated at query time. They have to be surfaced when the triggering data appears.
Consideration: re-retrieve as the agent accumulates context and add newly triggered rules to the
system prompt between tool calls.
Finding 4: Adding reasoning to a rule does not help, and sometimes hurts.
A variant (forge_dc
_reasoning) that attaches a one-sentence justification to each rule scores flat or slightly lower than
8


the bare directive on every model we tested. Given the reason behind a directive, the model evaluates
the directive and sometimes decides to override it. Consideration: do not try to convince the
model with reasoning. In our rule-based configuration, extra judgment material does not improve
compliance and can invite the model to second-guess.
Finding 5: The injection channel is part of the design.
The channel a rule arrives through is
a design choice separate from what the rule says. Different channels carry different trust profiles,
compete differently with the task for attention, and dilute when multiple instruction streams share
one slot. The channel that works for one stage of injection is not always the right one for another, and
what works on one model is not guaranteed to work on the next. Consideration: treat each stage’s
channel as a first-class design decision and re-validate when the model generation changes.
Finding 6: A memory must not regress the base.
Injected guidance can make an agent worse than
no memory: a rule that surfaces on a case it does not fit, or that overrides behavior the agent already
produces correctly, degrades an output that needed no change. This is easy to miss when a memory is
scored only on the cases it targets, so it is worth measuring against a no-injection baseline across
every dimension. Consideration: learn only from failures and corrections, and default to staying
silent when nothing needs to change, so the memory never degrades behavior the agent already gets
right.
Closing observation.
An LLM agent is a wrapped LLM. The memory layer is one source of the
tokens the model conditions on. Whether the agent acts on those tokens depends on what the model
was trained to do with instructions in that form, from that slot, in that voice. A behavioral memory
architecture has to be designed with this dependency in mind.
8
Discussion
Limitations.
The five-stage progression evaluates cumulative architectures and does not isolate the
individual effects of compilation, triggering, conflict resolution, or injection placement. DC-Bench,
the five approaches, the judge rubrics, and the AWM/Memp adaptations were built by the same
team. The mem0 and zep results reflect the retrieval configurations used here and may improve under
different tuning. The benchmark covers two domains, and compliance depends on the instruction-
following behavior of specific model versions.
Why corrections detach from retrieval (hypothesis).
We hypothesize that the asymmetry between
in-session and retrieved corrections is mediated by attention. With a wrong output present, the
correction text has a high-similarity neighbor that pulls it into attention at generation time. Without
one, the correction competes poorly with the rest of the prompt for attention, especially when placed
early in a long context [28]. We further hypothesize that imperative tokens (RULE, MUST, MANDATORY)
act as attention magnets independent of semantic similarity, because instruction following is heavily
reinforced during training. This is an interpretation consistent with the data, not a verified mechanism.
Verifying it would require attention analysis on a white-box model of comparable capability.
9
Conclusion
Much of the agent memory landscape emphasizes factual recall. Whether an agent applies a previously
learned correction to a new situation is what decides if a long-running deployment improves over time,
and it has been largely unmeasured. We built DC-Bench to make that question testable and developed
Decision Context, a four-layer pipeline that compiles behavioral signals into imperative RULE
directives. Through five approaches we arrived at forge_dc, which reaches 95% mean compliance
on DC-Bench and holds in the 0.93 to 0.97 range across six frontier models from Anthropic and
OpenAI. The external memory baselines, mem0 and zep, sit at 12% and 15%.
What emerges is a different shape for behavioral memory than for factual memory. Retrieval is
necessary but not sufficient. The form the rule takes, the slot it occupies, and the channel it travels
through decide whether the agent acts on the retrieved content, and those choices shift across model
generations. The next frontier is behavioral memory: systems that learn how to act differently as a
result of what happened. We hope DC-Bench provides a measurable target for that work.
