Approximate nearest neighbor search (ANNS) over high-dimensional vectors is a core primitive in modern
retrieval systems. In practice, objects are often also associated with labels (e.g., attributes or keywords), and
retrieval must combine vector similarity with explicit label-based filtering, giving rise to label-filtered ANNS.
This task is challenging because label filtering and ANNS favor very different index structures, selective filters
fragment the admissible search space, and updates complicate index maintenance.
To address these challenges, we propose DYLAN, a dynamic composite index for label-filtered ANNS
supporting containment, overlap, and their conjunctions and disjunctions. DYLAN organizes label sets by
shared prefixes in a frequency-ordered trie and selectively shares HNSW-style graph indices across trie-induced
subsets, so that each trie region has a constant-factor covering index while each object participates in only
logarithmically many indices. To mitigate fragmentation, DYLAN performs a cross-region multi-graph search
that exploits ancestor-level indices as bridges between otherwise isolated trie regions. To support insertions,
it adopts a threshold-based maintenance scheme that rebuilds shared indices only when necessary, yielding
low amortized update cost.
Extensive experiments with real data show that DYLAN consistently improves query throughput at compa-
rable recall, by up to two orders of magnitude on challenging label-rich datasets, while retaining competitive
memory, construction, and update costs.

model, an unstructured object, such as an image or a full-text article, can be mapped to a high-
dimensional vector called its embedding, in such a way that objects close in the vector space are
often semantically related. For example, under a vision-language model such as CLIP [29], the image
of a pill and the textual instructions of the corresponding medicine map to nearby embeddings. This
enables semantic retrieval over unstructured data, typically through approximate nearest neighbor
search (ANNS) [20], which is supported effectively in modern vector database systems [12, 13, 37].
In practice, however, retrieval is rarely based on vector similarity alone. Each object is often also
associated with a set of labels, such as categories, tags, or keywords. For example, medical articles
may be tagged as “papers in reputed medical journals”, “manufacturer instructions”, or “social
posts”. Accordingly, ANNS is often augmented with explicit label-based filtering, e.g., retrieving
only papers in reputed medical journals and manufacturer instructions, so as to provide stronger
control over the source of information. Such a query is referred to as label-filtered ANNS [19].
Main challenges. Although both ANNS and label-based filtering have been studied extensively,
their combination remains challenging because the two tasks favor fundamentally different index
structures. Label filtering is typically supported by set-oriented structures such as inverted lists [45],
whereas ANNS is usually supported by graph-based indices such as HNSW [26]. A straightforward
approach is to choose one of these structures, which leads to either pre-filtering (i.e., employing a
label index to filter objects but performing ANNS index-free) or post-filtering (index-based ANNS
with post-processing to filter the results with labels). The former may incur a costly scan over a
large candidate set, whereas the latter often requires substantial over-retrieval to maintain recall.
A more integrated direction, called in-filtering [28], performs filtering during graph traversal.
Specifically, when processing a label-filtered ANNS query on an HNSW-style graph [26], the
search expands only neighbors that satisfy the filter. The main difficulty is that a selective filter
may eliminate a large fraction of graph edges, effectively sparsifying the admissible subgraph
and making many qualified objects unreachable, which leads to false dismissals and low recall.
Existing techniques alleviate this issue by exploring larger local neighborhoods, e.g., via two-hop
expansion [28, 32], but this increases traversal cost and still does not exploit the structure of label-set
relationships. In particular, such methods are largely label-agnostic: they treat the filter as a generic
predicate rather than explicitly indexing how label sets relate to one another.

A first line of work augments a single graph index with label information. Filtered-DiskANN [19]
incorporates labels into both index construction and search and supports incremental updates, but
focuses on overlap filters, performs poorly on containment filters, and does not extend to complex
predicates. RWalks [5] instead guides retrieval by a hybrid score combining vector proximity with
label similarity, avoiding a hard admissibility check during expansion; however, it encodes labels
into vector-like representations, so its index expands substantially with many distinct label types,
and updates are not explicitly addressed. As reflected in Table 1, both fail to preserve enough edges
that guide the search from one qualified object to another, and hence struggle with highly selective
label filters, as shown in our experiments.
Another line of work adopts a partitioned multi-graph design. Notably, UNG [11] groups objects
by distinct label sets and builds a separate graph index for each group, which fragments the vector
space and weakens global navigability. UNG alleviates this with a label navigating graph (LNG)
connecting related subgraphs, but cross-region connectivity may still be insufficient for queries
spanning multiple regions, hurting recall. Inserting a new label set may also trigger widespread
changes in the LNG, slowing down updates.
A third category materializes filter states, e.g., UniFilter [41] combines an HNSW graph with
an AND/OR-style graph for label relationships. Targeting containment queries, it caps the size of
its auxiliary label index, so its memory stays bounded as the label universe grows; the price, as
reflected in Table 1, is that new labels are only partially absorbed and query performance degrades
substantially on label-rich datasets.
Finally, Curator [23] applies an IVF-based index for filtered ANNS under low selectivity, whose
search effectiveness is weaker than that of graph-based ANNS indices as acknowledged in [23].
Our solution. We propose DYnamic Label-filtered Approximate Nearest neighbor search (DYLAN),
an index for label-filtered ANNS with efficient updates. DYLAN supports containment, overlap,
and complex predicates composed via conjunction and disjunction. In this paper, we assume the
index fits in main memory, and our implementation is single-threaded.
Our starting point is simple: organizing data objects in a shared-prefix label trie (efficient for
label-based filtering), and then materializing graph indices (effective for ANNS) over trie-induced
subsets of vectors. The challenge, however, is that materializing a graph index for every trie node
incurs prohibitive space and update costs for a large trie, whereas maintaining graph indices only
at lower-level (i.e., fine-grained) trie nodes fragments the search space and restricts the global
navigability required by graph-based ANNS; moreover, updates may substantially change the
trie structure and invalidate pre-built graph indices. DYLAN therefore builds on three key ideas:
selective graph materialization, cross-region graph navigation, and threshold-based maintenance of
shared graph indices.
Concretely, DYLAN is built in two phases. The first constructs a label trie 𝑇capturing the
relationships among label sets in the data: each non-root node 𝑢∈𝑇carries a label and a prefix
formed by the labels on the root-to-𝑢path, each object is assigned to the leaf whose prefix matches
its label set, and the objects assigned to leaves in the subtree rooted at 𝑢form the trie region of 𝑢.
The second phase selectively materializes multiple HNSW-style graph indices embedded in 𝑇, rather
than building one for every trie node. Each object participates in only logarithmically many graph
indices, keeping the total index size near-linear (Theorem 3.9), while the shared index covering a
trie region contains at most a constant factor more objects than the region itself, thereby avoiding
substantial degradation in search efficiency. Intuitively, graph indices near the root capture more
global vector relationships across broader label regions, whereas those near the leaves preserve
denser local connectivity among objects with highly similar label sets.

Given a query vector q with a label predicate Φ, the filtered search space often spans multiple trie
regions. DYLAN first identifies a set N of trie nodes whose subtrees jointly cover the filtered object
set: the regions of containment and overlap predicates are located directly on the trie, whereas a
complex predicate is recursively decomposed into sub-predicates combined by conjunction or dis-
junction, whose regions are computed separately and then combined. Searching the corresponding
graph indices in isolation is ineffective, because the search may become trapped in local optima
and miss promising candidates in other regions. DYLAN therefore performs a cross-region multi-
graph search, further exploiting the graph indices at common ancestors of the nodes in N; these
ancestor-level indices may contain cross-subtree connections that serve as effective bridges across
otherwise isolated trie regions, restoring the global navigability needed by graph-based ANNS.
DYLAN also supports dynamic updates. Following common practice in dynamic graph-based
ANNS indices [22, 41, 43], deletions are handled lazily by marking deleted objects as invalid and
skipping them during search. Insertions are more challenging: a single insertion may affect multiple
shared graph indices along the corresponding root-to-leaf path, and an eager strategy would trigger
the construction of new graph indices or the rebuilding of existing ones. DYLAN therefore adopts
a threshold-based maintenance scheme, which rebuilds a shared graph index only when its size
mismatch with the target region exceeds a prescribed threshold, yielding a provably bounded
amortized insertion cost while preserving the search effectiveness of the maintained indices.
Extensive experiments on multiple real datasets validate the effectiveness of DYLAN. Our main
contributions are as follows.
• We propose the DYLAN index, which introduces a selective graph materialization scheme on a
label trie for effective label-filtered ANNS, while keeping the index size near-linear.
• We design a cross-region multi-graph search algorithm that exploits ancestor graph indices to
bridge fragmented trie regions, balancing query efficiency and accuracy.
• We develop a threshold-based maintenance scheme for dynamic updates, with a provably bounded
amortized insertion cost.
• Extensive experiments show that DYLAN achieves superior query efficiency at similar recall
levels, with favorable update and indexing costs across multiple datasets for label-filtered ANNS.

HNSW
Among existing ANNS algorithms, graph-based methods [17, 26, 35], notably hierarchical navigable
small world (HNSW) [26], have demonstrated superior performance in terms of the trade-off
between query time and accuracy. Given a set 𝑂of 𝑛vectors in R𝑑, it builds a proximity graph
𝐺, in which each vertex corresponds to a vector in 𝑂and each directed edge connects a pair of
vertices according to a pre-defined proximity rule under the distance metric 𝛿of Section 2.1. In
the particular case of HNSW, 𝐺consists of 𝐿layers, each of which contains a proximity graph
known as a navigable small world (NSW); let 𝐻[𝑖] be the graph at layer 𝑖. The number of vertices
decreases exponentially from the bottom layer 𝐻[0] to the top layer 𝐻[𝐿−1], and the maximum
out-degree is 2𝑀at 𝐻[0] and 𝑀at all higher layers, where 𝑀is a system parameter.
Search. To process an ANNS query q, HNSW starts from an entry vertex in the highest layer
𝐻[𝐿−1] and iteratively descends the layers, using the vertex closest to q at the current layer as
the entry point for the next. At the bottom layer 𝐻[0], it performs a greedy search maintaining
a candidate queue 𝐶of discovered vertices to be expanded and a result queue 𝑊of up to 𝑒𝑓
closest vertices to q seen so far. At each step, the vertex closest to q is extracted from 𝐶; the search
terminates once it is farther from q than the farthest vertex in 𝑊, and otherwise its out-neighbors
are examined and eligible vertices are inserted into both queues, with 𝑊truncated to size 𝑒𝑓.
Finally, the top-𝑘closest vertices in 𝑊are returned. A larger value of the system parameter 𝑒𝑓

Our Solution: DYLAN
Next, we present the proposed DYLAN indexing scheme. Sec. 3.1 introduces the label trie and the
selective graph materialization scheme. Secs. 3.2 and 3.3 describe the cross-region query processing
algorithm and the update mechanism based on threshold-based maintenance, respectively. These
three components correspond to the three core challenges outlined in the introduction: index
materialization, cross-region navigability, and dynamic maintenance. Table 2 summarizes the
common notations used in the paper.
3.1
Index Structure
Recall from Sec. 1 that DYLAN organizes objects in a frequency-ordered label trie and selectively
materializes HNSW-style graph indices over trie-induced subsets: the trie captures how label sets
relate to one another, while the graph indices preserve vector-space navigability within and across
the resulting subsets. Materializing a graph index for every trie node, however, would lead to
prohibitive space and update costs. DYLAN therefore selectively shares graph indices among trie
nodes, while bounding the additional search space introduced by such sharing. We next describe
the label trie and the selective graph materialization scheme.

the graph.

Query Processing
Query processing consists of three steps. First, given a filter Φ, we identify a set N of trie nodes
whose corresponding trie regions 𝑂𝑢form an exact disjoint cover of 𝑂Φ. Second, since the graph
indices associated with these trie nodes may be disconnected, we augment them with graph indices
from selected common ancestors, obtaining a graph set G that improves cross-region connectivity.
Finally, we jointly traverse the graphs in G and apply Φ to filter the visited objects. We describe
these three steps below.

Key-ancestor graph selection. Once the disjoint cover set N is computed, it is still challenging
to process the query. For each node 𝑢∈N, the 𝛼-approximate guarantee ensures that 𝑢.𝑖𝑛𝑑𝑒𝑥.𝐺
contains all objects in 𝑂𝑢while introducing only a constant-factor amount of additional search
space. Thus, the selected graph indices primarily serve to maintain search quality. However, these
graphs may be disconnected. A naive approach is to perform a separate ANN search on each graph
and subsequently merge the results, which is inefficient as the cost grows with the number of
nodes in N. Another approach is to perform a single HNSW search over all graphs with a shared
priority queue initialized with the entry point of each graph. However, in the absence of connecting
edges between different graphs, the search may become trapped in one graph and overlook closer
candidates in other regions.
The composite structure of DYLAN provides a natural solution to this problem. In particular,
if nodes in N occur in the subtrees rooted at two or more distinct children of a trie node 𝑎, the
HNSW graph associated with 𝑎may contain edges spanning these child subtrees.
Such edges can connect otherwise isolated graph indices and guide the search across different
coverage regions. We refer to selected common ancestors that provide such cross-region connectivity
as key ancestor nodes, defined below.
Definition 3.11 (Key Ancestor Node). Given a disjoint cover N, a trie node 𝑎is a key ancestor if
nodes in N occur in the subtrees rooted at two or more distinct children of 𝑎.

which we leave as future work.

For deletions, as in most ANNS indices such as HNSW described in Sec. 2.2, we apply soft
deletion and simply mark the corresponding vertices as invalid, which are skipped during search.
We therefore focus on insertions, which trigger non-trivial index maintenance. The insertion of an
object o includes three main steps: (i) insert o into the label trie 𝑇, (ii) update the affected graph
indices along the insertion path in𝑇, and (iii) adjust the graph index used by each node, and rebuild
an index if it becomes insufficiently effective for its associated node.
The first two steps update the existing trie and graph structures locally. For (i), all operations
are lightweight, using only O(|𝑓𝑜|) time, where |𝑓𝑜| is the number of labels in 𝑜. For step (ii), since
an object belongs to at most 𝑂(min{|𝑓𝑜|, log𝑛}) graphs, the cost is bounded by 𝑂(min{|𝑓𝑜|, log𝑛} ·
(𝑐upd + 𝑐𝑞)), where 𝑛is the number of objects in the dataset 𝑂, 𝑐upd is the cost for inserting an
object into an HNSW index, and 𝑐𝑞is the cost of a query in DYLAN.
The main challenge lies in the third step, where the size change of an affected subtree may
alter its log_size and hence its graph-sharing relationship. Adjusting this relationship may involve
expensive index rebuilding. To avoid rebuilding an index immediately after every such change, we
adopt a threshold-based maintenance strategy: we allow the effective index for each node to be a
4-approximate index (see Def. 3.3). By tolerating a slightly weaker index guarantee, we postpone
expensive rebuilds until the accumulated changes exceed a threshold. The cost of rebuilding is
then amortized over later updates, which bounds the amortized time complexity per insertion to
O |𝑓𝑜|𝑀+ min{|𝑓𝑜|, log𝑛} · (𝑐upd + 𝑐𝑞).

New labels and frequency drift. A label unseen at build time does not restructure the trie: it is
assigned the next available ID upon its first insertion, and since this ID is the largest so far, it is
traversed last in 𝑓o, so the insertion path follows existing nodes over the previously seen labels
and branches off only near the leaf. Existing IDs are never reassigned, and the terminal symbol #
ranks after every ordinary label, so the ordering invariant of Def. 3.1 is preserved. However, the
frequency order drifts from the true frequencies as updates accumulate, which affects efficiency
only, not correctness: the label trie and the disjoint cover computation of Sec. 3.2 are exact under
any ordering, which serves solely to place frequent labels near the root, where larger trie regions
admit more graph sharing. Drift has two effects: contSearch selects max{𝑓𝑞} as the least frequent
query label (Alg. 2, Line 9), so a frequent new label makes this choice suboptimal and widens the
scan of 𝐼𝑙; and frequent labels placed deep in the trie make it bushier, increasing trie space. Both
effects remain mild in our experiments (Figs. 23–24). If desired, rebuilding whenever 𝑛doubles
refreshes the ordering and amortizes to the same order as Thm. 3.15.
4
Experiments
We compare our DYLAN with state-of-the-art label-filtered ANNS methods. DYLAN is implemented
in C++, and all optimizations are enabled for competitor code. All indices reside in memory, and all
experiments are conducted single-threaded on a Linux machine with an Intel Xeon Gold 5320 CPU
@ 2.20GHz and 1TB memory.
Datasets. The experiments involve six real datasets. Five of them, together with their query settings,
are taken from the filtered-ANNS benchmark [33], which is widely tested in related research for
filtered ANNS [5, 11, 28, 32]: (i) TripClick [30], a large-scale health information retrieval dataset
comprising click logs from the Trip Database health web search engine; (ii) LAION1M [31], a
publicly available dataset of CLIP-filtered [29] image-text pairs; (iii) YFCC [36], a 1M-vector subset
of YFCC100M containing image/video embeddings and associated labels; and (iv) YTB-Audio and (v)
YTB-Video [4], a benchmark of millions of videos annotated with thousands of machine-generated
topical entities. We additionally build (vi) Yelp1M for RAG-style workloads: each review in the
Yelp Open Dataset [3] is treated as one text chunk, embedded into a 384-dimensional vector using
all-MiniLM-L6-v2 [39], and labeled with the multi-valued categories of its associated business.
Table 3 reports the statistics of these 6 datasets. The last column reports |𝑟|, the absolute Pearson
correlation between the label-set Jaccard similarity and the 𝐿2 distance of 1M randomly sampled
object pairs per dataset (using distance instead of similarity only flips the sign). A small |𝑟| thus
indicates that objects with similar label sets are not systematically closer in the vector space.
4.1
Experimental Settings
Evaluation metrics. Following prior work [5, 11, 19], we use queries per second (QPS) to measure
throughput and recall (defined in Sec. 2.1) to measure result quality, with 𝑘= 10 in all experiments.
We use 𝑠𝑒𝑙𝑒𝑐𝑡𝑖𝑣𝑖𝑡𝑦(𝑂, Φ) = |𝑂Φ|/|𝑂| to denote the proportion of objects satisfying the filter.
Query generation. We generate two types of queries for each dataset, with containment and
overlap label constraints. We first randomly generate candidate query label sets according to label
frequencies and compute their actual filter selectivities. We bucket the candidates into selectivity
ranges defined by powers of two and sample queries across these buckets to obtain workloads with
diverse selectivities while keeping the average selectivity around 0.09 for containment and 0.19
for overlap. Due to their skewed label distributions, the resulting averages on YFCC and TripClick
may deviate from these targets.
Competitors. We include the following methods in our experimental evaluation: (i) ACORN-1
and ACORN-𝛾[28], (ii) NaviX [32], (iii) Filtered-DiskANN [19], (iv) RWalks [5], (v) UNG [11], (vi)
UniFilter [41], (vii) Curator [23], (viii) Prefilter (described in Sec. 1), (ix) our DYLAN.

Impact of update. We evaluate two update workloads, comparing in each case an index built
directly on the final object set against one that reaches the same set through updates. The insertion-
only workload pre-builds on 80% of the objects and inserts the remaining 20%; the mixed workload
additionally deletes a disjoint, randomly selected 20% of the initial build set. Figs. 19 and 20 report
the two workloads on YTB-Video; the other datasets lead to the same conclusions and are deferred
to Appendix A.8. Under both, the recall-QPS curves of the updated index stay close to those of the
directly built one. This confirms the trade-off targeted by our threshold-based maintenance: keeping
a static index consistent with the data would require a full rebuild per update, at about 2×104 s each
(Fig. 17), whereas DYLAN absorbs an insertion in milliseconds (Fig. 18) with essentially no loss in
query accuracy. Insertions go through the maintenance scheme of Sec. 3.3, which keeps each node’s
index a 4-approximate one for its region (Thm. 3.15), while deletions are even cheaper, since they
only mark vertices as invalid and leave the graph topology untouched. As in standard soft-deletion
practice, invalid vertices accumulate under deletion-heavy workloads; a periodic compaction can
be applied when needed.
Query cost breakdown. To attribute DYLAN’s speedup to its index design, we instrument graph-
based search at recall 0.9 and record the numbers of visited points and distance computations,
together with a query-time breakdown. The two counts differ because points rejected by the
label filter incur no distance computation. On YTB-Audio, DYLAN visits 38.6× fewer points and
performs 75.5× fewer distance computations than UNG, reducing distance-computation time by
37.3×. The remaining throughput gap mainly comes from UNG’s preprocessing for finding minimum
supersets of the query label set, which is negligible in DYLAN. Figs. 21-22 report the corresponding
breakdowns on YFCC and YTB-Audio for both containment and overlap queries, excluding methods
that cannot reach 0.9 recall. Across both datasets, the speedup is explained by the number of points
the search needs to examine and the number of distance computations rather than by per-operation
efficiency, indicating that it stems from the index design rather than from implementation-level
optimizations.

Robustness study: frequency drift and new labels. We test robustness under frequency shift
and new label insertion with 50/50 dynamic workloads on YFCC and YTB-Audio (a 50/50 split
rather than the 80/20 used elsewhere, for a more aggressive shift): half of the data builds the initial
index and the other half is inserted, with label ordering determined only from the initial set. For
frequency shift, each object is scored by the average of log(1 + freq(𝑙)) over its labels 𝑙, and the
50% insertion suffix is sampled without replacement with probability biased toward high-score
objects. This makes high-frequency-label objects appear disproportionately during insertion. For
new label insertion, we maximize label diversity in the inserted half, introducing 169,496 new labels
on YFCC and 3,612 on YTB-Audio (93% and 94% of their label universes). Figs. 23-24 show that the
performance remains close to the original, demonstrating the robustness of DYLAN to evolving
label distributions.
Ablation study of optimizations. Fig. 25 evaluates two optimizations of DYLAN on YTB-Audio.
The corresponding results on YFCC are deferred to Appendix A.9 for space. First, we replace
multi-graph search with independent search, which searches each graph separately and merges
the results. The resulting drop in the QPS-recall tradeoff confirms that the key-ancestor graphs
are important for bridging otherwise disconnected regions and avoiding local optima. Second,
we disable supplementEdges. Its impact is dataset-dependent: it yields a clear improvement on
YTB-Audio but little on YFCC, whose materialized graphs are already well connected.
Scalability study. We evaluate scalability in two dimensions: the number of vectors and the size
of the label universe.
For the former, we use YFCC10M from the Big ANN Benchmarks [34], which shares the same
data source as YFCC. We vary the dataset size from 2M to 10M vectors, using the same queries as
on YFCC, and report QPS at a fixed recall of 0.90. Fig. 26 shows that the QPS of DYLAN degrades
only mildly as the dataset grows, and that DYLAN is the fastest method on both containment and
overlap queries across the entire range, typically by an order of magnitude over most baselines. The
only competitive baseline is Filtered-DiskANN on overlap queries, which performs well on overlap
filters but has no straightforward support for containment; on containment queries it becomes
the slowest method. Hence, no baseline is competitive on both predicate types, whereas DYLAN
handles them within a single index.
For the latter, we measure how the index size of each method grows with the size of the label
universe across the five 1M-scale datasets, excluding the raw vector storage so that only the index
structures are compared. The results, reported in Appendix A.5, are empirically consistent with the
Label Scalability column of Table 1: the index size of DYLAN and most baselines stays within a
narrow range, while that of RWalks grows sharply.
Impact of label-vector correlation. DYLAN does not assume that objects with similar label sets
are close in vector space. As shown in Table 3, the five widely adopted datasets all have absolute
Pearson correlation |𝑟| ≤0.0428, whereas the newly added Yelp1M reaches 0.48; bucketing object
pairs by label-set size does not change this picture, as reported in Appendix A.7. We therefore use
Yelp1M to isolate the effect of |𝑟|: keeping both the vectors and the multiset of label sets unchanged,
we vary their assignment to construct six variants with |𝑟| from approximately 0 to 0.5 (higher
values are hard to realize without synthesizing label sets). Fig. 27 reports the QPS at recall 0.9, which
is nearly unchanged across all correlation levels for both query types. This robustness follows
from our design. Correlation mainly changes how the qualifying objects sit in the vector space
relative to the trie regions, and either way the search covers them: when |𝑟| is high, the results
concentrate within a region’s own graph; when |𝑟| is low, they are reached across regions via the
key-ancestor graphs, so the effective search graph is the union of the graphs in G rather than any
single per-region graph.

5
Related Work
Approximate nearest neighbor search. Existing ANNS solutions can be broadly categorized
into three classes: LSH-based, PQ-based, and graph-based. Locality-sensitive hashing (LSH) and
its variants, e.g., [6, 7, 14, 20, 40], provide rigorous theoretical error guarantees, but often incur
considerable time and space overhead in practice. Product quantization (PQ) [21] partitions the high-
dimensional vector space into multiple low-dimensional subspaces, and quantizes each subspace to
compress the vectors. PQ-based methods, e.g. [8–10, 18, 24] trade result accuracy for significantly
lower memory usage, achieving high scalability. Graph-based methods [15, 17, 25, 26, 35] build a
proximity graph for the dataset, where vertices represent vectors and edges connect similar vectors.
ANNS with attribute filtering. There exist a plethora of research works [16, 19, 27, 38, 44, 46] on
designing generic solutions for attribute-filtered ANNS. Such solutions are often less effective than
specialized methods for particular filters [16, 46]. Beyond label filters, range-filtered ANNS has also
been studied [22, 42, 43, 46], which is orthogonal to our work.
6
Conclusion
This paper presented DYLAN, a dynamic composite index for label-filtered ANNS that combines a
frequency-ordered label trie, selective HNSW-style graph materialization, cross-region multi-graph
search, and threshold-based index maintenance. Experiments on real datasets show that DYLAN
achieves superior query efficiency at comparable recall, especially on label-rich datasets, while
maintaining favorable indexing and update-cost trade-offs. Future work includes an efficient multi-
threaded implementation, designing efficient index for external-memory settings, and considering
more complex settings such as joint label and multi-attribute range filters.

Parameter Tuning
Query parameters. All queries retrieve 𝑘= 10 results and are executed single-threaded. For each
approximate method, we vary its query-time search parameter to trace the recall–QPS tradeoff:

recall–QPS plots.
Construction parameters. We tune the build-time parameters of every method, DYLAN included,
on every dataset under one common protocol. Each configuration is scored by its QPS at recall 0.9 —
the operating point used throughout Sec. 4 for most experiments — on containment and on overlap
queries, and we select the configuration maximizing the geometric mean of the two; if only one
query type reaches this recall, the configuration is scored on that type alone, and if neither does,
configurations are ranked by the geometric mean of their highest attained recalls. The swept grids,
with the remaining parameters fixed to the values recommended by the corresponding papers,

A.5
Label Scalability
Sec. 4 evaluates scalability along two dimensions, the number of vectors and the size of the label
universe, and reports only the former; we report the latter here. Fig. 29 plots the index size of each
method against the number of distinct labels over the five 1M-scale datasets (all datasets except
YTB-Audio), whose label universes span from 29 labels on TripClick to 181,931 on YFCC. Since
all five datasets hold roughly the same number of vectors, the raw vector payload is essentially
constant across them and would mask the differences of interest; we therefore exclude it for every
method and report only the index structures built on top of it. The index size of DYLAN grows by
only 4.4× across the entire span and follows a trend similar to most existing methods, indicating
that neither the label trie nor the auxiliary structures grows substantially with the label universe.
RWalks is the clear exception: it encodes labels into vector-like representations, so its index size
increases sharply as labels accumulate, which is also why it exceeds the available 1 TB on YFCC.
These results are consistent with the Label Scalability column of Tab. 1 and confirm that DYLAN
scales effectively to large label universes.
A.6
Impact of Memory Layout
DYLAN stores vectors and adjacency lists separately, so reaching a neighbor’s vector requires an
extra indirection through its object ID. To isolate the cost of this indirection, we compare two layouts
of a standard HNSW graph on LAION1M in Figure 30. The first follows the original implementation
of HNSWlib [2], where each vertex stores its vector contiguously with its adjacency list, avoiding
an additional pointer dereference to locate the vector. The second is the separated layout used
by DYLAN, where adjacency lists hold only object IDs and all vectors reside in a global array, so
expanding a neighbor requires a second random access into that array. The two layouts achieve
nearly identical query performance, differing by less than 1%: the indirection is amortized over the
distance computation that follows it, and the vector array is accessed in the same order regardless
of layout. In DYLAN the effect is even smaller, since many visited neighbors fail the label filter and
are skipped without any vector access at all. Together with Fig. 30, this confirms that the separated
