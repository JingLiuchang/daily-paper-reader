Abstract
Multimodal agents use web and image tools to answer questions beyond their internal knowl-
edge. Some search tasks use images mainly to identify an initial entity, then rely on text
retrieval. These tasks offer limited insight into how agents connect information across im-
ages, objects, and search steps. We therefore focus on visual context management. This in-
volves organizing and using visual information and linking it to other findings during search.
Visually intensive tasks require agents to combine object appearance, local details, or spa-
tial relations with external information. We introduce VisSearch-Bench, with 204 human-
written tasks across 7 main domains and 25 subdomains. It covers Set-wise Visual Search,
Sequential Visual Search, Hybrid Wide–Deep Search, Competitive Visual Disambiguation,
and Visual-Structure-Guided Search. Each task provides a reference answer, traceable evi-
dence, and scoring rules. Accuracy measures complete task success, while Process Score
measures the correctness and completeness of individual results and subquestion answers.
Across 16 multimodal models, the best system fully solves only 26.47% of tasks, even with
search tools. These results highlight the challenge of linking visual evidence with search
results to produce complete answers.

Introduction
Multimodal large language models (MLLMs) are evolving from one-shot visual question answering
systems into agents that can plan, use tools, and interact with the open web over multiple rounds (Luo
et al., 2026; Wu et al., 2026b). With text search, image search, webpage browsing, and region-level
image inspection, these systems can gather evidence beyond the initial prompt and solve complex
information-seeking tasks (Chng et al., 2025; Zhang et al., 2026b). This paradigm is closer to real-
world information seeking than visual question answering based only on parametric knowledge.
At the same time, multimodal benchmarks are placing stronger demands on visual information. Mod-
els must not only understand images in the prompt, but also combine visual and textual evidence
found during search (Hou et al., 2026). MMSearch-Plus (Tao et al., 2026) emphasizes the extraction
and propagation of fine-grained visual cues. MM-BrowseComp (Li et al., 2025) and VisBrowse-
Bench (Zhang et al., 2026c) require agents to actively obtain visual evidence while browsing. To-
gether, these benchmarks make visual evidence an active component of search.
However, existing multimodal search benchmarks often focus on whether visual evidence is used
at some point in a task. How images are used can lead to different task demands. In some existing
tasks, images mainly serve to identify an initial entity (Wang et al., 2023; Chen et al., 2026). Once
the agent obtains the name of a person, object, or place, it can rely mainly on text search. Such tasks
provide limited insight into how agents handle multiple images or connect visual information across
search steps. More recent benchmarks involve more image searches and tool calls. However, higher
counts alone do not imply more complex visual context. We also need to examine how these visual
operations are connected and how they support later searches and the final answer.
Real-world information seeking is more than a series of separate image recognition tasks (Zhang
et al., 2026b). On the open web, agents need to update their understanding as they gather new evi-
dence (Yao et al., 2022). Early evidence may suggest an initial hypothesis. Later evidence may help
compare candidates, rule some out, or identify new ones. New information may also change how an
earlier image is understood. An agent therefore needs to connect visual evidence across search steps
and use it to guide further search (Hu et al., 2023). For example, finding all works in a catalog that
meet a visual condition requires several steps. The agent must first establish the full set of entries,
then inspect their images and combine the results. This raises a basic question: Can agents reliably
organize and use visual evidence as it accumulates during open-web search?
We use visual context management to describe how agents organize and use visual information and
its connections to findings during search. We study this ability through tasks that involve multiple
images, multiple objects, and linked search steps. We examine whether agents can connect visual
observations with external information to compare objects, filter candidates, and follow clues. We
also examine whether they can combine results across steps into a complete and consistent answer.
To evaluate this ability, we introduce VisSearch-Bench, with five task categories that reflect differ-
ent demands of long-horizon visual search. Set-wise Visual Search requires agents to collect and
check visual information for a set of objects, then filter, compare, or combine the results. Sequen-
tial Visual Search uses visual clues from earlier steps to guide later searches. Hybrid Wide–Deep
Search combines step-by-step search with search over a set of objects. Results from one stage de-
termine the search scope or targets of another. Competitive Visual Disambiguation focuses on us-
ing fine visual details to distinguish similar-looking candidates. Visual-Structure-Guided Search
combines object order, spatial positions, or connections in an image with information found through
external search. Agents use this information to locate objects, check conditions, and combine results.

Together, these tasks examine how agents handle multiple images, connect search results, and reason
across steps. Figure 2 presents the five categories and representative tasks from different domains.
VisSearch-Bench contains 204 human-written tasks across 7 main domains and 25 subdomains.
Dataset construction is led by human annotators and supported by automated checks. Annotators
build each task from public, searchable sources. They gather the required images, entity relation-
ships, and facts, then write the question and reference answer. They also document the evidence
supporting the solution. Automated checks and human review examine source accessibility, answer
consistency, and possible shortcuts that bypass the intended visual requirements. For evaluation, we
use Accuracy to measure whether the full answer meets the task requirements. We also use a task-
specific Process Score to assess the correctness and completeness of individual results and answers
to subquestions. Our main contributions are as follows:
1. We introduce a task-based perspective for evaluating visual context management in open-web
search. It focuses on how agents organize information from multiple images, connect different
objects, and use visual findings to guide later searches.
2. We construct VisSearch-Bench, with 204 human-written tasks across 7 main domains and 25
subdomains. Its five categories cover Set-wise Visual Search, Sequential Visual Search, Hybrid
Wide–Deep Search, Competitive Visual Disambiguation, and Visual-Structure-Guided Search.
3. We develop a human-led construction process supported by automated checks. Each task in-
cludes evidence sources, a reference answer, and scoring rules. Our evaluation combines full-
answer accuracy with scores for individual results and subquestions. This measures overall
task completion while also capturing which parts of an answer are correct or missing.

2.2
Agentic Information Seeking
Existing benchmarks evaluate agentic information seeking through reasoning, tool use, and infor-
mation gathering. GAIA focuses on multi-step reasoning and tool use in realistic tasks (Mialon
et al., 2023). BrowseComp requires agents to persistently search the open web for facts that are
diﬀicult to find but easy to verify (Wei et al., 2025). WideSearch extends the focus to large-scale
information gathering, emphasizing complete results that can be checked item by item (Wong et al.,
2025). DeepWideSearch combines multi-hop retrieval with broad information collection to evaluate
whether agents can handle both search depth and breadth (Lan et al., 2025).
Recent benchmarks place greater emphasis on answer coverage and information integration.
DeepSearchQA (Gupta et al., 2026) requires agents to follow linked search steps, gather infor-
mation from different sources, and produce complete answer lists. GISA supports several answer
formats, including individual items, sets, lists, and tables. It also provides human search trajectories
to support process analysis and model training (Zhu et al., 2026). DeepResearch Bench II (Li et al.,
2026) extends evaluation to long-form research reports. It uses detailed scoring criteria derived
from expert reports to assess information coverage, analysis, and presentation.
Research on search methods also examines how agents organize evidence and adjust later search
actions. SearchOS (Zhang et al., 2026b) maintains shared records of pending tasks, evidence, in-
formation coverage, and failed attempts. These records help coordinate multiple agents, fill infor-
mation gaps, and reduce repeated unsuccessful searches. Further work uses search trajectories for
supervised fine-tuning to connect retrieval decisions more closely with the reasoning process (Chen
et al., 2026).
2.3
Multimodal Search and Browsing
BrowseComp (Wei et al., 2025) mainly evaluates text-based information seeking on the open web
and provides a reference for assessing browsing capabilities. MMSearch (Jiang et al., 2024) in-
troduces image-text queries and evaluates query rewriting, result reranking, information summa-
rization, and end-to-end answer generation. BrowseComp-VL (Geng et al., 2025) combines visual
recognition with complex web retrieval, requiring agents to conduct multi-step searches based on
entities in images. Later benchmarks place greater emphasis on the role of visual evidence during
search. MMSearch-Plus (Tao et al., 2026) requires agents to extract fine-grained visual clues and
verify related facts and sources through multiple rounds of image-text retrieval. VDR-Bench (Zeng
et al., 2026) focuses on reducing shortcuts based on textual clues and whole-image matching. It
uses retrieval from image regions, entity verification, and multi-hop question construction to place
greater demands on visual search. VisBrowse-Bench (Zhang et al., 2026c) emphasizes actively gath-
ering visual information from webpages and evaluates spatial localization, attribute recognition, and
reasoning across images.
Other work further expands search structures and process evaluation. InterLV-Search (Hou et al.,
2026) examines how visual and textual evidence guide later search steps. Its open-web tasks in-
clude single-chain and multi-branch structures that involve comparing multiple objects or search
paths. MM-BrowseComp (Li et al., 2025) introduces multimodal evidence in both the input and the
browsing process. It uses reasoning checklists to assess the completion of key steps. BrowseComp-
V3 (Zhang et al., 2026a) covers alignment within image regions, integration across regions, and
reasoning across images. It requires publicly searchable evidence and evaluates both final-answer
accuracy and subgoal completion.

1) Set-wise Visual Search. These tasks involve a clearly defined set of objects. The set may come
from a catalog specified in the question or consist of objects shown in the input images. For
each object, the agent gathers and checks visual information. It then combines this information
with relevant facts to filter, compare, or summarize the results. The main challenge is to cover
all required objects and correctly link the information for each one. Individual judgments must
also remain consistent with the final summary.
2) Sequential Visual Search. These tasks involve multiple search steps that depend on one an-
other. An object, visual clue, or fact found in one step guides later searches. For example, an
agent may first identify an artwork in an image, then find records about its artist, collection, or
exhibitions. Different steps may involve image understanding or text search. The focus is on
correctly connecting the information found across steps to produce the required answer.
3) Hybrid Wide–Deep Search. These tasks combine sequential search with search over a set
of objects. Earlier findings can define the candidate set to be checked. Filtering this set can
then determine the target of the next stage. For example, an agent may start from one work
and identify its award and year. It then examines images of works from the same award cycle
and selects those that meet the given conditions. Further searches gather information about
the selected works. The main challenge is to correctly connect the search scope, individual
judgments, and later targets across stages.
4) Competitive Visual Disambiguation. These tasks focus on visual targets that are easily con-
fused with other objects. Candidates may look similar overall but differ in local shapes, textures,
markings, or individual parts. The agent compares the input image with retrieved images, de-
scriptions, and source records to verify the target’s identity. These tasks assess the accuracy of
visual detail matching and identity verification.

5) Visual-Structure-Guided Search. These tasks use object order, spatial positions, or connec-
tions in an image to determine what to search for, in what order, or where to search next. The
agent combines this structural information with external search results to locate objects, check
conditions, and summarize findings. The main challenge is to correctly connect image struc-
ture, object identities, and search results, then use these connections to complete the task.

4
Experiments
4.1
Experimental Setup
Models and agent frameworks.
We evaluate 16 representative multimodal models. The open-
weight models are GLM-5.3-Flash, Kimi-K3 (Team et al., 2026a), DeepSeek-V4.1-Flash (Xu
et al., 2026), Qwen3.8-27B, Qwen3.8-Flash, Qwen3.6-35B-A3B (Qwen Team, 2026c), Qwen3.6-
27B (Qwen Team, 2026b), Qwen3.5-397B-A17B (Qwen Team, 2026a), GLM-4.6V (Team et al.,
2026b), MiniMax-M3 (Lai et al., 2026), Qwen3-VL-235B-A22B-Thinking, Qwen3-VL-8B-
Instruct, and Qwen3-VL-4B-Instruct (Yang et al., 2025; Bai et al., 2025). The proprietary models
are GPT-5.5, Gemini 3.5 Flash, and Claude Opus 4.8. In the Direct Answer setting, a model receives
only the question and its initial images. We also pair Qwen3.6-35B-A3B, Qwen3.5-397B-A17B,
GPT-5.5, GLM-5.3-Flash, Kimi-K3, DeepSeek-V4.1-Flash, and Qwen3.8-27B with ReAct (Yao
et al., 2022). This comparison measures how much each search framework adds to the same
backbone.
Tools and inference limits.
All ReAct agents have access to five evidence tools: web search, web-
page reading, text-based image search, reverse image search, and image cropping. Each web, image,
or reverse-image search returns up to five results. Retrieved webpage text is truncated to 12,000 char-
acters. Images shown to the model have a longest side of at most 1,536 pixels. The image budget is
20 per task, shared by initial images, retrieved images, and crops. Crops can be enlarged by up to
four times. Each task allows up to 30 ReAct search rounds and 60 evidence-tool calls, with at most
four calls per round. If either limit is reached, one additional model call is used to submit the final
answer from the available evidence.
Inference and evaluation.
We evaluate each system once per task from a fresh context and report
its first complete response as Pass@1. The question, initial images, and required state-and-answer
schema are identical across settings; framework-specific instructions only define the corresponding
tool-use protocol. Forward web and image search use Serper, whereas reverse-image search uses
SerpApi. We use the metrics defined in Section 3.3. Accuracy (Acc.) measures whether the final
11


answer is correct. Process Score measures the correctness and completeness of individual results
and answers to subquestions in the final response, using task-specific scoring rules.
4.2
Main Results
Table 3 reports the Pass@1 results on VisSearch-Bench. In the Direct Answer setting, no model
exceeds 6.37% accuracy. With search, ReAct with Kimi-K3 achieves the highest accuracy at 26.47%.
ReAct with GPT-5.5 reaches 25.49% accuracy and the highest Process Score at 49.52%. The best
model therefore differs across the two metrics. Success on complete tasks does not fully align with
performance on individual items and subquestions. Even the system with the highest accuracy fully
solves only about one quarter of the tasks. There is still much room to improve how models link
information across images, verify objects, and combine results across search steps.
In the available paired experiments, both ReAct and DeerFlow improve accuracy and Process Score
over Direct Answer. For example, Qwen3.5-397B-A17B achieves 1.96% accuracy without tools.
ReAct and DeerFlow raise its accuracy to 15.69% and 10.29%, respectively. Its Process Score also
increases from 12.72% to 32.43% with ReAct and 28.37% with DeerFlow. Thus, search improves
both complete answers and the correctness and completeness of individual results and subquestion
answers.
The effect of the framework also varies across models. For GPT-5.5 and Qwen3.5-397B-A17B,
ReAct outperforms DeerFlow on both metrics. For Qwen3.6-35B-A3B, however, DeerFlow per-
forms better. It achieves 10.78% accuracy and a Process Score of 24.26%, compared with 7.35%
and 23.25% for ReAct. No single framework performs best for every model tested with both frame-
works.

adds computation. Full allows the agent to inspect retrieved images directly and use image cropping.
Table 5 shows that Full achieves the highest accuracy and Process Score for all three models.
Table 6 shows how gains and losses on different tasks partly offset each other. Switching from Full
to Caption loses 8 correct answers for Qwen3.6-35B-A3B, 10 for Qwen3.5-397B-A17B, and 20 for
DeepSeek-V4.1-Flash. Caption also correctly answers 6, 8, and 13 tasks that Full fails, respectively.
For tasks with demanding visual context, the additional description step may reduce the burden
of organizing image information. This may help the agent solve some tasks that fail under Full.
However, general descriptions may omit details needed for cross-image comparisons or other visual
judgments. Across all three models, Caption loses more correct answers than it gains. For example,
Qwen3.5-397B-A17B achieves 14.71% accuracy with Caption, below the 15.69% achieved with
Full. Its Process Score also drops from 32.43% to 25.42%.
Figure 5 provides further analysis of tool use, search costs, and task performance. Models differ in
their tool choices, search rounds, and runtime. More tool calls do not always correspond to higher
accuracy. Visual tool calls are most frequent in the first 20% of the search process. This stage ac-
counts for 41.5%–69.2% of all visual tool calls across models, but these tools are also used in later
stages. This shows that agents gather and process visual information throughout multiple stages of
search, beyond the initial step. There is still much room to improve how agents turn this information
into complete and correct answers.

5
Conclusion
We introduced VisSearch-Bench to evaluate visual context management in long-horizon open-web
search by multimodal agents. The benchmark contains 204 human-written tasks across five task
categories. These tasks examine how agents connect visual observations, object identities, and ex-
ternal information to compare candidates, filter results, and combine findings across steps. Each
task includes traceable evidence sources, a reference answer, and scoring rules. We use full-answer
Accuracy to measure overall task completion. Process Score measures the correctness and complete-
ness of individual results and answers to subquestions. Our evaluation covers 16 multimodal models.
Search improves both accuracy and Process Score in the paired comparisons, but the best system
still fully solves only 26.47% of the tasks. Model strengths also vary across task categories and agent
frameworks. Results on Set-wise Visual Search show a clear gap between obtaining partially correct
results and completing an entire task. Verifying multiple objects and combining findings into com-
plete, consistent answers therefore remain important challenges. VisSearch-Bench provides a basis
for evaluating improvements in handling multiple images, linking clues across steps, and producing
complete answers.

Related Benchmarks
This section describes several widely used public benchmarks for multimodal search. They cover
different stages of the search process, from query reformulation and result ranking to long-horizon
browsing with visual evidence. Table S1 summarizes their main features.
MMSearch.
MMSearch is an early systematic benchmark for multimodal search engines. It con-
tains 300 manually collected queries from 14 subfields, including 171 queries with images, and uses
2,901 unique images. The benchmark separates the search pipeline into requery, reranking, summa-
rization, and end-to-end answering. The component tasks reveal whether a model can reformulate
an image–text query and rank mixed search results, while the end-to-end setting evaluates whether
these operations lead to the correct answer.
MMSearch-Plus.
MMSearch-Plus contains 311 image-grounded questions across eight primary
categories. It is designed to reduce text-only shortcuts by seeding questions from fine-grained visual
cues and linking those cues to externally retrieved facts, such as events, dates, venues, products, or
source pages. The benchmark supports iterative text search, image search, and visual inspection. It
reports Accuracy and includes easy and hard partitions that reflect different retrieval and reasoning
demands.
MM-BrowseComp.
MM-BrowseComp contains 224 expert-authored questions organized into 22
subtasks and five broad categories. Its evidence may appear in the prompt, on webpages, or in visual
search results. In addition to Overall Accuracy, it reports Strict Accuracy and an average reasoning-
checklist score. We follow the oﬀicial Strict Accuracy setting in the cross-benchmark comparison
because it requires both the correct answer and the required supporting reasoning evidence.
VisBrowse-Bench.
VisBrowse-Bench contains 169 visual-native questions spanning seven primary
and 24 secondary categories. Every instance contains at least one image. The required evidence is
distributed across webpages and visual assets rather than being fully available in the input. Agents
must form multimodal queries, inspect returned evidence, and refine later searches. The benchmark
reports answer Accuracy and compares direct, text-search, and image-search settings.

E
Benchmark Construction and Release Details
E.1
Dataset Composition
VisSearch-Bench contains 204 human-authored tasks. Set-wise Visual Search contains 68 tasks;
each of the other four families contains 34. The benchmark also covers seven primary and 25 sec-
ondary content domains. Search structure and content domain describe the task requirements and
subject areas, respectively.
E.2
Data Release Format
The prepared release package stores records in Parquet, with input images embedded in each record.
Table S4 lists the nine fields in the English version. The Chinese version uses question_zh instead
of question_en and retains its original accuracy-prompt key. The local experiment files use JSONL
and include an additional image_paths field for absolute image paths. Their images field stores
relative paths. Absolute paths are excluded from the release package.
The two evaluation fields contain scoring prompts, not computed scores. Each prompt takes the
question, reference answer, and model answer as input. Accuracy evaluates the complete answer.
Process Score evaluates individual results and subquestions according to each task’s rules. Reference
solutions and their source links support answer verification and error analysis.

F
Qualitative Case Studies
We present 17 representative trajectories across five task categories: seven successful and ten failed
runs from multiple models using ReAct or DeerFlow. Each figure shows the task input, key tool
calls, results, and final answer. Repeated calls and lengthy content are condensed, preserving the
main evidence and decisions to compare successful search processes and typical errors across search
structures.
F.1
Set-wise Visual Search
These tasks require full set coverage and a summary of individual judgments. In Figure S1, the
agent crops and searches for all 12 museum objects. It uses oﬀicial material and dimension records
to assign photography equipment and check category counts. The failed case finds an index of 30
measured drawings but explicitly classifies only two (Figure S2). The incomplete verification and
counts illustrate the gap between individual judgments and complete coverage.
F.2
Sequential Visual Search
Search steps must correctly build on earlier findings. Successful cases trace a building photograph
to a step-free entrance (Figure S3), and an anesthesia machine interface to safety notices and suit-
able covers (Figure S4). One failed case treats a similar text description as a map identification and
searches the wrong location (Figure S5). Another finds the correct makerspace and detects conflict-
ing information, yet reports the wrong entity (Figure S6). Errors occur between search steps and
when combining results.
F.3
Hybrid Wide–Deep Search
These tasks connect sequential search with candidate screening. The successful case uses character
relationships and voice-actor information to identify candidate films, then compares poster back-
grounds to find a match (Figure S7). An incorrect motorcycle identification confines broad search
to the wrong category (Figure S8). Incorrect judgments of backpack images allow unsuitable candi-
dates into later specification checks and ranking (Figure S9).
F.4
Competitive Visual Disambiguation
These tasks distinguish similar candidates through visual details. The successful case compares
frames and plates in retrieved images, rejects its initial match, and identifies a grain cutter (Fig-
ure S10). Both failed searches retrieve the correct candidate. One agent favors descriptions of a
similar camera-accessory model (Figure S11). The other retains its initial interpretation of the com-
ponents and misidentifies a photosynthometer (Figure S12). Poor evidence selection can thus lead
to a wrong conclusion even after retrieving the correct candidate.
F.5
Visual-Structure-Guided Search
These tasks combine image order, positions, or connections with external results to select the next
target and determine when to stop. Successful cases use uploader records to return to the image and
select the next asset (Figure S13), and check advisories in order until the wind threshold is reached
(Figure S14). Failures include selecting the wrong next landform (Figure S15), skipping a route stop
(Figure S16), and linking the wrong asset record to the starting ID (Figure S17). These errors change
the path defined by the image and misdirect later searches and answers.
