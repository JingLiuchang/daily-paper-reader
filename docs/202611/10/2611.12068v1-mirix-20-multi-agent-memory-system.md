## 摘要
长期记忆使 LLM 智能体能够实现个性化、保持一致，并复用以往有效的方法。参数化记忆需要训练，整合可能永久丢失细节，而保留每条记录会导致可搜索的存储不断增长。我们提出 MIRIX-2.0，一个旨在同时兼顾实用性、准确性和效率的多智能体记忆系统。在五个 QA 基准中的四个上，它是所比较系统中最准确的。它在 LoCoMo 上达到 91.4%，在 LongMemEval-S 上达到 72.6%，在该基准上领先最强基线 14.3 个百分点；在禁用 AutoDream 时，它在单跳和多跳文档 QA 上分别比 HyperMem 高 31.0 和 22.0 个百分点。作为程序性记忆，它在 ALFWorld 和 WebShop 上于所比较的记忆方法中取得最高平均成功率，并在 MetaClaw-Bench 上达到 49.2%，而 MetaClaw 的技能库为 44.0%。六个带类型的记忆智能体将完整记录保存为记录系统，而来源超图用引用其数据行的 n 元框架索引情节记录和语义记录。检索在显式预算下运行，因此问题所检查的证据不会随历史增长而增长。AutoDream 在写入路径之外合并重复锚点，且不重写任何记录，并将任务会话蒸馏为技能。在禁用 AutoDream 时，MIRIX-2.0 在所有五个计时基准上回答速度快于 HyperMem。它无需微调，可配合闭源和开源模型运行，且代码公开。

## Abstract
Long-term memory lets LLM agents personalize, stay consistent, and reuse what worked before. Parametric memories need training, consolidation can lose details for good, and keeping every record leaves a growing store to search. We present MIRIX-2.0, a multi-agent memory system designed to be practical, accurate, and efficient at once. It is the most accurate of the compared systems on four of five QA benchmarks. It reaches 91.4% on LoCoMo and 72.6% on LongMemEval-S, where it leads the strongest baseline by 14.3 points, and with AutoDream disabled it gains 31.0 and 22.0 points over HyperMem on single-hop and multi-hop document QA. As procedural memory, it yields the highest mean success among the compared memory methods on ALFWorld and WebShop and reaches 49.2% on MetaClaw-Bench, against 44.0% for MetaClaw's skill library. Six typed memory agents keep complete records as the system of record, and a provenance hypergraph indexes episodic and semantic records with n-ary frames that cite their rows. Retrieval runs under explicit budgets, so the evidence a question inspects does not grow with the history. AutoDream merges duplicate anchors outside the write path without rewriting any record, and it distills task sessions into skills. With AutoDream disabled, MIRIX-2.0 answers faster than HyperMem on all five timed benchmarks. It needs no fine-tuning, runs with closed and open models, and its code is public.

# MIRIX-2.0 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体的工作跨度已远超单次上下文窗口。个人助理需要跨月记住用户对话，任务智能体需要在多轮 episode 中复用经验。长期记忆因此成为个性化、一致性和经验复用的基础能力。
- **现有路线的三重取舍**：
  - **抽取/压缩型记忆**（mem0、Auto-Dreamer 等）：存储紧凑，但丢弃的细节永久丢失，且整合过程本身可能制造错误记忆。
  - **全量保存型记忆**：无损，但检索必须在不断增大且噪声增多的历史中搜索，效率随历史膨胀。
  - **图记忆**：二元三元组会把 n 元事实拆成碎片，丢失参与者之间的关联；超图记忆（HyperMem）的超边只记录"归属"而非事实参与者，检索从存储时写的主题摘要向下走，细节只有在其主题被检索到后才可达。
  - **文件系统记忆**（如 Claude Code 的 auto memory）：依赖容量受限的单行摘要索引，摘要未提及的细节只能靠字符串搜索，既不能跨文件消解实体，也不能沿关系追踪。
  - **参数化记忆**：需要训练，无法用于闭源模型。
- **两类记忆的相反需求**：用户中心记忆要求广泛记录并连接细节；智能体中心记忆要求精确精炼，检索过多反而分散注意力。实践系统需用**一个存储同时服务两者**。
- **三项技术要求**：来源保真（source fidelity）、有界访问（bounded access）、时间身份（temporal identity）。

## 2. 方法论

### 2.1 总体思想：存储与索引分离

- **类型化证据平面** \(P_u\) 是系统记录（system of record），保存完整记录；**溯源超图** \(G_u\) 只是索引，图中每个事实都引用其来源行。
- 三条路径：写入路径（先存记录再建索引）、读取路径（规划→图遍历→只解引用选中记录）、AutoDream（写入路径之外运行）。
- 写入顺序保证 fail-soft：向量数据库提交先于图构建，图写入失败不回滚已存记忆；图读取报错时回退到直接证据检索。

### 2.2 类型化证据平面

- **六类记忆智能体**：Core、Episodic、Semantic、Procedural、Resource、Knowledge Vault，各自由专属写入器 \(W_k\) 负责 schema 与更新。
- **Meta Memory Manager** 路由输入：\(K_t = R_\theta(x_t)\)，仅 Episodic 与 Semantic 被超图索引，其余走各自类型化检索路径。
- **记录表示**：\(m=(i,k,y,\tau_e,\tau_m,\rho,z)\)，含不可变行 ID、类型、文本、事件时间、提及时间、来源/分块溯源、检索嵌入。完整摘要与细节留在向量数据库，图只存标识符与紧凑结构元数据。
- **源保真写入**：写入器提示要求保留完整列表、名称、计数、标题、地点、日期，不用主题化摘要替代；情景记忆存事件发生时间而非提及时间，计划事件存计划日期。

### 2.3 溯源保持的 n 元超图

- **超图结构**：\(G_u=(A_u,F_u,E_u)\)，即锚点、具体化事实框架、角色类型化关联边。
- **锚点**：\(a=(i_a,n_a,t_a,e_a,I^E_a,I^S_a)\)，含规范名、实体类型、名称嵌入、提及它的情景/语义行 ID。
  - 确定性键 \(\kappa(n)\) 规范化大小写、标点、虚词、词序、单复数，但保留数字（如 10 Gallons 与 20 Gallons 不合并）。
  - 准入闸门拒绝泛化归档词（advice、details 等）与对话角色伪实体（user、assistant），情景记录最多 16 个锚点、语义最多 18 个。
- **注册表引导的规范化**：ANN 检索最多 4 个相似度 ≥0.72 的既有锚点，每条记录一次 LLM 调用做保守的同实体判断；重命名只能选择已检索到的候选，嵌入只提议比较、不授权合并。
- **n 元框架**：\(f=(p,\{(r_j,a_j)\}_{j=1}^{d_f},\ell_f,\tau_e,\tau_m,C_f)\)，含规范谓词、开放词表角色、字面量属性、来源记录 ID 集合。日期、价格、计数、时长、度量作为字面量保留在框架上而非锚点，保证数值附着于其限定断言。框架至少解析到 2 个不同锚点才实体化；确定性审计发现遗漏高信号细节时，允许一次有界修复调用补充框架，但不能删除主抽取结果。
- **发生身份**：
  - 语义框架：\(id_S(f)=H(u,p,\sigma(f))\)，重复支持同一持久断言会累积引用。
  - 情景框架：\(id_E(f)=H(u,p,\sigma(f),\chi(f))\)，\(\chi(f)\) 取显式事件时间，否则取不可变记忆 ID。因此同一有日期事件共享框架，两个措辞相似但无日期的不同事件保持独立。

### 2.4 图主导的有界检索

- **查询规划**：\(\Pi(q)=(o_q,P_q,C_q,Y_q,T_q,B^B_q,B^R_q)\)，算子分 single、temporal、intersection、list-union、count 五类。
- **预算表**（基础行 \(B^B_q\) / 引用行 \(B^R_q\)）：single 6/4、temporal 6/6、intersection 7/7、list-union 7/9、count 8/12。预算随算子增长，证据量由算子而非历史长度决定。
- **锚点入口**：向量召回 15 个锚点；关系查询额外加入问题中精确命名的锚点（最多 16 个）。评分 \(s_A=s_{vec}+s_{exact}+s_{lex}+s_{pred}+s_{spec}-s_{hub}\)，向量分主导，对数度惩罚抑制通用枢纽，保留前 15。
- **两条证据通道**：
  - 基础召回通道：锚点直接关联的情景/语义 ID，经 n 元框架补充共参与者记忆；同分块支持与时间邻居从向量库溯源重算，不在图中重复建边。
  - 关系引用通道：精确命名锚点做邻接查找，谓词过滤在 Neo4j 内、240 帧上限，最多 \(B^R_q\) 帧渲染为显式图事实并贡献精确引用。
- **事实评分**：\(s_F\) 为九项加性分数（关系、命名实体、字面量、答案类型、时间、交集共享对象、参数特异性、角色方向、计划/完成状态）。无事件时间时状态项以半权重回退到源记录时间；交集问题先保留硬共享对象组。
- **引用平衡融合**：先取最多 \(B^R_q\) 条引用行，再取最多 \(B^B_q\) 条基础行，剩余容量从两通道补足且不重复行 ID；近重复情景改写仅在同一日历日期下折叠。
- **答案时验证**：回答智能体最多 5 次检索调用；规则检查（显式不确定、计数无数字、时间缺失、数字/月份不在证据账本、角色不兼容、计数题含计划事件、所有交集题）触发一次额外检索与重写，且不检查参考答案。
