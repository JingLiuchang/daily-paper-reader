## 摘要
在AI时代，向量数据库上的近似最近邻（ANN）搜索至关重要，因为它支持高维向量上的相似性检索，而这对许多大语言模型（LLM）应用不可或缺。为降低成本并提高可扩展性，向量数据库常被外包给云服务器，这给查询向量包含敏感信息的用户带来了隐私担忧。本文研究非对称隐私保护ANN搜索问题，其中向量数据库是公开的，但用户查询必须对不可信云服务器保持私密。为解决该问题，我们提出ObliSC，一种高效的隐私保护搜索框架，可保护查询隐私免受访问模式泄露的影响。ObliSC包括：(i) 一个搜索基础，以完全不经意性这一强隐私保证来检索ANN；(ii) 并行优化策略，在保持完全不经意性和检索质量的同时加速候选检索与精化。在六个标准ANN基准上的实验表明，ObliSC不仅达到了与基线方法相当的效率和结果质量，而且与所评估的隐私保护方法相比还保持了轻量级索引。

## Abstract
In the AI era, approximate nearest neighbor (ANN) search on vector databases is critical as it supports similarity retrieval over high-dimensional vectors, which is essential for many large language model (LLM) applications. To reduce costs and improve scalability, vector databases are often outsourced to cloud servers, raising privacy concerns for users whose query vectors contain sensitive information. In this work, we study the problem of asymmetric privacy-preserving ANN search, where the vector database is public but user queries must remain private from an untrusted cloud server. To solve this problem, we propose ObliSC, an efficient privacy-preserving search framework that protects query privacy against access-pattern leakage. ObliSC consists of (i) a search base that retrieves ANNs with a strong privacy guarantee of full obliviousness; and (ii) parallel optimization strategies that accelerate candidate retrieval and refinement while preserving full obliviousness and retrieval quality. Experiments on six standard ANN benchmarks show that ObliSC not only achieves efficiency and result quality competitive with baseline methods but also maintains a lightweight index compared with the evaluated privacy-preserving approaches.

## 1. 核心问题与整体含义

- **研究背景**：AI 时代（尤其 RAG 等 LLM 应用）依赖向量数据库上的高维近似最近邻（ANN）检索。为降本增效，向量数据库常外包至云服务器，但用户查询向量往往包含敏感信息（如未公开事件报告嵌入），云服务器可通过访问模式推断查询内容。
- **问题设定**：论文研究**非对称隐私保护 ANN 搜索**——向量数据库与索引对服务提供方（SP）公开，但用户查询必须对不可信 SP 保密。
- **威胁模型**：SP 为诚实但好奇（honest-but-curious），会遵循协议但可能从访问模式推断敏感信息。
- **隐私目标**：(i) 数据隐私——保护查询向量及查询相关中间值（除公开参数 k 外）；(ii) 访问模式隐私——SP 无法从访问模式推断出可能破坏数据隐私的信息。
- **与已有工作的差异**：Preco 需两个互不串通服务器；PP-ANNS 保护查询和数据库内容但无访问模式的正式保证；PACMANN 基于 PIR 保护图遍历；BiSON 用磁盘 ORAM 隐藏图访问但索引/存储开销大。本文聚焦**单服务器**设计，且提供**完全不经意性（Full Obliviousness, FO）**的形式化保证。

## 2. 方法论

### 2.1 核心思想
- 基于子空间碰撞（Subspace Collision, SuCo）检索范式，将明文 SuCo 流水线（IMI 构建 → 候选激活 → 精化）改造为**完全不经意**的版本，同时借助 TEE 保护私有数据值、ORAM 隐藏内存访问地址。
- 关键设计：**固定形状索引**（所有 IMI cell 填充至统一大小）+ **固定预算激活**（固定访问 α̂ 个 cell）+ **固定数量精化**（固定精化 β·n 个候选），使访问调度与查询值无关。

### 2.2 关键技术细节

- **离线索引构建（Algorithm 2）**：
  - 将 d 维均匀采样划分为 Ns 个子空间 S_i，每个子空间再拆成两半 S_i^(1)、S_i^(2)。
  - 对每半执行 K-means（√κ 个质心，t 次迭代），得到质心集 C_i^(1)、C_i^(2) 与分配数组。
  - 按质心对 (u,v) 将条目 j 放入 κ 个 IMI cell 中，记录最大 cell 大小 Max[i]。
  - 用虚拟标识符 ⊥（距离视为 +∞）将每个 cell 填充到 Max[i]，形成固定形状 IMI。构建过程仅依赖数据库与公开参数，天然满足 FO。

- **FO 候选激活（Algorithm 3）**：
  - 计算查询投影 q_i^(1)、q_i^(2) 到两组质心的距离 Dist1、Dist2。
  - 调用 Obli_Sort 对全部 κ 个距离和升序排序，存对应质心对 ID。
  - **固定扫描前 α̂ 个质心对**（不依赖动态碰撞比 α），每 cell 通过 ORAM 读取 Max[i] 个标识符，返回多重集 R_i（大小固定为 α̂·Max[i]）。
  - 复杂度：O(√κ·d/Ns + κ log²κ + α̂·log κ·Σ Max[i])。

- **FO Top-k 精化（Algorithm 4）**：
  - 扫描各子空间激活多重集 R_i，通过 ORAM 读改写为每个标识符累加碰撞得分 SC（虚拟标识符更新到保留的哑元槽）。
  - Obli_Sort 对 SC 降序排序，取前 β·n 个候选，ORAM 读取其原始向量并计算欧氏距离，存入数组 A。
  - 再对 A 按距离升序排序，ORAM 取前 k 个写入 A_k(q)。
  - 复杂度：O(ℓ·log n + n·log²n + β·n·d·log n)，其中 ℓ = Σ α̂·Max[i]。

- **并行优化（Algorithm 5 & 6）**：
  - **并行候选激活**：各子空间独立，分配 p 个 worker/子空间（共 Ns·p），并行计算距离、并行 Batcher 双调排序，sync 后合并。
  - **并行精化（核心难点）**：将共享 SC 更新拆分为
    - **局部累加**：每个子空间维护独立 ORAM 的局部得分数组 SC_i（含哑元槽），并行完成 ℓ_i 次更新；
    - **不经意全局聚合**：各子空间按公开标识符顺序读回 n 个真实得分 V_i，同步后并行按 SC[j] = Σ_i V_i[j] 合并；
    - 并行选择与并行距离计算（p worker 计算 β·n 个原始距离）。
  - 通过 Obli_Set 将虚拟标识符无分支地映射到哑元槽（地址 0），保证无数据依赖分支。
  - 定理：并行版返回与串行版完全相同的结果（Lemma 3），且仍满足 FO（Theorem 2）。

- **安全证明**：基于自适应安全 ORAM 与 TEE 保护私有值，通过不可区分性论证给出 Lemma 1（CanActive FO）、Lemma 2（TopkRefine FO）、Theorem 1（ObliSC FO）、Theorem 2（并行版 FO）。

## 6. 主要结论与发现

- **隐私性**：ObliSC 的索引构建、候选激活、精化三阶段均满足完全不经意性，串行与并行版均通过形式化证明（Theorem 1、2）。
- **效率**：
  - ObliSC-FO 搜索时间高于明文 SuCo，但**显著低于 PACMANN**（Sift100M：312.74 ms vs 1688.6 ms）。
  - 并行版 ObliSC-FO-par 在所有数据集上进一步降低时延（Sift100M 降至 116.18 ms）。
  - 索引构建时间仅为 SuCo 的 1.08–1.65×，远低于 PACMANN（Sift100M：99.13 s vs 14880 s）。
- **质量**：召回呈数据集依赖性——Gist1M 上比 SuCo 低 6.3 个百分点（0.871 vs 0.934），但 Sift100M（0.984 vs 0.982）和 Glove（0.880 vs 0.816）反超。
- **索引大小**：比 SuCo 大（填充所致），但小于 PACMANN（Sift100M：9.62 GB vs 15.94 GB）。
- **参数规律**：p=2 为最优并行度，继续增加因同步与内存争用反而变慢；α̂ 与 β 分别主要控制召回与激活/精化的成本-质量权衡；√κ=50、t=2 是较好的默认值。

## 7. 优点

- **形式化安全保证**：给出完整的 FO 定义与三阶段不可区分性证明，安全论证严谨。
- **索引与算法协同设计**

：固定形状索引（padding 至统一 cell 大小）、固定预算激活（固定 α̂）、固定数量精化（β·n）三者协同，把"数据依赖的访问调度"转化为"公开参数决定的访问调度"，这是实现 FO 的关键，且构建阶段天然公开、无需额外保护，设计上很经济。
- **TEE 与 ORAM 的职责分离**：TEE 只保护私有数据值（查询、向量、得分），ORAM 只隐藏地址，二者解耦，避免了"用 TEE 包办一切"带来的性能与攻击面问题，也规避了多服务器假设。
- **并行化的正确性有保证**：并非简单"多线程加速"，而是把共享得分更新拆成"局部 ORAM 累加 + 不经意全局聚合"，并用 Obli_Set 做无分支哑元映射，Lemma 3 证明并行与串行结果完全一致、Theorem 2 证明并行版仍满足 FO，工程优化没有牺牲安全语义。
- **实用性取向明确**：在 1 亿规模数据集上验证，构建时间仅为明文 SuCo 的 1.08–1.65 倍、搜索时延远低于 PACMANN，且索引小于 PACMANN，说明方案在真实规模下具备可用性，而非仅停留在理论复杂度。
- **实验对照公平**：与明文 SuCo 在相同召回度量（Recall@50）下对齐比较，并明确说明排除 PP-ANNS 的理由（无访问模式保证、未开源），对 BiSON 区分本地与模拟 WAN 两种条件，比较口径较为透明。

## 8. 缺点与局限

- **性能仍有明显税负**：相对明文 SuCo，搜索时延与索引体积均有可观增长（填充导致索引膨胀，ORAM 访问带来对数级开销），在延迟敏感场景（如在线 RAG 首字节时延）下可能不可接受。
- **威胁模型偏强假设**：仅考虑 honest-but-curious 单服务器，未讨论恶意 SP（可偏离协议、返回错误结果）、TEE 侧信道（如缓存/页错误/功耗）以及 TEE 被攻破后的隐私兜底——一旦 TEE 失守，私有值直接暴露，ORAM 只能保护地址。
- **召回存在数据集依赖的下降**：Gist1M 上比 SuCo 低 6.3 个百分点，说明固定预算 α̂ 在高维/难分数据集上会损失候选覆盖，缺少自适应调节机制。
- **参数敏感性与调参负担**：α̂、β、κ、Ns、t 共同影响召回-时延-索引大小三角，且敏感性实验只在 1–2 个数据集上完成，用户在新数据集上缺乏可靠的调参指引。
- **缺少消融与细粒度成本剖析**：未量化 padding、固定预算、并行分解各自的贡献；也未报告 ORAM 带宽、TEE 加解密、排序（Batcher/Obli_Sort）各环节的耗时占比，难以定位瓶颈。
- **实验统计性偏弱**：每数据集仅 100 条查询且未报告方差/置信区间；BiSON 的 WAN 为模拟而非真实跨网部署；与 PP-ANNS 缺乏直接对比。
- **可扩展性边界未探明**：最大规模为 1 亿、维度 ≤960，未讨论十亿级、超高维（如 4096 维 LLM 嵌入）或动态更新（插入/删除）场景；索引构建需全量重跑，增量维护未涉及。

## 9. 可能的改进方向

- **自适应预算**：以公开的、与查询无关的统计量（如各子空间 cell 大小分布）预先设定 α̂ 或分档预算，缓解高维数据集上的召回损失，同时保持 FO。
- **降低填充开销**：采用分层/变长但"形状公开"的填充策略，或对稀疏 cell 使用压缩 ORAM 布局，减小索引膨胀。
- **强化威胁模型**：引入可验证计算或冗余校验以抵御恶意 SP 返回错误结果；结合常量时间实现与侧信道加固，讨论 TEE 失效时的降级保护（如查询加密 + PIR 混合）。
- **更细的并行与流水线**：将激活与精化做流水线重叠，或将 ORAM 访问批处理以提升带宽利用率；探索 GPU/多机下的 Batcher 排序加速。
- **补全实验**：增加消融实验、真实 WAN 部署、更多查询样本与置信区间、跨数据集参数迁移实验，以及与 PP-ANNS 的可行对比。
- **动态与混合场景**：支持增量索引更新；与明文索引混合部署（公开部分明文、敏感部分不经意），在隐私-效率间提供可调档位。

## 10. 对领域的启发与意义

- 论文把"访问模式隐私"从图索引（BiSON/PACMANN 路线）推进到**子空间碰撞/倒排式 ANN**范式，说明 FO 并非只能依附于图遍历，为其他索引族（如 LSH、乘积量化、倒排文件）提供了可复用的"固定形状 + 固定预算 + 固定精化量"改造模板。

- 并行化中"局部累加 + 不经意全局聚合"的模式，对任何需要在 ORAM 上做多路共享累加的隐私算法（如隐私聚合、隐私图计算）都有借鉴价值。
- 在 1 亿规模上给出可接受的时延与构建开销，为隐私保护向量数据库从"原型可行"走向"工程可用"提供了实证支撑，也为 RAG 等 LLM 应用的合规部署提供了技术选项。

## 11. 总体评价

这是一篇问题定位清晰、安全论证严谨、工程实现扎实的系统性工作。其核心贡献在于：首次在单服务器设定下，为基于子空间碰撞的高维 ANN 检索给出**完全不经意性**的形式化保证，并通过固定形状索引、固定预算激活、固定数量精化三项协同设计把数据依赖的访问模式彻底消除；同时以"局部累加 + 不经意全局聚合"实现结果等价的并行加速，在 1 亿规模数据集上取得相对 PACMANN 显著更优的时延与更小的索引。主要不足在于性能税负仍存、威胁模型偏理想化、召回在高维数据集上有下降、实验的消融与统计严谨性有待加强。总体而言，该工作在"隐私保护 ANN 的系统设计与形式化安全"这一交叉方向上具有较高的参考价值，适合作为后续单服务器 FO-ANNS 研究的基础与对照基线。
