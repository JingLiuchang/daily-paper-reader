ABSTRACT 

Long-term agents accumulate large external memory stores as interactions un-fold, increasing the costs of storage, retrieval, and response generation. Effi-ciency is constrained by two coupled factors: a growing record count increases retrieval overhead, while longer retrieved contexts increase prefill computation and decoding-time attention costs. Existing methods prune or consolidate records, but pruning can discard useful evidence, whereas consolidation may produce fewer yet longer retrieval units. We introduce MemFolder , a structure-guided memory folding framework that sequentially reduces record count and context length. The framework comprises two core components that share memory groups, using cross-record structure to guide both evidence consolidation and compact representation. RecordFolder grounds entity mentions, progressively selects rep-resentative yet complementary anchors, and combines semantic and entity affinity with temporal chaining to consolidate compatible records into fewer retrieval units. 

ContextFolder encodes the original records within these groups into compact text and uses verification feedback to revise encodings when key facts cannot be recovered. Experiments on the three text-based memory benchmarks LoCoMo, PersonaMem, and LongMemEval and the two multimodal benchmarks M3-Bench-web and M3-Bench-robot demonstrate the strong performance of our methods. Notably, on Mem0, RecordFolder retains 99.0% of the original average perfor-mance across the three text-based benchmarks with 50% fewer records, exceeding the strongest baseline by 1.9 percentage points in performance retention. Com-bined with ContextFolder, existing record compression methods further shorten their output records while retaining most of their performance.

With a fixed top-k retrieval budget, fewer units can still yield a longer context . We aim to reduce both costs while retaining evidence an agent may need in later sessions. This observation motivates two distinct compression decisions. At the record level , we determine which records can share a retrieval unit while preserving complementary facts and state changes. At the context level , we determine how to encode each group compactly, expressing shared content once while retaining dates and other record-specific details. Group assignments connect these decisions while allowing record count and context length to be optimized separately. We address these two efficiency bottlenecks with MemFolder , a structure-guided memory folding framework with two complementary folding components. As shown in Figure 1(3), RecordFolder 

grounds entity mentions, progressively selects representative yet complementary anchors, and com-bines semantic and entity affinity with temporal chaining to consolidate N records into K retrieval units. Given these groups and their source records, ContextFolder generates compact encodings guided by a target token ratio while keeping one output unit per group. Verification feedback guides revisions when key facts are not recoverable. Given that it is independent of the grouping algorithm, ContextFolder can also shorten the contexts from record compression methods. As a plug-and-play component, ContextFolder also shortens outputs from other record-compression methods, yielding more favorable accuracy–efficiency trade-offs than BabelTele and LLMLingua-2. ContextFolder then compacts each group’s content through budgeted encoding and factual recovery checks that guide revisions to the encoding. 3. 2 RELATED WORK 

LLM Agent Memory Systems. Memory systems preserve information from past interactions for use beyond the current context window. Token-level external memory retains explicit records that can be inspected, updated, and retrieved without modifying model parameters. Generative Agents (Park et al., 2023) stores observations and reflections in a memory stream, while MemGPT (Packer et al., 2023) manages information across memory tiers. Mem0 (Chhikara et al., 2025) extracts and consolidates salient facts from conversations, and A-MEM (Xu et al., 2025) organizes structured notes through dynamically generated links. LightMem (Fang et al., 2026) organizes interactions across sensory, topic-aware short-term, and sleep-time consolidation stages, whereas REMem (Shu et al., 2026) links semantically related episodic memories with compact gists and temporal facts to support iterative agentic retrieval. Other approaches maintain experience in latent representations or model parameters. MemoryLLM (Wang et al., 2024) uses a fixed-size, self-updatable latent memory pool, whereas TMEM (Ren et al., 2026) incorporates distilled experience through online updates to fast LoRA weights. These forms can coexist: MemOS (Li et al., 2025) unifies the management of plaintext, activation-based, and parameter-level memories. Our work focuses on accumulated external records, whose count and textual content determine the size of the store and the evidence available for retrieval. Rather than introducing another memory architecture, MemFolder compresses these records within existing systems while preserving text for retrieval and generation. 

Long-Term Memory Compression. Memory efficiency can be improved during construction, maintenance, or inference. MemoryBank (Zhong et al., 2024) updates retention through forgetting and reinforcement, while SimpleMem (Liu et al., 2026a) constructs compact memory units and recursively consolidates related content. At inference time, LLMLingua (Jiang et al., 2023) shortens prompts, whereas token-level compression methods (Li et al., 2024; Liu et al., 2026b;c; 2025a; Lin et al., 2026) reduce the states retained during generation. These inference-side interventions do not by themselves reduce the number of records in a persistent external store. We study post-construction compression before retrieval, so compressed records can be reused across queries. Post-construction methods reduce existing stores through pruning or consolidation. Stream-MeCo (Wang et al., 2026a) prunes memory graphs using representative sampling and scores based on entity importance and semantic diversity, without rewriting the retained records. MemRefine (Kim et al., 2026) uses embedding similarity to propose candidate pairs, then an LLM judge determines whether their factual content warrants deletion, merging, or preservation. Its refinement loop targets a storage budget measured over serialized entries. MemForest (Wang et al., 2026b) combines global semantic similarity with local temporal continuity to partition memories into EventTrees, then pro-gressively merges records along selected tree edges. It also introduces anchor-guided propagation retrieval to supplement evidence with temporally related memories. MemFolder targets both record count and per-unit context length. Unlike end-to-end memory systems (Liu et al., 2026a; Fang et al., 2026; Shu et al., 2026), which either merge records without bounding per-unit token expansion or expand stores with multi-granularity graph nodes and multi-step retrieval, MemFolder operates as a plug-and-play post-construction layer that jointly folds record count and per-unit length over existing stores. Compared with EventTree-based merging (Wang et al., 2026b), RecordFolder groups records around progressively selected anchors and refines assignments through entity-aware temporal chains. ContextFolder reuses these groups to generate compact encodings under a soft token budget. It checks whether source-derived facts can be recovered from the encoding without exposing the original records to the reader, and uses the feedback for revision. This post-encoding check differs from deciding whether a candidate pair should be merged: it evaluates factual recovery from the resulting compact representation.

Figure 2 presents the pipelines of our MemFolder, which addresses both memory costs by sequentially folding the record store along two axes. RecordFolder grounds records, selects representative and complementary anchors, refines group assignments using entity, semantic, and temporal relations, and consolidates each group into one retrieval unit. ContextFolder reuses these groups to generate compact grammar-based encodings under group-specific budgets: a planner identifies facts to preserve, a compressor rewrites each group, and a verifier checks recovery from the encoding alone. Thus, retrieval accesses fewer units with less context in each. 3.3 RECORD FOLDER : R ECORD COMPRESSION VIA PROGRESSIVE CONSOLIDATION 

Records that refer to the same entities or events can remain in separate retrieval units, splitting related evidence across results. RecordFolder maps N records to K units by grounding entities, selecting complementary anchors, and refining assignments with entity-aware affinity and temporal links. Hungarian matching restricts these links to non-branching chains. An LLM then consolidates each multi-record group chronologically, while singleton records remain unchanged. 

Entity Grounding. The same entity may appear under different names or pronouns, so surface overlap alone can miss connections between records. We use an LLM to extract entities, including people, works, activities, and topics, and assign short canonical labels. Within each session, we process records together to resolve references in context, then process sessions chronologically while carrying earlier labels forward in a registry. The prompt reuses labels for known referents and adds qualifiers to distinguish namesakes. We merge residual label variants whose embedding cosine similarity is at least θent , retaining one representative per connected component. After removing conversation speakers and synthetic event identifiers, the remaining labels form the entity set Ei of record mi for affinity computation and later temporal refinement.

Singleton records remain unchanged, and we embed all resulting units for downstream retrieval and later query answering. 3.4 CONTEXT FOLDER : C ONTEXT COMPRESSION VIA VERIFIED ENCODING 

Consolidating records can reduce the number of retrieval units while lengthening each one; at a fixed retrieval top-k, this need not reduce the context passed to the agent. ContextFolder compresses the original records within each assigned group guided by a target fraction of source tokens, without changing group membership. A planner labels facts by importance and inferability and prepares QA checks. A compressor generates candidate encodings, and a blind verifier tests whether a reader can recover the facts from the encoding alone. Feedback on missing facts and token usage guides revision while preserving each group’s assignment and target ratio throughout compression. 5Preprint. 

Planner: Fact Extraction and Triage. For each group G, an LLM extracts atomic facts from its member records and writes a verification question with an expected answer for each fact. These records are the planner’s only source; downstream test queries and answers do not enter the process. The planner labels facts as high, medium, or low importance, prioritizing key events, entity bindings, exact dates and numbers, and negations. It also marks facts inferable from other facts or common knowledge. We weight facts by importance and discount inferable facts when computing weighted recovery. Let τ ∈ (0 , 1) denote the target fraction of source tokens to retain. Non-inferable high-importance facts are always required. Medium-importance facts are also required when non-inferable and τ ≥ τreq , where τreq is a verification threshold.

@YYYY-MM-DD for event dates, A -> B for state changes, and E: x for attributes. The symbols 

~ and ? indicate negation and uncertainty. The prompt prioritizes non-inferable, high-importance facts, omitting inferable details first and lower-priority content as needed. For retained facts, it requests exact entity names, numbers, and dates. Both the verifier and downstream agent use the same grammar legend to decode these compact symbols consistently. 

Verifier: Blind Recovery Check. Separate answering and judging calls evaluate each candidate. A blind reader receives the encoding, grammar legend, and verification questions, but not the source records or expected answers. It returns UNKNOWN when the encoding lacks sufficient evidence. A judge compares the responses with the reference facts, allowing semantic matches while requiring exact names, dates, and numbers. We run at most Rmax encoding-verification rounds. The loop stops when all required facts pass verification and the encoding uses at most (1 + ϵB )BG tokens, where 

ϵB is the budget tolerance. Otherwise, feedback guides revision until the iteration limit. We select the shortest candidate recovering all required facts. If none passes, we maximize weighted recovery, breaking ties by length. Weighted recovery is the fraction of total fact weight judged recoverable. If the selected encoding is no shorter than SG, we use the shortest candidate below SG, even if it misses required facts. If no candidate is shorter, we retain the source texts as one unit. Because the compressor conditions on both the prioritized fact list and the raw source records (Appendix C), details omitted during triage remain accessible, while the blind verification loop acts as an asymmetric failure-detection heuristic that guards against silent loss of required names, dates, and state changes (see Appendix B.4 for reliability traces).

4.1 EXPERIMENTAL SETTING 

Benchmarks. We evaluate MemFolder on four benchmarks: LoCoMo (Maharana et al., 2024), PersonaMem (Jiang et al., 2025), LongMemEval (Wu et al., 2025), and M3-Bench (Long et al., 2026), covering its web and robot subsets. For each benchmark and memory framework, all methods start from the same store constructed from the original interaction histories. 

Implementations. All experiments are conducted on two NVIDIA A100 (80GB) GPUs. We use gpt-4o-mini for memory node merging. In addition, all other settings, including those of the compared baselines and the underlying memory frameworks, follow the original papers. All experimental results are averaged over three runs. More details are provided in Appendix A. 

Baselines. For record compression, we compare with pruning baselines (Random Pruning, KMeans, and DART (Wen et al., 2025)) and merging baselines (Random Merging, ToMe (Bolya et al., 2023), and MemForest (Wang et al., 2026b)). Effects of Each Design. Table 4 evaluates anchor selection in RecordFolder. DPC achieves the best average accuracy of 57.2 and the highest LoCoMo score of 59.3, while MinMax leads on LongMemEval with 55.6. This indicates that progressive density-and-novelty selection balances local representativeness and complementary coverage. Table 5 isolates the assignment signals. The full model averages 57.2; removing cosine similarity causes the largest drop of 3.4 points, compared with 1.9, 1.1, and 0.6 points for gain gating, entity affinity, and temporal chaining. These results identify embedding similarity as the main semantic signal, with the other terms refining entity and temporal consistency. Table 6 compares pruning and merging with DPC anchors fixed. Merging averages 57.2, 6.1 points above pruning and only 0.9 and 0.2 points below the uncompressed scores on LoCoMo and LongMemEval. This mirrors Tables 1 and 2, where merging also performs better under record reduction. Table 7 evaluates ContextFolder after 50% record reduction. The full model achieves 56.6 and 51.8 accuracy with 12.31 and 13.40 tokens per record on LoCoMo and LongMemEval. Removing the planner lowers accuracy by 0.7 and 0.8 points while increasing token use; removing the verifier saves tokens but costs 1.9 and 1.4 points. The planner thus improves accuracy and compression, while the verifier strengthens recovery at a small token cost. Overall, RecordFolder forms stronger retrieval units, and ContextFolder further compresses their contents. 

Efficiency Analysis. Figure 4 reports retrieval latency across three text-based and two multimodal settings. Mean speedups rise from 1.41 –1.86 × at 50% retention to 1.88–5.34 × at 30%. At 30% retention, mean latency drops by 56%, 81%, and 72% on LoCoMo, LongMemEval, and PersonaMem, respectively; PersonaMem falls from 1,900 to 538 ms. The largest gain appears on LongMemEval, where the mean speedup grows from 1.45 × at 50% retention to 5.34 × at 30%, while tail latency falls from 97.5 to 15.5 ms. This parallel reduction in mean and tail latency shows that record compression alleviates expensive retrieval cases, not only the average query cost. M3-Bench-robot and M3-Bench-web reach 2.30 × and 1.88 × speedups, respectively, although their tail-latency gains are smaller than those on the text benchmarks. This gap suggests that record retrieval is only one part of the latency 9Preprint. in multimodal settings, where additional processing costs remain. Record compression therefore reduces both average and high-latency retrieval overhead as the external memory grows. 

5 CONCLUSION 

Growing external memory stores increase the storage, retrieval, and generation costs of long-term agents. To address these costs, we propose MemFolder, a structure-guided memory folding framework comprising two components: RecordFolder and ContextFolder. The former reduces record count by grouping and consolidating related evidence using semantic, entity, and temporal relations. The latter further reuses these groups for compact encoding, with fact-recovery checks guiding revisions. Experiments across multiple benchmarks demonstrate the strong performance of RecordFolder under record compression. Combined with ContextFolder, existing record compression methods further shorten retrieval units, reducing both record count and context length. AI USE STATEMENT

A ADDITIONAL EXPERIMENTAL DETAILS AND ANALYSIS 

Memory Framework Details. We consider both text-based and multimodal memory frameworks: • Mem0 (Chhikara et al., 2025) is a long-term memory system that extracts, updates, stores, and retrieves persistent textual records from agent interactions. We use Mem0 as the primary text-based framework and construct an uncompressed memory store before applying each compression method. • MemOS (Li et al., 2025) is a memory operating system for AI systems that organizes multiple forms of memory, including plaintext, activation, and parametric memory, under a unified management layer. It provides a framework-level setting for studying record compression beyond a single text-memory implementation. • M3-Agent (Long et al., 2026) is a multimodal agent framework that continuously processes video and audio inputs and builds an entity-centric long-term memory. Its memory integrates visual, auditory, and textual information, which supports multi-turn retrieval and reasoning over dynamic environments. 

Benchmark Details. We evaluate long-term memory compression on three conversational bench-marks and two multimodal video benchmarks: • LoCoMo (Maharana et al., 2024) contains long multi-session conversations and questions covering single-hop, multi-hop, temporal, and open-domain reasoning, testing whether an agent can recover evidence distributed across an extended interaction history. • LongMemEval (Wu et al., 2025) evaluates long-term interactive memory with single-session and multi-session questions, preference tracking, knowledge updates, and temporal reasoning. • PersonaMem (Jiang et al., 2025) benchmarks dynamic user profiling and personalized response generation. We use its 32K setting, which tests user-fact recall, preference evolution, recommendation, and generalization across scenarios. • M3-Bench-robot (Long et al., 2026) is an online first-person video benchmark collected from daily robot environments. Its questions require multi-evidence, multi-hop, cross-modal, person-centered, and general-knowledge reasoning over continuously observed interactions. • M3-Bench-web (Long et al., 2026) is an offline web-video benchmark spanning diverse video categories. It evaluates the same long-term multimodal reasoning abilities over prere-corded videos with questions that require evidence from multiple moments and modalities. 13 Preprint. 

Baseline Details. We compare record compression against pruning and merging baselines: • Random Pruning randomly discards records until the target keep ratio is reached. It isolates the effect of record removal without using content, temporal, or graph information. • KMeans (McQueen, 1967) clusters record embeddings into the target number of groups and retains the record closest to each cluster centroid, providing an embedding-space representative-selection baseline. • DART (Wen et al., 2025) is a diversity-based pruning method that removes highly redundant representations by comparing them with a small set of pivot representations. We adapt this operation from visual tokens to memory records. • StreamMeCo (Wang et al., 2026a) compresses structured memory graphs with a dual strategy: it samples representatives from isolated nodes and prunes connected nodes using entity importance and semantic similarity. • Random Merging partitions records into retained and removed sets, then randomly assigns removed records to retained records for consolidation until the target keep ratio is reached. • ToMe (Bolya et al., 2023) progressively matches similar representations across two partitions and merges each matched pair. We adapt this token merging procedure to records by matching each record with its most similar counterpart. • MemForest (Wang et al., 2026b) combines global semantic similarity with local temporal continuity to partition records into event-centric units. It constructs a maximum-spanning-tree EventTree for each unit and progressively merges high-weight pairs, while using anchor-guided propagation to retrieve relevant temporal neighbors. A.1 IMPLEMENTATION DETAILS 

All compression methods start from the same uncompressed memory store built with each memory framework. For Mem0 (Chhikara et al., 2025) and MemOS (Li et al., 2025), we use gpt-4o-mini 

for memory extraction and updating, and text-embedding-3-small for record embeddings, following the original papers. For M3Agent (Long et al., 2026), we deploy gpt-4o for evaluation and use text-embedding-3-large for record embeddings, as in the original paper. The resulting snapshots are shared by all methods before compression. For each target reduction ratio, methods operate on the same records and are evaluated with the same retrieval and question-answering procedure. We preserve the original question sets and report accuracy together with record-count and token-level statistics. Answer quality on Mem0 and MemOS is judged with gpt-4o-mini ,whereas M3Agent is evaluated with gpt-4o . All methods therefore share a common memory and evaluation protocol within each framework. 

Compression Settings. RecordFolder uses gpt-4o-mini for entity grounding, an entity-label similarity threshold θent = 0 .85 , and a neighborhood cap knn = 5 . Temporal refinement uses a predecessor window W = 50 and at most d = 8 positive-gain links per successor; both signal variances are floored at 10 −6. ContextFolder assigns weights of 3, 2, and 1 to high-, medium-, and low-importance facts and halves the weights of inferable facts. Its medium-importance requirement threshold is τreq = 0 .65 , its minimum token budget is 3, and its budget tolerance is ϵB = 0 .15 .
