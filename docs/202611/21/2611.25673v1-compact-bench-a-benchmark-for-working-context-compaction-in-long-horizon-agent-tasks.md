## 摘要
随着语言模型智能体被应用于越来越长的任务，其工作上下文会持续累积交互历史、工具观察、中间决策和任务进展。上下文压缩提供了一种实用方法来缩减不断增长的历史记录，同时允许执行继续进行，但现代大语言模型的压缩能力仍未被充分理解。我们提出 CompAct-Bench，一个通过工作上下文压缩对智能体任务完成的下游影响来评估该压缩能力的基准。从成功的智能体轨迹出发，我们在执行的不同阶段插入压缩边界，使用待评估模型压缩之前的工作上下文，并让同一执行器继续完成原始任务。为实现不同压缩器之间的公平比较，我们采用轻量级迭代比例调整过程，在受控保留率下对它们进行评估。CompAct-Bench 通过 BrowseComp、SWE-bench 以及内部 CompanyBench 评估，覆盖信息检索、软件工程和面向工作空间的任务。实验表明，即使对前沿模型而言，工作上下文压缩仍然具有很高的有损性：Claude 和 GPT 系列模型总体表现最强，但在激进压缩下，下游任务准确率仍会显著下降。进一步分析表明，失败往往不仅源于信息遗漏，还源于任务状态失真，例如将未解决的问题变成表面上的结论，或遗忘此前已确立的结果，这可能导致错误决策或冗余执行。这些发现凸显出，工作上下文压缩是大语言模型在长时程智能体任务中运行时的一项独特且仍具挑战性的能力。

## Abstract
As language-model agents are applied to increasingly extended tasks, their working context continuously accumulates interaction history, tool observations, intermediate decisions, and task progress. Context compaction offers a practical way to reduce this growing history while allowing execution to continue, yet the compaction ability of modern LLMs remains insufficiently understood. We introduce CompAct-Bench, a benchmark for evaluating working-context compaction through its downstream effect on agent task completion. Starting from successful agent trajectories, we insert compaction boundaries at different stages of execution, compress the preceding working context with the model under evaluation, and let the same executor continue the original task. To enable fair comparison across compactors, we evaluate them under controlled retention ratios using a lightweight iterative ratio-adjustment procedure. CompAct-Bench covers information-seeking, software-engineering, and workspace-oriented tasks through BrowseComp, SWE-bench, and an internal CompanyBench evaluation. Our experiments show that working-context compaction remains highly lossy even for frontier models: Claude- and GPT-family models perform strongest overall, yet substantial degradation in downstream task accuracy persists under aggressive compaction. Further analysis reveals that failures are often caused not only by omitted information, but also by distorted task state, such as turning unresolved issues into apparent conclusions or forgetting previously established results, which can lead to incorrect decisions or redundant execution. These findings highlight working-context compaction as a distinct and still challenging ability for LLMs operating in extended agent tasks.

# CompAct-Bench 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体被广泛用于长时程任务（信息检索、软件工程、工作空间自动化）。执行过程中，工作上下文持续累积用户指令、中间推理、工具观察、失败尝试与部分进展，最终逼近模型上下文窗口上限。
- **现有做法**：主流 agent harness（如 Claude Code、DeepSeek Harness）采用"上下文压缩（compaction）"——由 LM 将累积历史改写为更短的表示，使执行得以跨窗口边界继续；与之相对的是直接截断（truncation）。
- **核心问题**：现有系统把压缩交给 LM，但**模型自身的压缩能力及其对下游执行的影响缺乏系统评估**。有效压缩不是"写一份简洁的过去摘要"，而是"保留后续执行所必需的信息"，具有前瞻性（prospective）。
- **整体含义**：论文将工作上下文压缩重新定义为一种**执行关键（execution-critical）的模型能力**，而非通用摘要生成能力，并构建首个过程级、以任务完成为度量的基准。

## 2. 方法论

### 2.1 核心思想

- 将已有 agent 任务"转化"为压缩任务：从一条**成功完成的参考轨迹**出发，在中间阶段插入压缩边界；边界前的历史由待评估模型压缩；**同一执行器**从对应环境状态继续，用压缩后的上下文完成任务；最终任务成败即压缩质量的直接功能度量。

### 2.2 关键技术细节

- **轨迹筛选**：每个源任务用固定执行器独立运行 3 次，仅保留 3 次全解（pass 3）的任务；剔除少于 8 轮交互的轨迹，以保证上下文规模。
- **边界设置**：在 25%、50%、75% 执行进度处设边界（早/中/晚）；每条轨迹只分配一个边界以控制成本，按轨迹长度分层抽样以减少偏差。
- **形式化**：参考轨迹 τ=(a₁,o₁,…,a_T)，边界 b<T，压缩输入 H_b=(a₁,o₁,…,a_b,o_b)；压缩器 C_φ 输出 M_b=C_φ(H_b; r)，目标保留率 r；实际保留率 r_actual=ℓ(M_b)/ℓ(H_b)。
- **迭代比例校准（IRC）**：为避免"压缩质量"与"输出长度"混淆，采用两阶段校准——① 渐进收缩（按 α=0.82 逐步缩短，允许 β=0.90 小幅越过目标）；② 细粒度调整（在最佳候选基础上按衰减步长 γ=0.85 增删内容）；当相对误差 <ε=0.03 或达到 K=30 次调用即停止，返回**最接近目标**的候选。主实验 r=0.10，接受区间 [0.097, 0.103]。
- **保留头**：原始系统提示与任务指令逐字保留，**不计入**保留率分母；压缩输出须为"可续跑的工作上下文"，而非回顾式摘要。
- **后压缩执行**：执行器接收原始任务指令、M_b 和固定续跑指令，从边界环境状态恢复，**重新生成**续跑而非重放参考轨迹剩余部分。
- **匹配动作预算**：续跑最多允许 T−b 个执行器动作，防止执行器通过额外交互补偿信息损失，使 M_b 成为唯一变量。
- **环境状态重建**：Coding/Workspace 通过确定性动作重放（按原参数重放前 b 轮工具调用）重建边界状态；Search 环境无任务状态，无需重放。
- **评估指标**：严格成功（预算内完成、终止状态成功、被源基准评估器接受）；每个压缩上下文生成一次、评估三次独立续跑，报告 Avg@3 准确率。

- **充分性**：整体较为充分——控制变量严格（执行器、预算、环境状态、长度均固定），pass-3 筛选降低 rollout 方差，统计区间与跨域相关性分析较规范。

## 6. 主要结论与发现

- **压缩高度有损**：12 模型平均后压缩准确率仅 56.7%，最强 Claude Opus 5 为 68.5%，远低于压缩前的 100%。
- **能力部分跨域迁移但任务敏感**：跨域 Spearman 相关为 0.62（Search–Coding）、0.53（Search–Workspace）、0.26（Coding–Workspace），均为正但远小于 1。
- **阶段效应因域而异**：Search 随边界后移单调下降（52.9%→42.6%→34.6%）；Coding 单调上升（64.0%→72.7%→86.1%），12/12 模型在 75% 边界最佳；Workspace 非单调，50% 最高。
- **历史长度不足以解释难度**：三个域的压缩输入长度均随边界增加，但下游趋势相反。
- **任务状态分布是关键机制**：Coding 中已

完成的工作（已修改文件、已通过测试、已定位的 bug）持久化在环境中，压缩器只需保留"剩余待办 + 关键约束 + 已验证结论"，信息损失对续跑的影响相对可控；Search 中所有中间发现（候选实体、排除项、部分匹配证据）**仅存在于上下文**，一旦被压缩丢弃便无法从环境重新获取，故压缩越晚、累积证据越多，损失越致命；Workspace 的任务状态部分外化于文件系统、部分停留在上下文（如用户偏好、已完成步骤的语义），因此呈非单调、中等难度。

- **无历史对照揭示"环境状态 ≠ 上下文"**：在 only-state（不给 H_b、不给 M_b）条件下，Coding 仍有可观成功率，说明代码仓库本身承载了大量进度信息；Search 则几乎归零，因为环境无状态可供恢复。这直接支持"压缩的必要性取决于任务状态在环境与上下文之间的分布"这一解释框架。
- **压缩失败具有系统性而非随机性**：六类错误标注显示，失败主要集中在**进度状态误述**（把未完成写成已完成、混淆已试与未试路径）、**约束与指令细节丢失**（用户显式限制、API 签名、边界条件）、**计划与状态错位**（保留的待办与实际环境不符）以及**过早收敛**（把探索性中间结论固化为定论）；纯粹的"事实性幻觉"占比反而较低。这说明当前模型的压缩瓶颈不在于"写得不准"，而在于**缺乏对'什么信息对后续执行是必要的'的建模**。
- **案例研究（A–G）**：典型成功案例的共同点是压缩输出显式区分了"已完成 / 待完成 / 已知约束 / 已排除方案"；典型失败案例则表现为把长历史压成一段流畅的回顾式叙述，读起来完整但丢失了可操作的下一步。部分案例还显示，压缩器会**主动删除它认为"无关"的工具报错信息**，而这些信息恰恰是执行器避免重复犯错的关键。
- **保留率并非越高越好，但过低会断崖式下降**：多目标校准（5%–80%）显示性能随保留率上升先快后缓，在低比例区间（≤10%）下降最陡；不同模型对同一比例的"有效利用效率"差异显著——同样 10% 预算下强弱模型差距被放大，说明压缩能力的差异在**紧预算**下才充分暴露。
- **长度控制本身是能力的一部分**：IRC 校准结果显示各模型达成目标保留率的难度不同，部分模型需要更多次迭代才能落入容差，提示"按预算压缩"这一指令遵循能力与压缩质量存在耦合。

## 7. 贡献与创新点

- **问题重构**：把上下文压缩从"摘要质量"问题重新定义为"执行关键的模型能力"问题，并给出可操作的形式化（压缩器、边界、保留率、续跑预算）。
- **基准设计**：首个过程级、以端到端任务完成为唯一度量的压缩基准，覆盖 Search / Coding / Workspace 三类状态分布迥异的场景。
- **方法学贡献**：迭代比例校准（IRC）解决了"压缩质量"与"输出长度"的混淆；匹配动作预算与固定执行器使 M_b 成为唯一变量；确定性动作重放实现边界环境状态的精确重建。
- **实证贡献**：给出 12 个前沿模型的横向可比数据、跨域迁移相关性、边界阶段效应，以及基于错误标注的失效机制分类。

## 8. 局限与未来方向

- **覆盖范围**：Workspace 仅 25 个任务，统计功效有限；每条轨迹只评估一个边界，无法刻画同一任务在不同压缩点的完整曲线。
- **单次压缩假设**：真实长时程 agent 会经历**多次连续压缩**，误差会累积放大；本文只评估单次压缩，可能低估实际部署中的性能衰减。
- **执行器固定**：结论绑定于特定执行器（Claude Opus 4.8 / GPT-5.5 Codex），压缩器与执行器的"匹配效应"未被系统研究。
- **标注主观性**：错误分类由 LM 生成、人工抽检，类别边界仍有一定模糊性。
- **未来方向**：多次压缩的误差累积、压缩器-执行器协同训练、结构化/工具化记忆（把状态外化而非压进文本）、面向执行的压缩目标函数（而非语言建模式摘要）、以及自适应边界选择策略。

## 9. 实践启示

- 对 agent harness 设计者：不应把压缩当作"上下文快满了就摘要一下"的兜底机制，而应作为**一等执行组件**来设计与评测；优先考虑把任务状态外化到文件/结构化存储，减少对文本压缩的依赖。
- 对模型开发者：压缩能力与通用能力不完全一致（跨域相关仅 0.26–0.62），需作为独立能力单独优化与选型；在紧预算（约 10%）下的表现更能区分模型。
- 对使用者：压缩边界的选择应依任务类型而定——信息密集型检索任务宜**尽早压缩**（或避免压缩），代码类任务在进度后段压缩损失最小。

## 10. 总体评价

论文选题切中当前长时程 agent 部署的真实痛点，将"压缩"从工程技巧提升为可测量的模型能力，实验控制严格（固定执行器、匹配预算、精确状态重建、长度校准），结论具有明确的机制解释力而非仅排名。主要不足在于 Workspace 样本量偏小、单次压缩设定与真实多轮压缩存在差距，以及错误标注的部分主观性。总体而言，这是一篇方法学扎实、对 agent 系统实践有直接指导价值的基准论文。
