Abstract —Search, especially top-k similarity search, plays a vital role in many applications, but its performance can be severely limited by memory access overhead. In-memory search (IMS), an alternative to CPU/GPU-based approaches, exploits massive parallelism within a content-addressable memory (CAM) array to perform search in situ and provides both low latency and high energy efficiency. However, the capacity of a single CAM array is often insufficient for modern workloads, requiring data to be distributed across multiple arrays. Deploying scalable top-k

similarity search across multiple CAM arrays poses a fundamental problem that existing designs fail to address: how to accurately 

and efficiently reduce local binary match results to global top-k re-sults. This work introduces CAIMS, a cross-array IMS framework that is agnostic to memory technologies and applications, enabling scalable and efficient top-k similarity search while preserving accu-racy. To enable accurate top-k result reduction, CAIMS leverages the existing threshold match functionality with a combined offline and online parameter selection approach to transform local binary match results that lack globally comparable similarity information into global coarse-grained similarity scores. To further improve efficiency, CAIMS conducts hierarchical reduction and transfers only the selection results and necessary control signals with lightweight local peripherals. Implemented on a 3D NAND Flash model and demonstrated using the retrieval phase of retrieval-augmented generation, CAIMS improves throughput by up to 

22 .3 × /10 .1× and energy efficiency by 426 .6 × /23 .7× compared to the server-class CPU baseline and prior 3D NAND Flash accelerators, respectively, while maintaining comparable accuracy. 

I. INTRODUCTION 

Search, especially top-k similarity search, is a fundamental operation for many modern applications, such as recommender systems [1], memory-augmented neural networks (MANNs) [2], retrieval-augmented generation (RAG) [3], and memory-based deep reinforcement learning (DRL) [4]. While search involves only simple computation, the overhead of massive data movements severely limits overall system performance. Pre-vious work reveals that for data-intensive workloads, off-chip memory access can account for up to 90% of overall latency and energy consumption [5], indicating that data movement is the bottleneck for search-based data-intensive applications. In-memory search (IMS) offers a promising solution to this bottleneck. Unlike conventional CPU/GPU implementations, IMS exploits massive parallelism within a specialized memory architecture, i.e., content-addressable memory (CAM) [6], to perform in-situ similarity search against all candidate vectors stored within a CAM array, and produce match results based on the predefined matching scheme. By directly processing data where it resides, IMS avoids transferring the entire dataset across the memory hierarchy, producing match results in a few cycles with minimal energy consumption [7]. However, although CAM efficiently identifies matches within a single array, modern workloads often exceed both CAM array depth (i.e., number of entries), which limits the number of candidate vectors, and array width (i.e., number of cells per entry), which limits the dimensionality of each candidate vector. Vector datasets must therefore be partitioned and distributed across multiple arrays along the entry and/or dimension axes, with each array producing local binary match results (match or not match). While previous work has identified this challenge [8], existing efforts support scaling along only one of the two axes [9], [10]. Although digitizing similarity scores in each array then combining the results globally is possible, the required high-resolution ADCs can consume excessive chip area and more than 75% of the overall energy in analog in-memory computing architectures [11]. Therefore, an approach that supports scalable cross-array IMS by directly leveraging local binary match results is highly desirable. The fundamental challenge of scalable cross-array IMS is accurate and efficient result reduction, comprising aggregation, which counts local binary match results as per-candidate scores, and selection, which identifies the global top-k results. Regard-ing accuracy, each local match result lacks globally comparable similarity information. Consequently, simple aggregation does not yield faithful scores for final selection. Regarding efficiency, aggregation incurs substantial data movement across the mem-ory hierarchy, eroding the efficiency benefit of IMS. To address these challenges, we introduce CAIMS, a cross-array IMS framework that is agnostic to memory technologies and applications, enabling scalable and efficient top-k similarity search while preserving accuracy (i.e., HitRate@ k). II. BACKGROUND AND MOTIVATION 

A. Content-Addressable Memory (CAM) 

Unlike conventional memory that retrieves data based on a given address, CAM [6] is a memory architecture capable of comparing a query vector with all candidate vectors stored in the same array in parallel, returning the addresses of the matched results. Fig. 1(a) shows the generic architecture of a CAM array. Data in the array are organized row-wise, with each memory cell storing the value for one dimension, and each entry corresponds to a multi-dimensional candidate vector. The query vector is applied along the dimensions and compared with candidate vectors in all entries simultaneously. A candidate is considered a match if the matchline voltage level, as detected by the associated sense amplifier, satisfies the matching criterion. CAM supports diverse data representations (e.g., binary [12], ternary [13], multi-bit [9], and analog [14]), distance functions (e.g., Hamming distance [13], squared Euclidean distance [15], and cosine similarity [16]), and matching schemes (e.g., exact match [13], best match [17], and threshold match [13]). Its parallel search capability accelerates workloads such as tree-based models [18], HDC [9], MANN [19], and DRL [20]. However, device and circuit constraints inherently limit CAM array size. Prior work reports that for 4-bit per cell, extending the array width beyond 64 cells is challenging [14]. As the number and/or dimensionality of candidate vectors grows, data must be partitioned along the entry and/or dimension axes, requiring entry and dimension merges, as shown in Fig. 1(b). To realize scalable cross-array IMS while preserving accu-racy, entry and dimension merges should be jointly handled. Nevertheless, prior designs support merging along only one of the two axes, limiting their ability to simultaneously scale dataset size and vector dimensionality. For example, previous work [9] applies per-array best match and majority voting 

to implement cross-array best match . However, this approach addresses only dimension merge and assumes that every array contains the complete candidate set, limiting scaling along the entry axis. Moreover, this approach cannot be directly extended to top-k similarity search. On the other hand, ACRONYM [10] partitions each candidate vector into two subvectors corre-sponding to two disjoint dimension partitions, applying thresh-old match on both partitions sequentially to reduce the can-didate count from #candidates to kcoarse and finally kf inal .Consequently, ACRONYM extends the vector dimension from 

array width to 2 × array width with degraded recall. How-ever, the threshold selection algorithm for threshold match ,which controls the number of matches, is not discussed. While ACRONYM mentions potential configurations to further extend the vector dimension, the practical realization is not discussed. A few other works implement cross-array IMS [7], [21], [22]. Nevertheless, different dimension partitions are mapped to the same array as different entries, leading to matches of irrelevant query and candidate subvectors and may degrading accuracy. Hence, none of them achieves scalable cross-array IMS. 

B. Retrieval-Augmented Generation (RAG) 

RAG is an approach designed to extend the knowledge of large language models (LLMs) beyond training data while en-hancing reliability. Typical RAG systems consist of a retriever, which compares a query vector against candidate vectors to identify the top-k most relevant documents, and a generator, which produces the final response based on both the query and the retrieved documents. Because the retriever must search a potentially massive vector dataset for every query, retrieval can become a major performance bottleneck. Previous work [23] reports that retrieval accounts for, on average, 61% of the total runtime, while IKS [24] reports that this proportion can reach 97% in the worst case. Since retrieval is fundamentally a top-

k similarity search operation, RAG provides a representative workload for evaluating scalable IMS frameworks. 

C. 3D NAND Flash SSD 

Fig. 1(c) presents the typical architecture of a 3D NAND Flash SSD, comprising an SSD controller and hierarchically organized channels, chips, planes, and blocks. Channels, chips, and planes provide parallelism, whereas blocks within a plane share peripheral circuitry and cannot operate independently. Recent studies show that blocks can serve as CAM arrays [21], [22] and that the SSD controller can support general-purpose computation [25], [26]. III. CAIMS FRAMEWORK 

This section presents CAIMS, a cross-array IMS framework that is agnostic to memory technologies and applications. We first identify obstacles to accurately and efficiently reducing local binary results to global top-k results when the dataset must be split into multiple CAM arrays. We then present an overview of the CAIMS framework and introduce the detailed algorithm-hardware co-design approach. We finally discuss RAG retrieval acceleration using 3D NAND Flash as a case study. 

A. Overview 

The fundamental problem of scalable top-k similarity search with IMS is: how to reduce local binary match results to global top-k results accurately (i.e., select the most similar candidates) 

and efficiently (i.e., with lower latency and energy). 

Accuracy: This challenge arises because local binary match results may not have the globally comparable information required for top-k selection. Fig. 2 illustrates this issue us-ing a top-1 example. Ideally, a sufficiently large CAM array accommodates the entire dataset and directly identifies the best match for an input query. However, when the dataset is partitioned across multiple arrays, each array identifies its local winner based only on the subvectors it contains. Local winners therefore indicate relative rank within an array rather than a shared level of similarity across arrays. Consequently, selecting the candidate with the most local wins can yield an incorrect global result, as illustrated by the Naive Approach in Fig. 2. 

Efficiency: This challenge stems from the data movement of result reduction. While IMS avoids transferring the entire 

O(# candidates × #dimensions ) dataset to the CPU/GPU, centralized aggregation and selection would still require trans-ferring O(# candidates × #dimensions array width ) local match results. Al-though local aggregation and selection can reduce this traffic to 

O(k × #candidates array depth ), the required local selectors may consume considerable area, and many locally selected candidates may ultimately be discarded when reducing local selection results to global selection results. Efficient reduction therefore requires coordinating local and global selection to minimize unnecessary candidate transfers while keeping hardware overhead low. To tackle these identified challenges, we design CAIMS around three key components (see Fig. 3): Dataset-Assisted Scalable Search (DASS) and Online Result Count Adaptation (ORCA) to achieve accurate search, and Local Aggregation and Selective Transfer (LAST) to improve search efficiency. B. Dataset-Assisted Scalable Search (DASS) 

As a key component of CAIMS, DASS enables effective local-data filtering and global-result reduction that preserves search accuracy. By applying threshold match with a unified threshold Tf ilter in every CAM array, DASS gives every local match result the same similarity interpretation: whether the similarity between a candidate subvector and the query subvector from the same dimension partition exceeds Tf ilter .Aggregating the local match results thus produces a globally comparable, coarse-grained similarity score, as shown in Fig. 2. One challenge with the above approach is that coarse-grained similarity scores generally may not identify exactly k

results because multiple candidates may tie at the top-k cut-off. Since arbitrarily discarding tied candidates can degrade search accuracy, we introduce another threshold, Tselect , such that DASS returns every candidate whose score is at least that of the Tselect th ranked candidate, aiming to keep the average result count, c, as close to k as possible. Selecting appropriate 

Tf ilter and Tselect values is key to maintaining c ≈ k and achieving high top-k similarity search accuracy. 

DASS jointly determines Tf ilter and Tselect through offline calibration, as outlined in Algorithm 1. Since actual query vectors are unavailable during system setup, DASS randomly samples Nsmp candidate vectors from the dataset as pseudo queries, using the candidate distribution as an initial approx-imation of the query distribution. C. Online Result Count Adaptation (ORCA) 

Although DASS can select approximately k candidates for pseudo queries sampled from the vector dataset, runtime queries may follow a different distribution. This distribution discrep-ancy can result in deviation of c, with lower or higher c values reducing accuracy or efficiency, respectively. We design ORCA , as outlined in Algorithm 2, to adapt to query distribution shifts at runtime. Since altering Tf ilter online may be challenging, ORCA tunes only Tselect . Specifically,

With ORCA , CAIMS adapts to runtime query-distribution shifts, and DASS can be reapplied after substantial dataset updates if the original Tf ilter no longer controls c well.

By mapping subvectors belonging to the same candidate to different arrays in the same processing element (PE), local binary match results can be aggregated to coarse-grained similarity scores at the PE layer. After obtaining the scores, LAST performs coordinated global selection. The central processor first broadcasts the maximum possible score Max = ⌈ #dimensions array width ⌉ to all PEs, and each PE returns the candidates whose score equals Max . The central processor cumulatively counts the returned results and terminates once at least Tselect results have been collected; otherwise, it broadcasts Max -1 and repeats the process. By adopting LAST , only the scores and the global selection results are transferred across the memory hierarchy, eliminating un-necessary data movement. Moreover, the distributed local pro-cessing design allows the reduction latency to remain constant and depends only on the value k as the dataset size increases. The Local Peripherals in Fig. 4(a) support LAST with low-bit-width accumulators for aggregation and equality compara-tors for selection. Since these operations are faster than CAM search, CAIMS provisions only enough peripheral resources to keep reduction off the critical path, minimizing hardware over-head without sacrificing throughput. The General Peripherals handle communication and address decoding and are standard IMS components rather than CAIMS-specific additions.

Quantization is required to map full-precision vectors onto limited-precision NAND cells. While quantization has ad-vanced rapidly in recent years, most target model compression and therefore aim to minimize the reconstruction error [28]. However, value reconstruction is unnecessary when a vector dataset is used solely for top-k similarity search; instead, quantization should preserve the relative similarities among vectors. Conventional quantization schemes optimized for value reconstruction may hence be ill-suited for this purpose and can substantially degrade search accuracy. For instance, a recent work directly applying a scheme optimized for reconstruction reports 33% search accuracy loss for 4-bit quantization [29]. We use Quantile Quantization [30], an information-theoretically optimal scheme [31], to quantize query and candidate vectors. Instead of minimizing reconstruction error, 

Quantile Quantization determines quantization levels based on the quantile of the values in the input vector, ensuring approximate equal utilization of all quantization levels. By avoiding underutilization of quantization levels, similarity rela-tionships between vectors become more distinguishable, which empirically makes top-k selection significantly more accurate. IV. Since CAIMS uses coarse-grained similarity scores for top-k

selection, trading accuracy for high search efficiency, we want to measure whether CAIMS improves throughput and energy efficiency while maintaining comparable accuracy. In addition, as CAIMS does not guarantee selecting exactly k candidates, whether DASS and ORCA can control c is also important. A. Overall Performance 

Table III compares the overall performance of CAIMS with different baselines. CPU-based IVF trades a slight accuracy loss for significantly higher throughput and energy efficiency than CPU-based brute-force search, making it a practical software baseline. However, its throughput decreases rapidly with dataset size, from 64.8k QPS on BEIR-SciFact to 28.0 QPS on DPR-NQ. In contrast, CAIMS throughput is determined primarily by the fixed 3D NAND search latency within its parallel search capacity. Note that the effective CAM array width can be adjusted by selecting which WLs participate in each comparison. A narrower width provides finer-grained similarity scores, improving accuracy, whereas a wider width reduces search cycles, enhancing efficiency. TVLSI2026 also exploits in-storage parallelism but is query-sensitive, requires substantial in-block modification, and as-sumes an optimistic array width of 768. C. Design Feasibility 

We explicitly consider (1) peripheral area overhead and (2) the SSD power constraint when evaluating design feasibility. LAST requires only lightweight accumulation and equality-comparison logic at each plane, similar to the peripherals adopted by D-NOVA, which incur less than 1.5% plane-area overhead, suggesting that the additional hardware required by CAIMS is modest. For power, the modeled SSD has a 

25 W form-factor power limit [39]. Under the evaluated DPR workloads, CAIMS consumes at most 17 .0 W with conservative estimation, whereas TVLSI2026 would require approximately 

100 W and 40 W for DPR-NQ and DPR-TQA, respectively. We note that simultaneously activating all planes in the SSD may exceed the power envelope. In such cases, power-aware scheduling would be required, which we omit in this work. Overall, these results indicate that CAIMS can potentially be implemented with commercial SSDs. V. CONCLUSION 

IMS offers great potential for accelerating search-based data-intensive applications. However, existing cross-array designs remain constrained along the entry or dimension axis, failing to scale dataset size and vector dimensionality simultaneously. This work presents CAIMS, a cross-array IMS framework that enables fully scalable and efficient top-k similarity search while preserving accuracy. Evaluated using RAG retrieval on a 3D NAND Flash model, CAIMS improves energy efficiency across all evaluated datasets and throughput on large datasets. These results establish CAIMS as a promising framework for large-scale IMS.
