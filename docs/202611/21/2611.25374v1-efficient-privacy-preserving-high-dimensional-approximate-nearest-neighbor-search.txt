Abstract —In the AI era, approximate nearest neighbor (ANN) search on vector databases is critical as it supports similarity retrieval over high-dimensional vectors, which is essential for many large language model (LLM) applications. To reduce costs and improve scalability, vector databases are often outsourced to cloud servers, raising privacy concerns for users whose query vectors contain sensitive information. In this work, we study the problem of asymmetric privacy-preserving ANN search, where the vector database is public but user queries must remain private from an untrusted cloud server. To solve this problem, we propose 

ObliSC , an efficient privacy-preserving search framework that protects query privacy against access-pattern leakage. ObliSC 

consists of (i) a search base that retrieves ANNs with a strong pri-vacy guarantee of full obliviousness; and (ii) parallel optimization strategies that accelerate candidate retrieval and refinement while preserving full obliviousness and retrieval quality. Experiments on six standard ANN benchmarks show that ObliSC not only achieves efficiency and result quality competitive with baseline methods but also maintains a lightweight index compared with the evaluated privacy-preserving approaches. 

Index Terms —Approximate nearest neighbor search, query privacy, access pattern protection, obliviousness. 

I. I NTRODUCTION 

Vector databases support AI applications that retrieve ob-jects by semantic similarity. In retrieval-augmented generation (RAG), for example, a dense retriever embeds a question and searches a passage index for context that a language model can use to generate an answer [1]. Approximate nearest neighbor (ANN) search is a basic operation for such retrieval: it finds vectors close to the query without comparing it with every item in a large collection [2]–[4]. Nowadays, the cloud service is popular since the com-putational resources of individual users are limited. In this scenario, the query and the collection may have different privacy requirements. Consider a publisher that hosts a vector index of its technical manuals in its own cloud. The publisher already knows the manuals and can inspect their vectors in plaintext. A customer, however, may search the manuals with an embedding of an unpublished incident report. Even revealing which manuals the customer consulted could identify the product or fault under investigation. As there are increasing concerns about disclosing personal information [5], privacy rights and data protection [6], [7], and the design of privacy-preserving services [8], it is critical to protect what users reveal when they interact with a service provider (SP). Hence, in this paper, we study the corresponding asymmetric ANN search problem: the database and index are public to SP, whereas the user’s query must remain private from SP. Prior work such as Preco [9] protects the user’s query while bounding what the client learns about the database. However, Preco requires the user to query two servers and relies on them not pooling their respective query shares. In contrast, we focus on a single-server design for asymmetric ANN search that does not require a second, non-colluding server. Table 1 compares representative nearest neighbor search methods in terms of their system models, privacy targets, and performance. PP-ANNS [11] protects query and database contents using encrypted comparisons, but does not establish a formal privacy guarantee for query-dependent access patterns. PACMANN [12] protects queries over a public database by let-ting the user traverse a graph and privately retrieve information at each hop. Panther [14] protects the user’s query from the server and the server’s database from the user. BiSON [13] protects both the query and the outsourced database from the storage server and uses disk-compatible oblivious RAM (ORAM) to hide graph accesses. In the federated setting, FedKNN [15] protects the participating providers’ data during collaborative kNN search, but its threat model does not require the user’s query to be hidden from those providers. Like PACMANN, we study asymmetric ANN search in the single-server setting. This raises a natural question: can we answer such queries more efficiently while providing a formal guarantee of query privacy against access-pattern leakage? 

Our Approach. To answer this question, our idea is to design an oblivious 1 search framework that hides query-dependent memory accesses from SP. This goal leads to two challenges. 

Challenge 1: An efficient oblivious search framework. Effi-cient ANN search relies on indexes to restrict the search to promising candidates. However, incorporating an index into an oblivious framework requires protecting the entire search process. For example, graph traversal and cluster probing use query-dependent addresses, while candidate aggregation and refinement can reveal which items were selected. Protecting these operations without losing the efficiency of indexed search is challenging. Recent advances in subspace-collision search, including SuCo [4] and TaCo [16], offer an opportunity to design an efficient oblivious search framework. Building on their separation of cell probing, collision-score aggregation,

ObliSC ’s search base consists of a K-means-based inverted multi-index and fully oblivious ( FO ) search procedures: the index supports uniform cell retrieval, candidate activation selects promising items within a public probe budget, and refinement uses their collision scores to identify the final results, while hiding query-dependent accesses throughout the search. These stages execute within a trusted execution environment, which protects private data values during computation, thereby combining data confidentiality with access-pattern protection to preserve query privacy throughout the search. 

Challenge 2: Exploiting parallelism while preserving obliv-iousness. Parallel execution is a natural direction for further reducing the query latency of ObliSC ’s FO search base. How-ever, parallelizing oblivious sorting alone does not address the dependencies across search stages: candidate activation is independent across subspaces, whereas collision-score ac-cumulation updates shared state and determines subsequent candidate selection. Directly executing these updates concur-rently requires coordination of both the scores and the ORAM state, which can limit parallelism. We therefore separate query-dependent local computation from global aggregation in public item order. Each subspace independently activates candidates and accumulates local collision scores, which are then combined through an oblivious merge to support global selection and refinement. Together with parallel oblivious sorting and distance computation, this design exposes paral-lelism while keeping worker assignments, access schedules, and synchronization points independent of the query to achieve the guarantee of full obliviousness. It preserves the search base’s scoring semantics and retrieval quality at the cost of additional storage and aggregation work. 

Contributions. Our contributions are as follows:  

> •

We formulate single-server asymmetric ANN search over a public vector database with a private query, and specify full obliviousness under this setting.  

> •

We propose ObliSC , a privacy-preserving asymmetric ANN search framework with a subspace-collision-based search base, whose K-means-based inverted multi-index, candi-date activation, and candidate refinement are jointly de-signed to protect query-dependent access patterns through-out the search. We prove that ObliSC ’s search base satisfies the privacy guarantee of full obliviousness.  

> •

We develop parallel ObliSC by decomposing the shared collision-score updates during the candidate refinement into independent local accumulation and oblivious global ag-gregation, enabling concurrent processing across subspaces without contention on a shared score ORAM. Together with parallel candidate activation, oblivious selection, and dis-tance computation, this design exploits parallelism across the online search stages. We prove that it preserves full obliviousness and the search base’s results, and analyze the trade-offs among total work, parallel running time, and auxiliary space.  

> •

We implement a prototype of ObliSC and evaluate its retrieval quality, search time, and index construction on six standard ANN benchmarks, with comparisons to non-private and privacy-preserving baselines. The experimental results demonstrate ObliSC ’s competitive performance.

B. System Model and Security Basis 

System Model. We consider a cloud computing scenario with query privacy protection: the user submits a private query vector to a service provider (SP) for AkNN retrieval over a public vector database and its query-independent index. We adopt the widely used assumption in cloud computing that SP is an honest-but-curious adversary: it follows the computational protocol but may infer sensitive information about the user’s private query. Under this model, we consider the following two kinds of privacy as the privacy target : 

> •

Data privacy. The data privacy is to protect the user’s query vector and any query-dependent intermediate values except for the query parameter k; and  

> •

Access pattern privacy. The access pattern privacy is to ensure that SP cannot infer any information that may compromise the data privacy. Next, we introduce the security basis used in this paper. 

Security Basis. To protect data privacy, there have been cryptographic techniques supporting secure computational op-erators, such as secret sharing [17], [18], homomorphic en-cryption scheme [19]–[21], and trusted execution environment (TEE) [22]–[24]. To achieve the above privacy target, we can leverage these techniques to preserve the data privacy and mainly focus on designing secure search protocols with protection on the access pattern privacy .To protect access pattern privacy, obliviousness is a standard security notion that provides formal privacy guarantee. We adopt full obliviousness [25] to protect the complete observ-able search execution pattern.

C. Pipeline for Subspace Collision-Based AkNN Search 

Figure 1 summarizes SuCo’s plaintext pipeline [4] that con-sists of offline index construction followed by online search.  

> •

Offline index construction. SuCo partitions the d dimen-sions into Ns sampled subspaces and builds an inverted multi-index (IMI) for each subspace Si. It then splits Si

into two halves and clusters each half into √κ centroids using K-means. Each identifier is stored in one of κ IMI cells according to its nearest centroid pair.  

> •

Online search. SuCo projects the user query q into each subspace and computes its distances to both centroid sets. Then, it prioritizes IMI cells by the sums of these distances and retrieves identifiers until at least α·n items are activated as candidates, where α is the collision ratio and n is the database size. Next, SuCo (i) counts one collision vote for each retrieved item per subspace, and (ii) retains the β ·

n highest-scoring candidates, where β is the re-rank ratio. Finally, SuCo re-ranks these β · n candidates by original-space distances to return the closest k ones as Ak(q).SuCo’s index cell retrieval, candidate activation, and refine-ment accesses depend on the user query q and expose its access pattern. Index-Based ANN Search. Common ANN indexing and search techniques include product quantization [34], locality-sensitive hashing (LSH) [35], inverted files, trees [36], and graph-based methods such as HNSW [2]. Recently, subspace collision (SC) [4] has offered another approach: it aggregates collision information across multiple lower-dimensional sub-spaces to estimate proximity in the original space. Building on this framework, SuCo [4] combines a lightweight clustering-based index with efficient query-processing strategies. The efficiency gains of these methods often rely on query-dependent behavior, including bucket and cluster selection, graph traversal, pruning, and candidate refinement. While such adaptivity is natural in plaintext retrieval systems, the resulting access patterns can leak information about a private query vector. Designing ANN search methods that protect query privacy against access-pattern leakage while maintaining high search efficiency therefore remains an important problem. 

Privacy-Preserving ANN Search. In the single-server setting, Liu et al. [11] studied ANN search with protection for both query and database contents, but their construction does not hide query-dependent access patterns. Li et al. [14] proposed Panther, which combines PIR, secret sharing, garbled cir-cuits, and homomorphic encryption to protect both query and database privacy while hiding query-dependent access patterns against semi-honest adversaries. Das et al. [13] proposed BiSON, which combines DiskANN with a disk-compatible ORAM architecture to protect database contents, queries, and access patterns from an untrusted server in an outsourced setting. Zhou et al. [12] proposed Pacmann, a graph-based ANN search framework that protects query privacy and hides query-dependent graph accesses via Private Information Re-trieval (PIR) over a public database. Like Pacmann, ObliSC 

protects queries over a public vector database, using a trusted execution environment (TEE) for query confidentiality and oblivious search within the TEE to hide access patterns. In the two-server setting, Servan-Schreiber et al. [9] pro-posed Preco, a locality-sensitive hashing-based private ANN protocol using distributed point functions for private retrieval from two non-colluding servers, protecting the query while limiting database information disclosed to the client. In the federated setting, Zhang et al. [15] proposed FedKNN for secure kNN search across private data providers. FedKNN combines TEE with differential obliviousness to protect the providers’ data against access-pattern leakage. 

Oblivious Search. Full obliviousness [25] provides strong privacy guarantees by making observable access patterns in-distinguishable across inputs of the same public size. Prior work has employed oblivious designs, under different security models and leakage guarantees, for a wide range of query and data-processing tasks, including SQL queries [37]–[42], graph algorithms such as traversal, shortest-path computation, and minimum spanning trees [43]–[45], and graph pattern queries [46]–[50]. VII. C ONCLUSION 

In this paper, we study asymmetric privacy-preserving ANN search over a public vector database, where user queries must remain private from an untrusted cloud server. We propose 

ObliSC , an efficient search framework whose ANN index, candidate activation, and candidate refinement are jointly de-signed to protect query privacy against access-pattern leakage. We prove that its search base satisfies the privacy guarantee of full obliviousness. We further develop parallel strategies for candidate activation and refinement while preserving full obliviousness and the search base’s results. Experiments on six standard ANN benchmarks demonstrate that ObliSC achieves competitive efficiency and result quality while maintaining a lightweight index compared with the evaluated privacy-preserving approaches. As for future work, we may optimize each of ObliSC ’s components, implement ObliSC using alter-native cryptographic tools rather than a TEE to protect query values and private intermediate values, and extend ObliSC to support additional query workloads. Theorem 1. ObliSC satisfies full obliviousness. Proof. Consider two executions of ObliSC with the same public database, index, and parameters but different queries. Algorithm 2 constructs the index independently of the query. Algorithm 1 then performs initialization and query projection using access schedules determined by public sizes and the index partition. It invokes candidate activation and refinement in a fixed order. By Lemmas 1 and 2, both stages have query-independent local schedules and ORAM request counts. Adaptive ORAM security hides the private addresses across the complete sequence, including requests sharing ORAM state, while private intermediate values and results remain hidden from SP. Thus, sequentially composing these stages yields computationally indistinguishable traces and establishes Equation (2). 

Lemma 3. Algorithms 5 and 6 return the same answer as Algorithms 3 and 4. Proof. The distance computations use the same arithmetic order, and both sorts use the same tie-breaking rules. Consequently, the final top-k answers are identical.
