Abstract
To act effectively, agents must gather contextual information across resources
such as chats, issue trackers, email and knowledge bases, to answer questions
like what was decided in the last project meeting? or where is the FAQ for
our internal tooling? Where this information lives in a user’s environment is
unknown to the agent, so it re-explores the same resources across consecutive
interactions. Common routing approaches represent each resource as a tool and rely
on high-level descriptions to generalize to unseen environments. Such descriptions
often fail to separate similar or overlapping resources and cannot improve from
the agent’s subsequent interactions. We introduce Wayfinder, an adaptive router
that uses the documents cited by the downstream agent as feedback about where
relevant information resides. These citations update Wayfinder’s internal resource
representations, which subsequent interactions use to prioritize the resources likely
to contain relevant information. We also introduce resource augmentation during
offline reinforcement learning, which anonymizes and permutes resource identities
to discourage training-time overfitting of which resource holds which topic; our
ablations suggest it helps most when few training environments are available.
Because no openly available professional environments pair realistic queries with
resource-access patterns, we construct and release three controlled testbeds derived
from existing datasets: NFCorpus, FEVER and Tech Startup. Compared with
supervised, tool-retrieval and contextual bandit baselines under a shared closed-
loop protocol, Wayfinder gives the best routing when resources contain semantically
overlapping content that static descriptions cannot distinguish, while description-
based tool retrieval suffices when resources are drawn from distinct corpora.

Introduction
Large Language Models (LLMs) are increasingly judged by their ability to act as agents to accomplish
tasks on behalf of users [5, 11, 30]. To complete tasks, however, an agent must do more than reason
and act: it requires contextual information about the user’s environment. Answering what was decided
in the last project meeting? or where do I look up the FAQ for internal LiteLLM? means seeking
evidence across resources such as chats, issue trackers, email, or knowledge bases, each reachable
only through a tool that retrieves the documents that specific resource contains (e.g., conversations,
tickets, articles) [1, 2]. Where that grounding information resides is user- or organization-specific
and is not known to the agent in advance: an ongoing project may be documented in chat threads
in one organization, but captured in email conversations or issue tickets in another. This creates a
gap between the agent’s prior knowledge and the target environment (i.e., the collection of available
resources) in which it operates. Lacking that knowledge, the agent must rediscover the layout of
the environment during every new user-agent interaction, re-exploring the same resources across
consecutive interactions even after earlier ones revealed where some of that information is kept.

A natural response is to treat each resource together with its access tool as a distinct
tool, which frames resource routing as tool selection problem.
The distinction is that
these tools while having a different resource name often have the same search functionality
[resource_name].search(query)→docs, and differ only in the documents behind them. Thus,
any description used for selection must stand in for contents that cannot be enumerated ahead of
deployment. The dominant approaches consume exactly such descriptions: an LLM ranks resources
from them (ReSLLM [34]), or a contrastively trained bi-encoder embeds them and scores them
by similarity to the query (ToolRetriever [26]). Both inherit the limits of the description: they
cannot separate resources whose contents overlap semantically, and they are fixed at deployment,
so what the agent discovers in one interaction cannot inform the next. Reinforcement learning has
been applied to tool selection [25], but reward computation requires gold tool calls which are not
available at deployment. Supervised routers such as Learn2Rank [12] and RouteRAG [15] share
similar limitations requiring labeled queries of the target user’s environment but a newly encountered
environment supplies neither. What remains missing is a routing method that can adapt to a target
environment without labels from it.
User–agent interactions already supply a proxy for these labels: answering a query, the agent cites
the documents it relied on, and those citations are grounded evidence of where the information a
user needs resides in their environment. We introduce Wayfinder, an adaptive router that updates
itself from those cited documents. Wayfinder maintains a bounded representation of each resource,
which we call a resource sketch, that subsequent interactions consult to prioritize the resources likely
to contain the answer. Adaptation therefore happens online, without target-environment labels and
without access to the resources’ full contents. Routing is advisory rather than restrictive: the agent
remains free to search beyond the recommended resources, so the signal continues to arrive even
when the router is wrong. The policy itself is trained offline with Reinforcement Learning [27]
on training environments; to keep it from memorizing which resource names carry which topics
rather than routing on evidence, we anonymize and permute resource identities during training. Our
ablations indicate this augmentation matters most when a limited number of training environments is
available.
We evaluate in controlled federated environments spanning intra-corpus partitions (NFCorpus,
FEVER) and cross-corpus heterogeneity (Tech Startup), with every router run under the same
closed-loop protocol. Where resource descriptions read alike, citation-driven adaptation gives the
best routing (Table 2): F1r of 47.67 on NFCorpus and 64.72 on FEVER against 33.03 and 31.01 for
the strongest baselines, while cutting the agent’s search calls by 61.2% and 73.7%. On Tech Startup,
where five disjoint corpora make each resource recognizable from its description, ToolRetriever, a
bi-encoder trained on training-environment labels, leads with 98.86, and Wayfinder is second with
86.60.
Our contributions are as follows:2
• Problem formulation: we formalize the Adaptive Agent Routing Problem, in which routing
policies must be learned with each resource reachable only as a black-box retriever, weak
trajectory-level feedback, and without target-environment supervision, while generalizing
across environments.
• Citation-gated supervision and method: we introduce a supervision paradigm that up-
dates the routing memory only from documents cited by the agent, filtering out the noisy
retrievals that dominate early exploration (cited rate 74–95%, cited-doc accuracy 71–73%
in our trajectories). We instantiate this paradigm in Wayfinder, a zero-shot federated router
combining bounded resource sketches with a parameter-efficient LoRA (rank 16) policy
trained via RL.
• Generalization mechanism: we introduce session-randomized resource augmentation
during RL post-training. Resource identifiers are anonymized and re-permuted per session,
forcing the policy to read environment memory rather than memorize name–topic associ-
ations from training environments. Our ablation (Section 7.3) shows this augmentation
is most useful when training environments are scarce; when many training environments
are available the policy already sees enough variability and the augmentation’s benefit
diminishes.

Problem Formalization
Given a sequence of user queries Q = ⟨q1, q2, ..., qT ⟩issued sequentially to an agent π, and a
collection of N resources R = {r1, . . . , rN} (e.g., chats, issue trackers, email, knowledge bases,
etc.) we say that a resource rj is relevant to query qt iff it contains at least one document d ∈rj that
grounds the answer to qt. We refer to the collection of relevant resources as ¯Rt ⊆R.
Our objective is to define a routing function that, given a query qt and the history of previous
interactions between the user and the agent, identifies the resources relevant to qt and shares them
with the agent π to make exploration more efficient. We formalize this as the construction of a router
froute such that:
ˆRt = froute(qt, R, Ht−1)
(1)
where Ht−1 = ⟨(qi, τi)⟩i<t, is the interaction history before t, τi is the trajectory the agent produced
at round i and ˆRt ⊆R is the set of predicted resources. In this work, we study this problem under
the following constraints:
1. No access to target-environment supervision. During training, the router is learned from
a set of training environments and their associated queries, but the target environment and
its queries are not available. This setting reflects practical deployments of agentic systems
(e.g., Claude Cowork [1]) where models must generalize to previously unseen workspaces
without access to user-specific data at training time.
2. Restricted resource access via tools. Resources are accessible only through their corre-
sponding tools or APIs, and their contents cannot be exhaustively enumerated or randomly
sampled. Consequently, methods that assume full corpus access or centralized indexing
across resources are not applicable in this setting.
These constraints define a learning problem in which routing decisions must be inferred under partial
observability and weak supervision, distinguishing it from standard tool use settings where the tool
description and functionality does not vary across environments (bash, calculator, git, etc.). Because
the router must generalize from training environments to previously unseen target deployments, we
refer to this routing problem as the Adaptive Agent Routing Problem.

Related Work
End-to-end RL-based RAG systems.
Recent work optimizes retrieval-augmented generation
pipelines end-to-end with structured or verifiable rewards, jointly training query reformulation,
retrieval, reranking, or knowledge-graph traversal [8, 16]. These systems assume direct control over
the retrieval stack. Wayfinder instead isolates the upstream problem of resource routing, treats each
resource as a black-box retriever, and acts as a parameter-efficient routing layer that can be composed
with such pipelines rather than replacing them.
Resource selection and bandit routing.
Resource selection has a long history in distributed
information retrieval and federated search [28, 4]. Classical methods like CORI [7] use term statistics
with no learning. Supervised approaches [15, 12, 17, 9] learn classifiers or rankers from labeled query–
resource pairs and perform well in data-rich, stationary deployments, but assume stable resource
semantics and degrade under distribution shift or in low-data target environments. A complementary
line formulates routing as a bandit problem with online reward attribution [3, 14]. In agentic settings,

Tool retrieval and zero-shot tool generalization.
Treating each resource together with its access
tool as a distinct tool makes our action space formally an instance of tool selection with the key
distinction that descriptions, when used, have to reflect the content of the resources as the functionality
and signature are largely the same across tools (to retrieve documents and search(query)→docs).
ReSLLM [34] is a method that uses a description of the resource contents to describe the tool which
an LLM (used as the router) uses to rank the tools. On the other hand dense-retrieval variants like
ToolRetriever [26] embeds the same descriptions with a contrastively trained bi-encoder and scores
them by similarity to the query .
Reinforcement learning has also been applied to tool selection [25], with the reward computed by
matching the predicted call against a gold tool call. Learning therefore requires labeled data for these
tools. A newly encountered target environment, with a new distribution of resources, carries no such
annotation: no query is labelled with the resource that holds its answer. Wayfinder instead rewards a
routing decision using the documents the primary agent cites while answering requiring no labelled
data of the target environment.
Memory-augmented agents.
Long-term memory systems for LLMs (MemoryLLM [35], M+ [36],
MemGPT [24]) and agentic continual-learning systems such as CLIN [23] compress past interactions
to retain content or user preferences. These approaches target content retention rather than the
navigational problem of identifying which external resources are likely to be useful for a query.
What separates Wayfinder from the work above is its supervision, not its components. Most routers
discussed decide from evidence fixed before deployment: a resource description (ReSLLM, ToolRe-
triever), corpus statistics over enumerated contents (CORI, ReDDE), or labelled query–resource pairs
from the target environment (Learn2Rank, RouteRAG). Wayfinder instead uses the agent’s citations
to adapt to the target environment and become more efficient as the user interacts more with the
agent.
4
Methodology: Wayfinder
When we open a new agent session and ask it to perform an action or answer a question the agent often
needs to explore the environment to gather context, learning along the way where the information that
4


is relevant to that user is kept. This knowledge is lost when the session ends, and the next session has
to repeat the same exploration. We argue that this is inefficient. Queries about the same project tend
to be answered from the same few resources, so earlier sessions can inform later ones. Citations also
point at evidence the agent actually used to answer a question. Wayfinder builds upon this observation
and proposes a citation-gating mechanism to retain and utilize this knowledge across sessions.
Wayfinder is a routing method that is paired with an agent π to make its trajectories more efficient
over time. When a new query is passed to π it can call Wayfinder to retrieve the resource where the
information is likely to be found. On the other hand, when a trajectory from the agent π is completed,
this is passed to Wayfinder to store the knowledge. At a high level Wayfinder is composed of an
environment memory M, containing an internal representation of the environment, and a LLM-based
routing policy πroute that uses that memory to provide resource recommendations to the agent π.

4.2
Resource Sketches
Evidence is stored per resource. For each rj ∈R the resource sketch Mj is a bounded set of at
most M records, each a triple (d, q, t): a cited document d observed via a tool call to rj, the query q
that elicited the citation, and an access timestamp. The environment memory is then the collection
of these resource sketches M = (M1, . . . , MN). Sketches start empty, Mj
0 = ∅, so on the first
query the policy may emit an empty action set and let the agent fall back on static descriptions. Thus,
when Wayfinder is applied to a new environment it starts with an empty memory but a trained routing
policy πroute.
On each rollout, every document in Ct retrieved from a cited resource rj ∈ρ(Ct) is inserted into
Mj as a record (d, qt, t), evicting the least-recently-used record when the sketch is at capacity M.
Resources outside ρ(Ct) are untouched. Three consequences follow: retrieved-but-uncited documents
never enter, so early exploration does not pollute sketches with low-precision associations; when
the agent fails to cite, sketches go stale rather than wrong, giving slower but stable adaptation; and
the capacity M caps the storage and retrieval cost of the routing layer regardless of stream length.
Lastly, a centralized semantic index over M supports retrieval across resource sketches of the top-k
documents relevant to a query.

4.3
Routing
Given qt, the routing policy πroute reads the environment memory state at time t−1, Mt−1, through the
semantic index in a ReAct-style loop, optionally issuing further memory searches with refined queries
and reasoning over what it retrieves before emitting ˆRt. The agent then executes τt = π(qt, ˆRt) and
the trajectory returns for citation extraction, closing the loop.
The routing policy is implemented as a LLM trained with reinforcement learning with verifiable
rewards [21] and GRPO [27] on training environments only. Specifically, for each query we sample
a group of G rollouts and score rollout i by Ri = F1( ˆR(i)

{rj ∈R : rj ∩Dt̸ = ∅}, where Dt is the set of relevance-judged documents for qt; malformed
output (invalid identifiers or non-parseable JSON) scores zero. The G scores are then centred and
scaled against each other, Ai = (Ri −µq)/(σq + ϵ), where µq and σq are the mean and standard

its siblings on the same query receives positive weight, one that trails them negative. The policy is
then updated by advantage-weighted cross-entropy [37] over the router’s own generated tokens.
Labeled data Dt is only available on training environments; at testing time Wayfinder is applied to a
new environment with unseen resources and adapts from citations alone.
4.4
Forcing the policy to read evidence, not identifiers
A policy trained on a small number of environments can memorize which identifier carries which
topic (“coding questions go to resource A”). The shortcut scores well in training and collapses in a
target environment for which resources may carry different content, so it has to be prevented during
training rather than detected afterwards. We therefore apply two augmentations while training the
policy, both at the granularity of a session: a single training rollout, within which one assignment of
identifiers to resources is held fixed.

Dataset
Routing in real deployments combines two sources of heterogeneity: intra-corpus partitioning, where
different organizations split similar content across different resources (e.g., release notes in the wiki
vs. chat archives); and cross-corpus heterogeneity, where different resource types serve different
communicative functions and therefore expose different vocabulary, length, and structural style
(e.g., syntactic code blocks vs. conversational messages). Existing federated-search benchmarks
[33, 10] contain too few environments to support train–deploy splits, and BEIR [31] provides single-
corpus relevance judgments without independent environments. We therefore evaluate Wayfinder on
two complementary regimes (Table 1): intra-corpus environments derived from BEIR, and a new
cross-corpus Tech Startup benchmark in which each resource is drawn from a distinct real corpus.
We derive 18 environments by partitioning two BEIR corpora into disjoint resources via sentence-
transformer embeddings and a Gaussian Mixture Model: the specialized NFCorpus [6] (2 environ-
ments) and the larger fact-verification FEVER corpus [32] (16 environments). Each environment
inherits human-annotated document-level relevance judgments from the source dataset; queries are
arranged in an 80/20 temporal split.
We additionally construct a 5-environment Tech Startup benchmark in which the five resources
(emails, chat channels, issue tracker, wiki pages, code repository) are sourced respectively from
Enron emails [20], the Alpaca instruction-tuning corpus [29], GitHub issues from SWE-bench [19],
Wikipedia paragraphs from HotpotQA [38], and source code from CodeSearchNet [18]. Documents
and queries are disjoint across environments. Queries are rewritten to reference content rather than
the originating application and every retained query passes a semantic-retrieval quality gate (top-5
dense retrieval). Unlike the intra-corpus environments, resource boundaries here reflect natural
cross-application heterogeneity rather than synthetic clustering. Full construction and validation
details are in Appendix C.

Experimental Setup
We report three metrics, each a percentage for which higher is better. The router’s F1route [28, 4]
which scores the accuracy of the recommendation on its own. The agent’s citation F1cite, which
measures the effect of router on the agent’s grounding. We do not report answer accuracy: the primary
agent can answer many queries in these public benchmarks from parametric knowledge, so a correct
answer does not show that relevant evidence was retrieved, whereas F1cite credits only answers
7


grounded in the judged documents. The exploration savings S which measures that effect of the
router on the agent’s search effort: writing s(q) and s0(q) for the number of search calls the agent
issues on query q with and without a router, then S = 100 × meanq(1 −s(q)/s0(q)) is the saving
on a typical query.
We compare Wayfinder against baselines spanning classical, supervised, tool-retrieval and bandit
families. CORI [7] ranks resources from term statistics without learning. ResLLM [34] prompts an
LLM with document-derived resource summaries. ToolRetriever [26] embeds the same summaries
with a bi-encoder contrastively trained on training environments and scores them against the query.
LinUCB-D [22] treats each resource as a bandit arm updated from citation-derived binary feedback.
Learn2Rank [12] trains a supervised classifier using labels from the target environment which violates
our problem assumptions but we add for reference. LinUCB-D and Wayfinder adapt during the stream;
CORI, ResLLM and ToolRetriever are fixed once the environment is entered. All embedding-based
methods share the same MiniLM-L6-v2 encoder.
Wayfinder routing policy is implemented by finetuning Qwen3-8B using LoRA (rank 16, ∼0.1% of
base parameters) and resource randomization. The routing agent retrieves the top 25 memory entries
per decision step via semantic search to bound its context. Unless otherwise stated, the per-resource
sketch capacity is M = 100. Training runs 125 GRPO iterations; each iteration samples 8 queries
and generates 8 rollouts per query (GRPO group size for advantage normalization).
Reported results are average k-fold performance where datasets are partitioned at the environment
level (k = 2 for NFCorpus, k = 4 for FEVER and Tech Startup). Methods like ToolRetriever and
Wayfinder requiring cross-environment training are trained on the training split. If the method
relies on interaction statistics (e.g., CORI or Wayfinder) those are produced as test environments are
evaluated. Wayfinder is evaluated closed-loop: its memory is seeded with the documents cited in the
target environment’s training-split trajectories, without relevance labels, and is then updated from the
agent’s citations as test queries are processed. As a primary agent we use GPT-4o-mini.

Results
In this section we present experimental results and ablations under stationary conditions. Due to
space constraints the evaluations in non-stationary settings and case study are included in Appendix
A and Appendix B, respectively.
7.1
Experiment 1: Routers Comparison
Our hypothesis is that citation-derived adaptation pays in proportion to how poorly static descriptions
separate resources. On the intra-corpus benchmarks, roughly fifty resources are drawn from a single
corpus and their summaries read alike, so a router fixed at deployment has little left to discriminate
on; on Tech Startup each resource is a distinct corpus and its description is close to sufficient on its
own. Every router therefore enters the target environment cold and sees the identical query stream:
the adaptive routers revise their beliefs as that stream is processed while the static ones remain fixed,
and each router’s recommendations are logged as they are issued and scored afterwards against the
same relevance judgments. Wayfinder is evaluated closed-loop: its memory is updated with the
citations the primary agent emits after acting on Wayfinder’s own recommendations, on the same
query stream every baseline receives.
Routing budgets are B=5 on NFCorpus and FEVER and B=1 on Tech Startup. Wayfinder uses
the same LoRA policy with no retraining and one adapter per fold, and FEVER is capped at 50
queries per test environment. Each replay is paired with a no-router control on the same queries,
which issues 25.90, 32.90 and 5.86 search calls per query on the three datasets. F1c and Saved %
are measured by hard-routed replay because the closed loop itself is advisory: the agent may search
outside the recommendation, so its raw search counts exceed an unrouted agent’s and the savings
metric is negative by construction, which measures the protocol rather than the router. NFCorpus
rests on n=42: its two test splits yield only 9 and 33 GT-usable queries. F1route uses the same
RDR-based definition throughout the table; plain set recall would read 28.16 on NFCorpus, where
43% of queries emit fewer resources than there are gold ones.

not ground the most answers, however: CORI on NFCorpus (20.27) and ToolRetriever on FEVER
(55.52) reach higher F1c. Saved % must be read together with F1c, because a router that sends the
agent nowhere useful makes it give up early and so appears to save exploration: ResLLM saves
63.5% on NFCorpus while its F1c falls below the unrestricted agent’s (11.51 vs. 14.42).
On Tech Startup, where each resource is a distinct corpus and its description is close to sufficient on
its own, ToolRetriever is best on all three metrics (98.86, 85.31 and 70.4%). Wayfinder is second
on routing and citation F1 (86.60 and 80.78), ahead of Learn2Rank (83.28), which is trained on
target-environment labels, and of LinUCB-D (71.78), the other router that adapts online. No router
improves on letting the agent search all five resources (F1c of 87.44). LinUCB-D trails Wayfinder
on routing on all three datasets and on FEVER increases the agent’s search calls (−4.7% saved).
These results match the two regimes of our hypothesis: citation-derived adaptation gives the best
routing where resource descriptions read alike, while description-based tool retrieval suffices where
resources are distinct corpora. Although Wayfinder employs a reasoning-based routing policy with
environment memory, the routing behavior observed in our experiments is consistently shallow.
Across all three datasets, trajectories exhibit a median of two routing decisions per query, with over
99% of trajectories completing within two steps (one retrieval step and one action step) and no
evidence of long-horizon routing.

Limitations and future work
Wayfinder depends on the primary agent’s citations. Missing citations slow adaptation, but incorrect
ones write wrong evidence into the resource sketches, and routing degrades as their rate grows
(Appendix F.2); weighting updates by citation confidence, decaying unconfirmed evidence, or
revising a sketch when later citations contradict it could limit this, and we leave their evaluation to
future work. Our benchmarks are controlled testbeds built from public corpora, so they do not capture
enterprise permission structures or production-scale latency. Evaluating Wayfinder with authentic
tools and users is the natural next step.
9
Conclusion
We introduced Wayfinder, a router that adapts to a target environment from the citations its primary
agent emits, without target-environment labels. Under a closed-loop protocol shared by all routers,
Wayfinder gives the best routing on the intra-corpus benchmarks (47.67 and 64.72 F1r against 33.03
and 31.01 for the strongest baselines) and cuts the agent’s search calls by 61.2% and 73.7% while
improving its citation F1 over an unrouted agent. Where resources are distinct corpora, as in Tech
Startup, description-based tool retrieval suffices and ToolRetriever leads, with Wayfinder second.
Closed-loop routing stays within 3.3 points of the offline protocol, and RL post-training improves
routing F1 on both intra-corpus benchmarks.

Robustness to Non-Stationarity
Non-stationarity is a defining characteristic of federated environments, where the information within
resources can change over time independently of the agent’s actions. To evaluate robustness to such
exogenous changes, we progressively relocate an increasing fraction of ground-truth documents
associated with test queries to different resources before testing, simulating changes in where
information resides after deployment. Higher drift levels subsume lower ones to ensure consistency
across settings, and all methods are evaluated under identical drift realizations to isolate differences
in routing behavior. We report routing recall and precision to assess how effectively each method
maintains routing quality as the environment diverges from the training distribution.
Figure 2 shows that routing performance degrades for all methods as the degree of ground-truth
movement increases, reflecting the difficulty of routing under severe distribution shift. However,
Wayfinder maintains higher recall and precision across all drift levels, indicating greater robustness to
changes in where relevant information resides. In contrast, baselines that rely on static assumptions
or fixed ranking signals exhibit steeper performance declines as drift increases. These results suggest
that learning routing policies from interaction feedback yields representations that are less tightly
coupled to specific resource assignments, improving resilience to post-deployment environmental
changes.

Appendix: Data Construction Process
We construct synthetic federated retrieval environments from BEIR benchmarks to enable controlled
evaluation of routing under non-stationarity. Starting from a standard BEIR dataset (corpus, queries,
and relevance judgments), we transform static collections into dynamic, multi-resource environments
with temporal structure and exogenous drift.
For datasets with graded relevance (e.g., NFCorpus), we retain only highly relevant documents and
normalize relevance to binary. Queries without relevant documents after filtering are removed to
ensure well-defined routing supervision.
Each dataset is partitioned into multiple independent environments, representing distinct information
spaces. Documents are disjointly assigned to environments. Within each environment, documents
are organized into a fixed number of resources. Resources are constructed by clustering document
embeddings (using a sentence transformer) via a Gaussian Mixture Model, ensuring semantic
coherence within each resource and mimic similar content across resources.
To support description-based baselines, each resource is associated with an automatically generated
natural-language description. Descriptions are produced by prompting a large language model with
representative document samples from the resource (100).
Within each environment, queries are temporally ordered in a query stream to form a single timeline,
simulating interactions in a shared environment.
15


Queries are split temporally into training and test segments using an 80/20 ratio. When enabled,
exogenous drift events are realized by randomly moving documents across resources. Drifts are
applied only during the test period and preferentially target ground-truth relevant documents to
mimic meaningful drifts. Drift is introduced incrementally at multiple rates, where higher drift levels
subsume lower ones.
Before drift, we compute ground-truth coverage statistics per environment to characterize task
difficulty. The final dataset includes the initial resource state, persona query streams, relevance
judgments, train–test splits, pre-computed embeddings, and drift event specifications. All stochastic
components are seed-controlled to ensure reproducibility.
This construction enables systematic evaluation of routing policies under controlled resource frag-
mentation, partial observability, and increasing degrees of non-stationarity.
Tech Startup (cross-corpus) construction.
The Tech Startup benchmark is built outside the BEIR
pipeline, by combining five distinct real corpora into a single five-resource environment template
that mirrors a typical workplace stack. The five resources are sourced as follows: emails from
Enron [20], chat channels from the Alpaca instruction-tuning corpus [29] (response = document,
instruction-derived rephrasing = query), issue tracker from SWE-bench’s GitHub issues [19], wiki
pages from HotpotQA Wikipedia paragraphs [38], and code repository from CodeSearchNet [18].
We assemble five environments using a connected-component partition over (document, query) pairs
to ensure that no document or query appears in more than one environment.
Query rewriting and leakage control.
Each query is individually rewritten by an LLM rewriter
under explicit constraints: (i) reference document content rather than the originating application,
(ii) avoid surface words that name resources (“email”, “Slack”, “issue”, “ticket”, “commit”, “pull
request”, “wiki”, etc.), and (iii) read as natural questions a colleague would ask. After rewriting
we apply a regex-based blocklist filter that rejects any query still containing resource-revealing
tokens; matched queries are re-rewritten until the filter passes. We do not claim that residual style or
length artifacts are eliminated, since the underlying corpora differ in discourse type by construction
(cross-corpus heterogeneity is the property we want to measure); however, the same artifacts are
equally available to every baseline, and the cross-corpus regime’s natural difficulty is what makes the
supervised classifier (Learn2Rank) competitive in Table 2. Every retained query passes a semantic-
retrieval quality gate that requires its ground-truth document to appear in the top-5 of dense retrieval
(all-MiniLM-L6-v2) over the environment’s documents. The filter removes 4.0% of candidate queries;
the surviving 1,127 queries form the released benchmark.

Trajectory Generation and Citation Statistics
To isolate routing differences from stochastic exploration variance, we pre-compute primary-agent
trajectories once per environment and reuse them across Wayfinder, the bandit baselines, and all
ablations. This protocol fixes downstream interaction evidence so that performance differences reflect
how each method interprets and updates from the same retrieval traces, rather than differences in
agent exploration. Trajectories are generated with a production-grade tool-using agent (GPT-5-mini3)
configured with the structured search_resources and synthesize_answer tools described in
Section 4.1, with a per-rollout step budget of 5 and a context length of 16K tokens.
Citation rate and accuracy.
For each trajectory we measure the citation rate Prt[Ct̸ = ∅] and the
citation accuracy Et[ |ρ(Ct) ∩¯Rt|/|ρ(Ct)| | Ct̸ = ∅]. On FEVER, citation rates are high but vary
across environments (mean 85.7%, median 90.1%) while citation accuracy is stable (mean 71.3%,
std. 4.9%). On NFCorpus, both rate (mean 74.3%) and accuracy (mean 73.1%) are stable. On Tech
Startup, citation rate is consistently high (mean ∼95%) and accuracy is high (mean ∼73%) across
the five resource types. Low citation rates yield fewer memory updates rather than noisier ones,
supporting the observation that the citation gate trades coverage for precision, and motivating the
noise-robustness analysis in Section 7.

Training and Inference Hyperparameters
Routing policy.
Wayfinder is implemented as a LoRA-adapted routing policy on top of a Qwen3-
8B base model and trained using Group Relative Policy Optimization (GRPO). LoRA adapters use
rank 16 and are optimized with a learning rate of 5 × 10−6 and gradient accumulation over 4 steps.
Meta-training is performed for 25 GRPO iterations; each iteration samples 8 queries and generates
4 rollouts per query (GRPO group size for advantage normalization). Queries whose group has
zero-variance reward (e.g., all rollouts succeed or all fail) are filtered out by GRPO’s advantage
normalization and contribute no gradient signal.
Rollout and decoding settings.
Rollouts are generated with a maximum of 5 interaction turns and
a context length of up to 16K tokens. Decoding uses temperature 0.7 and nucleus sampling with
p = 0.95.
Memory and retrieval.
Unless otherwise stated, the routing agent maintains a per-resource memory
budget of M = 100 documents. At each routing decision, the agent retrieves the top 25 memory
entries via semantic search to constrain context length; this retrieval limit is independent of the
per-resource memory budget. Memory updates are enabled incrementally at test time and are gated
on agent-produced citations.
Embedding model.
All embedding-based components across methods use the same frozen sentence
encoder, sentence-transformers/all-MiniLM-L6-v2.
Bandit baseline.
LinUCB-D is a discounted linear UCB bandit with one arm per resource. Each
arm is represented by the centroid of the embeddings of up to 100 documents sampled from the
resource, and the context for query q and resource r is a fixed random projection (dimension 32) of the
elementwise product of their embeddings, concatenated with their cosine similarity and a bias term
(d=34). It selects the top-B resources by UCB score with exploration α=1.0, ridge regularization
λ=1.0 and discount γ=0.999. In the closed loop, after the agent acts on its recommendation, each
selected resource receives reward 1 if the agent cited a document from it and 0 otherwise.

Robustness to citation noise
A key claim of Wayfinder is that gating memory updates on agent citations rejects retrieval noise
without requiring labels. We stress-test this gate on Tech Startup by perturbing the cited-document

Memory Design (mem0 comparison)
We compare Wayfinder’s environment-structured memory against a generic semantic-memory base-
line implemented with mem04. The mem0 baseline stores past query–resource trajectories as text,
embeds them with a sentence-transformer model, and retrieves semantically similar trajectories by
vector similarity; candidate resources are then extracted from the retrieved trajectories. Wayfinder’s
memory instead represents resources as persistent entities and records interaction outcomes per
resource, enabling reasoning about resource-specific reliability over time. Both variants share the
same base model, resource representations, routing budget, and training procedure; only the memory
structure differs.
