## 摘要
程序演化为发现智能体记忆设计并研究其有效性背后的设计选择提供了一种有前景的方法。我们提出 MAPE，一个通过标准化生命周期接口和迭代式诊断-提议循环，从最小种子出发演化完整记忆程序的框架。在 LoCoMo 和 LongMemEval 上的实验表明，相比人工设计的基线，在服务成本为 35% 的情况下取得了最高 12% 的绝对准确率提升；进一步评估支持了跨服务后端和基准的迁移。实证分析和消融实验识别并验证了两种反复出现的设计模式：将原始对话保留为可检索证据，可保留提取记忆中遗漏的细节；而根据查询意图组织检索到的证据，有助于回答模型有效利用这些证据。将组合模块移植到五个现有记忆系统中，均提升了全部五个系统的准确率。除这些模式外，搜索目标决定了计算发生在何处：在优化准确率的同时优化服务成本，会将计算从基于 LLM 的记忆构建转移到查询时的选择性处理，同时保持有竞争力的准确率。这些发现共同为智能体记忆设计提供了实证经验。代码见 https://github.com/ash-ding/MAPE。

## Abstract
Program evolution provides a promising approach to discover agent memory designs and study the choices underlying their effectiveness. We introduce MAPE, a framework that evolves whole memory programs from minimal seeds through a standardized lifecycle interface and an iterative diagnosis-proposal loop. Experiments on LoCoMo and LongMemEval yield an absolute accuracy gain of up to 12% over manually designed baselines at 35% of the serving cost, with further evaluations supporting transfer across serving backbones and benchmarks. Empirical analyses and ablations identify and validate two recurring design patterns: retaining raw conversations as retrievable evidence preserves details omitted from extracted memories, while composing retrieved evidence according to query intent helps the answering model use it effectively. Transplanting the composition module into five existing memory systems improves accuracy across all five. Beyond these patterns, the search objective shapes where computation goes: optimizing serving cost alongside accuracy shifts computation from LLM-based memory construction to selective processing at query time while retaining competitive accuracy. Together, these findings offer empirical lessons for agent memory design. Code is available at https://github.com/ash-ding/MAPE.

## 2. 方法论：MAPE 框架

### 2.1 核心思想

- 用**标准化生命周期接口**把记忆流水线拆成可编程阶段，使整条管线对演化开放；用**迭代式"诊断—提议"循环**让 LLM 基于执行轨迹定位失败原因并生成修改方案；搜索从最小种子开始，并在目标函数中显式计入**服务成本**。

### 2.2 任务形式化（四阶段生命周期）

- 给定对话历史 $H_i$ 及其查询集 $Q_{H_i}$，记忆系统 $m$ 包含：
  - **Build**：$M_i = B_m(H_i)$，把历史转为持久记忆状态（内容 + 组织/索引结构），每个历史只构建一次。
  - **Retrieve**：$E_{i,j} = R_m(M_i, q_{i,j})$，选出与查询相关的证据。
  - **Compose**：$c_{i,j} = K_m(q_{i,j}, E_{i,j})$，把检索证据加工成回答上下文（受 CoM 启发，将"检索后的证据处理"显式独立为一阶段）。
  - **Answer**：$\hat{y}_{i,j} = G_\theta(q_{i,j}, c_{i,j})$，回答模型与提示词在所有候选间**固定不变**，以保证可比性。
- **搜索空间**：受接口兼容性与固定回答流程约束的程序空间 $M_I$；演化可修改 build/retrieve/compose 的实现及其支撑代码，从而探索替代表示、检索机制、证据处理流程，**包括跨阶段的协同修改**。

### 2.3 两个优化目标

- **准确率** $A_D(m)$：用 LLM 裁判给出二值正确性 $z_{i,j}=J_{\text{LLM}}(r,q,\hat{y},y)\in\{0,1\}$，先在每个历史内平均，再对历史做无权重平均。
- **生命周期服务成本** $C_D(m)$：按阶段统计 LLM 输入/输出与 embedding token，按单价折算：
  $C_{i,s}(m)=p_{in}T^{in}_{i,s}+p_{out}T^{out}_{i,s}+p_{emb}T^{emb}_{i,s}$，跨四阶段求和后按该历史所服务的查询数**摊销**，再对历史取均值并折算为"美元/千次查询"。
- **两种搜索模式**：
  - **MAPE-A**：只优化准确率。
  - **MAPE-P**：准确率与成本作为两个独立目标，维护**帕累托前沿**（无其他候选在准确率不低、成本不高且至少一项严格更优），提议器依据前沿引导搜索，档案保留全部已评估候选。

### 2.4 演化循环（算法流程）

1. 评估种子程序并入档（MAPE-P 用"无记忆 + 全上下文"两种种子；MAPE-A 只用"无记忆"种子以避免架构锚定）。
2. **Propose**：提议器（agent）查阅档案中的实现、评估结果与诊断，选择父代（可多父），产出一个新候选及其**设计假设**（改动内容 + 预期收益）。
3. **Sanity check**：小规模试跑检测执行错误，提议器可在固定预算内修复（最多两次），仍失败者不进入全量评估。
4. **Evaluate**：在固定搜索集上跑全量，得到准确率与成本。
5. **Diagnose**：独立诊断 agent 阅读实现、假设、结果与执行轨迹，把失败归因到 build/retrieve/compose/answer/judge/data（证据不足则标 `unattributed`），并给出后续线索；诊断不修改候选。
6. **Archive**：实现、父代引用、假设、结果、轨迹、诊断一并入档，**被支配的候选也保留**，以便后续提议回到早期实现。
7. 直到提议预算耗尽。之后用搜索集准确率（MAPE-A）或帕累托前沿（MAPE-P）初筛，冻结后在**演化期间不可见的更大评估集**上评测，并人工剔除不可扩展的实现（如检索时对全历史做穷举 LLM 处理），每个设置报告评估集准确率最高的程序。

## 6. 主要结论与发现

- **性能**：
  - LoCoMo（GPT-4.1 mini）：MAPE-ALCM 87.94%（全类别最优，成本 7.21），MAPE-PLCM 85.18%（成本 2.03，约为前者 28%）。
  - LongMemEval（Qwen）：MAPE-ALME 77.00%、MAPE-PLME 72.25%，均超最强基线 RAG 的 66.00%（+11.00 绝对）。
  - 换后端（Qwen）：MAPE-PLCM 81.33%，比 SimpleMem 高 **12.01% 绝对**，成本仅为其 **35%**。
  - 双向跨基准迁移均优于五个人工记忆系统（LoCoMo→LME 方向略低于 RAG）。
- **两种反复出现的设计模式**：
  - **保留原始对话作为可检索证据**：抽取的记忆会遗漏细节；去掉检索到的原始轮次使准确率下降 12.17%（LoCoMo）/ 6.50%（LongMemEval），LongMemEval 上单会话-助手类问题降幅达 20.00%。
  - **按查询意图组合证据（RQS）**：按意图路由到"LLM 抽取 + 确定性计算（日期算术、程序化计数/求和）+ 一次 deliberation"的脚手架；去掉后降 4.44%（LoCoMo）/ 6.25%（LME），时序类问题降幅最大；移植到 5 个系统带来 2.75–9.25% 绝对提升（Mem0 最小，因其错误以"检索缺失"为主，而 RQS 主要修复"证据足够但未被用好"的情形）。
- **优化目标塑造计算分配**：
  - 只优化准确率的搜索**渐进加码**：如第 13 步引入按会话的笔记抽取使成本约增 6 倍，谱系以"单主链叠加"为主；MAPE-ALME 的构建阶段占总成本约 92%。
  - 联合准确率—成本搜索**谱系更分支**、保留廉价替代方案；最终程序改为在查询时做选择性计算（MAPE-PLME 用纯 BM25、构建期零模型调用），在 LongMemEval 与 LoCoMo 上分别少用 **90%** 与 **40%** 的服务调用。
- **跨后端稳健性差异**：MAPE-ALCM 把最终日期解析留给回答模型，换到 Qwen 后时序准确率从 79.84% 跌至 43.80%；MAPE-PLCM 在回答前显式把相对时间解析为绝对日期，保持 70.93%（145 个时序错误中 134 个返回的是对话日期而非事件日期）。

## 7. 优点

- **问题定位清晰且有元科学价值**：不只追求分数，而是把"演化"当作发现设计规律的工具，并用消融 + 跨系统移植 + 错误归因三重手段验证规律，结论比单一 SOTA 更具迁移性。
- **接口设计合理**：把 compose 从 retrieve 中显式分离，使"证据后处理"成为可编程、可移植的模块——这正是 RQS 能被移植进 5 个异构系统的前提。
- **目标函数设计有洞察**：将生命周期成本（含构建成本按查询数摊销）纳入搜索，揭示了"成本约束会把计算从构建期推向查询期"这一非平凡结论，对实际部署有直接指导意义。
- **实验控制较严谨**：评估集在演化全程不可见；跨系统比较固定回答模型、提示与裁判；RQS 移植采用同一检索结果回放以隔离混淆；同时报告成本与准确率，而非只报准确率。
- **诚实的负结果与分析**：报告了后端切换导致的方法排序反转、跨基准迁移未超 RAG 等情况，并给出机制解释。

- **覆盖面有限**：仅两个对话记忆 QA 基准；组件分析集中在单个代表性程序（MAPE-ALME），其他三个入选程序的内部机制剖析较少；未涉及经验性记忆、开放式智能体等场景。
- **运行方差与主观判断**：LongMemEval 每个设置仅 1 次演化，轨迹与结果可能随运行变化；初筛与"剔除不可

扩展的实现"依赖人工判断，可能引入主观性；成本核算不含裁判与搜索 agent 的开销，故报告的是"服务成本"而非"研发总成本"，读者若据此估算落地成本需注意口径。
- **搜索预算偏小**：每次演化仅 20 步、每步 1 个候选，相对程序空间而言探索非常稀疏；"哪些设计未被发现"无法从本文推断，因此"演化能找到有效设计"的结论成立，但"演化能找到最优设计"并无证据。

- **可迁移性的边界未刻画**：RQS 的移植收益在 Mem0 上最小，作者归因于错误类型分布差异，但未给出"何种错误结构下该模块有效"的可操作判据，实际使用者仍需自行试错。
- **缺乏与"人类专家再设计"的对照**：论文主张演化能发现有效设计，但没有让专家在看到演化结果后重新设计系统，因而无法判断这些设计是"专家本可想到但未实现"还是"确实超出常规思路"。

## 9. 启示与可延展方向

- **对记忆系统工程的启示**：与其在"抽取式记忆 vs 原始上下文"之间二选一，不如把两者作为**互补证据源**同时保留，并把"证据如何被加工"独立成可替换模块；构建期与查询期的计算分配应作为一等设计变量，而非实现细节。
- **对自动化科研的启示**：把"诊断—提议"与"多目标档案"结合，使搜索过程本身产出可解释的设计假设（每条候选附带预期收益），这比单纯的分数优化更接近可累积的知识；将"组件移植回人工系统"作为验证环节，是弥补演化结果"只在自家管线内有效"质疑的有效手段。
- **可延展方向**：
  - 扩大搜索预算与运行次数，报告跨运行的稳定性区间而非单点结果；
  - 将搜索扩展到经验性/程序性记忆、多模态历史、多智能体共享记忆等场景；
  - 把延迟、存储与隐私约束纳入目标函数，检验"计算从构建期移向查询期"的结论是否稳健；
  - 引入更强/更弱的提议器做能力消融，厘清"发现"在多大程度上归功于搜索框架、多大程度上归功于底层模型；
  - 设计"专家再设计"对照实验，量化演化发现的**新颖性**而非仅有**有效性**。

## 10. 总体评价

- 这是一篇**方法论取向强于刷榜取向**的工作：其核心贡献不是 87.94% 或 77.00% 这些数字，而是"从无记忆种子出发整程序演化 + 双目标帕累托搜索 + 消融/移植/归因三重验证"这一套可复用的研究范式，以及由此提炼出的两条设计规律（保留原始对话、按意图组合证据）和一条机制性结论（成本约束改变计算在生命周期中的分布）。
- 实验在**控制变量**上做得比较扎实（评估集隔离、固定回答模型与裁判、检索回放式消融与移植），并如实报告了后端切换导致的排序反转、跨基准迁移未超 RAG 等负结果，学术诚信度较高。
- 主要短板在于**覆盖面与统计强度**：基准仅两个、LongMemEval 仅单次演化、组件剖析集中于单个程序、成本口径偏窄、裁判无人工校验。这些不足限制了结论的外推范围，但不影响其作为"用演化发现设计规律"这一方向的开创性示范价值。
- 适用读者：记忆系统/长程对话 QA 方向的研究者与工程师（可直接借鉴 RQS 与"原始轮次保留"两条实践），以及对 LLM 驱动程序搜索、自动化经验发现感兴趣的方法论研究者。
