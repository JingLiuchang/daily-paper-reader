## 摘要
构建跨领域的多智能体系统（MAS）应用需要将多样化需求转化为可执行系统，涉及任务分解、智能体与工具选择以及执行组织。现有研究已分别探索了 MAS 构建的各个方面，包括智能体生成、架构设计、工作流生成和组件选择。然而，这些方法通常被独立开发和评估，使用不同的任务规范、组件资源和执行设置。这使得难以比较它们的构建能力，也难以确定它们如何应用于不同领域。为解决这一问题，我们提出 OpenMAS-GApp，一个面向跨多样领域的 MAS 应用构建的 One-for-All 基准。它标准化任务输入、组件资源、构建接口和执行环境，以支持在一致条件下进行 MAS 构建。在 OpenMAS-GApp 中，我们提供 Graph Harness 作为参考构建方法，该方法推导任务依赖关系、选择兼容的智能体和工具，并将其交互组织为可执行图。我们在涵盖四种应用类型和四个专业领域的 20 种评估设置下，跨 19 个基准数据集评估了构建方法。

## Abstract
Constructing multi-agent system (MAS) applications across domains requires translating diverse requirements into executable systems, involving task decomposition, agent and tool selection, and execution organization. Existing studies have explored individual aspects of MAS construction, including agent generation, architecture design, workflow generation, and component selection. However, these methods are often developed and evaluated independently, using different task specifications, component resources, and execution settings. This makes it difficult to compare their construction capabilities or determine how they can be applied to different domains. To address this problem, we propose OpenMAS-GApp, a One-for-All benchmark for MAS application construction across diverse domains. It standardizes task inputs, component resources, construction interfaces, and execution environments to support MAS construction under consistent conditions. Within OpenMAS-GApp, we provide Graph Harness as a reference construction method that derives task dependencies, selects compatible agents and tools, and organizes their interactions into executable graphs. We evaluate construction methods across 19 benchmark datasets under 20 evaluation settings spanning four application types and four professional domains.

- **背景**：模式识别技术在生物医学、遥感、工业检测、自动驾驶等领域广泛应用，而这些领域的应用往往由多个相互依赖的阶段组成，每个阶段需要专门知识与处理能力。多智能体系统（MAS）通过把不同任务分配给专门智能体、并为其配备合适工具来满足这类需求，智能体之间还需交换中间结果并协调执行。
- **核心痛点**：跨领域构建 MAS 应用需要把多样化需求翻译成可执行系统（任务分解、智能体与工具选择、执行组织），但现有研究沿各自方向独立演进：

## 2. 方法论

### 2.1 基准的形式化定义

- 对领域 *d* 中的评估条目 *b* 与问题 *i*：构建方法 $F_m$ 接收需求 $R_{bi}$、组件注册表 $C=\{c_j=(p_j,I^c_j,O^c_j)\}$、领域资源 $K_d$、执行环境 $\Omega_d$、权限 $P_d$、预算 $B_d$ 与随机种子 $\xi_u$，输出应用 $A=(U,T,D,X)$（可调用智能体与工具、任务分配、数据连接、执行关系）。
- 由统一执行器产生输出与执行记录，再用源数据集的 parser/evaluator 在**完整预测集**上计算归一化分数 $M_b\in[0,1]$，跨 $R$ 次完整运行取均值作为任务得分（式 4）；构建成本与执行成本分开报告。

### 2.2 Graph Harness 三阶段流程（核心方法）

**阶段一：任务结构推导（Task Structure Derivation）**

- 用 LLM 从需求中抽取原子需求集 $U_d=\{u_k\}$ 与 $N$ 个候选任务 $\tilde\tau_i=(z_i,g_i,I_i,O_i)$（选择标志、目标与操作、所需输入、期望输出）。
- 任务选择建模为覆盖约束：$A_d z \succeq b$（$A_{ki}$ 表示任务 $i$ 是否满足需求 $k$，$b_k$ 表示是否强制需求），保证强制需求均被覆盖。
- 依赖关系区分**显式执行前置** $c_{ij}$ 与**数据依赖** $b_{ij}$（经类型与语义校验的 output→input 绑定），联合等待关系为 $a_{ij}=1-(1-c_{ij})(1-b_{ij})$。
- 通过整数秩约束 $h_j \ge h_i + 1 - N(1-a_{ij})$ 保证任务等待图无环；最终 Harness 另行允许受控反馈。

**阶段二：组件选择（Component Selection）**

- 能力匹配分数：$q_{ijr}=v_{ijr}\cdot\frac{1+\cos(e_{p_j},e_{k_{ir}})}{2}$（$v$ 为语义支持二值判断，$e$ 为嵌入）。
- 路径能力覆盖：$Q_i(p)=w_i^\top[\max_{c_j\in p} q_{ijr}]$，权重非负且和为 1。
- 接口兼容性：对字段 $f=(n,t,s)$ 定义 $\chi(f_o,f_r)=I[t_o\preceq t_r]\,h_f\,s_f$（类型可赋值/可注册转换、语义接受、连续匹配分）；强制输入字段必须通过硬性检查，加权得到边兼容度 $\eta_e$，路径均值为 $\Gamma_i(p)$。
- 路径效用：$U_i(p)=\lambda^\top[Q_i(p),\Gamma_i(p),-\bar C_i(p)]^\top$，成本在冻结的可行路径族上做极值归一化。
- 通过能力阈值 $\delta_i$ 与边阈值 $\epsilon_i$ 形成可接受路径族，固定保留 $k_i=2$ 条最高效用路径（少于 2 条即构建失败），合并为 Selected Component Graph。

**阶段三：图式 Harness 构建（Graph Harness Construction）**

- 借助领域知识 $\Psi$ 生成三类画像：Task Requirement Profile、Component Operation Profile、Domain Semantic Profile。
- 合成执行节点 $v_i=(s_i,\ell_i,I^v_i,O^v_i,\rho_i)$，$\rho_i\in\{\text{Exec},\text{Choice}\}$，要求 $\varnothing\neq\mu_d(v_i)\subseteq C_i$（每个执行节点绑定注册表内组件）。
- 合成带类型转移 $e_{ij}=(v_i,\tau_{ij},\gamma_{ij},v_j,m_{ij})$，$\tau\in\{\text{Seq},\text{Alt},\text{Par},\text{Fb}\}$；选择节点用打分 argmax（同分按标识符确定性打破）；并行分支用 join 守卫 $\gamma_{join}(t)=\prod_b d_b(t)$；反馈转移需同时满足单边预算 $N_e^{\max}$ 与总预算 $N_\Sigma^{\max}$（实现取 3 与 16），并以原子方式递增计数。
- 验证器检查任务覆盖、注册表成员、必需绑定、等待关系、类型化控制条件。

### 2.3 理论分析

- **命题 B.1**：在覆盖约束、绑定完备与秩约束下，所有强制需求均有覆盖任务、等待图无环、拓扑序尊重前置与生产者依赖、任务执行前输入就绪。
- **引理 B.2**：能力覆盖在无序组件集合上单调、有界且**次模**（边际收益递减）。
- **命题 B.3**：固定基数 $k_i$ 下，取效用最高的 $k_i$ 条路径即最优，最大总效用为前 $k_i$ 个效用之和。
- **命题 B.4**：执行合约不变量在提交式状态转移下归纳保持（版本失效、分支作用域、join 合并）。
- **命题 B.5**：有限 Harness + 有限初始 token + 有限扇出 + 去掉反馈边后无环 + 持久有界计数器 ⇒ 有限步内到达 completed 或 failed。

## 6. 主要结果与发现（据论文报告）

- **Q1 总体性能**：Graph Harness 在多数评估设置上取得最高或接近最高的归一化分数，且在跨领域（医学、金融、科学、法律）场景中相对通用型基线优势更明显；AFlow、ADAS、GPTSwarm、AgentSquare 等自动化设计方法在统一组件生态与预算下表现分化，说明原论文实验设置下的结论难以直接迁移。
- **Q2 Harness 范式必要性**：在相同组件与预算下，具备显式任务结构、依赖关系与类型化控制流的 Harness 类方法优于扁平组件选择与纯提示规划，表明"结构化编排"本身带来增益，而非仅靠组件数量或模型能力。
- **Q3 构建消融**：移除覆盖约束或数据依赖建模会显著降低构建成功率与任务分数；接口兼容性检查对跨领域任务尤为关键；Choice/Par/Fb 等控制结构的移除主要影响复杂推理与多跳问答类任务。
- **Q4 编排表示**：表达力更强的表示（Agent Graph / Workflow）整体优于 Sequence 与 Tree，但增益依赖于构建方法能否有效利用其表达力；表示越复杂，对构建方法的验证与约束要求越高。
- **Q5 组件规模**：组件池扩大后，Graph Harness 的能力匹配与接口兼容打分仍能维持选择质量，构建开销增长处于可控范围；朴素选择方法在组件池扩大时性能下降更明显。
- **Q6 效率**：Graph Harness 的构建开销（时间、调用次数、token）处于同类自动化设计方法的中等水平，但单位成本带来的性能增益更高；相比 Debate、Self-Refine 等推理时增强方法，其在执行侧的开销更可控。
- **Q7 鲁棒性**：多次运行的分数方差较小，构建成功率稳定；对需求与组件描述扰动具有一定容忍度，但接口字段描述缺失时性能下降明显。
- **Q8 跨领域案例**：案例分析显示方法能为不同领域自动组合出符合领域语义的智能体与工具链（如医学中的检索—分析—审查、金融中的表格抽取—算术—复核），验证了 One-for-All 设计的可行性。

## 7. 主要贡献

1. **基准层面**：提出 OpenMAS-GApp，统一了跨领域 MAS 应用构建的**任务输入、组件注册表、构建接口、执行环境与评估协议**，填补"评估应用构建能力"而非"评估智能体执行能力"的空白。

3. **理论层面**：给出覆盖完备性、等待图无环性、top-k 路径最优性、执行合约不变量保持与终止性等命题，并分析构建复杂度。
4. **实证层面**：在 20 个评估设置、4 类应用与 4 个专业领域上，与 7 种构建范式、4 种自动化设计方法及 4 种推理时增强方法进行统一条件下的系统比较，并给出消融、可扩展性、效率与鲁棒性分析。

## 8. 局限与未来工作

- **实例级构建成本**：每题单独构建导致总开销随题量线性增长，未来可探索应用模板复用、跨题迁移与增量构建。
- **单一骨干模型**：结论主要基于一个 LLM 骨干，需在更多模型（含开源小模型与更强闭源模型）上验证可迁移性。
- **组件生态规模**：20 组件注册表相对真实工程生态偏小，组件自动发现、注册与版本演化尚未纳入。
- **评估粒度**：以最终答案分数为主，对中间执行轨迹的质量、可解释性与失败模式缺乏细粒度度量。
- **安全与权限**：形式化定义中虽引入权限 $P_d$ 与预算 $B_d$，但对越权调用、工具副作用与多智能体协同安全的系统性评估仍不充分。

## 9. 总体评价

- **价值**：论文的核心价值在于**把"MAS 应用构建"从各自为战的工程实践提升为可比较的研究问题**，其统一接口与评估协议有望成为该方向的公共基础设施；Graph Harness 作为参考方法，展示了"结构推导—组件选择—图式构建"这一范式的可行性与理论可分析性。
- **方法成熟度**：三阶段设计职责清晰、约束明确，配有验证器与理论保证，工程可实现性较好；但方法对需求文本质量、组件接口描述的完备性较为敏感。
- **证据强度**：实验覆盖面与统一性较强，消融与鲁棒性设计合理；不足在于单骨干、实例级构建与有限种子数，削弱了结论的普适性与统计强度。
- **定位建议**：适合作为跨领域 MAS 构建方向的**基准论文 + 参考方法论文**阅读；若关注落地，需重点评估其在批量任务、组件动态演化与安全约束下的扩展性。
