## 摘要
近似最近邻搜索（ANNS）是现代数据密集型系统中的关键基础操作，其受内存限制的向量扫描阶段使存内计算（PIM）成为一种有前景的加速平台。现有基于PIM的ANNS系统大多将面向CPU的距离评估和top-k选择移植到PIM上，引入了计算和状态开销较大的操作，与轻量、隔离的PIM核心不匹配。为解决这些不匹配问题，我们提出PIVOT，一种带协作过滤的PIM原生向量搜索系统，它彻底重新思考了ANNS应如何在商用PIM上执行。首先，PIVOT围绕二值量化重构PIM侧距离评估，以利用PIM原生位运算，实现无需查找表（LUT-free）的评估，具有低算术开销和较小的本地内存占用。其次，PIVOT围绕阈值引导的协作过滤重新设计PIM侧候选选择，使用幸存质量模型（survivor-mass model）为CPU侧簇过滤和PIM侧下界过滤推导保守阈值，从而减少输出流量并消除每核top-k状态。PIVOT将这些阶段组织为协作工作流，将查询全局协调和重排序保留在CPU上，同时将内存密集型、数据并行的过滤分配给PIM。为高效实现该工作流并在设备间保持高利用率，PIVOT进一步生成配置专用的PIM内核，并在查询批次间将CPU侧准备与重排序同PIM侧过滤进行流水线化。在真实UPMEM硬件上的评估表明，PIVOT过滤掉99.3%–99.7%的探测向量，并且其QPS分别最高达到CPU基线和先前PIM基线的18.8倍和10.2倍。PIVOT还比现有PIM系统取得更高的召回率，并在高维嵌入上仍然有效。

## Abstract
Approximate nearest neighbor search (ANNS) is a key primitive in modern data-intensive systems, and its memory-bound vector-scanning stage makes processing-in-memory (PIM) a promising acceleration platform. Existing PIM-based ANNS systems largely transplant CPU-oriented distance evaluation and top-$k$ selection onto PIM, introducing arithmetic- and state-heavy operations that poorly match lightweight, isolated PIM cores. To address these mismatches, we present PIVOT, a PIM-native vector search system with cooperative filtering, which thoroughly rethinks how ANNS should be executed on commodity PIM. First, PIVOT recasts PIM-side distance evaluation around binary quantization to exploit PIM-native bitwise operations, enabling LUT-free evaluation with low arithmetic cost and a small local-memory footprint. Second, PIVOT redesigns PIM-side candidate selection around threshold-guided cooperative filtering, using a survivor-mass model to derive a conservative threshold for CPU-side cluster filtering and PIM-side lower-bound filtering, thereby reducing output traffic and eliminating per-core top-$k$ state. PIVOT organizes these stages into a cooperative workflow that keeps query-global coordination and reranking on the CPU while assigning memory-intensive, data-parallel filtering to PIM. To efficiently realize this workflow and sustain high utilization across devices, PIVOT further generates configuration-specialized PIM kernels and pipelines CPU-side preparation and reranking with PIM-side filtering across query batches. Evaluations on real UPMEM hardware show that PIVOT filters out 99.3-99.7% of probed vectors and achieves up to $18.8\times$ and $10.2\times$ the QPS of CPU and prior PIM baselines, respectively. PIVOT also achieves higher recall than existing PIM systems and remains effective on high-dimensional embeddings.

## 1. 核心问题与整体含义（研究动机与背景）

- **应用背景**：近似最近邻搜索（ANNS）是 RAG、向量数据库、推荐系统、语义检索等数据密集型系统的核心原语。其中基于聚类的 IVF（倒排文件）索引因索引紧凑、搜索代价可控、扫描模式高度并行，在十亿级生产系统中被广泛使用。
- **瓶颈**：大规模 IVF 搜索的向量扫描阶段受内存带宽限制，暴露出冯·诺依曼瓶颈，因此存内计算（PIM）被视为有前景的加速平台。
- **核心问题**：现有 PIM-based ANNS 系统（UPVSS、UpANNS、DRIM-ANN 等）基本是把面向 CPU 的距离评估与 top-k 选择流程直接搬到 PIM 上，与商用 PIM 的架构特性严重不匹配，论文将其归纳为两类“错配”：
  - **评估–内核错配**：浮点或乘法密集的距离计算、PQ 的查询相关查找表（LUT）依赖，与 PIM 核算术能力弱、本地内存（WRAM 仅 64 KB）有限的特性冲突。实测表明 PQ 的 LUT 在 M=32 时即超出 WRAM 容量。
  - **搜索范式错配**：分布式 top-k（per-DPU 或 per-tasklet）需要复制排名状态、同步更新，并导致候选输出放大（最高达 CPU 全局 top-k 的 7813 倍）；而“全部返回距离给 CPU”的方案又带来过量传输。两种方案都无法获得及时的全局剪枝阈值。
- **整体含义**：论文主张必须为商用 PIM 设计“PIM 原生”的 ANNS 执行路径——算术轻、状态轻、可独立执行，并将查询全局控制留在 CPU，从而真正释放 PIM 的聚合带宽与大规模并行能力。

## 2. 方法论：核心思想与关键技术细节

PIVOT 的核心思想是**联合重新设计距离评估内核与候选选择范式**，遵循三条原则：PIM 原生距离评估、以协作过滤替代分布式 top-k、按 CPU/PIM 各自优势划分工作并流水线化。

### （1）PIM 原生距离评估内核
- 基于 **RaBitQ 风格二值量化**：每个向量存 1-bit 基础码（用于 PIM 侧下界过滤）+ 多位精化码（留在 CPU 用于重排）。
- **中心化查询量化**（借鉴 FAISS 实现）：将查询围绕零点量化，消除对每个数据库码单独做 popcount 的开销，整数相似度项由**加权 XOR–popcount 与整数累加**完成，实现**免 LUT**。
- 下界重构公式：
  \[
  LB^2(q,x) = a_x + \rho_j^2 - b_x I(q,x) s_{q,j} - \rho_j e_x
  \]
  其中 \(a_x, b_x, e_x\) 为逐向量因子，\(\rho_j=\|q-c_j\|_2\)，\(s_{q,j}\) 为中心化查询缩放。
- **简化精度 FastFloat**：用符号+指数+编译期固定宽度的尾数表示操作数，通过整数与位运算完成对阶、尾数运算与规格化，并将 \(b_x I(q,x) s_{q,j}\) 融合为单次低精度运算，从而把通用软件浮点从逐向量热路径中移除。

### （2）阈值引导的协作过滤（替代分布式 top-k）
- **逐簇残差统计**：索引阶段为每个 IVF 簇建立残差范数直方图 \(H_j=\{(s_{j,b}, w_{j,b})\}\)，仅增加 \(N_h\) 项/簇，无逐向量元数据。
- **查询条件化幸存质量模型**：在高维各向同性近似下，角度项 \(\sqrt{D}\cos\theta \sim \mathcal{N}(0,1)\)，估计半径 r 内的期望向量数：
  \[
  \hat{G}_j(q,r)=\sum_{b=1}^{N_h} w_{j,b}\,\Phi\!\left(\frac{\sqrt{D}\,(s_{j,b}^2+\rho_j^2-r^2)}{2s_{j,b}\rho_j}\right),\quad \hat{M}_j(q,r)=|C_j|\hat{G}_j(q,r)
  \]
- **原始阈值选取**：\(\tau_0(q)=\inf\{r \mid \hat{\Lambda}(q,r)\ge k\}\)，因单调性可用二分查找。
- **保守阈值校准**：用小型离线查询集选择乘性校正因子 \(\beta_\epsilon\)，使 \(\Pr[R_k(q_i) > \beta_\epsilon\tau_0(q_i)] \le \epsilon\)，最终 \(\tau(q)=\beta_\epsilon\tau_0(q)\)。
- **CPU 簇级过滤**：若 \(\hat{M}_j(q,\tau(q)) \ge \mu_{\min}\) 才派发该簇；\(\mu_{\min}\) 按 nprobe 范围校准以保证召回损失不超过 δ。相比直接减小 nprobe，该方式基于查询条件化幸存质量自适应抑制低产出簇。
- **PIM 向量级过滤**：各 tasklet 独立处理不相交分片，仅当 \(LB^2(q,x)\le\tau^2(q)\) 时输出向量 ID，**无需 LUT、排名缓冲或逐向量同步**。
- **CPU 重排**：收集幸存者，用完整多位 RaBitQ 码重排得到最终 top-k。

### （3）实现优化
- **配置专用 DPU 内核**：在索引准备阶段按维度、qb、tasklet 数、DMA/输出缓冲大小、FastFloat 尾数宽度生成专用二进制，静态分配 WRAM 缓冲、消除分支、固定循环边界、展开 XOR–popcount 路径、内联融合 FastFloat。
- **流水线 CPU–PIM 执行**：连续查询批次重叠——DPU 过滤批次 i 时，CPU 同时准备批次 i+1 并重排批次 i−1。
- **数据路径**：沿用 list-slicing 与热表复制；每个 PIM 记录连续存放 ID、1-bit 码与下界因子；tasklet 用私有 DMA 大小缓冲累积幸存者，满时同步刷新，避免热路径同步。

## 6. 主要结论与发现

- PIVOT 在真实 UPMEM 上**过滤掉 99.3%–99.7% 的探测向量**（CPU 簇过滤先去除约 38%–55%，PIM 向量过滤再去除绝大部分）。
- **QPS 最高达 CPU 基线（FAISS-IVF-RaBitQ）的 18.8 倍、先前 PIM 基线（DRIM-ANN-Rerank）的 10.2 倍**；在 Recall@100 > 0.80 时对 CPU 有 5.0–5.1×，>0.95 时扩大到 14.0–18.8×。
- PIVOT 与 FAISS 达到几乎相同的最高召回，说明 PIM 原生内核与保守过滤**不损失搜索精度**；而 DRIM-ANN 系列受 PQ 量化误差与 WRAM 限制，无法达到 0.85（DEEP1B）/0.90（SIFT1B）以上召回。
- 消融显示：用 DPU 本地 top-500 替代 PIM 向量过滤使 QPS 下降约 68%–69%；两级过滤都关闭则下降约 77%–79%，证明两级过滤缺一不可。
- 优化效果：FastFloat 提升 QPS 2.57–2.75×（召回变化 ≤0.07 个百分点）；内核专用化提升 1.49–1.50×；流水线减少端到端时间 29.8%–37.2%。
- 高维场景（1024 维）下，Recall@100 > 0.95 时 PIVOT 仍达 CPU 基线的 4.38×，验证了方法的维度可扩展性。
- 总体结论：高效 PIM-based ANNS 必须**联合重设计距离评估内核与候选选择范式**，而非直接移植 CPU 工作流。

## 7. 优点（方法与实验亮点）

- **架构感知的深度协同设计**：不是简单移植，而是针对 PIM 的算术弱、WRAM 小、无共享内存/无核间通信三大约束，同时重构“评估内核”和“选择范式”，问题定位清晰（两类 mismatch 有实测数据支撑，如图 2 的 roofline 与 WRAM 占用分析）。
- **以“阈值 + 过滤”替代“分布式 top-k”**：巧妙消除排名状态、同步与输出放大，且阈值来自轻量统计模型（残差直方图，无逐向量元数据），并用离线校准保证保守性，兼顾效率与召回可控性。
- **软硬件协同的工程实现**：配置专用内核（静态 WRAM 分配、循环展开、分支消除）+ 跨批次流水线，充分利用了 PIM 的流式特性。
- **真实硬件验证**：在 2,543 个 DPU 的真实 UPMEM 上评估，而非模拟器，结果可信度高。
- **实验设计较严谨**：与 CPU 基线共享索引与重排路径、为基线设置 WRAM 上限内的最大 top-k、报告端到端时间并计入重排代价，消融维度丰富（过滤、内核、流水线、FastFloat、δ、ε、qb、k、DPU/tasklet 扩展、高维）。

## 8. 不足与局限

- **硬件平台单一**：仅在 UPMEM 上评估，虽作者声称设计原则可推广到更广的商用 PIM，但缺乏在其他 PIM 架构（如 GDDR6-AiM、HBM-PIM）上的验证。
- **低召回区间劣势**：在 MS MARCO10M 低召回区，固定 CPU–PIM 准备与传输开销未被充分摊销，PIVOT 略慢于 CPU 基线，说明小规模/低 nprobe 场景收益有限。
- **依赖离线校准**：阈值估计需要小型校准查询集（或用采样向量替代），若查询分布漂移，保守阈值 β_ε 的有效性可能下降；各向同性残差方向近似也引入建模误差，需靠校准补偿。
- **基线对比的公平性边界**：DRIM-ANN 受 PQ-M=16 与 WRAM 限制难以达到高召回，高召回区间的“10.2×”优势部分源于基线受硬件约束而非纯算法差距；未与 GPU/FPGA 等平台对比。
- **部分系统被排除**：UPVSS（容量超限）、UpANNS（WRAM 超限）未纳入对比，横向覆盖不完整。
- **扩展性非理想**：DPU 扩展呈次线性（CPU 侧阶段不随 DPU 扩展、IVF 列表大小不均导致负载不均衡）；tasklet 超过约 11 个后吞吐饱和。
- **未报告算力/能耗开销**：论文聚焦 QPS 与召回，未给出能效、功耗或总机时数据，对实际部署的成本评估不足。
- **对 k 与维度组合的覆盖有限**：高维仅一个数据集（MS MARCO10M），top-k 敏感性仅在 DEEP1B 上做，结论的普适性仍需更多验证。

## 9. 与相关工作的定位差异（承接前文的横向比较）

- **与 DRIM-ANN 的本质区别**：DRIM-ANN 属于“把 IVFPQ 搬到 PIM”的迁移式方案，其瓶颈来自 PQ 的查询相关 LUT 与 DPU 本地 top-k 排名状态；PIVOT 则从“PIM 能高效做什么”出发，反向选择 1-bit 量化 + 阈值过滤，二者的差异不是参数调优层面的，而是执行范式层面的。
- **与 PIMANN 的关系**：论文明确指出 PIMANN 是正交工作（其关注点不同），这意味着 PIVOT 的“阈值引导协作过滤”在原理上可以与 PIMANN 类方案叠加，而非互斥替代，这一点为后续组合式优化留下了空间。
- **与 CPU 侧 RaBitQ / FAISS-IVF-RaBitQ 的关系**：PIVOT 复用了 RaBitQ 的量化思想与多位重排路径，其增量贡献集中在“把 1-bit 下界过滤搬到 PIM 并把选择逻辑改为阈值驱动”。这种“站在成熟量化方法肩上 + 重构执行路径”的路线，使其实验对比具有同源可比性，但也意味着其精度上限基本由 RaBitQ 决定，创新点主要在系统层而非算法层。
- **与 GPU/FPGA ANNS 的定位**：作者以平台不可直接比较为由未做对比，这在系统论文中可接受，但也使“PIM 相对其他近存/加速方案的性价比优势”这一关键问题未被回答。

## 10. 可复现性与工程透明度

- **优势**：数据集（SIFT1B、DEEP1B、MS MARCO10M、DEEP100M）均为公开基准；硬件为商用 UPMEM DIMM + 标准 Xeon 服务器，软件栈版本（UPMEM SDK 2025.1.0、Ubuntu 22.04.5、FAISS + AVX-512 + MKL）交代清楚；指标定义（端到端 QPS 的计入/不计入边界）明确，避免了系统论文常见的“计时口径含糊”问题。
- **不确定项**：文中未明确说明代码与配置专用内核的生成脚本是否开源；UPMEM 平台本身可获得性有限（需专用 DIMM 与 SDK），因此“可复现”更接近“原理可复现”，而非“开箱即复现”。
- **调参透明度**：β_ε、δ、μ_min、N_h、qb、FastFloat 尾数宽度等超参虽给出了选取流程与敏感性分析，但未给出所有数据集上的最终取值表，读者难以直接照搬配置。

## 11. 可延伸的研究方向（基于本文暴露的空白）

1. **在线/自适应阈值校准**：用运行时采样的幸存者统计动态修正 β_ε，替代一次性离线校准，以应对查询分布漂移与多租户混合负载。
2. **索引动态性**：本文假设静态索引，未讨论插入/删除/合并对残差直方图与阈值模型的影响；增量维护直方图（近似分位数摘要）是一个自然的后续问题。
3. **负载均衡**：DPU 扩展呈次线性，部分原因来自 IVF 列表大小不均；可结合更细粒度的列表切分或工作量感知的簇调度（与本文的“簇级过滤”天然衔接）。
4. **跨平台迁移验证**：将“算术轻内核 + 阈值过滤”原则移植到 HBM-PIM、GDDR6-AiM 或 GPU（把阈值过滤用于 GPU 上的 IVF 扫描），检验其普适性。
5. **与正交方案组合**：与 PIMANN 类工作、图索引（如 PIM 上的近邻图遍历）、或多比特量化（qb 更大的分级过滤）结合，探索“多级下界 + 逐级收紧阈值”的流水线。
6. **能效与成本建模**：补充 DPU 利用率、功耗、每查询能耗与 TCO 分析，回答“PIM 加速 ANNS 在数据中心是否经济”的问题。
7. **端到端系统集成**：将 PIVOT 嵌入真实向量数据库（含过滤条件、混合查询、副本与容错），评估在 RAG 类负载下的实际收益。

## 12. 综合评价

PIVOT 是一篇问题定位精准、方法自洽、验证扎实的系统/架构类论文。其核心贡献不在于提出新的量化算法，而在于**识别出“评估–内核错配”与“搜索范式错配”这两类被现有 PIM-ANNS 工作忽视的结构性矛盾，并给出一个统一的、可在真实商用 PIM 上落地的解决路径**：以 1-bit 量化 + FastFloat 把距离评估做成 PIM 友好的整数/位运算，以统计模型驱动的保守阈值把“分布式 top-k”替换为“无状态过滤”，再以专用内核与跨批次流水线榨取硬件效率。三级过滤（CPU 簇级 → PIM 向量级 → CPU 重排）的设计在概念上简洁，在实现上有明确的数据支撑（过滤掉 99% 以上向量），其“用阈值换状态”的思想对 GPU、近存计算乃至磁盘索引上的 ANNS 都有借鉴价值。

主要保留意见集中在三点：一是**基线对比的解释力**——DRIM-ANN 受 WRAM 与 PQ 配置约束，高召回区间的倍数优势不宜被过度解读为纯算法差距；二是**平台单一与规模边界**——仅在 UPMEM 上验证，且在小规模/低 nprobe 场景收益有限，普适性仍待检验；三是**成本维度缺失**——未报告能效与总机时，使“是否值得为 ANNS 部署 PIM”这一产业界最关心的问题仍悬而未决。

总体而言，本文在“PIM 原生 ANNS 执行路径”这一方向上给出了目前较为完整且有说服力的答案，其设计原则（算术轻、状态轻、可独立执行、全局控制留在 CPU）具备超出单一系统的指导意义。
