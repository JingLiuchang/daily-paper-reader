Abstract
Frontier multimodal language agents such as GPT-6 As-
tra have demonstrated strong capabilities in controlling
robots directly via low-level numerical actions without
high-level primitives. However, existing benchmarks report
only episode-level success rates, which show neither how
these agents succeed nor where they fail. In this paper, we
present a systematic action-level analysis of frontier agents
on direct robot control across 12 manipulation benchmarks.
We introduce AgentRoboCritic, an intent-grounded critique
framework in which the policy agent states a local intent
alongside each action, and a critic evaluates the action’s
outcome and failure mode against this intent. Our action-
level analysis demonstrates the promising capabilities of
frontier agents on direct robot control, including closed-
loop recovery from local execution failures, reliable seman-
tic grounding across diverse scenes, and strong zero-shot
manipulation without task-specific adaptation. It also iden-
tifies their current limitations, including task-relevant phys-
ical execution bottlenecks such as grasping and alignment,
and uneven recovery across failure modes. Finally, we val-
idate our critic on a 400-action human-annotated bench-
mark and release a dataset of 12,844 annotated actions
alongside a fine-tuned open-source critic, Muse-Glimmer-
30B, whose failure-mode accuracy rises from 32.58% to
74.24%, enabling low-cost action-level analysis.1

Recent advances in robot foundation models follow two
main paradigms: Vision-Language-Action models (VLAs),
which adapt Vision-Language Models (VLMs) to out-
put low-level robot actions, and World-Action Models
(WAMs), which build upon video-generation world mod-

Despite building upon existing foundation models,
both families still suffer from brittle out-of-distribution gen-
eralization [15, 44, 56] and limited long-horizon mem-
ory [12, 39]. Moreover, deploying VLAs and WAMs to
new downstream tasks typically requires task-specific fine-
tuning [6, 21, 35, 50], limiting their zero-shot adaptation.
Beyond these two paradigms, frontier multimodal lan-
guage agents such as GPT-6 Astra [34] offer a promising
alternative: they control robots directly via low-level nu-
merical actions without relying on high-level primitives,
show strong zero-shot generalization and working memory
in robotic manipulation [18, 20, 22, 55], and outperform
specialized VLAs and WAMs [20, 47, 55]. These results
demonstrate the vast potential of leveraging frontier lan-
guage model agents directly as generalist robot policies.
Existing evaluations assess these agents at the episode
level, with binary success rates or aggregate task scores that
show neither how an agent succeeds nor where it fails. In
this paper, we provide a systematic, fine-grained investiga-
tion into the capabilities and limitations of frontier agents
on direct robot control by analyzing their behavior at the
action level. Evaluating an individual action can be am-
biguous because robot manipulation is inherently multi-
modal [10, 16, 38]: since multiple distinct trajectories can
validly advance the same task, whether an action succeeds
depends on its intended sub-goal. We resolve this ambigu-
ity by letting the policy agent state a local intent alongside
each action, establishing a verifiable local contract for every
action (Figure 1(a)). Conditioned on the global task goal,
this local intent, and multi-view observations, our Agent-
RoboCritic framework determines whether each executed
action succeeded and assigns a specific failure mode to ev-
ery failed action. Using GPT-6 Astra as the critic, we anno-
tate episodes across 12 robot manipulation benchmarks for
further analysis.

ities and the current limitations of frontier agents on di-

2. Related Work
Frontier Agents as Robot Policies.
Language models
have been connected to robots through planning over pre-
trained skills [19]. Code-as-policy approaches generate pro-
grams that call perception and control APIs [17, 23, 41].
Both lines of work delegate execution to skills and con-
trol primitives. Recent studies investigate frontier multi-
modal language agents that generate numerical actions di-
rectly from observations [18, 20, 22, 55]. We explore the
potential of frontier agents in direct robot control, which
reflects their intrinsic embodied abilities disentangled from
those of the primitives.
Evaluation on Frontier Agents in Direct Robot Control.
A growing set of studies measures frontier agents acting as
the robot policy. Reports on GPT-6 Astra score it against
public policies on all 42 RoboDojo tasks [8, 55], on the
memory-dependent tasks of RoboMME [12, 20], on the
simulated RoboLab-120 pick-and-place suite [48], on real
bimanual desk tasks [36], and on visuo-tactile UniVTAC
and OpenViTac tasks [47]. Cross-model studies run several
frontier models through one shared harness, across the four
RoboColiseum tracks [18] and on physical arms for six Ro-
boDojo tasks, where capability is tracked over time [22].
GPT-GEAR probes depth, in-context learning and tactile
use, then scores GPT-6 Astra on five established bench-
marks and a new geometry-constrained suite [57].
The
open harness Embodied First Exam [43] exposes hundreds
of simulated tasks to coding agents and verifies outcomes
independently of what the agent reports.
These evalua-
tions assess behavior at the episode level via binary success

3. Method
To systematically understand the capabilities and current
limitations of frontier agents in physical manipulation, we
first formulate the paradigm of direct robot control (Sec-
tion 3.1) and then introduce AgentRoboCritic, our intent-
grounded failure attribution framework that diagnoses agent
execution at the granularity of individual actions (Sec-
tion 3.2).
3.1. Frontier Agents on Direct Robot Control
We define direct robot control as a setting in which a fron-
tier multimodal language agent directly generates numeri-
cal robot control commands from a global task instruction,
visual observations, and interaction history. Consider a ma-
nipulation episode governed by a task instruction G (e.g.,
“open the box, take out the eraser, and close the lid”) over
discrete decision turns t ∈{1, . . . , T}. At each turn t, given

Unlike specialized VLAs or WAMs, which require ad-

tuning or in-context demonstrations, and compare their per-

Intent-Grounded Critique and Failure Attribution.
Given each action record (G, gt, Ot), we employ GPT-6
Astra as an automated action-level critic to generate struc-
tured annotations (ˆyt, ˆmt, ˆet). To ensure physical rigor and
prevent hallucinated causes, our annotation protocol en-
forces three core design principles: (1) Contact-aware tem-
poral windows: Evaluating whether an action achieved its
local intent requires matching the observation window to
the physical semantics of gt. While reaching and align-
ment steps can be judged from action-boundary frames
(Opre
t , Opost
t
), gripper-closing actions require evidence of
stable capture and retention, which we provide via imme-
diate post-grasp lift frames Oaux
t . (2) Decoupling local va-
lidity from episode outcomes: An action is judged strictly
against its local intent gt and visible physical transition.
An early failed grasp that the agent subsequently recov-
ers from is still labeled as an action-level failure.
Con-
versely, a deliberate diagnostic test (e.g., slightly loosen-
ing the gripper to test stability) or an intentionally small
intermediate adjustment is labeled Achieved when it ful-
fills gt. (3) Evidence-bounded failure attribution: For ev-
ery action judged as Failed, the critic classifies the failure
into one of the seven failure modes illustrated in Figure 3
(GRASP, ALIGNMENT, INTERFERENCE, EFFECT, INCOM-
PLETE MOTION, CHOICE, or UNRESOLVED) and writes a
concise diagnostic note ˆet specifying the active arm, target
object, contact geometry, and observed failure timing. More
details are provided in Appendix A.

4. Experiments
We design our experimental evaluation to systematically
characterize both the capabilities and the current limita-
tions of frontier agents in direct robot control.
We as-
semble an evaluation suite of GPT-6 Astra rollouts in di-
rect robot control across 12 manipulation benchmarks: Ro-
boDojo [8], StationeryBench [36], Astranomy [48], UniV-
TAC [7], OpenViTac [45], ContactBench 1.0 [46], LIBERO-
MAX [56], Meta-World+ [26], DexJoCo [42], RoboW-
its [24], RoboTwin 2.0 [9], and YAMLab [5]. We then ana-
lyze this collection with our AgentRoboCritic framework.
We verify the reliability of its critic against human annota-
tions in Section 5.
Implementation Details. For seven benchmarks (LIBERO-
MAX, Meta-World+, DexJoCo, RoboWits, RoboTwin 2.0,
YAMLab, and ContactBench 1.0), we collect new GPT-6
Astra episodes, requiring a local intent alongside every ac-
tion and recording camera observations at action bound-
aries. For the remaining five benchmarks, we ingest re-
leased GPT-6 Astra evaluation traces through unified align-
ment adapters that pair the intent notes with pre- and post-
action frames. We compare frontier agents against represen-
tative VLAs and WAMs, including π0.5 [35] and InternW0-
∆[27], under the same zero-shot setting without task-
specific fine-tuning. More implementation details are pro-
vided in Appendix B.
4.1. Capabilities and Promise of Frontier Agents
We first examine what frontier agents already do well in
direct robot control and why this paradigm holds strong
promise for generalist manipulation. Figure 4 summarizes
the action-level failure distributions across all evaluated
benchmarks, revealing that while failure patterns vary with
task structure and concentrate primarily in low-level physi-
cal grasping (GRASP), semantic selection errors (CHOICE)
remain remarkably rare. Building on our action-level cri-
tique and zero-shot policy evaluations, we highlight three
core strengths of frontier agents: closed-loop recovery from
local execution failures, reliable semantic grounding across
diverse scenes, and strong zero-shot manipulation without
task-specific adaptation.
Closed-Loop Recovery from Local Execution Failures.
A classic bottleneck of imitation-trained robot policies is
covariate shift [37], where a single execution error pushes
the robot outside the demonstration distribution and subse-
quent errors compound until the episode fails. Our action-
level annotations reveal that frontier agents in direct control
behave differently, recovering from local failures and still
completing the task. As shown in Figure 5(a), 49.8% of all
successful episodes contain at least one local failure, show-
ing that half of the successes are reached through recov-
ery. Episodes with one or two local failures still succeed in
40.3% of cases, compared to 75.1% for failure-free episodes
(Figure 5(b)), indicating that frontier agents complete a sub-
stantial share of tasks despite local failures. These results
show that frontier agents tolerate and correct their own exe-
cution errors.

We further quantify the failure recovery dynamics of
frontier agents on direct robot control. We analyze failed
actions across the 12 benchmarks and count a failure as re-
covered when a subsequent action in the same episode ver-
ifiably resolves it, such as a regrasp after which the object
rises with the gripper. In Figure 5(c), 38.9% of the ana-
lyzed failures are recovered within 10 actions and 57.7%
by the end of the episode, showing that frontier agents re-
solve more than half of their own failures. Figure 5(d) fur-
ther shows that benchmarks with a higher recovery rate also
reach a higher official success rate among the episodes that
contain a local failure, with a Pearson correlation of 0.81,
indicating that failure recovery is closely associated with
task success in direct robot control. This demonstrates that
frontier agents can act as closed-loop policies with promis-
ing failure recovery ability (Appendix C).
Reliable Semantic Grounding Across Diverse Scenes.
Specialized VLAs and WAMs remain vulnerable to vi-
sual perturbations, camera shifts, and spatial rearrange-
ments, often suffering steep performance drops on robust-
ness suites such as LIBERO-Plus, LIBERO-MAX, and
VLATest [15, 44, 56]. Our action-level critique highlights a
clear contrast for frontier agents. A failed action is labeled
CHOICE when its execution contradicts the object, order or
category stated in the local intent. As shown in Figure 4,
CHOICE accounts for 0.2% of all failed actions across the
12 benchmarks and for at most 3.3% on any single bench-
mark. Even when confronted with novel object instances
and visual distractors, frontier agents act on the object, or-
der and category stated in their local intent, demonstrating
reliable semantic grounding in direct robot control.
Strong Zero-Shot Manipulation.
Achieving zero-shot
generalization to unseen manipulation tasks and environ-
ments without in-domain demonstrations or task-specific
adaptation has been a long-standing goal in robot learn-
ing [6, 30, 31, 60]. However, existing VLAs and WAMs, in-
cluding recent generalist policies such as π0.5 [35], typically
struggle when deployed zero-shot outside their training dis-
tribution and require task-specific fine-tuning to achieve
reliable control.
As shown in Figure 6, frontier multi-
modal language agents such as GPT-6 Astra achieve strong
zero-shot success rates across diverse manipulation bench-
marks directly out of the box, substantially outperforming
unadapted VLA and WAM baselines. Moreover, frontier
agents achieve this manipulation capability while preserv-
ing their general-purpose language reasoning and multi-
modal understanding within a single unified model.
By
contrast, training or adapting VLAs on domain-specific
robot trajectories frequently degrades the pretrained VLM
backbone’s general visuo-linguistic reasoning and conver-
sational capabilities [49, 58, 59].

4.3. Fine-Grained Analysis of Grasp Failures
GRASP is the most frequent failure mode in direct robot
control (Figure 4). To locate the point at which a grasp fails,
the critic assigns every GRASP failure a sub-category that
records the contact error or the moment of loss. Figure 7(b)
reports their shares across all 12 benchmarks.
Grasps Fail at Closure. Three in five GRASP failures oc-
cur as the gripper closes, before the object is held, and only
one in five occurs after capture. At closure, the gripper most
frequently pinches only a rim, tip, or edge of the object, or
closes beside or above it. In each of these cases the agent
has selected the correct object and brought the gripper to
it, and the grasp fails due to a small offset in depth or lat-
eral position. This demonstrates that the grasping bottle-
neck of frontier agents is the fine 3D localization of the
gripper relative to the object. Closure is also the leading
stage on every benchmark with more than 100 GRASP fail-
ures (Appendix D), indicating that higher spatial precision
is the most direct path to more reliable direct robot control.
Failures After Capture. Once an object is captured, han-
dover and release account for only 1.5% of GRASP failures
and most losses occur during carrying, showing that the re-
maining risk lies in transport. A further 9.5% of GRASP
failures are actions issued with an already empty gripper, in
which the agent continues to lift or carry an object it has
lost. This shows that frontier agents can miss a lost object
in their observations, and indicates that an action-level critic
can serve as an online monitor that reports the loss at the ac-
tion where it occurs.

Human Evaluation of Annotated Data. We employ GPT-
6 Astra as the critic for all action-level annotations analyzed
in this paper and verify these annotations against human la-
bels. GPT-6 Astra achieves the highest accuracy among all
evaluated critics on the action outcome, the failure mode,
and Overall Accuracy. The annotators further re-inspect ev-
ery action on which GPT-6 Astra differs from their initial
label. They accept its critique in most of these cases, which
involve compound failures within a single action, such as
a shallow closure (GRASP) that simultaneously tips the ob-
ject away (ALIGNMENT), where the human annotator and
the critic each identify one of the two valid failure modes.
With the accepted critiques counted as correct, its agree-
ment with the annotators exceeds 90% on both outcome and
failure mode, demonstrating that GPT-6 Astra is a reliable
critic for action-level analysis.
Ablation on Local Intent. We withhold the local intent
gt and give GPT-6 Astra only the task goal and the obser-
vations, i.e., C(G, Ot). Both outcome accuracy and failure-
mode accuracy drop sharply, to the lowest values in Table 1.
Without the local intent, GPT-6 Astra labels most actions
UNVERIFIABLE, since the same motion is an incomplete
reach, a missed alignment, or a failed grasp depending on
its intended result. This confirms that relying solely on the
global goal leaves individual action evaluation ambiguous,
preventing the critic from reliably determining action suc-
cess. Local intent is therefore essential to make action-level
critique well-posed.
Comparison of Critic Models. We compare GPT-6 As-
tra against five other proprietary models (GPT-6.1 Sol [32],
GPT-6.1 Terra [33], Claude Fable 5.2 [2], Claude Opus
5.5 [3], and Claude Sonnet 5.5 [4]) and four open-
source models (Kimi K3.1 Pro [28], DeepSeek-V4.1-
Flash-1017 [13], GLM-5.3-Flash [52], and Muse-Glimmer-
30B [1]). The gap between GPT-6 Astra and every other
proprietary model is larger on failure-mode accuracy than
on outcome accuracy, and the open-source models with-
out fine-tuning misidentify the failure mode of most failed
actions. This demonstrates that judging the success of an
action is within reach of current frontier models, while at-
tributing a failure to its physical cause is the harder problem
and the one that separates critics. Within both the GPT and
Claude families, a higher model tier gives a more accurate
critic, indicating that action-level critique benefits directly
from stronger frontier models.
Open-Source Critic VLM. To make action-level critique
available without proprietary APIs, we fine-tune the open-
source Muse-Glimmer-30B [1] on our dataset of 12,844 an-
notated actions, separated from the test set at the episode
level.
We provide training details in Appendix F. Fine-
tuning raises its failure-mode accuracy from 32.58% to
74.24% and its Overall Accuracy from 34.75% to 67.75%.
The fine-tuned critic outperforms every other open-source
model on every metric, exceeds every proprietary model
except GPT-6 Astra on failure-mode accuracy, and has the
lowest inference cost among all critics, over 30× lower than
GPT-6 Astra. This demonstrates that the action-level cri-
tique of a frontier model transfers to an open-source VLM,
enabling low-cost critique of large trajectory collections.
Moreover, these results validate the effectiveness of our
action-level critique dataset for training open-source critics
competitive with frontier proprietary models.

6. Conclusion
We present a systematic action-level analysis of fron-
tier agents on direct robot control, enabled by Agent-
RoboCritic, an intent-grounded critique framework veri-
fied against human annotations. Our analysis across 12 ma-
nipulation benchmarks demonstrates the promising capabil-
ities of frontier agents, including closed-loop recovery from
local execution failures, reliable semantic grounding across
diverse scenes, and strong zero-shot manipulation without
task-specific adaptation. It also identifies their current lim-
itations, including task-relevant physical execution bottle-
necks such as grasping and alignment, and uneven recovery
across failure modes. We release our annotated dataset and
a fine-tuned critic VLM to support future research on fron-
tier agents as generalist robot policies via direct control.

A. Action-Level Failure Modes and Annotation Format
We define the action-level failure modes and the grasp sub-categories used in the paper as follows.
Action-level failure modes.
For every failed action, the critic assigns one failure mode.
GRASP. The object is not acquired or not retained, which defeats the local intent. For example, the bowl remains on the
table during an intended lift.
ALIGNMENT. A held object or an intended contact misses its local target relation. For example, a plug stays beside its
socket.
INTERFERENCE. Unintended motion, collision or displacement defeats the local intent. For example, an approaching
forearm knocks over a neighboring stack.
EFFECT. A tool stays under control but does not produce its stated effect. For example, a held scraping tool leaves the
target unchanged despite contact.
INCOMPLETE MOTION. A commanded movement, opening or reset remains incomplete and no more specific failure
mode applies. Rejected executions and executions with an uncertain result are not INCOMPLETE MOTION.
CHOICE. The execution contradicts the object, order or category stated in the local intent. For example, pressing key 7
when the local intent requests key 3 is CHOICE, whereas pressing key 7 as the local intent requests is not, even when the task
requires key 3.
UNRESOLVED. The action fails, but its failure mode cannot be established. An action with an unknown outcome is
UNVERIFIABLE, not UNRESOLVED.
The codebook in Section J gives a definition, an explanation, boundary rules and an example for each failure mode. The
boundary rules separate neighboring failure modes, for example GRASP for an object that is no longer held and ALIGNMENT
for a held object that stays offset from its target, or ALIGNMENT for a tool that misses its contact target and EFFECT for a
tool that makes contact without its stated effect.
In the release, PARTIAL is stored as partial_or_unconfirmed and FAILED as not_achieved. NOT APPLICABLE
marks an entry that is not an executed action, and it is distinct from UNVERIFIABLE, which marks an executed action whose
result cannot be judged.
Grasp sub-categories.
Each GRASP failure receives a sub-category that describes the contact error or the moment of loss
(Table 2). The sub-categories are grouped as in Figure 7(b) into failures at closure, losses after capture, actions issued with an
already empty gripper, and failed grasps whose contact cannot be resolved. A sub-category is assigned only after the action
is judged as failed.
Output format.
For each action, the critic outputs the outcome, the failure mode, the grasp sub-category and a short reason.
The last three are empty when the action does not fail. Each annotation also stores its source identifiers and file hashes, the
local intent, the commanded action and its execution status, the correspondence between cameras, frames and time, and the
inputs shown to the critic.
B. Implementation Details of AgentRoboCritic
Critique procedure.
We define one decision procedure for all benchmarks, and a benchmark-specific adapter converts
each source into its input format. For action-level critique, the critic and the human annotators receive the same fixed input
for one action and do not see the official outcome of the episode. Besides the task goal, the local intent and the frames of Ot,
this input contains the commanded action and its execution status. Automatic validation checks the format and the source
links of every annotation, and correctness is assessed against human labels (Section 5). Figure 8 shows the system prompt of
the critic, Section J gives the codebook that follows it, and Figure 9 shows the user prompt of each request.

Failed actions.
We analyze all 12,163 failed actions with an annotated failure mode in the 1,989 officially graded episodes
that contain at least one, across the 12 benchmarks. The reported shares give every failed action equal weight. RoboDojo
contributes 9,923 of the failed actions, and Table 4 lists every benchmark separately.
Recovery criterion.
For each failed action, we follow the saved trajectory forward and record the first later action that
shows a verified recovery. A recovery is either a repair of the original sub-goal or progress along a different route that
bypasses it. After a missed grasp, a regrasp counts once the object visibly rises with the gripper. In one trajectory, after
failing to grasp a ball inside a cup, the agent grasps and lifts the cup with the ball inside, which prepares the pour and counts
as a recovery along a different route. A later action that only achieves its own stated intent, such as lifting an empty gripper
after a missed grasp, does not count. The sub-goal to be recovered is taken from the local intent of the failed action and the
task instruction. A regrasp of the same object with either hand restores possession, whereas placing the object on the table
does not satisfy a required hand-to-hand transfer. Each failed action is assessed separately, and when consecutive actions
fail on the same sub-goal, such as two missed grasps of one object, the later action that achieves this sub-goal recovers both
failures. The distance to a recovery is the number of later actions up to and including the action that confirms it. A recovery
is counted even if the episode later fails. Of the 12,163 failures, 6,435 are repaired directly and 589 are bypassed along a
different route, and the remaining 5,139 are not recovered. All 12,163 remain in the denominator, including the failures at
the last action of an episode.
Robustness of the recovery rate.
Giving every episode equal weight, by averaging the recovered share of failures within
each episode, raises the share recovered by the end of the episode from 57.7% to 60.7%. When only the first failed action of
each episode is analyzed, 76.2% of these failures are recovered by the end of the episode. This shows that the recovery rate
holds under different weightings of failures.

F. Critic Training Details
Training data.
The critic dataset draws on 2,027 episodes. We keep executed actions with an achieved or failed outcome
and complete pre- and post-action observations, and sample one achieved action for every three failed actions. The splits are
separated at the episode level, and no episode contributes actions to more than one split (Table 9). The 400 human-annotated
actions used in Table 1 are drawn from the test split.
Input and target.
Each sample follows the critic formulation of Section 3.2. The input contains the task goal G, the local
intent gt and the ordered camera frames of Ot, preceded by a system prompt with the complete definitions of the outcome
and failure-mode categories. The target is a JSON object with the outcome, the failure mode, the grasp sub-category (Table 2)
and a short failure reason. The last three fields are null for an achieved action.
Fine-tuning.
We fine-tune Muse-Glimmer-30B with a LoRA adapter on the Fireworks AI platform, keeping the base
weights frozen. Table 10 lists the key hyperparameters.
Inference.
The fine-tuned critic decodes at temperature 0 with at most 1,024 output tokens. An output that is not valid
JSON counts as incorrect.

H.2. Effect of Local Intent on Task Success
Our policy rollouts require a local intent alongside every action (Section 3.2). We investigate whether this requirement
changes task performance by comparing our GPT-6 Astra episodes with the official GPT-6 Astra runs published by the
Embodied First Exam, which do not require a local intent, on the 76 Standard instances that both cover. GPT-6 Astra succeeds
on 42 of the 76 instances (55.3%) both with and without the local intent requirement. This shows that stating a local intent
alongside every action has little effect on the success rate of GPT-6 Astra, and that the local intents that AgentRoboCritic
relies on come at little cost to policy performance.
H.3. Zero-Shot Comparison on More Tasks
We extend the zero-shot comparison of Figure 6 to matched tasks from five suites of the Embodied First Exam, on which
both GPT-6 Astra and π0.5 have a scored episode. Both policies run each task instance without task-specific fine-tuning or
demonstrations, and the grader of each benchmark scores the episode. π0.5 sends a low-level action to the simulator after
every observation, and GPT-6 Astra issues numerical actions through tool calls (Section 3.1). Figure 16 shows the success
rates of both policies. GPT-6 Astra outperforms π0.5 on every suite, and every task that π0.5 completes is also completed by
GPT-6 Astra. This further supports the zero-shot advantage of frontier agents shown in Figure 6.

I. Verification Against Critic Self-Preference Bias
GPT-6 Astra serves as both the control policy and the primary critic in our study. We therefore examine whether using the
same model introduces self-preference bias, and whether fine-tuning on our dataset transfers such bias to the open-source
critic.
Frontier critics.
A critic biased toward its own policy would systematically label failed actions as ACHIEVED. Table 13
counts these errors for each critic on the human-annotated test set. GPT-6 Astra labels only 19 of the 264 human-labeled
failed actions as ACHIEVED, the fewest among all evaluated critics. Claude Fable 5.2, a frontier model from a different
model family, reaches a similar outcome accuracy of 78.25%, compared to 79.25% for GPT-6 Astra (Table 1). This shows
that GPT-6 Astra is the strictest evaluator of its own failed actions, and that the high agreement with human labels holds
across model families.
Fine-tuned critic.
Muse-Glimmer-30B is fine-tuned on our dataset of actions annotated by GPT-6 Astra and scored against
the human labels, on test episodes that are kept out of training (Sections 5 and F). Fine-tuning halves the failed actions that
it labels as ACHIEVED (Table 13) and raises its failure-mode accuracy above every critic except GPT-6 Astra (Table 1). This
shows that fine-tuning on our dataset makes the critic stricter on failed actions and more accurate on the human-annotated
benchmark.

J. Critic Codebook
The codebook below follows the system prompt of Figure 8 in every critic request. It gives a label, a definition, an explanation,
a boundary rule and an example for each failure mode, and a label and a definition for each GRASP sub-category. Table 14
lists the names used in this paper for its identifiers.
Codebook
M1 Acquisition / retention. Definition. The required object is not captured, is lost, or is already absent from the
manipulating hand. Explanation. Use when the current local manipulation fails because the required object is not
captured, slips out, is dislodged, or was already absent from the hand before the call. Identify the object, arm, contact
geometry, and stage of loss to the extent supported by the images. Boundary. Add an S1-S14 subcategory. Distinguish
a new loss from an already-empty follow-up (S11), and retain S12 when non-retention is visible but the contact error
is not. A deliberate release or a successful diagnostic test is not automatically an M1 failure. An object still held but
offset from its target is usually M2. Example. The note asks to grasp the coin, but the jaws close above its top and the
subsequent lift leaves it on the table: M1 with S1.
M2 Targeting / engagement. Definition. A held object or commanded contact remains offset, tilted, or outside its
intended target. Explanation. Use when a held object or intended contact misses the current local target because it
remains offset, misoriented, too shallow, or outside the intended contact region. Describe the visible target relation
rather than attributing the error to an unobserved controller or perception defect. Boundary. The immediate problem is
targeting or engagement, not missing possession (M1). A major unintended excursion or collision can be M3. If contact
is established but the intended tool effect is absent, consider M4. A small intermediate approach is not a failed insertion
unless insertion was the current stated goal. Example. The note requests inserting the retained plug, but the plug tip
stays beside the socket opening at the end of the call.
M3 Motion / interference. Definition. The current call causes a major unintended excursion, collision, or object
displacement. Explanation. Use when the current call produces a major unintended motion, collision, or displacement
that defeats its local goal. Record which hand or object moved, what it contacted, and the unwanted change; do not
label every incidental touch a collision failure. Boundary. An ordinary positional miss can be M2. When closure pushes
the intended object away and thereby prevents capture, the more specific acquisition description is M1/S4. A later call
should not inherit M3 solely because an earlier call disturbed the scene. Example. During a requested approach, the
forearm strikes a neighboring stack and knocks several blocks off their supports.
M4 Task-effect failure. Definition. A retained tool/object fails to produce its intended pour, strike, or other task effect.
Explanation. Use when the relevant object or tool remains retained but the call does not produce its stated physical
effect, such as a pour, strike, scrape, or target-state change. Identify the absent effect and the visible interaction that
supports the judgment. Boundary. If the hand is empty, use M1. If the tool visibly misses its contact target, M2 may be
the more specific mechanism. If the requested movement or opening itself never completes, consider M5. Do not infer
an absent effect that the released observations cannot show. Example. The hand retains the container and executes the
intended tilt, but no contents enter the receiving bowl despite the note requesting a pour into it.
M5 Incomplete motion / reset. Definition. A movement, opening, withdrawal, or return is incomplete without a more
specific mechanism. Explanation. Use when a requested movement, opening, withdrawal, reset, or return remains
incomplete and no more specific acquisition, targeting, interference, or task-effect mechanism is supported. Describe
the commanded change and the visible residual state. Boundary. This code requires a demonstrably unachieved local
goal; an intentionally incremental movement or a truncated, unobservable result may instead be partial/unconfirmed or
unverifiable. Rejected commands are not executed-action M5 failures. Do not infer why the mechanism failed to move.
Example. The note requests opening the gripper and releasing the object, but the fingers remain closed and the object
remains clamped at the supported endpoint.
M6 Unresolved mechanism. Definition. The local goal fails, but the available evidence does not identify a more
specific mechanism. Explanation. Use when the current local goal is demonstrably not achieved but the available
evidence does not identify a more specific action mechanism. State the failed local result, identify the missing or
occluded evidence, and avoid choosing a visually unsupported mechanical explanation. Boundary. M6 is different from
an unverifiable outcome: failure itself must be supported. If non-retention is established but its contact geometry is
unclear, use M1/S12 rather than M6. A missing original note is not by itself evidence of a failed local goal. Example.
26


The visible local target state is unchanged after an intended manipulation, but the relevant interaction is occluded and
the evidence cannot distinguish incomplete motion from a failed task effect.
M7 Wrong local choice. Definition. The stated local selection or relation itself is unsuccessful; a separate task mis-
match is not sufficient. Explanation. Use when the call fails its own stated selection, ordering, or categorical-relation
goal. The identifying issue is which object, answer, or relation was enacted, even if the low-level movement completed
normally. The original local note and the relevant reference must support that discrepancy. Boundary. A mismatch with
the overall task is not sufficient if the action faithfully executes its own note; this does not by itself establish a failed local
action. Distinguish choosing the wrong named target from a continuous targeting miss (M2). M7 remains unassessed
in the preserved RoboDojo-Precision baseline. Example. The note requests pressing the key labeled 3, but the robot
presses the clearly labeled 7 key. If the note itself requests 7 and the robot presses 7, that is not M7 merely because the
overall task required 3.
S1 Jaws close above object. Fingers close over the top rather than around the body; a vertical miss must be visible.
S2 Jaws close beside / ahead / behind. The object is outside the opposing jaw gap; record the visible lateral or depth
offset.
S3 Only rim / tip / edge pinched. Only a shallow rim, tip, edge, or tapered surface is caught; name the contact region.
S4 Closure pushes / tips object away. The acquiring hand pushes, rolls, or tips the object instead of enclosing it.
S5 Support / another object caught. A rest, fixture, support, or other object is caught instead of the intended target.
S6 Receiving hand misses transfer. The receiving jaws fail to secure the transferred object; donor timing is not
assumed.
S7 Slip during initial lift. After transient capture, the object separates during the first lift; it did leave its support.
S8 Slip during carry / wrist turn. An object that previously moved with the hand separates during carrying or turning.
S9 Contact pulls object out. Visible contact with a surface, target, obstacle, or other arm dislodges a held object.
S10 Opening before support. The gripper opens before a secure support is established and the object falls.
S11 Already-empty follow-up motion. The hand was already empty before this call; it is a downstream motion, not a
new loss.
S12 Contact error not visible. Non-retention is established, but offset, shallow contact, and transient slip cannot be
resolved.
S13 Wrong jaw faces / axis. The jaw orientation visibly fails to oppose the faces or axis that must be pinched.
S14 Inside-hole nut grasp fails. Visible contact inside a nut bore fails to lift the nut; internal contact must be observed.
