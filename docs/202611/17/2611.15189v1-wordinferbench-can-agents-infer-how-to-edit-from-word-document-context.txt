Abstract 

Document editing is among the most com-mon knowledge-work tasks, yet existing bench-marks for evaluating autonomous agents on Word document editing provide fully specified attribute-modification instructions. They do not evaluate agents’ ability to infer the appropriate attributes from document context, a capabil-ity essential in real-world editing where users expect consistency without spelling out every attribute. We introduce WordInferBench , a benchmark comprising 280 base document-editing instances, each paired with three instruc-tion conditions: descriptive (the instruction ex-plicitly lists every attribute change), referential 

(the instruction points to another object as an exemplar), and inferential (the agent must ex-amine document context to infer what attributes to apply). To evaluate contextual attribute in-ference, each base instance is constructed so that the target formatting is recoverable from an in-document exemplar. The instances are de-rived from real Word documents collected from Common Crawl and cover 13 object types and 81 attributes. We evaluate six recent coding-agent systems and find that the best-performing evaluated system, Claude Code with Opus 4.6, achieves a 62.9% task-level pass rate on de-scriptive variants but only 40.7% on inferen-tial variants, indicating that current systems complete tasks less reliably when the required formatting changes must be determined from document context.

Together, these conditions evaluate how agents perform formatting tasks under different informa-tion conditions. In descriptive tasks, the agent must parse the specifications and execute the attribute changes correctly. In referential tasks, the agent must determine which attributes are relevant for consistency and ensure complete attribute cover-age. In inferential tasks, the agent must explore the document context and infer both which existing object serves as the formatting reference and which attributes need to be modified. For construction, we use real Word documents from Common Crawl (Common Crawl Founda-tion, 2026) as reference documents and reset the attributes of a selected object to their defaults to produce the input document. The object’s original attributes serve as the ground truth. We require each document to contain at least one other same-type object with an identical formatting signature, ensuring that the original formatting is exactly re-coverable from an in-document exemplar. This de-sign limits inferential tasks to same-type exemplar discovery, providing agents with a relatively simple inference setting. Human verification further con-firms that the intended formatting is inferable from context and that the reference is unambiguous. We evaluate six recent coding-agent systems, in-cluding Claude Code with Opus 4.6 and Sonnet 4.6, Codex with GPT-5.5 and GPT-5.4, Claude Code with GLM 5.2, and Kimi CLI with Kimi K2.6 (An-thropic, 2026a,b,c; OpenAI, 2025, 2026b,a; Z.ai, 2026; Moonshot AI, 2026a,b), in sandboxed Win-dows environments. Our contributions are as follows: • We propose WordInferBench, a benchmark with three paired instruction conditions: ex-plicit specification, reference-based consis-tency, and context-driven inference. • Our benchmark covers 13 object types and 81 attributes, spanning paragraphs, tables, head-ers/footers, and various shape types. • We evaluate six recent coding-agent systems, showing that format execution remains diffi-cult for complex objects, and contextual ex-emplar identification is challenging.

2.2 Document Editing 

A related line of work studies automated docu-ment editing driven by natural-language instruc-tions. DocEdit-v2 (Suri et al., 2024) grounds edit requests to regions in document images and gen-erates editing commands via a multimodal LLM. Agent-DocEdit (Wu et al., 2024) localizes target elements in content-rich documents and generates edit programs through pre-defined APIs. LEDGER (Wang et al., 2026) uses dependency-aware graphs and graph-guided retrieval for semantically consis-tent edits across long-document paragraphs. These works address semantic or layout editing, target grounding, and cross-section consistency un-der high-level instructions. They do not evaluate exact recovery of native Word formatting attributes from in-document exemplars, which is the focus of our benchmark. 

2.3 Benchmarks for Other Office Applications 

Benchmarks have also been developed for other Office applications. In the presentation do-main, SlidesGen-Bench (Yang et al., 2026) eval-uates automated slide generation across content, aesthetics, and editability, while PresentBench (Chen et al., 2026) provides instance-specific, fine-grained rubric evaluation. In the spreadsheet do-main, FINCH (also introduced as FinWorkBench) (Dong et al., 2026) targets enterprise finance and ac-counting workflows. SpreadsheetBench (Ma et al., 2024) collects real user questions from online fo-rums and tests spreadsheet manipulation. Spreadsheet benchmarks often require agents to inspect file structure before acting. However, exist-ing Word benchmarks do not specifically evaluate tasks requiring target formatting to be inferred from within the document. WordInferBench evaluates this capability through context-driven formatting tasks. 

3 Benchmark Construction 

3.1 Task Formulation 

In WordInferBench, each base instance consists of an input document, a held-out reference document, and three editing-instruction variants. The agent 3receives only the input document and one instruc-tion; the reference document is not exposed and is used solely for scoring. The instruction requires modifying a target object in the input document to match its state in the reference document. Tasks are divided into three instruction speci-ficity conditions based on the amount of informa-tion provided in the instruction: • Descriptive : The instruction describes the specific attribute changes in detail. The agent only needs to understand and execute each change. • Referential : The instruction specifies another object of the same type in the document as a reference, without describing the specific changes. The agent must read the reference object’s attributes and apply them to the target. • Inferential : The instruction only identifies the target object, providing no reference or specific description. The agent must browse the document context and infer what changes should be made. 

3.2 Construction Method 

We collect real Word documents from Common Crawl (Common Crawl Foundation, 2026) as refer-ence documents. These documents originate from heterogeneous web sources and contain varied ty-pographic structures. We reset the attributes of a selected object in a copy of a real document to con-struct the input document, while the object’s orig-inal attributes define the evaluation ground truth. We select objects for which the context contains at least one exactly matching same-type exemplar. If an object’s formatting appears only once in the document, its original attributes are not recoverable from context after resetting, so it is ineligible. To filter documents and objects that can pro-duce valid tasks, we first parse the XML of Word documents to identify their object types, retain doc-uments containing at least two objects of a given type, and sample approximately 1,000 documents per category as candidates. For each candidate document, we extract the original attributes of all objects via Word COM. We then reset each candi-date object independently in a separate document copy and compute the difference between its reset and original states. On this basis, we pair objects of the same type within the same document that share identical for-matting but differ in content, forming (target, ref-erence) pairs. This construction scopes our infer-ential tasks to same-type exemplar discovery and exact attribute restoration. Exact matching ensures that the original formatting is recoverable from at least one in-document exemplar and enables deter-ministic evaluation through exact attribute compar-ison. We further use human verification to confirm that the intended formatting is inferable from con-text and that the reference answer is unambiguous (Section 3.4). While real-world scenarios may also involve inferring from multiple objects or coordi-nating changes across multiple targets, these are beyond the current scope. To cover as many at-tributes as possible, we employ a greedy set-cover algorithm to sample from all candidate pairs, maxi-mizing the variety of modified attributes covered: iteratively selecting the object whose attribute dif-ferences cover the most uncovered attributes, break-ing ties by preferring objects that cover more low-frequency attributes, and limiting each document to contributing at most one object per type. We use GPT-5.5 to generate three instruction variants for each base instance (see Appendix C for full prompts). For descriptive instructions, we first compute the target object’s structured attribute diff, converting all raw COM values to human-readable representations, e.g., enum constants to names (fill type 3 becomes "Gradient" ). This structured diff is fed to the LLM to rewrite all changes as natural-language instructions, followed by a second refine-ment pass for conciseness. For referential instruc-tions, the LLM generates instructions requiring format consistency between target and exemplar objects based solely on their positional information (type, page number, content), without specifying attributes. Inferential instructions provide only the target object’s positional information, requiring the agent to infer the modification plan from document context.

Documents are rendered as page screenshots and an LLM detects face photographs; documents containing faces are entirely removed. 3.4 Human Verification 

We recruit 9 annotators divided into 3 groups of 3 to verify all samples (see Appendix E for the detailed annotation protocol). Each group annotates all sam-ples, where each sample is assigned to exactly one instruction type within that group. The assignment is rotated across groups so that every sample’s three instruction types are each verified by one group. To verify inferability and answer uniqueness, annota-tors first complete the edit using only the input document and instruction, without access to the held-out reference. They then inspect the reference and rate instruction clarity, reference correctness, and agreement between their independently pro-duced output and the reference. This blind-first procedure provides an independent check that the intended formatting is inferable from context and that the reference answer is unambiguous. Annota-tors also check for PII. A sample is removed if all 3 annotators in at least one group reach consensus that it is problematic on any dimension. Cases with non-unanimous judgments are manually reviewed based on the annotators’ feedback, and the instruc-tion or reference is revised when necessary. After this process, 280 of the original 312 candidates are retained (89.7%). 

3.5 Statistics 

The benchmark contains 280 base editing instances, each paired with descriptive, referential, and in-ferential instructions, yielding 840 instruction-conditioned variants across 272 distinct documents. It covers 81 attributes across 13 object types: plain paragraph, listing, hyperlink, table of contents, ta-ble, header, footer, autoshape, textbox, picture, chart, SmartArt, and WordArt (see Appendix B for details). These attributes include character and paragraph formatting, hyperlinks, table borders and cell formatting, shape fill, line, shadow, 3D, glow, 5reflection, and other object-specific properties. The statistics of the 280 inferential variants high-light why this setting requires more than local at-tribute copying. In 42.9% of inferential variants, the selected matching exemplar is on a different page from the target, so the relevant evidence can extend beyond the target page. Documents also contain many same-type distractors: each instance contains a median of 11.5 same-type objects, with a median non-matching ratio of 80.9%. Thus, in-ferential variants require agents to decide which contextual objects are relevant before determining the attributes to edit. 

4 Results and Analysis 

4.1 Experimental Setup 

We evaluate the benchmark on six coding-agent systems: Claude Code (Anthropic, 2026a) with Opus 4.6 (Anthropic, 2026b), Claude Code with Sonnet 4.6 (Anthropic, 2026c), Codex (OpenAI, 2025) with GPT-5.5 (OpenAI, 2026b), Codex with GPT-5.4 (OpenAI, 2026a), Claude Code with GLM 5.2 (Z.ai, 2026), and Kimi CLI (Moonshot AI, 2026a) with Kimi K2.6 (Moonshot AI, 2026b) (see Appendix A for exact versions and environment configuration). Each system runs in an isolated Windows sandbox. A fresh sandbox is provisioned for each variant run; no execution history, cache, or workspace state is shared between runs, including among variants of the same base instance. Each system autonomously chooses its editing approach and executes modifications; the output document is scored against the held-out reference through Word COM. We use two metrics: Task-Level Pass Rate ,where a task passes only when all evaluated changed attributes of the target object are correct; and Attribute-Level Accuracy , which measures the fraction of target attributes requiring modifica-tion that are correctly updated in each task, macro-averaged across tasks. The evaluator compares the target attributes that differ between the input and reference documents. Both the reference and prediction documents are processed by the same COM-based extraction pipeline, which normalizes attribute values into canonical string representa-tions with standardized units, maps COM enum constants to human-readable names, and treats sen-tinel values such as wdUndefined as absent. Be-cause extraction reads the effective property values resolved by Word’s rendering engine, attributes set via style inheritance and direct formatting are com-pared equivalently. Prediction files that cannot be opened are scored as zero. Beyond target correctness, we separately evalu-ate whether model outputs preserve non-target doc-ument content. Target correctness and non-target preservation are scored independently. The preser-vation evaluator compares supported non-target ob-jects and their contents and formatting between the reference and model-generated documents. An output passes the preservation check only when no differences are detected in any evaluated non-target object. 

4.2 Evaluation Results 

Table 2 presents the overall results. All evaluated agent systems obtain lower pass rates on inferential variants than on descriptive and referential variants. Even the best-performing system, Claude Code with Opus 4.6, achieves only a 40.7% pass rate on inferential variants. Notably, several agents achieve higher pass rates on referential tasks than on descriptive tasks, though this pattern does not hold uniformly across all agents. One possible explanation is that pro-grammatically copying attributes from a refer-ence object can be simpler than parsing detailed natural-language attribute specifications, which re-quires correctly interpreting human-readable at-tribute names and values and mapping them to exact API parameters. The inconsistency across agents may reflect differences in their natural-language instruction following and code generation capabilities. Figure 3 shows average task-level pass rates by object type. Tables have the lowest pass rates across all agents, as they require modifying at-tributes across multiple cells, where each cell con-tains border properties, shading, vertical alignment, and text formatting, creating a deep attribute hi-erarchy that agents struggle to handle completely. 4.3 Sources of Difficulty in Inferential Editing 

To probe different sources of difficulty, we con-duct two diagnostic experiments using Codex with GPT-5.5. The exemplar-selection diagnostic re-quires only an object selection and is evaluated with localization accuracy, whereas the property-path diagnostic performs document editing and is evaluated by exact target-attribute matching. First, we isolate exemplar localization, one com-ponent of contextual inference. GPT-5.5 receives the input document and inferential instruction but performs no document modification and is not given a candidate list. It selects a same-type object as the formatting exemplar. If multiple same-type objects have the required target formatting, select-ing any of them is counted as correct. GPT-5.5 achieves an exemplar-selection accuracy of 81.2%. This diagnostic measures only exemplar localiza-tion, not property-path identification or document editing. This result indicates that exemplar infer-ence itself remains a source of error even when editing execution is excluded. Second, starting from the referential setting, where the exemplar is explicitly provided, we addi-tionally provide the property paths to be modified without revealing their target values. The agent must infer the values from the exemplar and pro-duce the edited document. Providing the property paths increases the task-level pass rate from 43.6% to 45.4%. Thus, under this setting, explicit prop-erty paths yield only a small improvement in target-object modification. Separately, in the descriptive 7condition, both the properties and their target val-ues are explicitly specified, yet the same agent achieves a pass rate of only 55.4%. This shows that failures remain even when contextual exem-plar and property discovery are not required. Taken together, these results indicate that inferential-task failures reflect both errors in exemplar localization and failures to correctly apply the required format-ting changes. 

4.4 Failure Analysis 

Qualitative inspection of failed agent trajectories revealed the following illustrative failure modes: 

Improper editing methods causing file corrup-tion or ineffective modifications. A Word docu-ment is essentially a ZIP archive containing XML files. In inspected failures, some agents unzip the document, modify the internal XML, and repack-age it rather than editing through Word’s program-ming interface. This approach can produce a mal-formed package even when the local XML edit appears correct. For example, an XML library may rename namespace prefixes during re-serialization while other locations still reference the original names, causing broken references. Word may then reject the file or silently discard modifications. 

Incorrect understanding of API parameter val-ues or semantics. When executing attribute mod-ifications through programming interfaces, agents sometimes misunderstand parameter values or meanings. For example, when setting chart type to “Scatter,” an agent used enum value 74, which ac-tually corresponds to “Scatter with Straight Lines and Markers,” while the correct value for a plain scatter plot is −4169 . Similarly, when setting both paragraph left indent and hanging indent si-multaneously, agents confuse the meaning of the 

LeftIndent property, which actually represents the sum of left indent and hanging indent, not the left indent alone. 

Incomplete attribute coverage. In referential and inferential tasks, agents must identify which attributes to modify on their own. Selected tra-jectories show cases where an agent locates the appropriate exemplar but omits some required at-tributes. The observed examples include complex nested objects for which the agent modifies outer attributes but neglects per-run formatting within paragraphs, per-cell styles in tables, or internal text formatting within shapes. Descriptive instructions specify these attributes, removing the discovery requirement, though execution may still fail. 

4.5 Limited Visual Understanding of Document Formatting 

In referential and inferential tasks, agents must au-tonomously determine which attributes of the target object need to be modified. A direct approach is to visually inspect the document context, comparing the target object with other same-type objects to infer the required attribute changes. We designed an experiment to test whether GPT-5.5 can identify formatting attribute changes through visual inspec-tion. For each of the 280 input–reference pairs, we render screenshots of up to three differing pages per document and ask GPT-5.5 to select the changed attributes from an 81-attribute checklist. We com-pare its selections with programmatically computed ground-truth attribute diffs. This setting is eas-ier than the actual task, where agents have access to neither the reference document nor an attribute checklist. GPT-5.5 achieves 0.740 precision, 0.351 recall, and 0.476 F1: its predictions are mostly correct but recover only about one-third of the changes, of-ten missing visually subtle properties such as line spacing, paragraph spacing, and font. Figure 4 in Appendix H shows an example, consistent with prior findings on fine-grained visual perception (Rahmanzadehgervi et al., 2024; Liu et al., 2024). Because coding agents may also inspect document properties through COM or XML, this result does not explain all agent failures, but cautions against relying on screenshot-only attribute detection or vision-only LLM judges without validation. 

5 Conclusion 

We present WordInferBench, a benchmark of 280 base editing instances and 840 instruction-conditioned variants that evaluates coding-agent systems on Word document formatting under de-scriptive, referential, and inferential instructions. Across six evaluated systems, pass rates are low-est on inferential variants. Qualitative trajectory inspection identifies illustrative bottlenecks includ-ing improper editing methods, misunderstanding of API parameter semantics, and incomplete attribute coverage, while a controlled GPT-5.5 experiment shows that screenshot-only inspection misses many fine-grained formatting differences. These findings 8show that context-aware attribute inference remains a core challenge for current coding-agent systems. 

Limitations 

Our benchmark currently targets only formatting attribute modifications in Word documents, without covering other Office applications such as Power-Point and Excel. Our three-level instruction design and attribute-comparison-based evaluation frame-work are in principle transferable to other applica-tions, and extending to a broader range of Office application scenarios is a direction for future work. Additionally, for evaluation convenience, our task design is limited to modifying a single target ob-ject per task. In real-world document editing, user requests often involve coordinated modifications across multiple objects, such as uniformly adjust-ing the formatting of all headings in a document. However, an agent’s ability to modify formatting on a single object is the foundation for completing multi-object coordinated edits, and performance on single-object tasks can reflect its core capability in more complex scenarios. 

Ethical Considerations 

We use publicly accessible Word documents col-lected through Common Crawl. The original doc-uments may contain personally identifiable infor-mation (PII). To reduce privacy risks, we replace detected PII with placeholders, exclude documents containing detected face photographs, and conduct additional privacy checks during human verifica-tion.

G Heuristic Baselines for Inferential Variants 

Inferential variants have lower pass rates than ref-erential variants. The core difference is that in-ferential variants require agents to identify which object in the document serves as the formatting exemplar, whereas referential variants directly pro-vide this information. To characterize how much of this gap may stem from exemplar localization, we design two heuristic baselines that measure the localization ability of naive strategies. For each target object, both baselines select a same-type candidate from the same document and check whether its attributes exactly match the ground truth. Nearest Neighbor selects the can-didate closest in document order. Majority Vote 

computes a formatting signature for each same-type candidate, selects the one belonging to the most frequent signature group, and falls back to nearest neighbor when no clear majority exists. Nearest Neighbor achieves 50.6% and Majority Vote achieves 45.8%. The superiority of nearest neighbor over majority vote indicates that spatial proximity provides a stronger signal than global format consensus—same-type objects in a docu-ment do not always share the same formatting. For example, when the target is a heading paragraph, the majority format among same-type candidates likely corresponds to body text rather than head-ings, causing majority vote to select incorrectly. Note that these heuristic baselines only evaluate reference object localization accuracy (whether the selected candidate’s attributes match the ground truth), without performing actual document editing. They are therefore not directly comparable to end-to-end agent pass rates, which additionally require correct execution of attribute modifications.
