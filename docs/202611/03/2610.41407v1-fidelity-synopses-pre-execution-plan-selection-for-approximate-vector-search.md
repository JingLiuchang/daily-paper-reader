## 摘要
向量搜索已成为一种数据库算子，具有多种物理实现：不同的索引族、构建期和搜索期参数，以及压缩或驻留磁盘的变体。每种实现都在成本与保真度之间权衡，保真度指某种配置返回的查询精确 top-k 最近邻所占比例。然而部署方仍离线选择一种配置并用于所有查询，因此按最难查询进行资源配置，并为其余查询多付成本。在包含 580 万条目的 LAION 基准上，使用四种嵌入模型，对每个查询运行足以满足其需求的最便宜配置，在典型设置下可将成本大约减半。利用这一点需要在运行前预测每种配置的保真度，这很难，因为保真度正是由近似索引所避免的精确搜索来定义的。关系型优化器通过离线概要解决基数估计的类似问题；我们为向量搜索提出一种概要。保真度概要围绕一组地标将嵌入空间划分为单元格，并针对每个单元格和配置记录该配置在查询样本上达到保真度目标的频率。在查询时，一次最近地标查找即可为每种配置给出经校准的估计，优化器则选择配置，使工作负载未达目标的频率不超过其要求所允许的范围。我们检验了该概要依赖的两个前提：保真度在嵌入空间中平滑变化，且其损失特定于每种配置。在与静态部署所满足的相同要求下，概要引导的选择在模型和查询方向的全部 16 种组合中都降低了成本，中位数为静态部署的 0.72 倍，批量查找每次查询耗时 21–32 微秒。相对于相同索引中的最佳静态选择，这种节省仍然存在，并且在单一索引内无需额外内存即可实现。

## Abstract
Vector search has become a database operator with many physical implementations: different index families, build-time and search-time parameters, and compressed or disk-resident variants. Each trades cost against fidelity, the fraction of a query's exact top-k nearest neighbors that a configuration returns. Deployments nevertheless choose one configuration offline and use it for every query, so they are sized for their hardest queries and overpay for the rest. On a 5.8M-item LAION benchmark with four embedding models, running each query on the cheapest configuration that suffices for it would roughly halve the cost in a typical setting. Exploiting this requires predicting each configuration's fidelity before running it, which is hard because fidelity is defined by the very exact search that approximate indexes avoid. Relational optimizers solve the analogous problem for cardinality with offline synopses; we propose one for vector search. A fidelity synopsis divides the embedding space into cells around a set of landmarks and records, for every cell and configuration, how often that configuration met a fidelity target on a sample of queries. At query time, one nearest-landmark lookup yields a calibrated estimate for every configuration, and an optimizer chooses configurations so that the workload misses the target no more often than its requirement allows. We test the two premises the synopsis relies on, that fidelity varies smoothly across the embedding space and that its loss is specific to each configuration. Held to the same requirement a static deployment is built to meet, synopsis-guided selection lowers cost in all 16 combinations of model and query direction, to a median of 0.72x the static deployment, with a batched lookup of 21-32 microseconds per query. The saving persists against the best static choice among the same indexes, and within a single index at no extra memory.

## 1. 核心问题与研究动机

- **背景**：向量搜索已成为数据库中的一类算子，存在多种物理实现：HNSW、IVFPQ、O-IVFPQ 等索引族，各自有构建期参数（图度、分区数、码长）与搜索期参数（efSearch、nprobe），还可压缩或驻留磁盘。每种配置都在**成本**与**保真度（fidelity）**之间权衡；保真度指该配置返回的查询精确 top-k 最近邻所占比例。
- **核心问题**：现有部署在离线阶段只选定**一个静态配置**并用于所有查询，因而按最难查询配置资源，对大量简单查询过度付费。作者在 580 万条 LAION 数据、4 个嵌入模型上测得：若每个查询都跑“足以满足它的最便宜配置”，典型设置下成本可**约减半**。
- **难点**：要利用这一机会，必须在执行前预测各配置的保真度；但保真度定义依赖精确 top-k，而近似索引存在的意义正是避免精确搜索，形成循环依赖。
- **现有方法不足**：
  - 早期终止方法（LAET、DARTH）只能在**已选定的索引内部**缩短搜索，无法跨索引族切换；DARTH 还假设所选索引能达到目标召回，而实测中该假设经常不成立（如 OpenCLIP 图像→文本，最准的 HNSW 配置也仅在 69% 查询上达到 0.7 保真度；部分跨模态查询无任何配置达标）。
  - 查询硬度度量（局部内在维度、Steiner-hardness）能解释“为何难”，但不是针对**特定配置**的**校准**保真度估计，无法告诉优化器哪个配置够用。
- **类比思路**：关系优化器用离线概要（直方图）估计基数，从而在执行前选择访问路径；作者为向量搜索提出对应的“保真度概要”。

## 2. 方法论

### 2.1 核心思想
- 保真度主要由查询周围语料几何决定（真邻居的密度、距离、是否跨 IVF 分区、HNSW 图局部连通性）。空间上相近的查询共享周边环境，因而在给定配置下表现相似。
- 将嵌入空间按**地标（landmarks）**划分为若干**单元（cell）**，离线记录每个“单元 × 配置”上的保真度统计；查询时一次最近地标查找即可读出所有配置的估计，再由优化器选配置。
- 概要依赖两个被显式检验的前提：
  - **平滑性**：保真度在嵌入空间中变化足够缓慢，单元统计能代表落入其中的新查询。
  - **配置特异性**：同一区域对不同配置的保真度损失不同（图导航与量化失效方式不同），故须按配置分别保存统计。

### 2.2 离线构建（四步）
1. **地标**：对语料向量做球面 k-means 得到 K 个地标，按最近地标划分 Voronoi 单元；每个模态一套地标，所有配置共享同一套单元。
2. **保真度标签**：对构造样本 Q 中每个查询计算一次精确 top-k，运行全部 m 个配置，记录 $y_{qj}=F(q,A_j)$。这是唯一使用精确搜索的步骤。
3. **分配**：将每个样本查询分配到最近地标所在单元 $i$，得到单元样本数 $n_i$。
4. **聚合**：对每个单元 $i$ 与配置 $A_j$ 记录：
   - 均值保真度 $\mu_{ij}$；
   - B=20 个等宽 bin 的保真度直方图，由此读出任意目标 $\tau$ 下的**覆盖率** $\pi_{ij}(\tau)=|\{q\in Q_i: y_{qj}\ge\tau\}|/n_i$，即该配置在此区域“够用”的估计概率。
   - 稀疏单元（$n_i<q_{\min}=10$）用全样本统计替代。
- **概要规模**：$O(K(d+mB))$ 个数，不随语料规模或样本规模增长；主要开销是地标本身。

### 2.3 在线选择（四步）
1. **定位**：对 K 个地标做线性扫描，找最近地标（$O(Kd)$）。
2. **读估计**：读取该行，得到所有配置的 $\hat F=\mu_{ij}$ 与 $\hat\pi=\pi_{ij}(\tau)$。
3. **预算规则**：
$$\hat A(q)=\arg\min_{A_j\in\mathcal{A}}\; c(A_j)+\lambda\bigl(1-\hat\pi(q,A_j;\tau)\bigr)$$
   其中 $\lambda$ 为“一次预期漏检的价格”，离线在 Q 上用 5 折交叉拟合，取使违规率不超过 $1-\rho$ 的最小值。由于选择只依赖单元，可预计算为查表。
4. **执行**：运行所选配置并返回 top-k；全程无精确搜索。
- **与静态计划的关系**：K=1 时退化为静态计划；节省完全来自单元间选择的变化。
- **对照的简单规则**：
  - 均值规则：选估计保真度 $\hat F\ge\tau$ 的最便宜配置；
  - 覆盖率规则：选单元内覆盖率 $\hat\pi\ge\rho$ 的最便宜配置（逐单元强制要求，更严格也更贵）。

## 3. 实验设计

- **数据集与基准**：LAION 图像–字幕对。原始 6,999,488 对，清洗（剔除退化边、近重复）后 6,826,287 对，按 85/10/5% 分层划分为：
  - 语料 C：5,802,772 对（建索引）；
  - 构造样本 Q：682,444 对（仅离线：建概要、选静态计划、调 λ）；
  - 留出工作负载 Q_test：341,071 对（所有结果在此报告）。
  - 图像与字幕各建一个集合，每个查询对两个集合各搜一次，得到 4 个查询方向：i→i、i→t、t→i、t→t；k=100。
- **嵌入模型（4 个）**：SigLIP2（1152 维）、OpenCLIP（768 维）、Jina-v4（2048 维）、Qwen3-VL（2048 维），覆盖对比学习双编码器与 VLM 嵌入器两类架构。
- **配置目录（9 个）**：HNSW / IVFPQ / O-IVFPQ 各 low / moderate / high 三档（FAISS 1.15.1），共 9 个独立构建；参数经 5 万向量采样调优，目标是平均保真度落在 0.65–0.75、0.75–0.85、≥0.85 三个带。
- **默认设置**：τ=0.7（另测 0.8、0.9），ρ=0.9（至多 10% 查询可未达标），K=10,000，B=20，$q_{\min}$=10。
- **对比方法**：
  - 位置无关基线：全局平均保真度 / 全局覆盖率（等价 K=1）；
  - 仅密度估计（单元局部密度线性项）；
  - 共享概要（每单元一个难度偏移，所有配置共用）；
  - 静态计划（Q 上选出的最便宜达标配置）；
  - 三种每查询最优：matched（与静态计划同等服务水平）、unconstrained（所有可服务查询）、≤1−ρ（满足要求的最便宜分配）；
  - 选择规则：均值规则、覆盖率规则、预算规则（分别按“静态实际违规率”与“要求 ≤1−ρ”调 λ）。
- **小目录实验**：HNSW-only（3 索引）、单索引（hnsw_high 的 3 个 efSearch，无额外内存）、Union（9 配置 + 2 个单索引设置 = 11 配置），各自计算本目录内的静态计划、最优与概要。
- **成本测量**：单查询（单线程）与批量（4,096 查询 / 64 线程）两种模式，主结果用批量；5,000 条随机查询，预热 500 条，重复至 ≥20 s 且 ≥3 轮取中位数。
- **五个研究问题**：RQ1 机会大小；RQ2 位置是否预测保真度（平滑性）；RQ3 是否须按配置保存（配置特异性）；RQ4 端到端选择是否降本且不超违规要求；RQ5 概要成本与参数敏感性。
- **统计方法**：95% bootstrap 置信区间（按单元重采样，1,000 次）；Wilcoxon 符号秩检验（估计误差、短缺）、McNemar 检验（违规）；Benjamini–Hochberg 校正（FDR q<0.05）；3 个聚类种子做稳健性检验。
