## 摘要
分布式向量数据库日益支持安全敏感型应用，然而现有系统主要保护索引完整性或副本可用性，而非检索结果的可信性。因此，一个被攻陷的副本可以返回看似合理但经过操纵的结果，且该结果在密码学上仍然有效；而传统的复制与拜占庭防御并不能直接判定检索结果是否可信。我们提出 TrustANN，一种中间件层，可在不修改底层 ANN 算法的前提下，为分布式近似最近邻（ANN）检索提供查询级信任。TrustANN 引入三种互补协议：TrustBind，从经过认证、一致且故障域独立的副本证据中验证检索信任；CoordShift，在查询关键路径之外异步构建可复用的协调纪元；AvailGuard，在副本不可用、过期或冲突时执行有界恢复，同时保持信任判据。仅当每个相关分片都存在足够的独立证据时，查询才被标记为 Trusted；否则，TrustANN 返回 Unverified。在采用分布式 FAISS HNSW 的 AWS 部署中，在三取二副本验证下，针对所测试的拜占庭检索攻击，TrustANN 将检索攻击成功率从 1.000 降至 0.000。该验证层仅使正常情况下的 p95 延迟增加 9.36%。在副本崩溃情况下，TrustANN 可在 33% 的故障下维持可信检索，并在足够证据不可用时正确返回 Unverified。

## Abstract
Distributed vector databases increasingly support security-sensitive applications, yet existing systems primarily protect index integrity or replica availability rather than the trustworthiness of retrieved results. Consequently, a compromised replica can return a plausible but manipulated result that remains cryptographically valid, while conventional replication and Byzantine defenses do not directly establish whether the retrieved results are trustworthy. We present TrustANN, a middleware layer that provides query-level trust for distributed approximate nearest-neighbor (ANN) retrieval without modifying the underlying ANN algorithm. TrustANN introduces three complementary protocols: TrustBind, which verifies retrieval trust from authenticated, consistent, and failure-domain-independent replica evidence; CoordShift, which asynchronously constructs reusable coordination epochs outside the query critical path; and AvailGuard, which performs bounded recovery when replicas are unavailable, stale, or conflicting while preserving the trust criterion. Queries are marked Trusted only when sufficient independent evidence exists for every relevant shard; otherwise, TrustANN returns Unverified. On an AWS deployment using distributed FAISS HNSW, TrustANN reduces retrieval attack success rate from 1.000 to 0.000 under the tested Byzantine-retrieval attack with two-of-three replica verification. The verification layer increases clean p95 latency by only 9.36%. Under replica crashes, TrustANN maintains trusted retrieval through 33% failures and correctly returns Unverified when sufficient evidence is unavailable.

# TrustANN 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：分布式近似最近邻（ANN）检索已成为 RAG、推荐系统、语义搜索等应用的基础设施，系统通过分片（shard）与副本（replica）实现扩展与容错。
- **核心问题**：分布式化扩大了信任边界。现有工作主要保护**索引完整性**或**副本可用性**，但无法回答“检索结果本身是否可信”。
- **关键缺口**：
  - 被攻陷的副本可以返回**看似合理但被操纵**的结果，且密码学签名仍然有效；认证状态 ≠ 可信检索。
  - 传统 BFT 共识/区块链锚定若放在查询关键路径上，会引入不可接受的同步延迟，与 ANN 低延迟目标冲突。
  - 副本故障时“有响应”不等于“有足够独立证据”；简单接受可用响应会把可用性误当正确性。
- **目标**：在不修改底层 ANN 算法的前提下，提供**查询级检索信任（query-level retrieval trust）**，并在证据不足时显式返回 `UNVERIFIED` 而非降低标准。

## 2. 方法论

### 2.1 总体架构
- TrustANN 是位于现有分布式 ANN 之上的**中间件层**，将“检索执行”与“检索信任”、“后台协调”与“查询级安全”分离。
- 三个互补协议：**TrustBind**（查询级证据验证）、**CoordShift**（异步协调纪元）、**AvailGuard**（有界证据恢复）。

### 2.2 威胁模型与证据边界
- 部署含 N 个 worker、M 个分片、每分片 r 个副本；部分同步网络。
- 每分片至多被腐化副本数：`f_s = ⌈r/2⌉ − 1`；腐化副本可共谋、返回不完整/过期/冲突结果、操纵排序、重放或选择性响应。
- 信任按**分片独立**判定，跨分片证据不可合并；若证据不足则返回 `UNVERIFIED`。
- 独立性由**配置的故障域元数据**（可用区、网络域等）决定，而非 worker 身份。

### 2.3 TrustBind：一致性感知的查询级信任
- 对每个相关分片 j 构造证据图 `G_q,j`，顶点为有效响应，边权：
  `w_ab = λ·J(C_a,C_b) + (1−λ)·R(C_a,C_b)`
  其中 J 为候选 ID 的 Jaccard 相似度，R 为归一化排名一致性。
- 聚合一致性：`C(S) = 2/(|S|(|S|−1)) · Σ w_ab`。
- 故障域覆盖：`D(S) = |{d : ∃v∈S, domain(v)=d}|`。
- 分片可信条件：
  `Trusted_j(q) ⇔ |S_q,j| ≥ θ ∧ C(S_q,j) ≥ γ ∧ D(S_q,j) ≥ d_min`
  默认 `θ = ⌈r/2⌉`；全局信任要求所有相关分片均满足。
- 采用**贪心证据选择**（非最大团精确求解）：从支持度最高的响应出发，迭代加入边际一致性增益最大且满足故障域约束的响应。
- 每个响应需通过签名与当前 epoch 校验，来源元组为 `⟨shard, replica, worker, domain⟩`，防止重复计数。

### 2.4 CoordShift：多样性感知的异步协调
- 每轮从成员中随机采样候选池 `P_t`（|P_t| = k′ > k），再用贪心多样性目标选 quorum：
  `F(Q) = Σ_{d∈D} min{1, |Q∩d|}`
- 各 worker 返回签名状态摘要，按分片取多数支持值；无多数则沿用旧值；整轮失败视为 no-op。
- 关键设计：CoordShift **不提供拜占庭安全的状态证书**，也不在查询关键路径上；即使协调轮被 adversary 影响，也不能直接使查询被信任。

### 2.5 AvailGuard：独立性感知的有界恢复
- 当某分片 TrustBind 失败时，保留已有证据，优先选择能带来**新故障域覆盖**的副本，而非单纯增加响应数。
- 恢复最多 `K_max` 轮，**从不降低 θ、γ、d_min**；仍不满足则返回 `UNVERIFIED`。
- 恢复按分片独立进行，不允许其他分片证据替代。

### 2.6 安全性质
1. 协调不决定检索信任；
2. 信任按分片独立建立；
3. 证据必须满足一致性与独立性；
4. 故障恢复不削弱信任；
5. 恢复有界（最多 K_max 轮）。
- 通信上界：`B_q ≤ F·r·(1+K_max)`（F 为相关分片数，r 为副本数）。
