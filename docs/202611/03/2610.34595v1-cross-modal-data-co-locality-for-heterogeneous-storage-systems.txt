# Cross-Modal Data Co-Locality for Heterogeneous Storage Systems 

# Abdullah Al-Mamun Augusta University aalmamun@augusta.edu 

# Abstract 

Distributed vector stores increasingly serve multimodal work-loads whose representations are jointly accessed but inde-pendently partitioned and placed. As a result, cross-modal physical locality remains largely unoptimized. Multimodal queries can incur remote accesses and cross-tier data move-ment even when each modality’s ANN search remains effi-cient. We present CoLoc, a storage-management layer that makes cross-modal access locality a first-class data-layout sig-nal. A Cross-Modal Access Graph combines semantic affinity, co-access, and temporal behavior. A movement-aware opti-mizer places frequently co-accessed vectors under capacity and topology constraints. A migration manager adapts place-ment as workloads shift by weighing locality gains against migration cost. A confidence-gated prefetcher hides remain-ing slow-tier latency. CoLoc operates above existing ANN indexes without modifying embeddings, search, or retrieval semantics. We deploy CoLoc on a multi-tier AWS testbed spanning GPU, NUMA-DRAM, NVMe, and S3. CoLoc sub-stantially reduces data movement and query latency while leaving ANN retrieval unchanged. Under a scheduled work-load shift, its migration manager matches the locality of peri-odic global reorganization while moving 5.9 × less data and completing 3.9 × faster. 

# 1 Introduction 

Multimodal applications increasingly represent the same logi-cal object using multiple modality-specific embeddings, such as text, images, clinical records, and sensor data [7, 9, 10, 36]. Medical workloads, for example, increasingly combine elec-tronic health records (EHRs), medical images, laboratory mea-surements, and other clinical modalities [11], motivating new systems support for multimodal data storage and retrieval [17]. These representations are often independently embedded and indexed, allowing each modality to use an appropriate ANN structure but also allowing related representations to become physically separated. This separation creates a physical data-layout problem that is largely orthogonal to ANN search efficiency. Consider a multimodal query that first searches text or EHR vectors and subsequently accesses the corresponding image representa-tions. The two modality-specific ANN searches can each be efficient, yet their results may reside on different machines, NUMA domains, memory tiers, or storage devices. The sys-tem must then move data across the network, NUMA hierar-chy, CPU–GPU boundary, or storage hierarchy to assemble the final result. Thus, a vector system can optimize its indi-vidual ANN searches while still paying a substantial physical data-movement cost at the multimodal query level . The fun-damental problem is therefore not only where vectors should be searched, but also where heterogeneous representations required by the same query should physically meet .Recent vector systems increasingly optimize physical lo-cality, but at different levels. Distributed ANN systems such as CoTra and RED-ANNS optimize partitioning, communi-cation, and distributed execution [8, 37], while d-HNSW ex-plores vector search over disaggregated memory [12]. Storage-aware vector systems exploit locality within vector indexes to reduce I/O [20], and heterogeneous-memory systems study locality-aware placement and migration across memory tiers [13, 24, 38]. Meanwhile, vector database architectures are increasingly spanning heterogeneous memory and stor-age resources [18, 21, 22]. These systems address important forms of index, communication, or resource locality, but do not make cross-modal co-consumption a first-class physical placement objective. Table 1 summarizes the fundamental limitations of current representative locality-aware systems. In summary, multimodal queries induce a distinct form of physical locality: representations that are repeatedly con-sumed together should preferably be physically close, even when they belong to different indexes and modalities. Seman-tic similarity alone is insufficient because semantically related representations need not be accessed together, while observed co-access can be sparse for emerging workloads. We present CoLoc, a storage-management layer that in-troduces cross-modal co-locality as a first-class placement objective without modifying embeddings, ANN indexes, dis-tance metrics, or retrieval semantics. The Cross-Modal Access Graph (CAG) captures relationships among independently in-dexed representations using cross-modal co-access, semantic affinity, and temporal proximity. The Co-Locality Placement Optimizer (CPO) translates these relationships into capacity-, load-, and topology-aware placement decisions while account-ing for physical movement cost. A topology-aware layer maps logical decisions onto GPU memory, NUMA DRAM, NVMe, and remote storage, while the Locality-Preserving Migration Manager (LPMM) adapts placement under workload drift only when the expected future locality benefit justifies migra-tion cost. The central distinction is simple: existing vector systems optimize where vectors are searched; CoLoc opti-mizes where the heterogeneous representations required by a query physically meet. 

In summary, the paper makes the following contributions: • Cross-modal co-locality abstraction. We introduce cross-modal co-locality as a physical data-layout prim-itive for independently indexed multimodal representa-tions. • Movement-aware placement. We develop CAG and CPO to translate cross-modal co-access, semantic and temporal evidence into topology- and capacity-aware placement decisions that minimize physical data move-ment. • Adaptive migration. We develop LPMM to adapt place-ment under workload changes while explicitly trading future movement savings against migration cost. • System evaluation. We implement CoLoc above ex-isting ANN indexes and evaluate it on a real multi-tier AWS deployment spanning GPU, NUMA-DRAM, NVMe, and S3. CoLoc eliminates cross-tier movement entirely (73% →0% of multimodal queries) and reduces end-to-end latency by up to 25% over independent place-ment at high multimodal query intensity. LPMM adapts to workload shift while moving 5.9 × less data and com-pleting 3.9 × faster than periodic global reorganization; a CAG-driven prefetcher further reduces latency by 8.5% by overlapping remote fetches with query processing. Retrieval quality (Recall@ k) remains completely unaf-fected by placement throughout. 

# 2 Related Work 

Newer ANN serving and multimodal query systems. 

Recent large-scale and GPU-accelerated ANN systems – DistVS [32], GIDS [1], and VecFlow [3] – continue the search-execution focus already discussed in §1; none reasons about placement across independently-managed indexes. Closer in spirit is ARCADE [30], a real-time engine for hybrid, con-tinuous queries across diverse data modalities. ARCADE ad-dresses query execution across modalities within one system; it does not address the physical co-location of independently-indexed representations across heterogeneous storage tiers, which is where CoLoc operates – the two are complementary rather than competing. 

General cost-aware data placement. Beyond the hetero-geneous storage/memory placement model of §3.3, similar movement-vs-reorganization trade-offs appear in learned di-rectory placement [34], Markov-clustering-based locality for MapReduce [25], and multicloud placement [5]. This work is domain-agnostic; CoLoc specializes the same trade-off to independently-indexed multimodal vectors, where the place-ment unit and migration trigger are shaped by cross-modal query structure (§3.1) rather than a generic access trace. Industry movement toward object-storage-integrated vector search [6] and filtered ANN search at scale [2] reflects the same trend motivating CoLoc: vector workloads increasingly span storage tiers by default. 

Multimodal retrieval quality and clinical fusion. A separate line of work improves what gets embedded and how modali-ties are combined for retrieval quality: generative multimodal search [15] and noisy-correspondence-robust cross-modal alignment [4, 27, 28, 33]. In the clinical domain, DrFuse [31] and missing-modality EHR embedding [16] extend the fu-sion challenge §1 raised via MedMod. All of this determines embedding and retrieval semantics, which CoLoc explicitly does not touch (§3); better embeddings increase the value of correct placement without changing where independently-indexed vectors physically end up relative to each other – the gap CoLoc fills. 

VDBMS engineering maturity. Work characterizing relia-bility gaps [26], real production bugs [29], and fundamen-tal system concepts [23] in vector database management re-2flects growing engineering rigor in this space. Physical place-ment across heterogeneous tiers remains comparatively under-examined in that line of work; CoLoc treats it as a first-class, independently evaluable concern (§4). 

# 3 Cross-Modal Co-Locality Design 

CoLoc is a storage-management layer above existing modality-specific embedding and ANN indexes. It does not modify embeddings, ANN search algorithms, distance func-tions, index structures, or retrieval semantics. Instead, it adapts the physical placement of heterogeneous representations ac-cording to their joint consumption by multimodal queries. Cross-modal accesses are asynchronously collected by the 

Cross-Modal Access Graph (CAG) , which combines observed co-access with semantic and temporal evidence through incre-mental updates. The Co-Locality Placement Optimizer (CPO) 

uses this signal to determine movement-aware placement through an iterative group-partitioning heuristic and maps the resulting groups onto topology- and tier-aware resources. The Locality-Preserving Migration Manager (LPMM) adapts placement when workload changes justify migration. A CAG-driven prefetcher (§3.6) complements these mechanisms by warming a bounded cache ahead of predicted accesses with-out changing placement. Together, these components form a closed control loop with no synchronous coordination on the query critical path.

# 3.2 Cross-Modal Access Graph 

Semantic affinity alone does not establish that two represen-tations will be consumed together [7, 9–11, 36], while sparse observations can be insufficient for emerging relationships. CoLoc therefore combines observed co-access with semantic and temporal evidence in a weighted graph GA = ( V, EA,WA),where each vertex is a placement unit. For each pair u, v, CAG maintains co-access Auv , semantic affinity Suv , and temporal proximity Tuv , fused as 

wuv = αAuv + βSuv + γTuv , (4) with tunable α, β, γ. Co-access provides the primary evidence, semantic affinity provides cold-start evidence, and temporal proximity captures short-lived correlations. This weighted fusion provides a practical locality score rather than a proba-bilistic model. CAG uses an incremental maintenance policy. Each new access event marks its object dirty , and a rebuild recomputes 

Auv /Suv /Tuv only for pairs touching a dirty object. Since em-beddings are static, Suv is cached permanently. All other edges remain unchanged: co-access pairs form only within one ob-ject, and Tuv depends only on the two endpoints’ own last-access times. One caveat is that the normalization denominator of Auv 

is a global statistic, computed from a robust percentile of co-access counts to reduce sensitivity to individual high-traffic pairs. Consequently, the statistic can change even when the updated workload does not directly involve a particular object. When such a change invalidates the existing normalization, the implementation falls back to a full rebuild to avoid us-ing stale co-access weights. Thus, the benefit of incremental maintenance is most pronounced under frequent, small work-load updates and progressively diminishes toward full-rebuild cost for large, infrequent workload shifts. The Control-Plane Overhead evaluation in §4 examines both regimes rather than assuming that the incremental bound holds unconditionally.

# 3.6 CAG-Driven Prefetching 

Placement and migration change where data resides, but can-not eliminate the fraction structurally forced onto the slowest tier under tight capacity (see end-to-end performance evalu-ation in §4). CoLoc instead hides the cost of reaching that data. When a query accesses u, its CAG neighbors become candidates for background retrieval into a bounded cache, overlapping the slow tier’s round trip with subsequent compu-tation. The cache is maintained separately from the placement map p(·): a hit changes where a fetch is served from, but not CPO’s or LPMM’s record of where v is placed. Raw co-access counts do not provide calibrated confidence: two-of-two and two-hundred-of-two-hundred reflect different levels of evidence that Auv alone cannot distinguish. # 3.7 Operational Overhead and Isolation 

All optimization mechanisms stay off the query critical path: execution generates only lightweight access observations, while CAG updates, CPO, topology evaluation, LPMM mi-gration, and prefetching (§3.6) run asynchronously in the background – a prefetch cache miss simply falls through to the vector’s normal placed resource at no extra cost. The de-sign also avoids global reorganization: CPO evaluates only affected groups, and LPMM migrates only units whose sav-ings justify their cost, so migration decisions scale with the amount of workload change , not dataset size. Incremental CAG maintenance (§3.2) is a second, narrower reduction: it bounds rebuild cost by workload drift only under 

frequent, small updates, where the global co-access normal-ization stays stable between calls. A single large, infrequent shift – such as the workload shift in Adaptive Migration eval-uation in §4 – can still trigger a full rebuild. CoLoc there-fore bounds control-plane overhead by workload drift in the frequent-update regime specifically, not unconditionally. The Evaluation section reports both regimes rather than assume the bound holds everywhere convenient.

Experimental Setup. We deploy CoLoc on one AWS EC2 instance per tier: g5.xlarge (GPU), r6i.4xlarge (NUMA-DRAM), i4i.2xlarge (NVMe), and Amazon S3 (remote, measured 24.2 ms round-trip, 86.4 MB/s – one to two or-ders of magnitude slower than every other tier). Tier capac-ities are sized relative to dataset size (15%/20%/30%/50% for GPU/NUMA/NVMe/remote) so no strategy can trivially avoid multi-tier use. We evaluate 50,000 objects (100,000 vectors, 768 dimensions) from MIMIC-CXR [14] (377k ra-diographs, 228k reports). CAG weights use α = β = γ = 1.0(Eq. 4, uniform weighting). We compare five configurations: 

(i) Independent : modality-specific representations are placed independently without cross-modal coordination; (ii) Access-Aware : placement uses observed cross-modal access only, iso-lating the contribution of workload co-access from semantic and temporal signals. (iii) CAG+CPO : cross-modal relation-ships are constructed by CAG and translated into capacity-and topology-aware placement by CPO. (iv) Full System :CAG+CPO plus LPMM for adaptive migration. (v) Full Sys-tem+Prefetch : the complete system with confidence-gated background prefetching. 

End-to-End Performance and Movement. Table 2shows that CAG+CPO eliminates cross-tier access (73.04% →0.00%) and reduces end-to-end latency by 6.8% (12.52 →11.67,ms), while satisfying the tier-capacity constraints. Although CAG+CPO places slightly more data on the remote tier (38.8% vs. 34.9%), it achieves lower latency by co-locating frequently accessed representations. In contrast, Independent placement exceeds its capacity allocation (166.7%), whereas CAG+CPO remains within the limit (100%). These results demonstrate that movement-aware placement improves cross-modal locality and query performance under constrained heterogeneous storage. Table 3 shows that the latency benefit of CAG+CPO increases with multimodal query intensity. The reduction grows from 8.3% at 10% multimodal queries to 16.4% at 30% and 24.8% at 50%, indicating that cross-modal co-locality becomes increasingly beneficial as more queries access multiple modalities. 

ANN Quality, Retrieval Neutrality, and Prefetch. Table 4 shows that Recall@10 (1.0000) and ANN latency (8.72,ms) remain unchanged across all configurations, demonstrating that CoLoc does not alter the ANN retrieval path. Full System+Prefetch further reduces end-to-end latency from 11.76,ms to 10.75,ms (8.5%) relative to Full System, showing that confidence-gated prefetching can hide remaining remote-access latency without affecting retrieval quality. 

Adaptive Migration. Table 5 shows that LPMM adapts to the workload shift with substantially lower migration cost than periodic reorganization. LPMM moves only 5.10,MB and completes migration in 14.03,s, compared with 30.19,MB and 54.65,s for periodic reorganization—a 5.9 × reduction in data movement and 3.9 × faster migration. At the same time, LPMM nearly restores the locality of periodic reorganization, reducing post-shift cross-tier access from 42.02% to 0.11% and achieving the lowest post-shift latency (10.15,ms). These results demonstrate that LPMM effectively adapts placement while substantially reducing the cost of global reorganization. 

Control-Plane Overhead. Table 6 shows that incremental CAG maintenance reduces construction time from 5.235,s to 0.756,s, providing a 6.92 × speedup in the many-small-updates regime. The mechanism triggers a full rebuild only once across 19 batches, demonstrating that incremental main-tenance substantially reduces control-plane overhead when workload changes are small and frequent. 

# 5 Conclusion and Future Work 

We presented CoLoc, a storage-management layer that treats cross-modal co-locality as a first-class data-layout objective for distributed vector stores and comprises three tightly cou-pled components. CAG captures cross-modal access, seman-tic, and temporal locality. CPO translates these signals into topology- and capacity-aware placement. Finally, LPMM adapts placement under workload shifts. A confidence-gated prefetcher complements these components by reducing re-maining slow-tier latency. CoLoc operates above existing ANN indexes without altering retrieval semantics. Our AWS evaluation demonstrates that cross-modal placement reduces data movement and end-to-end latency, while LPMM recovers locality after workload shifts with substantially less migration than global reorganization.
