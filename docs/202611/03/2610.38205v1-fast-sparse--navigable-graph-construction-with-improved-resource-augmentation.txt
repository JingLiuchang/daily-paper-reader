# Fast Sparse α-Navigable Graph Construction with Improved Resource Augmentation

Abstract 

Graph-based nearest neighbor search methods have surged in popularity in recent years. These methods are based on running greedy search on a directed graph constructed over a set of n points, x1, . . . , x n, endowed with some distance function. A common goal is to construct a search graph that has the α-navigability property, which ensures that greedy search returns provably good approximate nearest neighbors and converges in a small number of iterations. As the parameter α ≥ 1 increases, accuracy improves, as does convergence rate, but there is a tradeoff: higher values of α require the graph to have more edges, which increases both the data structure’s space and search time. This tradeoff has motivated the study of algorithms for constructing a sparsest α-navigable graph for a given set of points. In this work, we present improved algorithms for constructing α-navigable graphs. For any point set and any distance function, we show how to compute an α-navigable graph G with a number of edges no more than O(log n) times that of the sparsest (1 + ε)α-navigable graph. The algorithm runs in O(nω log(∆) /ε ) time, where ω < 2.372 is the exponent of fast matrix multiplication and ∆ is the ratio between the largest and smallest pairwise distances in the input set. This result improves on recent work by Khanna, Padaki, and Waingarten (SODA 2026), who achieve the same runtime, but are only competitive with the sparsest 2(1 + ε)α-navigable graph. Since sparsity often increases rapidly with α (typically α is chosen ≤ 1.1)such a result can be significantly weaker than our bound. Previously, the best algorithm that could compete with the sparsest (1 + ε)α-navigable graph required eO(n2.5) time. Beyond our main result, we show that our techniques extend to the related problem of constructing sparse 

τ -monotonic graphs, another popular target in nearest neighbor search. Moreover, we provide a fine-grained complexity analysis that suggests that improving the O(nω ) running time in our result is unlikely, or at least would require a very different algorithmic approach. This analysis is based on proving hardness results for problems related to verifying whether a graph is navigable, which is a topic of independent interest. 

# 1 Introduction 

Nearest neighbor search has been a central problem in computer science for decades [4, 6, 7, 9–11, 23, 27, 29]. Given a dataset P = {p1, . . . , p n} together with a distance function d(·, ·), the goal is to construct a data structure that can answer (approximate) nearest-neighbor queries: given q, return a p ∈ P that (approximately) minimizes d(p, q ). Given the problem’s importance, many different methods have been proposed to solve approxi-mate nearest neighbor search, including well-known and widely used methods like locality sensitive hashing [2, 3, 20], quantization-based inverted file indices [17, 23, 24], and tree-based methods [7, 35]. In recent years, there has been a surge of interest in a class of algorithms referred to as graph-based nearest neighbor search methods . Such methods include Hierarchical Navigable Small World (HNSW) Graphs [33], Vamana/DiskANN [28, 40], Navigating Spreading-out Graphs (NSG) [16], and more [5, 6, 15, 18, 32, 34, 36, 37]. Such methods offer state-of-the-art performance on a number of leading benchmarks and search competitions [6, 37, 38]. In graph-based methods, the core data structure used to support nearest neighbor search is a directed graph G = ( P, E ) with a node corresponding to every point in the dataset. A query q is serviced by starting at some node in the graph, and greedily moving to the out-neighbor that is closest to q. The search continues in this way, terminating when no closer neighbor exists. Given the simplicity of this greedy search algorithm, a key differentiator between graph-based methods is how the search graph G is constructed. How should the edges in E be chosen to facilitate fast and accurate nearest-neighbor search? 

1.1 α-Navigable Graph Construction 

While many different approaches have been employed to construct search graphs, navigability has been repeatedly identified as a desirable property for such graphs [32, 40]. A graph is navigable 

if, for every source point s and distinct target point t in P , the graph has an edge (s, v ) where 

d(v, t ) < d (s, t ), i.e. the source has an edge that leads closer to the target. On such a graph, a greedy traversal from any starting point in P must converge to any query point, so long as that query is itself a member of P ; at every step, the navigability property ensures that the traversal can make progress, until it lands on the query itself. This basic property can be strengthened to α-navigability , defined for any parameter α ≥ 1.In this case, it is not sufficient that a source simply have an edge leading closer to each target: it must have an edge that shrinks the distance to a target by a multiplicative factor of α or more. Formally, for each source-target pair s, t , there must be an edge (s, v ) where d(v, t ) < 1 

> α

d(s, t ).

1.2 How much resource augmentation is too much? 

While resource augmentation leads to a clear runtime advantage, reducing graph construction cost from roughly eO(n2.5) time to roughly eO(nω) time, it is natural to ask how much of a price is paid in terms of graph sparsity. In other words, how much larger is OPT 2α(1+ ε) than OPT α?

In short, the answer is that the gap between these quantities can be substantial. When con-structing α-navigable graphs for real-world datasets, practitioners tend to set α close to 1 (usually in the range [1 .0, 1.2]) [33, 34, 39, 40]. α is always chosen less than 2. Recalling that higher α improves both accuracy and convergence rate, this suggests that even OPT 2 ≤ OPT 2α(1+ ε) is too large to be usable. Indeed it has been confirmed experimentally that, on many real-world datasets, as α grows towards 2, the sparsest α-navigable graph becomes essentially complete. One explanation for this is that, while not truly random, many modern high-dimensional vector embedding datasets exhibit properties of random points in Euclidean space. In particular, the majority of vectors are nearly orthogonal to each other, so distances between points tend to be similar. Indeed, in common embedding datasets, the aspect ratio is quite low, with the maximum pairwise distance no more than a small factor of the minimum. In an α-navigable graph with α > 2,any source-target pair requires an edge that gets at least 50% closer to the target. For common datasets, such an edge may simply not exist: the only option is to connect directly to the target. I.e., OPT 2 will be close to n2.Given this, the goal of this work is to develop graph construction algorithms that enjoy the same efficient runtime as the method of [25], but without sacrificing so much on sparsity. In particular, instead of competing with OPT 2(1+ ε)α, ideally we would return a graph whose sparsity is competitive with the best (1 + ε)α-navigable graph, where ε can be set arbitrarily close to zero.

Hardness of navigability verification. A key component of our construction, inherited from [25], is a black-box procedure that determines which source-target α-navigability constraints are satisfied by the edges currently in the graph. After distances are discretized, the constraints at each distance scale can be checked using one matrix multiplication. These matrix multiplications dominate the running time of our algorithm, so a substantially faster verification procedure would immediately yield a faster resource-augmented constructions. This motivates us to study navigability verification as an independent algorithmic problem. We prove two hardness results. First, even when restricted to source-target pairs at a single fixed dis-tance, α-navigability verification is at least as hard as Boolean matrix multiplication: an n × n

Boolean matrix product can be computed using one call to the verification procedure and O(n2)

additional time. Thus, bypassing matrix multiplication in our verification routine would require a corresponding breakthrough for Boolean matrix multiplication. Second, we consider exact verifica-tion over all undiscretized distances. We show that this problem is equivalent, up to polylogarithmic factors, to Boolean min-plus product. Combining this equivalence with a recent conditional lower bound for Boolean min-plus product [14], we show that, under the APSP conjecture, exact α-navigability verification cannot be solved in O(n2.5−δ) time for any constant δ > 0. Together, these results suggest that both the matrix multiplication bottleneck and the use of resource augmentation are difficult to avoid within our framework. 

1.4 Technical Overview and Prior Work 

A first general answer for the question of how sparse a navigable graph can be made, and how efficiently such a graph can be constructed was given by [13]. They showed every n-point dataset admits a nontrivial sparse navigable graph, independent of the ambient dimension and without relying on metric structure. Their construction takes the union of a nearest-neighbor graph and a random graph, and in eO(n2) time constructs a navigable graph with eO(n3/2) edges. Equivalently, every point set admits a navigable graph of average degree eO(√n). This bound is essentially tight in the worst-case: for random points in O(log n)-dimensional Euclidean space, a navigable graph must have average degree Ω( n1/2−o(1) ) (with high probability). This worst-case picture, however, does not capture the instance-by-instance structure of the problem. Many datasets may admit navigable graphs far sparser than the eO(n3/2)-edge worst-case guarantee. Thus the more refined objective is not merely to construct some sparse navigable graph, but to approximate the sparsest navigable graph for the given instance. This instance-optimal viewpoint was subsequently developed [12, 25]. The key observation in both of these works is that the sparsest α-navigable graph problem decomposes into n coupled set-cover instances, one for each source s. For a fixed source s, a candidate outgoing edge (s, u ) covers exactly those targets t for which u gives a valid α-progress step toward t. Thus, choosing the minimum out-neighborhood of s

is precisely a minimum set-cover problem over the set of targets P \ { s}. Solving these n set-cover instances near-optimally yields a near-optimal sparsest α-navigable graph. In fact, it produces an even stronger approximation property: for every s ∈ P , the out-neighborhood of s is approximately the size of the minimum neighborhood of s in any navigable graph. This set-cover formulation immediately yields an O(log n)-approximation to the optimum via the greedy set-cover algorithm, but a direct implementation takes cubic time even only to construct the sets explicitly. The main algorithmic driver of [12] is a randomized simulation of the greedy algorithm, intended to solve each set cover instance without explicit constructions of the sets. At each step, a universe 5element is sampled. Then, all sets covering the element are recorded. The amount of votes a set received is used as an estimator for its size, used to pick larger sets. This produces an algorithm that computes a O(log n)-approximation of the sparsest navigable graph in eO(n · OPT ) time. Pairing this with clever preprocessing that exploits relationships between the different set cover instances reduces the running time for general α ≥ 1 to eO(min {n · OPT , n 2.5}. For the case of α = 1 , i.e., navigable graphs, further dependencies can be exploited to produce a near-optimal eO(n2) running time. The work by [25] includes an algorithm that computes an O(log n)-approximation of the sparsest 

α-navigable graph in eO(n · OPT ) time. It features the same core idea of a randomized simulation of the greedy algorithm seen in [12]. It also includes a potentially faster resource augmented approx-imation algorithm that runs in O(nω · log(∆) /ε ) time, and computes an O(log n)-approximation of the sparsest 2α · (1 + ε)-navigable graph, where ε > 0 can be chosen arbitrarily, and ∆ is the aspect ratio of the point set. Observe that this is a weaker density guarantee as the spars-est 2α · (1 + ε)-navigable graph may be much denser than the sparsest α-navigable graph. This resource augmented approximation is largely comprised of two subroutines. The first subroutine covers a constant fraction of all uncovered source-target constraints, and the second subroutine is used to verify all satisfied constraints. The implementation of the first subroutine introduces the multiplicative 2 in the 2α · (1 + ε)-approximation. Further, for a fast implementation of the second subroutine, specifically by using fast matrix multiplication, distances are discretized, which introduces the multiplicative (1 + ε) approximation term. 

# 2 Preliminaries 

2.1 Navigability and α-Navigability 

Definition 2.1 (Navigable Graph) . Given point set P and distance function d : P × P → R+, we say that a directed graph G = ( P, E ) is navigable if, for any source point s ∈ P and target point 

t ∈ P , s̸ = t, there exists some edge (s, v ) ∈ E such that d(v, t ) < d (s, t ). That is, s has an edge that, when taken, gets closer to t.

Equivalently, for every source s and target t, there exists a directed path p0 = s, p 1, ..., p k = t

from s to t such that ∀i : d(pi+1 , t ) < d (pi, t ). That is for every source-target pair, there exists a monotone path from the source to the target, and thus the most basic form of greedy search will succeed. Navigability has been studied in the nearest-neighbor search literature for decades [5, 12, 22, 25]. While the definition of navigability only guarantees the convergence of basic greedy search for targets that are within P , recent work also shows that multiplicative approximation guarantees can be obtained for points outside of P in an arbitrary metric when using Adaptive Beam Search, a variant of basic greedy search [1].

2.2 Distance Access Model 

Our input is a set of points P = {p1, . . . , p n} together with oracle access to a distance function 

d : P × P → R≥0. A query to the oracle returns the distance between two points in O(1) time. We otherwise treat the points and the distance function as black boxes; in particular, our algorithms do not require access to an explicit representation of the points. We make only two assumptions on the distance function. The first is that d is symmetric, that is, d(pi, p j ) = d(pj , p i).6 The second is that d(pi, p j ) is 0 if pi = pj and positive if pi̸ = pj . This is so that a point is its own nearest neighbor; otherwise, greedy traversal may not converge on a query even on a navigable graph. Notably, we do not require that d is a metric. 

2.3 Reducing Sparsest Navigable Graphs to Minimum Set Cover 

It has been observed independently by [12,25], that the problem of constructing a sparse α-navigable graph over a point set P = {p1, ..., p n} can be cast as a collection of n coupled set cover instances, each with n − 1 elements, and n − 1 sets. Specifically, we have a single set cover instance for each point. The instance corresponding to point pi involves covering all points pk̸ = pi, and has a set for every j̸ = i, denoted by Si→j . Si→j contains every point pj provides a greedy step towards when standing at pi, i.e., all points pk such that d(pj , p k) < 1 

> α

· d(pi, p k). In other words, if we consider source-target α-navigability constraints in which pi is the source, Si→j contains all targets which corresponding constraints are satisfied by adding the directed edge (pi, p j ). Observe that a set cover for this instance corresponds to an out-neighborhood for pi that covers all α-navigability constraints in which pi is the source, and a minimum set cover corresponds to a minimum such out-neighborhood. Consequently, finding minimum set cover for all said instances produces a minimum navigable graph. The relationship between these different set cover instances was leveraged by [12] to produce efficient query access to these instances without explicitly constructing them, which we will review next.

# 3 Fast Resource Augmented Sparsest α-Navigable Graphs 

In this section, we prove our main positive result. Recall from Section 2.3 that for each source point 

s ∈ P , choosing the outgoing neighbors of s is exactly a set cover problem: each possible edge (s, v )

9covers the targets t for which d(v, t ) < 1 

> α

d(s, t ). Thus, constructing a sparse α-navigable graph amounts to solving n set cover instances, one for each possible source. A direct greedy set cover implementation is too slow. Across all sources, there are n set cover instances, each with n−1 candidate sets and n−1 elements. Explicitly materializing all sets already takes Ω( n3) time and space in the worst case. [12] circumvents this cost by avoiding building these sets explicitly. However, it incurs the cost of repeatedly updating the set of uncovered targets. For a source s, these updates can take eΩ( n · OPT α(s)) time, and summing over all sources gives the 

eΩ( n · OPT α)-type bottleneck of prior approaches without resource augmentation. Our main idea is to separate the tasks of proposing a cover for a set of uncovered points and applying that cover to remove those points. Locally, for each source s, we use a voting procedure to choose a batch of promising outgoing edges. Globally, after many such edges have been added across many sources, we use fast matrix multiplication ( VerifyNav ) to recompute which source-target constraints remain uncovered. Thus, the expensive materialization step is not performed after each selected edge, but only after a whole batch of updates. We will show that, for each set cover instance, each batch of edges added covers a constant fraction of the remaining constraints, so only O(log n) such global updates are needed. This is similar to the approach taken by [25], which also sought to repeatedly cover a constant fraction of constraints, but the method we use to achieve this bears closer resemblance to an algorithm described in [19], which computes covers over subsamples of a larger set cover instance. Recall that the VerifyNav procedure requires rounding distances into a small number of ge-ometric buckets, after which it can no longer distinguish between distances within a bucket, up to a (1 + ε) multiplicative factor apart. It can, however, distinguish constraints that are definitely unsatisfied at parameter α from constraints that are definitely satisfied at the stronger parameter 

α(1 + ε). This is why our sparsity bound is measured against the optimal α(1 + ε)-navigable graph: the residual instances we continue to solve may erroneously contain points falsely believed by Ver-ifyNav to be unsatisfied at parameter α, and it may not be until the graph is α(1 + ε)-navigable before it correctly indicates that the graph is fully α-navigable. For clarity, we have the following local notation. For β ≥ 1 and source s ∈ P , let 

OPT β (s) = min {|C| : C ⊆ P \ { s} and ∀t ∈ P \ { s}, ∃v ∈ C such that d(v, t ) < d (s, t )/β } (1) Equivalently, OPT β (s) is the minimum out-degree needed at s to satisfy all β-navigability constraints whose source is s. The theorem below gives a per-source guarantee, and therefore also implies the corresponding global edge bound of Theorem 1.2 by summing over all sources. 

Theorem 3.1. Let P be a set of n points with distance function d and aspect ratio ∆, and let 

α ≥ 1. For any ε > 0, there is a randomized algorithm running in eO(nω log(∆) /ε ) time that constructs an α-navigable graph over P such that, with high probability, every point s ∈ P has out-degree ≤ O(log n) · OPT α(1+ ε)(s).

Before giving the algorithm, we spell out the two ingredients that are combined in the proof. 

Voting as approximate greedy set cover The procedure VoteCover , introduced in [12], can be viewed as a fast randomized simulation of the standard greedy set cover algorithm. The standard greedy algorithm achieves a log n approximation, but naively applied, leads to O(n3) time to find a near-optimal α-navigable graph. Given a source s and a set U ⊆ P \ { s} of currently uncovered targets, VoteCover repeatedly samples uncovered targets from U . A sampled target t

casts a vote for every candidate edge (i.e., set) (s, v ) that would cover it, namely every v satisfying 

d(v, t ) < d (s, t )/α . Sets with many votes are good estimators for sets covering many currently 10 uncovered targets, so the algorithm adds the set with the most number of votes (after ∼ log n

samples), then explicitly updates U by removing every target now covered by that set. This explicit update of U is the bottleneck. Without efficient access to the points covered by a given edge, this is done in VoteCover through a full scan over U . Because the size of U does not shrink quickly enough with each new edge, this takes Ω( n · OPT α(s)) total time in the worst case. Summed over all sources, this is too expensive for the desired nω-time bound – recalling that 

OPT α = Pns=1 OPT α(s), we would obtain a running time of Ω( n · OPT α). It was shown in [12] that a preprocessing step could reduce this cost to amortized eO(n) per source by shrinking the initial size of U when α = 1 , but the approach does not extend in general to α > 1.

Batched verification by matrix multiplication To reduce the cost of updating U , our algo-rithm introduces a second main ingredient: the verification routine of Section 2.5. Suppose first that the distances between input points take only W distinct values. This can be enforced by rounding each continuous distance to the nearest discrete distance scale. For a fixed distance scale, the set of constraints satisfied by the current graph can be found by one Boolean matrix multiplication, as reviewed in Section 2.5. Repeating over all W scales gives a verification procedure running in eO(nωW ) time. By rounding distances geometrically to powers of (1 + ε), we may take W = O(log(∆) /ε ); this is the source of both the (1 + ε) resource augmentation slack and the log(∆) /ε factor in the running time. Our algorithm uses this routine as a global replacement for the expensive scans inside Vote-Cover . Rather than updating the uncovered set after each selected edge, we let every source add a batch of edges, and then use a VerifyNav routine to refresh all their uncovered sets simultane-ously. The rest of this section formalizes this batched voting procedure. In Section 3.1, we define 

PartialVoteCover , which covers a constant fraction of a given residual instance. In Section 3.2, we show how to obtain a fast overall runtime by running this partial cover routine for all sources in parallel and using VerifyNav to update the residual constraints between batches. 

3.1 Partial Cover 

Here we introduce PartialVoteCover (Algorithm 3.1), which differs from VoteCover in one fundamental way: given a set U of uncovered elements, PartialVoteCover is only asked to cover at least |U |/2 elements of U rather than all of them. The way this manifests itself is that Par-tialVoteCover constructs a cover over a sample K of U instead of over U directly. Controlling the size of the sample allows us to bound both the amount of work we do and the number of sets in the partial cover. This approach bears similarity to sampling methods used in prior work on set cover algorithms in sublinear-time models of computation [19]. The voting process is largely as in VoteCover . Each uncovered sample casts votes for the sets containing it until some set receives c ln n votes, where c is a fixed constant. That set is then added to the cover, and the points that voted for it revert their votes for other sets. This repeats until all samples have voted, and the cover is returned.

# 4 Hardness 

This section addresses two natural questions about the algorithms from the previous sections. 1. Can the running time of the resource augmented algorithm be improved? The main bottleneck is the subroutine that, at a fixed distance scale d0, lists all source-target pairs (s, t ) whose 

α-navigability constraints become satisfied after the newly added edges are inserted. In our current implementation, this subroutine is based on fast matrix multiplication and runs in 

O(nω) time. Is there a substantially faster implementation? 2. Can one eliminate the discretization step and obtain a more efficient exact single-criterion algorithm? More precisely, can one efficiently test, in the original metric, which α-navigability constraints are satisfied by the current edge set? Any O(n2.5−ε)-time algorithm for this task, for a fixed constant ε > 0, would improve upon the current worst-case running time of the best known single-criterion algorithm. 19 We formalize the corresponding testing problems and prove hardness results that answer both questions negatively.
