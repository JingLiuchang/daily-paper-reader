## 摘要
基于图的近似最近邻（ANN）索引（如 HNSW）是现代向量搜索的骨干。然而，其庞大的内存占用造成了严重的基础设施瓶颈。虽然向量量化被广泛用于减少存储数据向量所需的内存，但图的边结构日益主导总内存使用。为在线搜索压缩这些邻接表提出了关键的系统挑战：由于解压缩发生在查询处理期间，即在图导航过程中，内存节省不能以查询延迟为代价。本文提出一种专门面向实时 HNSW 路由的压缩技术。通过应用离线图置换来人为诱导结构局部性，我们能够使用 SIMD 加速的整数压缩器（如 Stream VByte）进行快速即时解压缩。在多种真实世界工作负载上评估，我们在压缩率和查询延迟方面均显著优于当前最先进方法。实验结果表明，与未压缩基线相比，我们实现了高达 52.7% 的压缩率，且延迟损失可忽略不计。此外，我们的技术已在 eBay 生产环境中有效部署，实现了高达 44.3% 的边存储减少，且查询延迟没有下降。

## Abstract
Graph-based Approximate Nearest Neighbor (ANN) indexes, such as HNSW, are the backbone of modern vector search. However, their massive memory footprint creates a severe infrastructure bottleneck. While vector quantization is widely adopted to reduce the memory required to store data vectors, the graph's edge structure increasingly dominates total memory usage. Compressing these adjacency lists for online search presents a critical system challenge: because decompression occurs during query processing, i.e., while navigating the graph, memory savings cannot come at the expense of query latency. In this paper, we present a compression technique explicitly tailored for live HNSW routing. By applying offline graph permutations to artificially induce structural locality, we enable the use of SIMD-accelerated integer compressors, such as Stream VByte, for rapid on-the-fly decompression. Evaluated across diverse real-world workloads, we significantly outperform the current state of the art in both compression ratio and query latency. Our experimental results show that we achieve compression ratios up to 52.7% with negligible penalties in latency compared to the uncompressed baseline. Furthermore, our technique has been effectively deployed in production at eBay, achieving up to 44.3% reduction in edge storage with no degradation in query latency.

## 1. 核心问题与研究背景

- **应用背景**：现代检索系统将文本、图像、商品等表示为高维向量，依赖近似最近邻（ANN）搜索。基于近邻图的方法（尤以 HNSW 为代表）因精度—延迟权衡优异，已成为 FAISS、hnswlib、kANNolo 及 Elasticsearch、Qdrant、Weaviate、Pinecone 等系统的主流索引。
- **核心痛点**：HNSW 索引需常驻内存以保证低延迟，内存成为大规模部署的首要瓶颈。向量量化（如 PQ）已广泛用于压缩向量，但**图的边结构（邻接表）在总索引内存中的占比日益突出**——在量化场景（SnowFlake）或低维场景（eBayProducts7M）中，边可占索引内存的 60%–80%。
- **关键系统约束**：邻接表在查询时被**在线解压**（图遍历过程中随机访问），因此压缩不能以查询延迟为代价。熵编码（Huffman/ANS）虽压缩率高，但逐位解码延迟不可接受；参考式压缩（WebGraph）虽在图归档领域成熟，但其解压链开销与 ANN 随机访问模式冲突。
- **研究缺口**：现有文献（如 Meta 的 Severo et al.）主要系统研究向量 ID 压缩，对**近邻图邻接表的在线无损压缩**缺乏深入探索，且已有证据多基于小型稠密数据集。
- **整体含义**：本文旨在回答“能否在几乎不增加查询延迟的前提下，无损压缩 HNSW 邻接表”，并给出可生产部署的方案。

## 2. 方法论

### 2.1 核心思想

采用“**离线图置换诱导结构局部性 → gap（差分）编码 → SIMD 友好的字节对齐整数压缩**”三段式流水线，使解压可在线、按邻接表粒度、无分支地快速完成。

### 2.2 关键分析与设计依据

- **排除参考式压缩（WebGraph）**：
  - HNSW 对每节点施加严格度数上界（实验 M=32，实际平均 30–50 条边），邻接表短且有界，两表最大可共享边数很小，元数据开销难以摊销；这与 Web/社交图的幂律高枢纽结构截然不同。
  - 论文给出理想节省上界公式：对节点 u，`S(u) = max_{v≠u} [ k_{u,v}·B − log₂ C(|N(v)|, k_{u,v}) ]`，其中 k 为两表交集大小、B 为每条边位打包成本、第二项为“从参考表中选择哪些元素被复制”的组合选择成本。
  - 该式已刻意乐观（允许环状/无限参考链、忽略参考 ID 编码、假设理想排序）。实测在 eBayProducts7M 上，尽管理论上 >99.9% 节点存在“有利”参考，聚合节省上界仅 **8.8%**，最优参考中位仅覆盖 8.1% 的边，故判定其性价比不佳并排除。

- **值分布与重排序**：
  - 原始邻接表的零阶熵很高，bit-packing 每值仅比熵多 ≤1.23 bit，说明端点近似均匀分布，定宽打包已接近最优。
  - 直接 gap 编码仅把每值熵从 22.77→18.69 bit（CoCondenser）、22.62→18.52 bit（eBayProducts7M），仍不足。
  - 对节点 ID 做离线置换（对应 NP-hard 的最小线性排列 MLA 问题的启发式近似），可把共现节点映射到相邻 ID，使 gap 集中于零附近。
  - 对比两类划分算法：递归二分（RB，代表 EGB，其增益式细化专为压缩优化）与直接 k 路划分（KaMinPar，可处理 k>1024 的细粒度分组）。重排序后 gap 熵：EGB 降至 16.02/14.99 bit，KaMinPar 降至 15.86/14.90 bit，二者差 <1%。**最终默认选 EGB**：理论上更贴合最小化表内 gap，工程上是轻量原生 Rust 实现，易集成。

- **整数编码器选型**：
  - 在 EGB 置换后的 gap 列表上评测 Zeta、Stream VByte、Fibonacci、Elias Delta/Omega/Gamma、Rice、Bit Packing 等。
  - Zeta 最紧凑（CoCondenser 17.69、eBayProducts7M 16.51 bit/边），但非字节对齐、解码慢；Stream VByte 仅多约 1 bit/边，却可**无分支 SIMD 解码**，且支持块级索引与部分解码/跳过，契合 HNSW 每次只访问部分邻居的随机扩展模式。

- **辅助结构**：kANNolo 用扁平数组存邻居、用单调 offset 数组 `off` 标记各表边界。对 `off` 采用 **Elias–Fano** 编码（n 个取自大小 U 的全集的单调整数，约 `n(2+log₂(U/n))+o(n)` bit）；因 U/n ≤ 2M=64，每元素仅约 8+o(n)/n bit，远优于原始 64 bit，且支持随机访问与单值解压。

### 2.3 系统实现要点

- 在 kANNolo 的 HNSW 中引入**邻接表抽象层**，将物理表示与逻辑遍历解耦，核心搜索算法零修改，可插拔压缩/未压缩后端。
- 压缩以**单条邻接表为粒度**（而非全局扁平数组），解码入口与表边界对齐，实现按需独立解压。
- 解压后的邻居写入**栈上小块缓冲**，消除临时堆分配与重复解码。
- 重排序后，向量与图 ID 一同离线置换，**查询关键路径无需 ID 转换**，仅最终结果经逆置换映射回原始 ID；逆置换用 `⌈log₂N⌉` bit 定宽打包存储，且仅在压缩收益覆盖其开销时启用。

## 6. 主要结论与发现

- **Stream VByte 是唯一同时逼近 Zeta 压缩率与未压缩基线延迟的方法**：压缩比 1.7×–2.1×（Sift1M 最高约 52.7% 空间节省），延迟在 CoCondenser、eBayProducts7M、SnowFlake 上与 Plain 持平甚至更优（eBayProducts7M 在 98% Accuracy@10 下延迟低约 11%），Sift1M 仅有边际开销。
- **Zeta** 压缩最紧（1.7×–2.3×），但解码慢，Sift1M 上慢约 27%、eBayProducts7M 慢约 14%。
