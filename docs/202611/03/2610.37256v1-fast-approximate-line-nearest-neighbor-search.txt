## Abstract 

Approximate nearest neighbor (ANN) search, which retrieves vec-tors close to a given query vector, is a fundamental operation in vector databases. However, emerging applications, such as select-ing source images for photo-based animation and video synthesis, may require matching content while allowing a query-specified aspect contrast, such as an illumination change, to vary; a single query point does not directly express this requirement. In this pa-per, we study approximate line nearest neighbor (LANN) search, where an infinite query line removes the distance contribution along a specified direction while database records remain points. Prior approaches focus on top-1 search only for LANN and can in-cur high construction costs. Converting LANN into ordinary point ANN search through dimension lifting substantially increases index construction and query costs, while direct search on a proximity graph built for ordinary point ANN search can miss distinct regions close to a line. To address these issues, we propose LinePG , which enhances an existing proximity graph with pair edges to facili-tate navigation between separated near-line regions. To find these pair edges efficiently, we first generate region pairs with spatial or graph separation, and near a line. We then score edges between the selected region pairs to guide the point endpoint selections. We con-duct extensive performance studies and confirm the accuracy and efficiency of LinePG in comparison with the baseline approaches. 

## 1 Introduction 

Approximate nearest neighbor (ANN) search is a fundamental op-eration in vector databases [34, 35, 37, 40, 41]. Given a query vector, it retrieves data vectors that are close under a specified distance. Many approaches have been proposed for this ANN query, includ-ing proximity graph methods that navigate between nearby data points [3, 11, 17–19, 23, 27, 36, 42], which are among the state-of-the-art approaches for ANN search. However, emerging applications, such as visual media creation, introduce additional requirements for query processing. Google’s Picasa included a Face Movies fea-ture based on Exploring Photobios, which selects and orders pho-tographs of the same person to create face animations [14]. Both Runway’s Gen-4 References [28] and photo-based time-lapse min-ing [24] need to maintain subject or scene consistency while han-dling illumination differences in video-creation workflows. These workflows motivate retrieving content-consistent objects despite query-specified aspect changes. For example, when assembling a same-subject, same-pose face sequence across illumination changes for video generation, a user needs images that match the subject and pose while allowing lighting conditions to change. An ordinary ANN uses a query point for search, it does not explicitly specify which aspect variation should be disregarded, and can thus favor similar lighting over the characteristics the user wishes to preserve. A directional model of the allowed aspect change provides a way to express this retrieval requirement. Image inversion maps real images to latent representations suitable for editing [32], while latent-direction studies identify approximately linear directions for selected facial-attribute changes [29]. A similar geometric formula-tion arises in query-side tangent-distance methods [15, 30], where a one-parameter image transformation is locally approximated by an affine line, and similarity to a fixed database vector is measured by its minimum distance to this line. These findings motivate rep-resenting a specified aspect change by an affine line 𝑧 + 𝑡𝑢 , where 

𝑧 is an image code, 𝑢 specifies the direction, and 𝑡 controls the amount of change. For retrieval, the objective is to find existing images compatible with the specified variation; we therefore con-sider an infinite line query 𝑧 + R𝑢 , which ranks database vectors by their minimum distance to the line without fixing the amount of change 𝑡 . In the illumination example, two observations of the same subject and pose under different lighting conditions provide a query-specific secant direction through the difference between their embeddings. Motivated by these query requirements, in this paper, we study line nearest neighbor search. Given a dataset P ⊆ R𝑑 , a query is an infinite affine line 𝐿 = {𝑏 0 +𝑡 (𝑏 1 −𝑏 0) : 𝑡 ∈ R} through distinct end-points 𝑏 0, 𝑏 1. The search retrieves 𝑘 nearest data points of the query line 𝐿 , i.e., under the distance 𝛿 (𝑝, 𝐿 ) = min 𝑡 ∈R ∥𝑝 − 𝑏 0 − 𝑡 (𝑏 1 − 𝑏 0)∥ .

The database continues to store one vector per record. The line specifies which component of the difference is not penalized. Due to the curse of dimensionality [10], the exact line nearest neighbor search is computationally intensive. We focus on the approximate line nearest neighbor search (LANN) in this paper, which has not been well studied. If all queries shared one direction, a fixed projec-tion followed by ordinary point ANN would suffice. We consider varying directions and offsets, as in the endpoint-defined workloads, so one fixed projection cannot serve all queries. In the literature, existing approaches for LANN is theoretical studies for top-1 search [2, 26]. They decompose vector data into dense near-line groups and a sparse residual set, but literal group construction is expensive, higher than quadratic in dataset size. Al-ternatively, existing point-to-hyperplane nearest neighbor search [9] provides an insight to solve LANN problem by lifting the vector dimension, and then converts the query into a point query in a higher-dimensional Euclidean space. However, we prove that the lowest dimension we need for LANN problem to solve in such a way is Θ(𝑑 2), which significantly increases the index construction and search cost due to the much larger dimension distance computation that is needed. Another idea is to reuse a proximity graph built for point ANN search and replace its point-to-point comparisons with point-to-line distances. The difficulty is that points close to one line need not be close to each other. They can occupy several regions separated along the line, while paths between those regions pass through points farther from the line. Hence, a search may find enough candidates in one region and stop before entering another region with better results. In this paper, we propose LinePG , which constructs a line-enhanced proximity graph from an existing proximity graph built for point ANN search. The main contributions of this work are summarized below. ➊ We analyze why existing point-search structures can miss multiple near-line regions, motivating pair edges that connect separated regions close to a common line. These edges are used to enhance the original proximity graph to facilitate navigation between separated near-line regions. ➋ To find these pair edges effi-ciently and avoid examining all point pairs, we propose first finding promising pairs of regions. We introduce a balanced hierarchy that considers both vector locations and proximity graph connections to find spatially separated candidate regions, together with a quotient graph that identifies region pairs without short connecting paths. Next, a geometric score combines separation with support near a representative line to rank candidate region pairs. ➌ We propose an edge-scoring mechanism to select pair edges, turning these region pairs into useful edges in the graph for navigation without increas-ing the total degree limit. It selects endpoints whose connecting direction is supported by multiple points in the target region and discourages directions redundant with existing or previously se-lected edges. The selected pair edges enhance the proximity graph, replacing retained original edges only when necessary to satisfy the total degree limit. ➍ We further design a search algorithm for the line-enhanced proximity graph that uses selected pair edges as additional entrances into promising regions while avoiding redun-dant entrances into regions already being explored. ➎ Experiments on six real-world datasets show that LinePG achieves 1 .44–4 .23x QPS of direct search on the original proximity graph when both methods reach at least 99% recall. On other datasets, LinePG can reach higher recall than 99%, while direct search can not. Compared with dimension lifting and existing theoretical methods, LinePG 

achieves QPS speedups of up to 976 .17x and 1 ,665 .63x, respectively, with much smaller index cost, at 100% recall on the 𝑁 = 512 subsets. The paper is organized as follows. Sections 2 and 3 define the problem and discuss existing approaches. Section 4 presents our design. Sections 5 and 6 give the region construction and candi-date region pair selection algorithms. Section 7 describes search, followed by experiments in Section 8. Section 9 concludes this work.

## 3 Limitations of Existing Approaches 

In this section, we discuss the limitations of existing approaches to support LANN search. 

Provable Line ANN Search: Andoni et al. [2] study LANN search with 𝑘 = 1 from a theoretical perspective; we denote their approach as TheoryLP . Its objective is to return, with constant success prob-ability, a point whose distance to the query line is within a factor 

(1 + 𝜖 ) of the optimum. Later work by Mulzer et al. [26] supports fixed-dimensional affine-flat queries, including lines, with improved space bounds. Both guarantees concern one returned neighbor. At a high level, TheoryLP decomposes the dataset into dense near-line groups and a sparse residual set . Dense near-line groups are selected iteratively. In each round, TheoryLP examines axes through pairs of remaining data points, and chooses the axis with the smallest 𝑚 -th point-to-axis distance, where 𝑚 is of order √𝑁 .The points within this radius form a dense group, for which a Cylinder-DS is constructed to reduce line ANN search inside a dense cylinder to a small number of point ANN queries. For the points not handled by sufficiently thin cylinders, i.e., points in the sparse residual set, TheoryLP uses a Projection-DS, which randomly projects the data into a constant-dimensional space and reduces the resulting low-dimensional line nearest-neighbor problem to a geometric ray-shooting problem following Magen [20]. At query time, TheoryLP first uses the Projection-DS over the full dataset to obtain a coarse neighbor ˜ 𝑝 and estimate the relevant distance scale. It then queries the Cylinder-DS structures whose radii are sufficiently small relative to this estimate, while the re-maining points are handled by a Projection-DS.

## 4 Line-Enhanced Proximity Graph 

Section 3 identifies three limitations. Enumerating all point pairs to construct line-specific structures is expensive, and quadratic lifting increases the dimension of every distance computation. Moreover, reusing a proximity graph for LANN search is difficult, since points close to one line may occupy several regions, whereas the graph mainly connects nearby points. Thus, a beam search can explore one region and stop before reaching another. To address these issues, we design a line-enhanced proximity graph, which reuses the original proximity graph and enhances it with a limited number of connections between regions. 

Connect Near-Line Regions: Our key idea is to use original edges in the proximity graph for local exploration and add pair edges to reach other near-line regions. Within a small region, points are close to each other, and the proximity graph already provides useful local connections. The missing connection is often between two regions far apart along the line. When two regions are close to a query line but far apart, we can find a line linking them with a direction highly similar to the query line. To see this, let distinct 𝑝, 𝑞 ∈ 𝑆 𝑟 (𝐿 ) and let 𝑢

Performance metrics: Following existing vector search works [9, 17, 27, 35, 39], we employ QPS (Queries Per Second) to measure efficiency and use Recall to show the accuracy. QPS is the quantity of queries processed per second, while Recall is defined in Section 2. 

Experimental environments : The experiments are conducted on a CentOS Linux server with Intel(R) Xeon(R) Silver 4215 CPU @ 2.50GHz with 128GB memory. All algorithms are implemented in C++17. The code is compiled with g++ 11.5.0 under O3 optimization. For index construction, we report the index time and size on the same machine using multiple threads. For vector search, we set 𝑘 =

10 by default and evaluate the performance of the search algorithms using a single thread following [9, 27, 35, 38], and incrementally adjust parameters within the search algorithm to achieve the desired recall in the experiments. 

Exp. 1: Search Performance Comparison. Figs. 10 and 11 com-pare LinePG with DirectSearch , Lift , and BruteScan on the full datasets with 𝑘 = {10 , 100 } and the 𝑁 = 512 subsets with 𝑘 = 10, re-spectively. The results show that LinePG improves query efficiency at high recall while also extending the recall attainable by direct graph search. TheoryLP is evaluated only on the small bases due to its high index construction cost, as shown in Exp. 2. For full-set 

Lift , construction times out after two hours on CelebA , SIFT and 

GIST , and runs out of memory on FFHQ . It completes on YaleB 

and Multi -PIE , as reported in Table 2. On the full datasets, we first compare QPS when recall is at least 0.99. For 𝑘 = 10, LinePG achieves QPS speedups of 4 .23x, 2 .00x, 2.14x, and 1 .55x over DirectSearch on YaleB , CelebA , FFHQ , and 

Multi -PIE , respectively. For 𝑘 = 100, the speedups are 2 .44x, 1 .86x, 1.71x, 1 .44x, 1 .67x, and 2 .15x on YaleB , CelebA , FFHQ , Multi -PIE ,

SIFT , and GIST , respectively. DirectSearch does not reach 0 .99 re-call on full SIFT or GIST for 𝑘 = 10 within the tested search range. Importantly, the efficiency advantage is not obtained by sacrific-ing retrieval quality. For example, LinePG attains reported recall 1.0 for both values of 𝑘 on full YaleB , CelebA , FFHQ , and Multi -

PIE . On SIFT , its highest observed recalls are 0 .9993 and 0 .9994 for 𝑘 = 10 and 100, respectively, whereas DirectSearch reaches only 0 .9893 and 0 .9924. On GIST , the highest observed recalls of 

LinePG are 0 .9997 and 0 .9995 for 𝑘 = 10 and 100, respectively, whereas DirectSearch reaches only 0 .9899 and 0 .9948. Exp. 5: Scalability. We evaluate the scalability of LinePG on 

SIFT100M [1] by scaling the dataset size from 10M to 100M points. Fig. 16(a) reports QPS achieved at fixed target recalls. As the scale increases, query throughput consistently decreases for all settings, while the method still delivers 394.3 QPS at Recall@10 = 0.95 and 140.8 QPS at Recall@100 = 0.95 on the 100M dataset. The index size (excluding base vectors) curves in Fig. 16(b) exhibit nearly linear growth with data scale for both the underlying HNSW graph and our enhancements. The en-hancement stage is comparable to HNSW construction cost across the full range, which confirms that the overall index construction remains practical even at the largest scale tested. 

## 9 Conclusion 

In this paper, we study the approximate line nearest neighbor search in vector databases. We propose LinePG , which enhances a proxim-ity graph with selected pair edges while retaining the original vector Fast Approximate Line Nearest Neighbor Search 

dimension and total degree limit. Our extensive experiments demon-strate that LinePG outperforms all existing methods for LANN search. At Recall@10 of 0.99, LinePG delivers up to 4.23x QPS of 

DirectSearch , and a higher recall that DirectSearch cannot reach. Compared with Lift , it achieves better search performance while using only 1.86% of the index space and 2.15% of the construction time on full datasets on average. LinePG achieves index construc-tion that is more than 3 orders of magnitude faster, with a much smaller index size and higher search performance than TheoryLP .
