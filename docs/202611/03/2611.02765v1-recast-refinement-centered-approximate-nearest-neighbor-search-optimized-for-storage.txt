## ABSTRACT 

Large-scale ANNS systems often exploit storage in addition to DRAM for supporting vector search. The central question is how to divide the work between memory and storage for achieving both high query throughput-recall and good index maintenance perfor-mance. Existing storage-optimized ANNS paradigms fall short of providing a complete answer: disk-resident graph indexes have difficulty in supporting efficient vector deletions, while posting list based systems often incur larger amount of disk I/Os for queries. In this paper, we introduce a refinement-centered paradigm for storage-optimized ANNS systems. We propose Recast as a concrete design of this paradigm. Recast stores the raw vectors on disk, and keeps an IVF index with our proposed RecastQ quantization encoding in memory. For an ANNS query, Recast selects nprobe inverted lists, and performs SIMD-based FastScan on the RecastQ codes in the lists to compute a list of refinement candidates in mem-ory. Then, it performs disk I/Os to retrieve the candidate vectors, compute exact distances, and refine the top-𝐾 result. To reduce disk I/Os, RecastQ supports the computation of uncertainty intervals so that the true distance falls in the corresponding interval with high probability. Then, we propose a QUIC policy to select a minimal set of candidates to refine based on the uncertainty intervals, thereby minimizing the number of I/Os for retrieving the candidate vec-tors. For index maintenance, both the on-disk raw vectors and the in-memory IVF structure are amenable to insertions and deletions. Experiments on real-world data sets show that Recast processes batched insertions and deletions 3 .10–37 .27 × faster than SPFresh and OdinANN, while its QPS at 0.99 recall changes by at most 6 .9% after updating 50% of the corpus. For static queries at 0.99 recall, Recast achieves 1 .56–2 .01 × the QPS of the strongest baseline with the matched memory budget on each data set, while requiring 1 .22– 6.75 × less external storage than the evaluated systems. At matched in-memory space, RecastQ also provides a better Recall–refinement frontier than RaBitQ.

## 1 INTRODUCTION 

Approximate nearest-neighbor search (ANNS) for embedding vec-tors is widely used in recommendation [39], image retrieval [32],

For suffi-ciently large vector collections, it is often uneconomical to keep all the vectors and the search structures in DRAM. Therefore, large-scale ANNS systems often exploit storage in addition to DRAM for supporting vector search. For storage-optimized ANNS systems, the central question is how to divide the work between memory and storage for achieving high query throughput without sacrificing the recall and index maintenance performance. Existing storage-optimized ANNS systems take two influential paradigms. Disk-resident graph indexes, such as DiskANN [42], Starling [44], and OdinANN [23], store the vectors and a proximity graph on disk and exploit memory for keeping part of the search structures and caching recent entries to accelerate graph traversal. Posting list based systems, such as SPANN [11] and SPFresh [47], store each vector into (possibly multiple) posting lists on disk and use an in-memory index to select and retrieve postings for subse-quent distance evaluation. While both paradigms have shown good storage ANNS performance, neither provides a complete answer to the above question: graph-based solutions have difficulty in sup-porting efficient vector deletions, and posting list based systems often incur larger amount of disk I/Os for queries. In this paper, we would like to rethink the design of storage-optimized ANNS systems. One natural way is to revisit a widely used main-memory ANNS paradigm: IVF PQ with FastScan and Refinement. IVF narrows the search to a subset of inverted lists, vec-tor quantization keeps per-vector state compact, and PQ FastScan accelerates distance computation on compressed codes with SIMD operations [3, 28, 41]. Given the short candidate list computed by IVF PQ with FastScan, Refinement then accesses a small number of candidate vectors and computes exact distances to obtain highly accurate top-𝐾 results. Together, these features form an effective scan-and-refine paradigm that achieves high query throughput-recall performance. At the same time, the IVF structure is known to be amenable to index maintenance. Inspired by the main-memory IVF PQ with FastScan and Re-finement, we propose Recast (Refinement-Centered Approximate nearest neighbor search optimized for STorage). Recast stores the exact vectors on disk, and keeps the IVF structure and quantization codes in memory. Note that quantization can effectively reduce the memory footprint to a small fraction (e.g., 1/4–1/10) of the original data set size. For an ANNS query, Recast selects nprobe inverted lists whose centroids are closest to the query vector, and scans the quantization codes in the nprobe lists to compute the list of refine-ment candidates in memory. Then, Recast performs disk I/Os to retrieve the candidate vectors, compute exact distances, and refine the top-𝐾 result. Recast brings the following benefits:

## 2 STORAGE-OPTIMIZED ANNS PARADIGMS 

We compare storage-optimized ANNS paradigms in this section. Table 1 summarizes the comparison. For fair comparison, we assume the same allocated memory budget across different systems, which is used by in-memory structures for both query processing and update support. We consider five aspects of the design in the table, including three aspects on ANNS query processing, one aspect on index main-tenance, and one aspect on the space cost. (1) Query performance 

summarizes the ANNS throughput-recall performance. (2) Amount of disk data accessed accounts for not only raw vectors but also auxiliary structures retrieved from disk during query processing. (3) 

Dependent I/Os indicates whether an I/O read decision can depend on information returned by previous I/Os in the same query, which may have adverse impact on I/O efficiency. (4) Maintenance support 

qualitatively describes whether and how efficient the systems sup-port vector insertions and deletions. (5) Storage footprint compares the total amount of storage space consumed by vector data and auxiliary structures required by queries and updates. ## 2.1 Disk-Resident Graph Indexes 

Static disk-resident graphs. DiskANN [42] is the first static disk-resident solution. It stores vertices (i.e., exact vectors along with graph adjacency lists) on disk, while keeping compressed PQ codes

and preserving a vertex cache in memory. Starling [44] constructs a sampling-based in-memory navigation graph to get better entry points for the disk graph search, and improves I/O locality by plac-ing vertices and out-neighbors in the same disk blocks as much as possible. MARGO [50] further improves the disk data layout by pri-oritizing out-edges based on their importance in the graph search. GPS [49] appends out-neighbors’ adjacency lists to each vertex en-try on disk so that an I/O obtains more graph structure information. PipeANN [22] gives up the strict compute-I/O order across search steps and issues asynchronous I/Os based on the current candidate pool, regardless of uncompleted I/Os or computation. 

Dynamic disk-resident graphs. For updates, FreshDiskANN [40] follows a main+delta design. It constructs one or more TempIndexes for insertions and a DeleteList in memory, in addition to the read-only disk-resident graph. When the memory is full, FreshDiskANN merges the three structures to compute a new disk-resident graph. IP-DiskANN [46] proposes an in-place deletion algorithm, which approximates the in-neighbors of a deleted vertex by vertices vis-ited during the graph search, but has to periodically scan the full index to remove dangling edges. OdinANN [23] performs direct vec-tor insertions to reduce foreground performance variation during updates. For deletions, it buffers the deleted vector IDs in memory and merges the deletes to the disk graph periodically. 

Representative systems and performance aspects. In this pa-per, we consider DiskANN [42] and Starling [44] as two classical solutions, and OdinANN [23] as the state-of-the-art solution in the paradigm of disk-resident graphs. As shown in Table 1, the graph-based solutions store adjacency lists with vectors on disk, leading to a moderate storage footprint. Moreover, there are dependency among I/O operations during graph search. Furthermore, OdinANN achieves moderate index update performance. However, compared to the static solutions, OdinANN allocates large per-thread I/O buffers for improving I/O efficiency, and keeps significant metadata, such as vector mapping and allocation structures, in memory. Given the same memory budget, OdinANN has to reduce the PQ code length, which leads to less accurate distance estimation, incurring higher amount of disk I/Os and lower query performance. 

## 2.2 Posting List Based Systems 

Static posting list based systems. SPANN [11] performs hierar-chical clustering to generate a large number of posting lists so that each posting fits into a small number of disk blocks (e.g., 10–100KB). Then, it assigns (boundary) vectors to multiple postings for better recall, and constructs an in-memory index on the medoids (i.e., vectors closest to the centroids of postings). A query first searches the in-memory index to obtain candidate postings, then reads the candidate postings to compute the top-𝐾 result. 

Dynamic posting list based systems. SPFresh [47] adds incre-mental in-place update support to SPANN. Vector updates are han-dled locally in posting lists. If a posting exceeds an upper threshold, SPFresh splits it into two smaller ones. If the size of a posting is smaller than a lower threshold, SPFresh deletes it and reassigns its vectors to nearby postings. 

Representative systems and performance aspects. In this paper, we evaluate SPANN [11] and SPFresh [47] as two representative solutions in the paradigm of posting list based systems. As shown in Table 1, they incur high storage cost because vectors can be stored redundantly in multiple postings. Moreover, the I/Os for retrieving postings are independent of each other in a query. Furthermore, since full postings of vectors are retrieved, SPANN and SPFresh read higher amount of disk data than graph based solutions, which can adversely impact the query performance. 

## 2.3 This Paper: Refinement-Centered Paradigm 

We introduce a refinement-centered paradigm for storage-optimized ANNS systems. As shown in Table 1, it achieves a low storage footprint for storing vectors without per-vector adjacency lists or redundant assignment. Moreover, it keeps an IVF structure on com-pressed vector encodings in memory. Both the in-memory structure and the on-disk vectors are update friendly. Furthermore, a query searches the in-memory IVF index to obtain a list of refinement candidates, then issues selective, independent I/Os for retrieving the candidate vectors for refinement. Finally, as will be described in the Recast design, the RecastQ encoding and the Quic policy minimize the number of candidate vectors and the amount of disk I/Os, thereby improving the query performance.

## 5.3 Bit-Gain-Aware Uneven Grouping 

PQ performs even grouping: every dimension group contains the same number of (e.g., 2) dimensions. Since a group is encoded with a fixed number of (e.g., 4) code bits, even grouping treats each dimension equally in essence. However, different dimensions can have significantly different data distributions. We propose uneven grouping in RecastQ to capture the dif-ference across dimensions. The basic idea is to (1) partition the dimensions (for vectors in the transformed space) into uneven groups, which can contain different numbers of dimensions, and (2) keep the fixed number of code bits (i.e., 4 bits) per group. The benefits of uneven grouping are as follows. First, the number of code bits per dimension is lower for groups with larger number of dimensions. This reflects the data variance across dimensions, thereby improving the encoding quality and decreasing the error 

∥e∥. Second, lower errors result in narrower uncertainty intervals, leading to smaller number of refinement candidates and better query throughput. Finally, the resulting code still follows the fixed 4-bit group size, which is compatible to Faiss PQ4 FastScan, and amenable to SIMD acceleration. 𝐿𝑜𝑜𝑘𝑢𝑝𝐴𝑑𝑑 (𝐴, 𝑄, 𝐿 ) widens the 16 bytes in 𝑄 to 16 32-bit indices with 𝑉 𝑃𝑀𝑂𝑉 𝑍𝑋 𝐵𝐷 , performs 16 register lookups with 𝑉 𝑃𝐸𝑅𝑀𝑃𝑆 ,and accumulates the retrieved values with 𝑉 𝐴𝐷𝐷𝑃𝑆 . Finally, the procedure shuffles and returns the decoded values for the 32 vectors in the packed block (Line 13–16). 

Metadata bytes and SIMD-based Quic computation. For each 32-vector code block, RecastQ stores three 32-byte arrays for the encoded norm , scale , and error . During the RecastQ FastScan, the metadata bytes are processed 16 vectors at a time. For each 16 vectors, a 16-byte array is loaded into a 128-bit XMM register. Then, each 8-bit code is widened to 32 bits and decoded in a 512-bit ZMM register. After that, the estimated distance ˆ𝑑 and uncertainty interval [𝐿, 𝑈 ] are computed in SIMD. Given the computed [𝐿, 𝑈 ], Quic uses a masked SIMD compar-ison to reject upper bounds above 𝑐𝑢𝑟𝜃 𝐾 . The remaining upper bounds are inserted to the heap. Quic performs a second SIMD comparison to filter vectors with lower bounds above 𝑐𝑢𝑟𝜃 𝐾 . For the surviving candidate vectors, Quic appends their estimated dis-tances, lower and upper bounds, and computed in-list offsets to a buffer. After the RecastQ FastScan, Quic obtains the global 𝜃 𝐾 ,and re-compares the lower bounds of vectors in the buffer against 

𝜃 𝐾 to obtain the final refinement candidates. In summary, the SIMD-accelerated procedure fuses metadata decoding, reconstruction of ˆ𝑑 and [𝐿, 𝑈 ], global-bound update, and refinement candidate selection, while avoiding the materialization cost of per-vector uncertainty intervals for most vectors.

## 7.2 Static Query Performance 

Figure 3 reports top-10 static query performance. Each column in the figure corresponds to a data set. The upper row reports the measured Recall–QPS frontier, while the lower row reports the number of 4-KiB disk page accesses per query. We see that Recast achieves the best performance across all data sets. At Recall@10=0.99, Recast achieves 1.56–2.01 × the QPS of the strongest baseline with the same memory budget, while reading 1.73–4.10 × fewer pages. This suggests that the high-recall throughput of Recast comes from the reduction of the number of I/Os. Moreover, as the recall increases, the number of I/Os of Recast grows only slightly. Higher recalls typically require larger 

nprobe , i.e., probing more IVF lists, while our RecastQ and Quic policy effectively filter out unnecessary exact-vector refinement. Posting list based solutions incur much higher number of disk I/Os at high recalls because of retrieving whole selected postings, resulting in less competitive query performance. In contrast, graph-based solutions issue fewer I/Os and are generally more competitive than posting list based systems in the experiments. Interestingly, DiskANN out-performs Starling in some cases. Compared to DiskANN, Starling allocates part of its memory budget to the navigation graph and the mapping structures. As a result, the PQ code length is reduced. This pressure is the strongest on DEEP100M because DEEP100M contains float32 vectors compared to the uint8 vectors in SIFT100M and SPACEV100M. Starling has to use 8B PQ codes, incurring significant accuracy degradation of the PQ-based distance estimation. (Note that this is a memory-budget-dependent trade-off, not an inherent claim that Starling is weaker than DiskANN.)

We study the scalability of the storage-optimized ANNS solutions in this subsection. We vary the number of query worker threads from 1 to 72. ## 8 RELATED WORK 

We have studied previous storage-optimized ANNS systems in Section 2. Since Recast builds an in-memory index that stores RecastQ encodings, we discuss the related work on in-memory ANNS indexes and quantization encodings in this section. 

In-memory ANNS indexes. In-memory ANN spans tree and hashing methods such as KD-tree, ball tree, VP-tree, FLANN, and LSH variants [2, 8, 9, 29, 33, 37, 48]; proximity graphs such as HNSW and NSG [15, 26, 34, 38, 43]; and cluster-based indexes such as IVF, IMI, ScaNN, and BLISS [6, 24, 25, 41]. Clustered layouts support contiguous scans that combine naturally with quantization and SIMD execution. Recast uses an IVF-compatible in-memory organization rather than introducing a new coarse-search index; its focus is deciding from compact scan results which exact vectors must subsequently be accessed from storage. 

Quantization encoding and reranking. Compact vector repre-sentations include dimension-wise schemes such as VA-File [45], ITQ [19], and LVQ [1]; additive-codebook methods such as AQ [5] and LSQ [35]; and product methods such as product quantization (PQ) [28] and optimized product quantization (OPQ) [18]. PQ and OPQ encode vectors into short Cartesian-product codes and sup-port asymmetric distance computation. PQ Fast Scan [3], Quicker ADC [4], and related kernels reorganize codes and lookup tables for SIMD execution. These methods primarily optimize approximate ranking, reconstruction, or scan throughput. RecastQ reuses a PQ4 execution substrate but stores the magnitude and directional-error information needed for refinement candidate selection. RaBitQ [17] and Extended RaBitQ [16] combine randomized quantization with bounded distance estimators and lower-bound-guided reranking. They are the closest encoding-level baselines to RecastQ. We use the reference library and native reranking rule rather than replacing it with Recast’s selector. Recast differs in co-designing the uncertainty information, the global Top-𝐾 selec-tor, page planning, and mutable external-store architecture as one system. 

## 9 CONCLUSION 

In conclusion, we have introduced a refinement-centered paradigm for storage-optimized ANNS systems. We have proposed and stud-ied Recast as a concrete design of this paradigm. It enjoys a simple storage layout with low footprint and easy update support, and exploits a compact in-memory IVF index with the RecastQ encod-ings and the Quic policy for efficient query processing. We believe that our proposed solution provides a promising answer to the central design question, achieving high query throughput without sacrificing the recall and index maintenance performance.
