## 摘要
大规模 ANNS 系统通常除 DRAM 外还利用存储来支持向量搜索。核心问题是如何在内存与存储之间划分工作，以同时获得高查询吞吐量-召回率和良好的索引维护性能。现有的存储优化 ANNS 范式未能提供完整答案：磁盘驻留图索引难以支持高效的向量删除，而倒排列表系统在查询时往往产生更多磁盘 I/O。本文提出一种以精化为中心的存储优化 ANNS 系统范式，并提出 Recast 作为该范式的具体设计。Recast 将原始向量存储在磁盘上，并在内存中维护带有 RecastQ 量化编码的 IVF 索引。对于 ANNS 查询，Recast 选择 nprobe 个倒排列表，并对其 RecastQ 编码执行基于 SIMD 的 FastScan，以在内存中识别精化候选。随后从磁盘取回候选向量，计算精确距离，并对 top-K 结果进行精化。为减少磁盘 I/O，RecastQ 计算以高概率包含真实距离的不确定区间。我们的 QUIC 策略基于这些区间选择最小精化集合，从而最小化候选取回 I/O。磁盘上的原始向量和内存中的 IVF 结构均支持插入和删除。在真实数据集上的实验表明，Recast 处理批量插入和删除比 SPFresh 和 OdinANN 快 3.10-37.27 倍，而在更新 50% 语料后，其在 0.99 召回率下的 QPS 变化至多 6.9%。对于 0.99 召回率下的静态查询，在每个数据集上匹配内存预算时，Recast 达到最强基线的 1.56-2.01 倍 QPS，同时所需外部存储比所评估系统少 1.22-6.75 倍。在匹配内存空间时，RecastQ 也比 RaBitQ 提供更好的召回率-精化前沿。

## Abstract
Large-scale ANNS systems often exploit storage in addition to DRAM for supporting vector search. The central question is how to divide the work between memory and storage for achieving both high query throughput-recall and good index maintenance performance. Existing storage-optimized ANNS paradigms fall short of providing a complete answer: disk-resident graph indexes have difficulty in supporting efficient vector deletions, while posting-list systems often incur more disk I/Os for queries. In this paper, we introduce a refinement-centered paradigm for storage-optimized ANNS systems. We propose Recast as a concrete design of this paradigm. Recast stores raw vectors on disk and keeps an IVF index with our RecastQ quantization encoding in memory. For an ANNS query, Recast selects nprobe inverted lists and performs SIMD-based FastScan on their RecastQ codes to identify refinement candidates in memory. It then retrieves candidate vectors from disk, computes exact distances, and refines the top-K result. To reduce disk I/Os, RecastQ computes uncertainty intervals containing true distances with high probability. Our QUIC policy selects a minimal refinement set based on these intervals, minimizing candidate-retrieval I/Os. Both the on-disk raw vectors and the in-memory IVF structure support insertions and deletions. Experiments on real-world data sets show that Recast processes batched insertions and deletions 3.10-37.27x faster than SPFresh and OdinANN, while its QPS at 0.99 recall changes by at most 6.9% after updating 50% of the corpus. For static queries at 0.99 recall, Recast achieves 1.56-2.01x the QPS of the strongest baseline with the matched memory budget on each data set, while requiring 1.22-6.75x less external storage than the evaluated systems. At matched in-memory space, RecastQ also provides a better Recall-refinement frontier than RaBitQ.

## 1. 核心问题与研究背景

- **应用背景**：嵌入向量的近似最近邻搜索（ANNS）广泛用于推荐、图像检索、RAG、LLM 长上下文 KV-cache 等场景；当向量规模很大时，无法把全部向量与索引结构放在 DRAM，必须同时利用 SSD 等外部存储。
- **核心问题**：在存储型 ANNS 系统中，如何划分"内存负责什么、存储负责什么"，以**同时**取得高查询吞吐-召回率与良好的索引维护（插入/删除）性能。
- **现有两类范式均不完整**：
  - **磁盘驻留图索引**（DiskANN、Starling、OdinANN）：查询性能好、访问数据量低，但 I/O 存在依赖关系，且**向量删除困难**（需后台合并、周期性全索引扫描或删除缓冲）。
  - **倒排列表系统**（SPANN、SPFresh）：I/O 独立、更新相对友好，但查询需取回整条 posting，**磁盘 I/O 量大**，且向量冗余存储导致**存储足迹高**。
- **论文定位**：提出"以精化为中心（refinement-centered）"的第三种范式，并给出具体系统 **Recast**，试图同时兼顾查询吞吐、召回、索引维护与存储开销。

## 2. 方法论

### 2.1 核心思想

- 借鉴主存 IVF-PQ + FastScan + Refinement 的成熟范式，将其"下沉"到存储场景：**原始向量存磁盘，IVF 结构与量化码存内存**。
- 查询流程（Algorithm 1）：内存中选出 nprobe 个倒排列表 → 对 RecastQ 码做 SIMD FastScan 得到精化候选 → 按候选的磁盘位置发起**独立异步 I/O** 取回原始向量 → 计算精确距离并精化 top-K。
- 两大挑战及对应设计：
  - 挑战 1（减少磁盘 I/O）→ **RecastQ 编码 + QUIC 选择策略**；
  - 挑战 2（降低内存侧计算开销）→ **PQ 编码质心 + AVX-512 精确浮点 FastScan**。

### 2.2 系统架构与空间开销

- **内存结构**：
  - 列表质心用 PQ 编码（D 个 4-bit 组），质心大小由 4D 降至 0.5D 字节（8× 节省），列表选择获 4.5× 加速。
  - 每个 IVF 列表存打包的 RecastQ 码：M 个 4-bit 码组 + 3 字节元数据（norm、scale、error），即每向量 **0.5M + 3 字节**。
  - 不存向量 ID 与磁盘地址：由"列表 ID + 列表内偏移"直接推算磁盘位置，每向量至少省 4B。
- **磁盘结构**：
  - 每个 IVF 列表对应一个 list file，按相同顺序存 32-bit ID + 原始向量；第 j 个码对应 `(j mod n_B)` 记录、第 `⌊j/n_B⌋` 页。
  - 额外维护 ID→磁盘位置映射（仅删除时使用），可选备份内存结构以加速重启。
  - 磁盘足迹 ≈ N·S（原始向量大小），远小于图索引的邻接表与倒排系统的冗余副本。

### 2.3 RecastQ 编码与不确定区间

- **编码流程**：减去参考中心 c → 计算模长 r 与单位向量 u → 正交变换 T 后按"位增益感知的非均匀分组"量化为 M 个 4-bit 码 → 附带 norm/scale/error 三字节元数据。
- **距离估计**（平方 L2）：`d̂(q,x) = ||q_c||² + r² − 2r/||y'||·⟨q'_c, y'⟩`。
- **不确定区间**：`[d̂ − zτ, d̂ + zτ]`，其中不确定尺度 `τ(q,x) = (1/√D)·2r·||q_c||·||e||`。
  - 确定性界：由 Cauchy–Schwarz 得 `|d − d̂| ≤ 2r||q_c||·||e||`，无分布假设但过松。
  - 概率界：在"方向各向同性"假设下，归一化残差在超球面均匀分布，`√D·γ → N(0,1)`，故真实距离落入区间的概率趋于 `2Φ(z) − 1`（Theorem 5.4）。
  - 元数据溢出时置哨兵值并把区间视为无界，保证不会误排除向量（实测溢出率 < 0.002%）。
- **位增益感知非均匀分组**（Algorithm 3）：按 `b_j = max(0, log₂σ_j − λ)` 计算各维码位需求（总预算 4M），按需求降序贪心分配到剩余预算最大的组；高方差维度获得更多码位，降低量化误差 ||e||，从而收窄区间、减少候选。

### 2.4 QUIC（Query-aware Uncertainty-guIded Candidate selection）策略

- 定义 `θ_K = S 中第 K 小的上界 U_i`；候选集 `C(S) = {x_i : L_i ≤ θ_K}`。
- **质量保证**：若所有区间都覆盖真实距离，则 C(S) 保留 S 中全部真实 top-K（Theorem 4.2）；概率区间下给出期望召回下界 `exp((√2τ/Δ)·I(√2z))`（Theorem 4.3），候选数为 `K + ⌊2zτ/Δ⌋`（Theorem 4.4），说明 z、τ 越小、Δ 越大则候选越少。
- **实现**：FastScan 中维护大小 K 的最大堆求全局 θ_K，SIMD 批量比较过滤上界，再二次比较下界筛选候选；设有 2000 条目的临时短名单兜底（几乎不触发）。

### 2.5 内存侧 SIMD 优化

- **为何用精确浮点累加**：Faiss 常规 uint8 LUT 量化会引入额外残差 δ_LUT，使不确定区间与实际距离不一致；改用 float32 LUT 可在相同召回下减少精化候选。
- **AVX-512 精确浮点 FastScan**（Algorithm 4）：沿用 Faiss PQ4 的 32 向量打包布局，每轮处理一对码组，用 `VPERMPS` 在 ZMM 寄存器内完成 16 路查表、`VADDPS` 累加；元数据字节也以 16 向量为单位 SIMD 解码并融合 QUIC 比较，避免逐向量物化区间。
- **I/O 优化**：候选磁盘位置排序后按同页/相邻页合并，QD=8 异步流水提交。

### 2.6 索引维护

- **插入**（InsertBatch）：分配 ID → 按最近质心分列表 → 批量编码 → 按列表分组并行追加内存码与磁盘记录 → 更新 ID→磁盘位置映射。
- **删除**（DeleteBatch）：查映射 → 校验 → 按列表分组并行执行 swap-with-last（把尾部有效记录搬到被删槽位并截断）→ 更新映射并打墓碑；内存 IVF 列表中**不留墓碑**，查询路径无无效分支。
- 全流程原地更新，**无后台合并/压缩任务**。
