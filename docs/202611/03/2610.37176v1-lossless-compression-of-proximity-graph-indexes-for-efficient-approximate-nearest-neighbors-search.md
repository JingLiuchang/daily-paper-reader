## 摘要
基于图的近似最近邻（ANN）索引（如 HNSW）是现代向量搜索的骨干。然而，其巨大的内存占用造成了严重的基础设施瓶颈。虽然向量量化被广泛采用以减少存储数据向量所需的内存，但图的边结构在总内存使用中日益占据主导地位。为在线搜索压缩这些邻接表提出了关键的系统挑战：由于解压缩发生在查询处理过程中，即在图导航期间，内存节省不能以查询延迟为代价。在本文中，我们提出了一种明确面向实时 HNSW 路由的压缩技术。通过应用离线图排列来人为诱导结构局部性，我们能够使用 SIMD 加速的整数压缩器（如 Stream VByte）进行快速即时解压缩。在多样化的真实工作负载上评估，我们在压缩率和查询延迟方面均显著优于当前最先进水平。实验结果表明，与未压缩基线相比，我们实现了高达 52.7% 的压缩率，且延迟损失可忽略不计。此外，我们的技术已在 eBay 的生产环境中有效部署，在查询延迟不下降的情况下，边存储减少高达 44.3%。

## Abstract
Graph-based Approximate Nearest Neighbor (ANN) indexes, such as HNSW, are the backbone of modern vector search. However, their massive memory footprint creates a severe infrastructure bottleneck. While vector quantization is widely adopted to reduce the memory required to store data vectors, the graph's edge structure increasingly dominates total memory usage. Compressing these adjacency lists for online search presents a critical system challenge: because decompression occurs during query processing, i.e., while navigating the graph, memory savings cannot come at the expense of query latency. In this paper, we present a compression technique explicitly tailored for live HNSW routing. By applying offline graph permutations to artificially induce structural locality, we enable the use of SIMD-accelerated integer compressors, such as Stream VByte, for rapid on-the-fly decompression. Evaluated across diverse real-world workloads, we significantly outperform the current state of the art in both compression ratio and query latency. Our experimental results show that we achieve compression ratios up to 52.7% with negligible penalties in latency compared to the uncompressed baseline. Furthermore, our technique has been effectively deployed in production at eBay, achieving up to 44.3% reduction in edge storage with no degradation in query latency.

- **研究缺口**：已有工作（Severo et al., Meta）系统研究了 ANN 索引的 ID 与倒排表压缩，但对**图邻接表压缩**缺乏深入探索，且已有证据多基于小型稠密数据集（Sift1M、Deep1M、FB-ssnpp）。
- **整体含义**：论文提出一套面向"在线 HNSW 路由"的无损图压缩框架，并在 eBay 生产系统 Cassini 落地，说明该问题具有明确的工程价值与可部署性。

## 2. 方法论

### 2.1 核心思想
**离线图排列（graph permutation）人为诱导结构局部性 → 邻接表 gap（delta）编码 → 字节对齐、SIMD 加速的整数编码器（Stream VByte）在线解压**，辅以 Elias–Fano 压缩偏移数组。

### 2.2 关键分析（支撑设计选择）
- **排除列表级/引用式压缩**：HNSW 有严格度数上界（M=32 时约 64），节点度数集中于上界（CoCondenser 均值 45.3，eBayProducts7M 均值 49.9），邻接表短且有界，重叠有限。论文给出乐观上界公式：
  - \(S(u)=\max_{v\neq u}\left(k_{u,v}\cdot B-\log_2\binom{|N(v)|}{k_{u,v}}\right)\)，其中 \(k_{u,v}=|N(u)\cap N(v)|\)，B 为每边 bit-packing 成本。
  - 该式故意放宽（允许环状/无限引用链、忽略引用 ID 编码成本、假设理想排序）。即便如此，eBayProducts7M 上总节省上限仅 **8.8%**，最优引用中位覆盖 8.1%、90 分位 22.7%，净收益约 101 bits/表。结论：WebGraph 类方法对 HNSW 不划算。
- **值分布分析**：邻接表零阶熵高，bit-packing 每值仅比 \(H_0\) 多 ≤1.23 bits；gap 编码后熵从 22.77→18.69（CoCondenser）、22.62→18.52（eBayProducts7M）；经 **EGB** 重排后降至 16.02 / 14.99，**KaMinPar** 进一步降至 15.86 / 14.90。
- **重排的附带收益**：提升向量空间局部性、缓存复用与预取，使未压缩基线查询时间下降 3.0%（CoCondenser）至 17.0%（eBayProducts7M）。

### 2.3 技术流程
1. **离线重排**：比较递归二分（Metis/PaToH/Scotch、EGB）与直接 k-way（KaMinPar）。默认选 **EGB**——其增益式 refinement 专为压缩优化邻接表分布，且提供原生 Rust 轻量实现；两者差距 <1%。同时存储逆排列（⌈log₂N⌉ bits/ID），仅在压缩收益覆盖其开销时启用。
2. **gap 编码**：邻接表排序后转为单调递增序列并差分。
3. **Stream VByte 压缩**：控制流与数据流分离，每控制字节用 2 bits 描述一个 32 位整数的字节长度（1–4 字节），解码**无分支**、可 SIMD 并行；块级索引支持部分解码与跳过，契合 HNSW 只访问少量邻居的模式。
4. **偏移数组 off 用 Elias–Fano**：单调序列，\(2+\log_2(U/n)\le 2+\log_2(2M)\)，M=32 时约 8 bits/元素（原 64 bits），且支持 Select 随机访问。
5. **工程实现（kANNolo, Rust）**：邻接表抽象层隔离物理表示与逻辑遍历，核心 HNSW 搜索算法零修改；压缩以**单个邻接表为粒度**对齐解码入口；解压邻居写入栈上小块缓冲以避免堆分配；遍历在重排后的本地 ID 空间进行，仅最终结果经映射还原，关键路径无 ID 转换开销。

## 6. 主要结论与发现

- **引用式压缩不适用于 HNSW**：受严格度数上界约束，即便在最乐观假设下节省上限也仅 8.8%，且引入链式解压延迟，故排除 WebGraph 类方案。
- **节点 ID 顺序不反映拓扑**：默认（摄入序）分配下边在 ID 空间近似均匀分布，gap 编码收益有限；EGB/KaMinPar 重排可将 gap 熵再降 2.7–3.6 bits/值。
- **Stream VByte 是最佳折中点**：压缩率接近最优的 Zeta（差距约 4–10%），但延迟与未压缩基线持平甚至在 3 个数据集上更优（eBayProducts7M 在 98% Accuracy@10 下快约 11%），仅在 Sift1M 有边际开销。
- **Zeta 空间最优但延迟代价明显**：最高节省 2.3×（Sift1M），但 Sift1M 上慢约 27%、eBayProducts7M 上慢约 14%。
- **Elias–Fano（用于邻接表）在空间和延迟两个维度均被支配**：比 Bitpacker 更慢且不更省空间（但其用于 off 数组仍然合理）。
- **量化/低维场景收益最大**：边主导内存时压缩价值最高；整体实现最高 52.7%（≈2.1×）边空间缩减，延迟惩罚可忽略。
- **生产可用**：eBay 部署实现 44.3% 图内存下降、召回不变、延迟无退化，使 HNSW 可扩展到更多搜索场景。

## 7. 优点

- **问题定位准确**：抓住"解压发生在查询关键路径"这一系统本质约束，将压缩问题重新表述为"压缩率–解码延迟"的联合优化，而非单纯追求压缩比。
- **先分析后设计**：用度数分布、零阶熵、引用收益上界（公式 1）等定量证据排除错误方向（引用式压缩），再选择编码器，方法论链条清晰、可迁移。
- **重排与压缩协同**：把图重排这一"离线一次性成本"同时用于降低熵与改善缓存局部性，形成双重收益，且论证了 EGB 相对 KaMinPar 的工程合理性（<1% 差距 + 原生 Rust 实现）。
- **实现细节考究**：邻接表粒度对齐解码入口、栈上缓冲消除堆分配、在重排 ID 空间内遍历以避免关键路径 ID 转换——这些都是影响实测延迟的实质性优化。
- **评测可信度较高**：以高度优化的 kANNolo 为统一基线、在等精度下比较延迟、覆盖稀疏/量化/低维/稠密四类真实负载，并给出生产环境验证，超出多数同类学术工作。
- **落地价值明确**：公开实现将进入 kANNolo，且已有 eBay 线上数据佐证。

## 9. 可复现性与工程落地

- **代码与基线**：实现基于开源 kANNolo（Rust），压缩作为邻接表抽象层的一个可选实现接入，核心 HNSW 搜索算法零修改，作者声明将合入主干，这使复现门槛显著低于仅描述算法的论文。
- **公开数据集**：Sift1M、MsMarco-v1（SnowFlake / CoCondenser 两种编码）均为公开基准，超参（M=32、efConstruction、efSearch 与 λ 扫描范围、Zeta 的 κ）报告较完整，主要表格具备可复现基础。
- **不可复现部分**：eBayProducts7M 与 Cassini 线上结果依赖私有数据与内部系统，仅能作为工程可行性佐证，而非可验证的科学结论。
- **落地路径清晰**：以"单邻接表"为压缩/解码单元、栈上小缓冲、在重排 ID 空间内完成遍历并在末端一次性映射回原 ID，这些设计使压缩对上层检索逻辑近乎透明，替换成本低，是该方法能进入生产的重要原因。

## 10. 总体评价与启示

- **定位**：这是一篇"系统导向"的索引压缩工作，其贡献不在于提出新的整数编码器（Stream VByte、Elias–Fano、Zeta 均为已有技术），而在于**用定量分析把设计空间裁剪到可行子集**（排除引用式压缩、排除慢解码器、选定重排 + SVB 组合），并在真实检索栈与生产系统中验证。
- **最有价值的可迁移结论**：① 对"解压位于查询关键路径"的数据结构，压缩方案必须以解码吞吐为一等约束，"高压缩比但需链式跳转/分支解码"的方案在工程上会被支配；② 改变数据的物理排列可以同时降低熵与改善缓存局部性，是"零查询期成本"的预处理红利；③ 压缩的边际价值随"边内存占比"上升而上升，因此量化程度越高、维度越低，收益越大。
- **主要待补方向**：动态插入/删除下的压缩维护、高度数图（M=64–256）与其它图索引（Vamana、NSG、DiskANN）上的验证、与有损图简化的联合优化、高并发下的系统级测量，以及十亿规模下的构建与重排开销评估。
- **结论性判断**：论文较有说服力地回答了"邻接表能否被无损压缩而不牺牲延迟"这一问题——在 HNSW、M=32、1M–8.8M 规模的设定下答案为"能，且收益可观（最高约 2.1×）"；但其外推边界（图类型、度数、规模、动态性、并发）尚未被系统检验，读者在借用其结论时应明确这些前提。
