# ABSTRACT 

Large language model agents accumulate experience in memory, and how that memory evolves during interaction is as important as what it stores. Recent methods update memory online, yet both the operators that transform memory and the rules that select them remain fixed by design. We propose EvoDisco , which formulates agent memory evolution as evolutionary strategy discovery :the agent must discover which operator to apply, when to apply it, and how to instantiate it, rather than rewriting memory under a static operator schedule. A learnable policy conditions on the current memory state and recent task history, then selects and instantiates one of four semantic operators— ABSTRACT , R EFINE , B RIDGE , and R EFRAME —which respectively compress related memories, decompose overloaded entries, connect weakly linked experiences, and reorganize retrieved reasoning chains. The policy is updated with a bi-level fitness. An inner signal scores each transformation using a retrieval-quality improvement regularized by memory complexity. An outer signal scores strategic efficacy over a window of past decisions, combining historical operator-utility regret, utility-prediction error, and selection diversity. Under a one-pass online plus frozen-transfer protocol on ALFWorld, WebShop, and LifelongAgentBench (OS and DB), EvoDisco improves over strong memory baselines including MemP and MemRL. The largest gains are on ALFWorld ( +8 .8 online / +12 .9 frozen-transfer points over MemP; +16 .4 / +17 .9 over MemRL). Ablations attribute these gains to both fitness levels and the operator library. 

Keywords Agent memory · Strategy discovery · Large language model agents · Evolutionary learning 

# 1 Introduction 

Large Language Model (LLM)-based agents have emerged as a powerful paradigm for tackling complex, long-horizon tasks that require reasoning, planning, and multi-turn interaction. However, effective agency in such settings demands more than the ability to solve isolated prompts—agents must accumulate experience, retain task-relevant information across sessions, and selectively reuse past knowledge. This requirement exposes a fundamental limitation of context-only interaction: even with long-context models, relevant information can be diluted or forgotten as interactions grow, leading to unstable recall and degraded reasoning performance. Memory systems have thus become a core module in LLM-based agents. Recent work has increasingly recognized that 

how memory is organized matters as much as what is stored. A growing body of research has moved beyond flat vector retrieval toward structured memory representations, particularly knowledge graphs, which offer superior capabilities for modeling inter-memory relations, enabling multi-hop reasoning, and providing interpretable access. Representative systems include AriGraph [1], which integrates semantic and episodic memories within a unified knowledge graph; Zep [2], which provides a temporal knowledge graph architecture for agent memory; A-MEM [3], which adopts a Zettelkasten-inspired interconnected knowledge network; and G-Memory [4], which employs a hierarchical graph-based memory design. These graph-based approaches have demonstrated significant advantages over unstructured memory in tasks requiring structured access and associative retrieval.

Despite these advances, a critical limitation persists across existing memory systems: the memory structure itself remains static after its initial construction . Most structured memory mechanisms rely on one-time restructuring workflows to build their memories, neglecting ongoing updates and optimization of the memory structures. An advanced agent should progressively enrich and refine its memory structure throughout interactions with the environment. While some recent works have begun to address memory evolution—for instance, HAGE [5] employs reinforcement learning to drive weighted graph evolution, and MemEvolve [6] introduces a meta-evolutionary framework that jointly evolves experiential knowledge and memory architecture—these approaches still rely on fixed evolutionary operators (e.g., mutation and crossover with predetermined probabilities) or manually engineered adaptation mechanisms .This raises a fundamental question: If the agent itself is capable of reasoning about its own memory, why should the way memory evolves be predetermined by human designers? 

In this paper, we propose EvoDisco (Strategy Discovery for Evolving Agent Memory), a novel framework that elevates agent memory evolution from rewriting memory under a fixed operator schedule to discovering how memory should evolve . Unlike prior work that treats evolution as a blind search using fixed genetic operators, EvoDisco enables the agent to discover which evolutionary operation to apply, when to apply it, and how to instantiate it based on the current memory state and recent task performance. The agent maintains a strategy policy —a learnable module that selects from a curated cognitive operator library (abstraction, refinement, bridging, and reframing)—and the policy itself 

undergoes evolution guided by a bi-level fitness function that evaluates both the immediate utility of each operation and the strategic efficacy of the agent’s historical decisions. Figure 1 gives an overview. Our contributions are threefold: • Evolutionary Strategy Discovery. We formulate memory evolution as a learnable strategy-selection problem, shifting from a fixed operator schedule to state-conditioned selection and instantiation of semantic memory transformations. • Bi-Level Fitness with Strategic Efficacy. We introduce a dual fitness framework that evaluates the retrieval-quality change and structural cost of each memory update, together with the policy’s historical accuracy in selecting high-utility operators. • Cognitive Operator Library. We design a curated set of four semantic-level operators—A BSTRACT (com-pressing related memories into higher-level concepts), R EFINE (decomposing overloaded memories), B RIDGE 

(connecting weakly linked experiences), and R EFRAME (reorganizing retrieved reasoning chains)—that provide sufficient expressive power while maintaining controllability. Through extensive experiments on ALFWorld, WebShop, and LifelongAgentBench (OS and DB), we evaluate the learned policy against fixed-strategy and memory baselines. 

# 2 Related Work 

2.1 Memory Systems for LLM Agents 

Memory lets an agent retain experience beyond the current context. Early systems store transcripts, embeddings, or key-value records and retrieve them by semantic similarity [7]. Similarity search is effective for direct lookup, but it provides little support for multi-hop relations or for deciding how stored experience should be reorganized. Graph-structured memory addresses the relational part of this problem. GraphRAG-style pipelines extract entities and relations and use the resulting graph for retrieval and summarization [8–11]. Agent memory systems then keep such graphs online: AriGraph [1] links semantic and episodic memories, Zep [2] indexes a temporal knowledge graph, A-MEM [3] grows a Zettelkasten-style note network, and G-Memory [4] organizes memory hierarchically for multi-agent settings. Other systems do not rely on an explicit graph. Mem0 merges atomic facts [12], MemP distills trajectories into procedures [13], Self-RAG gates retrieved text [14], and MemRL ranks episodic notes with a nonparametric Q-value while the backbone stays frozen [15]. Surveys organize these designs by structure and function [16]. A separate limitation cuts across them: most structured memories are built by a one-time workflow and are not subsequently reorganized as the task distribution changes [17]. 

2.2 Memory Evolution 

Several systems do update memory over time. Production agents already separate declarative, procedural, and episodic stores and run background consolidation to distill or prune them [18]. Surveys describe this line as a shift from storing trajectories, to reflecting on them, to abstracting them into reusable experience [21, 22]. What stays fixed is the evolutionary mechanism itself. Mutation and crossover use predetermined probabilities, edge updates follow a chosen reinforcement-learning rule, and configuration search stays inside a human-specified action space. The agent can change memory content, weights, or a small set of architecture parameters, but it does not learn which kind of reorganization is appropriate for the current memory state. 

2.3 Strategy Selection and Evolutionary Search 

Choosing among strategies is well studied when the strategy is an external behavior. SMART models strategy selection for reasoning as a Markov decision process [23]. MetaClaw continually updates both a base policy and a library of reusable skills [24]. Meta-reinforcement learning gives a broader account of adapting from environmental feedback at test time [25]. These methods select an action in the task, not an edit to the agent’s own knowledge structure. Metacognitive work on LLM agents similarly monitors answers and reasoning traces [26], rather than the rule used to reorganize memory. Evolutionary computation supplies the other nearby toolset. Genetic programming and Genetic Network Programming evolve behaviors or graph-structured programs [27, 28]; LLM-in-the-loop methods mutate prompts or code [29, 30]; and EvoLattice stores a population of candidate behaviors in one directed acyclic graph [31]. The operators in these loops are part of the algorithm design. When evolution is applied to memory, it typically decides which experiences to retain, not how the memory graph should be restructured, and the operator set remains constant. EvoDisco targets that missing choice. Relative to MemEvolve, the learned object is the policy that selects operators, not a schedule of architecture parameters. Relative to HAGE, the agent chooses among qualitatively different semantic edits rather than training one edge representation. Relative to SMART and MetaClaw, the action is an internal reorganization 3EvoDisco arXiv preprint 

of memory. Bi-level fitness then scores both the immediate utility of an edit and the policy’s historical accuracy in choosing high-utility operators. 

# 3 Method 

EvoDisco learns a state-dependent strategy for reorganizing an agent’s persistent memory. Task interactions supply new memories, cognitive operators transform their organization, and observed outcomes guide subsequent operator selection. The backbone language model remains frozen; adaptation occurs through the memory graph and a lightweight strategy policy. Figure 1 summarizes this loop.

3.2 Cognitive Operator Library 

The fixed library O = {O abs , Oref , Obrg , Orefr } contains four semantic transformations. EvoDisco learns their selection and instantiation, not additional operator categories. 

Abstract: consolidate related memories. Given a seed neighborhood, Oabs synthesizes a higher-level concept or reusable procedure and connects it to supporting memories through generalizes edges. A configured pruning criterion optionally removes redundant memories. 

Refine: separate overloaded memories. Oref decomposes a broad memory into more selective units along a temporal, causal, or categorical dimension. The original node is retained as a summary or replaced, depending on the instantiation. 

Bridge: connect separated knowledge. Obrg identifies semantically related but weakly connected memory regions and generates typed relations between them. 

Reframe: reorient edges on a path. Orefr keeps every node’s text and adds no node. It rewrites causes and 

precedes edges along one existing path. The policy selects the frame, and one frozen LLM call returns a reorientation; the executor then reverses or relabels each consecutive pair (Appendix A.8). The executor proposes at most eight candidates for each operator by a fixed rule, and masks any operator whose set is empty. A BSTRACT ranks seeds whose 2-hop neighborhood contains at least two nodes, by neighborhood size and retrieval count. R EFINE ranks hubs by degree. B RIDGE ranks component pairs at graph distance at least 2 by embedding similarity; if none exists and the graph has at least six nodes, it proposes one pair from a two-means split 4EvoDisco arXiv preprint 

of the embeddings. R EFRAME uses a fixed sample of long paths. A second head selects the candidate index by a dot product between candidate features and a learned projection of s.Five categorical heads are sampled from s on every attempt, including heads the chosen operator does not read. Neighborhood radius k ∈ { 1, 2, 3} and pruning level p ∈ { 0, 0.5} are read by A BSTRACT , and B RIDGE also reads p.Child count m ∈ { 2, 3, 4} and a dimension in {temporal , causal , categorical } are read by R EFINE . A logical frame in {temporal_to_causal , causal_to_temporal , effect_cause } is read by R EFRAME . The frozen LLM writes new node text for A BSTRACT , R EFINE , and B RIDGE only after o, c, and θ are fixed. The R EFRAME call returns a reorientation and writes no node. Similarity cutoffs controlled by p are fixed rules (Appendix A.8).

3.5 Online Learning and Evaluation 

The agent processes the online stream once, writing memories after each episode. Evolution is enabled only during the first ρ = 0 .8 fraction of episodes. Within this interval, an attempt is triggered either after T episodes without evolution or by a moving-average score decline exceeding ϵ (Appendix A.9). Both triggers are disabled after the cutoff, while ordinary memory writes continue. Algorithm 1 in the appendix summarizes the procedure. For held-out evaluation, the accumulated memory is frozen: retrieval remains active, but writes and evolution are disabled. This frozen-memory evaluation differs from cross-benchmark policy transfer, where policy parameters are frozen while a new target-domain memory is constructed online. 

# 4 Experiments 

Our experiments examine whether adaptive memory evolution improves online task performance, whether the resulting memory remains useful on held-out tasks, and whether the learned operator-selection policy transfers across environ-ments. We evaluate EvoDisco against six baselines on four interactive benchmarks, followed by component ablations, cross-benchmark policy transfer, and an analysis of computational cost. Representative graph edits are reported in Appendix B.4. 

4.1 Experimental Setup Baselines & Benchmarks. We compare EvoDisco against RAG-based (RAG, Self-RAG), agentic-memory (Mem0, MemP), and MemRL baselines, together with a no-memory agent, under a frozen-backbone setting (Appendix A.3). Evaluations span four benchmarks: ALFWorld (household interaction), WebShop (web shopping), LifelongAgentBench-OS (system administration), and LifelongAgentBench-DB (database manipulation). Details are in Appendix A.2. Every method uses the same frozen backbone, GPT-5-mini; implementation choices are in Appendix A.4. 

Metrics. We report success rate (SR), the fraction of episodes completed successfully. Online SR is this ratio over the training stream, and transfer SR is the same ratio on the held-out split. We evaluate EvoDisco and the baselines under two settings. Runtime Learning assesses the ability to learn and adapt within a single pass over the training stream. Transferring evaluates whether the learned memory generalizes to held-out tasks from the same benchmark once writes and evolution are disabled. 4.2 Main Results 

Table 1 reports full-stream online SR and frozen-memory transfer SR. Cumulative online trajectories and success rates over the final 20% are reported in Appendix B.1. All results are expressed as percentages; differences discussed below are in percentage points. EvoDisco achieves the highest observed online and frozen-transfer SR on all four benchmarks. The largest gains occur on ALFWorld, where it reaches 77 .7% online SR and 88 .6% transfer SR, exceeding the strongest baseline, MemP, by 8.8 and 12 .9 points, respectively. Relative to MemRL, the corresponding gains are 16 .4 and 17 .9 points. On OS, EvoDisco improves over MemP from 71 .7% to 74 .0% online and from 76 .0% to 77 .3% in transfer. The gains are smaller on WebShop and DB: transfer SR exceeds the strongest baseline by 1.0 and 0.8 points, respectively. These smaller margins should be interpreted as numerical differences rather than evidence of statistical significance. The benefit of memory varies substantially across environments. On DB, several memory-based baselines underperform No Memory, whereas EvoDisco reaches 88 .4% online SR and 87 .1% transfer SR, compared with 88 .1% and 84 .9% 

without memory. Adding memory therefore does not uniformly improve performance in this setting. EvoDisco also achieves the highest late-stream SR on ALFWorld, WebShop, and OS, and ties No Memory on DB (Appendix Table 8). Appendix Figure 2 shows that the ALFWorld lead is present throughout training, rather than only in the final aggregate. EvoDisco’s final-20% SR exceeds its full-stream average on ALFWorld ( 82 .4% versus 77 .7% ), WebShop ( 34 .0% versus 32 .8% ), and OS ( 80 .0% versus 74 .0% ). On WebShop, it is the only evaluated method with a late-stream SR above its overall online SR. Because evolution is disabled during this interval, these results are consistent with continued utility of the evolved memory alongside ordinary writes. However, the comparison involves different subsets of tasks and does not by itself isolate the effect of memory growth.

4.4 Analysis 4.4.1 Cross-Benchmark Policy Transfer 

Frozen-memory evaluation tests whether a graph transfers to held-out tasks within its original benchmark. We separately examine whether the operator-selection policy π transfers across benchmarks. Specifically, we initialize the target agent with the MLP weights learned on ALFWorld and keep those weights fixed throughout the target run. Each target memory graph is constructed from scratch using the same one-pass online and frozen-memory evaluation protocol, with no further REINFORCE updates. This experiment therefore transfers the policy, not the ALFWorld memory graph, and still permits memory construction from target training episodes. As shown in Table 3, reusing the ALFWorld-trained policy yields 31 .0% , 75 .3% , and 82 .7% transfer SR on WebShop, OS, and DB, which are 4.0, 2.0, and 4.4 points below the target-trained models. Appendix B.2 is a separate commit log, not the transferred checkpoint, so the gaps should not be read off those frequencies. These results do not establish that the source-trained policy is preferable to an untrained selector; that comparison would require an additional control. 

4.4.2 Computational Cost 

An EvoDisco evolution step consists of local graph-statistics computation and state encoding, a forward pass through the policy network, and an LLM call when the selected operator requires generation or relation inference. Immediate utility is computed locally from retrieval quality and graph complexity; the default implementation does not invoke a separate LLM call to estimate operator effects. Thus, an evolution event requires approximately one operator-generation call when applicable, in addition to local computation, rather than evaluating a population of graph variants through repeated task rollouts. In the reported ALFWorld runs, end-to-end wall-clock time is 21 .6 hours for EvoDisco, compared with 33 .6 hours for MemRL and 36 .8 hours for No Memory. On OS, EvoDisco completes in 4.2 hours, compared with 6.1 hours for MemRL. These measurements include task execution and memory maintenance: successful episodes can end early, while unsuccessful ALFWorld episodes may reach the 50 -step cap, so the lower runtime is total agent cost rather than isolated evolution overhead. 

# 5 Conclusion 

EvoDisco learns which cognitive operator to apply when evolving agent memory, instead of following a hand-specified rule. Its policy selects among A BSTRACT , R EFINE , B RIDGE , and R EFRAME and is trained with bi-level feedback: 8EvoDisco arXiv preprint 

retrieval-quality gain regularized by structural complexity, together with operator-utility regret, utility-prediction error, and selection diversity. The study is limited by a fixed library of four operators, a trigger that is scheduled or heuristic rather than learned, and evaluation with a single backbone and an ALFWorld-only transfer source. Within that scope, EvoDisco matches or exceeds MemP and MemRL on ALFWorld, WebShop, and LifelongAgentBench (OS and DB). The largest gain is on ALFWorld, where online and frozen-transfer success rise by 8.8 and 12 .9 points over MemP, and ablations tie that transfer gap to both fitness signals and learned operator selection.

# A Additional Implementation Details 

This appendix provides the experimental protocol, benchmarks, baselines, and implementation choices deferred from Section 4.1, together with further implementation details for EvoDisco, including the shared hyperparameter setting, operator instantiation settings, the evolution-trigger configuration, the execution of the three component ablations, OS ablations (Table 7), operator-usage statistics, strategic-efficacy trajectories, two qualitative graph edits (Figure 5), and the shared prompt templates (Appendix C). 10 EvoDisco arXiv preprint 

A.1 Evaluation Protocol 

We adopt a one-pass online learning followed by frozen-memory transfer protocol, with the backbone LLM held fixed throughout. Runtime Learning is the online phase: each agent processes the training split once and may write memories after every episode. For methods with memory evolution, evolution is restricted to the first 80% of the training stream. Ordinary memory writes remain enabled throughout the stream, including the final 20% .We report success rate (SR) over the full online stream and separately over its final 20% . The latter measures late-stream performance after evolution has stopped, although ordinary memory accumulation continues; those rates are in Appendix B.1. Transferring is the frozen-memory phase. After the online pass, we freeze all memory state and evaluate on the held-out split without further writes or evolution. Frozen-memory transfer is our primary measure of whether the accumulated memory supports unseen tasks within the same benchmark. 

A.2 Benchmarks 

We evaluate on four benchmarks chosen to cover household interaction, web shopping, operating-system administration, and database manipulation. Within each benchmark, every method uses the same agent loop, split files, backbone LLM, and step budget. Split sizes and budgets are summarized in Table 6. • ALFWorld [32]: A text-based household environment for embodied navigation and manipulation. Each episode states a goal in natural language, such as finding an object and placing it at a destination, and the agent must issue a sequence of high-level actions (navigate, open, take, and place) until the goal holds or the step limit is reached. Success therefore depends on retrieving a multi-step plan that matches the current scene, rather than on a single lookup. We use all 3553 training episodes and the 140 -task in-distribution evaluation split, with a budget of 50 steps per episode. • WebShop [33]: A simulated shopping website on which the agent must satisfy a natural-language product instruction by searching, selecting an item, and choosing options. The environment returns a page observation at each step, so the agent has to keep the instruction constraints in view while navigating search results. In addition to binary success, WebShop assigns a graded purchase score that reflects how closely the chosen product matches the instruction. We use 500 training instructions and 200 validation instructions, with a budget of 15 steps per episode. Reported tables use binary success. • LifelongAgentBench-OS [34]: Interactive Ubuntu/Bash administration tasks. The agent issues shell com-mands, reads their output, and must finish the requested administration steps over a multi-turn session. The benchmark is designed for continual tool use: later tasks reuse commands and patterns that appeared in earlier tasks. We use the official MemRL split of 350 training tasks and 150 validation tasks, with a budget of 15 

steps per episode. • LifelongAgentBench-DB [34]: SQL interaction with a live database. The agent writes queries, inspects results, and revises them until the requested table state or answer is obtained. Tasks share a schema, so a query pattern learned on one task can apply to a later request against the same tables. We use the official split of 361 

training tasks and 139 validation tasks, with a budget of 15 steps per episode. 

A.3 Baselines 

We compare against protocol-matched reimplementations of the memory systems in the MemRL evaluation [15]. Every baseline uses the same frozen backbone, agent loop, splits, and step budgets as EvoDisco. During Runtime Learning a baseline may write after each episode; during Transferring its memory is frozen. None of these systems selects or instantiates a graph-evolution operator. • No Memory : The agent conditions only on the current episode: the task text, the latest observation, and the actions already taken in that episode. It does not write a note, embed past experience, or retrieve anything from previous episodes. This baseline measures task performance when no cross-episode memory is available. • RAG [7]: After each episode the backbone writes a reflection of the trajectory and stores it as an embedding. At the start of a new episode the system embeds the task and returns the top-k notes by cosine similarity. Retrieval ranks notes by cosine similarity alone. Both successful and failed episodes are stored, so later retrieval can surface either kind of note. • Self-RAG [14]: Self-RAG uses the same note store as RAG and adds a decide-then-critique filter. Before retrieval, the backbone answers whether stored memories would help the current task; a negative answer skips retrieval. When retrieval runs, each candidate is marked keep or drop, and only the kept notes are passed to the 11 EvoDisco arXiv preprint 

agent. The filter is intended to suppress notes that are similar in embedding space but not useful for the current instruction. • Mem0 [12]: A memory layer that maintains a persistent store through add, retrieve, and update operations. After an episode it extracts one to three atomic facts—a lesson, a constraint, or a working pattern—rather than saving the raw trajectory. Each fact is embedded and compared with existing notes. If the nearest note has cosine similarity of at least 0.82 , that note is overwritten with the new fact; otherwise the fact is inserted as a new note. Retrieval is the same cosine top-k used by RAG. • MemP [13]: A procedural-memory method. On a successful episode it distills the trajectory into a numbered, high-level procedure that states the sequence of operations that worked, and stores that procedure for later retrieval. The stored text is this distilled procedure. On a failed episode it does not add a new procedure; it instead lowers the reliability of the procedures that were retrieved for that episode. The resulting store is updated by this build–retrieve–update cycle and is queried by cosine similarity. • MemRL [15]: An episodic-memory baseline that keeps the backbone frozen and ranks stored notes with a two-phase score. The first phase retrieves candidates by semantic similarity; the second re-ranks them with a non-parametric Q-value estimated from past task outcomes. The memory topology is held fixed: MemRL updates the utility used at retrieval, and it does not rewrite, merge, or restructure the stored notes. We use the same frozen-backbone protocol as the other baselines. • Fixed-Strategy Evolution : This variant is an ablation of EvoDisco. Each variant clamps the operator to one of A BSTRACT , R EFINE , B RIDGE , or R EFRAME and applies that operator at every evolution step. The candidate and the instantiation parameters are still sampled, but the policy receives no REINFORCE update, so the choice of operator does not change with experience. These four runs are reported in Section 4.3 and Appendix A.13.

A.9 Evolution Trigger 

We use a hybrid evolution trigger. A.12 Component Ablation Execution 

The rows w/o Outer Fitness , w/o Inner Fitness , and w/o Cognitive Operators in Table 2 and Table 7 each remove one component of the evolution step. The online-then-frozen protocol, splits, backbone, step budgets, retrieval, ordinary memory writes, hybrid trigger, and 80% evolution cutoff are those of the Full run. An attempt is applied only when the chosen edit commits a graph change. 

Without outer fitness. Outer fitness is the strategic-efficacy signal Ei (Section 3.3.2) that trains the strategy policy. This variant keeps the cognitive operators and immediate utility, and disables policy selection and policy learning. At each evolution attempt the executor builds the same per-operator candidate sets as Full. It then draws an operator uniformly among those with a nonempty candidate set, draws one candidate uniformly from that set, and draws the instantiation uniformly from the grids in Section 3.2: radius k ∈ { 1, 2, 3}, child count m ∈ { 2, 3, 4}, pruning threshold, decomposition dimension, and logical frame. The drawn operator is executed with the same generator used by Full. Immediate utility follows the committed-edit rule in Eq. equation 4, and a non-committed attempt stores Ui = −0.05 .The MLP is not queried, and the REINFORCE update that would apply Ei every N events is skipped, so later attempts remain uniform over the valid candidates. 

Without inner fitness. Inner fitness is the immediate utility Ui (Section 3.3.1). Candidate construction, policy sampling, cognitive-operator execution, and the outer-loop update every N = 5 events match Full. The retrieval-quality change and the complexity penalty are omitted from the recorded outcome: every event stores Ui = 0 , whether or not 15 EvoDisco arXiv preprint 

the operator commits an edit. The utility predictor is supervised with these zero targets. The replay buffer, which admits only events with Ui > 0, receives no events. Strategic efficacy is still evaluated on the resulting history, so \Regret i

and PredErr i are computed from zero utilities while Div i remains the operator entropy of the window. The policy therefore continues to update, and the update no longer depends on retrieval quality or structural complexity. 

Without cognitive operators. This variant keeps the hybrid trigger and replaces the library 

{ABSTRACT , REFINE , BRIDGE , REFRAME } with three structural edits. No candidate set is built, the policy is not queried, and the language model is not called to author new node text. Each attempt draws one edit uniformly. • Add edge. Two distinct nodes are drawn uniformly. A relation is drawn uniformly from analogous-to ,

causes , precedes , and is-a , and inserted with weight 0.5.• Delete edge. One existing relation is drawn uniformly and removed. When the graph contains no relations, the attempt commits no edit. • Merge. Two distinct nodes are drawn uniformly. The retained node’s text is the concatenation of the two contents, truncated at 2000 characters. Its embedding is the ℓ2-normalized sum of the two embeddings, and its confidence is their arithmetic mean. Relations incident on the discarded node are rewritten onto the retained node, after which the discarded node is removed. Immediate utility is computed on the edited graph and stored. The policy receives no update, so the next edit is again a uniform draw over the three structural edits. A graph with fewer than two nodes commits no edit. The fixed-operator rows are a separate intervention. Each clamps o to one named cognitive operator. The initial MLP still samples that operator’s candidate and the instantiation heads in Section 3.2, and those weights receive no REINFORCE update. These rows do not use the structural edits above.
