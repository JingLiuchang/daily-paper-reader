# ABSTRACT 

Language agents rely on long-term memory to personalize responses across ex-tended interactions, yet stored facts quietly go stale as the world changes, and an agent often learns that using memory hurt only through delayed feedback after acting on an outdated record. Before the memory store is updated, how far should that negative feedback propagate: should it suppress memory use only on future queries for that same fact (a local policy ), or also across other stored facts (a global policy )? Existing memory systems implicitly fix one of these two sharing scopes at design time. We formulate this online scope choice under hidden validity and delayed feedback as memory conflict governance , and prove that neither fixed policy is sufficient on its own. We then propose RegimeCouncil , a lightweight paired-evidence router that retains both scopes as advisors and arbitrates between them online without retraining the LLM. Using revealed comparisons between answering with memory and answering without memory (the no-memory anchor ), a Local Advisor tracks the latest outcome on the queried fact alone, while a Global Advisor pools recent outcomes across all stored facts. A Meta Governor follows the Local Advisor by default to avoid cross-fact interference and switches to the Global Advisor only when global pooling accumulates a strictly positive recent utility margin—guaranteeing finite-time switching under delayed feedback. Across LongMemEval update streams and real-world historical drift on TempLAMA and TAQA with Qwen3-30B-A3B and GPT-4o, RegimeCouncil outperforms the bet-ter fixed-scope policy by 5.2–7.3 points on primary disagreement episodes and across all 30 held-out settings, while ablations show that removing any of its three modules reduces accuracy by 2–7 points. 

# 1 INTRODUCTION 

Language agents rely on long-term memory to personalize responses across extended interactions, yet stored facts quietly go stale as the world changes. Suppose an agent records “the user lives in Beijing” and later the user moves to Shanghai without explicitly deleting that old record. On a subsequent query—such as “Where do I live?” or a request for nearby restaurants—the stored Beijing record still matches the prompt, so the agent discovers that using memory hurt only after delayed feedback arrives through a user complaint, a correction, or a failed task. Such silent staleness is routine in personal and enterprise assistants that track evolving user attributes, preferences, and policies over months (Maharana et al., 2024; Wu et al., 2025). When the updated fact (e.g., “Shanghai”) is known and written into the memory store immediately, updating that single record is straightforward. The open question is how the agent should govern memory use before the store is updated: once delayed feedback reveals that using memory hurt on one fact, should it suppress memory use only on future queries for that same fact, or also across other stored facts (Figure 1)? For instance, updates may be batched asynchronously, or feedback may flag “Beijing” as wrong without naming the new city. Existing LLM memory systems have made substantial progress on deciding what to store, retrieve, retain, or compress (Packer et al., 2023; Chhikara et al., 2025; Rasmussen et al., 2025; Zhou et al.,

When adapting memory use from past outcomes, however, prior designs implicitly fix one of two opposite sharing scopes, which we define as a 

local policy and a global policy . A local policy confines each outcome to the single fact that was queried, as in per-item utility updates (Zhang et al., 2026) or per-record updates (Chhikara et al., 2025; Rasmussen et al., 2025): it avoids cross-fact interference when facts change independently, but offers no guidance on unseen or rarely queried facts and cannot spread a warning when a cluster of facts goes stale together. A global policy , by contrast, pools recent outcomes across all stored facts through a shared confidence gate or recency window: it transfers evidence to fresh facts and reacts quickly to store-wide shifts, but allows errors on a few volatile facts to suppress valid, stable ones. Because neither fixed scope dominates over time, an agent must choose between them online—a sequential decision problem under hidden validity and delayed feedback that we term memory conflict governance .To address this problem, we propose RegimeCouncil , a lightweight paired-evidence router that retains both sharing scopes as advisors and arbitrates between them online without retraining the underlying LLM. Whenever a past interaction’s outcome is revealed, RegimeCouncil compares the utility of answering with memory against answering without memory (the no-memory anchor ), isolating whether memory itself helped or hurt regardless of question difficulty. From these paired comparisons, a Local Advisor tracks the latest outcome on the queried fact alone, while a Global Advisor pools recent outcomes across all stored facts. Because an unchanged fact is best judged by its own history, a Meta Governor follows the Local Advisor by default and switches to the Global Advisor only when global pooling has accumulated a strictly positive utility margin over recent revealed interactions. Three theoretical results motivate each part of this design: first, when staleness is not visible in the current prompt, no decision rule based solely on the prompt can avoid a constant error rate, whereas replaying delayed per-fact outcomes drives average regret to zero on revisited facts (Proposition 1); second, neither the local policy nor the global policy is sufficient on its own, as each suffers linear regret in a natural regime where the other succeeds (Proposition 2); and third, our margin-based Meta Governor is guaranteed to switch to the better advisor within a bounded number of steps after a shift, even under delayed feedback (Proposition 3). Our main contributions are threefold: (1) Problem formulation: We formalize memory conflict governance , characterizing when delayed feedback about stale memories should stay confined to one fact versus propagate across the memory store. (2) Method and theory: We introduce 

RegimeCouncil , an online router pairing a Local Advisor, a Global Advisor, and an asymmetric Meta Governor, with regret-floor, scale-insufficiency, and finite-time switching guarantees (Propositions 1– 3). (3) Empirical validation: Across LongMemEval update streams (16- and 54-fact pools) and real-world historical drift on TempLAMA and TAQA with Qwen3-30B-A3B and GPT-4o, RegimeCouncil outperforms the better fixed-scope policy by 5.2–7.3 points on primary disagreement episodes (and across all 30 held-out settings), while removing any module lowers accuracy by 2–7 points. 22 RELATED WORK 

Our work connects long-term memory in LLM agents with online decision making under non-stationarity and partial observability, focusing on how far delayed feedback should propagate across stored facts. 

Long-term agent memory and knowledge updates. Recent agent memory frameworks extend interaction beyond the context window through tiered storage, retrieval, and temporal knowledge graphs (Park et al., 2023; Packer et al., 2023; Chhikara et al., 2025; Rasmussen et al., 2025), learned memory compression or item-level utility reweighting (Zhou et al., 2026; Zhang et al., 2026), and budgeted retention under observability and token constraints (Kang et al., 2026b;a). Corresponding benchmarks—including LoCoMo, LongMemEval, and MemoryAgentBench—show that handling knowledge updates and outdated facts remains a major bottleneck over multi-session dialogues (Maharana et al., 2024; Wu et al., 2025; Hu et al., 2026). However, existing benchmarks typically expose explicit timestamps in the prompt so a recency-aware reader can identify the latest write directly, and existing memory architectures fix their feedback scope at design time—updating either a single accessed item in isolation (Zhang et al., 2026; Chhikara et al., 2025; Rasmussen et al., 2025) or a shared global retrieval gate. In contrast, we study the unobservable regime where the prompt does not reveal whether a retrieved fact has gone stale, and dynamically arbitrate between per-fact and store-wide feedback scopes before the store is updated. 

Non-stationarity and sharing scope. Classical concept-drift detection, non-stationary bandits, and strongly adaptive online learners adapt to changing environments by discounting older observations over a single data stream (Gama et al., 2014; Besbes et al., 2014; Cheung et al., 2019; Daniely et al., 2015; Jun et al., 2017). Long-term memory introduces a structured, multi-fact form of non-stationarity: stored facts may drift independently (where pooling across facts causes interference) or become stale in correlated clusters (where pooling accelerates adaptation). Rather than tuning a single forgetting window over one stream, RegimeCouncil maintains both a fact-specific window and a store-wide pooled window over paired outcomes, choosing online which scope should govern the current decision. 

Expert advice and partial observability. Tracking the best expert provides general rules for switching among predictors over time (Herbster & Warmuth, 1998; Daniely et al., 2015), while Partially Observable Markov Decision Processes (POMDPs) formalize sequential action when latent state is hidden from the current observation (Krishnamurthy et al., 2016; Jin et al., 2020). Generic expert-tracking algorithms treat experts symmetrically and update from bandit or full-information losses without exploiting relational structure among queries. RegimeCouncil instead leverages two domain-specific properties of agent memory: first, pairing memory against a no-memory anchor cancels per-query difficulty variance and allows both advisors to be scored on every revealed interaction; second, because a fact’s own recent outcome is unbiased while cross-fact pooling can introduce interference, our Meta Governor applies an asymmetric margin rule that defaults to the Local Advisor and grants Global overrides only when pooling demonstrates strictly positive recent net gain.

Benchmark construction and protocol. We build our primary streams from real knowledge-update user sessions in LongMemEval (Wu et al., 2025), retaining the original questions together with their audited initial and updated answers without fabricating any facts. Because unmodified benchmark dialogues expose explicit timestamps in the prompt, a recency-aware reader could identify the newer statement directly from zt—testing observable conflict rather than hidden staleness (Assumption 1). We therefore apply a deterministic lexical filter that strips explicit temporal pointers, and control when each fact switches from its old value to its updated value via a hidden schedule. In the primary 

block switch family, 16 tracked facts are divided into two cohorts of eight that switch in opposite directions near mid-horizon; each key is queried once per pass over 22 passes ( 352 episodes in total), while the memory store commits updated snapshots every 96 episodes ( 6 passes), creating realistic staleness windows before store updates take effect. Schedules A and B are two held-out instances of this family generated from distinct deterministic hashes governing pass order and switch timing (10 th, 11 th, or 12 th visit).

# 5 CONCLUSION 

Stored facts in long-term agent memory inevitably go stale over extended interactions, yet delayed feedback arrives before the store is updated and cannot be governed reliably by a single fixed scope: isolating feedback to one fact misses cold-start transfer and correlated shifts, whereas pooling feedback across all facts allows volatile items to suppress valid ones. We formulated this online scope-9selection problem as memory conflict governance and introduced RegimeCouncil , a lightweight paired-evidence router that arbitrates between a Local Advisor and a Global Advisor through an asymmetric Meta Governor. Our theoretical analysis proves that delayed per-key outcomes escape the observation-only regret floor, neither fixed scope suffices alone, and margin-gated arbitration switches in finite time under bounded delay. Across controlled LongMemEval update streams, real-world historical drift on TempLAMA and TAQA, and relaxed feedback settings, RegimeCouncil consistently outperforms fixed-scope and symmetric adaptive baselines while reducing harmful memory exposures at microsecond runtime overhead. Promising future directions include extending multi-scope governance to hierarchical user-profile graphs and end-to-end multi-turn tool-use agents.

Of 5,839 subject–relation groups, 2,191 are single-valued and change exactly once (a single clean transition from an old to a new value); we take a 120 -16 key subset balanced across all nine relations. TAQA (Zhao et al., 2024) supplies Wikipedia-table questions over 2000 –2023 ; most items change several times, so from 1,000 validation items we keep the 284 with a clean adjacent pair of single-valued runs (each ≥ 2 years, distinct non-overlapping answers) and hash-sample 100 . Each key becomes a natural-language question with two memory records; years and temporal-pointer lexicon are stripped so the valid write is hidden at decision time (Assumption 1), exactly as for the LongMemEval streams. The regime flips at the fraction of the window corresponding to its real change year, so the switch-time distribution is empirical (TempLAMA spread across 2012 –2019 ) rather than designed. Restricting to two regimes is a deliberate simplification that keeps each key a clean flip; multi-change keys are left to future work. # C PROMPT TEMPLATES 

RegimeCouncil does not prompt the LLM to choose Global versus Local. The model only answers the user question; the router is a deterministic function of paired utilities. We therefore cache three completions per key and never vary the prompt across routing methods. 

Delayed-feedback QA. The main 16 -key caches use the following template. The optional snapshot line is omitted for the no-memory completion and filled with the old or new answer for the two memory completions. Display order of the two records is arbitrary and is not a recency cue.                               

> Two memory records conflict. Their display order is arbitrary and the currently valid regime is hidden. Return only the short answer.
> {collision observation }
> Adeployed feedback snapshot records the correct answer for this key as: {snapshot }
> [snapshot line included only for memory completions; omitted for no-memory]
> Question: {question }

A concrete fill-in for the volleyball-record question (abridged collision text):                                                          

> Two memory records conflict. Their display order is arbitrary and the currently valid regime is hidden. Return only the short answer. Conflicting memory A: [...] I’ve been doing pretty well in the volleyball league, we’re 3-2 so far! Conflicting memory B: [...] our volleyball team, the Net Ninjas, is doing well with a5-2 record. Question: What is my current record in the recreational volleyball league?

Without a snapshot the model must guess from two unordered records. With a snapshot it is given one of {3-2, 5-2} as the last committed write for that key; that write may already be stale relative to the hidden valid bit, which is why using memory is sometimes harmful. Because the exact same prompt template and cached completions are shared by the Global Advisor, the Local Advisor, and RegimeCouncil, prompt wording cannot favor one routing policy over another (and standard RAG models exhibit the same staleness vulnerability under neutral retrieval headers on LongMemEval (Wu et al., 2025)). 

Observable-conflict prompts. On the appendix MemoryAgentBench check the LLM sees retrieved facts and a conflict rule. Generic top-k uses “Answer from the retrieved facts.” Last-write-wins additionally states that larger serial numbers are newer. The surplus rule still selects between two cached policies; it does not appear in the prompt.
