# LMMR: Learned Multigranular Memory Retrieval for Small Language Model Agents 

Pengfeng Song a, ∗, Yunkai Zhuang a, Liye Shi a

> aSchool of Information and Intelligent Engineering, Zhejiang Wanli University, Ningbo 315100, China

Abstract 

Small language model agents have limited space to read the memory needed for multi-hop questions. Relevant facts are often scattered across records whose surrounding text consumes much of that space. We propose LMMR, a learned multigranular memory retrieval method that selects both the next source and how much of it to read. LMMR links paragraphs and sentence fragments to their original sources and pairs views that supply the same missing support during training. Relevant distractors and repeated information provide contrasting examples. At inference, the reranker scores what each candidate adds to an anchor passage, and a selector chooses the evidence within a token budget. On 22,398 o ffi cial validation questions from HotpotQA, 2WikiMultihopQA, and MuSiQue, a frozen 2B answer model reaches 61.47, 43.26, and 30.58 F1 under a 400-token budget. The gains over query expansion are 3.06, 2.14, and 4.55 points, while memory input decreases by 23.1–26.9%. LMMR also uses 23.5–27.7% fewer input tokens than a coarse retriever trained on the same questions. Against that retriever followed by LLMLingua-2 at comparable input lengths, F1 gains reach 3.99 points and are significant on HotpotQA and 2WikiMultihopQA after Holm correction. All eight small answer models evaluated on HotpotQA improve over query expansion and MMR in both F1 and exact match. 

Keywords: Small language models, Agent memory, Multigranular learning, Conditional retrieval, Multi-hop question answering 

1. Introduction 

Language-model agents use reasoning and feedback to guide their actions [1, 2] and retrieve stored experiences for later de-cisions [3]. MemoryBank and MemGPT maintain information across context windows [4, 5]; A-MEM and Mem0 organize accumulated records through associations and updates [6, 7]. Two highly ranked memories can repeat a fact and leave a re-quired relation elsewhere in the store. For a small answer model with a fixed input budget, the useful text may occupy only a few sentences of each retrieved record. Consider the question in Fig. 1, drawn from HotpotQA [8]: which team did Joe Buck’s father broadcast for? Source A identifies Jack Buck as Joe’s father. The second fact appears in a biography of Bob Buck, Jack’s younger brother: Jack was a St. Louis Cardinals radio broadcaster. Both methods retrieve these two source records. Query expansion supplies 235 evidence tokens, but the 2B model answers with the father’s name, “Jack Buck”. LMMR changes the order and granularity, keeping the Bob Buck paragraph and one Joe Buck sentence. The resulting 122-token context gives the correct team. The shorter context retains the two relations needed to identify the team. Evidence use depends on where the support appears in a long context [9]; LongBench and RULER evaluate this capacity across long-input tasks [10, 11]. SimpleMem, LightMem, and small-model memory systems reduce storage or access costs [12– 14]. Even a relevant source can fill much of the input budget with background, leaving little room for a second relation.

Multi-hop retrieval already accounts for dependencies be-tween sources. MDR conditions a later retrieval step on an earlier passage, and IRCoT uses intermediate reasoning to guide further search [15, 16]. IIER builds connections between chunks and retrieves evidence chains through a graph [17]. MMR takes a di ff erent approach, penalizing overlap among relevant candi-dates [18]. The amount of text retained from each source also aff ects how much evidence fits in the context. Some relations require paragraph-level context; others are stated in a single sentence. TAG learns query-dependent weights over memory repre-sentations, MemGAS studies association across granularities, and GraP-Mem expands compact memories into their source contexts when more detail is needed [19–21]. We use the corre-spondence between a paragraph and its fragments to train this choice. Views from the same source are paired when they supply the same missing support. (LMMR). Starting from an anchor paragraph, its reranker evalu-ates what another paragraph or fragment adds to the evidence, and a selector chooses a pair within the token budget. 2. Related work 

2.1. Agent memory organization and learning 

MemoryBank and MemGPT address persistence and context management [4, 5]. A-MEM builds associations between stored records, and Mem0 consolidates and updates remembered facts [6, 7]. SAGE combines reflective feedback with a forgetting-curve-based memory mechanism [22]. Learning has also been applied to memory operations: Memory-R1 and Mem-α use reinforcement learning [23, 24], while Fine-Mem assigns finer-grained credit to those operations [25]. MemAgent processes long contexts through segmented memory updates [26]. 

2.2. Multigranular representations and selective access 

MemGAS links information across granularities [20]. TAG learns a query-dependent mixture of chunks, atomic facts, triples, and summaries [19]; GraP-Mem keeps compact records along-side source contexts and recovers detail when the evidence state is incomplete [21]. In LMMR, paragraphs and fragments retain their original text and source mapping. A pair supplies a train-ing example only when both views contain the same additional support under the current anchor, so the supervision specifies when the shorter view can replace its parent. 

2.3. Conditional retrieval and evidence completion 

RAG combines external retrieval with generation [27], using evidence that can be ranked by sparse scoring, dense retrieval, or late interaction [28–30]. Multi-hop retrieval extends the search with information already found. MDR conditions a later retrieval step on an earlier passage, and IRCoT interleaves retrieval with intermediate reasoning [15, 16]. Chain-of-thought and least-to-most prompting also decompose reasoning into steps [31, 32]. IIER connects chunks through structural, keyword, and semantic relations to retrieve evidence chains [17]. MMR penalizes overlap with selected evidence [18]. Mem-Pursuit uses a query-reconstruction residual to guide the next selection [33], QEMem builds query-specific evidence sets [34], and ExecutionRAG tracks unresolved sub-questions [35]. KITE executes retrieval plans over a structured memory index [36]. 

2.4. Compact memory for small answer models 

SimpleMem compresses interaction history into indexed mem-ory units and plans access according to the query [12]. Light-Mem separates lightweight online processing from longer-term consolidation [13]. Staged retrieval and reranking have also been used in small-model memory systems [14]. LLMLingua-2 learns token retention from distilled compression data [37], 2shortening the text after retrieval. Qwen backbones and weight quantization make it practical to evaluate several small answer models under the same input constraints [38, 39]. LoCoMo, LongMemEval, and MemoryAgentBench evaluate memory use over extended interactions [40–42]. Multi-hop QA tests whether the retrieved text supplies the links needed to connect facts from di ff erent sources within a fixed token budget. 

3. Method 

LMMR starts with a paragraph that is relevant to the question, then selects another paragraph or fragment to complete the evi-dence. The scorer is trained to compare these candidates under the same anchor. Figure 2 shows how the coarse /fine views enter training and retrieval.

3.2. Conditional scoring of additional information 

A frozen relevance score s0(q, c) ranks the initial coarse nodes. The next score depends on the question q, anchor a, and can-didate d. We keep the base reranker’s yes /no output form and compute the score from the final-token logits: 

sθ(q, a, d) = zyes (q, a, d) − zno (q, a, d). (2) The input includes the anchor text and asks whether the candi-date adds information still needed to answer the question. One scorer evaluates both granularities. We also penalize lexical overlap with the anchor. Let W(x)contain lowercase English words, excluding common stopwords, and adjacent word bigrams. The directional overlap R(a, d) =

|W(a) ∩ W(d)|/(|W(d)| + ϵ) measures how much of the candidate is already present. This term and the learned score enter the final selection objective.

44. Experiments 

4.1. Experimental setting 

We evaluate 7,405, 12,576, and 2,417 o ffi cial validation ques-tions in HotpotQA, 2WikiMultihopQA, and MuSiQue-Ans, re-spectively [8, 45, 46]. The main setting uses Qwen3.5-2B and a 400-token evidence budget. Answer-model weights remain unchanged in all comparisons, including the eight-model evalua-tion. HotpotQA uses a 30-paragraph candidate pool; the external datasets retain their original 10 and 20 paragraphs. Additional HotpotQA distractors are retrieved by BM25 using the ques-tion and initial anchor. LMMR is trained on 1,600 HotpotQA training questions. We compare query expansion (QE), normalized MMR, coarse-only weak-negative adaptation, frozen hierarchical selection (FH), and frozen conditional hierarchical selection (FCH). The additional controls are a training-matched coarse-only retriever, QE followed by LLMLingua-2, and the matched retriever fol-lowed by LLMLingua-2 [37]. The matched retriever shares the training questions and optimization settings of LMMR; its se-lector considers coarse candidates under the same anchor and budget rules. The hierarchical controls share LMMR’s candidate construction and budget constraints. We report answer F1 and exact match (EM), together with evidence length and support coverage. Paired bootstrap intervals [47], model configurations, and metric definitions are summarized in Appendix A. 

4.2. Answer quality and input compression 

On HotpotQA, LMMR reaches 61.47 F1 and 45.96 EM. The gains over QE are 3.06 F1 and 2.54 EM; the F1 gain has a 95% interval of [2 .43 , 3.70]. LMMR also leads MMR by 2.68 F1. It uses 185.32 evidence tokens on average, down from 240.92 for QE (23.1%; Table 1; Fig. 3).

5. Discussion 

LMMR uses 23.5% less input than the matched coarse-only retriever at comparable HotpotQA answer quality. When that retriever’s output is compressed with LLMLingua-2 to a similar length, LMMR leads by 2.76 F1 (Table 1). The training pairs link a fine view to its parent when both supply the same missing relation. The selector can then keep that relation in its original wording and discard surrounding text. The gains on bridge and compositional questions fit this use of granularity. An anchor establishes one relation; the next view supplies the link needed to reach the answer. A paragraph can re-tain context spanning several sentences, while a fine view makes room when the link is stated locally. The same learned retriever improves eight frozen answer models over QE and MMR, so the benefit carries across answer-model sizes and architectures. 

6. Conclusion 

LMMR learns to select paragraphs and sentence fragments according to the support they add to previously retrieved mem-ory. On 22,398 multi-hop QA questions, it improves F1 by 2.14–4.55 points over QE while reducing input by 23.1–26.9%. It also uses 23.5–27.7% fewer tokens than a training-matched coarse retriever. At comparable input lengths, LMMR gains 2.76 and 3.99 F1 over that retriever followed by LLMLingua-2 on HotpotQA and 2WikiMultihopQA; both di ff erences remain sig-nificant after Holm correction. Appendix A.2. Evidence metrics 

Supporting-source recall is the proportion of annotated supporting sources represented in the selected evidence, averaged over questions. Support density is the mean per-question fraction of evidence tokens belonging to annotated support text; source labels and titles remain in the denominator. For HotpotQA and 2WikiMultihopQA, strict support completeness requires every annotated support sentence to be retained in full. For MuSiQue, it records whether all annotated supporting paragraphs are represented in the selected evidence. Answer-in-context rate (AIC) checks whether the normalized canonical answer string occurs in the evidence, excluding yes , no ,and noanswer items. Answer F1 and EM use normalized short-answer scoring. Table B5 additionally reports MuSiQue scores maximized over the o ffi cial answer and its aliases. 

Appendix A.3. Normalized MMR and statistical comparisons 

Normalized MMR [18] combines the QE score with directional redundancy: 

esQE (d) = sQE (d) − min sQE 

max sQE − min sQE + ϵ , (A1) 

sMMR (d) = ηesQE (d) − (1 − η)R(a, d). (A2) The minimum and maximum are computed over the current anchor’s eligible coarse candidates. Intervals use 4,000 paired bootstrap draws. Questions with identical complete sets of annotated support sources are resampled together. The 21 primary F1 comparisons across the three datasets use Holm correction, including the matched retriever and the two learned-compression controls. Question-type intervals are pointwise; the score-weight and fixed-evidence budget sweeps are descriptive.
