Abstract —Multi-vector retrieval models such as ColBERT achieve state-of-the-art effectiveness by representing documents as sets of token-level vectors and scoring via MaxSim, but their high computational cost limits scalability to large corpora. Existing approximate methods face fundamental bottlenecks: centroid interaction matrix approaches require computing a full matrix at every query and rely on GPU-accelerated clustering, while data-oblivious compression methods yield unstable recall that requires repeated compensation. Graph-based approaches may retain existing centroid-clustering and residual-compression pipelines, operate at the document-set level with complex con-struction procedures, or demand specialized GPU hardware. We propose SIMQ (Single Graph Index for Multi-vector Query), a framework that bridges single-vector graph indices and multi-vector retrieval through data-aware sampling-based clustering and per-token graph navigation, simultaneously bypassing all aforementioned bottlenecks. SIMQ organizes all token vectors into fine-grained clusters via data-aware sampling, builds a single graph index over cluster centroids independently of PLAID’s residual representation, and approximates the MaxSim score through per-token graph search without materializing any in-teraction matrix or relying on GPU acceleration. We provide theoretical analysis showing that, under a manifold assump-tion and successful cell retrieval, data-aware partitioning has a smaller expected approximation error than a data-oblivious partition. Building on this foundation, SIMQ+ further introduces count-based scoring and a dynamic candidate set to improve robustness across varying query conditions. Experiments on five benchmarks compare recall, throughput, and construction time against several baselines, primarily on CPU; large-scale PLAID 

k-means centroids are built on a separate GPU machine. SIMQ has been integrated into VSAG, an Ant Group’s open-source vector search library. 

Index Terms —multi-vector retrieval, approximate nearest neighbor search, data-aware partition

Existing multi-vector retrieval methods each face fundamen-tal limitations rooted in their partitioning strategy. PLAID’s [3] centroid-based approach, although data-aware in its k-means clustering, is forced by the interaction-matrix bottleneck to keep the number of centroids K small; each centroid must then cover a large, semantically diverse region that may span multi-ple clusters, and running k-means over hundreds of millions of token vectors further requires GPU acceleration. IGP [4] adds graph navigation over PLAID’s existing clustering centroids, but retains the underlying clustering and residual-compressed token representation. MUVERA’s [5] LSH partitioning, by contrast, is data-oblivious: the random hyperplanes slice the space, which mixes semantically distinct tokens into the same cell. Repeating the pipeline many times compensates for the resulting recall variability. Designing an efficient multi-vector retrieval framework faces three key challenges: (C1) Data-aware partitioning without GPU. Producing fine-grained, semantically coherent clusters typically requires k-means clustering over hundreds of millions of token vectors, which is prohibitively slow on CPU and depends on GPU acceleration. A partitioning strategy must remain data-aware while avoiding iterative convergence. 

(C2) Avoiding the interaction matrix bottleneck. Any approach that computes a full centroid-query interaction matrix at every query faces a fundamental trade-off: reducing the number of centroids hurts cluster granularity, while increasing it raises the per-query cost proportionally. The framework must bypass the interaction matrix entirely while retaining fine-grained cluster-ing. (C3) Robust approximate scoring. Under a fine-grained arXiv:2611.22079v1 [cs.IR] 17 Nov 2026 partition, centroid inner products are uniformly close to 1 for all retrieved centroids, making the approximate scores of different candidate documents similar in magnitude. A robust scoring mechanism must separate relevant documents from irrelevant ones under such near-uniform centroid similarity. In this paper, we propose SIMQ (single graph index for multi-vector query), a framework that bridges single-vector graph indices and multi-vector retrieval through a data-aware centroid graph. SIMQ organizes all token vectors into fine-grained clusters via sampling-based data-aware partitioning, builds a single graph index over the centroids, and com-putes the approximate score fM(d, Q ) through per-token graph search, where Q indicates a query and d denotes a document. SIMQ constructs its token-level partition through sampling, assignment, and local splitting, then indexes the updated cluster centroids. SIMQ addresses (C1) with sampling and graph-guided assignment, followed by local splits for over-sized clusters, rather than corpus-wide iterative k-means. It addresses (C2) by bypassing the interaction matrix. SIMQ+ addresses (C3) with count-based scoring and a dynamic candi-date set. We provide a theoretical analysis that under the stated manifold and successful-cell-retrieval assumptions, SIMQ’s data-aware partitioning has smaller expected approximation error than MUVERA’s data-oblivious LSH partitioning. To summarize, we make the following contributions:

B. Existing Multi-Vector Retrieval Approaches 

Existing methods partition token vectors, but differ in whether they preserve token-level interactions or compress each document into a single vector, and whether their par-titions adapt to the data or not. 

PLAID. PLAID [3] applies data-aware k-means to cluster the 

N p token vectors into K centroids. It preserves the multi-vector structure by computing a K × m centroid–query-token interaction matrix, then progressively refines the candidate documents and exactly reranks them. Residual quantization compresses token storage. The full interaction matrix is a query-time bottleneck, while clustering very large token sets typically requires GPU acceleration. 

MUVERA. Let b be the number of binary hash bits per parti-tion, dproj the projected dimension per cell, and R the number of independent partition repetitions. MUVERA [5] uses data-oblivious LSH to partition tokens into 2b cells, then aggregates and projects each cell into a fixed-dimensional encoding (FDE) of size 2bdproj per document. These encodings can be indexed as single vectors. To reduce the instability of randomized partitions, MUVERA repeats this process R times and aver-ages the scores. The cells do not adapt to token distributions, and compressing low-dimensional token embeddings may lose useful information. Before optional product quantization, the FDE space is O(R2bdproj N ), growing exponentially with b

and linearly with R.III. SIMQ F RAMEWORK

B. Data-Aware Sampling-Based Partitioning 

SIMQ adopts a data-aware sampling-based partitioning strategy derived from the Point Aggregation Graph (PAG) [6]. PAG is a proximity graph structure over a sampled subset of vectors, called aggregation points , that supports efficient nearest-neighbor navigation for the remaining residual points .Aggregation points are obtained via uniform random sampling and used to construct a proximity graph; residual points are subsequently assigned to their nearest aggregation point. PAG builds a high-quality partition without iterative clustering, achieving significantly lower construction cost than k-means while remaining entirely data-aware. In SIMQ, we adapt PAG to the multi-vector retrieval set-ting: aggregation points serve as initial centroids. After token assignment and splitting of oversized clusters, each centroid is updated to its cluster’s normalized mean. A single query graph index is built over these updated centroids for efficient per-token navigation. Compared with PLAID’s k-means clustering, the PAG-based partition has two key advantages. First, it avoids the iterative Lloyd’s algorithm that must scan all N · p token vectors in each iteration until convergence, reducing the build time from O(N · p · I) full-data iteration work (i.e., I is the number of iterations) to graph-guided assignment, with approximately logarithmic search cost per token under fixed search settings; this comparison excludes local splitting and final graph construction and suppresses vector dimension and centroid-comparison costs. Second, the initial centroids are sampled directly from the data, thus follows the empirical data distribution; by contrast, k-means centroids are arithmetic means that may fall between clusters in low-density areas, par-ticularly when K is constrained to be small. After assignment and local splitting, SIMQ updates each centroid to its cluster’s normalized mean, then final centroids need not coincide with observed token vectors. 

C. Motivation 

The main bottleneck of PLAID [3] is that computing the full K × | Q| centroid–query interaction matrix at every query is mandatory. As illustrated in Figure 3, changing the cluster number K cannot resolve this, as decreasing K increases document candidate filter costs while increasing K inflates matrix computation costs. Additionally, producing PLAID’s centroids via k-means requires processing all token vectors and typically relies on GPU acceleration at scale. Rather than computing this full matrix, SIMQ leverages data-aware sampling and graph-based indexing to navigate each query token directly to its most relevant centroids, naturally bypassing irrelevant ones. This allows SIMQ to use far more centroids than PLAID without the associated computational penalty, yielding smaller and more precise clusters while keeping query-time cost low and avoiding GPU dependency entirely. > α

Cluster Assignment and Splitting. We first build a tempo-rary graph-index Ginit over the sampled centroids. For each remaining token vector, graph search on Ginit approximately identifies its nearest centroid for assignment. The online scheme described below updates the graph during assignment. Because uniform sampling can under-represent locally dense regions, some sampled centroids may receive many vectors from the same region. We therefore enforce a maximum cluster size T . There are two ways to enforce this bound: 

Online split-insertion. Clusters exceeding T trigger imme-diate splitting using a farthest member as the new centroid, followed by local reassignment and incremental graph inser-tion. This handles local density well but couples assignment with graph mutation, requiring synchronization and limiting it to single-threaded builds. Extra insertions can also degrade construction efficiency and search quality in less robust graph backends. 

Deferred recursive k = 2 splitting. Vectors are assigned against a fixed centroid set before oversized clusters undergo recursive binary splitting until all sizes are ≤ T . Final cen-troids are inserted into the graph in a single phase. Decoupling assignment from graph mutation enables safe parallelization with minimal clustering overhead.

The theoretical analysis in §IV shows that SIMQ’s data-aware partitioning produces fine-grained, semantically coher-ent cells, where each cell contains vectors from a small, locally coherent region of a semantic cluster. Under such a partition, the centroid of each cell closely approximates its member vectors, and query tokens that are semantically similar to document tokens are more likely to effectively cover them through graph search. This causes relevant documents to accumulate hits across more query tokens, naturally separating them from irrelevant ones. SIMQ+ is designed around this observation, introducing count-based scoring and a dynamic candidate set to further improve retrieval quality. Figure 4 illustrates the SIMQ+ pipeline. Given a query 

Q, the per-token centroid search and raw document-pool construction are shared with basic SIMQ. However, SIMQ+ counts all documents in each raw pool, without per-token approximate-document-score filtering or top-nd truncation. The key modifications are in the scoring and candidate se-lection stages: (1) instead of computing approximate MaxSim scores fM(d, Q ) from centroid inner products, SIMQ+ assigns each candidate document a hit count cnt (d) reflecting how many distinct query tokens retrieved it; (2) instead of selecting a fixed top-kr candidate set, SIMQ+ collects candidates in decreasing order of cnt (d) and stops at the first count level at which the accumulated candidate count reaches the minimum reranking candidate count Nmin , retaining all ties at that level. If fewer candidates are available, all are retained. The selected candidates are then re-ranked by exact MaxSim computation 

M(d, Q ).Figure 5 illustrates the ranking-reversal bad case that moti-vates SIMQ+. A relevant document with a high exact MaxSim score can be represented by an approximate lower point, while an irrelevant document with a lower exact score can be represented by an approximate upper point. The approximate ranking may therefore reverse the order of the two documents before exact re-ranking. We call a document d underestimated 

when its approximate score satisfies fM(d, Q ) < M(d, Q ),and overestimated when fM(d, Q ) > M(d, Q ). A relevant document with a high exact MaxSim score may therefore be pushed downward by an underestimated proxy, while an irrelevant document with a low exact score may be promoted by an overestimated proxy. The resulting inversion is espe-cially harmful when a fixed candidate cutoff separates the two documents. This is the failure mode that motivates the count-based scoring and dynamic candidate selection in SIMQ+. 

A. From Inner Products to Count-Based Scoring 

Under SIMQ’s fine-grained partition, each centroid cj

lies close to its member vectors. Since all vectors are ℓ2-normalized, the inner product ⟨qi, c j ⟩ between a query token and a nearby centroid is close to 1 for all retrieved centroids. As a result, the approximate MaxSim scores across different candidate documents become similar in magnitude, and the 

relative ordering of documents is driven more by how many 

query tokens hit each document than by the precise inner product values. This motivates replacing inner-product scoring with count-based scoring. For each candidate document d ∈ Smi=1 Ui, let

A document’s count reflects the number of distinct query tokens for which it was covered, providing a more robust signal than inner product values when centroids are close to their member vectors. Count-based scoring treats all hits equally, flattening the tail of the score distribution and reducing the advantage of spurious high-scoring irrelevant documents that arise from fa-vorable centroid alignment. When the number of query tokens 

m is large, relevant documents accumulate hits across more tokens due to semantic relevance, and count-based scoring naturally produces a clear separation between relevant and irrelevant documents. From a probabilistic perspective, the expected hit count of a document d is E[cnt (d)] = Pmi=1 P (d ∈ U i), where the probability is taken over the randomness of the query. For a relevant document whose token vectors are semantically close to many query tokens, P (d ∈ U i) is high for a large fraction of tokens, yielding a large expected count. For an irrelevant document, P (d ∈ U i) is small for most tokens, yielding a small expected count. The difference in expected counts provides a robust signal for separating relevant from irrelevant documents, which is more reliable than the fine-grained inner product values when centroids are close to their member vectors.

In this section, we evaluate the performance of SIMQ and SIMQ+ through extensive experiments on five benchmark datasets. We evaluate index construction and query processing on CPU-based systems to demonstrate the practical efficiency of our approach. PLAID’s large-scale k-means centroids are the exception: because CPU construction was prohibitively slow, those final centroids were generated on a separate GPU machine. We aim to answer the following research questions:  

> •

RQ1: How does SIMQ compare with state-of-the-art multi-vector retrieval methods in terms of recall, query throughput, and index construction time?  

> •

RQ2: How does the PAG-based clustering strategy compare with alternative clustering methods (e.g., k-means and LSH) in terms of retrieval quality and query throughput?  

> •

RQ3: How does SIMQ+ improve upon SIMQ, and what benefit does its count-based scoring and dynamic candidate selection provide?  

> •

RQ4: Can SIMQ support different graph-based ANNS backends? 

A. Experimental Setup 1) Datasets: We evaluate our methods on five widely-used information retrieval datasets from the BEIR benchmark [14] and the ColBERTv2 evaluation suite [2]:  

> •

Quora : A duplicate question retrieval dataset with 522,931 passages and 10K queries. Each query seeks semantically equivalent questions.  

> •

SciDocs : A scientific paper retrieval dataset with 25,657 passages and 1K queries, where queries are paper titles and relevant passages are abstracts.  

> •

NQ (Natural Questions) : A large-scale question answering dataset with 2,681,468 passages and 3.5K queries, derived from Google search queries and Wikipedia articles.  

> •

HotpotQA : A multi-hop question answering dataset with 5,233,329 passages and 7.4K queries, requiring reasoning across multiple documents.  

> •

2) Baselines: We compare SIMQ and SIMQ+ against the following state-of-the-art multi-vector retrieval methods:  

> •

PLAID [3]: A multi-stage retrieval engine built on Col-BERTv2, employing residual quantization and a centroid interaction matrix for candidate pruning.  

> •

MUVERA [5]: It reduces multi-vector retrieval to single-vector retrieval via Fixed Dimensional Encodings (FDEs) using LSH-based partitioning and random projections.  

> •

> •

GEM [15]: A native graph-based index for multi-vector retrieval, which constructs proximity graphs over document vector sets using set-level clustering and bridges between local graphs. All methods use the same ColBERTv2 token embed-dings [2] with dimension h = 64 and the same evaluation qrels. Unless otherwise stated, we report Recall@100@100. 

3) Metrics: We evaluate the following metrics:  

> •

Recall@ k@k: For each query, we divide the size of the intersection between the exact top-k documents under MaxSim and the retrieved top-k documents by k, then average this fraction over the evaluation queries. The main experiment reports k ∈ {20 , 50 , 100 }; unless otherwise stated, the remaining experiments use k = 100 . 

> •

Queries Per Second (QPS) : The number of queries the system can process per second, measuring throughput.  

> •

Index Construction Time : The time required to build in-dexes, including any clustering or graph construction steps.

4) RQ4: Flexibility across Graph Backends: SIMQ treats the centroid graph as a replaceable ANNS backend: any graph-based backend that indexes the cluster centroids and supports nearest-centroid search can provide the navigation stage of the framework. HNSW is the default implementation used in the main experiments, rather than a requirement of SIMQ. To demonstrate this flexibility, we evaluate three representative backends: HNSW [7], NSG [9], and DPG [16], on NQ and HotpotQA. We retain the same PAG-based partitioning, candidate generation, and exact MaxSim reranking pipeline, replacing only the graph construction and search algorithms. All backends use deferred recursive K = 2 partition refine-ment after token assignment. We keep the shared retrieval parameters fixed across back-ends, so the comparison examines substituting the centroid-navigation backend within SIMQ. Figure 9 shows that all three backends support SIMQ’s retrieval pipeline, demonstrating that its centroid navigation is not tied to HNSW. Their curves exhibit different recall– throughput trade-offs, so backend substitution preserves the framework while allowing different performance characteris-tics. HNSW, NSG, and DPG provide representative empirical validations of this modular design; the reported performance comparisons concern the measured NQ and HotpotQA results. 

C. Summary of Experimental Findings 

The experimental results lead to the following conclusions: 1) SIMQ and SIMQ+ provide competitive retrieval quality and efficiency against PLAID, MUVERA, IGP, and GEM across five diverse datasets; exact operating-point claims are reported in the corresponding figures and tables. 2) At nearly matched Recall@100@100, PAG achieves re-trieval quality close to k-means with comparable or higher QPS. Its sampling and graph-guided assignment provide a more CPU-friendly construction path than repeated global k-means iterations; Table III reports re-trieval metrics, while LSH is shown only at its available lower-recall operating point. 3) SIMQ+’s count-based scoring and dynamic candidate set address ranking reversals caused by biased approximate scores under fine-grained partitioning. 4) SIMQ separates its multi-vector retrieval pipeline from the underlying centroid-navigation backend. Experiments with HNSW, NSG, and DPG on NQ and HotpotQA demonstrate that the backend can be replaced with-out changing partitioning, candidate generation, or exact reranking; the recall–throughput trade-off varies with the chosen backend. VII. R ELATED WORK 

Multi-Vector Retrieval Models. ColBERT [1] and Col-BERTv2 [2] use token-level MaxSim scoring, which is com-putationally expensive. PLAID [3] accelerates this via k-means centroids and residual quantization (also adopted by XTR [17] and WARP [18]), though it faces bottlenecks in ma-trix granularity and GPU-dependent clustering. Alternatively, MUVERA [5] compresses documents into fixed-dimensional encodings (FDEs) via LSH and random projections; however, its data-oblivious partitioning requires R hash repetitions to stabilize recall. 

Graph-based Multi-vector Retrieval. GEM [15] builds a dual proximity graph over document vector sets, decoupling Earth Mover’s Distance based construction from Chamfer scoring via semantic shortcuts, though its set-to-set compu-tations scale with token length. IGP [4] builds a proximity graph over PLAID centroids using incremental probing for candidate generation while retaining PLAID’s quantization. VecFlow-Chamfer [19] is a GPU-optimized multi-vector re-trieval method for high-throughput systems. 

Data Partitioning for Retrieval. Partitioning approaches vary: PLAID uses data-aware yet GPU-heavy k-means clus-tering, while MUVERA relies on fast but data-oblivious LSH. DSANN [6] introduces the Point Aggregation Graph (PAG) via sampling for data-aware partitions without iterative clustering. SIMQ adapts PAG for multi-vector retrieval, delivering fine-grained, stable clusters without GPU dependency. 

Graph-based ANNS Methods. Graph-based indices such as HNSW [7], Vamana [8], and NSG [9] are widely used graph-based methods for single-vector approximate nearest neighbor search. SIMQ builds upon these single-vector graph methods by constructing a graph index over cluster centroids and adapting per-token graph navigation to approximate multi-vector MaxSim scoring. VIII. C ONCLUSION 

We presented SIMQ, a multi-vector retrieval framework that combines data-aware sampling-based clustering with per-token graph navigation. By indexing cluster centroids refined after sampling-based initialization, SIMQ avoids materializing a centroid interaction matrix and reduces reliance on GPU-based large-scale k-means. Under a manifold assumption and successful cell retrieval, our analysis shows that SIMQ has lower expected intra-cell approximation error than MUVERA’s data-oblivious LSH partitioning. SIMQ+ adds count-based scoring and a dynamic candidate set to improve ranking robustness. Experiments on five benchmarks measure retrieval quality, throughput, and construction-time trade-offs against PLAID, MUVERA, IGP, and GEM, and evaluate alternative graph backends on CPUs.
