## Abstract 

Exact k-nearest-neighbor ( k-NN) vector search is a common feature of vector libraries and database systems. It serves ap-plications that require exact results and provides the ground truth for evaluating approximate search. However, floating-point rounding and overflow can cause an “exact” search to return mathematically incorrect top-k result sets. These errors can go unnoticed and affect downstream tasks that rely on exact results. We present Errpedia, a purpose-built dataset for testing the numerical correctness of exact vector search. Errpedia contains 1,616 queries across 21 error cate-gories, with ground truth independently verified using exact rational arithmetic. We evaluate 20 widely used library and database configurations and find that every tested configura-tion returns mathematically incorrect top-10 result sets on at least 1 applicable query. Failures include misranking nearly equidistant vectors and returning incomplete results: 1 library omits all 10 exact matches to a query, and several systems return fewer than k neighbors. We release Errpedia as a re-producible benchmark for developers and researchers to test their implementations. The dataset is publicly available at 

https://github.com/dynos01/errpedia .

## 1 Introduction 

Exact k-nearest-neighbor ( k-NN) vector search returns the k

vectors closest to a query under a specified distance measure, and is widely supported by vector libraries and database sys-tems [4, 5]. It serves recommendation workloads [9] and pro-vides ground truth for evaluating approximate nearest neigh-bor (ANN) search [1], training query cost estimators [11], and learning query termination policies [3]. Errors in these answers can therefore affect retrieval, evaluation, and training. Despite its importance as a reference oracle, the numerical correctness of exact vector search implementations is rarely evaluated independently. In particular, existing vector search benchmarks typically focus on the accuracy and performance of approximate search [2, 7], while the correctness of the underlying exact search is often taken for granted. Algorithmic exactness does not ensure numerical correct-ness in floating-point arithmetic. Rounding can merge distinct distances or reverse their order, and intermediate values can overflow even when the final distance is representable. Similar robustness problems have long been studied in computational geometry [8, 10]. For example, in a test, Faiss [5] returns no valid neighbors from a database containing 10 exact copies of the query, all at distance 0. Indeed, Faiss itself acknowledges that even brute-force search can suffer from floating-point rounding errors 1. In practice, not every application requires mathematically exact results, and floating-point errors may have little impact in routine use. We argue, however, that users who rely on exact answers need to be aware of when such errors can change the returned neighbors. Developers also need a systematic, reproducible benchmark to assess the numerical correctness of their implementations. In response to these issues, we present Errpedia, a purpose-built dataset dedicated to systematically testing numerical correctness in exact vector search. Its 1,616 queries span 21 error categories to help discover a wide range of numerical errors. To the best of our knowledge, Errpedia is the first dataset of this kind. 

## 2 Sources of Error 

Problem definition. Let X = {x1, . . . , xn} be a collection of 

d-dimensional vectors and q a query vector in the same space. Each member has a unique identifier. Distinct members may have identical coordinates. All coordinates are finite IEEE 754 32-bit float values interpreted as exact reals. We use squared Euclidean distance D(q, x) = ∑dj=1(q j − x j)2. Unless other-wise stated, distance refers to this measure. For 1 ≤ k ≤ n,

Rk(q) contains the k nearest members of X, with identifiers breaking exact ties. Errpedia uses k < n and a strictly positive top-k boundary gap, making membership in Rk(q) indepen-dent of tie-breaking. We independently verify each ground-truth set using exact rational arithmetic. We consider an un-

k members as correct. Under this setting, even exhaustive search can violate this criterion when numerical errors alter comparisons or candi-date selection for multiple reasons. 

Rounding and accumulation. Evaluating D(q, x) in floating point produces a computed distance score bD(q, x) through subtraction, multiplication, and addition, each of which can round its exact result to the working precision [6]. Small terms may be absorbed into a large partial sum, and changing the accumulation order can change the result. Distinct distances can then become tied or reversed. Errors comparable to the gap at the top-k boundary can change the returned set. Wider arithmetic can reduce errors but does not certify the order. 

Cancellation. An equivalent expression is 

D(q, x) = ∥q∥2 + ∥x∥2 − 2q⊤x. (1) For nearby vectors with large norms, this expression subtracts large, already rounded quantities to obtain a small residual. Errors in those quantities can dominate the true distance and obscure the ordering of candidates. Algebraic equivalence therefore does not guarantee equivalent numerical behavior. 

Overflow and underflow. Finite coordinates do not ensure that every intermediate result is representable. A difference, square, or partial sum can overflow to infinity, while a tiny nonzero term can round to 0. Subsequent operations involving infinities can produce NaN. Intermediates can be out of range even when the final distance is representable, so checking inputs alone cannot rule out range failures. 

Score conversion. Distance evaluation may be followed by a square root, conversion to a similarity score, or a reduction in precision. Strictly monotone transformations retain dis-tance distinctions in real arithmetic, but their floating-point implementations can map different inputs to the same out-put. Selecting the top-k by these scores can lose distinctions preserved by the distance computation and select a farther candidate from a computed tie. 

Candidate handling. Top-k collection must distinguish valid candidates from unused slots. Using an extreme distance score for an empty slot can make it indistinguishable from a candi-date with that score. If insertion requires strict improvement, the candidate may be rejected while a slot is still empty. NaN distance scores also require explicit handling because ordered comparisons with them are false. These interactions can leave fewer than k neighbors despite enough eligible vectors. 

Other sources. Additional failures can arise from unintended coordinate changes during parsing or type conversion, non-conservative pruning bounds that discard true neighbors, or output and transport failures that prevent complete results from reaching the caller. ## 3 The Errpedia Dataset 3.1 Specification 

Errpedia contains a vector collection X with n = 22 ,501 mem-bers and a query collection Q = ( q1, . . . , qb) with b = 1,616, 

d = 128, and k = 10. All coordinates are finite 32-bit float values. Each query q ∈ Q defines a test case over X with a unique ground-truth top-10 result set as defined in Section 2. The 21 categories form 6 evaluation groups (Table 1). 

Contents. The release stores X in data/base.csv , 1 vector per row without a header. Identifiers are 0-based row indices. Query JSON files occupy 6 group directories under data/ :

ap , rl , nd , fp , sm , and ir . For example, data/ap/sub_01. json stores case_id , category , query_row (the original 0-based query index), query (the coordinates), and gt_ids (the 10 ground-truth identifiers). Coordinates use complete exact decimal values, preserving the inputs under correctly rounded 32- or 64-bit float parsing. 

Applicability. Some systems impose numerical constraints on their inputs. We mark a query as not applicable when its inputs do not satisfy these constraints. Although an implemen-tation may accept such inputs and even return correct results, evaluation should respect the input requirements specified by its developers. 

Scoring. A query passes only if it returns exactly the 10 dis-2tinct ground-truth identifiers, regardless of order or rounding in reported distances. For an evaluation group G, let CG con-tain its categories with applicable, executed queries, and let

## 3.2 Construction 

General Methodology. Each case starts from a small candi-date set. A typical case contains 9 vectors closer to the query than 2 remaining candidates. These 2 candidates should oc-cupy ranks 10 and 11, respectively. We choose their coordi-nates so that a floating-point model of the computation can lose the difference between their distances. 

Arithmetic precision (AP). The sub construction pairs a large query coordinate with small, opposite-sign candidate co-ordinates, making distinct exact differences round identically. For sq_round , we search for 2-term squared sums whose order is lost through product rounding. The absorb construc-tion adds a nonzero squared term smaller than 1 /2 of the local spacing of a large partial sum, while order_disc varies term order and placement across accumulator lanes. To expose small gaps, neartie perturbs coordinate-permuted distance patterns. The collision_ladder construction places several strictly ordered candidates within a region of tied distance scores in the floating-point model. The sqrt construction uses distinct squared distances whose rounded square roots coincide in the targeted precision. 

Range limits (RL). For sq_underflow , we perturb exact matches so that nonzero squared differences round to 0 or are cleared under flush-to-zero. The sq_subnormal construc-tion searches for ordered squared sums that tie or reverse after product rounding on the 32-bit float subnormal grid. In 

overflow_inf , individual squares or their sum overflow. The 

diff_overflow cases use large, finite, opposite-sign coordi-nates whose differences exceed the 32-bit float range. The 

max_sentinel construction makes boundary distance scores round to the largest finite 32-bit float value, testing implemen-tations that also use it as an empty-slot threshold. 

Norm-dot-product evaluation (ND). The normdot_cancel 

construction uses identical or nearby vectors with large norms, so cancellation in the expanded distance formula obscures their small exact distances. The normdot_overflow cases contain 10 exact query matches whose individual norm terms or accumulated norms overflow in the same formula. 

16-bit float computation (FP). These categories target IEEE 754 16-bit float operations on 32-bit float inputs. The 

fp16_term construction uses coordinates representable in 16-bit float whose squared sums tie or reverse after product rounding. For fp16_underflow , differences remain nonzero in 16-bit float but their squares round to 0. The fp16_absorb 

cases place small terms after a large term in 1 accumulator lane. The fp16_overflow cases overflow 16-bit float prod-ucts or lane sums while keeping inputs representable. 

Similarity mappings (SM). The sim_saturation construc-tion pairs 0 and small positive squared distances D whose 32-bit float similarity scores 1 /(1 + D) both become 1. For 

exp_similarity , distinct distances produce 32-bit float sim-ilarity scores exp (−√D) that underflow to 0. 

Input representation (IR). For decimal_ingest , we search for distinct 32-bit float coordinates that serialize to identical 7-significant-digit text. The serialization erases the distinction at an exact-match boundary. 

Packing and ground truth. We pack the candidate sets into 1 shared base collection. Where coordinate positions are avail-able, we give a query and its candidates shared values at those positions to separate them from other candidate sets. These values cancel in direct coordinate differences but still partic-ipate in norm-dot-product evaluation, so validation uses the complete vectors. Every finite 32-bit float coordinate is an integer multiple of 2 −149 . Squared distances can therefore be compared using exact integer arithmetic in units of 2 −298 .We check the ground-truth sets against the shared collection and independently verify them using exact rational arithmetic to ensure that other candidate sets do not change a query’s top-10 result set. 

Coverage and selection. Constructions vary target preci-sion, scale, coordinate position, accumulator layout, candidate count, and identifier placement. We generate cases by formula and search, retaining only those with a strictly positive top-k

boundary gap lost in the targeted floating-point model. The compact release preserves declared coverage of con-struction variants, parameter ranges, candidate identifier or-ders, floating-point model behavior, and numerical endpoints. Selection is independent of measured product outcomes. Cat-egory sizes reflect the configurations needed to meet these requirements. For example, the 480 order_disc queries con-servatively retain strata for the number and placement of small terms under both candidate identifier orders. The 6 

max_sentinel queries cover 1 threshold regime, model be-havior, and numerical endpoints. Different parameter settings can produce the same model outcome.

## 5 Failure Analysis 

We analyze 1 representative case from each of the 6 groups to explain how numerical errors lead to incorrect search results. For each case, we trace how the error arises, show its effect on the returned neighbors, and discuss how to prevent it.

## 5.2 Range limits (RL) 

Case max_sentinel_02 makes Milvus v3.0.5 return 9 neigh-bors for k = 10. 9 local candidates have distance scores below 

FLT_MAX . The remaining 2 boundary distance scores round to that finite value. The underlying Knowhere collector ini-tializes empty slots to FLT_MAX and accepts candidates only when their distance scores strictly improve the threshold 23 .Neither boundary candidate can therefore fill the 10th slot. Collectors should track occupancy independently of dis-tance scores and admit eligible candidates while slots remain empty. This restores completeness for the finite sentinel col-lision. Resolving the rounded distance tie still requires an accurate boundary comparison. 

## 5.3 Norm-dot-product evaluation (ND) 

Case normdot_overflow_17 contains 10 exact copies of the query. Each individual coordinate square is finite in 32-bit float, but their norm sum overflows. Faiss v1.15.1’s BLAS path 24 evaluates Eq. 1, producing an indeterminate expres-sion involving infinities even for an exact match. The full-collection search returns 10 invalid identifier slots, omitting every neighbor at distance 0. A local test uses the 11-vector candidate set and a fixed batch of 1,616 query copies. Chang-ing only the dispatch threshold to select direct differences restores all 10 matches with distances of 0. Direct differences avoid this failure for identical vectors. More generally, nonfinite intermediate results require recom-putation with sufficient range. Candidate selection must not silently discard a possible neighbor because its provisional distance is NaN.

## 5.4 16-bit float computation (FP) 

Case fp16_underflow_13 isolates product underflow in a 16-bit float model. The inputs are exactly representable in 16-bit float. A nonmatching vector differs from 10 exact query copies by 2 −13 in 1 coordinate. Its squared distance is 2 −26 ,below 1 /2 of the smallest positive 16-bit float subnormal, 2−24 . The product rounds to 0, creating a computed tie. The model then includes the nonmatch among its 10 results. Promoting the operands before multiplication preserves this term in 32-bit float and restores the local top-10 result set. Widening only the accumulator cannot recover a product already rounded to 0. The model isolates underflow during multiplication, before accumulation. 

## 5.5 Similarity mappings (SM) 

Case sim_saturation_04 has 10 exact query copies and a perturbed candidate with D = 9 · 2−56 > 0. This distance survives 32-bit float evaluation, but 1 + D rounds to 1. The Lucene v9.11.1 mapping 1 /(1 + D) used by Neo4j v5.26.12 25 

therefore assigns it the same similarity score as a match at distance 0. In the full-collection search, all 10 returned iden-tifiers lie outside the exact-match set, and all have reported similarity score 1. The mapping hides distinct exact distances. To preserve distance order, selection should retain the un-mapped distance and refine uncertain comparisons. Similarity scores may be rounded after the neighbor set has been se-lected. Reranking only the returned identifiers cannot recover matches already excluded by score saturation. 

## 5.6 Input representation (IR) 

Case decimal_ingest_05 illustrates information loss before distance evaluation. Its decisive coordinates are 12570212 and 12570213, both exact 32-bit float values. In a serialization test, a serializer retaining 7 significant decimal digits writes both as 1.257021e+07 . Parsing this text merges an exact match and a nonmatch, and a search over the parsed vectors returns an incorrect top-10 result set. Base and query vectors should be transported in binary or decimal text that preserves every 32-bit float value. 9 signifi-cant digits suffice with correctly rounded 32-bit float parsing. Our 9-digit serialization test preserves every local coordinate and restores the correct top-10 result set. Wider arithmetic after 7-digit ingestion cannot recover the original distinction.

## 6 Conclusion 

We present Errpedia, a dataset for testing the numerical cor-rectness of exact vector search. It contains 1,616 queries across 21 categories, with unique ground-truth sets verified using exact rational arithmetic. Each of the 20 tested con-figurations returns mathematically incorrect top-k result sets for some applicable queries. Errpedia provides reproducible cases for validating implementations, checking benchmark ground truth, and detecting numerical regressions. Errpedia has 2 main known limitations: it covers only squared Euclidean distance and uses fixed parameters of 

d = 128 and k = 10. Extending its coverage to other distance measures and parameter settings remains future work.
