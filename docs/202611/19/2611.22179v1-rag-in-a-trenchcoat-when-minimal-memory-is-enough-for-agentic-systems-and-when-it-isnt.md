## 摘要
智能体记忆研究在检索增强生成之上累积了抽取、取代、反思和图合成等机制。然而，我们发现，在我们测试的记忆基准上，这些原语几乎都无法证明其开销是合理的：我们通过 BRIDGE 展示了这一点。BRIDGE 是一种刻意最小化的 RAG 记忆，采用链式观察笔记、混合 BM25 与余弦检索，以及按时间顺序呈现；它在 LongMemEval-S 和 BEAM 上于 bootstrap 置信区间内达到与先前 SOTA 相当的水平，并在匹配 reader 的条件下，在 EverMemBench 上比最佳记忆基线高 5.7–6.3 分。它每次查询约使用 5–7K 的 reader 提示 token，每次摄入或查询仅需一次 LLM 调用。我们认为，这种持平本身就是结果：标准基准衡量的是记忆检索到什么，而不是记忆在智能体行动时使其能做什么。为测试后者，我们引入了五个对抗性探针（规则应用 +−、模式归纳（风格/程序性）、动态多轮），在生成时由跨厂商验证链进行评判；其中每个查询只能通过应用其从未提及的已记忆规则或模式来解决。在 5 个探针 × 20 个场景中，没有架构能普遍胜出：原子事实抽取器（LangMem）在规则应用上胜出，而 BRIDGE 的块摘要记忆在模式归纳上胜出。该结果在四个领域、三名评分者和三个 reader 系列上均成立。每种设计都在对方胜出之处失败，其原因在于召回基准无法看到：原子事实抽取器丢弃了示范模式所采取的形式，而块摘要记忆检索到了规则，但 reader 并不据此行动；更突出地呈现规则可大体弥合这一差距。区分记忆设计的不是它们检索到什么，而是它们使智能体能做什么，而这才是智能体记忆应被评估的方面。

## Abstract
Agentic memory research has accumulated extraction, supersession, reflection, and graph synthesis on top of retrieval-augmented generation. However, we found that almost none of those primitives earn their cost in our tested memory benchmarks: we show this with BRIDGE, a deliberately minimal RAG memory with chained observation notes, hybrid BM25 with cosine retrieval, and chronological rendering, which reaches parity within bootstrap CI with the prior SOTA on LongMemEval-S and BEAM, and beats the best memory baseline on EverMemBench by 5.7-6.3 points at matched reader. It runs at ~5-7K reader-prompt tokens per query, using a single LLM call for each ingestion or query. We argue that this parity is itself the result: standard benchmarks score what memory retrieves, not what memory enables when the agent acts. To test the latter, we introduce five adversarial probes (Rule Application +-, Pattern Induction Style / Procedural, Dynamic Multiturn) judged at generation time by a cross vendor verification chain, where each query can only be solved by applying a remembered rule or pattern it never mentions. Across 5 probes x 20 scenarios, no architecture wins universally: atomic fact extractors (LangMem) win rule application, while BRIDGE's block-summary memory wins pattern induction. This result holds across four domains, three graders, and three reader families. Each design fails where the other wins, for reasons a recall benchmark cannot see: atomic-fact extractors discard the form a demonstrated pattern takes, while block-summary memory retrieves the rule but the reader does not act on it, a gap that presenting the rule more prominently largely closes. What separates memory designs is not what they retrieve but what they enable an agent to do, and that is what agentic memory should be evaluated on.

# 论文总结：RAG in a Trenchcoat（风衣下的RAG）

## 1. 核心问题与整体含义

- **研究动机**：过去两年智能体记忆研究不断在 RAG 之上叠加抽取、取代（supersession）、反思、图合成、工作记忆缓存等原语，并默认每一项都是"对朴素 RAG 的必要改进"。但这些原语是否真的带来可测量的收益，缺乏系统检验。
- **核心问题**：现有记忆基准（LongMemEval-S、BEAM、EverMemBench 等）几乎都是"对历史提问并评分"的召回型 QA 任务，能否区分不同记忆架构？记忆设计真正应该被评估的能力是什么？
- **整体主张**：论文提出"always-on applied memory"（常驻可用记忆）概念——用户不在请求中重述规则、约定或偏好，智能体必须自行浮现并应用。作者认为这才是长时运行智能体的价值所在，而现有基准测的是"检索到什么"而非"使智能体能做什么"。

## 2. 方法论

### 2.1 BRIDGE：极简 RAG 记忆基线

- **设计哲学**：故意保持简单，作为"所有复杂记忆系统必须超越的最低门槛"；不含图数据库、不含取代层、不含反思、不含智能体框架集成，被作者戏称为"RAG in a trenchcoat"。
- **两阶段流程**：
  - **摄入阶段**：对话按自然边界分块（token 上限 $T_{tok}=2000$）；抽取 LLM 为每个块生成 XML 标记的观察笔记，抽取时可见最近 $W=10$ 条历史笔记（跨块上下文链）；同时持久化原始文本 $x_{t,k}$ 与蒸馏笔记 $o_{t,k}$；用冻结句编码器嵌入笔记。
  - **检索阶段**：对查询 $q$ 同时计算余弦相似度 $s_{cos}$ 与 BM25 分数 $s_{bm25}$（BM25 索引笔记+原文的拼接）；每通道保留 top-60，用 Reciprocal Rank Fusion（$k_{rrf}=60$）融合：$s_{rrf}(q,B)=\frac{1}{k_{rrf}+r_{cos}(B)}+\frac{1}{k_{rrf}+r_{bm25}(B)}$。
  - **两级渲染 + 时序重排**：取 top $K=10$ 块，其中余弦 top $r=3$ 以原文渲染，其余以"Summary: 笔记"渲染；再按全局时间位置升序重排后拼接。
  - **Reader**：单次 LLM 调用（$\tau=0$），wrapper 提示要求"即使用户未提及，也应用记忆中记住的规则/约定"。

### 2.2 五类对抗探针（Adversarial Probes）

- 每个场景是一段带日期的多会话历史 + 一个请求；**请求从不提及它所依赖的记忆**，评分的是生成的工作产物而非对历史的回答。
- **五类探针**：
  - **RA+**（正向规则应用）：一条规则作为闲聊旁白植入某会话，请求触发其适用领域。
  - **RA−**（禁令应用）：植入的是一条禁令，请求的显然解法恰是被禁方案。
  - **PI-S**（风格模式归纳）：编码约定只通过示例演示、从不陈述。
  - **PI-P**（程序模式归纳）：同一多步流程在 4 次过往案例中演示、从不陈述。
  - **DM**（动态多轮）：复用 RA+ 语料，将单请求替换为模拟用户驱动的 5 轮对话，同时评最终轮与逐轮回归。
- **生成时评判**：评判器针对场景约束（而非金标准答案）给出 applied / violated / n/a，通过率为 $n_{applied}/(n_{applied}+n_{violated})$；评判器来自与生成器、Oracle、reader 不同的厂商，避免同族偏好与自我偏好偏差。
- **公平对比协议**：所有系统共用同一 reader、embedder、评判器；每个基线获得约 100 词的 wrapper 提示，命名其原生原语并指示 reader 主动应用规则；仅通过各系统文档推荐的用户级杠杆调优。

## 3. 实验设计

- **标准记忆基准**：LongMemEval-S（GPT-4o reader，500 题）、BEAM 100K（GPT-4.1-NANO，10 能力均值）、EverMemBench（GPT-4.1-MINI 与 GEMINI-3-FLASH 双 reader）。
- **对抗探针基准**：5 探针 × 20 场景（原始软件/基础设施人设），扩展到 87 个新领域场景（临床运营、法律合规、财务运营）+ 80 个更难难度级别（RA+ 与 PI-P 各两级），共 247 场景。
- **对比方法**：
  - 标准基准：MEM0、LANGMEM、GRAPHITI、Zep、Supermemory、EmergenceMem、LIGHT、MemOS、Full-Context、Naive RAG。
  - 探针：MEM0、LANGMEM、GRAPHITI、BRIDGE，外加 Oracle（强模型读完整历史，作为上限参考）。
- **鲁棒性检验**：3 名跨厂商评判者、3 个 reader 家族（GPT-4.1-mini、Llama-3.3-70B、Qwen2.5-7B）、3–4 次重复运行、4 个领域、两档难度级别。
- **消融实验**：对 BRIDGE 的 5 个原语（W=0、r=0、无时序重排、BM25-only、cosine-only）在三基准上做留一法消融，报告逐类别配对 bootstrap CI。

## 5. 实验数量与充分性

- **实验规模**：
  - 标准基准 3 个 × 多 reader 栈（含 reader × extractor 的 2×3 网格）。
  - 对抗探针 5 类 × 20 原始场景 × 5 系统（约 500 条存储答案、每评判者约 1,190–1,195 条判决）。
  - 领域扩展 87 场景、难度扩展 80 场景。
  - 3 名评判者交叉复评、3 个 reader 替换、3–4 次重复运行。
  - BRIDGE 的 5 项原语消融 × 3 基准 + 探针消融（2 次重复）+ LANGMEM 模式定向 schema 调优对照。
- **充分性评价**：
  - **较充分**：多维度鲁棒性检验（领域、评判者、reader、重复运行）设计严谨；使用配对 bootstrap CI；跨厂商评判避免同源偏差；报告了重复运行的标准差。
  - **统计功效有限**：每探针仅 20 场景，单场景即移动规则探针 5 分，作者明确表示"不解释小于约 15 分的差异"；新增领域单元仅 4–8 场景，只读符号不读大小。
  - **公平性**：所有系统共用 reader/embedder/评判器，wrapper 深度校准到同一层级，仅用各系统文档推荐杠杆调优；但 LANGMEM 被额外做了模式定向 schema 调优对照，MEM0 与 GRAPHITI 未做同等重调，存在轻微不对称。
  - **部分实验未覆盖**：DM 只跑一次且不参与鲁棒性检验；W=0 消融未在 LongMemEval-S 上跑。

## 6. 主要结论与发现

- **标准基准上极简记忆即可持平 SOTA**：BRIDGE 在 LongMemEval-S 上与 EmergenceMem 在 95% CI 内持平（落后 1.4 分）；在 BEAM 上与 LIGHT 差距处于显著性边缘（0.370 vs 0.345）；在 EverMemBench 上领先最佳记忆基线 MemOS **5.7–6.3 分**（CI 外）。作者认为"这种持平本身就是结论"——这些基准无法区分记忆设计。
- **对抗探针上设计分化明显**：
  - **LANGMEM（原子事实抽取）在规则应用上大幅领先**：RA+ 80% vs BRIDGE 35%（差 45 分，CI 不重叠），RA− 90% vs 55%，DM 75% vs 40%。
  - **BRIDGE（块摘要记忆）在模式归纳上大幅领先**：PI-P 88% vs LANGMEM 55%（差 33 分），PI-S 81% vs 47%。
  - **没有架构通吃**；GRAPHITI 与 MEM0 在两类探针上均未胜出。
- **失败原因不对称**：原子事实抽取器丢弃了示范模式所采取的"形式"（form）；块摘要记忆**检索到了规则但 reader 不据此行动**——在全部 20 个 RA+ 场景中规则块均被检索到，13 次失败中 12 次规则以原文到达 reader。
- **呈现方式而非检索决定成败**：仅增加一次额外调用，从已检索笔记中抽取"常驻指令"并置于上下文顶部，RA+ 原始探针从 52.6% 升至 **94.7%**（超过 LANGMEM 的 80%，接近 Oracle 的 90%）；最难级别从 42.1% 升至 78.9%。而同等开销的"通用摘要"对照反而更差（40.0%），证明增益并非来自额外调用。
- **路由不可行**：仅凭请求预测"需要陈述规则还是示范模式"的分类器准确率仅 49–61%，不优于多数类基线 60%——因为探针请求本就不携带可路由信号。
- **消融显示无单一原语独立有效**：每项原语至少在一个能力上移除有益、在另一能力上移除有害；池化准确率掩盖了逐类别 5–30 分的效果（如 r=0 使 LongMemEval-S SSA 下降 30.2 分；无时序重排使知识更新下降 7.7 分；BM25-only vs cosine-only 使 EverMemBench 记忆更新摆动约 38 分）。

## 7. 优点

- **"极简基线"作为方法论武器**：用刻意简单的 BRIDGE 作为照妖镜，直接质疑复杂原语的边际价值，论点犀利且可复现。
- **评估视角的范式转移**：从"检索召回"转向"生成时是否应用"，提出 always-on applied memory 这一有实践价值的概念。
- **生成时评判设计精巧**：请求从不提及所依赖的记忆、评判约束而非金标准答案、跨厂商评判链，有效规避了自我偏好与同族偏差。
- **鲁棒性检验扎实**：4 领域 × 3 评判者 × 3 reader × 3–4 次重复，方向全部保持，且明确指出弱评判者会收窄但不会反转结论。
- **诊断而非方法的诚实定位**：呈现方式实验被明确表述为"diagnostic rather than a method"，并设置了同等开销的对照排除混淆。
- **失败案例剖析透彻**：附录 I 逐句追踪 rate-limit 场景在 BRIDGE 与 LANGMEM 中的差异，机制解释清晰。
- **消融揭示"池化掩盖机制"**：逐类别配对 bootstrap CI 的做法比单一池化数字更有信息量。

## 8. 不足与局限

- **统计功效受限**：每探针 20 场景，单场景即 5 分；
