Abstract 

Runtime skills can improve agents’ problem-solving capabilities by providing procedural guidance for tasks such as code review and de-bugging. However, these benefits reach only a minority of users, as most do not proactively invoke skills in practice. We argue that such generalizable procedures should become part of the model’s capabilities rather than remain op-tional external add-ons, making them directly available without explicit skill loading. To this end, we present SkillCore , a data pipeline and supervised fine-tuning recipe for internal-izing generalizable skills. We transform real agent trajectories by removing skill-loading scaffolding while preserving the task context and subsequent agent actions, thereby super-vising direct execution without external skill content. To preserve access to task-specific skills that provide genuinely external informa-tion, we mix these scaffold-removed trajec-tories with a small proportion of skill-native trajectories that preserve supervision for skill invocation. On a held-out skill-free evalua-tion, SkillCore improves task completion qual-ity over the base Qwen3-8B and Qwen2.5-72B models by 54 .4% and 24 .8% , respectively, while preserving task-specific skill invocation on a separate probe and general coding perfor-mance on SWE-bench Verified.

Task-specific skills, by contrast, contain procedures or resources tailored to a particular task or system, such as private APIs, system-bound instructions, or task-specific infor-mation. Accordingly, an effective internalization approach should make generalizable procedures available without runtime skill access while pre-serving runtime access to task-specific skills when specialized procedures, external information, or functionality are required. In this work, we propose SkillCore, a framework that integrates a trajectory construction pipeline with a tailored supervised fine-tuning recipe to internalize generalizable skills while preserving runtime access to task-specific skills. Specifically, for generalizable skills, the data pipeline applies skill-scaffold removal: it removes the skill invo-cation, returned document, and associated loading artifacts while preserving the task context and the agent’s subsequent actions. This produces train-ing trajectories that retain the demonstrated actions while excluding the skill-relevant context that orig-inally guided them. Fine-tuning on these trajecto-ries transfers the demonstrated procedure into the model’s parameters, enabling direct execution with-out the skill. By contrast, for task-specific skills, the training recipe retains a small proportion of skill-native trajectories with their invocation scaf-folding intact, preserving supervision for when and how such skills should be invoked. We evaluate SkillCore along three complemen-tary dimensions: internalization of generalizable skills, retention of task-specific skill invocation, and preservation of general coding capability. First, a held-out skill-free evaluation assesses whether SkillCore improves model performance when gen-eralizable skill content is unavailable. In this set-ting, SkillCore improves task completion quality over the base Qwen3-8B and Qwen2.5-72B mod-els by 54 .4% and 24 .8% , respectively. Second, on a separate evaluation suite constructed from task-specific skill trajectories, SkillCore preserves skill invocation at rates comparable to those of the cor-responding base models. Third, the resulting mod-els maintain or improve performance on the auxil-iary SWE-bench Verified evaluation (Jimenez et al., 2024; OpenAI, 2024). Ablations further show that retaining generalizable-skill scaffolding leads to more runtime skill invocations when skill content is unavailable, whereas omitting skill-native super-vision suppresses appropriate task-specific calls.

2.2 Context Distillation and Skill Internalization 

Context distillation transfers behavior induced by privileged runtime context into model parame-ters. Prior work distills fixed prompts, instruc-tions, demonstrations, and explanations so mod-els can reproduce the corresponding behavior with less context (Askell et al., 2021; Choi et al., 2023; Snell et al., 2022). A related line of work dis-tills the results of costly inference-time reasoning into model parameters, allowing direct responses without repeating the reasoning process (Yu et al., 2024). Despite demonstrating effective context-to-parameter transfer, these approaches primarily operate on non-interactive input–output examples rather than multi-turn agent trajectories with tool use and environment feedback. Recent work extends this paradigm to agent tra-jectories and skills. On-Policy Context Distilla-tion trains a student without privileged context to match a context-conditioned teacher on student-generated trajectories (Ye et al., 2026), while Skill-SD conditions only the teacher on skills summa-rized from completed on-policy trajectories (Wang et al., 2026). SKILL0 and SIRI instead inte-grate skill internalization into agentic reinforce-ment learning: the former progressively withdraws skill context (Lu et al., 2026), whereas the latter mines and validates skills from current-policy roll-outs before distilling beneficial skill-guided actions 3into the plain policy (He et al., 2026). Together, these approaches depend on newly sampled on-policy behavior, typically obtained from controlled, executable benchmark tasks. LatentSkill offers an offline alternative by converting textual skills into modular LoRA adapters that must still be selected and loaded at inference time (Hu et al., 2022; Yu et al., 2026). SkillCore instead constructs super-vision offline from heterogeneous real-world user trajectories whose original environments cannot be readily reconstructed: it removes generalizable-skill scaffolding while preserving subsequent agent actions, then applies supervised fine-tuning. It therefore requires neither fresh policy rollouts nor an executable environment during corpus construc-tion or training, and internalizes reusable proce-dures directly into the model’s parameters while retaining runtime access to task-specific skills. 

3 Methodology 

3.1 Overview 

Let τ = ( μ1, . . . , μ L) denote an agent trajectory. Each message μi = ( ri, c i) has one of four roles 

ri: system, user, assistant, or tool; its content ci

may be natural language, a structured tool call, or a tool result. The skill scaffold comprises the invocation and returned skill content, assistant ut-terances whose function is to announce or man-age the skill use, and later accesses to the skill’s internal files. For generalizable skill calls, we re-move this scaffold while preserving the task con-text, non-target skill interactions, and substantive downstream agent behavior, yielding a scaffold-removed trajectory eτ . The validated outputs form the scaffold-removed corpus Dremoved .Task-specific skills encode procedures or re-sources that transfer less readily across tasks, mak-ing their internalization less broadly useful. Some also depend on external information, proprietary interfaces, or environment-specific functionality that cannot be supplied by model parameters alone. For these skills, we retain skill-native trajecto-ries , including their skill calls and returned con-tent, to preserve supervision for runtime invocation. These trajectories constitute the skill-native corpus 

Dnative . SkillCore trains on a mixture of Dremoved 

and Dnative to balance direct execution of general-izable procedures with runtime use of task-specific skills. Figure 2 summarizes the framework; the following subsections describe data construction, training, and evaluation. 

3.2 Data Curation and Scaffold Removal Skill-Use Filtering. We collect 3,352 ,057 real-world agent trajectories and filter for those contain-ing valid structured use_skill calls. We consider a call effective only when it specifies a non-empty skill name, is paired with a successful skill-loading result, and is followed by at least one agent action. Only 108 ,514 trajectories ( 3.2% ) pass this filter, in-dicating that successfully loaded and subsequently used skills are sparse in the collected trajectories. Because annotating and transforming the entire fil-tered pool is costly, we select 44 ,960 trajectories for subsequent annotation and scaffold transforma-tion while preserving coverage over distinct skills. 

Quality and Generalizability Annotation. For each selected trajectory τ , let Ceff (τ ) denote its set of effective skill calls. We use Claude Opus 4.8 (Anthropic, 2026) to assign a trajectory-level quality score q(τ ) ∈ {1, . . . , 5} and, for each 

κ ∈ C eff (τ ), a generalizability score gen( κ) ∈{1, . . . , 5} that assesses the reusability of the loaded skill procedure beyond the current task. Scores near 1 indicate task-specificity, whereas scores near 5 indicate broad reusability. The judge also returns two Boolean labels: applied( κ) indi-cates whether subsequent agent actions apply the loaded skill’s procedure, and skillobj( κ) indicates whether the user’s task targets the skill itself. Let validend( τ ) indicate that the task is com-pleted or ends because of collection truncation, 

noloop( τ ) that no repeated error loop occurs, and 

nodissat( τ ) that the user expresses no dissatisfac-tion. We define the Boolean trajectory-quality gate and the set of generalizable calls targeted for scaf-fold removal as

Coupling-Aware Scaffold Transformation. For each trajectory selected for scaffold removal, we construct a compact, indexed representation that 4fits within Claude Opus 4.8’s context window. Mes-sages and skill calls receive stable identifiers, while long system fields and tool results retain only infor-mative prefixes and suffixes. We choose between exact deletion and local rewriting based on whether the target scaffold can be isolated from assistant content. When it can, Claude Opus 4.8 identifies the target calls κ ∈ G (τ ) and their corresponding text spans, which are then removed deterministi-cally. Otherwise, Claude rewrites only the affected local window and leaves the remainder of the tra-jectory unchanged. Both routes remove the scaf-fold associated with calls in G(τ ), including later accesses to skill-internal files, while preserving non-target skill interactions and downstream agent behavior. We denote the resulting trajectory by eτ .

Transformation Validation. We retain a trans-formed trajectory eτ only after it passes two com-plementary validation stages. First, a determinis-tic structural gate verifies that the invocation and linked result for every target call κ ∈ G (τ ) have been removed, while all non-target skill calls are retained. It also verifies that all remaining tool calls and results are correctly paired, the system message remains unchanged, and the user request is non-empty. These checks ensure that scaffold removal does not corrupt the agent interaction pro-tocol. However, they cannot determine whether the target scaffold has been fully removed or task-relevant content has been inadvertently deleted. We then use Claude Opus 4.8 to conduct a se-mantic review of each transformation that passes the structural gate. It checks six properties: com-plete removal of the target scaffold, preservation of the original task intent, preservation of task-relevant agent actions, coherence of the edited mes-sage sequence, absence of later access to the re-moved skill’s internal files, and continuity of the overall discourse and task structure. A trajectory is retained only if all six checks pass, yielding 10 ,037 

validated scaffold-removed candidates. Figure 3 summarizes the full data-construction pipeline. 

3.3 Training

and Dnative , where skill-native trajectories preserve task-specific skill calls and their returned skill con-tent. By default, we set the native-to-removed data ratio to 25% . This mixture provides supervision for both direct execution of internalized procedures and runtime invocation of task-specific skills. 3.4 Evaluation Skill-Content-Free Continuation. This suite tests whether the model can complete tasks sup-ported by a generalizable skill when its content is no longer provided. We construct 348 continua-tion tasks spanning 274 skills, prioritizing broad skill coverage. The suite includes target skills both represented in and absent from the final training corpus, enabling us to assess transfer beyond skills observed during training. We manually review each task to verify the source trajectory, skill categoriza-tion, and the validity of the evaluation prefix. Each task provides the base and fine-tuned checkpoints with the same trajectory prefix ending immediately before the target skill call; neither the call nor its re-turned skill content is provided. Both checkpoints generate up to three assistant rounds, stopping once a round contains no tool call. When a generated round invokes a tool, we replay the next aligned source-recorded tool result rather than execute the tool, so the protocol measures controlled continua-tion rather than closed-loop success. We evaluate each continuation along two axes. The first is the residual use_skill invocation rate, which mea-sures continued runtime skill invocation when the target skill content is withheld. The second is over-all trajectory quality and task completion, which we assess with an LLM-as-a-judge protocol (Zheng et al., 2023) using Claude Opus 4.8; it produces a pairwise preference between the base and fine-tuned continuations, together with a 1–5 score for each (higher is better).

4 Experiments 

4.1 Overview 

We evaluate SkillCore with Qwen3-8B and an agent-post-trained Qwen2.5-72B checkpoint on two complementary suites: skill-content-free con-tinuation, which measures task performance when target skill content is withheld, and task-specific skill routing. We ask whether scaffold-removed supervision improves task completion while re-ducing residual skill invocation (RQ1); whether the observed performance gains arise from scaf-fold removal rather than training on the same tra-jectories with scaffolding retained (RQ2); how internalization-only training affects task-specific skill routing (RQ3); and how skill-native supervi-sion trades off routing preservation against internal-ization (RQ4). We additionally examine the effects of corpus construction choices and check general coding performance. 

4.2 Experimental Settings 

All models undergo full-parameter fine-tuning us-ing the Megatron backend (Narayanan et al., 2021) and Hermes agent template implemented in ms-swift (Zhao et al., 2025). We use a maximum sequence length of 65 ,536 tokens, with left trun-cation retained only as a fallback after template serialization. System, user, and tool-result mes-sages provide context without contributing to the loss, whereas assistant language and tool calls are supervised. We use Adam with an initial learning rate of 10 −5, cosine decay to 10 −6, a 5% warmup ratio, weight decay of 0.1, gradient clipping at 1.0,and seed 42. The global batch size is 128 for 8B and 64 for 72B, with a microbatch size of 1. We train the 8B and 72B models for 6 and 3 epochs, respectively. Training uses two nodes, each with eight 141-GB NVIDIA H200 GPUs. 

4.3 RQ1: Can Scaffold-Removed Supervision Internalize Generalizable Skills? 

We evaluate internalization-only models trained exclusively on Dremoved , without skill-native data 6from Dnative . Table 1 reports their performance on the skill-content-free continuation suite. For Qwen3-8B, the residual skill-invocation rate falls from 16 .7% to 2.6% ; its continuations win 82 .8% 

of pairwise comparisons against those from the base checkpoint, while the mean judge score in-creases by 1.23 points ( 54 .4% ). For Qwen2.5-72B, residual invocation falls from 33 .6% to 0.9% ; its continuations win 62 .4% of comparisons, with a mean judge-score increase of 0.45 points ( 16 .0% ). Across both model scales, scaffold-removed su-pervision improves task completion quality while substantially reducing residual skill invocation. 

4.4 RQ2: Is Scaffold Removal Necessary? 

The Scaffold-retaining control uses the same source trajectories and training epochs as internalization-only, but retains the generalizable-skill scaffolds. Compared with scaffold removal, retaining them raises residual invocation from 2.6% to 44 .5% for 8B and from 0.9% to 59 .5% for 72B, while reduc-ing pairwise win rates from 82 .8% to 58 .9% and from 62 .4% to 35 .1% , respectively. It also yields smaller quality changes: +0 .42 points ( +16 .4% )rather than +1 .23 (+54 .4% ) for 8B, and −0.37 

(−11 .7% ) rather than +0 .45 (+16 .0% ) for 72B. Overall, this matched comparison indicates that the gains arise from scaffold removal rather than fine-tuning alone, enabling task completion with far less reliance on external skills. 

4.5 RQ3: What Routing Cost Does Internalization-Only Training Impose? 

The gains on generalizable skills come at a sub-stantial cost to task-specific skill routing (Table 1). On the task-specific routing suite, the call rate drops from 50 .0% to 13 .2% for 8B and from 

65 .4% to 7.0% for 72B. Correspondingly, the over-internalization rate rises from 50 .0% to 86 .8% for 8B and from 28 .5% to 89 .9% for 72B, as the mod-els respond directly or invoke another tool instead of calling the target skill. Among the relatively few generated skill calls, however, the target skill is usually selected correctly (Corr@Call: 93 .3% 

and 100% ). The main degradation therefore lies in deciding whether to invoke a skill, not in selecting which skill to invoke once a call is made. Overall, internalization-only training substantially weakens task-specific skill routing despite preserving condi-tional selection accuracy.

6 Conclusion 

Motivated by the low utilization of runtime skills, we argue that generalizable skills should be inter-nalized while task-specific skills providing exter-nal information remain callable. We present Skill-Core, which removes generalizable-skill scaffolds while preserving task descriptions and subsequent actions, and mixes in a small proportion of skill-native trajectories to retain task-specific skill invo-cation. SkillCore improves the skill-free response quality of Qwen3-8B and Qwen2.5-72B over their base models by 54 .4% and 24 .8% , respectively, while preserving task-specific skill invocation and general coding ability. SkillCore thereby makes capabilities delivered through runtime scaffolds in-trinsic and available to all users by default. 8Limitations 

Our evaluation uses one training seed, one deter-ministic generation per checkpoint, and one Claude Opus 4.8 judgment per task. We therefore do not estimate variation across training runs, generations, or judges, and report point estimates rather than confidence intervals. The continuation suite re-plays recorded tool results instead of executing generated actions, while the routing suite evaluates only the decision to invoke a skill. Neither suite measures closed-loop task success. Because the study uses real-world agent trajecto-ries, sharing the data or derived models requires ap-propriate access controls and privacy review. Full-parameter fine-tuning at long context lengths also requires substantial computation, which may limit reproducibility and practical adoption. These con-straints bound our claims to the evaluated models, data distribution, and protocols.
