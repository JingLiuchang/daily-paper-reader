## 摘要
AI可穿戴设备（如智能眼镜）将智能体可用的上下文从数字环境扩展到用户的物理周围环境。借助这些设备，计算机任务可以源于用户正在进行的活动，而不仅仅源于明确指令。通过第一人称观察，智能体能够识别与用户请求相关的物体和活动，并将数字任务建立在周围上下文之上。我们将这一交互范式称为Ego Use。然而，第一人称观察受佩戴者视角限制，可能提供关于正在进行的活动的不完整或模糊证据。随着新的观察到来，智能体可能需要修正其对物理上下文和用户意图的理解，并重新评估此前的数字操作是否仍然有效。当前智能体能否可靠处理这些变化仍缺乏充分评估。我们提出EgoUseBench，一个用于在三种具有不同第一人称上下文层级的交互设置下评估Ego Use的基准。Computer-Use依赖明确指令，Offline Ego Use在执行前提供预先录制的第一人称上下文，Online Ego Use在用户意图演变过程中提供持续观察。基于超过74小时的真实世界第一人称录制数据，我们构建了覆盖三种交互设置的693个任务。为捕捉任务演变，我们分别跟踪第一人称观察、用户需求和网站状态。我们进一步根据执行期间信息的变化方式对任务分组，得到三种类型：Graft（修订的用户需求）、Refresh（新的第一人称观察）和Clarify（智能体主动信息搜寻）。我们评估了先进模型，发现Online Ego Use的平均成功率比Computer-Use低26.3%。这一结果揭示了使任务执行与不断演变的第一人称上下文和用户意图保持一致的难度。

## Abstract
AI wearables, such as smart glasses, extend the context available to agents beyond digital environments to users' physical surroundings. With these devices, computer tasks can originate from users' ongoing activities rather than solely from explicit instructions. Through first-person observations, agents can identify objects and activities relevant to user requests and ground digital tasks in the surrounding context. We call this interaction paradigm Ego Use. However, first-person observations are limited by the wearer's viewpoint and may provide incomplete or ambiguous evidence of ongoing activities. As new observations arrive, agents may need to revise their understanding of the physical context and user intent, and reassess whether prior digital actions remain valid. Whether current agents can reliably handle these changes remains insufficiently evaluated. We introduce EgoUseBench, a benchmark for evaluating Ego Use across three interaction settings with different levels of first-person context. Computer-Use relies on explicit instructions, Offline Ego Use provides prerecorded first-person context before execution, and Online Ego Use provides continuous observations as user intent evolves. Based on over 74 hours of real-world first-person recordings, we construct 693 tasks across the three interaction settings. To capture task evolution, we track first-person observations, user requirements, and website state separately. We further group tasks by how information changes during execution, resulting in three types: Graft (revised user requirements), Refresh (new first-person observations), and Clarify (agent-initiated information seeking). We evaluate advanced models and find that average success rates in Online Ego Use are 26.3% lower than in Computer-Use. This result reveals the difficulty of keeping task execution aligned with evolving first-person context and user intent.

- **整体含义**：现有 Computer-Use 与离线第一人称基准无法评估“执行中上下文与意图演化”带来的动态对齐问题，论文据此提出 EgoUseBench 作为受控评测平台。

## 2. 方法论

### 2.1 三种交互设置

- **Computer-Use**：仅提供显式、已解析的最终指令，不提供第一人称视频，禁用提问。
- **Offline Ego Use**：执行前一次性提供完整预录制第一人称视频和原始请求。
- **Online Ego Use**：执行过程中按回放时间表持续提供第一人称观察，用户请求可在执行中修订，并允许智能体主动提问。

### 2.2 三类任务变化机制

- **Graft（需求修订）**：用户在执行中修改请求，细分为：
  - Refine：调整属性或数量；
  - Augment：增加要求但保留原有要求；
  - Replace：替换某个请求选项；
  - Drop：撤回某项要求。
- **Refresh（视觉证据更新）**：请求保持不变，新画面改变可接受答案：
  - Replace：新证据使先前选择失效；
  - Retain：新证据不改变先前选择的合法性。
- **Clarify（主动澄清）**：场景中存在多个可能指代对象，智能体可提问，系统返回经审核的固定回复：
  - Position：空间位置；
  - Sequence：时间顺序；
  - Variant：颜色、尺寸等可见属性。

### 2.3 异步状态演化设计

环境分别维护三个演化状态：

- **第一人称观察**：按固定回放时间表逐步投递，每步推进 8 秒源视频，1 fps 采样，通常四帧拼为一张图。
- **用户需求**：按预定义时间表在特定决策步投递 Graft 后续请求。
- **网站状态**：仅由智能体动作改变，且跨更新持续保留。

形式化地，用 \(x\) 表示当前网站状态，\(G\) 表示满足已解析请求的可接受状态集合。新观察或请求修订可在不改变 \(x\) 的情况下改变目标集合：

\[
(x, G^-) \rightarrow (x, G^+)
\]

其中 \(G^-\) 与 \(G^+\) 分别为更新前后的可接受状态集合。这使智能体必须区分“初始选择错误”与“更新后选择失效”。

### 2.4 任务构造与验证流程

- 从 Ego2Web、CaptainCook4D、HD-EPIC、EgoOops、EgoLife、HoloAssist、EgoSchema 等来源选取真实第一人称活动片段。
- 构造流程包括：
  1. **Ground a request**：将请求锚定到物理指代物，并设计一次信息变化；
  2. **Construct goal sets**：在冻结网站上枚举可接受最终状态；
  3. **Verify**：程序检查、盲解、反例审查、开发运行与轨迹复核。
- **可接受目标集**：
  \[
  G(i)=\{x\in X_{\text{site}}: x\models R_i\}
  \]
  其中 \(R_0\)、\(R_1\) 为初始与最终要求。Graft 和 Refresh 同时验证更新前后两个目标集。
- **信息捷径检查**：若仅凭请求文本或非更新信息即可唯一确定答案，则视为存在捷径，需要修改请求或更换素材。
- **独立审查**：由独立 Coding Agent 在未见答案前先给出解法，再检查答案覆盖与捷径；未解决的语义问题交由人工复核。

### 2.5 交互环境与输入

- 构建 Amazon、YouTube、Google Maps 的本地模拟站点，支持搜索、加购、保存视频/地点等操作。
- 每步输入包括：
  - 第一人称观察；
  - 当前网页截图与可访问性树；
  - 按投递步标注的用户消息。
- 每步仅允许一个 JSON 动作；主要评估最多 20 步，组合任务最多 30 步。
- 视觉历史策略：
  - Full：保留全部帧；
  - Compressed（默认）：旧批次隔帧保留，约 0.5 fps；
  - Summarized：旧批次由模型生成文本摘要替代。
- 投递方式：
  - Concurrent：执行中随批次到达；
  - Wake-up：若智能体提前结束，后续请求唤醒执行，网站状态保留，待机不消耗动作步。

### 2.6 评分

最终网站状态归一化为 \(N(x_T)\)，与验证目标集比较：

\[
\text{Success}(x_T)=1[\exists g\in G: N(x_T)=N(g)]
\]

- 只检查终止状态，中间错误若被修正不扣分。
- 不要求必须提问，也不要求额外提交动作。
- 归一化忽略展示顺序，并处理注册过的包装等价关系。

## 6. 主要结论与发现

- **总体性能差距**：
  - 六模型等权平均成功率：Computer-Use **86.1%**，Offline Ego Use **64.2%**，Online Ego Use **63.4%**。
  - Online 比 Computer-Use 相对下降 **26.3%**；Online 与 Offline 平均仅差约 1.2%。
- **Online 内部差异大**：整体成功率从 Kimi 的 39.0% 到 Terra 的 87.0% 不等；Terra 在三个任务类型上均领先。
- **任务类型差异**：
  - Graft 相对 Computer-Use 的平均下降最小。
  - Clarify–Position 在两种 Ego Use 设置中下降最大，说明空间指代仍难解析。
  - Offline→Online 时，Refresh–Replace 平均下降最大，四个模型退步、无人提升；Graft–Replace 反而平均提升。
- **成功率接近但成功集合变化大**：例如 qwen3.5-27b 在 Offline 成功 83 个、Online 成功 82 个，但 200 个任务中有 53 个结果发生变化；Kimi 有 23 个丢失、20 个新增。
- **Token 成本**：Online 比 Offline 少用 16.4%–38.0% token，主要来自输入侧第一人称图像减少，而非输出更短。
- **输入条件影响**：
  - Concurrent 投递优于 Wake-up；Wake-up 下智能体常找到新答案却保留旧选择。
  - 更多视觉历史并不稳定提升成功率；Compressed 对 Terra/DeepSeek 最好，Summarized 对 Kimi 最好。
  - 场景变化提示略有帮助；附加场景描述对部分模型有帮助，但也可能诱导错误替换。
  - 回放速度影响不一致：Terra 在 8 s/步最好，DeepSeek 与 Kimi 在 16 s/步最好。
- **请求更新次数**：更多请求更新并不一致地增加难度；插入额外请求平均不降低甚至提高成功率，合并请求可好可坏，且结果在重复运行间会反转。
- **失败归因**：
  - Context Grounding 中的 Linking 是 Computer-Use 失败主因（90.2%），也是 Kimi/qwen 在 Online 中的主要失败类型。
  - Intent Continuity 是 Terra 和 DeepSeek 在两种 Ego Use 设置中的首要失败类别，占其 Online 失败的 45.7%。
  - Execution Adaptation 中的 State Control 与 Verification 占 Online 失败约 9.2%。
  - 典型错误是“找到正确的新选项，但未删除已失效的旧选择”。

## 7. 优点

- **问题定义新颖**：首次系统提出 Ego Use 范式，并区分 Offline 与 Online Ego Use，明确“执行中上下文演化”这一被忽视的评测维度。
- **状态建模清晰**：将第一人称观察、用户需求、网站状态解耦为三个独立演化状态，便于控制变量和归因分析。
- **任务变化机制系统**：Graft、Refresh、Clarify 覆盖用户驱动、环境驱动和智能体主动三类信息更新，且进一步细分子类型。
- **验证严谨**：
  - 同时验证更新前后目标集，可区分初始错误与更新后失效；
  - 显式检查信息捷径；
  - 使用独立盲解与人工复核；
  - 接受包装等价和多种合理答案，减少评分偏差。
- **实验对照设计较好**：三设置在相同任务、网站和预算下匹配比较；输入条件消融保持任务固定，采用配对统计和录音级 bootstrap。
- **分析深入**：不仅报告成功率，还分析 token 成本、更新投递时网站状态、失败轨迹、澄清行为及重复运行方差，揭示“分数接近但行为不同”的现象。
- **实践启示明确**：指出智能体需具备“识别新信息如何使旧选择失效并主动修正网站状态”的能力，而不仅是找到新答案。

## 8. 不足与局限

- **环境覆盖有限**：仅模拟 Amazon、YouTube、Google Maps 三类网站，任务集中在购物、教程检索和地点收藏，难以代表复杂跨应用、桌面软件或多步骤工作流。
- **真实可穿戴交互简化**：
  - 第一人称视频为预录制回放，非真实实时流；
  - 澄清回复为固定文本，不评估提问质量；
  - 未建模真实设备延迟、隐私、能耗和用户多模态反馈。
- **样本与统计限制**：
  - 主实验每任务仅一次运行，单次结果方差未充分报告；
  - Refresh、Clarify 及部分子类型样本量小，细粒度结论可能不稳定；
  - 组合任务仅两个模型参与。
- **模型与接口偏差**：所有模型共享固定 JSON 动作接口，UI-TARS 因接口不适配得分为 0，说明结果受接口适配影响；模型版本为论文设定的未来模型，外部复现依赖其可用性。
- **评分只关注最终状态**：不惩罚过程错误，也不要求澄清或提交动作；可能掩盖“碰巧得到可接受状态”的行为差异。
