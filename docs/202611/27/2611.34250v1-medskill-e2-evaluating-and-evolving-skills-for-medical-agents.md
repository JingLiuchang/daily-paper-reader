## 摘要
大型语言模型（LLM）智能体越来越多地使用技能来获取领域知识并完成真实世界任务。我们观察到，即使技能已规定了任务所需的规则和流程，智能体在自主执行时仍可能无法有效应用这些规则和流程，我们将这一现象称为技能已启用但利用不足（skill Enable But Underuse, EBU）。这一问题在医疗任务中尤为关键，因为忽视单个关键约束就可能产生看似合理但错误的结果。为评估并解决 EBU，我们提出 MedSkill-E$^{2}$，一个用于评估和演化医疗智能体技能的框架。我们构建了 EBU-Bench，这是一个具有挑战性的基准，涵盖 12 个医学相关任务组及相关技能，用于评估智能体自主使用可用技能的能力。我们将 EBU 差距量化为同一技能在自主使用与显式引导下阅读并应用时的技能使用准确率之差。在 EBU-Bench 上，所有被评估的模型–执行框架组合均表现出 EBU，平均差距为 43.94 个百分点（pp）。对于同一模型，自主使用下的技能使用准确率在不同执行框架间最多相差 38.96 pp。受这些观察启发，我们提出 EBU-Evolve，它利用自主使用和显式引导使用技能时的执行反馈，将有效指导提炼为可复用的技能指令。相对于演化前版本，修订后的技能在自主执行中将技能使用准确率提高了 33.33 至 55.17 pp，并且在迁移到多个模型和执行框架时仍能带来提升。我们的结果表明，在模型和技能固定的情况下，自主技能使用准确率会随执行框架而变化，模型排名也可能改变。即使技能已被打开，EBU 仍可能持续存在。EBU-Evolve 能提高同一技能下未见任务的自主技能使用准确率，且收益可迁移到不同模型和执行框架。

## Abstract
Large language model (LLM) agents increasingly use skills to access domain knowledge and complete real-world tasks. We observe that even when a skill specifies the rules and procedures needed for a task, agents may fail to apply them effectively during autonomous execution, a phenomenon we call skill Enable But Underuse (EBU). This issue is particularly consequential in medical tasks, where overlooking a single critical constraint can yield a plausible but incorrect result. To evaluate and address EBU, we introduce MedSkill-E$^{2}$, a framework for evaluating and evolving skills for medical agents. We construct EBU-Bench, a challenging benchmark covering 12 medically relevant task groups and associated skills, to evaluate agents' ability to use available skills autonomously. We quantify the EBU gap as the difference in skill-use accuracy between autonomous use and explicitly guided reading and application of the same skill. On EBU-Bench, all evaluated model-harness combinations exhibit EBU, with a mean gap of 43.94 percentage points (pp). For the same model, skill-use accuracy under autonomous use differs by up to 38.96 pp across harnesses. Motivated by these observations, we propose EBU-Evolve, which uses execution feedback from autonomous and explicitly guided skill use to distill effective guidance into reusable skill instructions. Relative to their pre-evolution versions, the revised skills improve skill-use accuracy during autonomous execution by 33.33 to 55.17 pp and continue to yield improvements when transferred across multiple models and harnesses. Our results show that autonomous skill-use accuracy varies across harnesses with the model and skill held fixed, and model rankings can change. EBU can persist even after a skill is opened. EBU-Evolve improves autonomous skill-use accuracy on unseen tasks within the same skill, with gains transferring across models and harnesses.

- **研究问题**：
  1. 在模型与技能固定时，EBU 在不同模型和执行框架间如何变化？

## 2. 方法论

### 2.1 问题形式化与核心指标

- 对每个任务给定：问题描述、数据、关联技能、工具环境；智能体提交最终答案，由固定评分程序判定（0/1）。
- 定义**技能使用准确率** \(P(m,h)\)：模型 \(m\) 在框架 \(h\) 下，在任务集上的平均得分。
- 定义 **EBU 差距**：
  \[
  \Delta_{\text{EBU}}(m,h) = P_{\text{supported}}(m,h) - P_{\text{natural}}(m,h)
  \]
  其中 supported 为"操作支持下的技能使用"，natural 为"自然技能使用"。该差值衡量"技能本可带来的收益中，智能体自主执行时尚未兑现的部分"。允许负值，跨框架按等权平均。

### 2.2 四种评估条件（关键实验设计）

| 条件 | 技能是否挂载 | 附加提示 | 作用 |
|---|---|---|---|
| No Skill | 否 | 无 | 无技能基线 |
| Natural Skill Use | 是（名称+描述常驻上下文） | 无 | 自主使用，主指标之一 |
| Prompted Skill Use | 是 | 仅"鼓励使用相关资源"的一般性提示 | 检验"提醒是否足够" |
| Operationally Supported Skill Use | 是 | 明确要求读全技能、识别适用流程并逐步执行 | 提供收益上界经验参考（不泄露答案） |

- 技能采用**渐进式加载**：仅名称与描述常驻上下文，正文 `SKILL.md` 与 `references/` 需智能体主动打开。

### 2.3 EBU-Evolve：从"干预"到"指令"的蒸馏

核心思想：**把"操作支持"带来的执行改进，持久化写回技能文本**，使后续自主执行无需逐任务提示。流程如下：

1. **配对执行证据采集**：在同一任务、同一技能版本、同一模型与框架下，分别跑 Natural 与 Supported 两条轨迹，记录工具调用、返回、最终答案、得分、是否打开技能。
2. **反思（Reflection）**：将配对轨迹、原始技能与参考资料、全部训练对概览、访问诊断（未读取 / 读取但误用 / 未知）输入反思模型，产出**可复用的修订规则**（明确适用条件、执行步骤、结果如何使用），并要求引用可在原技能包中定位。
3. **联合改写描述与正文**：一次编辑同时产出修订后的描述 \(d'\) 与正文 \(b'\)，构造三个候选：
   - 仅正文：\(s_{\text{body}}=(d_0,b')\)
   - 联合：\(s_{\text{joint}}=(d',b')\)
   - 仅描述：\(s_{\text{description}}=(d',b_0)\)
4. **候选审查**：编辑规模上限、原文可定位性检查、来源核验（新增标识符/依赖/链接）、独立语义审查（是否被原材料支持、是否篡改适用条件）；不通过可依审查意见修复一次（不使用验证/测试反馈）。
5. **验证集选择**：在 Natural Skill Use 下用同一模型/框架评测，每任务重复 \(K=3\) 次，目标函数
   \[
   J(s)=\frac{1}{|V|}\sum_{i\in V}\Big(\frac{1}{K}\sum_{k=1}^{K} y_{i,k}(s)\Big)
   \]
   仅在**严格优于原始技能**时采纳；平局保留原始，修订间平局取编辑量小者。
6. **冻结与测试**：选定版本冻结后在**未参与改写与选择的测试任务**上评估；测试反馈不回流。
7. **约束**：不改模型参数，不改参考文件/代码/数据，只改指令文本；新增内容不得包含训练任务 ID、具体数值或答案。

### 2.4 两个 EBU 机制诊断（定性）

- **规则未获取**：只读主 `SKILL.md`，未打开判断所需的 `references/` 文件。
- **条件识别但未落实**：识别到任务条件，却未把该条件带入计算（如把"assay 合格但无注释"的实体排除，导致背景集从 12 缩为 10）。

## 3. 实验设计

### 3.1 基准：EBU-Bench

- **规模**：331 个任务（**EBU-Bench Lite 154 个**用于主实验），覆盖 **12 个任务组 / 4 类工作类型**。
- **构成**：
  - 公开基准筛选 113 个：MedCalc-Bench 78（HAS-BLED 8、PSI 2、Delta gap 30、白蛋白校正 Delta gap 38）、BixBench 35（4 个数据胶囊）。
  - 自建/扩展 218 个：摘要筛选 61、临床证据筛选 53、变异功能证据 53、富集审查 51（基于 TrialPanorama、ClinGen SVI PS3/BS3 框架、GEO GSE10586 等公开材料）。
- **三阶段构建筛选**：
  1. 无技能可解性筛选（先 DeepSeek V4 Pro，再 GPT-5.5，9,646 → 9,305 → 2,966 → 1,293）；
  2. 技能配对与有效性验证（15,368 候选技能 → 1,996 → 1,478 检索池；须在 Supported 下可完成）；
  3. **自主使用差距筛选**：保留"Supported 可完成但 Natural 不可完成"的任务（主要用 GLM-5.1）。
- **Lite 子集规则**：保留全部 113 个公开任务 + 每个"源问题–技能"组合各取 1 个代表任务（41 个），选取与评估结果无关。

### 3.2 模型与执行框架

- **9 个模型**：GPT-5.5、Claude Opus 4.8、Gemini 3.8 Flash、DeepSeek V4 Pro、GLM-5.2、Atria-Dawn-Preview、Kimi K2.7 Code、Qwen3.8 Max、Qwen3.8 27B FP8。
- **2 个框架**：Claude Code 2.1.257、Codex 0.148.0（经 codex-acp 1.6.0）。
- **执行环境**：BenchFlow 0.7.7，独立容器，禁用外部检索与数据下载以防泄漏。
- **总计**：9 × 2 × 4 × 154 = **11,088 条运行记录**。

### 3.3 对比方法

- **GEPA**（反思式提示演化）与 **SkillOpt**（技能优化），各在 Std（标准反馈）与 Paired（配对证据）两种设置下，同一预算与编辑权限。
- **通用轨迹反思改写（Generic trace-reflection rewriting）**：仅用 Natural 轨迹反馈。
- **规则前置（Rule frontloading）**：仅给原始材料、无执行反馈，把规则前移到描述。
