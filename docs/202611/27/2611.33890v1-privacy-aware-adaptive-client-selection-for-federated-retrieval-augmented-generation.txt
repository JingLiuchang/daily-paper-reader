Abstract 

Federated retrieval-augmented generation retrieves evidence from distributed corpora, but broadcast-ing queries increases retrieval work and query exposure. We present Privacy-aware Adaptive Client Selection for Federated Retrieval-Augmented Generation (PACS-FedRAG), an online selector com-bining perturbed semantic profiles with evidence feedback, latency, payload cost, and exploration. In a ten-client simulation selecting three clients, the archived end-to-end benchmark reports evi-dence overlap of 0.372 and answer accuracy of 0.287. However, the retrieval-only evaluation reuses a full-broadcast reference with different fusion tie-breaking. Disjoint-client rank fusion also imposes an overlap ceiling of 0.375, limiting its relevance interpretation. Accuracy is below a fixed-label diagnos-tic of 0.645, and raw generator responses are unavailable for parser verification. Corrected baselines and new answer-level evaluation are therefore required to assess quality preservation. Selecting three clients reduces query recipients by 70%; profile perturbation does not provide query or passage confidentiality.  

> Keywords: Federated retrieval-augmented generation, Client selection, Resource-aware routing, Differential privacy, Distributed information retrieval, Online adaptation

# 1 Introduction 

Retrieval-augmented generation (RAG) combines parametric generation with non-parametric evi-dence retrieval, allowing a language model to con-dition its output on external documents [1]. The architecture is particularly useful for knowledge-intensive question answering because the evidence store can be updated without retraining the gen-erator. In many practical deployments, however, useful evidence is distributed across hospitals, lab-oratories, companies, or devices that cannot pool their complete document collections because of governance, ownership, confidentiality, or infras-tructure constraints. Federated learning estab-lished a broader paradigm for collaboration with-out centralizing raw training data [2, 3]; federated RAG extends the same decentralization principle to retrieval and generation. The Flower FedRAG example provides a refer-ence pipeline for federated retrieval [4]. It queries client-side FAISS indexes and combines returned candidates before generation. This architecture provides a useful basis for studying selective retrieval, but full broadcast requires retrieval work at every available source. Our implementation reuses Flower FedRAG components in a sequential 1arXiv:2611.33890v1 [cs.IR] 25 Nov 2026 simulation; it is not a deployment benchmark of independent organizations or a distributed Flower Message API experiment. Full broadcast increases the number of query recipients and the aggregate local retrieval work. It also enlarges the candidate pool processed by the coordinator; the effect on latency depends on concurrency, network conditions, fusion, and gen-eration. A query sent to an irrelevant source is still disclosed to that source. We therefore distinguish the number of recipients, a data-minimization measure, from formal query confidentiality. The system problem is to allocate a limited retrieval budget while retaining useful evidence, not simply to reduce the number of contacted clients. Source selection is a classical problem in feder-ated information retrieval [5]. RAGRoute applies a lightweight neural classifier to source selection for retrieval-augmented generation [6]. Client selec-tion itself is therefore not the novelty claimed here. PACS-FedRAG investigates a complemen-tary design: query-dependent semantic matching combined with online evidence and system feed-back, without task-specific router training. RAGRoute is retained as closely related work, but is not implemented or evaluated in this study; no empirical superiority over it is claimed. PACS-FedRAG (Privacy-aware Adaptive Client Selection for Federated RAG) scores clients using a perturbed corpus centroid, historical evi-dence contribution, measured retrieval latency, estimated payload cost, and an exploration bonus. It selects a fixed number of available clients, combines their candidates using reciprocal rank fusion (RRF), and updates client statistics after retrieval. This design provides a lightweight rout-ing policy for a coordinator that cannot inspect complete remote corpora in its intended deploy-ment. Its current evaluation isolates the selection policy in a local simulation. The contributions are as follows: 

• An online, fixed-budget selector that combines semantic relevance with historical evidence con-tribution, retrieval latency, payload cost, and exploration, without fitting a separate super-vised router. 

• A Gaussian-perturbed profile mechanism with an explicit replace-one adjacency model and sensitivity calculation, separating profile protec-tion from passage disclosure and query-recipient reduction. 

• A comparison against full broadcast, ran-dom selection, round-robin selection, and static perturbed-profile selection on two biomedical question sets, with fixed retrieval budgets and published per-query records. 

• A retrieval-only privacy-budget sweep and com-ponent analysis with per-query records and cali-bration provenance, with explicit limitations on baseline compatibility and overlap-metric valid-ity, and an assessment of deterministic rerun consistency. The paper does not claim end-to-end confi-dential inference, a new differential privacy mech-anism, or an optimal routing policy. Selected passages are intentionally disclosed to the coordi-nator, and queries are visible to selected clients. The intended privacy scope concerns released pro-files under the assumptions in Section 3.3. The publicly seeded simulation is not a production privacy guarantee. 

# 2 Related Work 

## 2.1 Retrieval-Augmented Generation 

Lewis et al. introduced RAG as a sequence-to-sequence generation framework that combines a pretrained generator with retrieved passages [1]. Subsequent RAG systems commonly use dense embeddings, approximate nearest-neighbor search, candidate reranking, and evidence-conditioned generation. FAISS provides efficient vector indexing and similarity search primitives used by many such pipelines [7]. For medical RAG evaluation, MIRAGE/MedRAG unifies sev-eral QA datasets and four corpora and reports both retrieval and answer-level outcomes [8]. These components motivate our use of the exist-ing Flower pipeline instead of constructing an unrelated system. 

## 2.2 Federated RAG and Confidential Retrieval 

Federated RAG retains source documents at participating data providers while coordinat-ing retrieval and generation. C-FedRAG places 2orchestration and inference inside a confidential-computing environment to protect intermedi-ate results from an over-curious orchestrator [9]. FRAG studies secure and efficient feder-ated vector-database management and crypto-graphic protocols for collaborative retrieval [10]. FedE4RAG focuses on federated embedding learn-ing, knowledge distillation, and homomorphic protection of exchanged model information [11]. Other work combines federated fine-tuning and RAG for domain-specific language models [12]. A systematic mapping study identifies privacy-preserving retrieval, cross-client heterogeneity, and limited evaluation practice as central open concerns [13]. These systems span different privacy goals. Keeping raw corpora local prevents wholesale data centralization but does not by itself guarantee that retrieved passages, semantic profiles, model updates, or queries reveal no sensitive information. C-FedRAG explicitly calls for threat modeling and considers differential privacy and trusted exe-cution environments as complementary technolo-gies [9]. PACS-FedRAG therefore states a limited threat model and applies formal perturbation only to the profile used for routing. 

## 2.3 Client and Source Selection 

Federated learning uses client selection to man-age statistical utility, system heterogeneity, and training speed. FedAvg samples clients and aver-ages local model updates [3]. Oort preferentially selects clients that offer high statistical util-ity while accounting for execution speed [14]. Power-of-choice selection shows that non-uniform client choice can accelerate federated optimization under heterogeneous data [15]. Our problem dif-fers because clients do not train a shared model in each query round; they retrieve evidence. Nev-ertheless, the underlying idea—balancing utility, cost, and exploration—transfers naturally. In federated search, resource selection esti-mates which collections are useful for a query [5]. RAGRoute is the closest related source-routing approach: it uses a trained neural classifier rather than the heuristic online score studied here [6]. PACS-FedRAG combines profile similarity with observed evidence contribution and system costs, and perturbs routing profiles. These are design distinctions, not measured advantages over RAGRoute. The archived experiments include only non-neural selectors, and the validity limita-tions in Sections 4.6–4.10 constrain their interpre-tation. A controlled comparison with RAGRoute would require common corpus partitions, retrieval settings, evaluation queries, and a stated router-training protocol. Routing also introduces integrity risks. Aclient that advertises a misleading semantic pro-file can attract queries and return irrelevant or poisoned evidence [16]. We assume honest clients and an honest-but-curious coordinator. Evidence feedback may reduce a client’s score after unhelp-ful returns, but this is not a Byzantine-robust defense and has not been evaluated as a poisoning detector. 

## 2.4 Differential Privacy 

Differential privacy (DP) limits changes in the output distribution between neighboring datasets [17, 18]. Here, neighboring corpora have the same public size and differ in one indexed record. The retrieval-only implementation uses the ana-lytically calibrated Gaussian mechanism [19] for a bounded-sensitivity centroid. This calibration provenance does not extend retrospectively to the earlier end-to-end run. Releasing a new inde-pendently randomized profile consumes privacy budget; reusing the same released profile for computations based only on that profile is post-processing. Composition would be required for repeated releases [20, 21].

A record is an indexed text chunk; protection for a com-plete source document containing multiple chunks would require separate group-privacy accounting. Queries arrive sequentially. A coordinator selects St from the available clients At, with |St| =min(m, |At|), and provides returned evidence to a generator. All clients use a common embedding model E. ## 3.2 Threat Model and Privacy Scope 

The intended coordinator is honest-but-curious and clients are honest. Authenticated, encrypted transport is an operational assumption, not aproperty tested by the local simulation. Com-plete corpora and indexes remain client-side in the intended architecture, but are loaded locally by the experimental driver. Selected passages are deliberately returned for generation and lie out-side the profile privacy mechanism. The coordi-nator and selected clients observe query content. Recipient reduction measures less dissemination, not concealment from those parties. The protected contribution is one indexed record in a released client profile. Adjacency means replacing one bounded record in a corpus of fixed public size. A fixed profile can be reused for profile-only computations without an addi-tional release, whereas regenerating noisy profiles requires composition. A server transcript that also contains retrieved passages and evidence-derived feedback is not covered by a profile-only DP claim. The simulation generates profiles separately for each seed; those runs do not constitute a single accounted private deployment.

## 3.6 Complexity and Communication 

Computing profile similarities and client statistics costs O(Nd) per query and stores O(Nd) profile coordinates plus O(N) state. The current imple-mentation sorts all scores, costing O(N log N); a bounded heap could reduce selection to O(N log m), but is not used here. Only m indexes are searched instead of N, and up to mk candidates replace up to Nk. The recipient ratio is m/N and the ideal candidate-count reduction is 1 −m/N. These arithmetic reductions follow from the bud-get and are shared by all fixed-m selectors. Actual payload and latency depend on returned text length, scheduling, transport, and generation. The experiment measures the sequential simulation rather than parallel cluster speedup. 

# 4 Experiments 

## 4.1 Research Questions 

The evaluation separates the earlier end-to-end benchmark from the retrieval-only validation and addresses four questions: 6• RQ1: What answer accuracy and overlap with full-broadcast evidence are observed when three of ten clients are selected? 

• RQ2: How does PACS-FedRAG compare with random, round-robin, and static perturbed-profile selection at the same budget? 

• RQ3: How do analytically calibrated profile-noise settings affect selected-client agreement, evidence overlap, participation uniformity, and communication volume? 

• RQ4: How are evidence overlap, participation uniformity, and communication volume associ-ated with removing historical utility, latency components, or exploration from the selector? 

## 4.2 Datasets and Federation Construction 

The experiment uses the StatPearls and Text-books retrieval corpora and the PubMedQA and BioASQ question sets through the Flower FedRAG/MIRAGE workflow [4, 8]. PubMedQA originates from biomedical research questions [23]; BioASQ provides biomedical question-answering tasks [24]. The evaluated data are the option-based versions loaded by the repository, not every task or original answer format in those bench-marks. Table 1 lists the subsets used. The federation contains N=10 simulated clients: five per retrieval corpus. Each corpus con-tributes 2,000 indexed chunks. The repository assigns chunk identifiers to clients by a seeded SHA-256 hash modulo five. This creates coarse source heterogeneity, but is not a controlled topic-skew or realistic institutional partition. Chunks from one original source document need not remain in one silo. The driver evaluates the first 100 loaded questions per dataset, using the same order across methods and seeds. Thus there are 200 distinct question identifiers, rather than 600 independent questions across the three runs. The partition seed is 42: a chunk d is assigned within its corpus to integer(SHA-256(”42 ” + d)) modulo five. This chunk-level rule does not keep all chunks from one source document together. The scorer is initialized anew for each dataset and seed.

## 4.4 Baselines 

Full queries all ten client indexes and serves as the broadcast reference. Random-3 samples three available clients uniformly; Round-Robin-3 cycles through clients without query information. Static-DP-3 selects the three highest profile similarities without evidence feedback. PACS-DP-3 uses the complete score. All selective methods have the same client budget. RAGRoute [6] is discussed as closely related work but was not implemented or evaluated. Consequently, these experiments do not compare PACS-FedRAG with supervised neu-ral routing or support a claim of superiority over RAGRoute. No-RAG is not an evaluated condi-tion.

## 4.7 Privacy Budget Analysis 

At ε=4 and ε=1, selected-client Jaccard over-lap with the unperturbed route is 0.706 ±0.010 and 0.571 ±0.017, respectively. Thus the profile-noise setting changes routing on this fixed work-load. Archived-reference evidence overlap is non-monotonic, but it is constrained by Eq. (13) and by the fusion mismatch; it cannot establish that noise improves or preserves retrieval util-ity. The reported total text-payload means are 12,330, 12,425, and 13,283 bytes for ε=∞, 4, and 1. Returned-text means alone are approximately 12,106, 12,200, and 13,059 bytes. Matching deter-ministic fields across the two stored runs supports rerun consistency under fixed artifacts, not valid-ity of the Full reference, robustness to resampling, or independent reproduction.

## 4.9 Component Analysis 

Removing historical utility changes archived-reference overlap from 0.358 to 0.328 and increases participation uniformity from 0.479 to 0.758. Removing the complete latency penalty gives over-lap 0.375, exactly the structural ceiling in Eq. (13), alongside lower Jain index and fewer text bytes. This does not demonstrate the best relevance or answer quality: the metric rewards avoiding two arbitrarily excluded reference clients. These ablations describe selection and payload behavior under one calibration and query order. They do not isolate a causal speed benefit of the latency penalty, and a common-protocol Full comparison is still required. Any change to fusion that changes the reward requires rerunning complete online tra-jectories rather than replacing final evidence in stored rows. 

## 4.10 Descriptive Analysis and Reproducibility 

No confirmatory significance or noninferiority claim is made. Repeated questions across seeds and online state dependence preclude treating all records as independent observations. Table 3 pre-serves its historical population SD across three seed means (ddof=0); Tables 4 and 5 preserve sample SD (ddof=1). These measures are descrip-tive and are not confidence intervals. Matching deterministic fields in two stored retrieval-only runs demonstrates consistency for fixed inputs; wall-clock fields remain observational. The anal-ysis uses archived records; no new retrieval or generation experiment is reported. Independent reproduction requires the upstream data, indexes, models, and recorded environment.

The published records permit inspection of client selection, label predictions, calibration, and payload accounting. Selecting three of ten clients reduces direct query recipients by 70%, a property shared by all three-client selec-tors; it is not end-to-end confidential inference. Feedback is sensitive to fusion semantics. With disjoint chunk identifiers, equal local ranks pro-duce equal RRF scores. Insertion-order ties in the archived driver and document-ID ties in the retrieval-only driver select different subsets. Either deterministic convention can make a survival-based reward reflect an arbitrary ordering rather than relevance. Recomputing a same-protocol Full baseline repairs reference compatibility, but does not by itself repair the weak relevance interpre-tation of rank-only fusion in this partition. A relevance-sensitive fusion control and validated answer-level evaluation are needed. Malicious routing remains an untested integrity risk [16]; exploration and EWMA are not demonstrated poisoning defenses. The immediate next evaluation should use an identical, explicitly versioned fusion protocol for Full and selective methods, validate answer parsing with retained raw outputs, and include dataset-level and no-RAG controls. A changed fusion/reward policy requires new complete online sequences. Broader extensions include client-budget sweeps, topic-skewed partitions, query-order changes, availability changes, independently remeasured latency profiles, and distributed throughput and tail-latency measurements. Gold relevance judgments, dependence-aware uncer-tainty analysis, supervised-router comparisons, multi-centroid profiles, and malicious-client tests remain open work. 

# 6 Limitations 

The strongest limitation is measurement validity: archived-reference overlap is structurally capped and tied to arbitrarily favored clients, while the retrieval-only Full cache uses incompatible tie-breaking. Archived answer accuracy is below the fixed-label diagnostic, and absent raw responses prevent retrospective verification of parser behav-ior. Corrected same-protocol and answer-level results are not yet available. External validity is further limited by a sequential ten-client simula-tion, two restricted corpus subsets, the first 100 questions per dataset, one fixed budget, coarse hash partitions, fixed query order, and one latency calibration. The 600 question–seed records con-tain only 200 distinct questions. The scorer resets between datasets. Retrieval-only runs omit gen-eration, and the earlier end-to-end run lacks equivalent analytic profile-calibration provenance. Neither three deterministic seeds nor a dupli-cate run demonstrates sensitivity to resampling or fresh production randomness. The study does not test malicious clients, profile poisoning, query privacy, passage confidentiality, dropouts, net-work contention, or composition across repeated releases. 

# 7 Conclusion 

PACS-FedRAG is an online fixed-budget selec-tor that combines perturbed semantic profiles with evidence and systems feedback. Its imple-mentation and archived results make the pol-icy inspectable, and the three-client budget reduces direct query recipients by 70% in the ten-client simulation. The archived end-to-end result is 0.372 ±0.001 overlap@8 against Full and 0.287 ±0.002 answer accuracy. Those values do not establish quality preservation: the overlap metric 12 has a 0.375 structural ceiling, accuracy is below a fixed-label diagnostic, and the retrieval-only com-parisons use a fusion-incompatible archived Full reference. Analytic Gaussian provenance supports the stated retrieval-only calibration, but not a production-private deployment or a retrospective guarantee for the earlier run. Corrected baselines, validated generation outputs, and complete reruns after reward-affecting changes are required before stronger performance conclusions can be drawn. The implementation and versioned result records are available in the project repository. Reproducibility details are provided in Data and Code Availability.
