## 摘要
大语言模型智能体可以利用来自先前任务轨迹的程序性记忆，随时间实现自我改进，但来自局部成功与局部失败的记忆各自具有的不同效用仍未被充分探索。本文在一种现实设定中研究这一问题，该设定包含多领域工具使用任务的异构流以及真实场景中常见的各种环境约束。我们提出了“双极性记忆与周期性维护”（Dual-Polarity Memory with Periodic Maintenance，DualPM），这是一种简单且无需检索的记忆工作流，其特点在于：（1）可针对每条轨迹中的局部成功与局部失败，定制化地生成反思与程序性记忆；（2）在给定记忆容量下，对长任务流进行周期性记忆巩固，从而防止记忆爆炸。采用细粒度指标的在线预序评估表明，失败记忆更能拓宽覆盖范围，成功记忆更能精简执行过程，而结合这两种极性能够有效整合二者的优势。进一步研究表明，DualPM 能够实现跨域记忆泛化与持续记忆适应，同时在 EvoMemBench 上的外部评估揭示了 DualPM 作为一种通用长期程序性记忆方法的可移植性与有效性。

## Abstract
Large language model agents can self-improve over time by utilizing procedural memory derived from prior task trajectories, yet the distinct utilities of memories derived from local successes and failures remain underexplored. This work studies this question in a realistic setting with heterogeneous streams of multi-domain tool-use tasks and various environment constraints common in real-world scenarios. We develop \emph{Dual-Polarity Memory with Periodic Maintenance} (DualPM), a simple, retrieval-free memory workflow characterized by (1) customizable reflection and procedural memory generation from both local successes and failures within each trajectory, and (2) periodic memory consolidation over long task streams under a given memory capacity, preventing memory explosion. Online prequential evaluation with fine-grained metrics reveals that failure memory more strongly broadens coverage, success memory better streamlines execution, while combining both polarities effectively integrates both benefits. Further studies demonstrate that DualPM enables cross-domain memory generalization and continual memory adaptation, while external evaluation on EvoMemBench reveals the portability and effectiveness of DualPM as a general long-term procedural memory method.

- **研究缺口二（局部成败）**：成功/失败可以发生在**轨迹内部局部层面**——成功轨迹可能含应避免的局部失败，失败轨迹也可能含值得复用的有效行为。
- **研究缺口三（真实环境约束）**：真实用户场景中往往缺乏显式结果信号，且存在用户请求隐晦、工具集庞大且嘈杂、工具非全量可见、记忆池容量固定等约束。如何在这种异构多领域任务流中**长期维护**可用的程序性记忆，仍缺乏探索。
- **核心研究问题**：成功记忆与失败记忆，单独及联合使用时，分别如何影响智能体表现？

## 2. 方法论：DualPM

### 2.1 核心思想
- **双极性、免检索**的程序性记忆工作流：对每条完成的任务轨迹同时反思**局部成功**与**局部失败**，分别生成两类记忆草稿，并在长任务流中**周期性巩固**为两个独立记忆池，在容量约束下注入后续任务。

### 2.2 形式化与流程
- **问题设定**：给定有序任务序列 $\{t_i\}_{i=1}^n$，智能体在记忆上下文 $M_i$ 下产生轨迹 $\tau_i \sim \pi(t_i, M_i)$；目标是把历史轨迹转为记忆上下文以改善后续任务，且**不更新模型、运行框架或环境**。
- **分块循环（Blockwise Cycle）**：将任务序列切为大小 $b$ 的连续块 $B_k$，每块依次执行三阶段：
  1. **任务阶段**：块内所有任务使用**冻结**的同一记忆上下文 $M_{k-1}$ 执行，产生轨迹。
  2. **反思阶段**：对每条轨迹做**两次顺序 LLM 调用**——先反思（输入任务、可见轨迹、工具响应、最终答案，**绝不暴露金标准轨迹/参考答案**），再基于反思起草成功/失败记忆草稿（每极性至多 $d$ 条）。
  3. **维护阶段**：两个极性各做一次独立 LLM 调用，接收上一轮记忆池与新草稿，返回更新后的完整列表 $M_k^p$，满足 $|M_k^p| \le m$；允许保留、修订、合并、拆分、新建、删除，而非简单追加。
- **记忆上下文**：$M_k = M_k^+ \cup M_k^-$ 注入下一块；首块 $M_0 = \varnothing$ 冷启动。
- **记忆条目 Schema**：`memory_type`（成功/失败）、`title`（可迁移的短名）、`content`（可操作指导+理由）、`evidence`（轨迹证据，至多 $e$ 条）、`applicability`（"阶段: 可观察触发条件"形式的路由线索）、`confidence`（低/中/高）；另记录草稿索引与来源回合以保证溯源。
- **关键设计**：反思提示中的**可定制反馈信号段**定义何为局部成功/失败（如 TRAJECT-Bench 中以"收到有效工具响应"为细粒度成功信号）；失败教训须写成**建设性条件式指导**；两极性间尽量减少重叠。

### 2.3 实验环境构建
- 基于 **TRAJECT-Bench**（轨迹感知工具使用基准）构建更真实的单智能体运行时：provider-native 工具提供、并行工具调用、ReAct 式交互；工具在参数正确时回放金标准响应，否则返回通用失败消息。
- 仅用 **hard 版本**（用户请求口语化、隐晦）；将候选工具池藏在 `tool_search` 函数后（BM25 排序），模拟 ChatGPT/Copilot 式"核心工具+按需发现"。

### 2.4 阶段感知评估指标
- 将任务分解为三阶段漏斗：**发现**（Discovery recall）→ **选择**（Selection recall）→ **使用**（Usage recall、Usage precision），另加 **总轮数（Turns）** 与 **最终答案准确率**（由不同模型评判，避免同模型自评）。

## 6. 主要结论与发现

- **双极性互补**（表 2，四用户均值）：
  - **失败记忆"拓宽"**：发现/选择召回显著高于仅成功（81.0/73.9 vs 78.7/72.2，p=.002/.018），像"覆盖与补救清单"，促使智能体分解请求、持续追查未完成子任务。
  - **成功记忆"精炼"**：使用精度最高（56.2%）、轮数最少（5.4）（均 p<.001），像"路由指引"，把并行工作组织为更紧凑的轨迹。
  - **双极性结合**：召回最强（81.1/74.5/72.4），精度（53.7%）与轮数（5.5）接近仅成功；相对仅失败显著提升精度与效率（p<.001）；最终准确率最高（73.2%），但三种记忆开启条件间差异不显著（p≥.17）。
- **所有记忆开启条件**在三种召回（p≤.001）与最终准确率（p≤.015）上均显著优于无记忆。
- **行为改变**：有记忆时智能体更常将多部分请求拆为子任务专用 `tool_search` 查询，金标准工具在搜索结果中的平均排名更靠前（7.7→5.5）。
- **跨域迁移**（表 3）：冻结的异域记忆带来中等增益（准确率 72.0→75.0）；允许持续适应后可达与从零构建相当的水平（78.5 vs 78.0）。
- **记忆演化**：从零构建的记忆在第 5 块后结构趋于稳定，后续以修订/精炼为主；以迁移记忆热启动时，更新与修订持续更久。
- **EvoMemBench**（表 4）：DualPM 总体 **69.8%**，优于最佳基线 ReasoningBank（68.5%），在 4 域中的 3 域（车辆控制 84.0、交易机器人 80.7、旅行预订 47.3）领先；尽管存在"无检索 + 首块冷启动"两项设计劣势。
- **范围消融**（表 6）：仅限工具发现的记忆能提升发现召回并间接改善整体表现（准确率 56.7→64.4），但无限制的端到端记忆提升更大（69.4）。
- **成本权衡**：仅成功记忆更省 token（131.7k vs 162.3k），双极性性能更强但成本更高。

## 7. 优点

- **问题切入有新意**：首次系统区分并实证刻画"成功记忆 vs 失败记忆"的**差异化功能**（覆盖 vs 效率），而非笼统比较"有/无记忆"。
- **细粒度、阶段感知的评估体系**：将任务拆为发现/选择/使用三阶段漏斗，配合轮数与精度，能揭示最终成功率掩盖的机制性差异。
- **贴近真实的实验设定**：隐晦请求、工具隐藏于 `tool_search`、容量约束、无金标准泄漏，显著提升外部效度。
- **方法简洁、免检索、应用友好**：结构化 schema 可人工编辑；反思反馈信号段可定制（可用于安全性、简洁性、用户满意度等维度）；容量参数可控；块划分可灵活化（如按时间/低峰期触发）。
- **公平性与严谨性**：在线预序评估、共享冷启动块、配对非参数检验、异模型评判、跨环境/跨骨干模型的外部验证。

- **开源式透明度**：论文公开了完整的反思/起草/维护提示词模板、记忆条目 schema、块循环伪代码与评估配置，使"反思质量"这一最易被诟病的黑箱环节可被复现与审计；记忆池以纯文本列表维护，便于人工检查、编辑与版本管理。

## 8. 局限与可改进之处

- **设计参数缺乏系统消融**：块大小 $b$、每轨迹草稿上限 $d$、池容量 $m$、证据条数 $e$ 均取固定值，未给出敏感性曲线。由于 $b$ 直接决定"记忆新鲜度 vs 上下文稳定性"的权衡，$m$ 决定容量压缩强度，这一空白使实践者难以迁移超参数。
- **成本结构不占优**：双极性配置的加权 token 消耗最高（162.3k/回合），约为无记忆的 2.3 倍；论文虽给出成本代理指标，但未做"单位 token 增益"的效率分析，也未讨论在真实产品预算下如何按任务价值动态开关某一极性。
- **基线对比口径不完全一致**：EvoMemBench 上 DualPM 为 3 次运行均值，而多数基线数值直接引自原论文表格，运行次数、提示词与预算控制未必对齐；主实验的四种条件虽内部配对严谨，但缺少与 AWM、ReasoningBank 等外部程序性记忆方法在同一 TRAJECT-Bench 设置下的直接对比，削弱了"双极性优于现有方法"的说服力。
- **迁移实验覆盖面窄**：跨用户记忆迁移仅做 U1↔U4 一对双向案例，未考察领域距离、用户画像相似度对迁移增益的影响，也缺乏"何时应当拒绝迁移"的判定机制。
- **对反思模型能力存在隐性依赖**：局部成败的判定、建设性改写与记忆合并/拆分全部由同一 LLM 完成，论文未报告较弱骨干模型下的表现退化程度，也未分析反思错误（如把偶然成功误标为可复用技能）的传播与自我纠偏情况。
- **负迁移与安全性风险讨论不足**：失败记忆被鼓励写成条件式指导，但若触发条件写得过宽，可能抑制本可成功的探索行为；论文以平均指标呈现结果，未报告最差任务或最差用户上的退化案例。

## 9. 对读者的启示

- **"记忆不是越多越好，而是分工不同"**：把记忆极性当作可独立调度的资源——需要提高任务覆盖率、避免遗漏子目标时偏重失败记忆；需要压缩轨迹、降低轮数与误用工具时偏重成功记忆。这一视角可直接用于产品侧的开关策略。
- **评估应下沉到阶段级**：仅看最终准确率会掩盖"发现变好但使用变差"的相互抵消；三阶段漏斗 + 轮数 + 精度是复用到其他记忆系统的低成本诊断模板。
- **容量约束下的"维护"比"积累"更关键**：维护阶段允许合并、拆分、删除，而非追加式存储，这提示长期记忆系统的核心工程问题在于压缩策略与去重语义，而非存储规模。
- **冷启动与在线适应可分离设计**：迁移实验表明"冻结的异域记忆"已有中等收益，"持续适应"才能追平从零构建，说明记忆系统应默认支持在线修订而非一次性导入。

## 10. 总体评价

论文以一个干净的问题切分——把"记忆"按极性拆成两个功能假设，并用阶段感知指标给出机制层面的证据——回答了一个此前被笼统处理的问题，方法本身无需训练、易于落地，实验在真实性与公平性上高于同类工作。其不足主要不在结论可靠性，而在**参数与成本层面的工程指导性**以及**外部基线对比的完备性**。作为"记忆功能分化"这一方向的开创性实证工作，它更重要的贡献是提出了可复用的评估范式与可检验的假设，而非某个具体超参数配置。
