Agentic Waterfall: An Intent-Driven Information Discovery
Framework for Reclaiming User Control in the Attention Economy
Yige Luo, Shining Zhang, Jikun Liu, Hongjiao Qiang, Ran Guan
2012 Laboratories, Huawei
November 2026
Abstract
We formalize Agentic Waterfall Feed, a new
problem of personalized information discovery
in which users actively direct recommendations
and the system adapts to evolving needs in-
ferred from both explicit requests and browsing
behavior. We address this problem with the
Agentic Waterfall framework, whose language-
model controller maintains persistent user state
and coordinates content retrieval, ranking, and
state updates. To evaluate systems on this task,
we contribute the Agentic Waterfall Dataset
and a replay-based evaluation protocol. The
dataset combines real content metadata with
simulated interaction histories. The protocol
compares systems under shared histories using
relevance scores and blind judgments of how
well recommendations satisfy current user goals
and constraints. Agentic Waterfall remains com-
petitive with strong baselines on conventional
recommendation tasks across five public bench-
marks. On the Agentic Waterfall Dataset, it
outperforms the strongest baseline in both eval-
uations, with relative improvements of up to
16.1%.

Introduction
In the attention economy, recommendation feeds
shape what users see, while platforms determine
the objectives governing those feeds. These objec-
tives can diverge from users’ current goals [13].
Users therefore need a way to redirect recom-
mendations as their needs change. For example,
a user may move from comparing cameras to
seeking filming guides after making a purchase.
We formalize this requirement as Agentic Wa-
terfall Feed. At each interaction, a system uses
the available requests and browsing history to
infer the user’s current goal and constraints, then
decides what information to acquire and recom-
mend.
Building on this task formulation, we de-
velop the Agentic Waterfall framework, whose
language-model controller coordinates retrieval,
ranking, and state updates. It combines capa-
bilities studied in prior work on user commands
in RecBot [9], hierarchical memory in MARS
[8], and retrieval planning in ClawRec [10]. The
controller links these capabilities through a per-
sistent record of user facts, preferences, and ac-
tive goals, which it updates from requests and
browsing evidence to guide subsequent retrieval
and recommendation.
To evaluate how well a system follows these
changing needs, we introduce a replay protocol
that compares systems under the same inter-
action histories. It combines relevance scoring
and blind comparisons by a model judge, using
the current goal and constraints to assess the
recommendations. However, such adaptation is
difficult to evaluate from conventional click or
rating datasets alone.
We therefore contribute the Agentic Waterfall
Dataset, which combines real content metadata
with simulated interaction histories. We define
two targeted subsets, Behavior Ambiguity and
Interactive Revision, to address two recurring
challenges in existing recommendation systems.
Replaying these histories supports end-to-end
comparison of different recommendation imple-
mentations. We compare ten systems spanning
traditional and LLM-based methods, evaluate
five Agentic Waterfall variants, and complement
these experiments with evaluations on five public
benchmarks.

Conventional sequential recommenders such
as SASRec [5] predict the next item from in-
teraction histories and do not directly accept
free-form requests ct as an input. Responding
to ct requires understanding its meaning in the
context of the user’s history, which motivates
LLM-based approaches.
2.2
Action selection and execution
• Acquire searches a permitted source or
requests details about an item. Returned
content and metadata enter the candidate
pool.
• Recommend orders items from the avail-
able pool and replaces or appends to the
pending feed queue.
• UpdateState writes an evidence-linked
change to the user records, such as marking
a task complete or revising a constraint.
Agentic Waterfall brings user understanding,
memory updates, retrieval, and ranking under a
single language-model controller (Figure 1). The
controller interprets new requests and browsing
behavior in the context of memory mt, which
stores user facts, preferences, and active goals.
Based on this understanding, it decides which
action or combination of actions to take. For ex-
ample, the controller may select UpdateState
to revise memory when new requests or browsing
behavior change its understanding of the user’s
needs.
The results of acquisition in turn inform the
controller’s next decision. The controller checks
how well the returned content supports the cur-
rent goal. It may search further, revise the rec-
ommendations, or combine the two. Once rec-
ommendations are shown, subsequent browsing
and new requests provide fresh evidence about
the user’s needs (see the example below). We
therefore introduce a new protocol in Section 4
to evaluate systems end to end on the Agentic
Waterfall Feed task as user needs evolve across
interactions.
Example.
After buying a camera, a user may
ask for advice on photographing a football match.
The request changes the recommendation target
from choosing equipment to learning how to use
it, even though the browsing history still consists
of camera comparisons.

Datasets
3.1
Public benchmarks
We use five public benchmarks to evaluate ex-
isting recommendation tasks before turning to
the evolving needs studied in Agentic Waterfall
Feed.
• AgentRecBench [7] contains recommenda-
tion tasks from Amazon, Goodreads, and Yelp,
including classical, evolving-interest, and cold-
start settings. We evaluate 300 tasks with 20
candidates each.
• KuaiRand [3] records video viewing behavior,
including randomly exposed videos. We rank
101 fixed candidates in each of 617 tasks, with
one held-out long-view item as the target.
• KuaiRec [2] provides dense user-video inter-
actions. We evaluate 1,129 users on a shared
frozen catalog, requiring systems to find useful
candidates as well as rank them.
• ClawRec-SimBench [10] evaluates next-
step recommendations from cross-platform be-
havior histories against a user’s held-out next
need. We evaluate all 210 events, with systems
retrieving content before ranking it.
• MIND [12] is a news recommendation dataset
with logged candidate impressions and click
histories. We evaluate systems on the MIND-
small development set.
These benchmarks evaluate ranking and next-
step recommendation from observed histories.
Agentic Waterfall Feed also requires tracking how
recommendations respond when similar brows-
ing histories reveal different needs or an explicit
request changes the current goal. This response
is hard to trace in the public benchmarks be-
cause they lack controlled trajectories of such
goal shifts.
We therefore construct a dataset
with these comparisons built into its user jour-
neys.
3.2
Agentic Waterfall Dataset
The Agentic Waterfall Dataset combines real
content metadata with simulated interaction his-
tories. The catalog contains 60,674 distinct cards
from 25 sources across multiple content formats,
including short clips, long-form videos, articles,
and illustrated posts.
To model how people
browse in practice, we generate each trajectory
with a language-model agent guided by a private
user persona and a short-term goal. Across feed
visits, the trajectories record which items users
open, like, or save and how long they spend on
feed cards and linked content. Its 50 trajecto-
ries and 300 evaluation checkpoints cover general
browsing and two targeted subsets, Behavior
Ambiguity and Interactive Revision.
Behavior Ambiguity contains ten pairs of users
with distinct personas. The two users in each
3


pair initially see the same cards and take the
same actions, so their early browsing history fits
either persona. As they pursue different goals on
later visits, their choices of what to open or save
begin to diverge. These users make no explicit re-
quests or comments, so their different needs must
be inferred from browsing behavior. Interactive
Revision contains twenty users who each revise
an initial request, switching tasks or narrowing
or relaxing requirements. We place checkpoints
on either side of each revision, holding browsing
history and the supplied profile fixed across each
pair.
The remaining trajectories record general
browsing without scripted revisions or paired
behavior. Replaying each user’s full trajectory
gives all systems the same interaction history
at each checkpoint and lets us compare their
performance over time. The following protocol
specifies how each system receives this evidence
and how its recommendations are evaluated.
4
Evaluation protocol
We use Hit@K, Precision@K, nDCG@K, AUC,
and MRR to compare rankings with the rele-
vance labels for each public-benchmark task. On
ClawRec-SimBench, a large language model as-
signs these labels by scoring recommendations
without seeing which system submitted them.
We likewise use a language model as a blind
judge in our end-to-end evaluation of Agentic
Waterfall Feed, rating item relevance and com-
paring recommendations at each checkpoint to
measure how well each system’s feed serves the
user’s goals.
4.1
Shared-history replay
Evaluation checkpoints let us compare what dif-
ferent systems would show the same user at the
same moment (Figure 2). At each checkpoint,
we pause replay and collect the top five items
from each system given the same public profile
and interaction history. Replay then continues
with the next recorded interactions, and systems
with memory carry their records forward.
Using this replay protocol, we compare Agen-
tic Waterfall with local adaptations of ClawRec,
RecAgent, and iAgent [7, 10, 13], as well as
BM25+BGE, which combines lexical and dense
scores and reranks with BGE [1, 6]. Because
these methods differ in whether they can ac-
tively search for content, all of them start from a
shared candidate pool, while methods that sup-
port acquisition can search a larger content pool
within our fixed catalog. This setup lets us fairly
compare the end-to-end performance of each im-
plementation without introducing extra modules
that could bias the results. All language-model
methods and the judge use DeepSeek-V4.1-Flash-
1017. To evaluate the returned lists at each check-
point, the judge receives the interaction history
along with the private persona and short-term
goal that guided the simulated user’s browsing.
4.2
Relevance scoring
Based on this context and each card’s metadata,
the judge assigns a topical relevance score from
0 to 3 to each distinct recommended card. We
aggregate the top-five ratings for each system us-
ing discounted cumulative gain with linear gains

4.3
Blind comparison
Relevance scoring evaluates each item separately.
We complement it with rank-by-rank blind com-
parisons that test which system’s recommenda-
tion the user would most want to open given their
current goal and constraints.1 At checkpoints
where all five systems return complete lists, the
judge compares the shuffled cards at each rank.
Each chosen card earns one vote, shared among
the methods that submitted it at that rank. Ties,
responses of neither, and indeterminate answers
receive no vote credit.

5.2
Agentic Waterfall Dataset
Across the public benchmarks, Agentic Water-
fall matches the strongest baselines on fixed-
candidate ranking and achieves clear gains on
tasks that require retrieving new candidates. On
the Agentic Waterfall Dataset (Table 2), Agentic
Waterfall ranks first overall in both evaluations,
reaching 7.86 in topical DCG@5 (+4.4% over
ClawRec and +22.4% over BM25+BGE) and
419.58 blind vote credits (30.9% of the total,
+16.1% over ClawRec’s 361.33).
Behavior Ambiguity.
When users make no
explicit requests and diverge only through brows-
ing actions, Agentic Waterfall achieves the high-
est topical DCG@5 (7.20) and 134.50 blind votes,
ahead of both ClawRec (6.92 DCG@5, 109.08
votes) and iAgent (7.03 DCG@5, 95.83 votes).
Tracking browsing evidence in persistent memory
helps the controller separate users whose trajec-
tories begin similarly but later pursue different
goals.
Interactive Revision.
The gain is especially
clear when users explicitly revise their requests:
Agentic Waterfall reaches 8.40 in DCG@5 and
229.75 blind votes, outperforming ClawRec (8.04
DCG@5, 189.75 votes) by 21.1% in blind votes.

Ablation study
We replayed five Agentic Waterfall variants
across the checkpoints on the Agentic Water-
fall Dataset (Table 3).
Two omit either user
expression or browsing. The others fix action
order, disable content acquisition, or block state
writes. The variants start from the same pub-
lic profile and history prefix, then rebuild state
and candidates with the allowed inputs at each
checkpoint. Full uses the archived lists from the
shared-history replay, which carried state across
checkpoints.
In Table 3, Full scored 7.198 in behavior am-
biguity and the variant without browsing scored
4.414. In interactive revision, Full scored 8.396
and the variant without user expression scored
6.959. The latter variant also scored below Full
in behavior ambiguity (6.259 vs. 7.198), where
users gave no requests or comments. The differ-
ence in state carryover could contribute to these
gaps.
Full had roughly as many wins as the fixed
workflow, no-acquisition, and frozen-state vari-
ants (Figure 3). With content acquisition dis-
abled, the variant won 145 checkpoints and Full
won 137, with 17 ties. Full’s larger winning mar-
gins yielded a positive mean gap of 0.350.

Code and data availability.

Ethics.
The experiments reported in this study
used simulated users, model-generated interac-
tions, and model judgments. Although our demo
system supports user data collection, no collected
user data is included in this study or publicly
released.
