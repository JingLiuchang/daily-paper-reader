## 摘要
近年来，AI智能体的进展使得利用Figma等专业工具进行自主UI设计成为可能，但由于设计任务的开放性与唯一真值的缺失，评估其设计能力仍具挑战。我们提出FigmaEval，一个用于评估AI智能体在专业UI设计任务上表现的基准，包含源自真实Figma设计文件的84个任务和783个界面。FigmaEval采用约束规范、开放解决方案的范式，在标准化任务需求与设计资源的同时，允许智能体自主决定布局、视觉层级、组件构成和视觉呈现。为在参考相似度之外评估设计质量，我们制定了涵盖六个维度的22项基于专家经验的评估细则，并引入人工评估竞技场，由专业设计师通过盲法成对判断比较智能体生成的设计。在统一的Figma智能体设置下评估十一个模型，我们发现基于细则的评估与人类偏好具有高度一致性，同时在设计实践和质量—效率权衡方面存在明显差异。FigmaEval为系统评估专业UI设计能力以及理解当前AI智能体的优势与局限提供了框架。

## Abstract
Recent advances in AI agents have enabled autonomous UI design using professional tools such as Figma, yet evaluating their design capabilities remains challenging due to the open-ended nature of design tasks and the absence of unique ground truths. We introduce FigmaEval, a benchmark for evaluating AI agents on professional UI design tasks, comprising 84 tasks and 783 screens derived from real-world Figma design files. FigmaEval adopts a constrained-specification, open-solution paradigm, standardizing task requirements and design resources while allowing agents to independently determine layouts, visual hierarchies, component composition, and visual presentation. To assess design quality beyond reference similarity, we develop 22 expert-grounded evaluation rubrics across six dimensions and introduce a human evaluation arena where professional designers compare agent-generated designs through blinded pairwise judgments. Evaluating eleven models under a unified Figma agent setup, we find substantial agreement between rubric-based assessments and human preferences, alongside distinct differences in design practices and quality--efficiency trade-offs. FigmaEval provides a framework for systematically assessing professional UI design capabilities and understanding the strengths and limitations of current AI agents.

## 1. 核心问题与研究动机

- **背景**：AI 智能体已可通过 Figma 官方 MCP 服务器直接创建和修改原生设计文件，具备自主完成专业 UI 设计的潜力。
- **核心问题**：如何评估 AI 智能体在 Figma 中自主产出“专业质量、原生可编辑”UI 设计的能力？
- **现有基准的不足**：
  - 代码导向基准（Design2Code、FigmaBench 等）主要评估 HTML/CSS 或设计转代码，而非原生 Figma 设计产物。
  - CANVAS 等工具型基准多采用“复制/修改参考设计”的范式，侧重还原而非从需求出发的原创设计。
  - Design Arena 等偏好评估覆盖网站、应用、演示等，但不专门评估可编辑的 Figma 原生设计文件。
- **评估难点**：
  - 无约束设计简报会导致智能体自由改变方案范围与复杂度，破坏可比性；固定参考设计又限制设计自由。
  - 同一需求存在多种合理设计方案，基于参考相似度的指标不足以衡量专业设计质量。
  - Figma 设计质量不仅包括渲染后的视觉外观，还包括图层结构、组件复用性、可编辑性与交付质量。
- **整体含义**：论文提出 FigmaEval，试图在“设计自由度”与“任务可比性”之间取得平衡，为专业 UI 设计智能体建立可系统比较的评估框架。

## 2. 方法论

### 2.1 核心思想：约束规格、开放方案

- 标准化产品需求、功能、内容与设计资源，但**不提供参考布局**，允许智能体自主决定布局、视觉层级、组件构成与视觉呈现。
- 期望输出是完整、连贯、原生可编辑的 Figma 设计交付物，而非可执行应用。
- 同一任务简报下，不同智能体可产生明显不同的设计方案，但仍可按统一标准比较。

### 2.2 任务构建流程

论文采用四阶段管线：

1. **来源筛选与范围选择**：从 Figma Community  curated 84 个公开设计文件，要求多屏、高保真、有完整功能流程；排除单屏概念、线框图、组件库及不完整设计。
2. **需求抽象与数据归一化**：AI 辅助提取产品上下文、屏幕需求、功能元素、导航关系与界面内容，再由专业设计师审核改写为结构化任务规格；跨屏共享实体（价格、数量、总价等）需保持一致。
3. **设计资源准备**：提供 Foundations（品牌色、字体）与 Components（按钮、输入框等基础组件）页面；排除与原参考设计强绑定的装饰性元素，避免隐式规定原始方案。
4. **质量验证与打包**：专业设计师核对需求完整性、事实正确性与跨屏一致性，并确认存在多种视觉上不同的可行方案。

每个任务打包为只读 Figma Starter File，含四页：

- `00 Start Here`：产品简报、必需屏幕、功能需求、固定内容与数据、导航关系。
- `01 Foundations`：品牌色与字体。
- `02 Components`：基础界面组件。
- `04 Media`：图片、Logo、插画、图标等带稳定标识的资产。

### 2.3 统一智能体设置

- 所有模型运行在同一个 **Claude Code agent harness** 中。
- 仅开放四个 Figma MCP 工具：
  - `whoami`：账户验证；
  - `get_metadata`：结构检查；
  - `get_screenshot`：视觉反馈；
  - `use_figma`：通过 Figma Plugin API 直接创建/修改原生元素。
- 明确排除外部代码执行、HTML/CSS-to-Figma 转换等辅助流程，以隔离“原生 Figma 设计能力”。
- 每个任务-模型对使用独立可写副本，智能体在 `Workspace` 页交付，保留参考页。
- 单次运行时间上限为 5,400 秒；执行后由平台检查屏幕覆盖与空白内容，合格产物才进入评分。

### 2.4 评估框架

#### （1）22 条专家评分细则（Rubric）

覆盖六个维度、共 53 分：

| 维度 | 评估重点 | 条目/满分 |
|---|---|---:|
| 用户体验 | 关键内容与操作可发现性、控件可供性 | 4 / 8 |
| 信息组织 | 分组、阅读层级、语义正确性、操作优先级 | 5 / 15 |
| 布局质量 | 对齐、间距、比例、留白 | 4 / 12 |
| 一致性 | 组件语义与样式统一、跨屏视觉语言一致 | 2 / 4 |
| 视觉呈现 | 字体、色彩角色、状态语义、整体构图 | 5 / 10 |
| 交付质量 | 图层命名与结构层级 | 2 / 4 |

- 评分同时依据**渲染截图**与**Figma 图层结构摘要**；交付质量必须依据图层证据。
- 设置 **G0 门槛**：若设计整体不可用（大面积重叠、空白、核心页面缺失等），总分置零。
- 每条细则要求整数分数与证据性理由，评分按影响而非缺陷计数，避免重复扣分。

#### （2）VLM-as-a-Judge

- 使用三个 VLM 评委：Claude Opus 5.5、GPT-6.1 Sol、DeepSeek V4.1 Flash。
- 每个评委独立评分 3 次，共 9 次判断/产物。
- 产物级总分为 9 次判断的等权平均，再归一化为百分比：
  - 单次判断总分 \(S=\sum_{k=1}^{22}x_k\)，满分 53；
  - 最终分数为 \(100\bar S/53\)；
  - 维度分数按该维度满分归一化，因此总体分数是“按满分加权”的组合，而非六维简单平均。

#### （3）Figma Design Arena 人类偏好评估

- 专业设计师对同一任务的两个产物进行**盲法成对比较**。
- 隐藏模型身份与自动评分，左右位置随机化。
- 评审可查看任务规格、对齐截图与可编辑 Figma 文件。
- 判断依据：需求完整性、信息组织、视觉质量、可用性。
- 采用 Bradley–Terry 模型聚合偏好，转换为 Elo 风格评分；胜率计算中平局计半分。
- 与 rubric 评估的一致性用两个层级衡量：
  - 模型级排序一致性：Kendall’s \(\tau_b\)；
  - 设计对级一致性：rubric 偏好与人类投票一致的比例。

#### （4）基于修复的微调（附加实验）

- 依据 rubric 定义 20 类设计缺陷，向 Figma 页面注入缺陷，构造 1,485 个修复任务。
- 以 Claude Opus 5 为教师模型，通过 Figma MCP 定位并修复缺陷，保留正确区域。
- 得到约 16,000 次编辑调用、5,880 次截图调用的多模态轨迹。
- 对 Qwen3.8-9B 进行全参数监督微调（附录写为 Qwen3.5-9B，文中存在型号不一致），视觉编码器与多模态对齐器冻结。
