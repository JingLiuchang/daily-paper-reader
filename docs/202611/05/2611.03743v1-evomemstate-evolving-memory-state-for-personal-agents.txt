Abstract 

Long-term memory enables large language model (LLM) agents to provide continuous per-sonalized assistance by retaining user informa-tion across interactions. Existing systems sup-port this process through fact extraction, organi-zation, updating, and retrieval, but largely main-tain memories as independent facts. This fact-centric paradigm may overlook how new facts update, constrain, or conflict with earlier ones, while leaving their applicability, role, and prior-ity for the current request implicit. In this paper, we introduce EvoMemState , a state-centric framework that augments persistent facts with two complementary states: Relational States that capture how facts remain valid and relate to one another as memory evolves, and a Reason-ing State that determines how these facts should be applied to the current request. Specifically, EVO MEM STATE consists of three key compo-nents: (i) Ontology-Guided Memory State In-duction extracts Persistent Facts and constructs Relational States that maintain their validity, scope, and evolving relations. (ii) RL-Based State Evolution internalizes memory-use ex-perience into a policy through reinforcement learning to generate a request-specific Reason-ing State. (iii) State-Aware Reasoning then combines the relevant facts with their Rela-tional States and the generated Reasoning State to guide the personal agent. Extensive experi-ments on long-term dialogue and memory-use benchmarks demonstrate consistent improve-ments over existing memory systems in re-trieval completeness and memory-grounded re-sponse accuracy. Our code and implementation details are available at https://github.com/ XMUDeepLIT/EvoMemState.git .

Long-term memory sup-ports this continuity by preserving user preferences, experiences, circumstances, and constraints across sessions (Li et al., 2026; Du et al., 2025; Ning et al., 2026; Yang et al., 2026a). This accumulated con-text provides a foundation for consistent and per-sonalized assistance over time (Wang et al., 2026b; Zhang et al., 2026b). Recent work has explored how to construct and maintain long-term personal memory from interac-tion histories. MemoryBank (Zhong et al., 2024) summarizes user experiences for subsequent re-trieval, while MemGPT (Packer et al., 2023) man-ages memory across storage tiers. LightMem (Fang et al., 2026) improves efficiency through compres-sion and selective retrieval. Other systems em-phasize memory organization and maintenance: Mem0 (Chhikara et al., 2025) extracts and updates atomic facts, A-MEM (Xu et al., 2026) dynami-cally associates related memories, and Supermem-ory (Supermemory AI, 2026) and SimpleMem (Liu et al., 2026) support continual updates and memory lifecycle management. Together, these approaches enable personal agents to retain and access informa-tion across interactions through memory extraction, organization, updating, and retrieval. Despite this progress, existing memory systems largely follow a fact-centric paradigm , focusing on the storage, updating, and retrieval of factual records. However, the validity and scope of a stored fact may change as related memories ac-cumulate, while its appropriate use depends on the current request. Associating records or revising their contents alone may not adequately capture these dependencies. state-centric paradigm that augments stored facts with evolving memory states. A memory state de-scribes the status of stored facts and their roles in an interaction, which cannot be determined from factual content alone and must be considered in relation to other memories and the current request. Such states make the validity, scope, and relations of facts explicit and guide how retrieved memories should be used for the current request. Augmenting personal memory with explicit states presents two challenges: (i) It is challeng-ing to construct and maintain coherent memory states. Personal information accumulates across conversations as scattered and inconsistent observa-tions. Simply collecting these observations leaves their relations implicit, while merging them into a summary may lose historical information and hide conflicts between records. The challenge is to orga-nize related facts and maintain their validity, scope, and relations as new information arrives, while pre-serving the original records. (ii) It is challenging to learn memory-use strategies from experience. 

The same memory can serve different purposes across requests, so its validity and relations alone do not determine how it should affect the agent’s behavior. This requires learning when memories should inform, constrain, or have no bearing on that behavior, using feedback from memory use to refine these judgments. To address these challenges, we introduce EVO MEM STATE , a state-centric framework for maintaining and using long-term personal mem-ory. First, Ontology-Guided Memory State In-duction extracts Persistent Facts from personal in-teractions and incrementally organizes them into a personal memory ontology. It preserves the orig-inal facts while maintaining their validity, scope, and evolving relations as Relational States. Second, 

RL-Based State Evolution internalizes memory-use experience into a policy through reinforcement learning. The learned policy generates a request-specific Reasoning State that specifies the applica-bility, role, and priority of relevant facts. Third, 

State-Aware Reasoning combines the relevant Relational States with the generated Reasoning State to guide the personal agent’s response. To-gether, these components connect fragmented facts through Relational States and combine them with a request-specific Reasoning State, enabling personal agents to interpret and use memory appropriately. Our contributions are summarized as follows: • We identify the limitations of fact-centric per-sonal memory: individually maintained facts may lack the relational context needed for in-terpretation, and complete retrieval does not ensure appropriate memory use. • We introduce E VO MEM STATE , a state-centric long-term memory framework representing personal memory through Persistent Facts, Relational States, and Reasoning State. It realizes this formulation through Ontology-Guided Memory State Induction, RL-Based State Evolution, and State-Aware Reasoning. • We evaluate E VO MEM STATE on long-term di-alogue and memory-use benchmarks, demon-strating consistent improvements over exist-ing memory systems in retrieval completeness and memory-grounded response accuracy.

2.1 Do Fact-Centric Systems Capture Relations among Memories? 

To examine whether fact-centric memory systems capture relations among memories, we evaluate five systems. As shown in Figure 2, MemoryBank, LightMem, and Supermemory do not retrieve all relevant information in 58.9%, 61.8%, and 58.0% of cases, respectively. For four of the five systems, answer accuracy is 5.9–33.3% higher when all re-quired memories are retrieved than when some are missing. These findings motivate explicit modeling of memory relations, so that individual facts can be interpreted alongside the information affecting their validity and scope.

3.2 Ontology-Guided State Induction 

Persistent Facts alone are insufficient to construct a memory state because their current meaning de-pends on their validity, scope, and relations to other facts. Therefore, we construct a personal mem-ory ontology incrementally and induce Relational States from its evolving structure. Persistent Facts retain the original information, while their Rela-tional States are updated as new facts are added. The resulting ontology and Relational States form the persistent personal memory.

3.3 RL-Based State Evolution

We there-fore treat state evolution as the internalization of reusable memory-use experience and instantiate the state inference function Ψ with a Memory State Evolution Policy πθ. > Zq∼πθ(· | q, Fq,Rq).(8)

We compare EvoMemState with memory systems using Qwen3-8B and GPT-4o-mini. Table 1 reports results on MemSyco-Bench and MemTrapBench for memory use, and on LoCoMo and LoCoMo-Refined for long-term memory reasoning.

It also achieves the best Safety and Task Boundary scores on MemTrapBench, showing that factual records support recall while reasoning states prevent irrelevant history and prior task rules from overriding the current request.

Guided by the personal memory ontology, its Relational State preserves each fact’s current attributes together with related updates, conflicts, and constraints. This organiza-tion allows related memories to provide complete evidence rather than remain independent records.

6 Conclusion 

In this paper, we presented EvoMemState, a state-centric long-term memory framework for personal agents that constructs coherent Relation States from multi-source memories and learns from con-8tinual memory use to generate Reasoning States. Experiments across memory-use and dialogue-recall benchmarks show consistent improvements, particularly under preference updates and conflict-ing evidence, demonstrating that reliable personal memory requires both coherent state construction and use-driven state evolution. 

Limitation 

Our study focuses on text-based interaction histo-ries. Real-world personal memory systems must also handle multimodal information, including doc-uments, images, and other user artifacts. Extending our memory structure to represent, connect, and apply information across modalities remains an important direction for future work.

A Frequently Asked Questions (FAQs) 

A.1 What are the main advantages of EvoMemState? 

EvoMemState differs from conventional memory systems in how it maintains and uses personal in-formation. Rather than storing facts independently, it organizes them within an ontology that tracks changes in validity, scope, and relations. This al-lows earlier records to remain accessible even when newer information supersedes or contradicts them. The framework also separates memory storage from memory use. A learned policy generates a Reasoning State for each request, indicating which memories are relevant and how they should influ-ence the response. The policy is trained using feed-back from downstream answers, rather than relying on predefined rules or repeated self-reflection. The Reasoning State is provided as natural-language guidance and can be used with different response models without modifying their parameters. 

A coherent and evolving memory state. The personal memory ontology organizes Persistent Facts and maintains their validity, scope, and re-lations as new interactions arrive. Original facts remain traceable, while relation-aware retrieval re-covers the connected information needed for their interpretation. 

Use-driven state evolution. For each request, a Reasoning State specifies the applicability, role, and priority of memory evidence. The Memory State Evolution Policy learns from whether candi-date states improve the personal agent’s answers, al-lowing experience from prior memory use to guide future requests. 

Compatibility with different personal agents. 

Reasoning States are expressed in natural language and provided alongside the relevant facts and rela-tions. They can therefore guide different personal-agent backbones without modifying their parame-ters. 

A.2 Why use a personal memory ontology instead of independent records? 

Independent memory records can preserve individ-ual observations, but they provide limited informa-tion about how those observations relate over time. For example, a newly stated preference may replace an earlier one, while two conflicting records may need to remain unresolved until further evidence becomes available. EvoMemState uses an ontology to represent these relationships explicitly. Facts are grouped under concepts and linked through typed relations, allowing retrieval to include not only a relevant record but also the information needed to interpret it. The original records are retained, so historical questions can still be answered after a preference or circumstance changes. 

Connecting facts across interactions. The con-cept hierarchy organizes facts by topic, while their attributes and relations record changes in valid-ity and scope. Earlier facts remain traceable even when they are superseded or conflict with later in-formation. 

Recovering complete evidence. Semantic re-trieval may identify an individually relevant fact while omitting the related facts needed to interpret it. Starting from retrieved facts, EvoMemState tra-verses their stored relations to recover connected updates, conflicts, and constraints, providing the complete context required by the current request. 

A.3 Why are Reasoning States needed, and how do they differ from summaries? 

Relation States describe whether facts remain valid and how they are related, but do not determine how they should affect a particular request. A Reason-ing State makes the applicability, role, and priority of memory evidence explicit for the current inter-action. 12 Using the same fact in different contexts. Aknee injury may answer a factual question, con-strain an activity recommendation, or be irrelevant to another request. Similarly, a superseded pref-erence may be irrelevant to a current decision but necessary for answering a historical question. The Reasoning State distinguishes these uses according to the request. 

From memory content to response guidance. AReasoning State is intended to guide the use of retrieved memories, rather than summarize their content. The distinction matters because the same fact can serve different purposes depending on the request. Consider a user who previously mentioned a knee injury. The information is relevant when the user asks for exercise recommendations, but it may have no bearing on a question about travel expenses. Similarly, an outdated preference should not determine a current recommendation, although it remains useful when answering questions about the user’s past interests. The Reasoning State captures these request-dependent distinctions. It is generated from the retrieved facts and their relations, while the original evidence remains available to the response model. 

A.4 Why use a separate policy model instead of agent self-reflection to generate Reasoning States? 

Self-reflection requires the personal agent to deter-mine how memory should be used anew for each re-quest, without retaining successful decisions from previous uses. In contrast, the Memory State Evo-lution Policy is trained offline by repeatedly gen-erating and evaluating candidate Reasoning States, thereby internalizing memory-use patterns that im-prove downstream responses. At inference, it di-rectly provides the personal agent with a ready-to-use Reasoning State, avoiding repeated execution or iterative reflection for each request. This sepa-rates the accumulation of memory-use experience from response generation and makes that experi-ence reusable across requests and personal agents. 

A.5 How is the Memory State Evolution Policy trained and evaluated? 

The policy is trained according to how much its Reasoning States improve the personal agent’s an-swers. Evaluation separately measures whether the system retrieves complete evidence and whether the personal agent uses that evidence correctly. 

Learning from memory-use experience. Given a request, relevant Persistent Facts, and their Rela-tion States, the policy samples a group of candidate Reasoning States. Each candidate is applied by a frozen personal agent under the same request and memory evidence, together with a baseline that uses the evidence directly. The resulting perfor-mance difference serves as feedback on the can-didate’s memory-use decisions and defines the re-ward in Equation 10. GRPO optimizes the policy using relative feedback within each group. Across repeated memory-use episodes, the policy internal-izes reusable patterns for determining the applica-bility, role, and priority of memory evidence. Only the policy is updated, allowing this experience to guide the personal agent without modifying its pa-rameters. 

Separating evidence retrieval from evidence use. 

Complete Retrieval Rate measures how often the retrieved context contains all required evidence, while Acc@Complete measures answer accuracy on those cases. Figure 5 reports both metrics on LoCoMo-Refined and MemSyco-Bench, distin-guishing errors caused by missing evidence from those caused by incorrect evidence use. Table 2 further compares variants without Reasoning States or RL-based policy training. Together, these eval-uations assess both the complete system and the contribution of learned state evolution.

The memory construction pipeline, re-trieval procedure, and response model remain fixed throughout training. The resulting policy is used to generate Reason-ing States at inference time.

C.2 Guidance from the Answer Model 

To compare learned memory-use guidance with guidance generated by the response model, we eval-uate Self-Guide and Dynamic Rules under Qwen3-8B and GPT-4o-mini (Figure 9). Self-Guide uses the response model to generate guidance, whereas Dynamic Rules uses the trained Memory State Evo-lution Policy to generate a Reasoning State. Dynamic Rules yields larger gains on memory-use benchmarks than on conversational recall. Rel-ative to Self-Guide, it improves MemSyco-Bench accuracy by 8.2 percentage points with Qwen3-8B and 6.1 percentage points with GPT-4o-mini, with corresponding MemTrapBench score gains of 16.8 and 11.0 points. Improvements on LoCoMo are smaller, at 0.9 and 1.0 points, respectively. On LoCoMo-Refined, Dynamic Rules improves the Qwen3-8B score by 1.1 points but reduces the GPT-4o-mini score by 1.4 points. These results suggest that learned guidance is particularly useful for determining the applicability and priority of memories, while offering less consistent benefits for conversational recall. Conversational recall primarily requires recover-ing and combining stored information. MemSyco-Bench and MemTrapBench also test whether his-torical information should influence the current response, particularly when preferences change or prior interactions introduce misleading assump-tions. Unlike Self-Guide, the Memory State Evolu-tion Policy is trained using feedback on the answers produced with its guidance. Candidate rules are evaluated against a baseline answer generated from the same records without rules, assessing whether applying, restricting, or prioritizing memories im-proves correctness. The larger gains on memory-use benchmarks support learning from memory-use 18 experience to determine the applicability, role, and priority of evidence.

C.7 Memory Application with Complete Evidence 

To assess how Reasoning States support memory application when retrieval supplies all required ev-idence, we evaluate the Valid Memory Selection tasks of MemSyco-Bench. Figure 13 reports com-plete retrieval rate and compares Acc@complete under two conditions: w/ self-reflection , where the personal agent reflects on how to use the retrieved memories, and w/ reasoning state , where it uses an explicit Reasoning State to guide memory applica-tion. Complete retrieval rate gives the proportion of questions with all gold evidence retrieved, while Acc@complete measures answer accuracy on this subset for each system. EvoMemState achieves a complete retrieval rate of 93.7%. Its Acc@complete increases from 75.4% with self-reflection to 86.7% with a Reasoning State, a gain of 11.3 percentage points. This im-provement on questions with complete evidence suggests that retrieving the required records does not by itself ensure correct memory use. The agent must still resolve differences in temporal validity, scope, and evidence roles. The Reasoning State makes these application decisions explicit through dynamic rules, specifying how updates, constraints, and competing information affect the current re-quest. For the baselines, replacing self-reflection with a Reasoning State yields only small gains or de-creases: +0.4 percentage points for LightMem, +0.1 for MemoryBank, -0.8 for A-MEM, -1.6 for Mem0, -0.1 for MemGPT, and -0.4 for Supermem-ory. Thus, an explicit Reasoning State alone does not consistently improve memory application. The larger gain for EvoMemState is consistent with the benefit of its Memory State Evolution Policy, which learns application decisions through downstream answer-quality feedback. These results suggest that effective memory use depends on the quality of the decisions encoded in the state, rather than merely adding an intermediate reflection or instruc-tion step.

D.1 Training Data Construction 

To train the Memory State Evolution Policy to generate a Reasoning State from a request and its relevant Relational State, we construct approx-imately 60K question–memory training instances from FEVER (Thorne et al., 2018), SciFact (Wad-den et al., 2020), and PersonaMem (Jiang et al., 2025). For objective questions, we convert the fact-verification tasks in FEVER and SciFact into question-answering instances with supporting ev-idence and reference answers. We then construct user memories that conflict with the objective ev-idence from the perspectives of personal belief, identity, and perceived expertise. For preference questions, we use the preference annotations in Per-sonaMem to construct scenarios involving current preferences, historical preferences, and preference updates, enabling the model to learn how different memories should influence a response. To improve the difficulty and diversity of the training data, we further introduce distractor mem-ories. For objective questions, bias-related memo-ries are mixed with irrelevant everyday information. For preference questions, we add one or two gen-uine preferences from unrelated topics associated with the same user, including more challenging dis-tractors drawn from the same conversational sce-nario but concerning a different topic. This design requires the model to identify relevant information based on memory content and applicability, rather than relying on superficial cues such as memory count, position, or fixed rule templates.

F Related Work 

F.1 Personal Agents and User Modeling 

Personal agents use persistent user information to adapt their responses across interactions (Li et al., 2026). LaMP retrieves relevant profile items to sup-port personalized generation (Salemi et al., 2024). HELLO, Reflective Memory Management, and re-lated methods maintain and update user representa-tions as new interactions arrive, allowing the agent to track changes in user preferences and experi-ences (Li et al., 2025; Tan et al., 2025b; Kang et al., 2025). PGMem further links persona information to events that support or revise it, connecting the user representation with evidence from interaction history (Choi et al., 2026). Recent studies evaluate memory-based person-alization over long user-agent interactions, with attention to changing user information and contin-ued memory use (Zhang et al., 2026b; Huang et al., 2026). Other work extends personalization beyond dialogue to Web actions and agent training (Cai et al., 2025; Sun et al., 2025). Research has also examined security risks introduced by persistent memory and tool use in personal agents (Wang 29 et al., 2026b). Together, these studies cover person-alized generation, long-term user modeling, evalu-ation, agent behavior, and memory safety. 

F.2 Long-Term Memory Systems for LLM Agents 

MemGPT manages hierarchical storage (Packer et al., 2023), LightMem uses staged compression and consolidation (Fang et al., 2026), and Mem0 incrementally extracts and updates facts (Chhikara et al., 2025). A-MEM organizes interconnected notes (Xu et al., 2026), while PGMem links per-sona signals to supporting or revising events (Choi et al., 2026). Temporal consistency and the avail-ability of related evidence are also important con-cerns in long-term memory (Rasmussen et al., 2025; Gutiérrez et al., 2024; Xiang et al., 2026b). EvoMemState preserves explicit supersession and unresolved-conflict relations when assembling re-trieved records, retaining the evidence needed to interpret evolving personal information. Prior research also examines the contribution of memory to downstream task performance (Wang et al., 2025; Cai et al., 2026; Yan et al., 2026; Zhou et al., 2026). Other studies consider how external information affects response quality (Li et al.; Ye et al., 2024). EvoMemState learns a separate pol-icy that generates request-specific usage guidance alongside assembled evidence for a frozen response model. 

F.3 Reliability of Memory-Augmented Agents 

Reliability requires faithful memory maintenance (Yang et al., 2026b; Zhang et al., 2025a) and context-appropriate memory use. Existing evalua-tions examine hallucinations during memory pro-cessing (Chen et al., 2025), knowledge updates, temporal reasoning, and abstention (Wu et al., 2024), and reliance on obsolete or invalidated infor-mation (Uddin et al., 2026). Other studies iden-tify over-personalization, cross-domain leakage, and memory-induced sycophancy (Hu et al., 2026; Pulipaka et al., 2026), as well as safety risks aris-ing from evolving user contexts (An et al., 2026). MemSyco-Bench tests scope, updates, and con-flicts with objective evidence (Xiang et al., 2026a), while MemTrapBench examines reasoning fixation and belief distortion (Wang et al., 2026a). At inference time, Self-Recheck filters retrieved memories to reduce inappropriate personaliza-tion (Hu et al., 2026); MemGate controls query-conditioned memory admission (Zhang et al., 2026a); and Dynamic Partition organizes memory presentation by domain (Hannoon et al., 2026). EvoMemState learns request-specific guidance about the applicability, role, and priority of assem-bled evidence. Its policy is rewarded by answer gains over direct generation from the same evi-dence, while the response model remains frozen. 30
