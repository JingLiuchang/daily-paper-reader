# Scalaris: A Scalable Enterprise Memory Architecture for Conversational AI Assistants

Abstract 

Enterprise conversational systems require mem-ory to personalize interactions, retain informa-tion across sessions, and maintain conversa-tional coherence. At enterprise scale, how-ever, memory must not only retrieve relevant information accurately but also provide it effi-ciently to the answer-generation model. Exist-ing memory systems face a trade-off between retrieval accuracy and context efficiency. Re-trieving more context can improve recall but in-creases inference cost and latency. We present Scalaris, a scalable enterprise memory architec-ture that addresses this trade-off through a uni-fied long-term and short-term memory design. We propose that user interactions and assistant responses possess distinct characteristics and roles in a conversation: user interactions cap-ture evolving knowledge about the user and provide value across sessions, whereas assis-tant responses must be stored efficiently so that only information relevant to the current query is retrieved. We therefore treat them separately and support each with specialized representa-tions and ingestion/retrieval pipelines. Scalaris reaches 92.2% accuracy on LongMemEval-S and 90.77% on LoCoMo using Qwen3-32B, state-of-the-art results on both benchmarks, while supplying the answer-generation model with approximately 10 × fewer retrieved con-text tokens than Hindsight, a leading memory system for conversational AI. When integrated with our proprietary closed-source AI assis-tants, Scalaris improved overall response qual-ity by 36%. Together, these results establish Scalaris as a cost-effective framework for build-ing scalable, personalized conversational AI systems. 

1 Introduction 

The emergence of large language models has en-abled organizations to deploy conversational AI systems across user-facing applications such as cus-tomer support and sales assistance (Yi et al., 2026). Memory is essential to these systems for maintain-ing continuity across conversations and personal-izing interactions (Wu et al., 2025b). However, simply providing an assistant with prior message history becomes limiting as conversations grow longer and span multiple sessions, since model per-formance degrades over long contexts (Liu et al., 2024). Existing memory frameworks have there-fore explored mechanisms for selectively storing and retrieving information from past conversa-tions (Zhang et al., 2025a), but they often face a trade-off between retrieval accuracy and context efficiency. Zep (Rasmussen et al., 2025), for exam-ple, retrieves relatively little context but achieves lower accuracy on long-term memory benchmarks, whereas Hindsight (Latimer et al., 2026) achieves substantially higher accuracy while retrieving con-siderably more. An effective enterprise memory system must therefore retrieve the information re-quired to answer a query accurately without un-necessarily increasing the context supplied to the answer-generation model (Lewis et al., 2020; Shi et al., 2023; Chhikara et al., 2025). Conversational memory must also operate across two different timescales. Information such as user preferences, interests, and circumstances may re-main useful across sessions and must evolve as new interactions occur (Xu et al., 2025; Zhang et al., 2025b), creating the need for long-term memory. At the same time, an assistant must retain the im-mediate conversational state required to interpret follow-up questions, resolve references, and main-tain coherence within an ongoing session (Packer et al., 2024; Yu et al., 2026), motivating short-term memory. A scalable conversational memory archi-tecture must therefore support both persistent cross-session knowledge and immediate within-session context. Our Proposal: We present Scalaris, a unified long-term and short-term memory architecture de-signed around this distinction. As illustrated in Figure 1, Scalaris maintains separate memory rep-resentations for user interactions and assistant re-sponses. User interactions are organized in a tempo-ral knowledge graph that maintains relevant facts, entities, and evolving user information, together with user and session summaries. Assistant re-sponses are decomposed into independently retriev-able atomic units and stored in a vector database, allowing only information relevant to the current query to be retrieved. In parallel, user interac-tions and assistant responses are preserved verba-tim in a shared history store for recent conversa-tional context. By providing specialized ingestion and retrieval pipelines for these different forms of memory, Scalaris aims to preserve the information needed for accurate recall while limiting unneces-sary retrieved context. Our main contributions are as follows: (1) We present Scalaris, a unified long-term and short-term memory framework for building scal-able, enterprise-ready conversational AI assistants. (2) We propose that user interactions and assis-tant responses exhibit distinct characteristics that call for different memory representations, and we support each with a specialized ingestion and re-trieval pipeline. (3) We achieve state-of-the-art performance on both LongMemEval-S (92.2%) and LoCoMo (90.77%) using the relatively small Qwen3-32B model, while requiring approximately 10 × fewer retrieved context tokens than Hindsight. 

2 Related Work 

Long-Term and Knowledge-Graph Memory Representations. Long-term memory frame-works let conversational agents retain informa-tion across sessions through varied representations. Knowledge-graph approaches such as Zep (Ras-mussen et al., 2025) and Supermemory (Superme-mory, 2025) capture entities and their evolving re-lationships over time, while Mem0 (Chhikara et al., 2025) combines graph components with selective consolidation. LangMem (LangChain, 2025) pro-vides a general-purpose toolkit for extracting and consolidating memories. Unit-based and reflec-tive models such as A-Mem (Xu et al., 2025) treat memory as interconnected units that update as new interactions occur; RGMem (Tian et al., 2026) de-rives higher-level user profiles from episodic logs, and RMM (Tan et al., 2025) applies reflective man-agement to long-term dialogue. Others target ef-ficiency through different mechanisms: Simple-Mem (Liu et al., 2026) compresses conversations into compact semantic units, FraCom (Ke et al., 2025) composes fine-grained fragments at retrieval time, RecMem (Dai et al., 2026) optimizes mem-ory construction cost, and Zero-Mem (Xiao et al., 2026) eliminates LLM calls during memory opera-tions through deterministic memory management. 

Temporal Organization and Hierarchical Archi-tectures. Operating across immediate and multi-session contexts requires tracking temporal evolu-tion and balancing short- against long-term stores. MemGPT (Packer et al., 2024) introduced hierar-chical, OS-like memory management, while Age-Mem (Yu et al., 2026) learns actions across long-and short-term tiers. To handle temporal shifts over long interaction spans, TiMem (Li et al., 2026), APEX-MEM (Banerjee et al., 2026), and THEA-NINE (Ong et al., 2025) structure information around timelines and state updates. Complemen-tary work explores content-based categorization: Hindsight (Latimer et al., 2026) organizes memory into world knowledge, agent experience, entity ob-servations, and beliefs. This implicitly separates assistant-originated opinions from user observa-tions, but the division follows from epistemic role rather than a deliberate partition by the origin of the information. 

Partitioning User Interactions and Assistant Re-sponses. Despite these developments, no exist-ing system uses the functional distinction between user interactions and assistant responses as an ex-plicit organizing principle. User inputs call for relational, graph-based representations that track changing preferences, facts, and context across ses-sions, whereas assistant responses are better de-composed into independently retrievable atomic units so that downstream models receive only the relevant excerpts. Scalaris closes this gap, unify-ing short- and long-term stores while applying a representation tailored to each source. 

3 Methodology 

3.1 System Architecture 

Scalaris is a unified long-term and short-term mem-ory architecture designed for conversational AI as-sistants. As illustrated in Figure 2, the architecture is partitioned into a long-term component tailored for cross-session recall and a short-term component dedicated to intra-session continuity. The long-term component is built on Graphiti (Rasmussen et al., 2025; Zep AI, 2024), an open-source temporal knowledge graph framework, which we substantially modify for use as a memory layer. It consists of a user summary and Relevant user interactions. The user summary maintains an evolving, holistic profile of the user’s attributes, behavioral patterns, and focus areas. It is updated incrementally after each interaction and periodically rebuilt from historical logs to prevent semantic drift. Relevant user interactions extract three elements from user messages: Relevant Facts ,which capture temporal semantic data; Relevant Entities , which represent previously discussed people, organizations, or concepts alongside their context; and Relevant Past Messages , which preserve the verbatim user interactions. The short-term component consists of a ses-sion summary, the Last-N Exchanges, and Rele-vant Assistant Messages. The session summary compactly tracks the ongoing dialogue state, while the Last-N Exchanges provide the verbatim re-cent context required for immediate coreference resolution and intent tracking. For Relevant As-sistant Messages, we leverage a vector database to store assistant responses as independently re-trievable atomic units. The assistant’s outputs are fragmented into self-contained units, ensuring only informative segments are retrieved rather than full, verbose responses. We intentionally keep Relevant Assistant Messages in short-term memory for two reasons. First, assistant responses are often not useful across sessions, and enabling cross-session retrieval increases retrieved context with limited benefit. Second, in domains with rapidly changing information like finance, retrieving stale assistant responses increases the likelihood of hallucinations. This behavior is nonetheless configurable for appli-cations that require assistant responses to persist across sessions. Figure 3 details the complete in-gestion and retrieval pipeline. 

3.2 Ingestion Relevant user interactions. Each incoming user message is ingested as an episode from which enti-ties, facts, and temporal information are extracted and linked to the memory graph. The memory uses a bi-temporal model that tracks both a fact’s valid-ity interval and when it was learned or recorded, preserving historical changes. Each episode is pro-cessed as follows: (a) Entity Extraction. Entities are extracted from each episode, and a concise summary of up to 250 characters is maintained for each entity to capture its conversational context. (b) Entity Resolution. Extracted entities are matched against existing entities using a reso-lution pipeline that combines exact matching, lexical similarity, and embedding-based sim-ilarity. If a match is identified, the entity is linked to its existing graph representation; oth-erwise, a new representation is created. (c) Fact Extraction. Atomic facts are extracted from the episode and represented as relation-ships between resolved entities, capturing the specific information conveyed by the user and its associated temporal context. Relevant user interactions. Relevant user inter-actions are retrieved through a three-stage search, reranking, and context-construction pipeline. (a) Search. The reformulated query is used to retrieve candidate facts and entities through semantic, lexical, and graph-traversal search. Semantic search uses dense em-bedding similarity, computed with Cohere’s 

embed-english-v3.0 model (Cohere, 2023) to identify facts and entities that are seman-tically related to the query. Lexical search uses BM25 (Robertson and Zaragoza, 2009) over fact text and entity names to recover exact terms, names, and rare expressions. Graph traversal complements these searches by starting from seed entities and exploring a bounded number of graph hops, retrieving related facts that may not be lexically or se-mantically similar to the query. (b) Reranking. Candidate results are reranked us-ing Reciprocal Rank Fusion (RRF) (Cormack et al., 2009), which combines independently ranked lists without requiring their scores to be directly comparable. 4 Experiments and Results 

4.1 Experimental Setup 4.1.1 Datasets 

We evaluate Scalaris on two long-term conver-sational memory benchmarks: LongMemEval-S (Wu et al., 2025a), comprising 500 questions across six evaluation categories with approximately 115K input tokens per question, and LoCoMo (Ma-harana et al., 2024), comprising 1,986 questions across 10 multi-session conversations and five cat-egories, with approximately 9K tokens per conver-sation. For LoCoMo, we follow the category labels and question distribution provided by the Hugging Face version of the dataset. 

4.1.2 Evaluation Metrics 

To assess both the effectiveness and practical viabil-ity of the memory systems, we measure accuracy 

(%), the primary metric for retrieval and reasoning success across all benchmark categories; retrieval efficiency , the average number of context tokens re-trieved per query; and latency , the average retrieval time per query in seconds. 

4.1.3 Implementation Details 

For the end-to-end memory system, we con-sider Qwen3-32B (Qwen Team, 2025) and OSS-120B (OpenAI, 2025) as the underlying models. Following benchmark protocols, GPT-4o (OpenAI, 2024) is used as the answer generator and evaluator. Because these benchmarks primarily evaluate long-term memory recall and reasoning rather than conversational continuity, we exclude the session summary and Last-N Exchanges during evalua-tion. We configure Relevant Assistant Messages for cross-session retrieval to align with the bench-marks’ requirements. All other components, includ-ing the proposed ingestion and retrieval pipelines, remain unchanged from the core architecture. The recommended hyperparameter ranges and sensitiv-ity analysis are presented in the extended analysis in Appendix A.2. Baseline results in Tables 1 and 2 are taken from Latimer et al. (2025).

Nei-ther baseline distinguishes user interactions from assistant responses, and each sits at one end of the trade-off: Zep organizes all conversational content in a single knowledge graph, retrieving exception-ally lightweight contexts (averaging 1.6K tokens) at the cost of severe accuracy degradation (71.2% on LongMemEval) (Rasmussen et al., 2025), whereas Hindsight stores all content in a single PostgreSQL-backed memory bank (Latimer et al., 2025), secur-ing high accuracy but demanding massive context windows. By representing each source according to its role, Scalaris attains comparable accuracy at a fraction of the context, validating our design choice to structurally differentiate user interactions from assistant responses.

The results demonstrate that memory organiza-tion plays a critical role in retrieval effectiveness and efficiency. Utilizing a graph-based structure for assistant responses yields poor accuracy despite retrieving more context, suggesting that relational graphs are not well suited for assistant responses. 4.4 Internal Evaluation 

To validate Scalaris in a live production environ-ment, we integrated the architecture into our pro-prietary, closed-source conversational AI assistants and evaluated its performance on a sample of 1,200 real user interactions. For each query, we generated two responses: one with memory (WM) utilizing all Scalaris components, and one without memory (WOM) relying solely on the Last-N Exchanges. Using a blind evaluation protocol, GPT-4o scored each response on a 0–5 scale consider-ing five dimensions: answer quality, personal-ization, clarity, actionability, and context consis-tency. Memory-enabled responses were preferred in 91.9% of cases, achieving a mean score of 4.33 compared to 3.18 for the WOM baseline (+36.2%). For the evaluation prompt and extended analysis, refer to the Appendices A.4 and A.5. Notably, the performance gap widened signifi-cantly as dialogue length increased. For queries in the latter half of extended sessions (defined as ses-sions exceeding 20 turns, representing 433 queries in our dataset), WM responses averaged 4.62, while WOM responses dropped sharply to 2.40. This con-firms Scalaris’s ability to maintain conversational coherence in long-horizon interactions. 

5 Conclusion 

We present Scalaris, a unified long-term and short-term memory architecture designed to address the diverse memory requirements of conversational AI systems. Scalaris enables agents to personalize re-sponses based on users’ preferences and interests, recall relevant information with temporal aware-ness, and maintain coherence across long and com-plex conversations. By appropriately organizing user interactions and assistant responses accord-ing to their characteristics, Scalaris achieves state-of-the-art performance on both LongMemEval-S and LoCoMo. Notably, these results are achieved with a relatively small Qwen3-32B model while re-quiring approximately 10 × fewer retrieved context tokens than Hindsight with comparable accuracy. Internal evaluation further demonstrates significant improvements in response quality when Scalaris is integrated with conversational AI assistants, high-lighting its potential as a practical and scalable framework for enterprise conversational AI sys-tems. 6 Limitations 

The current Scalaris architecture is restricted to declarative and episodic memory—such as user preferences, explicit facts, entities, and past interac-tions—and lacks dedicated mechanisms for model-ing procedural knowledge like learned skills, work-flows, or reusable action sequences. Furthermore, Scalaris is designed exclusively for text-based inter-faces and has not been evaluated in voice-driven en-vironments, which require strict real-time latency, continuous streaming, and low-overhead retrieval. 

Future Work: To address these constraints, future research will extend the framework to incorporate procedural memory capabilities while optimizing retrieval pipelines and streaming efficiency to sup-port ultra-low-latency voice interactions. 

7 Ethical Considerations 

While Scalaris enhances personalization and conti-nuity in conversational AI, persistent memory ar-chitectures introduce potential privacy and security risks. Long-term memory stores sensitive user in-formation across sessions, making data protection critical. To mitigate these risks, production de-ployments must incorporate robust access controls, data anonymization, and user-driven mechanisms for inspecting, editing, or deleting stored memory entries (aligning with right-to-be-forgotten regula-tions). Furthermore, because long-term memory retains user preferences and traits, systems must safeguard against amplifying user biases or uninten-tionally storing personally identifiable information (PII).

A.1 Retrieval Component Analysis 

To better understand the contribution of individ-ual retrieval mechanisms, we evaluate the retrieval pipelines of Relevant Assistant Messages and Rele-vant User Interactions independently on the corre-sponding LongMemEval categories. Specifically, the assistant-response retrieval pipeline is evaluated only on the single-session-assistant category, while the user-interaction retrieval pipeline is evaluated only on the single-session-user category. These subsets isolate questions whose answers primarily depend on assistant responses or user interactions, respectively, allowing each retrieval component to be analyzed without interference from the other memory stream. Also, these questions require in-formation distributed across multiple human-AI exchanges within one session, where omitting even a single relevant memory unit can lead to an in-complete or incorrect response. During each exper-iment, only the retrieval mechanism under evalua-tion is enabled while all other retrieval components within the same pipeline are disabled. Since graph traversal (BFS) requires an initial set of retrieved entities, it is evaluated only in combination with semantic retrieval or BM25 rather than as an inde-pendent retrieval mechanism. For reference, the complete retrieval pipeline achieves 83.93% ac-curacy on single-session-assistant and 97.14% on single-session-user. The single-session-assistant (SSA) gap relative to some baselines in Table 1 reflects a deliber-ate design trade-off. The SSA subset contains 56 questions, of which Scalaris answers 47 correctly (83.93%). As noted above, these questions require combining details from several assistant responses within a session, so an answer is correct only if every relevant response is retrieved; missing even one yields an incomplete answer. This setting natu-rally favors systems that retrieve large portions of the conversation: Hindsight, for instance, retrieves roughly 10 × more context than Scalaris (Table 3). Scalaris instead retrieves compact atomic units un-der a fixed retrieval budget, and among low-context systems it remains stronger than Zep (83.93% vs. 80.4%).

A.3 Qualitative Error Analysis 

To understand the limitations of Scalaris, we con-ducted a qualitative analysis of the remaining ∼8% of failure cases in LongMemEval. The majority of errors stem from three distinct patterns. First, 

ambiguous temporal expressions (e.g., “a couple of quarters ago”) occasionally fail to resolve ac-curately when the surrounding context lacks ex-plicit anchor dates. Second, distributed evidence retrieval remains challenging when the information required to answer a query is scattered across multi-ple distant interactions, but the initial retrieval stage fails to surface all relevant memory units needed for complete reasoning. Finally, implicit fact negation 

poses a challenge; when a user implicitly changes a previously stated preference without directly con-tradicting it, the temporal edge invalidation fails to trigger, causing the system to retrieve outdated context. Addressing these implicit reasoning bot-tlenecks remains a critical area for future work. 

A.4 Internal Evaluation: Detailed Analysis 

To complement the quantitative results presented in Section 4.4, we performed a qualitative analy-sis of 1,200 real user queries collected from our proprietary production finance assistants. Unlike benchmark datasets, these conversations represent genuine user interactions and therefore naturally contain incomplete follow-up questions, pronouns, ellipsis, and implicit references. Rather than re-stating the complete context in every turn, users progressively rely on the assistant’s conversational memory, making later queries increasingly ambigu-ous when viewed independently. A representative conversation from our evaluation is shown below: 1. Compare Tata Steel and Hindalco. 2. Which one looks better for long-term invest-ment? 3. Compare it with Larsen & Toubro. 4. Which one is the weakest stock now? 5. Replace the weakest stock. 6. Which one looks safer? 7. What are the downside risks? 8. What are the upside drivers? 9. What is the expected timeline? 10. Summarize the key insights. Although the first few questions explicitly iden-tify the companies under discussion, the subse-quent queries depend almost entirely on the pre-ceding conversation. References such as “it”, “the weakest stock”, “the downside risks”, “the upside drivers”, and “the expected timeline” cannot be interpreted correctly without resolving the conver-sational context established in earlier turns. Simi-lar interaction patterns were consistently observed throughout the internal evaluation, reflecting how users naturally communicate with conversational assistants rather than how benchmark datasets are typically constructed. To understand how existing memory frameworks handle such conversations, we additionally evalu-ated the same production queries using Zep and Hindsight. A common limitation observed across both systems was their inability to consistently resolve conversational coreferences and implicit follow-up queries before retrieval. Retrieval was frequently performed using the surface form of the latest user query, causing relevant memories associ-ated with previously discussed entities to be missed. In contrast, Scalaris first reformulates each conver-sationally dependent query into a self-contained retrieval query by resolving pronouns, omitted en-tities, and implicit continuations before initiating memory retrieval. Despite this shared limitation, the two frame-works exhibited different behaviors. Zep was able to provide limited personalization through its main-tained user summary, but often failed to recall previously generated assistant responses. Conse-quently, the downstream assistant repeatedly in-voked external tools to retrieve information that had already been fetched earlier in the conversation, increasing unnecessary computation and response latency. Hindsight recalled prior assistant infor-mation more reliably by retrieving substantially larger portions of the conversation, thereby reduc-ing repeated tool invocations. However, this came at the cost of retrieving significantly more context tokens, frequently overwhelming the answering model with redundant information. Furthermore, because Hindsight does not explicitly maintain an evolving user profile, it was generally less effective at personalizing responses according to long-term user preferences. These observations suggest that an effective con-versational memory system must adapt to the way users naturally communicate, rather than expecting them to formulate fully self-contained queries at every turn. Real-world conversations are inherently incremental, with users relying on shared conversa-tional context through pronouns, omitted entities, and implicit references. Furthermore, accurate re-call alone is insufficient for a practical memory sys-tem. It must retrieve only the information necessary to answer the current query, avoiding redundant or irrelevant context. This is particularly important in enterprise deployments, where excessive retrieval increases latency, inference costs, and can over-whelm the downstream language model, increasing the likelihood of hallucinations.
