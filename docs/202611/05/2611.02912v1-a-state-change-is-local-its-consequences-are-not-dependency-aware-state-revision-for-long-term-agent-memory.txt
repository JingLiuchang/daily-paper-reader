Abstract 

Long-lived agents rely on persistent memory of users, tasks and decisions, and this memory must stay consistent with a world that keeps changing. When an upstream fact changes, however, memory systems can revise the con-tradicted memory itself while the beliefs, plans and actions derived from it remain accepted, even though they have lost their support. We therefore formulate dependency-aware state re-vision, which asks not only what changed but also which dependent states should no longer be trusted. To address it, StateGraph maintains an evolving state dependency graph whose edges are recovered from interaction histories. Its core design is counterfactual verification: each candidate edge is tested by asking whether the dependent state would survive the loss of its premise, which separates support dependence from semantic relatedness, and revision then invalidates a dependent state only when a strict dependency fails and no independent support path survives. To test this design, we intro-duce StateChangeBench, a controlled bench-mark of 50 author-constructed cases annotated with cascade depth, hard negatives and action consequences. On it, StateGraph’s Impact-F1 margin over a CUPMem reimplementation is 6.9 percentage points at depth 1 and 26.0 at depth 3+. On public long-term memory bench-marks, its point estimates are comparable to or higher than those of the evaluated baselines on most datasets. These results provide ini-tial evidence that explicit dependency tracking can improve selective memory revision under changing conditions. 

1 Introduction 

Long-lived agents must update persistent state as availability, tasks, permissions and book-ings change. Existing systems consolidate facts (Chhikara et al., 2025), link notes (Xu et al., 2025), page context (Packer et al., 2023), track tempo-ral validity (Rasmussen et al., 2025) or adjudi-cate state conflicts with propagation-aware search (Chao et al., 2026). These systems address consoli-dation, temporal validity and state conflicts, but do not necessarily identify which downstream conclu-sions lose support after an upstream revision. Consider states s1: the user is available Friday afternoon, and s2: a 3pm review is feasible, with pending action a1: schedule the review. The user then mentions a Friday-afternoon flight, which in-validates s1 without directly contradicting s2, leav-ing s2 unsupported but still accepted, so item-level revision can let a1 proceed (Figure 1). A state change is local, but its consequences need not be. Knowledge-editing benchmarks show a similar gap between recalling a changed fact and reasoning about its implications (Zhong et al., 2023; Cohen et al., 2024). We therefore formulate dependency-aware state revision : identify changed states and the downstream beliefs, plans and actions requiring re-vision. Three challenges arise. Discovery must re-cover dependencies that are rarely stated explicitly; 

verification must distinguish support dependence from semantic similarity; and propagation must revise consequences without invalidating weakly dependent states, which should be flagged instead, or independently supported ones. StateGraph addresses these challenges in turn. Bounded candidate discovery proposes dependency pairs from structural, provenance and linguistic cues rather than comparing all state pairs. Its core design is counterfactual verification: each candi-date is tested by asking whether the dependent state would survive the loss of its premise, which grades the edge as S TRICT , W EAK or N ONE instead of accepting topical association as dependence. reasoning and obsolete-information avoidance (Wu et al., 2025; Uddin et al., 2026; Hu et al., 2025), but lack joint labels for dependencies, downstream targets, unaffected states and action consequences. To test the design, we introduce StateChangeBench, a controlled benchmark of 50 author-constructed cases that provides these labels. On it, StateGraph’s Impact-F1 margin over our CUPMem reimplemen-tation is 6.9 percentage points at depth 1 and 26.0 at depth 3+, and on public memory benchmarks its point estimates are comparable or higher on most datasets. These results provide initial evidence that explicit dependency tracking can improve selec-tive memory revision when upstream facts change; establishing this beyond a small controlled bench-mark requires larger independent evaluations. We make four contributions. 1. We identify how local state changes invalidate downstream beliefs, plans and actions through latent dependencies without directly contradict-ing them. 2. We introduce StateGraph, whose main method-ological contribution is recovering support de-pendencies from interaction histories and ver-ifying them counterfactually; its propagation stage applies established dependency-directed revision with explicit support and scope checks rather than invalidating every reachable state. 3. We introduce StateChangeBench , a controlled 50-case benchmark annotating dependency structure, cascade depth, hard negatives and ac-tion consequences, with metrics for dependency recovery, multi-hop impact and over-/under-invalidation. 4. We evaluate StateGraph against eight memory baselines and two ported-mechanism variants, with ablations isolating verification, alternative support, conservative revision and propagation (§6). 

2 Related Work 

Vector and agentic memory. RAG couples gen-eration with retrieved non-parametric evidence (Lewis et al., 2020), and search-augmented rea-soning can learn how much retrieved evidence to acquire and expose (Xiong et al., 2026a). Agent memory adds reflection (Park et al., 2023), recall-based decay (Zhong et al., 2024), consolidation (Chhikara et al., 2025), linked notes (Xu et al., 2025) and context paging (Packer et al., 2023). MemoryOS organizes hierarchical storage and up-dating (Kang et al., 2025); LightMem combines input compression with offline consolidation (Fang et al., 2026). DIVE accumulates persistent natural-language skills and revises them from verifier feed-back (Xiong et al., 2026b); such revision targets reusable procedures rather than factual states and their consequences. StateGraph focuses on whether new evidence removes the warrant for downstream states. 

Graph-based memory. HippoRAG and Hip-poRAG 2 combine knowledge graphs with Personalized PageRank for relational retrieval (Jiménez Gutiérrez et al., 2024; Gutiérrez et al., 22025). StructMem preserves event-level bindings and consolidates cross-event connections (Xu et al., 2026). Temporal graphs encode semantic relations and validity intervals, excluding superseded facts at retrieval time (Rasmussen et al., 2025). SWAP represents reasoning steps as an entailment graph whose intermediate steps can be verified (Xiong et al., 2025), but the graph is built within a single reasoning episode rather than maintained across a changing memory. Retrieving related states and de-termining which states lose support after a change are distinct tasks. 

State-aware memory. STALE (Chao et al., 2026) evaluates implicit conflict: later observations invalidate earlier memories without explicit nega-tion. CUPMem combines state consolidation and propagation-aware search. MCB evaluates whether an agent reusing information should persist it, use it only in context, re-verify it or ask for clarifica-tion (Li et al., 2026); we instead ask which down-stream states require revision once an upstream state changes. Our direct revision (§4.1) follows write-time adjudication, while dependency verifi-cation determines downstream support. 

Knowledge editing and ripple effects. Multi-hop editing benchmarks distinguish recalling ed-its from propagating their consequences (Zhong et al., 2023; Cohen et al., 2024). These bench-marks evaluate the propagation of triple edits over knowledge graphs; we recover latent dependencies from unstructured observations. Parametric editing methods (Meng et al., 2022, 2023) target model parameters rather than memory states. 

Questionable assumptions in QA. QA bench-marks study questions with questionable premises (Kim et al., 2023; Yu et al., 2023). Stale premises are a temporal instance: a premise was valid earlier but has since changed. Memory records when it ceased to hold, enabling evidence-backed correc-tion. 

Truth maintenance and belief revision. Truth maintenance retracts unsupported beliefs (Doyle, 1979; de Kleer, 1986); belief revision formalizes change (Alchourrón et al., 1985); incremental view maintenance propagates updates (Gupta and Mu-mick, 1995). These systems receive explicit depen-dencies. StateGraph discovers and counterfactually verifies dependencies latent in interaction (§4.2– §4.3), then applies dependency-directed propaga-tion.

3.3 A Consistency Property 

Gold labels assess revision correctness; conditional invalidation closure checks consistency given de-pendency and support judgments. A S TRICT edge states that sj depended on si given the evidence available when the edge was verified (§4.3); it does not rule out support that arises later. A node has alternative support when CURRENT, scope-compatible evidence or states independently li-cense its operative claim after removal of the failed path. Self-support, failed-path evidence and cir-cular justification are excluded; reachability alone does not make otherwise independent support inel-igible.

4 StateGraph 

StateGraph’s main methodological contribution lies in recovering and verifying support depen-dencies from interaction histories. Its propagation stage applies established dependency-directed revi-sion principles (Doyle, 1979) with explicit support and scope checks. StateGraph incrementally per-forms direct revision (§4.1), candidate discovery (§4.2), counterfactual verification (§4.3) and con-servative propagation (§4.4). Premise-aware use (§4.5) gates queries and actions (Figure 2). 

4.1 State Representation and Direct Revision 

Observation xt yields states with type, provenance and temporal/conditional scope (§3). Canonical slot identifiers track logical states; separate iden-tifiers distinguish assertion versions. Matching uses canonical revision keys and functional iden-tity, meaning that the assertions describe the same logical state. Each matched pair is classified as 

consistent , duplicate , update , explicit conflict , im-plicit invalidation , temporary exception or uncer-tain (Figure 2A). Updates and conflicts change sta-tus while preserving older assertions and prove-nance. Scoped overrides distinguish temporary ex-ceptions from general changes. We adopt the write-time adjudication principle of CUPMem (Chao et al., 2026) within StateGraph’s state schema, canonical matching and scoped status transitions. This produces the seed set It; §6.2 compares the implemented systems’ direct-revision outcomes.

4.3 Counterfactual Dependency Verification 

For each candidate si → sj , we probe whether sj

survives antecedent invalidation: 

If si were no longer a valid current premise, and all other evidence in the verification context remained unchanged, would sj still hold? 

and label the edge from the answer: • S TRICT — sj does not survive in the verification context. Its support there runs through si.• W EAK — si contributes to sj ’s support, but sj

is not defeated without it: either its validity be-comes undetermined, or independent support al-ready in the verification context still establishes it. • N ONE — sj is unaffected. The states were re-lated, not dependent. The verifier rejects judgments inconsistent with their counterfactual outcome. Accepted S TRICT 

and W EAK edges retain direction, relation type and dependency strength; N ONE edges do not propa-gate. The counterfactual probe is designed to distin-guish support dependence from topical relatedness by testing whether the dependent claim loses its warrant; it also grades the dependency as S TRICT 

or W EAK and identifies reachable states that sur-vive antecedent removal (Equation 5). 

Strictness and alternative support. Verification and revision answer different questions. Verifica-tion runs when an edge is proposed and judges sj

against the support context available to the verifier at that time. An edge is S TRICT only if sj fails in that context once si is removed; if independent support for sj is already present there, sj holds and the edge is labeled W EAK (Appendix B.5). STRICT thus means that sj depended on si given the evidence available at verification, not that no other support can arise later. Invalidating the de-pendent state therefore additionally requires that no independent support path survives at revision time. 5 StateChangeBench 

5.1 What Existing Benchmarks Do Not Isolate 

Existing benchmarks measure recall, retrieval, tem-poral reasoning, abstention, environment experi-ence and obsolete-information avoidance (Maha-rana et al., 2024; Wu et al., 2025, 2026; Uddin et al., 2026; Hu et al., 2025), without the dependency and downstream-revision labels needed to assess cas-cades. Episode-level protocols for workflow agents score state continuity, evidence traceability and escalation decisions rather than one-shot outputs (Yao et al., 2026a), and task success can diverge from the behavior a system is meant to support, so the two should be reported separately (Yao et al., 2026b). StateChangeBench likewise scores post-revision states and downstream actions separately from answer accuracy. 65.2 Case Design 

Each case includes history, pre-existing states and dependencies, new evidence, and a query or pending action. Gold labels specify every state’s post-revision status, invalidation depth/-path, S TRICT /W EAK strength, surviving-support conditions and action ( proceed , revise-plan , ask-clarification ). Strata cover depth 0–3+, implic-it/weak dependencies, alternative support, tempo-rary exceptions, historical states and action conse-quences. 

Hard negatives. Weak dependencies, surviving support and scope-narrowing exceptions test se-lective revision against indiscriminate invalidation. StateChangeBench has 50 cases: 10/15/15/10 at depth 0/1/2/3+, including 17 hard negatives (34%) and 36 action-consequence cases (72%). We report over-invalidation alongside recall; Appendix C, Ta-ble 9, provides the specification and distribution. 

5.3 Construction and Quality Control 

Cases are seeded from interaction data (Wu et al., 2025) and organized under a stratum specification. Human annotators label post-update state status, cascade depth and dependency type. Agreement on a double-annotated subset, whose size was not recorded, is reported separately for these dimen-sions, with Cohen’s κ values of 0.7915, 1.0000 and 0.5583, respectively. Dependency paths, down-stream revision targets and preservation conditions are specified in Appendix C.

6.5 RQ4: Supplementary Evaluation on Public Memory Benchmarks 

This supplementary evaluation checks whether adding dependency revision coincides with lower performance on standard long-term memory tasks. Using State Answer Accuracy, StateGraph scores 52.0% on STALE versus CUPMem’s 51.7%, and 53.9% on LongMemEval (Wu et al., 2025) versus Mem0’s 51.3%. On MemoryAgentBench it scores 36.6%, below A-MEM’s 43.1% and above CUP-Mem’s 28.1%. Its point estimates are comparable to or higher than those of the evaluated baselines on five of the six benchmarks. We did not run significance tests, so these results do not establish the absence of degradation. Appendix A, Table 7, reports all six benchmarks.

7 Analysis 

Why the margin is larger at greater depth. The larger margin at depth 2–3+ is observed on State-ChangeBench’s depth strata; the following explana-tion is consistent with the ablations but is not sepa-rately tested. At depth 1, new evidence often lies near affected states in topic and time, enabling di-rect adjudication. At depth 2+, new evidence need not mention downstream states. Unverified propa-gation compounds false edges across hops; counter-factual verification selects supported edges, while conservative revision preserves independently sup-ported states (Figure 3; Observations 1–3). 

8 Conclusion 

Long-term agents can fail not only by forgetting or by remembering the wrong thing, but by con-tinuing to trust conclusions whose grounds have disappeared. We formulated dependency-aware state revision and introduced StateGraph, which recovers dependencies, verifies them counterfactu-ally and propagates revisions selectively, together with StateChangeBench for measuring this capa-bility. StateGraph addresses downstream loss of support that may remain unresolved after direct memory revision. Experiments on a small con-trolled cascade benchmark suggest benefits from explicit dependency verification and selective prop-agation. Larger independent evaluations are needed to establish robustness across domains, backbones and extended interaction histories. An open prob-lem is how to verify dependencies without relying on the same model that proposes them: the cur-rent pipeline provides no independent guarantee of detecting correlated errors across proposal, verifi-cation and support assessment. 

Limitations 

The evidence supports dependency-aware revision under the evaluated conditions: full-benchmark ex-periments using DeepSeek-v4-Flash, including all 50 StateChangeBench cases and depth strata. Stat-eChangeBench isolates cascade reasoning through author-constructed English cases, a written stra-tum specification and double annotation of a subset (Appendix C); the broader memory benchmarks provide complementary coverage. With 50 cases and 10–15 cases per depth stratum, and without sig-nificance tests, the depth-wise differences should be read as initial evidence. Our retained records are incomplete. They do not preserve the number of evaluation runs per con-figuration or the size of the double-annotated sub-set, so these quantities are not reported. For the 9same reason, this version omits the action-decision evaluation and the premise-gate ablation: their ag-gregation could not be reconstructed from the re-maining records. We plan to rerun these evalua-tions with complete logging in a future version. These results do not establish performance across other backbones, languages, multimodal inputs or multi-agent deployments. Relation typing, counterfactual verification and alternative-support assessment use the same LLM, so their errors can be correlated. CVR checks clo-sure using the system’s support judgments and is not an independent validation of those judgments; gold-labeled impact and invalidation metrics pro-vide complementary outcome evaluation. WEAK edges trigger reassessment without recursive prop-agation, restricting cascades to verified STRICT dependencies. Propagation uses lineage-aware cy-cle handling; mutually supporting cycles require separate validation. Verification adds write-time computation; the tables report total per-case LLM tokens and latency, with costs depending on work-load and serving conditions. 

Ethics Statement 

StateGraph addresses outdated premises and un-supported downstream actions through counterfac-tual verification, alternative-support checks and premise-aware gating. Incorrect dependency judg-ments can nevertheless cause missed or unneces-sary revisions. This version does not evaluate ac-tion decisions, and benchmark results do not certify deployment safety or replace human authorization for consequential actions. Evaluation uses existing memory benchmarks and StateChangeBench to assess memory revision and downstream action behavior. For deployments that store personal states, memory management should also incorporate data minimization, access controls, appropriate retention periods, and user correction and deletion mechanisms for both mem-ories and dependency links.

A.6 Implementation and Reproducibility Propagation. Cascade traversal has no fixed numerical depth bound. It terminates when its queue is exhausted, deduplicating source/root/effect lineages and skipping cycles back to directly invalidated seeds. Only new status effects trigger further traversal; weak dependencies prompt revalidation without extending the cascade. Depth in Algorithm 1 records traversal distance rather than imposing a cutoff. Retrieval graph depth 2, beam width 4 and relational maximum hops 3 are separate retrieval settings. 

Candidate limits. The modular discovery request permits at most 64 unordered endpoint pairs. Struc-tural candidates are then added and unordered pairs deduplicated before separate direction/type clas-sification. The 64-pair limit applies to each model response, not to the combined pool after structural supplementation. 

Generation. All experiments use DeepSeek-v4-Flash with thinking disabled. Maximum output tokens are 8,192 for fact proposal; 2,048 each for semantic validation, direct revision and cross-observation dependency proposal; 4,096 for dependency verification; and 512 for shared answer generation. These are request ceilings, not observed completion lengths. Each logical request permits up to three transport attempts, with SDK retries and structured-output repair attempts set to zero. 

Answer-time evidence. Retrieval selects up to ten states, prioritizing query-field coverage and prove-nance anchors, then expanding dependency neighbors breadth-first. Serialized evidence spans are limited to 480 characters each. The final answer-context helper preserves input order, admits at most ten items and 64,000 characters, truncates the first over-budget item and stops. The configuration also declares 16,000 tokens; the helper enforces item and character limits rather than a tokenizer-based hard token cap. These limits apply only to answer-time context. C.2 Stratum Specification 

Case authors work from the following specification and are not shown the method. Each case must be solvable from the history alone. • Depth 0 — the new observation directly contradicts exactly one state; nothing downstream depends on it. • Depth 1 — exactly one state depends on the contradicted state, and nothing in the history contradicts that dependent state. • Depth 2, 3+ — as above, chained. Every intermediate state must be individually plausible in isolation. • Implicit dependency — the dependency is never stated linguistically and must be inferred from task structure. • Weak dependency — the antecedent raised the dependent state’s plausibility without establishing it; the gold status is U NCERTAIN , not S TALE .• Alternative support — a second, independent line of evidence licenses the dependent state; gold status is C URRENT .• Temporary exception — the change narrows a scope rather than voiding it; the general state survives, the scoped instance does not. • Historical state — the superseded state remains correct as history and must stay retrievable. • Action consequence — a pending action depends on the affected state; the gold action label is not 

proceed .

D Case Studies 

D.1 Study Case 

Evaluation setting. This case study reports a StateGraph run using DeepSeek-v4-Flash on State-ChangeBench case SCB_006 , with the results compared against its gold annotations. Case SCB_006 is a D3+ example with structural depth three. Its history records that order #4471 was addressed to 12 Elm Street, a courier label was printed from that address, a Thursday estimate was based on the label route, and an arrival email was queued for Lena. A handwritten gift note is recorded separately. The new observation says the parcel should not go to Elm Street and requests 88 Oak Avenue instead. The query asks to tell Lena that the parcel will arrive Thursday at the old address. StateGraph first aligned the new address assertion with the existing address slot. Given the source’s explicit correction, direct revision marked the old address stale while retaining the replacement as current. The gold graph specifies three strict links: address to label ( DEPENDS_ON ), label to estimate (DERIVED_FROM ), and estimate to queued email ( AFFECTS_ACTION ). Relation typing and counterfactual verification accepted these source-grounded links. Propagation assessed each downstream state for independent current support and marked the label, estimate, and queued email stale at depths one through three, matching the gold targets. The unrelated gift note remained current. At query time, premise-aware gating rejected the old address as current evidence and blocked the original action referencing the stale chain, requiring replanning. The benchmark identifiers are retained below; the implementation distinguishes state nodes from pending actions when applying AFFECTS_ACTION .
