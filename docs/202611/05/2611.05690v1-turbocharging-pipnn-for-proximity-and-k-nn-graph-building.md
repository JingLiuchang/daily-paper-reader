## 摘要
基于图的近似最近邻搜索（ANNS）索引（如 HNSW 和 Vamana）以较大的索引时间为代价，提供最先进的查询性能。最近提出的 PiPNN 方法通过利用稠密矩阵乘法和 top-$K$ 聚合内核的基于分区的算法，大幅加速了索引构建。在本文中，我们充分释放 PiPNN 硬件友好算法设计的潜力。我们提出 PiPNN II，它优化了 PiPNN 流程中的多个步骤，使基于图的 ANNS 索引构建获得最高 $8\times$ 的加速。此外，我们提出 GPiPNN，一种 GPU 实现，其构建质量相当的 ANNS 索引，速度最高比 Jasper 快 $43.7\times$，比 CAGRA 快 $50\times$。我们还扩展 PiPNN II 和 GPiPNN 以直接计算高质量的 $k$-NN 图，相比许多现有系统中用于聚类、异常检测等任务的方法带来巨大加速。对于在 $90\%$ 召回率下构建 10-NN 图，与先前最佳方法相比，我们在 CPU 上获得最高 $13\times$ 的加速，在 GPU 上获得 $6.6\times$ 的加速。PiPNN II 可以在 16 分钟内构建十亿规模的 10-NN 图。PiPNN II 和 GPiPNN 的共同点是使用量化来减少内存流量并利用快速低精度矩阵运算。Top-$K$ 成为新的瓶颈，我们通过针对特定 $K$ 的专用代码，以及将其与矩阵内核融合以避免将距离矩阵物化到内存中来优化。在 CPU 上，我们通过在 Vamana 中提出并在 PiPNN 中使用的 RobustPrune 过程中利用我们的矩阵内核，展示了进一步的性能提升。在 GPU 上，我们将递归分区展平为分段批次，使用一个融合的 top-$K$ 抽象进行分区和叶评分，并使用已见证的直接边进行剪枝，而不是进行新的候选到候选评分遍历。

## Abstract
Graph-based Approximate Nearest Neighbor Search (ANNS) indexes such as HNSW and Vamana deliver state-of-the-art query performance at the cost of large indexing times. The recently introduced PiPNN method drastically accelerated index construction by way of a partitioning-based algorithm leveraging dense matrix multiplication and top-$K$ aggregation kernels.   In this paper, we unlock the full potential of PiPNN's hardware-friendly algorithm design. We introduce PiPNN II, which optimizes multiple steps of the PiPNN recipe, giving up to $8\times$ speedups for graph-based ANNS index construction. In addition, we present GPiPNN, a GPU implementation which builds comparable ANNS indices up to $43.7\times$ faster than Jasper and up to $50\times$ faster than CAGRA. We also extend PiPNN II and GPiPNN to compute high-quality $k$-NN graphs directly, which unlocks massive speedups over methods used in many existing systems for clustering, anomaly detection, and more. For 10-NN graph building at $90\%$ recall, we obtain up to a $13\times$ speedup on CPUs and $6.6\times$ on GPUs as compared to the prior best methods. PiPNN II can build a billion-scale 10-NN graph in under 16 minutes.   Common to both PiPNN II and GPiPNN is the use of quantization to reduce memory traffic and leverage fast low-precision matrix operations. Top-$K$ emerges as a new bottleneck, which we optimize with specialized code for specific $K$, and by fusing with the matrix kernel to avoid materializing the distance matrix to memory. On CPUs, we demonstrate further performance improvements by leveraging our matrix kernels in the RobustPrune procedure proposed in Vamana and used in PiPNN. On GPUs, we flatten recursive partitioning into segmented batches, use one fused top-$K$ abstraction for partitioning and leaf scoring, and prune with already-witnessed direct edges rather than new candidate-to-candidate scoring passes.

# 《Turbocharging PiPNN for Proximity and k-NN Graph Building》论文总结

## 1. 核心问题与研究动机

- **背景**：图基近似最近邻搜索（ANNS）索引（HNSW、Vamana/DiskANN、NSG 等）在查询阶段性能领先，但其构建依赖增量式束搜索（beam search），伴随大量随机内存访问与缓存缺失，构建一个高质量近邻图往往需要数小时甚至数天。
- **痛点**：构建时间已成为系统总成本的关键因素——数据漂移需重建索引、参数需跨数据集调优，且 ANNS 还是 k-means 加速、层次聚类、最小生成树、单链接聚类等任务的内循环原语；慢构建方法在现代工作流中几乎不可用。
- **前期工作**：PiPNN 通过“分区—拾取—剪枝”的流程，用分区内稠密全对比较替代构建期图搜索，已比 ParlayANN-Vamana 快至多 11.6×，但原版仍保留 FP32 GEMM、将完整距离矩阵物化到内存再做逐行 top-k 归约，未充分释放硬件潜力。
- **本文目标**：从第一性原理重构 PiPNN 全流程，在 CPU（PiPNN II）与 GPU（GPiPNN）上实现硬件友好的量化+融合 top-K 内核，并将同一方法扩展到直接构建高质量 k-NN 图。

## 2. 方法论

### 2.1 总体思路
- 以**量化**压缩向量、降低访存，并启用低精度整数矩阵指令；将 **GEMM 与 per-query top-K 选择融合**，在寄存器内消费距离，避免物化 $M\times N$ 距离矩阵；针对 PiPNN 中实际出现的特定 $K$（1、3、10）专门化选择代码。

### 2.2 量化方案
- 采用两种量化：**RSQ8**（旋转标量量化，8 bit/维）与 **TQ4**（TurboQuant 的 4-bit 变体）。
- TQ4 变体：先随机旋转（Fast Walsh–Hadamard + 小随机正交矩阵，$O(d\log d)$、数据无关），再对每维独立做标量 Lloyd–Max 量化；用额外码本比特 + 每向量缩放因子 $\sigma$（原范数/量化范数）替代原 TurboQuant 的 QJL 残差；距离估计为整数内积乘以 $\sigma_q\sigma_d$ 校正。
- 解码后统一为 int8，可用 16 项码本经 `vpshufb` 在寄存器内快速展开；该模板也兼容 RaBitQ、DRIVE/EDEN 等量化器。

### 2.3 CPU 内核（PiPNN II）
- **矩阵乘结构**：外层循环 query、中层循环 database、内层按维度归约，使点积在循环结束时即为最终值，无需溢出到内存。
- **VNNI 指令**：使用 AVX-512 `vpdpbusd`（u8×i8 四维点积，16 个 i32 lane 并行）；由于该指令只支持无符号×有符号，将 database 码整体 +128 变为 u8，再减去 $128\sum b_i$ 修正误差。
- **数据布局**：将 database 按 16 点一组的 **panel** 交错存放，使 64 字节连续存放 16 个点的同一 4 维组，一条指令同时为 16 个点打分，避免逐点水平归约。
- **展开**：query 方向展开 $M_q=6$，panel 方向展开 4，内层每轮 24 条 `vpdpbusd`。
- **AssignLeaders 内核**：非对称 GEMM + 逐 query top-$K$；leader 预转置，按 $F=10/3/1$（逐层衰减）专门化。
- **top-K 选择**：
  - $K=1$：向量化 ArgMin，寄存器内维护逐 lane 最小值与索引，最后水平归约；
  - $K\in\{3,10\}$：**位移排序（displacement sort）**——逐 lane 独立维护 top-$K$，每轮用掩码 + 条件混合把被挤出元素沿位移寄存器传递，循环结束后再标量合并；$K=10$ 时 tracker 溢出到 L1 但可接受。
- **Leaf 内核**：利用距离对称性只计算下三角（约省一半计算），用掩码将自距离与重复对置为 $+\infty$；query 侧 tracker 常驻寄存器，database 侧 tracker 每 panel 载入一次、批内复用；**无分支的 lane 并行 top-2 插入**仅需 6 条 blend 指令（比通用 top-2 少 2 条），最后做跨 lane 归约。
- **RobustPrune 加速**：比较“朴素向量化”“面板化距离矩阵”“融合面板（仅保留 survivor 与下一批 query）”三种实现，融合版相对 Distmat 再快 1.08×。

### 2.4 GPU 内核（GPiPNN）
- **展平递归**：用固定轮数的 assign-then-radix-sort 替代显式递归；默认 $f_0=8$、$f_1=4$，每点最多 32 个叶成员资格，与 CPU 的约 30 相当；两轮足以达到高召回。
- **正则化桶大小**：radix sort + run-length encode 得到桶大小，拆分过大桶、合并过小桶至目标约 1024，使固定 tile 内核可统一处理所有叶，避免长尾导致的 SM 空转。
- **单一融合分段 top-K 原语**：所有批量 top-K 共用一个内核，直接在解码后的 i8 码上打分；使用 Hopper **wgmma**（$M=64$ query 行 × $N=128$ database 列 × $W=32$ 字节收缩宽度），累加器分布在 warpgroup 寄存器中；数据库行打包进单一 slab 以便 TMA 拷贝；以固定大小 **score tile** 静态分配线程块，一个 launch 同时处理数千个叶（分段）。
- **寄存器 top-K + butterfly 合并**：每 lane 私有 top-K，插入前先与第 $K$ 名比较快速拒绝，全展开 compare-swap 链保持编译期常量槽位以避免寄存器溢出到 local memory；行内 4 个 owner lane 用 mask 1、2 的 shuffle butterfly 两轮合并。
- **HashPrune → sort-and-merge**：GPU 上用锁竞争严重，改为每批叶发射固定大小候选记录（含 12-bit SimHash 残差方向草图），按 owner 行与距离做 radix sort，使每个 owner 的候选连续，再单线程顺序合并；瞬态缓冲受 per-batch slab cap（约 6 GB）约束，不随全图增长。
- **DirectEdgePrune**：剪枝时若已接受邻居 $p^*$ 的邻接表中已有候选 $p'$，则复用其存储距离作为“已见证”的 $d(p^*,p')$ 做 $\alpha$-剪枝测试；该松弛只有单侧误差——可能漏掉精确 RobustPrune 会剪的边，但绝不会多剪，因此图更稠密（30–58%）但质量相当。
- **直接 k-NN 模式**：将 leaf top-K 与累加器容量设为 $k$，关闭同草图过滤、仅按目标 id 去重，跳过最终剪枝直接导出有向图，避免“先建索引再自查询”的双倍开销。

## 3. 实验设计

- **数据集**：共 12 个 CPU 数据集、13 个 GPU 数据集，覆盖文本、图像、文本到图像三类模态，维度 96–4096，规模 50 万–10 亿（GPU 最大 1 亿，受 80 GB HBM 限制）。包括 DEEP（96 维，10 亿）、MS-Turing（100 维，10 亿）、Text2Image（200 维，10 亿）、MSMARCO（768 维，1.01 亿）、MSMARCO-Arctic（1024 维，1.14 亿）、Wiki-Cohere（3500 万）、wiki-all（8800 万）、DBpedia-1536/3072、Wiki-Qwen-500K（4096 维）、OpenAI-ArXiv、DataCompDr（1278 万）等。
- **任务与指标**：
  - ANNS 索引构建：构建时间 + 查询 QPS-vs-recall 曲线（10@10 recall）；
  - 直接 k-NN 图构建：达到 recall ≥ 0.9 的最快构建时间（5,000 个种子点对暴力 top-10 采样）；
  - 消融：leaf 2-NN 内核逐步优化、RobustPrune 三种实现、精度/维度扫描、SOL 利用率分析。
- **对比方法**：
  - CPU：PiPNN 原版（FP32/RSQ8/TQ4）、ParlayANN-Vamana（FP32 与 SQ8/JL+SQ8）、PyNNDescent（SQ8）；
  - GPU：Jasper（Vamana 的 GPU 移植 + RaBitQ）、CAGRA（NN-Descent 构建，含 FP16/PQ4/PQ8 变体）、cuVS NN-Descent、IVF-PQ8。
- **公平性处理**：对 ANNS 任务选取各方法“高质量配置”（QPS-recall 曲线与未量化 Vamana 可比）；对 k-NN 任务统一以 recall ≥ 0.9 为门槛取最快配置；CPU 上调 $\alpha$ 使 PiPNN 与 Vamana 平均度相差 ±2；GPU 查询统一使用 Jasper 的搜索内核以排除查询实现差异。

## 6. 主要结论与发现

- **CPU（PiPNN II）**：比原版 PiPNN 快至

- **CPU（PiPNN II）**：比原版 PiPNN 快至多约 4×，相对 ParlayANN-Vamana（含其 SQ8+JL 过滤的最强配置）快至多约 14×；在十亿级数据集（DEEP-1B、MS-Turing-1B、Text2Image-1B）上构建 10-NN 图均在 16 分钟内完成，把十亿级近邻图构建从“小时级”压到“分钟级”。
- **GPU（GPiPNN）**：单卡 H100 上比 Jasper（Vamana GPU 移植 + RaBitQ）快至多约一个数量级（约 13×），比 CAGRA（含其 FP16/PQ 变体）快更多；1 亿点规模构建约 20 秒量级，且随规模近似线性扩展，未出现明显长尾塌陷。
- **直接 k-NN 图模式**：在 recall ≥ 0.9 门槛下，GPiPNN 的最快构建时间显著优于 CAGRA / cuVS NN-Descent，且省去“先建索引再自查询”的双倍开销，验证了“把 k-NN 图当作一等构建目标”的设计价值。
- **量化几乎无损**：RSQ8 与 TQ4 在绝大多数数据集上的 QPS-recall 曲线与 FP32 基线可比，TQ4 在部分数据集上甚至因正则化桶、图略稠密而召回略高；说明 4-bit 量化 + 每向量缩放校正足以支撑高质量图构建，而非仅用于近似打分。
- **DirectEdgePrune 的取舍**：松弛剪枝使图平均度增加 30–58%，但查询质量与精确 RobustPrune 相当，换来了剪枝阶段显著的时间节省；作者明确指出这是“单侧误差”——只会保留更多边，不会误删。
- **内核级收益分解**：消融显示收益主要来自三处叠加——(i) 量化 + 整数 VNNI/wgmma 指令替代 FP32 GEMM；(ii) GEMM 与 top-K 融合、消除 $M\times N$ 距离矩阵物化与二次访存；(iii) 针对 $K\in\{1,3,10\}$ 与 top-2 的专用寄存器内选择代码（位移排序、无分支 blend 插入）。SOL 分析表明 leaf 内核在计算与访存两个维度上都接近硬件上限，剩余空间主要受限于选择逻辑的指令组合。
- **总体判断**：论文证明了“用分区内稠密比较 + 硬件友好量化 + 融合选择”可以在 CPU 与 GPU 两条路线上同时击败基于图搜索的增量构建方法，并给出了一套可复用的内核模板（兼容 RaBitQ、DRIVE/EDEN 等量化器）。

## 7. 贡献与意义

- **方法论层面**：把近邻图构建从“图搜索问题”重新表述为“稠密分块打分 + 选择问题”，使构建阶段的计算形态从随机访存主导转为规则 GEMM 主导，从根本上契合现代 CPU/GPU 的吞吐特性。
- **工程层面**：给出了完整的 CPU（AVX-512 VNNI、panel 布局、位移排序）与 GPU（Hopper wgmma、TMA、分段融合 top-K、butterfly 合并）实现细节，具有较强可复现性与移植价值。
- **系统层面**：将十亿级 10-NN 图构建压缩到分钟级、亿级压缩到秒级，使“数据漂移即重建”“按数据集调参重跑”在工程上变得可行，并可直接服务于 k-means、层次/单链接聚类、MST 等以内循环近邻为原语的任务。
- **可复用性**：量化模板、融合 top-K 原语、DirectEdgePrune 与 sort-and-merge 剪枝等组件相对独立，可被其他图构建或检索系统单独采纳。

## 8. 局限与未来工作

- **分布式缺失**：所有实验均为单机/单卡，未验证多卡或多机扩展；对超过单卡 HBM（本文上限 1 亿点）的规模，如何分片与跨片合并边仍是开放问题。
- **度量覆盖**：以 MIPS 与 L2 为主，未系统覆盖余弦之外的稀疏/非欧度量或带过滤（attribute filtering）场景。
- **参数敏感性**：GPiPNN 的 $f_0,f_1$、桶目标大小、slab cap，以及 PiPNN II 的 panel 展开与 $\alpha$ 等参数仍需按数据集调优，论文虽给出默认值与扫描，但未提供自动化调参策略。
- **剪枝松弛的代价**：DirectEdgePrune 使图更稠密，内存占用与查询期访存相应上升；在内存受限场景下的收益需重新权衡。
- **baseline 覆盖不完整**：部分 baseline 因内存溢出或不支持 MIPS 未能在全部数据集上跑通，聚合加速比只基于可完成子集，跨方法比较的完备性有限。
- **未来方向**（作者暗示与可推断）：多卡/分布式 GPiPNN、把同一模板推广到更多量化器与稀疏度量、将构建与查询内核统一以进一步压缩端到端成本、以及面向动态数据的增量重建策略。

## 9. 总体评价

这是一篇“系统 + 内核”双轮驱动的扎实工作：问题动机清晰（构建时间成为 ANNS 的总成本瓶颈），技术路线统一（量化 + 融合 GEMM/top-K + 专用选择代码），并在 CPU 与 GPU 上分别给出接近硬件上限的实现与大规模实证。其价值不仅在于加速比数字，更在于把“近邻图构建”的计算范式从图遍历迁移到稠密分块，为后续系统设计提供了新的基线。主要不足在于缺少分布式验证与更广的度量/过滤场景覆盖，参数调优仍偏人工。
