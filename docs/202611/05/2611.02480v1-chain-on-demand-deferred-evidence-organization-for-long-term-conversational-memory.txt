## ABSTRACT 

Long-term conversational memory faces a timing mismatch: write-time sum-maries and graphs organize history before a future query is known, while indepen-dent retrieval can allocate a limited evidence budget to redundant or fragmented turns. We introduce Chain on Demand (C OD), a query-time evidence organization framework over an unchanged turn-level memory. Given a broad candidate pool, COD constructs a temporary evidence chain by allocating a fixed anchor budget according to query relevance, lexical diversity relative to selected anchors, and newly covered query terms, followed by deterministic restoration of each selected anchor’s same-session neighborhood. The resulting chain is used only for the current query, while the underlying conversational memory remains unchanged. In a paired comparison over all 1,986 LoCoMo questions, changing only the al-location rule improves accuracy from 74.5% to 76.3% (+1.86 percentage points; conversation-cluster 95% CI [0.59, 3.15]). C OD also achieves 82.2% accuracy on the 1,540 non-adversarial questions. On LongMemEval-S, one fixed configuration that indexes both user and assistant turns obtains 86.6% across all 500 questions. These results show that long-term memory can preserve the original conversation while deferring evidence organization until the information need is known. Our code is available at https://github.com/Renkiroo/chainondemand 

## 1 INTRODUCTION 

Conversational agents need to retain information across interactions that span days, weeks, or months. A later interaction may depend on a fact mentioned much earlier, a preference estab-lished in another session, or several pieces of information spread across the conversation. As history grows, the information needed for a later question becomes harder to recover from the full inter-action record. Since the complete history rarely fits within the effective context available to the answer model, long-term memory systems must determine which parts of the history to present for the current query. Long-term memory involves two separable decisions: what representation persists across interac-tions, and what evidence is presented for a particular query. Many systems construct summaries, segments, links, graphs, or hierarchical memory units during or shortly after interaction (Zhong et al., 2023; Pan et al., 2025; Xu et al., 2025; Rasmussen et al., 2025; Fang et al., 2026; Xu et al., 2026a;b). These representations can make long histories easier to search and manage. However, they commit to an organization before the later query reveals which details matter. Retaining the original turns avoids rewriting the conversational record, but does not determine how a limited query-time evidence budget should be allocated. Independent query-time retrieval addresses this timing problem only partly. Standard top-K re-trieval scores candidates independently (Gao et al., 2024). Under a fixed budget, several similar turns may occupy the available slots while a less similar turn supplies a missing relation, temporal detail, or intermediate step. The retrieved turns can therefore be individually relevant but collectively insufficient. Query-conditioned compression and set-wise retrieval account for query requirements more explicitly (Xu et al., 2024; Lee et al., 2025), but conversational evidence adds another depen-dency: a selected turn may require nearby dialogue and temporal order to be interpreted. Simply retrieving more text does not necessarily resolve this issue, as models can fail to use relevant infor-mation embedded in long inputs (Liu et al., 2024). Recent conversational memory systems recover source context through temporal–semantic expansion, archive-level context recovery, or reranking and tool use (Wang et al., 2026; Li et al., 2026a; Sen et al., 2026). These approaches establish the value of source-context recovery, but leave open a central question: given a fixed candidate pool and anchor budget, how should conversation locations be selected jointly before their local context is reconstructed? We introduce Chain on Demand (C OD), a query-time evidence organization framework that con-structs a temporary evidence chain over an unchanged turn record. Given a query, C OD first retrieves a broad candidate pool, then allocates a fixed anchor budget using a set-aware relevance–diversity– coverage rule, and finally restores the original same-session neighborhood around the selected lo-cations. The selected anchors therefore specify where evidence should be organized rather than constituting the final evidence context themselves. The resulting chain is constructed only for the current information need and discarded after answering, while the underlying conversational record remains unchanged. This separates persistent memory from query-specific evidence construction while making the allocation decision explicit and directly testable. An adaptive acquisition variant further allows unresolved evidence gaps to trigger additional query-time selection without modify-ing the persistent memory. Table 1 positions C OD relative to representative query-time evidence construction designs. The comparison highlights three properties that jointly define our framework: preserving the original conversational record, using a fixed query procedure with explicit set-aware allocation, and restoring source context after selection. Our central evidence is a paired LoCoMo comparison that changes only the allocation rule. Un-der the same memory, candidate pool, anchor budget, temporal reconstruction, answer model, and judge, C OD raises accuracy from 74.5% to 76.3%, a 1.86-point gain with a conversation-cluster 95% confidence interval of [0.59, 3.15]. Development diagnostics further isolate the contributions of evidence volume, temporal reconstruction, and set-aware allocation. On LongMemEval-S, a fixed configuration that indexes both user and assistant turns obtains 433/500 (86.6%) across all questions, supporting applicability on a second long-term memory benchmark. ## 2 RELATED WORK 

Persistent Memory Construction. Long-term conversational memory systems differ in what they preserve across interactions. MemoryBank summarizes events and user traits (Zhong et al., 2023); SeCom builds topical segments and compressed retrieval units (Pan et al., 2025); and A-MEM aug-ments stored interactions with attributes, links, and evolving notes (Xu et al., 2025). Other systems use temporal graphs, structured summaries, or multiple levels of granularity (Rasmussen et al., 2025; Xu et al., 2026a; Fang et al., 2026; Kang et al., 2025; Xu et al., 2026b). These designs primarily determine what information persists and how it is indexed. Even when they route or filter memory according to a query, the underlying textual units or relations are constructed before that query is known. C OD instead keeps the original turn record unchanged and defers the allocation of query-specific evidence until the information need is available. 

Query-Time Evidence Allocation and Reconstruction. Standard retrieval-augmented genera-tion independently ranks candidates (Gao et al., 2024). MMR introduced relevance–diversity rerank-ing (Carbonell & Goldstein, 1998); RECOMP performs query-conditioned compression (Xu et al., 2024); and SetR explicitly selects passages as a set (Lee et al., 2025). Multi-stage and agentic sys-tems make retrieval or memory operations adaptive through deliberative search, learned policies, or program evolution (Cao et al., 2026; You et al., 2026; Packer et al., 2023; Yan et al., 2026; Yu et al., 2026; Liu et al., 2026; Li et al., 2026b). In conversational memory, the closest systems already restore source context. CueMem indepen-dently retrieves generated cues, maps them to source-turn anchors, and expands over a precomputed temporal–semantic graph (Wang et al., 2026). ReFind combines an unmodified chat archive with multi-round agent-controlled lexical search and local context expansion (Li et al., 2026a). Chronos combines raw turn and extracted event calendars with reranking, same-session expansion, and an iterative tool loop (Sen et al., 2026). These lines of work provide query conditioning, raw-record access, set selection, and local expansion in different combinations. C OD combines these compo-nents into a query-time pipeline in which selected units are conversation locations for subsequent source reconstruction rather than final passages. Its allocator is fixed and non-agentic, allowing its contribution to be measured while holding the candidate pool, anchor budget, reconstruction, answer model, and judge fixed. 

## 3 METHODOLOGY 

Given a query q and an ordered memory of original conversation turns, Chain on Demand (C OD) constructs query-specific evidence at query time. The pipeline separates three decisions: which turns are available, which conversation locations receive a fixed anchor budget, and which original context is restored around those locations. Its core allocation mechanism explicitly accounts for the evolving selected set: a greedy rule re-scores candidates as anchors are added. Candidate access defines the feasible locations, while deterministic reconstruction maps selected locations back to source context without making another set-dependent allocation decision. ## 4 EXPERIMENTS 

We evaluate C OD on LoCoMo (Maharana et al., 2024) and LongMemEval-S (Wu et al., 2025). Our main comparison isolates the effect of set-aware allocation by fixing candidate access, anchor count, reconstruction, answer model, and judge. We further evaluate performance across question types, analyze the roles of evidence volume and temporal reconstruction on a 100-question LoCoMo development subset, and measure the query-time cost of the evidence-construction pipeline. 4.1 EXPERIMENTAL SETUP 

For LoCoMo, we report results on both the 1,540 non-adversarial questions and the full set of 1,986 questions. For LongMemEval-S, we evaluate all 500 questions. GPT-4o-mini serves as both the answer model and evaluator in our runs; answer generation uses temperature 0 and at most 512 tokens. We retain each original turn with its speaker, timestamp, session, and dense embedding. Using 

text-embedding-3-small and Qdrant, C OD retrieves 200 candidates, allocates 60 anchors with λ = 0.06 and β = 0.10 , and restores two turns on each side within the same session. LongMemEval-S indexes both user and assistant turns. The primary comparison changes only the allocator; memory, questions, candidate pool, anchor budget, reconstruction, answer model, and judge remain fixed. Mechanism tests use a fixed 100-question LoCoMo development subset that is contained in the 1,986-question set, so these results are diagnostics rather than independent held-out estimates. Published values are reproduced from MemPro’s comparison table (Liu et al., 2026), which combines reproduced held-out runs with values taken from prior papers. MemPro reserves 154/1,540 LoCoMo and 50/500 LongMemEval questions for framework evolution and evaluates on the remaining 1,386 and 450; our rows report all 1,540 and 500. These values therefore provide context rather than matched comparisons. Appendix A gives the full protocol. 4.2 MAIN RESULTS

We next examine three factors on the fixed 100-question LoCoMo development diagnostic: evidence volume, local reconstruction, and set-aware allocation. These results are intended to explain the mechanism and are not independent benchmark estimates. Increasing independent dense retrieval from 60 to 200 turns raises accuracy from 51.0% to 57.0%. At nearly the same final volume, restoring local same-session context around relevance-selected anchors reaches 73.0% (202.87 turns and 4,566 words, compared with 200 turns and 4,587 words). Thus, on this diagnostic, increasing independent retrieval to a similar evidence volume does not reproduce the effect of local reconstruction. Dense plus temporal and C OD use the same candidate pool, 60-anchor budget, and reconstruction procedure, and produce nearly identical context sizes: 202.87 versus 202.82 turns and 4,566 versus 4,575 words. Replacing relevance-only anchors with set-aware allocation increases accuracy from 73.0% to 77.0% at essentially unchanged evidence volume. The resulting comparisons separate evi-dence quantity from organization: Dense-60 versus Dense-200 gives a 6-point increase from broader independent retrieval, Dense-200 versus Dense plus Temporal gives a 16-point increase from local reconstruction at similar volume, and Dense plus Temporal versus C OD gives a 4-point increase from changing the anchor allocation. These development results are not an additive decomposition of benchmark-wide performance. Section 5 further examines diversity, coverage, candidate avail-ability, and alternative allocation rules.

Figure 2(b) isolates the components of the allocation rule. With the same candidate pool, anchor budget, reconstruction, answer model, and judge, relevance-only selection reaches 73.0%. Adding diversity alone ( R + D) reaches 70.0%, adding coverage alone ( R + C) reaches 73.0%, while the combined R + D + C rule reaches 77.0%. The diversity and coverage terms are recomputed against the evolving selected set rather than applied as fixed per-turn scores. We further test whether the combined rule needs to control the full anchor budget. The protected-coverage and protected-D + C variants reach 72.0% and 73.0%, respectively, compared with 73.0% for relevance-only selection. Neither reproduces the 77.0% accuracy of C OD, where relevance, diversity, and coverage jointly influence all 60 anchor decisions. A gold-informed allocator reaches 78.0%, one point above C OD, but it directly uses gold evidence identities and is not deployable; we therefore use it only as a reference. Together, these controls indicate that the diagnostic improvement is not reproduced by applying di-versity or coverage only after a relevance-ranked prefix has been fixed. The full set-aware rule allows the three signals to interact throughout anchor allocation. The corresponding matched comparison over all 1,986 questions gives a +1.86-point gain with a conversation-cluster 95% CI of [0.59, 3.15] (Section 4). 5.3 CANDIDATE AVAILABILITY LEAVES AN ALLOCATION OPPORTUNITY 

Figure 2(c) tracks the 142 dataset-provided gold evidence items before reconstruction. The candidate pool contains 125 items (88.0%); 84 become anchors, 41 are available but not selected, and 17 are absent from the pool. Among the 58 items not selected as anchors, 41 (70.7%) are therefore already visible to the allocator. 8Preprint This leaves a substantial allocation opportunity: most gold items missed at the anchor stage are present in the candidate pool rather than unavailable to retrieval. At the same time, 17 gold items remain absent from the pool. These are anchor-stage counts, not final-context misses or answer errors, since reconstruction can still restore an unselected turn as a neighbor of another anchor. 5.4 ADAPTIVE EVIDENCE ACQUISITION 

Figure 2(d) evaluates the adaptive gap-directed acquisition variant using selection-level evidence coverage. Starting from the same initial configuration, iterative acquisition improves Gold Re-call@60 from 85.2% to 86.6% and Full-Gold Coverage from 84.0% to 87.0%. The procedure maintains a temporary evidence state and acquires additional anchors when unresolved evidence gaps remain, while keeping the candidate pool fixed. These results show that additional query-time acquisition can improve evidence coverage without modifying the persistent memory. They are reported only as selection-level diagnostics: the end-to-end accuracy results in Section 4 use the fixed-budget pipeline without the iterative loop. ## 6 CONCLUSION 

We introduced Chain on Demand (C OD), a query-time evidence construction framework that pre-serves the original conversational record and organizes evidence only after the information need is known. Given a broad candidate pool, C OD allocates a fixed anchor budget with set-aware greedy scoring and then reconstructs the original same-session context around the selected locations, form-ing a temporary evidence chain without modifying persistent memory. On LoCoMo, changing only the allocation rule improves accuracy from 74.5% to 76.3% over all 1,986 questions (+1.86 points; conversation-cluster 95% CI [0.59, 3.15]). The development anal-yses further show the complementary roles of set-aware allocation and source-context reconstruc-tion, while the LongMemEval-S results demonstrate that the same query-time evidence construction framework transfers to a second long-term memory benchmark. Together, these results support de-ferring evidence organization until the query is known, rather than committing the organization of conversational history in advance. 

## 7 LIMITATIONS 

Our evaluation has several limitations. First, the 100-question LoCoMo development subset is con-tained in the full 1,986-question evaluation, so the component analyses are development diagnostics rather than independent held-out estimates. Second, the answer model and judge are fixed to GPT-4o-mini in the reported runs; other models and evaluators remain untested. Third, LongMemEval-S does not include a matched relevance-only allocator ablation, so its results support applicability across benchmarks rather than an independent estimate of the allocator’s effect. The current configuration also fixes the candidate pool at 200 turns, the anchor budget at 60, and the reconstruction window at two turns on each side. We do not systematically study how these choices scale with longer histories or different evidence budgets. Query-time construction addition-ally incurs higher prompt-token and construction costs than Dense-60 in our measurements. Finally, reconstruction is limited to local same-session context and does not explicitly model long-range temporal dependencies or cross-session links.

On the fixed 100-question diagnostic set, iterative acquisition increases Gold Recall@60 from 85.2% to 86.6% and Full-Gold Coverage from 84.0% to 87.0% relative to the fixed-budget base selector. We additionally report an offline gold-informed planner as a reference. This planner directly uses gold evidence identities to guide selection within the candidate pool and is therefore not deployable. It reaches 90.8% Gold Recall@60 and 90.0% Full-Gold Coverage. These results are selection-level diagnostics rather than end-to-end generative evaluation. They indi-cate that unresolved evidence gaps can provide useful signals for reallocating a fixed anchor budget, but they do not establish an answer-accuracy improvement from adding an iterative agent loop to the complete memory system.
