## 摘要
诸如 DiskANN 之类的磁盘驻留图索引将每个向量及其图边作为一条记录存储在 SSD 页上。一次搜索需要读取其所扩展的每条记录所在的页，因此其页读取次数取决于页面布局，即哪些记录共享同一页。使用强化学习训练的搜索智能体会反复查询这样一个索引，并且每次图遍历都可以连同其扩展的记录一起被记录到日志中。因此，我们利用一次已完成运行的日志，在给定的内存预算下为索引布局，从而使后续运行读取更少的页。相比之下，Starling 和 MARGO 等现有布局仅根据图和向量计算得到，不使用日志。从日志中学习布局具有挑战性，因为日志必须在每种布局下都保持有效，节省量取决于预算所缓存的内容，并且寻找最优布局是 NP 难的。我们的关键观察是：DiskANN 风格的搜索依据内存中的编码及其所扩展的记录进行路由，而从不依赖这些记录的同页记录。因此，记录的遍历可以通过重放为每种布局评估代价，而缓存中的记录不会增加页读取。据此，我们提出 HyperPage：它首先基于未缓存记录的日志遍历，为给定预算构建布局。然后，它通过重放验证步骤，选择一种布局，以及热记录与页缓存之间的预算划分。此外，拉格朗日下界可表明某种布局可能距离最优解有多远。我们在一次 Search-R1 智能体运行上学习，并在随后一次具有不同奖励的运行上测试，覆盖 100 万和 2100 万条段落。在七种缓存预算下，HyperPage 的页读取次数比 MARGO 少 5.2% 至 21.2%，且没有其他对比布局的页读取更少。当缓存较小时，优势最大。例如，在 100 万索引的 1% 缓存下，MARGO 需要接近 3 倍的预算才能读取同样少的页。在 2100 万索引上，HyperPage 还将每步搜索时间最多缩短 10.4%。这种节省在第二个智能体模型和第二个语料库上依然成立。

## Abstract
Disk-resident graph indexes such as DiskANN store each vector with its graph edges as one record on SSD pages. A search needs the page of every record it expands, so its page reads depend on the page layout, that is, which records share a page. Search agents trained with reinforcement learning query one such index run after run, and every graph traversal can be logged with the records it expands. We therefore use the logs of a finished run to lay out the index for a declared memory budget, so later runs read fewer pages. In contrast, existing layouts such as Starling and MARGO are computed from the graph and vectors and use no logs. Learning a layout from logs is challenging, because the logs must stay valid under every layout, the saving depends on what the budget caches, and the best layout is NP-hard to find. Our key observation is that DiskANN-style search routes on in-memory codes and the records it expands, never on their page-mates. As a result, the logged traversals price every layout by replay, and cached records add no page reads. Accordingly, we propose HyperPage, which first builds layouts for the declared budget on the logged traversals of uncached records. It then selects one layout, together with the budget split between hot records and a page cache, by replaying validation steps. In addition, a Lagrangian lower bound shows how far a layout may be from the optimum. We learn from one Search-R1 agent run and test on a later run with a different reward, over 1M and 21M passages. Across seven cache budgets, HyperPage reads 5.2% to 21.2% fewer pages than MARGO, and no compared layout reads fewer. The advantage is largest when the cache is small. For example, at 1% of the 1M index, MARGO needs nearly 3 times the budget to read as few pages. On the 21M index, HyperPage also cuts search time per step by up to 10.4%. The saving holds for a second agent model and a second corpus.

# HyperPage 论文结构化总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：DiskANN 类磁盘驻留图向量索引把"向量 + 邻接表"作为一条记录存放在 SSD 页上（每页 B 条记录），一次 beam search 需要读取它扩展的每个节点所在的页。因此**页布局**（哪些记录共享同一页）不改变搜索结果，却直接决定 SSD 页读取次数，是向量数据库的物理设计决策；在 DRAM 相对索引很小时（例如 64 GB 内存 vs 683 GB 索引）尤为关键。
- **现有方法的空白**：Starling、MARGO、RCM、VeloANN、SHP、Mt-KaHyPar 等布局只依赖**图结构与向量**，不使用查询日志；LSM-VEC 的热图仅使用部分查询信息；工作负载超图划分把请求视为独立查找。它们都无法回答"更好的布局还能省多少"。
- **论文动机**：使用强化学习训练的搜索智能体（如 Search-R1 + GRPO）会成百上千次地查询同一索引，且后续运行与训练运行**遍历高度重叠**（测试中一个 rollout group 83.9% 的节点扩展是重复的）。这些遍历可以被完整记录，且由于 DiskANN 路由只依赖内存 PQ 码和已扩展记录的邻接表、**从不依赖同页记录**，日志在任意布局下都有效。
- **核心问题**：能否利用一次已完成运行的日志，在给定 DRAM 预算下重新布局索引，使后续运行读更少的页？挑战有三：
  1. 日志必须在每种候选布局下保持有效（page search 会破坏这一点）；
  2. 节省量取决于缓存内容与预算划分；
  3. B≥3 时最优布局是 NP 难的，且 swap 搜索可能停滞在 B/2 倍最优。
- **整体含义**：把"日志驱动的布局优化"转化为一个**可精确重放验证**的优化问题，为 SSD 图索引提供一条可度量、可审计的读放大降低路径。

## 2. 方法论

### 2.1 核心思想

- **关键观察**：DiskANN 式搜索的扩展集 $e_q$ 只由 $(q, G, L, W)$ 与 PQ 码决定，与布局 $\pi$、缓冲区内容无关（假设 A1）；引擎只读扩展节点所在页、不预取（A2）、冷启动（A3）、作用域内页只读一次（A4）。因此**一次运行的日志可以为每种布局精确标价**，且被缓存记录不产生页读取。
- **总体流程（图 2 六组件）**：日志采集 → 作用域超图构建 → 精化 → 按预算选择布局与缓存划分 → 重放定价 → 下界审计。

### 2.2 关键技术细节

**(1) 作用域超图与目标函数（问题 1）**
- 每个作用域 $\sigma$（一个 group / request / step 等）有并集 $E_\sigma = \bigcup_{q\in\sigma} e_q$，合并重复并归一化权重 $\omega_E$，构成超图 $H=(V,E,\omega)$。
- 目标（SET 目标）：
$$F_{conn}(\pi)=\sum_{E\in\mathcal{E}}\omega_E\big(\lambda_\pi(E)-1\big),\quad \lambda_\pi(E)=|\pi(E)|$$
即最小化"页连通度"，等价于读一次作用域缓冲区的页数。

**(2) 成本模型（Lemma 1 / Corollary 1）**
- 在 A1–A3 下，$E_{buf}$ 对每条子查询读 $IO_{buf}(\pi;q)=\lambda_\pi(e_q)$ 页，且 $\lceil|e_q|/B\rceil \le \lambda_\pi(e_q) \le |e_q|$，无引擎能读更少。
- 在 A1、A2、A3、A4 下，作用域缓冲读 $\lambda_\pi(E_\sigma)$ 页，且与到达顺序无关；$D \ge \lambda_\pi(E_\sigma)$ 的私有 LRU 读页数不变。
- 结论：**日志遍历可精确等价为每种布局的读页数**，无需真正运行引擎；并据此解释为何 page search（$E_{ps}$）和 PipeANN 等不满足 A1。

**(3) 目标函数族与精确增益（第 V、VI-B 节）**
- 定义 SET（$F_{conn}$）、CLQ（clique 展开）、ARC（限制在弧上）、P05（SHP 概率 fanout 在 $\theta=0.5$）。
- 命题 1：$F_{w^{clq}}(\pi)=g(\pi)+\Omega(\pi)$，其中 $g$ 是线性页节省，$\Omega\ge 0$ 是"集中度奖励"，仅当某页容纳某集合 ≥3 个成员时非零。
- 命题 2：$g(\pi)\le F_{w^{clq}}(\pi)\le \frac{\bar b}{2}g(\pi)$，clique 目标是精确节省的 $2/\bar b$ 松弛。
- 命题 4：逐查询目标可能错失跨查询复用，因此 HyperPage 训练于**作用域并集**。
- 移动与交换的精确增益公式（式 4、5）只需更新包含被移动记录的集合计数。

**(4) 精化算法（Algorithm 1）**
- 从现有布局（默认 MARGO 页序）出发，按随机节点序做**严格下降**：候选页为超边内前 32 个共现记录所在页 + 图邻居在训练超边内的页，取共现最多的 $\bar p=16$ 页；只在 $\Delta F<0$ 时应用最佳移动/交换，不走上坡、不回滚。
- 单趟复杂度 $O(\bar p B(nnz+n\,deg_{max}))$；命题 9 保证 $F(\pi)\le F(\pi_0)$，训练作用域平均读页数不增。

**(5) 缓存感知精化与预算选择（第 VI-D 节）**
- 混合缓存 $H_{D,\rho}$：$\lfloor\rho D\rfloor$ 页用于静态热记录缓存（训练频率最高的 $B\lfloor\rho D\rfloor$ 条记录），其余构成共享 LRU 页缓存；$\rho=0$ 退化为纯 LRU，$\rho=1$ 时所有布局读页数相同。
- Corollary 3：固定记录缓存下，作用域读 $\lambda_\pi(E_\sigma\setminus C)$ 页，与放置位置无关——因此**缓存感知精化在残差并集 $E\setminus C$ 上运行**，缓存记录不参与移动、只作交换空位；另有冻结训练并集外记录的变体 ARC-CF。
- 选择：对每个候选布局与 $\rho$ 网格（0, 0.1, 0.25, 0.5, 0.75, 0.9, 1）在新运行的**验证步骤**上按部署到达序重放，取验证读页最少者，并列时保留 incumbent；因此选中者不会比 incumbent 在同一预算下更差。

**(6) 重放下界与可保证性（第 V、VI-E 节）**
- 表 I 给出各种布局的最坏读页倍数：任意布局 $\le B R^\star$（紧）、swap 局部最优可达 $\frac{B}{2}R^\star$、最大权匹配 $\lceil B/2\rceil R^\star$、精确 fanout 最小化 $\le (2-2^{1-B})R^\star$；B≥3 时 NP 难且 APX 难。
- 命题 7：逐 incidence 的拉格朗日松弛给出对**所有布局**有效的下界，用度类 + 投影次梯度求解。
- 命题 8：共享 LRU 下无 B 的比值界，但给出窗口下界。

**(7) 重放引擎**
- 对 stock DiskANN 打补丁，保持记录格式、PQ 码、入口点不变；作用域缓冲为 page→slot 哈希表，扩展节点分 hit / shared read / miss 三类；热记录进入 DiskANN node cache，其余经共享 LRU 页缓存；重放结果与真实引擎在 1M 验证步骤上**逐页一致**。
