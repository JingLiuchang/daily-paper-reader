ABSTRACT
Vector databases rely on Hierarchical Navigable Small World
(HNSW) indexes for similarity search, but a graph built from
data alone can be poorly matched to a skewed or changing query
workload. We present REWEAVE (Reward-Guided Rewiring
of Vector Graphs), an online index-maintenance method that
learns edge utility from query feedback and periodically rewires
the bottom layer within the original per-node degree cap. The
method supports sparse exact-neighbor feedback combined
with self-labels, and standard HNSW serving without learning
overhead once adaptation is disabled.
Under explicit assumptions we prove value-estimation and
graph-stabilization guarantees. Under stationary skew, REWEAVE
improves held-out recall by up to 23.3 percentage points over
HNSW. In comparisons with query-aware baselines on up to
100M vectors, it achieves up to 3.3× NGFix’s query throughput at
recall@100 of 0.80. On Amazon-ESCI with query drift, it increases
stream recall@100 from 0.745 to 0.979 with 34% fewer search
distance computations than frozen HNSW. These results illustrate
the potential to improve retrieval quality and reduce search
effort within an existing graph-degree budget, while incurring
additional work during adaptation.

INTRODUCTION
Approximate nearest-neighbor (ANN) search underpins vector
databases [40], retrieval-augmented generation [27], recom-
mendation [12], and similarity joins [33]. Graph indices lead
the recall-latency frontier; HNSW [35] routes queries through
progressively denser proximity-graph layers. These indices
are built from the corpus alone, although the query workload
determines which edges are useful.
Workload-adaptive [19] and workload-optimized database
systems [39, 41] adapt physical design to the queries they serve.
Learned indices such as ALEX and the PGM-index similarly
demonstrate the value of updatable, learning-augmented struc-
tures [11, 13]. For graph ANN, this motivates using query feedback
to decide which edges occupy the index’s degree budget.
Query workloads can differ substantially from the indexed data.
Under stationary skew, a fixed, nonuniform query distribution con-
centrates on a small region of the data manifold [9, 21]. A retrieval-
augmented generation system, for example, may index an entire
knowledge base but serve many queries about a few topics. Un-
der drift, interests move the query mass over time, and previously
useful edges can lose value. In both regimes, a corpus-built graph
may spend its degree budget on rarely traversed edges while miss-
ing useful links, reducing recall or increasing search effort.
Adding edges incurs storage, distance-evaluation, and cache
costs. We therefore keep the per-node out-degree cap 𝑀fixed

Our analysis separates learning to navigate a given graph from
discovering and selecting its edges. This distinction connects adap-
tation cost to the supply of useful candidates, while our evaluation
measures recall and serving cost under stationary skew and drift.
We propose REWEAVE (Reward-Guided Rewiring of Vector
Graphs), which learns to reallocate a fixed per-node degree budget
to the query workload while serving queries. REWEAVE treats
navigation as an online learning problem: each outgoing edge is
a possible search move, whose reward measures its usefulness
on the query. We call this adaptive procedure the learner: it
chooses search moves, updates edge scores from query feedback,
and selects edges at rewiring batches. It executes a five-step
loop (Figure 2): navigate, assign reward, update values, collect
candidates, and rewire.

STEP 1: NAVIGATION
Step 1 (Algorithm 1, lines 4–12) uses the current graph and scores
to return an answer and the search records used by Steps 2–4. Nav-
igation favors high-reward edges while testing uncertain alterna-
tives: an early low estimate can otherwise prevent a useful edge
from receiving more feedback. We use 𝜖-greedy or UCB ranking,
following the first distance-improving edge in either order. Strict
distance improvement prevents cycles. The optional beam variant
(§4.3) explores several routes at a time.
4.1
𝜖-greedy Ranking
For query 𝑡, let b
𝑄𝑡−1(𝑢, 𝑣) be the score of edge (𝑢, 𝑣) computed
from earlier feedback (updates are in §5.4). Let 𝜖𝑡∈[0, 1] be the
exploration probability. At each visited node, with probability 1−𝜖𝑡,
order its out-edges by decreasing score, breaking ties by distance to
the query and then ID. With probability𝜖𝑡, use a uniformly random
order instead. Either way, follow the first edge whose destination
is closer to the query than the current node; stop if none exists.
We use 𝜖𝑡= min{1,𝑐𝜖/√𝑡}, where 𝑐𝜖> 0 controls the amount
of exploration. Random ordering becomes less frequent as more
queries arrive. Each visited node makes a fresh independent choice
using the same 𝜖𝑡for that query. Random ordering treats all im-
proving edges equally, giving each an exploration-selection proba-
bility of at least 𝜖𝑡/𝑀at that visit. Repeated sampling also requires
queries to visit the node while the edge is present and improving.

4.3
Beam Navigation (Width 𝑊)
The single-path walk commits to one next node at each step. Beam
navigation is an optional training variant that keeps several search
routes active, allowing a query to explore different parts of the
graph and collect feedback on more edges. The frontier is the set of
visited nodes whose out-edges are ranked at the current step. The
beam width 𝑊is the maximum number of nodes in this set.
In the experimental variant, each frontier node proposes its
top-𝑏distance-improving neighbors under the chosen ranking
rule. Here 𝑏is the branch factor, which limits proposals from one
node. We pool and rank these proposals, then accept up to 𝑊
destinations to form the next frontier. Each destination node is
accepted at most once per query: if several frontier nodes propose
the same neighbor, only one proposal is accepted, avoiding

repeated work and duplicate credit. For example, with 𝑊= 4 and
𝑏= 2, a full frontier proposes at most eight edges, from which at
most four distinct destinations form the next frontier.
A wider beam gathers feedback along more routes at the cost
of extra distance evaluations. §10.2 compares UCB with 𝑊= 1
and 𝑊= 64 to measure the recall effect. This choice affects train-
ing navigation; frozen serving uses standard HNSW on the learned
graph.
The beam analysis uses all improving out-edges to unvisited des-
tinations, applying the per-source cap 𝑏during acceptance instead
of truncating proposals before pooling. Its guarantees concern this
variant, with at most 𝐻total acceptances per query; §8 identifies
the scope of the extended analysis.

The recall reward gives an edge credit for participating in a search

RELATED WORK
HNSW [35], NSG [14], and disk/memory hybrids such as
DiskANN [49], SPANN [10] and HM-ANN [45] are the domi-
nant vector search indices; surveys confirm their lead on the
recall–latency frontier [34, 51]. All build the graph from the
data alone and do not revisit it for the query workload. Learned
indices [11, 13, 23] apply learning to other access patterns.
Workload-adaptive databases have transformed modern data
management [8, 20, 43]. These include cost-driven index selection
and "what-if" optimization utilities [6, 7, 52].
Methods that tune ANN search behavior [28, 38] modify traver-
sal path rather than the topology. Several query-aware approaches
build graphs from sampled queries before deployment [9, 18, 21,
47]; query-hardness measures [53] guide such construction. OOD-
DiskANN [21] and CDMG [56] adapt an entire index to an out-of-
distribution query workload, but build it as a whole rather than
updating the graph incrementally as queries arrive.
NGFix [17] guides graph repairs around difficult queries and
supports online graph construction. CORAL [50] incrementally
constructs cross-modal graphs via coverage-aware adaptive
pruning, Fully Neighborhood-Aware Projection (FNAP), and
targeted connectivity enhancement. REWEAVE learns edge
values from exact/self feedback to select candidates within a
fixed degree budget. Streaming indices [31, 48, 54, 55] maintain
the graph under data insertion and deletion, an orthogonal
form of dynamism. Filtered ANN [16, 42, 58] adapts to predicate
constraints, not query workloads.
Reinforcement learning has been applied at the retrieval appli-
cation layer (query reformulation [37]); routing on a proximity
graph has been learned for recommendation [12] and made proba-
bilistic [32], but these choose among existing edges rather than re-
allocating the degree budget, and offer no regret guarantee. Mean-
while, we utilize stochastic approximation [24, 46], finite-armed
bandits and the UCB1 analysis [2, 25, 26], sleeping bandits, where
only a changing subset of choices is available at each decision [22],
and switching/non-stationary bandits [3, 4, 15].
12
CONCLUSION
Under retained evidence, conditional-mean control, and candidate
coverage, the learned graph stabilizes at a reward-specific
value-greedy graph. Our regret bounds distinguish routing error
from graph mismatch. Mixed-feedback estimation further gives
sufficient bias and margin conditions for agreement with the
exact-reference graph. Future work will focus on extending
this framework for disk resident indexes which raise important
challenges for IO optimizations.
