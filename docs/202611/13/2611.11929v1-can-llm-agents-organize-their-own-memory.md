## 摘要
在大多数LLM智能体中，权重在部署后是固定的，因此新信息必须保留在外部记忆中。现有方法通常依赖预定义的记录和固定的组织规则，难以适应不断变化的任务和交互。这引出了一个问题：LLM智能体能否使用普通文档来组织自己的记忆？我们提出了自组织记忆（SoMem），这是一个将记忆存储在相互链接的文档中的框架。智能体决定总结什么、如何对相关信息进行分组，以及何时修订现有主题，并且其生成的每个摘要都保持与原始交互的链接作为证据。运行时验证更新，并自动从组织后的内容中派生时间、关系和近期记忆视图。在查询时，智能体选择搜索和阅读的内容，按需沿着文档链接并检查原始证据。在LoCoMo、BEAM-100K和LongMemEval-S上，SoMem分别比最强基线高出2.66、3.10和2.00个百分点。所构建的记忆可以跨模型复用，额外的推理投入可以进一步提高答案质量。这些发现证明了智能体通过普通文档组织和利用自身持久记忆的可行性。代码见：https://github.com/Qi202/SoMem。

## Abstract
In most LLM agents, weights are fixed after deployment, so new information must be retained in external memory. Existing approaches often rely on predefined records and fixed organizational rules, which cannot readily accommodate evolving tasks and interactions. This raises the question: can LLM agents organize their own memory using ordinary documents? We introduce self-organized memory (SoMem), a framework that stores memory in linked documents. The agent decides what to summarize, how to group related information, and when to revise existing topics, and every summary it produces stays linked to the original interactions as evidence. The runtime validates updates and automatically derives temporal, relational, and recent-memory views from the organized content. At query time, the agent chooses what to search and read, following document links and inspecting original evidence as needed. On LoCoMo, BEAM-100K, and LongMemEval-S, SoMem outperforms the strongest baseline by 2.66, 3.10, and 2.00 percentage points, respectively. The constructed memory can be reused across models, and additional reasoning effort can further improve answer quality. These findings demonstrate the feasibility of agents organizing and using their own persistent memory through ordinary documents. Code is available at: https://github.com/Qi202/SoMem.

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体部署后模型权重通常固定，新获得的用户偏好、任务进度、环境变化等信息只能写入外部记忆。外部记忆使智能体能够跨会话保持个性化、延续任务并利用经验。
- **现有方法的问题**：
  - 多依赖预定义记录结构、固定组织规则或固定检索流程，难以适应不断变化的任务和交互。
  - 完整保存历史可保留细节，但检索负担大；压缩记录可降低阅读成本，却可能丢失限定条件、上下文和证据。
  - 新交互可能修订旧事实、连接不同事件或改变陈述有效时间，因此记忆系统既要支持简洁访问，也要能回溯原始证据。
- **核心研究问题**：LLM 智能体能否使用普通文档自主组织自己的持久记忆，并在修订语义组织的同时保持证据可追溯、访问结构一致？
- **整体含义**：论文提出 **SoMem（Self-Organized Memory）**，让模型负责“如何总结、如何分组、何时修订”的语义组织，运行时负责验证证据引用并自动重建时间、关系和近期视图。其意义在于把记忆从“预定义数据库”推进为“智能体可编辑、可复用、可追溯的文档工作区”。

## 2. 方法论

### 2.1 核心思想

- 记忆以**可编辑的 Markdown 链接文档**表示；模型是语义组织者，运行时是结构一致性的保证者。
- 原始交互被归档为**不可变 Source 证据**；模型据此创建和修订 **Topic 文档**；再从 Topic 中提升少量长期偏好和常需背景形成有容量限制的 **Core**。
- 运行时从 Topic 自动派生 **Graph、Timeline、Recent** 三类访问视图，避免模型为每种访问方式分别维护一份表示。

### 2.2 记忆结构

- 更新流程可概括为：
  - \(S_t = \mathrm{Append}(S_{t-1}, x_t)\)
  - \((T_t, C_t) = \mathrm{Organize}(S_t, T_{t-1}, C_{t-1})\)
  - 其中 \(S_t\) 为不可变 Source 记录，\(T_t\) 为 Topic 文档集合，\(C_t \in T_t\) 为容量受限、始终进入上下文的 Core。
- 每个记忆单元表示为：
  - \(u_i = (b_i, c_i, E_i, L_i)\)
  - \(E_i = \{(s_{ij}, \tau_{ij}, R_{ij})\}_{j=1}^{n_i}\)
  - \(b_i\) 为稳定段落标识，\(c_i\) 为段落文本，\(L_i\) 为跨文档链接；每个证据标注把陈述片段 \(s_{ij}\) 与事件时间 \(\tau_{ij}\) 和 Source 引用 \(R_{ij}\) 关联。
- Markdown 中用脚注记录时间和来源，用段落标识支持跨文档引用；Topic 可创建、更新、合并、移动段落或提升内容到 Core。

### 2.3 更新验证与安装

- 所有编辑先进入**暂存状态**，由运行时检查：
  - Source 是否保持不可变；
  - Topic 段落结构是否符合约定；
  - Source 引用和文档链接是否可解析；
  - 时间值是否合法；
  - 路径是否位于工作区内；
  - Core 引用与容量是否满足限制。
- 通过后原子安装、修复相对链接，并重建 Graph、Timeline、Recent 和文件清单；拒绝则保留旧状态。
- 支持周期性重组已变更 Topic，以及可选的最终全量重组；二者复用同一“提议—验证—安装”路径。

### 2.4 自动派生访问视图

- \(G_t = \mathrm{Graph}(T_t)\)：以记忆单元为节点，以段落引用为有向边，生成出链和反链索引。
- \(L_t = \mathrm{Timeline}(T_t)\)：按事件时间将陈述分组到 `timeline/YYYY.md`、`YYYY/MM.md`、`YYYY/MM/DD.md`，保留 Source 引用。
- \(R_t = \mathrm{Recent}_K(T_t)\)：按记忆单元创建顺序选取最近 \(K\) 个单元，进入初始查询上下文。
- 最终记忆状态为 \(M_t=(S_t,T_t,C_t,G_t,L_t,R_t)\)。

### 2.5 查询时检索

- 智能体获得 Core、Recent、文件清单和问题日期，可使用只读工具集 \(F=\{\mathrm{Search},\mathrm{List},\mathrm{Read}\}\)：
  - 内容搜索支持 BM25 词法检索或稠密语义检索，可选路径和时间过滤；
  - 文件列表与读取支持定位文档、查看行范围；
  - 可沿 Topic 链接、Graph 反链、Timeline 日期和 Source 引用继续检查原始证据。
- 查询与回答共享同一轨迹：\(y=\mathrm{Agent}(q;M_t,F)\)。智能体不被强制按固定顺序检索，可多次搜索、阅读和回溯证据。

## 6. 主要发现与结果

- **主实验表现**：在 LoCoMo、LongMemEval-S 和 BEAM-100K 三个 benchmark 上，SoMem 整体优于 Full Context 及 A-Mem、Mem0、MemoryOS、Nemori、LightMem、E-mem 等记忆基线，尤其在多跳推理、知识更新、时序推理和矛盾消解等需要跨会话整合与修订的任务上优势更明显。
- **记忆组织的价值**：消融显示，移除 Topic 组织、Core 提升或派生视图后性能下降，说明“模型自主总结与分组 + 运行时结构保障”的组合对长时记忆有效；但部分组件（如 Core、某些视图）的单独贡献在采样波动范围内，需结合重复实验判断。
- **证据可追溯性的作用**：Source/Topic masking 对照表明，保留不可变 Source 并允许回溯原始证据，有助于处理需要精确细节、时间限定和冲突消解的问题；仅依赖压缩后的 Topic 会损失部分可验证信息。
- **访问结构一致性**：Graph、Timeline、Recent 由 Topic 自动派生，使智能体能够在不同查询路径间切换，而不必为每种访问方式维护独立表示；这降低了组织负担，并保持链接、时间与来源引用的一致。
- **跨模型复用**：Writer–Reader 组合实验显示，由一个模型构建的记忆可被其他 Reader 模型使用，性能随 Reader 能力提升而改善，说明 SoMem 的记忆表示具有一定模型无关性和可迁移性。
- **推理投入缩放**：增加 Reader 的 reasoning effort 或多轮检索通常带来性能提升，但收益存在边际递减；不同任务类型对检索深度和推理投入的敏感度不同。
- **成本与延迟**：SoMem 的构建成本显著高于轻量基线，查询成本较低但调用次数和延迟较高；缓存命中可明显降低实际费用。整体呈现“前期构建投入较高、查询阶段可复用”的成本结构。
- **长历史补充**：BEAM-1M 实验表明方法可扩展到更长历史，但随着记忆规模增长，组织、验证和检索的开销与噪声也会上升。

## 7. 局限与可复现性

- **算力信息缺失**：未报告 GPU 型号、数量与运行时长，难以精确估计复现所需硬件资源；虽然方法不涉及训练，但大规模构建与多轮查询的推理成本较高。
- **成本公平性**：SoMem 使用智能体控制的多轮搜索，基线与 SoMem 的检索预算、调用轮数和自主性不完全一致；缺少同等 token/调用预算下的对照，性能收益可能部分来自更高预算。
- **消融范围有限**：组件消融主要在 LoCoMo 上进行，且多为单次运行；冻结记忆的消融只改变查询时可访问组件，不能完全反映“移除组件后重新构建记忆”的效果。
- **依赖 LLM Judge**：主要指标依赖 GPT-4o-mini 作为评判模型，可能引入评判偏差；BEAM 的 rubric 评分虽更细粒度，但仍依赖评判标准与提示设计。
- **运行时约束的完备性**：验证机制主要检查结构、引用、时间和路径等形式约束，难以保证语义正确性、事实一致性和组织质量；错误总结一旦通过验证仍可能进入记忆。
- **可扩展性**：随着 Source 与 Topic 增长，重组、链接修复和视图重建的开销上升；论文未充分讨论超大记忆下的索引维护与冲突解决策略。
- **任务覆盖**：benchmark 以对话记忆为主，对工具使用、多智能体协作、长文档和多模态等场景的适用性仍需验证。

## 8. 结论与启示

- **核心贡献**：论文将持久记忆建模为“智能体可编辑的 Markdown 文档工作区”，把语义组织交给模型，把结构一致性、证据验证和视图派生交给运行时，形成“提议—验证—安装”的闭环。
- **设计启示**：
  - 记忆系统应区分**不可变证据层**与**可修订组织层**，以兼顾压缩访问与证据追溯。
  - 语义组织与结构维护应解耦：模型负责“记什么、如何分组、何时修订”，系统负责“引用是否有效、结构是否一致、视图是否同步”。
  - 多种访问视图可由同一组织层自动派生，避免多份表示之间不一致。
- **实践意义**：SoMem 提供了一种可落地的高成本、高可控记忆方案，适合对个性化、任务连续性和证据追溯要求较高的智能体应用；对成本敏感场景，可结合缓存、轻量 Writer 或按需重组降低开销。
- **未来方向**：在同等预算下比较记忆机制、引入语义级验证与冲突检测、支持增量索引与更大规模记忆、扩展到多模态与多智能体场景，以及建立更细粒度的错误分析体系。
