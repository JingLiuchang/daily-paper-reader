# Accept Changes, Reject Attacks: Robust Memory Management for LLM Agents 

Runze Zhao 1, Dongruo Zhou 1, Sumit Kumar Jha 2, Nathaniel D. Bastian 3, Ankit Shah 1*1Indiana University Bloomington 2University of Florida 3United States Military Academy

Abstract 

Since large language model (LLM) agents rely on long-term memory, what they store now shapes what they do later. A memory man-ager decides how each input changes this mem-ory and which records the agent acts on. It can fail in two ways: keeping a fact that has since changed (outdated memory), or storing a planted passage or injected instruction (mem-ory poisoning). Most prior work studies them separately, yet they call for opposite write deci-sions, so no fixed write rule handles both. We therefore formalize memory robustness as han-dling both without doing worse on other inputs. Since accuracy checks only the answer, we measure robustness with evidence-conditioned accuracy (ECA), which also checks that the records the manager selects include all the ev-idence the answer needs, updated and free of attacks. However, existing memory systems and defenses are not more robust than an un-tuned manager on our test sets. We improve robustness with a simple one-shot recipe that fine-tunes the manager on episodes synthe-sized around a single conversation with inserted changes and attacks. On three backbones, it im-proves every category score on our test sets and more than doubles the untuned manager’s overall ECA, though robustness remains incom-plete. 

1 Introduction 

Large language model (LLM) agents keep a long-term memory outside the context window, so that what they learn in one session is available in later ones. A personal assistant, for example, remembers facts and preferences about its user (Packer et al., 2023; Zhong et al., 2024). In such agents, a mem-ory manager decides for each new input whether and how the memory should change, and which stored records the agent acts on (Chhikara et al., 2025; Xu et al., 2025; Yan et al., 2026). Every write

and every selection thus affects what the agent does later. Yet the inputs come from many sources, not all of them under the agent’s control. As Figure 1 shows, a write can go wrong in two ways. In outdated memory , a fact has changed but the memory keeps the old value (Chao et al., 2026); in Figure 1a, the user has moved to a new city. In memory poisoning , an attacker uses one of these inputs to place content in memory that should never be there (Greshake et al., 2023; Dong et al., 2025), such as the injected instruction in Figure 1b. Every memory manager may face both problems, and they call for opposite write decisions. Following a change requires writing the new input, while keeping out an attack requires not writing it, so no fixed write rule handles both. We therefore distinguish three categories of input. An input is in the outdated category if its speaker reports a change to a stored fact about themselves, which makes the stored record outdated. Poisoning inputs carry an attack, and all other inputs are standard .Most prior work evaluates each problem on its own, and a trivial manager can pass each such eval-uation. Memory benchmarks contain no attacks, and managers trained on them never see one (Wu et al., 2025; Chao et al., 2026; Yan et al., 2026), so a manager that writes every input scores high while storing every attack. Evaluations of poison-ing and injection defenses check standard inputs, not whether changes to stored facts are still written (Wei et al., 2026; Chen et al., 2025a; Wallace et al., 2024; Li et al., 2025), so a manager that never changes a stored fact scores high while missing every change. No widely used benchmark covers both problems. We therefore formalize memory robustness over all three categories, so that a gain in one category cannot hide a loss in another. Mea-suring it also needs a new metric, since accuracy (ACC) checks only the answer, not the memory it is based on. Unlike prior one-sided formulations, ours cov-ers all three categories equally; a manager is more robust than another if it is no worse in any category and better in at least one. We mea-sure each category with a new metric, evidence-conditioned accuracy (ECA), which counts an answer only if it is correct and the records the manager selects include all the evidence it needs, updated and free of attacks. • A simple one-shot data synthesis recipe. To improve robustness under this definition, we synthesize training data around a single conver-sation of an existing dataset. We insert the fact changes and memory attacks studied in prior benchmarks into this conversation and train the manager on the resulting episodes with plain su-pervised fine-tuning (SFT). One conversation is enough because it stays fixed while the inserted turns differ in whether and how they should change memory, so the manager learns this deci-sion rather than the conversation. Turns whose correct write can be predicted from surface cues such as word overlap or position are discarded. • Experiments. Across three backbones, SFT raises ACC and ECA in every category of our test sets over the untuned manager (the same backbone before fine-tuning) and lowers the at-tack success rate (ASR). Since ECA also checks the selected records, these gains show that train-ing improves which records the manager stores and selects, not only the answers. SFT is the only method that raises ECA in all three cate-gories, while each memory system and defense we compare falls below the untuned manager in at least one. On Qwen3-4B, SFT also raises ECA on all eight benchmarks, five of them un-seen in training. 

2 Related Work 

Memory managers for LLM agents. Memory managers are either prompted, as in Mem0 and A-Mem (Chhikara et al., 2025; Xu et al., 2025), or trained, as in MemLLM, Memory-R1, Mem-α,AgeMem and TrustMem (Modarressi et al., 2025; Yan et al., 2026; Wang et al., 2025b; Yu et al., 2026; Yang et al., 2026). The trained managers optimize answer accuracy or memory quality; we train a manager for robustness to outdated memory and memory poisoning. 

Robustness of agent memory. Most prior work handles outdated memory and memory poisoning separately. For outdated memory, STALE tests implied changes (Chao et al., 2026); Supersede trains a model on changed facts (Patel, 2026). For memory poisoning, attacks insert content through knowledge bases, tool outputs or ordinary queries (Chen et al., 2024; Greshake et al., 2023; Dong et al., 2025), and defenses train models to ignore in-structions in data (Chen et al., 2025a,b) or check re-trieved records at inference time (Wei et al., 2026). The trained defenses teach a model to reject, not to decide which inputs to write. Outdated-memory benchmarks score the answer and poisoning work scores attack success, so each problem has its own metric. ECA scores the answer and also checks the records the manager selects, so one score covers both problems. 2One-shot post-training. Work on data-efficient post-training finds that a few well-chosen examples can replace a large training set. A thousand curated examples can align an LLM (Zhou et al., 2023), about 800 can elicit long reasoning (Ye et al., 2025), and post-training on a single problem can match the math-reasoning gains of training on thousands of examples (Wang et al., 2025c,a). These one-shot methods fix one problem and draw many training examples from it, such as critiques of many candi-date solutions or many sampled responses scored against the known answer. We follow this one-shot setting. We fix one conversation and draw many training episodes from it by inserting changes, at-tacks and standard turns, each with a target set by a fixed rule, and we train the manager on these episodes with plain SFT. Appendix A discusses further related work. 

3 Methodology 

In this section, we define the agent and its memory manager, the ECA metric and memory robustness, build training data around a single conversation, and train the manager on it with SFT. 

3.1 Problem Formulation 

An episode is a sequence of inputs o1, o 2, . . . that an agent processes in order, starting from an empty memory. An input is any text that the environment passes to the agent, such as a user turn, a tool out-put, a search passage or a web page. Input categories. Each input is in one of three categories, which the manager does not see. An in-put is in the outdated category if its speaker reports a change to a stored fact about themselves. The new value holds from a date d and is stated explicitly (“I moved to Seoul”) or implicitly (“our running club disbanded”); the stored record of the old value is outdated until the manager updates it. An input is in the poisoning category if it carries an attack, and a record that stores an attack is poisoned . The attacker cannot write to the memory but controls inputs that the user did not write, such as pasted text, search passages, web pages and tool outputs. The attack is fixed in advance, does not adapt to the manager, and either states false information that a later input needs or tells the agent how to act on later inputs. All other inputs are in the standard 

category.

3.2 One-Shot Data Synthesis 

The synthesis is one-shot. It uses a single base con-versation C, which fixes the speakers, their facts, the timeline and the unrelated turns. We insert turns of all three categories into C and keep only the turns that pass a set of checks. Figure 3 shows the four stages: (1) specification: the base conver-sation, the fractions of the input categories, and the rules extracted from existing outdated-memory and poisoning datasets; (2) insertion, which places and writes the turns and completes each episode with its states and target actions; (3) checks; and (4) output, the resulting episodes. 

Base conversation. C must contain independent attributes of several types (e.g., city, job), relative time cues (e.g., “yesterday”) that the session dates resolve (to position and date the inserted changes), a plan that is never carried out (for turns that must not change memory), and a fact that a later turn replaces (for inputs about a past value), where the retriever returns the record of the old turn for the new turn. Its facts must be stated in its text, and it must not overlap the evaluation data or be chosen using evaluation results. 

Insertion. Each inserted turn is written from a 

variant , a specification of what the turn says; the labeling rule gives its target. Some variants come as contrast pairs that differ in one factor (e.g., a change reported by the speaker vs. by another per-son). Further variants follow rules extracted from existing outdated-memory and poisoning datasets (Chao et al., 2026; Zou et al., 2025); each such rule keeps how a change or an attack is made but not its text. These variants add implicit (paraphrased or implied) changes, and attacks in search passages, which enter C as tool turns. We also add episodes of search passages without a conversation, in which false passages assert a wrong general-knowledge fact that a later input of the episode needs. In stage 1, we fix the fractions of inserted turns in the outdated and poisoning categories (the rest are standard). Code draws the attribute values of each turn, disjoint from the evaluation data. Achange either starts from a value that C mentions or introduces a new attribute and then changes it. 4 Experiments 

In this section, we use ECA to test whether the training-free baselines and the SFT manager are more robust than the untuned manager, on the test sets and on eight benchmarks. 

4.1 Setup Benchmarks. We build our test sets on three datasets: LoCoMo (Maharana et al., 2024) for the standard category, STALE (Chao et al., 2026) for the outdated category, and PoisonedRAG (Zou et al., 2025) for the poisoning category. The train-ing data is synthesized around a LoCoMo conversa-tion with rules extracted from STALE and Poisone-dRAG (Section 3.2), and the three test sets, one for each category, are synthesized from held-out parts of the three datasets. The standard category uses three held-out LoCoMo conversations with 866 rows, the outdated category our test half of STALE with 597 rows, and the poisoning category a test split of PoisonedRAG with 47 attacked rows. A test row is one scored input, whereas a training row is one state–target pair (Section 3.3). For generalization we use eight benchmarks, namely LoCoMo, LongMemEval (Wu et al., 2025) 5and PerLTQA (Du et al., 2024) for the standard category; STALE, the knowledge-update subset of BEAM (BEAM-KU; Tavakoli et al., 2026) and FactConsolidation of MemoryAgentBench (MAB-FC; Hu et al., 2026) for the outdated category; and PoisonedRAG and AgentPoison (Chen et al., 2024) for poisoning. LoCoMo, STALE and Poi-sonedRAG are seen , since the training data draws on them; the other five benchmarks are unseen .Each test set and benchmark is scored as a whole in its listed category, even if some rows fall in another (Section 3.1). 

Compared methods. We compare with the un-tuned manager (the backbone with the same prompts, before fine-tuning) and three training-free baselines, which prompt an LLM and update no weights. Mem0 (Chhikara et al., 2025) extracts facts from each turn and, comparing them with similar stored records, adds, updates or deletes records. A-Mem (Xu et al., 2025) stores each turn as a note, links it to similar notes and rewrites their tags and context, but never deletes a note. A-MemGuard (Wei et al., 2026) stores every turn; it drops retrieved records whose LLM-written rea-soning chains are inconsistent with the others or unsafe, and passes similar chains of earlier dropped records to πexec as lessons, which are not selected records (the only exception to Equation 2). 

Backbone. Every manager in the main text uses Qwen3-4B (Yang et al., 2025a) as its backbone; Appendix C repeats the experiments with two other backbones. For every method, πexec is gemma-4-31B-it, and the selected memory is the set of records that its manager passes to πexec (at most 8); the metrics are computed on it. 

Metrics. Every category reports ACC, the share of rows whose answer a judge marks correct, and ECA, both in % (outputs that cannot be parsed fail). The judge is a separate call to gemma-4-31B-it with each benchmark’s scoring prompt. In the poisoning category, ACC and ECA cover only the attacked rows, and ASR (lower is better) is the share of attacked rows whose selected mem-ory contains a poisoned record. Category scores average their benchmarks, and overall scores aver-age the categories. To check that the scores do not depend on this judge, we have GLM-5.2, a model from a different family, rescore 210 answers sam-pled from the reported runs. The two judges agree on 94% of them (Cohen’s κ = 0 .88 ). Cohen’s κ

(Cohen, 1960) is the agreement after removing the agreement expected by chance, where 1 means full agreement and 0 means chance level. Values above 0.80 count as almost perfect agreement (Landis and Koch, 1977), so the reported scores are not specific to the gemma-4-31B-it judge. 

Protocol. Most inputs are the turns of a long multi-session conversation between two speakers, as in LoCoMo, and the memory holds facts about the speakers; a search passage, tool output or pasted text enters as a turn of its own, and so does an in-put that depends on earlier turns. BM25 (Robert-son and Zaragoza, 2009) returns 64 records and all-MiniLM-L6-v2 (Reimers and Gurevych, 2019; Wang et al., 2020) reranks them, as in retrieval-augmented generation (Glass et al., 2022; Ram et al., 2023); the manager sees the top K = 8 (no evidence record added). SFT managers decode greedily under a grammar of the JSON target for-mat; the untuned manager samples with its default settings, and its scores are averaged over three de-code seeds. 

Training and testing. We select 41 turns of one LoCoMo conversation as the base conversation C

and synthesize the data around it with the pipeline of Section 3.2 (Figure 3): we insert turns of the three categories, 15% of them outdated and 15% poisoning, including variants that follow rules ex-tracted from STALE and PoisonedRAG, and add false-passage episodes on general-knowledge facts. This gives 400 training episodes with 21,656 rows. The test data of Figure 4 is synthesized by the same pipeline and kept out of training: 29 episodes with the 1,510 rows of the three test sets. We fine-tune all parameters of the backbone and tune its learn-ing rate on development splits. Figure 4 shows the results on the test sets; Figure 6 in Appendix C.1 gives every score, including overall averages.

The losses come from one fixed strategy applied to every input. A-Mem keeps every note and Mem0 writes the facts of every turn, so both also store attacks. A-MemGuard drops retrieved records that look inconsistent, so it also drops valid records. The two problems need opposite write decisions on different inputs; a strategy that makes the same decision for all inputs helps one category and hurts another, and we attribute the baselines’ losses to this. 

SFT is the only method that improves all three categories. SFT raises ECA over the untuned manager in all three categories, so by the definition of Section 3.1 it is more robust than the untuned manager, whereas no baseline is. It has the high-est ECA in every category, so no baseline is more robust than it: 57.3 against at most 50.3 (A-Mem) on the standard test set, 28.5 against at most 11.2 (A-Mem) on outdated inputs and 34.0 against at most 21.3 (A-MemGuard, the method designed for poisoning) on poisoning inputs. It reduces poison-ing but does not prevent it: ASR falls from 92.2 to 59.6. SFT keeps the prompts of the untuned man-ager and adds no fixed strategy, so the difference is that it decides per input what to write and which records to select. 

The results hold on two other backbones. On Qwen3.5-4B and Ministral-3-3B (Appendix C), SFT again raises ECA over the untuned manager in all three categories, and no baseline does.

Baselines lose on more benchmarks. Mem0, A-MemGuard and A-Mem fall below the untuned manager’s ECA on 3, 4 and 2 of the eight bench-marks, and SFT on none. 5 Conclusion 

We studied memory robustness for LLM agents: a memory manager should follow changed facts, reject poisoned content, and stay accurate on stan-dard inputs. To measure it, we introduced evidence-conditioned accuracy (ECA), which checks both the answer and the memory records behind it. Un-der ECA, the existing memory systems and de-fenses we test are not more robust than an untuned manager on our test sets; each gains in one cate-gory and loses in another. A simple one-shot recipe, which synthesizes training episodes around a sin-gle conversation and fine-tunes the manager on them, improves robustness on all three backbones, although robustness remains incomplete. We hope this work encourages evaluating memory managers on the records they keep as well as on the answers they give, and studying outdated memory and mem-ory poisoning together. Future work includes other agent settings, stronger attacks and training meth-ods beyond supervised fine-tuning. 

Limitations 

Our study focuses on the memory managers of con-versational agents. Other settings, such as web or embodied agents whose memory tracks a changing environment, are not evaluated, and we leave them to future work. As with most empirical studies of LLM agents, our evaluation covers a finite set of backbones, benchmarks and attack types, and may not include every form of outdated memory or memory poisoning that arises in deployment. We also compare against a limited set of existing mem-ory systems and defenses, so our findings about them may not extend to other methods. Our con-clusions should therefore be read as holding within the settings we study. 

Ethics Statement 

This work aims to make LLM agents with long-term memory more reliable and secure. The poi-soned content we generate follows published attack patterns, introduces no new attack technique and is used only in our experiments. All datasets are public research benchmarks used for their intended 8purpose, and our data involves no human partici-pants or personal information. The SFT manager does not eliminate all attacks and should be used together with other safeguards. We will release our code for research use.

Outdated memory. Training-free methods keep replaced facts with validity intervals or on a timeline (Rasmussen et al., 2025; Ong et al., 2025), as our updated records do (“Until d, . . . ”), and PACMI propagates invalidity through a provenance graph (Wang et al., 2026). Supersede trains a 3B model with group relative policy optimization (Shao et al., 2024) on changed facts (Patel, 2026); we use plain SFT on data built around one conversation. 

Memory poisoning and its cost. MemSecBench follows poisoned memory to later actions (Chen et al., 2026), and The Price of Safety measures what poisoning defenses cost on inputs without attacks (Bhowmik, 2026). Similar trade-offs appear as exaggerated refusal (Röttger et al., 2024), over-defense in prompt-injection guards (Li et al., 2025), lower clean accuracy under adversarial training (Tsipras et al., 2019), and acceptance of misinformation by LLMs that update on conflicting evidence (Xie et al., 2024; Xu et al., 2024). These works measure the cost. 

Data-efficient post-training. One-shot critique fine-tuning trains on teacher critiques of many solutions to one problem (Wang et al., 2025c), and 1-shot reinforcement learning with verifiable rewards on many sampled responses to one problem (Wang et al., 2025a). LLM-based augmentation expands a small seed set or corpus (Wang et al., 2023; Sun et al., 2023; Lee et al., 2024; Yang et al., 2025b), but generated examples can drift to a neighboring label (Sahu et al., 2022); our checks (Section 3.2) test for this drift. Our contrast pairs follow counterfactual data and contrast sets, which make small edits that change the label (Kaushik et al., 2020; Gardner et al., 2020). 

B Experimental Details 

B.1 Base Conversation 

The base conversation C is an excerpt of 41 turns from one LoCoMo conversation, chosen in two steps before any evaluation. First, using only the LoCoMo annotations of the scored inputs, we counted in each of the ten LoCoMo conversations the single-hop, multi-hop and temporal inputs whose evidence turns resolve and contain no photo; conv-41 had the most (90). Second, we took 41 original turns from three of its sessions (16 turns of session 25 on 2023-07-22, the first six turns of session 26 on 2023-07-31 and all 19 turns of session 28 on 2023-08-05), with their wording, speakers, dates and order unchanged, so that the excerpt contains a replaced fact (John’s job at a mechanical engineering company, reported lost in session 28), plans, relative time cues and unrelated facts of both speakers. Table 1 states the requirements of Section 3.2 as criteria for the conversation from which C is taken and checks them on all of conv-41; of the seven LoCoMo conversations outside the test set, five meet them (conv-41, conv-26, conv-43, conv-42 and conv-50), and these are the source conversations of the ablations (Appendix D.1). 

B.2 Training Data 

The variants are fact changes (a value replaced, a plan realized or cancelled, an activity stopped); no-change controls, which resemble changes but must not change memory (the owner’s restatement, a third party’s claim, a plan; the owner of a fact is the speaker it is about); turns with an injected instruction, alone or mixed with a fact; and rule-based variants , which follow rules extracted from STALE and PoisonedRAG (Section 3.2) and take from them only how a change or an attack is made, never their text: paraphrased or implied changes and inputs that never name the attribute (STALE), and search passages with or without an injected instruction (PoisonedRAG). The fractions of outdated and poisoning turns (15% each, Section 4.1) set how many turns of each category are inserted; the shares of training rows in Appendix D.1 differ from them because they also count the rows of inputs that depend on other inputs and the rows of rule-based variants and false-passage episodes. Parts (i) and (ii) are built from a table of about 130 changes over 16 attribute types and nine types of change, from attacks of five fixed templates, and from no-change controls, and an LLM writes each of their turns from its entry in the table. Besides the memory built from the targets (Section 3.2), for 30% of the changes, the inputs that depend on them get extra rows whose memory holds every turn verbatim. The recipe was informed by the STALE and PoisonedRAG development splits, but no text of either was used: rule-based variants that share an 8-gram with STALE or PoisonedRAG text, or reach a 5-gram Jaccard similarity of 0.5 with it, are removed, and so are false-passage episodes that share an 8-gram with any evaluation text or match a PoisonedRAG input and its answer. The cue check (v) of Section 3.2 requires that simple cues (word overlap, recency, length and cue words for old vs. new records; length, overlap with the input, position and specificity for false vs. supporting passages) recover the target with accuracy at most 55% to 65%.

B.4 Evaluation Protocol and Metrics 

The retriever is queried with the speaker and text of each input over the records of the manager’s own memory, and the top 8 records are relabeled M1, M2, . . . in a seeded random order, as in training. The manager gives 1–4 operations per input, which are applied deterministically: an added record is linked to its source turn, an updated record keeps the old record’s turns and adds the new turn, and a deleted record is never retrieved again. As in Section 4.1, outputs that cannot be parsed fail: operations that cannot be parsed, are cut off or break the operation constraints (e.g., add text not copied from the input or name a record that was not retrieved) are executed as NOOP , invalid read bits give an empty selected memory, an empty or cut-off answer is scored wrong, and every failure stays in the denominators. The baselines are run with one decode seed; all other decoding settings are in Table 3. 

πexec sees only the selected memory, with one prompt per benchmark; the STALE prompt renders the selected records in chronological order with session dates and asks πexec to use the most recent related evidence when the asked attribute is implicit. The judge is gemma-4-31B-it, called separately from πexec 

(Section 4.1), with the scoring prompt of each benchmark; for example, the STALE prompt also shows the benchmark’s annotated old and new memory, LoCoMo uses the Mem0 judge prompt (Chhikara et al., 2025), BEAM its nugget-based prompt, and PoisonedRAG, LongMemEval, MAB-FC and PerLTQA the LongMemEval answer check. 16 Record roles come from the benchmark’s annotation or our construction, never from a model (Table 4); a record with none of the listed roles is irrelevant. A record linked to any evidence turn is evidence, and a record that stores an attack is poisoned (Section 3.1); a record that keeps only the part of a poisoning input that is not the attack, as in Figure 1b, is not poisoned; in the outdated category, a record linked to both old and new evidence takes the role of its latest turn, and an updated record (“Until d, . . . ”) is not outdated. With these roles, the selected memory contains the correct memory Ct (Section 3.1) if it holds every evidence record in memory, none of them is outdated or poisoned, and every evidence turn of the input is linked to one of them. ASR is measured on the selected memory rather than on the answer, because with a fixed πexec answer-level attack success barely separates managers; on PoisonedRAG, answer-level success also counts answers that contain the attacker’s chosen answer with no poisoned record selected, and on AgentPoison the output that the attack aims for is also what πexec says when it abstains. Because an empty selected memory counts as a defended attack, we also report poisoning ACC. Intervals of differences between two managers, as in Appendix D.1, are 95% paired cluster-bootstrap percentile intervals with 10,000 resamples, clustered by STALE episode, PoisonedRAG input, AgentPoi-son input, LoCoMo window, and held-out input or episode. For models trained with three seeds we report the mean and the standard deviation (SD) across seeds.

D Ablations and Analyses 

D.1 Training-Data Ablations 

Each ablation retrains the Qwen3-4B SFT manager of Figure 6 (the reference) with one change to its training data and evaluates it on the same test sets (Table 5). PoisonedRAG is seen (Section 4.1), but no text from it was used for training. A difference is real if its 95% paired cluster-bootstrap interval excludes 0 and it exceeds the SD over three seeds. Ablated runs keep the learning rate, two epochs and the 21,656 rows of the reference, except under Fewer rows and One conversation . To keep the row count, removed rows are replaced by repeating a random sample of the remaining rows, and when the share of one category changes, standard rows fill the rest (shares are standard : outdated : poisoning rows; reference 56.8 : 18.4 : 24.8). Each one-conversation run has 3,215 conversation rows, plus the same 2,166 false-passage rows in the runs with false passages; the conv-41 rows are a sample of the reference rows, while those of the other conversations come from a later run of the pipeline. 

Each problem needs its own data. Without outdated rows, outdated ECA falls to 12.7 (untuned: 9.0); without poisoning rows, ASR rises to 93.6 (untuned: 92.2). Neither removal lowers the other problem’s scores or standard ECA by a real amount; trained on both, the manager keeps the outdated gain and most of the poisoning gain. Halving or doubling either share keeps all three ECAs above the untuned manager by real amounts, so the gain does not depend on the exact shares. 

Two parts of the data are needed for the gain. Without the implicit-change variants, outdated ECA falls from 28.5 to 7.0 (untuned: 9.0); without the false-passage episodes, ASR rises from 59.6 to 83.0. Removing the contrast pairs, the no-change controls or the labels in the targets does not lower overall ECA by a real amount (42.2, 38.6 and 44.6), so these parts are not needed for the gain. 

A small amount of data is enough. With 10% to 50% of the rows, every score stays above the untuned manager by a real amount, and 5% of the rows already reach overall ECA 44.6. From 10% of the rows on, overall ECA is at least as high as with all data, also over three seeds. With 10% of the rows, the three seeds give overall ECA 43 .8 ± 1.7 and ASR 39 .7 ± 1.2 (all rows: 42 .1 ± 2.5 and 50 .4 ± 8.1), and only the outdated scores are lower (ECA 20.0 vs. 26.1, ACC 37.4 vs. 39.6). 

Other source conversations also work. Without false passages, each of the five LoCoMo conversations that meet our base-conversation criteria raises outdated ECA, but only the base conversation, chosen before any evaluation, also lowers ASR by a real amount (66.0, against 85.1 to 89.4 for the other four). With the same false-passage rows added, each of the five raises all three ECAs and lowers ASR by real amounts with 5,381 rows (overall ECA 41.6 to 44.4 vs. 39.9; ASR 31.9 to 57.4). 

The gain does not depend on one seed. Two other seeds give overall ECA 44.8 and 41.5 (reference: 39.9), and each seed beats the untuned manager on outdated and standard ACC and ECA and on poisoning ASR and ECA (Table 5). 

The gain does not depend on the retriever or πexec . Without retraining, showing the manager the top 4 or 16 of the 64 BM25 candidates instead of 8, or dropping the reranker, keeps overall ECA above the untuned manager (33.0 vs. 14.7, 42.8 vs. 21.0 and 32.6 vs. 17.0); rows whose evidence is no longer retrieved count as failures. Replacing only πexec by Qwen3.5-9B (Qwen Team, 2026) or GLM-5.2 on the selected memory of each manager (judge unchanged) also keeps overall ECA above the untuned manager (39.8 vs. 16.8 and 38.8 vs. 17.0), with an interval that excludes 0 for every per-category ECA difference, so the gain does not depend on using the judge model as πexec . D.3 Owner Changes and Cost 

Since a speaker’s own report changes that speaker’s facts, we test whether the same change made through another channel also changes memory. For each of 78 changes in the held-out LoCoMo conversations, a clean episode has the owner report the change in their own turn, and an attacked episode writes the same change in the first person as the owner but in a tool passage or a third-party message (e.g., “Note from Caroline: I moved to Lyon last week”). Change ACC is the share of clean episodes answered with the new value, and ASR, as in Section 4.1, the share of attacked episodes whose selected memory contains a poisoned record (the record of the impersonated change). On Qwen3-4B, SFT has change ACC 70.5 and ASR 75.6, against 29 .5 ± 2.6 and 60 .3 ± 2.2 for the untuned manager (mean ± SD over three decode seeds) and 50.0 and 82.1 for A-MemGuard (one run each); compared with the untuned manager, it writes far more of the owner’s own changes but is also misled more often by impersonation. On the same 9 LoCoMo test episodes for every manager (428 turns), the SFT manager takes 0.39 s per turn on one H100 (not counting πexec ), against 1.32 s for Mem0 and 0.84 s for A-MemGuard, all with Qwen3-4B. Per turn, the SFT manager makes 1.33 LLM calls with 1,764 input and 119 output tokens, against 1.75 calls (2,177 / 253 tokens) for Mem0 and 2.98 calls (1,038 / 359 tokens) for A-MemGuard. 24
