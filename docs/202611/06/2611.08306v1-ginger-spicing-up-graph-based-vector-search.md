## 摘要
我们提出 Ginger，一个面向基于图的近似最近邻搜索（ANNS）的最先进开源 C++ 库。我们在 Google 开发了 Ginger，旨在提升大规模和高维嵌入数据集上图搜索的速度与内存效率。Ginger 在查询吞吐量和索引时间方面超越现有 ANNS 库，同时其内存占用与最节省空间的竞争方案相当。Ginger 基于邻近图构建（PiPNN）和向量量化（TurboQuant）的最新进展。我们引入嵌套 TurboQuant（NTQ），一种两级量化器，可在单一编码中支持低精度图导航和高精度重排序。该表示以约 1/2.6 的内存占用达到接近浮点精度。我们还将邻近图的大小最多压缩 2.5 倍，且不影响查询吞吐量。我们将图重排序与一种名为 AdaptiveGap 的新型无损压缩编解码器相结合，后者基于 StreamVByte 构建。在 95% 召回率下，Ginger 的查询吞吐量平均达到每个数据集上最快竞争方案的 1.8 倍，并至少达到任何单一库的 2.3 倍。在高维嵌入上，这一领先优势相对于紧凑型库扩大到 2.9 倍。

## Abstract
We present \textsc{Ginger}, a state-of-the-art open-source C++ library for graph-based approximate nearest neighbor search (ANNS). We developed \textsc{Ginger} at Google to push the speed and memory efficiency of graph search on large and high-dimensional embedding datasets. \textsc{Ginger} surpasses existing ANNS libraries with regards to query throughput and indexing time while matching the memory footprint of the most space-efficient competitors.   \textsc{Ginger} builds upon recent advances in proximity graph construction (PiPNN) and vector quantization (TurboQuant). We introduce Nested TurboQuant (NTQ), a two-level quantizer which supports low precision graph navigation and high precision reranking in a single code. This representation achieves near floating point precision with $2.6\times$ less memory. We also compress the size of our proximity graphs by up to $2.5\times$ without impacting query throughput. We combine graph reordering with a new lossless compression codec called AdaptiveGap, which builds upon StreamVByte. At $95\%$ recall, \textsc{Ginger} speeds up query throughput by an average of $1.8\times$ over each dataset's fastest competitor and by at least $2.3\times$ over any single library. This lead grows to $2.9\times$ over compact libraries on high-dimensional embeddings.

## 1. 核心问题与研究动机

- **背景**：深度学习推动 ANNS 成为信息检索与数据分析的核心组件；工作负载同时向“实体数量”和“嵌入维度”两个方向急剧增长。在高维场景下，邻近图（HNSW、Vamana/DiskANN、NSG、PiPNN）是保持高召回的主流索引结构，其查询通过贪心束搜索（beam search）在图上路由。
- **三大瓶颈**：作者指出图索引在实践中受限于（1）检索时的**内存带宽**、（2）托管索引的**内存占用**、（3）**索引构建时间**。
- **已有工作缺口**：作者团队的 PiPNN 已解决构图时间问题（十亿级索引从数小时降到数十分钟），但**查询吞吐**与**内存占用**仍未被同时解决；同时 PiPNN 缺少生产级实现。
- **论文定位**：发布 Google 内部研发并开源的 C++ 库 Ginger，作为 PiPNN II 的官方开源实现，目标是在**同一套系统中同时**达到 SOTA 查询速度、内存效率与索引时间，并可与 Faiss、ScaNN、DiskANN、SVS、Hnswlib、ParlayANN、SymphonyQG 等成熟工业/研究系统正面竞争。

## 2. 方法论

### 2.1 总体思路

围绕“**降低内存流量（memory traffic）**”这一主线设计检索的每一步：量化压缩 → 快速 SIMD 打分 → 投影/预过滤 → 图压缩，四者协同而非孤立优化。

### 2.2 Nested TurboQuant（NTQ）两级量化器

- **基础**：沿用 TurboQuant/EDEN 的旋转 + 高斯 Lloyd–Max 标量码本，4 bit 用于图导航。
- **嵌套细化**：把每个正的 4-bit 区间 $[t_u, t_{u+1})$ 再切成 $2^k$ 个连续子区间，每个子区间有**独立的** $2^k$ 项 Lloyd–Max 码本，得到 $(4+k)$ bit 编码；其**4-bit 前缀本身就是一个合法的 TurboQuant 码**，因此导航精度不受影响。常用 10 bit（k=6）与 12 bit（k=8）。
- **理论依据**：随机旋转使各坐标近似高斯，而高斯源在 MSE 下是**可逐次细化（successively refinable）**的，因此“强制细化”几乎不损失精度（优于共享码本的残差量化）。
- **偏置校正**：存储每向量标量 $s_b(x)=\lVert x\rVert_2/(\sqrt{1-D_b}\lVert \tilde y\rVert_2)$ 抵消量化收缩偏置，把全部 bit 留给码本（不像 TurboQuant 需留 1 bit 做 QJL 符号草图）。
- **非 2 的幂旋转**：分解 $d=r\cdot 2^\ell$（$r$ 为奇数），用随机符号 + 分块 Walsh–Hadamard + $r\times r$ Haar 随机正交矩阵组合成正交变换，复杂度 $O(d\log d)$，避免 EDEN 式零填充带来的约 33% 额外编码与打分开销。
- **存储布局**：4-bit 码（每字节两个）+ 导航尺度因子构成导航数组；细化码与 $s_{4+k}$ 单独成数组，仅重排时读取，束搜索**不额外加载字节**。

### 2.3 快速打分内核

- **4-bit 导航打分**：码本仅 16 项，将其舍入为 int8 并常驻向量寄存器；用 `pshufb` 做表查（每个 128-bit lane 一份表，一次 64 次查表），用 `vpdpbusd`（VNNI）做无符号×有符号点积累加；表项统一加 128 变为无符号，产生的与查询相关、与候选无关的偏置按查询预计算后扣除；查询按偶/奇坐标拆成两路，避免跨 lane 拆 nibble；配合软件预取掩盖 DRAM 延迟。
- **(4+k)-bit 重排**：以 float 精度对未量化的旋转查询打分。因 10/12-bit 码本需 memory gather（$d=4096$ 时约占重排时间 80%），改用**分段三次多项式**在寄存器内由索引直接算质心：7 个有界区间各一段三次曲线，无界尾部按 $M_6=8$、$M_8=16$ 段切分，用 `vpermps`/`vpermi2ps` 选系数 + 3 次 FMA（Horner），重排延迟约减半且不掉召回。

### 2.4 搜索优化

- **PCA 投影检索**：高维数据先投影到低维（保留约 90% 方差，按 cache line 对齐调优），并对投影矩阵行也做 4-bit 量化以降低投影阶段带宽竞争。
- **候选预过滤**：允许**过滤度量与导航度量解耦**（只需各自与查询的距离序相关），仅用 $d_{\text{filt}}$ 做保守门控、由 $d_{\text{nav}}$ 决定是否入束，从而保持 4-bit 搜索轨迹不变。两种过滤器：
  - **TurboSlice**：旋转后取 4-bit 码的前 $d_{ts}\in\{128,256\}$ 个坐标为无偏点积草图（零额外存储，只读 1–2 个 cache line）；
  - **1-bit 稀疏 JL**：$d_{jl}=1024$ 位符号草图，用 Hamming 距离比较，稀疏 $\{-1,0,+1\}$ 投影矩阵加速查询投影。
- **自适应阈值**：束未满时关闭预过滤；束满后取束尾 $w$ 个点的平均过滤距离 $\mu_t$，阈值 $\tau_t$ 取 $\mu_s$ 的滑动平均，随搜索收紧。
- **束管理**：单一有序数组 + 已访问标志 + 首个未访问下标（$O(1)$ 取下一个扩展点）；跨多次扩展**批量**收集、打分、一次线性归并，替代逐点 $O(L)$ 插入。

### 2.5 图无损压缩

- **RGP 重排序**：对（对称化后的）图做并行多层递归划分，按递归序给叶块与块内顶点编号，使邻居 ID 接近、gap 变小；优于 RGC 与 RGB。
- **AdaptiveGap 编解码**：在 StreamVByte 基础上引入**子字节位宽**——每条邻接表从 16 种 mode 中选一种（每种含 4 个位宽，如 $\{4,12,20,28\}$），2-bit 选择子 + 单 control byte，一次 `pshufb` 把覆盖某 gap 的字节聚到 32-bit lane，再移位/掩码取值，前缀和还原 ID；首个 ID 可选以 varint 单独存为 anchor 以避免整表退化到 mode 0；预计算 16×256 组 shuffle 掩码、移位与位掩码；约束为 $o+w\le 32$。
