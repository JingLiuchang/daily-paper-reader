Abstract 

Large language model agents increasingly undertake complex, long-horizon tasks that benefit from sustained personalized support through long-term memory. Existing memory-augmented meth-ods retrieve and use memory primarily from the initial request, with limited awareness of ongoing execution and emerging person-alization needs. Agents may therefore overlook user preferences and project constraints during multistep tasks. We propose Pulse, a streaming personalization method for long-horizon tasks. An independent, lightweight memory agent continuously monitors execution, identifies emerging personalization needs and potential preference conflicts, and uses user and project memories to pro-vide targeted interventions at appropriate stages. Reinforcement learning optimizes when and how the memory agent intervenes, improving the timeliness and accuracy of personalized support. Pulse scores 71.9% on 𝜋 -Bench and 46.4% on MCP-Persona, achiev-ing the highest overall scores among the compared methods on both datasets while improving task execution efficiency.

1 Introduction 

As large language model agents take on long-horizon tasks such as online shopping, travel planning, and project collaboration, multi-step planning [31] and tool use [21] become part of a continuous execution process. These tasks require agents to combine the cur-rent request with earlier interactions, user preferences, and evolving project state [17]. Users rarely repeat every preference or estab-lished constraint [37], so agents must apply long-term information at different stages to make decisions suited to the user [19]. User preferences may remain stable while their relevance to the current task becomes clear only during execution. The initial request typically describes a goal, whereas search, tool results, and intermediate decisions identify the concrete objects, available op-tions, and conditions of execution. A memory that initially supplies background may therefore become a requirement to check once a specific action is proposed. Sustained personalization must identify when existing memory begins to affect the current decision and sup-ply applicable preferences and constraints before the corresponding action is executed. Existing memory methods extract, organize, and retrieve histor-ical information to preserve background and preferences across sessions [24]. However, retrieval conditioned on the initial request struggles to cover new entities, subgoals, and candidate actions that emerge during execution [8]; even relevant memory included in the context may be overlooked in later decisions [14]. This creates two challenges: first, long-horizon execution requires sustained personalization , with relevant memory supplied as the task state changes; second, memory operations occupy the task agent’s execution process . • We formulate sustained personalization for long-horizon tasks and design two complementary types of long-term memory: user Topic graphs encode preferences across tasks, while project memory preserves reusable workflows and value memories to support execution-time decisions. 

• We develop a streaming online personalization framework driven by an independent memory agent that gates retrieval with execution events and chooses silence, non-blocking supplementation, or pre-commit intervention. GRPO opti-mizes its memory-use policy. 

• Experiments on 𝜋 -Bench and MCP-Persona show that Pulse improves personalized task performance in Web applica-tions and effectively increases memory-use efficiency and task execution speed. 

2 Related Work 2.1 Streaming Agents 

Streaming agents continuously receive new observations, update their context, and decide when to respond. Proactive assistance learns intervention opportunities from human activities and user feedback, linking response timing with users’ willingness to accept assistance [15]. In continuous video interaction, compressed visual histories support real-time understanding [33], while temporally aligned training enables models to answer questions as new frames arrive [4]. Streaming decisions also require coordination between response timing and evidence use. Decoupling perception, decision, and reaction supports asynchronous interaction [18], while anticipat-ing future evidence guides selective perception and historical re-trieval [30]. Bounded KV caches retain attention sinks and recent tokens to sustain continuous inference [27]; corresponding eval-uations examine both real-time perception and understanding of earlier events [13]. In Web interaction, page screenshots and in-teractive elements support action selection, and new observations after execution drive subsequent decisions [7]. Feedback on state changes after actions helps verify execution outcomes [1], while hierarchical planning and local exploration support adjustments to subsequent steps based on new observations [35]. As the task state changes, systems must adjust their response timing and use of historical evidence. Pulse brings streaming to personalized memory: the memory agent continuously observes Web task execution, supplies user and project evidence as needed, and intervenes before conflicting actions are submitted. 

2.2 Personalized Memory 

Personalization infers preferences from interaction histories and adapts outputs accordingly. Prior work preserves informa-tion across sessions through long-term memory and selective forgetting [37], and retrieves user profiles to support personal-ized generation [19]. Dynamic profiles [12] and user-centered retrieval [32] further adapt to changing needs in long-term interaction, supplying relevant preferences for the current request. Memory organization and updates affect how historical evidence is stored and used. External retrieval [11] and hierarchical man-agement [16] connect working context with long-term storage. Recursive summaries support retrieval at multiple levels [20], while graph structures [9] and linked notes [28] establish connections be-tween pieces of information. Fact extraction [5], topic summaries, and offline consolidation [6] maintain memory content. Verbal feedback [23] and trajectory comparisons [36] help distill reusable experience, and experience stores further adjust reuse and prune outdated procedures according to utility [3]. For Web tasks, prior work derives reusable workflows from task experience to guide sub-sequent execution [26]; reinforcement learning optimizes memory management and use policies [29]. Our Pulse combines personal-ized user and project memories, which the memory agent retrieves and uses as needed during execution, to provide sustained person-alization for long-horizon tasks in Web applications.

3.2 Long-Term Memory 

Long-term memory combines sets of retrievable user and project records, organized by the Topic graph and project structures: 

M = Muser ∪ M project . (3) 

User memory. User memory takes the form of a Topic-managed multilayer knowledge graph. A thematic layer organizes domains into Topics and subtopics; an entity layer links people, objects, places, and activities; a factual layer stores attributes, preferences, and applicability conditions. Topics index these relations. In Fig-ure 2, Coding links Languages to Python, while Writing links Reply style to code examples and brief replies. Code examples connect both Topics for joint retrieval. Retrieval is driven by the request or a new execution event. Pulse first locates Topics using the current subgoal, entities, and proposed action, then follows subtopic and entity relations to obtain facts together with their applicability conditions. Topic selection narrows the candidate space, and relational expansion recovers the context needed to interpret individual preferences. When explaining code, for example, the language preference can lead to requirements on examples and response length. Evidence selection considers step relevance, temporal validity, and information gain over the existing context, yielding facts and conditions that can affect the next decision. Historical interactions initialize the graph, and new information from subsequent tasks is written into the relevant Topic subgraphs. Existing entities retain their identities; new facts attach to their en-tities and Topics, with cross-topic links for facts spanning multiple domains. An explicit preference revision records its source, update time, and relation to the superseded version, while task-specific requests retain their applicability scope. This organization accumu-lates long-term preferences while allowing retrieval to distinguish revised facts from currently valid constraints. Appendix A.1 and Appendix A.2 detail memory population and updates. 

Project memory. Project memory contains reusable workflow experience and current project information: 

Mproject = W ∪ S . (4) 

W stores Skill-like workflows: task steps, tool-use procedures, de-pendencies, inputs, outputs, and applicability conditions. These records provide operational experience for the current subgoal.

4 Experiments 4.1 Experimental Details 

Evaluation configurations, per-category ablation results, and sup-plementary experiments appear in Appendix B. 

4.1.1 Datasets. 𝜋 -Bench [34] combines Web application tools with the work requirements of five user roles—researchers, marketers, pharmacists, law trainees, and finance professionals—to construct long-horizon workflows with cross-session dependencies. Tasks unfold in persistent project workspaces and require reusing his-torical preferences and project state in subsequent operations. We report COMP for task completeness. MCP-Persona [25] covers personal applications for collaboration, content management, social media, and email, using environment simulation to construct single- and cross-service tasks. Agents must combine user profiles, preferences, and application state to complete multistep operations. We report Acc for checkpoint completion. Persona2Web [10] targets open Web environments, providing user histories that implicitly reveal preferences and ambiguous requests that require agents to infer user intent from history. We use its data-generation scripts to generate an entirely new train-ing set for GRPO training of Pulse’s execution-time policy, and use the benchmark’s existing data for supplementary experiments. Supplementary evaluation appears in Appendix B.4. 

4.1.2 Comparison Methods. As agent harnesses integrate persis-tent memory into session management, context organization, and tool invocation, the execution framework also affects how memory is stored and used. We therefore compare two groups—traditional memory systems and harness memory strategies—to examine inde-pendent memory components and memory mechanisms embedded in execution workflows. 

Traditional memory systems. Mem0 [5] maintains long-term memory through fact extraction, updates, and consolidation. Light-Mem [6] combines lightweight filtering, topic aggregation, and offline updates to reduce memory-processing costs. A-MEM [28] or-ganizes historical information through structured notes and evolv-ing links. 

Harness memory strategies. OpenClaw integrates persistent memory, workspace files, and skills into the execution environment. dsh composes the agent loop, tools, and session management through plugins. ZCode maintains project files, execution history, and tool context across long-running tasks. Pulse w/o RL retains the full memory architecture and execution-time interventions without GRPO updates. Pulse (Full) uses GRPO to optimize the complete control policy. 

4.1.3 Implementation Settings. We use GPT-5.4 mini as the task agent and text-embedding-3-small for embeddings. All memory agents across the compared methods use Qwen3-8B as their back-bone. Pulse is initialized from the base policy and trained with GRPO for 100 steps with a batch size of 32. Store Token counts the memory model’s token output to the memory system; Retrieve Token counts the memory tokens it supplies to the task model. 5 Conclusion 

We formulate sustained personalization in long-horizon tasks, exam-ining how memory influences decisions throughout task workflows. Effective personalization depends on when and how historical evi-dence enters and shapes execution. Pulse combines user and project memories with a memory agent that supplies relevant information to sustain task personalization. GRPO optimizes its choices among silence, supplementation, and intervention. Experiments on multi-ple datasets show significantly more accurate personalized memory retrieval in both content and timing, alongside more stable perfor-mance and higher efficiency throughout long-horizon execution. These findings offer a direction for streaming personalization in agents performing long-horizon tasks.

A Method Details A.1 Memory Population and Organization 

Memory population takes historical conversations and existing task traces available before the task. Records retain source identi-ties and timestamps, distinguishing user statements, tool receipts, and project artifacts. User information is organized into indepen-dently retrievable facts under Topics and subtopics, with entities, attributes, and preference relations attached to the corresponding subgraphs. Entity identities are shared across Topics, and shared entities or factual relations connect relevant domains. For exam-ple, programming-language preferences belong to Coding, whereas code examples and response length belong to Writing; their links support joint retrieval when explaining code. Project memory is isolated by project identity and divided into workflows W and current information S. Workflows record goals, applicability conditions, steps, tools, and input/output dependencies. Current information records accepted decisions, file and artifact ver-sions, progress, pending items, and stage summaries. Retrieval first selects the user, project, and information cutoff, then matches the request or execution event against Topics and subgoals to recover valid facts, workflows, and project state. 

A.2 Incremental Writes and Updates 

Updates proceed through candidate extraction, source validation, merging, and commit. Explicitly stated durable preferences and identity facts become user-memory candidates, retaining their sup-porting quote and event identity. Successfully executed tool calls generate project-state candidates from receipts matched to the pro-posed action. Candidates are committed together when a conversa-tion closes. Equivalent facts are merged, while new records retain provenance and effective time. An explicit revision establishes a supersession link to the old record, so later retrieval selects the cur-rently valid version. Aborted conversations discard uncommitted candidates. User preferences, project facts, and workflows have distinct up-date evidence. User statements confirm preferences; execution re-sults confirm progress and artifact changes; reusable experience is organized into steps and dependencies with applicability con-ditions. A temporary choice retains its task context, and a later project decision updates the corresponding state record. Retaining sources and version relationships allows subsequent retrieval to establish the relevant user, project, and time interval. 

A.3 Execution-Time Policy Training Protocol

B.5 Comparison with a Shared Pulse Memory Backend 

Mem0, dsh, Pulse w/o RL, and Pulse share our memory storage and retrieval backend, comprising user Topic graphs and project workflow/state memory. Each run starts from an independent copy of the same memory snapshot, with the embedding model, retrieval interface and budget, writeback rules, task model, memory-model backbone, task set, decoding configuration, and execution budget held fixed. Each method retains its policy for when to access mem-ory and how to supply it during execution. Table B4 reports results for this experiment.
