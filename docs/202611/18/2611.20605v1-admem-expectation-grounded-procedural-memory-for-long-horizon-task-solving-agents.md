## 摘要
一个跨任务携带记忆的智能体，其表现取决于它所保留的记忆条目。我们从一个易于复现且令领域不安的观察出发：朴素地累积跨任务经验可能使智能体比完全没有记忆时更差。在 AgentBoard 上，工作流归纳记忆在八个领域中的七个里解决的任务数少于无记忆的 ReAct 智能体，而在 Jericho 上，一个没有周围结构的逐步程序性存储会损失 ReAct 完成量的一半。我们认为缺失的成分是逐动作的信用分配以及存储条目的显式生命周期，并提出同时提供二者的 AdMem。在每个动作之前，执行者承诺一个预期结果；并发运行的评论者根据该期望对实际结果评分，并写入一条携带二值奖励和反思的程序性条目，从而使信用落在真正获得它的动作上，且不需要环境奖励。随后每个条目携带一个标量效用，在 noisy-OR 奖励模型下在线更新，该效用与上下文相似度共同对检索排序，并驱动淘汰与合并，使存储具有遗忘和巩固策略，而不是无界增长。在八个 AgentBoard 领域的 707 个任务中，AdMem 解决了 441 个，而 ReAct 为 388 个，工作流归纳基线为 312 个——在双侧 Fisher 精确检验下总体增益显著，且集中在提供可迁移跨任务结构的领域。所有记忆都保持为人类可读文本，这正是上述失败可诊断的原因——并且正如我们所讨论的，也使存储成为一个可审计但可攻击的表面。

## Abstract
An agent that carries memory across tasks is only as good as the entries it keeps. We begin from an observation that is easy to reproduce and uncomfortable for the field: naively accumulating cross-task experience can make an agent \emph{worse} than one with no memory at all. On AgentBoard, a workflow-induction memory solves fewer tasks than a memoryless ReAct agent in seven of eight domains, and a per-step procedural store with no surrounding structure loses half of ReAct's completions on Jericho. We argue that the missing ingredients are per-action credit assignment and an explicit life cycle for stored entries, and present AdMem, which supplies both. Before each action the actor commits to an expected outcome; a concurrently running critic scores the realized outcome against that expectation and writes a procedural entry carrying a binary reward and a reflection, so credit lands on the action that earned it and no environment reward is required. Each entry then carries a scalar utility, updated online under a noisy-OR reward model, that ranks retrieval jointly with context similarity and drives eviction and merging, giving the store a forgetting and consolidation policy instead of unbounded growth. Across 707 tasks in eight AgentBoard domains AdMem solves 441 against 388 for ReAct and 312 for the workflow-induction baseline --- a pooled gain significant under a two-sided Fisher exact test, concentrated in the domains that supply transferable cross-task structure. All memory stays human-readable text, which is what makes the failures above diagnosable --- and, as we discuss, also makes the store an auditable but attackable surface.

## 1. 核心问题与研究动机

- **核心问题**：跨任务记忆并非"越多越好"。论文从一个易于复现却令领域不安的观察出发——**朴素累积跨任务经验可能让智能体比完全没有记忆时更差**。
- **具体证据**：
  - 在 AgentBoard 上，工作流归纳记忆（AWM）在 8 个领域中的 **7 个**解决任务数少于无记忆的 ReAct；总体 312/707 对 ReAct 的 388/707，下降约 10.7 个百分点（Fisher 精确检验 p = 7×10⁻⁵）。
  - 作者自己的消融显示：保留程序性存储但去掉规划与作用域结构的 LTP 变体，在 Jericho 上只解出 4/20，而 ReAct 为 8/20。
  - 独立基准（Wei et al., 2025）也在四骨干评估中报告了类似现象。
- **根因诊断**：作者认为缺失两个关键成分：
  1. **逐动作信用分配**（per-action credit assignment）：现有系统多以任务级或轨迹级判决写记忆，奖励在多次动作之后才到达，信用无法落到具体动作上。
  2. **存储条目的显式生命周期**：写入后缺乏评估、巩固、遗忘机制，错误归纳会被反复检索，成为持续性而非暂时性损失。
- **整体含义**：设计问题不是"如何存更多经验"，而是"哪些经验值得保留"；记忆必须在有可迁移结构处获益，在无迁移处至少不造成伤害。

## 2. 方法论（AdMem）

### 2.1 总体架构：三个并发模块

- **Actor（执行者）**：与环境交互的唯一决策者，维护短期记忆，并在每个动作前**承诺预期结果**。
- **Critic（评论者）**：并发的第二个 LLM，缓存"动作 + 预期"，等观测到齐后对照预期打分，写入程序性条目；从不发出环境动作。
- **Long-Term Memory Store（长期存储）**：检索索引 + 管理策略，自身不做推理（语义条目更新除外）。
- 三者分线程运行，actor 不阻塞于 critic，记忆写入与评估与行动重叠。

### 2.2 期望锚定的信用分配（核心创新）

- **流程**：actor 在行动前显式声明 `expectation`（该动作预期达成什么）→ 动作执行 → critic 等待相关观测全部到达 → 将实际结果与预期对比 → 输出二值奖励 `r_k ∈ {0,1}` 和反思 `f_k` → 写入程序性条目 `(context, action, expectation, reward, reflection)`。
- **两条关键性质**：
  1. **逐动作**：第 30 步的动作只按自身结果评判，失败任务中的好动作不被惩罚，成功任务中的侥幸动作不被奖励。
  2. **无需环境奖励**：奖励来自"行动前承诺 vs 行动后结果"的对比，适用于任何返回观测的环境。
- **作用域驱动的可判定性**：通过 `plan_for_the_task`、`add_subgoal`、`conclude_subgoal`、`take_action`、`think` 等记忆工具，把任务组织为子目标栈；一个待评记录恰在其作用域关闭时可判定（act 记录看紧随观测，sub-goal 记录看 push 到 pop 之间，任务计划看整个任务），从而限定待评队列。

### 2.3 短期记忆：作用域与压缩

- 采用**运行栈**结构：活跃帧保存当前子目标及其计划；帧外轮次由 actor 自己的 LLM 压缩为摘要，当前作用域全分辨率可见，上层压缩。
- 弹出子目标时压缩其轮次，任务结束时清空短期记忆；跨任务只保留 critic 或语义/情景摘要器写入长期存储的内容。
- 语义条目以**优先堆**（按相关性排序）呈现，情景条目以**作用域有序栈**（最近优先）呈现，两者共享固定提示预算。

### 2.4 长期记忆：检索、效用与生命周期

- **三类条目**：语义 `M_S`（环境事实）、情景 `M_E`（事件摘要）、程序性 `M_P`（决策指导）。
- **检索**：
  - 语义/情景按稠密相似度检索。
  - 程序性按 **效用 × 上下文相似度** 排序：`score(m|ct) = v_m · ψ(ct)ᵀψ(c_m)`，其中 `v_m ∈ [0,1]` 为效用，ψ 为归一化嵌入。
  - 程序性条目还按**动作空间硬作用域**过滤：合法工具集不匹配则不可检索。
- **效用更新（noisy-OR 奖励模型）**：
  - 奖励建模为"任一被检索条目有帮助，或无需记忆也能成功（概率 p₀）"的 noisy-OR；条目 i 的帮助概率为 `v_{m(i)} · σ_i`，σ_i 为上下文相似度（截断到 [0,1]）。
  - E 步：给定奖励求潜变量后验 γ_i；**r=0 时所有 γ_i 精确为 0**（noisy-OR 只有全失败才输出 0）。
  - M 步：`v̂ ← [(1-η)v̂ + η·γ_i/σ_i]`，实现中使用梯度形式 `v̂ ← [v̂ + η·∂log Pr/∂v̂]`，η = 10⁻³，新条目初始 `v̂ = 1`（乐观初始化）。
  - **不对称性**：失败动作按相似度成比例地下调所有被检索条目；成功动作按"谁是原因"的概率分配信用。
  - 实现中固定 `p₀ = 0`（论文说明这会高估成功时的信用，并给出理由）。
- **合并**：两条程序性条目若在"任一条被检索的轮次"中共同被检索的比例 > 1-ε_m（且至少一条累计足够检索次数），则合并。
- **遗忘**：条目驻留足够久（≥500 轮）后，若检索频率低于 ε_e = 0.01 则从索引移除；因排序是效用加权，低效用条目自然停止被检索，进而被淘汰——**遗忘通过检索通道发生**，而非直接奖励阈值。
- **溯源**：每条程序性条目保留原始上下文、动作、反思、二值标签与当前效用，全程人类可读。

## 3. 实验设计

### 3.1 Benchmark 与场景

- **AgentBoard** 的 8 个领域，共 **707 个任务**：
  - AlfWorld（134，具身家务）、BabyAI（112，网格指令）、Jericho（20，交互小说）、PDDL（60，符号规划）、Tool-query Academic（20，工具调用）、Tool-query Weather（20，工具调用）、WebShop（251，网页导航）、ScienceWorld（90，科学实验）。
- **流式多任务设定**：每个领域内任务依次到达，单一 lifelong episode，长期存储**不重置**；每配置只流式跑一遍。
- **指标**：AgentBoard 原生两项——任务完成率 C（解出比例）与平均进度 P（逐任务进度 p_i ∈ [0,1] 的均值）。

### 3.2 对比方法

- **ReAct**：无跨任务记忆的对照组，每任务从零开始。
- **AWM（Agent Workflow Memory）**：最接近设定的已发表系统，从自身轨迹在线归纳可复用工作流。
- 未移植 Mem0 / MemGPT / MIRIX 等对话记忆系统，理由是需要自行定义"环境步的记忆单元"和"动作时检索查询"，结果会变成"移植版"而非原系统；反思记忆基线的角色改由内部 LTP 消融承担。

### 3.3 消融与扩展实验

- **Jericho 上的组件消融**（20 任务）：
  - **STP**：仅短期规划与上下文管理，无长期召回。
  - **LTP**：仅长期程序性存储（逐步骤检索 + critic 反思 + 奖励效用），无规划与作用域。
  - **AdMem**：全部组件。
- **三 epoch 流式**：LTP 与 AdMem 把任务集再流式跑 3 个 epoch，存储不重置，效用跨 epoch 延续，用于检验累积是否随时间获益。
- **统计稳健性**（附录 C）：Fisher 精确检验 + Wilson 区间 + 最坏情况 McNemar 配对检验 + 设计效应（聚类）敏感性分析。

### 3.4 关键超参数

- 程序性检索 top-n = 3，纳入阈值 0.1；情景 top-n = 3；语义条目整条注入。
- ε_e = ε_m = 0.01；淘汰需驻留 ≥500 轮，合并需 ≥100 轮；子目标栈深度上限 3；短期窗口 30 条消息。
- 效用步长 η = 10⁻³，新条目 v̂ = 1，p₀ = 0；嵌入模型 text-embedding-3-small，L2 归一化。
- 骨干统一为 **Claude Haiku 4.5**（actor、critic、摘要器均为同一骨干），贪心解码（temperature 0，top-p 1），每任务上限 30 步。

## 5. 实验数量与充分性

### 5.1 实验规模

### 5.2 充分性与公平性评估

**优点：**
- 骨干完全固定（同一 Claude Haiku 4.5 用于所有方法），提示词与任务指令一致。

- **每配置仅一次运行、单一骨干**，无种子扫描；记忆臂是耦合流，二项区间反保守。
- 消融仅在 Jericho 一个领域上做，且每 epoch 差异单独看功效不足（LTP vs AdMem 第三 epoch 6 vs 12，p = 0.11）。

- 未做对抗性评估，也未报告鲁棒性。
