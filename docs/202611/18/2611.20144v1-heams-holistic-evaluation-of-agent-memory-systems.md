## 摘要
记忆系统使 AI 智能体能够在多次交互之间持久保存信息，从而使其更具个性化，并在长时程任务上具备更强能力。这种持久化引入了新的风险：存储的信息可能在不当情境中被披露，可能抗拒更正或删除，可能在超出用户意愿的情况下被保留，或被投毒以影响智能体后续行为。然而，记忆系统通常仅根据任务性能和效率进行评估。我们认为，记忆系统应被视为其用户持久信息的保管者，其责任超出帮助智能体完成任务的范围，并应针对所有这些责任对其进行整体评估。我们提出 HEAMS（Holistic Evaluation of Agent Memory Systems，智能体记忆系统的整体评估），一个以这种方式评估智能体记忆系统的开源框架。首先，我们将智能体记忆系统的责任表述为明确的行为期望，涵盖性能、效率、安全性、隐私和用户主权。其次，我们构建了一个覆盖这些期望的基准测试套件，并承认仍存在的空白。第三，我们开发了 MilaMem——一个原型记忆系统，以及一个可封装任意记忆系统的治理层，从而能够对记忆系统设计选择进行受控研究。第四，我们在完整的 HEAMS 基准套件上比较了多种记忆系统。我们发现，没有一种记忆系统能在所有性能基准上领先，且较高的性能得分可能与较差的隐私、用户主权和安全性得分并存。治理会强烈影响结果：召回策略可以降低不当披露，但以有用性为代价；而召回策略和保留策略均能提升抗投毒能力。因此，仅凭性能和效率基准无法揭示记忆系统在多大程度上履行其责任。代码：https://github.com/milatechtransfer/heams

## Abstract
Memory systems allow AI agents to persist information across interactions, making them more personalized and more capable on long-horizon tasks. This persistence introduces new risks: stored information can be disclosed in inappropriate contexts, resist correction or deletion, be retained beyond what users desire, or be poisoned to influence later agent behaviour. Yet memory systems are typically evaluated on task performance and efficiency alone. We argue that a memory system should instead be understood as the custodian of its user's persistent information, with responsibilities that extend beyond helping an agent complete its tasks, and that it should be evaluated holistically against all such responsibilities. We present Holistic Evaluation of Agent Memory Systems (HEAMS), an open-source framework for evaluating agent memory systems in this way. First, we state the responsibilities of agent memory systems as explicit behavioural desiderata spanning performance, efficiency, security, privacy, and user sovereignty. Second, we assemble a benchmark suite that covers these desiderata and acknowledge the gaps that remain. Third, we develop MilaMem, a prototype memory system, and a governance layer that can wrap any memory system, enabling controlled study of memory system design choices. Fourth, we compare memory systems across the full HEAMS benchmark suite. We find that no memory system leads every performance benchmark, and strong performance scores may coexist with poor privacy, user-sovereignty, and security scores. Governance strongly influences results: recall policies can reduce inappropriate disclosure at a cost in helpfulness, while both recall and retention policies improve poisoning resistance. Performance and efficiency benchmarks alone therefore cannot reveal how well a memory system meets its responsibilities. Code: https://github.com/milatechtransfer/heams

# HEAMS：智能体记忆系统的整体评估 —— 论文结构化总结

## 一、核心问题与整体含义

- **背景**：记忆系统（AMS）让 AI 智能体跨会话持久保存用户偏好、事实知识与任务上下文，使智能体更个性化、更能胜任长时程任务。ChatGPT、Claude、OpenClaw、Hermes、Grok Bot 等产品均已内置持久记忆。
- **核心问题**：持久化本身带来新风险——信息可能在不当情境被披露、难以被用户检查/更正/删除、被超期保留，或被投毒以持续影响后续行为。然而现有评测（LoCoMo、LongMemEval、BEAM 等性能基准，以及 Mem0、Hindsight 等产品报告）几乎只测**任务性能与效率**，隐私、安全、用户主权被边缘化。
- **核心主张**：记忆系统应被理解为**用户持久信息的"保管者"（custodian）**，其责任超出"帮智能体完成任务"。责任应归属于记忆系统而非调用它的智能体，理由有三：
  - 信息寿命长于任何智能体，删除、保留期限等义务须贯穿记忆全生命周期；
  - 同一用户可能授权多个（甚至不可审计的）智能体访问同一记忆，责任若下放则安全性取决于最不谨慎的智能体；
  - 任务智能体本身有完成任务的偏向，且可能被所处理内容操纵，不适合治理信息。
- **整体含义**：借鉴 HELM 的整体评估思想，主张对记忆系统按**全部责任**做多维、非聚合、受控可比的评估。

## 二、方法论

### 2.1 核心思想：三大要素

1. **显式行为期望（desiderata）并承认不完整**：把责任写成可观测的行为期望，映射到基准，并显式标注"未被覆盖"的空白。
2. **多元、非聚合测量**：性能、效率、安全、隐私、用户主权各自用独立指标**并排报告**，不合成单一分数，使权衡可见。
3. **受控、标准化比较**：通过统一接口，固定智能体与记忆交互策略，使结果差异可归因于记忆系统或其配置。

### 2.2 五维行为期望

| 维度 | 核心含义 | 代表性子期望 |
|---|---|---|
| 性能 | 提升任务成功率 | 任务成功提升、有用保留、有用召回、有用整合（未覆盖）、稳健更新 |
| 效率 | 资源成本 | 系统级/操作级 token 与成本、运行时、延迟、存储占用 |
| 隐私 | 上下文完整性 | 情境适当的召回 |
| 用户主权 | 用户可见、可控、可治理 | 忠实记忆查询、可靠更正与删除、保留策略遵从；保留/召回许可策略（未覆盖） |
| 安全 | 抵抗恶意内容 | 恶意保留抵抗、恶意召回抵抗；整合完整性/净化、策略绕过抵抗（未覆盖） |

### 2.3 关键技术组件

- **统一记忆接口**：`retain`（保留）、`recall`（召回）、`delete`（删除）、`consolidate`（整合）四个操作，交换文本内容与可选元数据；第三方系统需写适配器。
- **治理层（Governance Layer）**：可包裹任意记忆系统的可选包装器。
  - **保留策略**：在入库前评估条目，决定"准入/拒绝"；
  - **召回策略**：在披露前评估候选，决定"暴露/扣留"（扣留不等于删除）；
  - 支持规则、LLM 解释的自由文本策略、或混合模式；两类策略可独立开关。
- **智能体与交互策略**：基于 Mozilla.ai 的 TinyAgent，模型、提示、工具限制、记忆交互策略（工具调用式 / 确定性钩子式 / 仅召回变体 / 含删除处理的变体）均可配置，与记忆系统解耦。
- **场景生命周期**：`初始化 → 摄取（priming）→ 执行（探针与脚本步骤）→ 审计 → 清理`，全程记录配置、记忆操作日志、消息与工具调用序列，保证可追溯。
- **MilaMem 原型系统**：四个操作均可独立配置。保留时做去重/冲突判定（0.85 余弦门限 + LLM）；召回支持 BM25、向量、混合检索与 cross-encoder 重排，支持"重定向"（命中过期文本时返回更新版本）；删除通过精确匹配或 LLM 选择候选后隐藏（原始日志保留）；整合采用锚定式比较。设计上把"允许存什么/分享什么"的规则移出系统本身，交给治理层。
- **AMS Card**：面向架构性属性（可移植性、控制面、托管治理）的文档标准，与行为基准互补。

### 2.4 关键指标（文字化说明）

- **情境完整性（CI）**：字段泄漏率 = 被披露的禁止字段数 / 禁止字段总数；场景泄漏率 = 至少泄漏一个禁止字段的任务比例；允许覆盖率；有用率；"有用且无泄漏"率。
- **可编辑/可擦除（EE）**：**真实成功（genuine success）** = 仅当"请求前答对（证明曾学到）"且"请求后合规"才计成功，防止系统因"从未学会"而虚假得分。
- **保留策略**：禁止召回率（受联合结果上界约束）、允许召回率、平衡准确率。
- **透明度**：场景平均评分、严格通过率、完整性/溯源/时间状态/数据最小化/反幻觉等维度。
- **MPBench**：抗投毒率 = 答案未受毒化记忆影响的比例；另报最差攻击类。

## 六、主要结论与发现

1. **没有系统在所有性能基准上领先**：HippoRAG 在 BEAM 三档最高（59.71% @1M），In-context 在 LoCoMo/STALE/Evo-Memory 最高，MilaMem 在 LongMemEval 最高（73.20%）。In-context 随历史增长明显退化（BEAM 500K/1M 约 30%）。
2. **高性能与差隐私/安全可以并存**：HippoRAG 在 BEAM 上最强，但在 CI 上 94.79% 有用率伴随 71.74% 场景泄漏率；说明"有用"不等于"私密"。
3. **记忆类型决定收益**：依赖"记住事实"的任务（LoCoMo 等）上所有记忆系统至少比无记忆高 14 个百分点；而 Evo-Memory 这类"复用经验"的任务上，无系统超过基线 1.33 点。
4. **成本结构不同**：In-context 在回答时付费（98K–238K tokens/刺激），其他系统提示小（1.2K–12K）但存储极慢（Mem0 在 LongMemEval 813 秒/刺激，HippoRAG 1,533 秒）。
5. **召回治理以少量有用性换大幅降泄漏**：MilaMem 加"必要性门控"后场景泄漏 57.61%→31.82%，有用性仅降 4.80 点，"有用且无泄漏"从 30.86%→45.95%（全场最高）。
6. **用户主权普遍薄弱**：透明度最高仅 84.00%；删除成功率最高为 MilaMem 47.00%（Letta 19.00%，其余 0），编辑成功率无一超过 3.66%。
7. **保留治理是唯一控制手段**：加治理后禁止召回上界从 100% 降到 15.63%，但允许召回从 100% 降到 84.47%；其余系统根本不提供保留限制能力。
8. **治理显著提升抗投毒**：无治理仅 40.00%，仅保留 85.00%，仅召回 82.22%，两者结合 88.61%（最差类仍仅 68.33%）。
9. **总体结论**：性能基准不能预测隐私、安全、用户主权表现，整体评估对高风险部署是必要的；治理是让记忆系统尽责的关键抓手。

- **治理层的可迁移性**：同一策略可跨系统复用，使"策略效果"与"系统实现"可分离研究。
- **开源与生态意识**

- **开源与生态意识**：框架、基准与 AMS Card 文档标准被定位为公共基础设施——统一接口降低了新系统接入成本，适配器模式使"评测对象"可扩展；AMS Card 把可移植性、控制面、托管治理等难以用行为基准测量的架构属性单独文档化，与行为评测形成互补，避免"只测行为、不问架构"的盲区。
- **对"权衡"的正视**：全文坚持非聚合报告，明确展示"降泄漏必损有用性""加治理损允许召回"等此消彼长关系，而不是用单一综合分掩盖取舍，这对部署方做风险决策比排名更有价值。
- **结论可操作**：把"治理层"作为独立可插拔组件提出，并给出四配置消融（无治理/仅保留/仅召回/两者），使"该在哪里加控制"成为一个有实验支撑的工程问题，而非原则性呼吁。

## 八、局限与批判性讨论

1. **统计效力不足**：每个配置仅单次运行、无置信区间与显著性检验，而作者自己承认领先系统之间差距常小到"换一个配置即可重排"。这意味着性能榜的名次应被读作"同一档次"，而非确定性优劣。对隐私、安全、主权这些方差可能更大的维度（LLM 判官 + 生成式智能体），单次运行的结论尤其脆弱。
2. **判官即测量仪器，却未校准**：LLM 判官（gpt-4o-mini）在透明度、情境完整性、编辑/删除成功等维度承担核心判定，但未报告与人工标注的一致性（如 Cohen's κ）。若判官系统性偏好"看起来合规"的回答，则会高估用户主权类指标；若对"部分泄漏"不敏感，则会低估隐私风险。这是当前 LLM-as-judge 类工作的通病，但在一个主张"测量即责任"的论文中尤为关键。
3. **治理策略的开发/测试泄漏**：CI 的"必要性门控"召回策略与 MPBench 的策略均在基准示例上开发，属于 in-sample 调参。因此"治理把场景泄漏从 57.61% 降到 31.82%""抗投毒从 40% 升到 88.61%"应视为**上限估计**，真实部署中的策略需针对具体业务语料重写，效果可能明显下降。
4. **适配器即"测量的构造"**：结果刻画的是"经适配器之后的系统"，而非系统原生能力。Letta 的原生可编辑上下文块、Mem0 的原生更新机制在四操作接口下被压缩，可能低估其真实表现；反之，MilaMem 作为作者自研系统，其"重定向""锚定式整合"等设计与基准期望天然对齐，存在**自家系统与自家指标同构**的风险。论文未设置"由第三方实现的 MilaMem 适配器"或"由作者实现竞品最优适配"的双向校验。
5. **场景与用户模型单一**：单用户、聊天/助手式交互为主，缺少多用户共享记忆、企业级多租户、跨设备同步、家庭成员共用账户等现实中最容易出隐私事故的形态；也缺少"用户策略本身冲突或含糊"的情形（如用户先说"记住"后说"别用"）。
6. **时间维度被压缩**：保留期限、过期、遗忘曲线等"长期"义务多以静态策略判定形式测量（1,152 个决策），而非真实跨会话、跨月的时间演化实验；"超期保留"这一核心风险缺少纵向验证。
7. **攻击面覆盖有限**：MPBench 采用"毒化记忆直接植入"的强假设，绕过了"攻击者如何进入记忆"的入口问题（如通过被检索的网页、被转述的第三方消息）。对间接注入、多轮渐进式投毒、记忆污染后的"洗白"（consolidation 后难以溯源）等更现实路径覆盖不足。
8. **成本与可复现性门槛**：全流程依赖闭源商业模型 API，评测成本与模型版本强绑定（如 `gpt-5.6-luna`），第三方难以精确复现；论文未汇总总开销，也未报告模型更换后的敏感性分析，削弱了"标准化比较"的可持续性。
9. **"责任归于记忆系统"的论证有边界**：三条理由（信息寿命、多智能体共享、任务智能体的偏向）成立，但把治理责任完全上收至记忆系统，也可能导致**责任稀释**——智能体侧仍可做出不当的召回请求，若记忆系统只做"策略过滤"，则"该不该问"这一层判断无人负责。论文对"记忆系统与智能体责任如何划分"给出了原则，但未给出可操作的接口契约（例如智能体是否必须声明召回目的、目的声明是否可验证）。

## 九、对研究与实践的启示

- **对评测研究**：应把"性能榜"与"责任榜"分栏报告；引入重复运行与显著性检验；把治理策略的 held-out 划分作为标准做法；为 LLM 判官报告人机一致性。
- **对系统设计者**：四操作接口 + 可插拔治理层是一个低成本、可渐进落地的架构模式——先加保留策略（收益最确定：禁止召回上界 100%→15.63%），再加召回策略（隐私收益最大：场景泄漏近乎减半），最后补删除/编辑（当前全行业最薄弱环节，最高仅 47% 删除、3.66% 编辑成功率）。
- **对部署方**：不要把性能基准当作采购依据。HippoRAG 在 BEAM 最强却在 CI 上 71.74% 场景泄漏，说明"最强"与"最合规"常指向不同系统；应按业务风险面选型，并把治理配置纳入验收测试。
- **对用户主权议题**：删除/编辑成功率普遍接近 0，提示当前记忆系统的"记忆"更接近**追加式日志**而非可治理的知识库。这是产品与监管（被遗忘权）之间最直接的缺口。

## 十、总体评价与定位

这是一篇**立场明确、工程扎实、测量诚实**的评测框架论文。其最大贡献不在于给出某个系统排名，而在于三件事：（1）把记忆系统重新定义为"用户信息的保管者"，从而把隐私、安全、用户主权从"附带讨论"提升为**一等评测对象**；（2）用统一接口 + 可插拔治理层 + 固定智能体，把"整体评估"从口号变成可执行的实验装置；（3）通过非聚合报告与显式空白标注，主动暴露自身覆盖不足，学术诚实度高于同类基准论文。

其最大弱点在于**测量精度与结论强度不匹配**：单次运行、未校准的 LLM 判官、in-sample 开发的治理策略，使得具体数字（尤其是 1–3 个百分点量级的差异）不宜被当作定论；同时自研系统与自研指标的同构性，使"治理有效"这一核心主张仍需独立复现。就定位而言，它更像**一份可扩展的评测协议与问题清单**，而非终局榜单——这正是其长期价值所在：后续工作可以替换模型、增加重复、扩展多用户与纵向时间维度，而不必推翻框架。

**一句话总结**：论文论证了"记忆系统必须为它保管的信息负责"，并给出了可操作的评测装置；它证明了性能无法预测责任，但也坦承自己尚未把责任测准。
