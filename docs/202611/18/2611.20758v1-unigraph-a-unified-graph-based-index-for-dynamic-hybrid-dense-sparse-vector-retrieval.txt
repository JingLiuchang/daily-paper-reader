# UniGraph: A Unified Graph-based Index for Dynamic Hybrid Dense-Sparse Vector Retrieval 

Keyu Chen 1, Xiaoyao Zhong 1, Jiabao Jin 1, Peng Cheng 1, Wangze Ni 2, Jingkuan Song 1, Heng Tao Shen 1

Abstract —Hybrid dense-sparse vector retrieval combines se-mantic signals from dense representations with lexical signals from sparse representations, typically ranking items by a query-dependent weighted sum of dense and sparse vector distances. Existing systems commonly search separate dense and sparse vector indexes and rerank the union of their candidates, in-curring two retrieval passes and potentially discarding items that rank highly only after the semantic and lexical signals are combined. Constructing a graph-based index directly under a hybrid distance can mitigate this premature candidate loss. However, because varying the hybrid weight alters the underlying neighborhood relationships, a single static graph built at a fixed weight cannot accommodate dynamic query-specific weights. Therefore, we propose a Unified Hybrid Graph (UniGraph), which merges neighbor sets computed at multiple hybrid weights into a single bounded-degree hybrid graph, enabling hybrid vec-tor retrieval with different query-specific weights without index reconstruction. We further develop an adaptive weight-guided search framework that chooses between sparse- and dense-guided entry points according to the query weight, together with a dense-first hybrid distance pruning strategy that avoids unneces-sary exact sparse distance computations. Extensive experiments show that UniGraph provides a favorable Recall-QPS trade-off across different query weights. In the mixed-weight setting, UniGraph delivers 27.6% ∼52.3% higher QPS than the fastest baseline across datasets at Recall@100 ≥ 0.95 . UniGraph has been deployed at scale in Ant Group’s production environment, where hybrid retrieval with query-dependent weights is in strong demand. 

Index Terms —hybrid retrieval, graph-based index, ANNS 

I. I NTRODUCTION 

The growing volume of unstructured data and the increasing use of retrieval-driven AI applications have established vector search as a fundamental component of modern information systems. Retrieval-augmented generation (RAG), for example, relies on vector search to retrieve relevant information from external document collections and utilizes the retrieved in-formation to provide large language models with additional context [1], [2]. In vector search, data objects and queries are encoded as high-dimensional vectors, and the objects are ranked according to their distances or similarities to the query. Vector search commonly uses either dense or sparse rep-resentations. Dense vectors effectively capture semantic sim-ilarity but may not preserve exact lexical information such as rare terms or identifiers [3]. Sparse vectors retain term-level information and are therefore well suited to exact lexical matching [4], [5]. By combining the complementary semantic and lexical signals from dense and sparse representations, hybrid retrieval can achieve higher retrieval effectiveness than dense-only or sparse-only retrieval [6]. Hybrid dense-sparse vector retrieval has also seen growing adoption in practical information retrieval systems [7]. In hybrid dense-sparse vector retrieval, each item x in the base dataset is represented by a dense vector xd and a sparse vector xs. Given a query q with its dense representation qd

and sparse representation qs, the hybrid distance Dh(q, x ; α)

is defined as a weighted sum of the dense distance Dd(qd, x d)

and the sparse distance Ds(qs, x s):

Dh(q, x ; α) = α · Dd(qd, x d) + (1 − α) · Ds(qs, x s), (1) where α ∈ [0 , 1] controls the trade-off between semantic and lexical matching. This weight is naturally query-dependent. A conceptual question may rely more on dense similarity, while a query containing rare terms or identifiers may require stronger sparse matching. In this work, we consider the setting where 

α is specified at query time, focusing on efficiently supporting retrieval under the resulting query-specific hybrid distance. A common existing approach to hybrid retrieval is a two-route pipeline that searches dense and sparse indexes indepen-dently, merges their candidate sets, and reranks them under the query-specific hybrid distance [8]–[11]. This design entails an effectiveness–efficiency trade-off: for a requested result size (k), retrieving fewer candidates from each index risks missing some of the final hybrid top-k results, whereas retrieving more candidates increases the costs of both searches and reranking. Alternatively, a graph constructed directly under a certain Dh is tailored to the hybrid query weight used during construction and cannot maintain stable retrieval performance under dynamically varying query weights [12]. Our key observation is that dense and sparse vectors are complementary representations of the same underlying objects. 

Although they emphasize different aspects of relevance, both are derived from the same content and therefore induce corre-lated similarity structures: objects with high dense similarity also tend to have high sparse similarity. Figure 1 illustrates this observation. A more direct and efficient design is to use a unified index in which dense and sparse signals are combined during graph construction and traversal. > •

We propose UniGraph, a unified graph index for dense-sparse hybrid retrieval with dynamic query-specific weights. Its α-cover construction merges neighborhoods sampled at multiple dense-sparse trade-off weights into a bounded-degree graph, allowing a single hybrid graph to support different query-specific weights without recon-struction.

III. U NIFIED HYBRID GRAPH 

A. Motivation 

Dense and sparse vectors are paired representations of the same items in the base dataset. They are partially correlated: not identical, but not independent. This partial correlation cre-ates both the problem and the opportunity. The problem is that two-route retrieval may miss hybrid top-k results when an item does not rank highly in either vector modality. The opportunity is that neighborhoods under nearby α values overlap, allowing a unified graph to reuse edges across multiple hybrid weights. Figure 2 analyzes the source composition of the exact hybrid top-k result sets across five real-world datasets. For k = 100 ,we classify each item in the exact hybrid result set according to whether it also appears in the exact dense and sparse result sets. At intermediate weights, both dense-only and sparse-only results account for substantial portions of the hybrid top-100, indicating that neither component overwhelmingly dominates the hybrid ranking. This suggests that, for the datasets shown, the dense and sparse distance scales are sufficiently compati-ble. The Neither portion shows that some hybrid top-k results are absent from both single-modality result sets. On dataset NQ at α = 0 .3 and 0.5, this portion reaches 24%. These omissions limit the recall of two-route retrieval. Figure 2 also suggests why a unified graph is feasible. As 

α increases from 0 to 1, the contribution of the two modalities changes accordingly, while the portion shared by both rankings remains stable. In other words, hybrid neighborhoods are weight-dependent but still related: different weights favor different neighbors, yet part of the neighborhood structure can be reused. A graph constructed at a fixed α value captures only the neighbor relations under that weight. This motivates the 

α-cover construction of UniGraph, which combines neighbor relations from multiple α values, retaining weight-specific connections while sharing their common structure in a single graph. 

Why Is Discrete α Sampling Effective? The effectiveness of discrete sampling depends on how the hybrid neighborhood changes with α. For a fixed center base vector pair xi and a candidate neighbor xj , the hybrid distance can be rewritten as 

Dh(xi, x j ; α) = Ds(xsi , x sj ) + α Dd(xdi , x dj ) − Ds(xsi , x sj ). (8) 

This equation shows that the hybrid distance between two base vector pairs changes linearly with α. For a fixed center base vector pair xi, each of the remaining N − 1 base vector pairs defines a linear hybrid distance function of α. When two candidates are compared, their relative order can change only at a crossing of their distance functions. Only crossings within α ∈ [0 , 1] can affect the candidate ranking, and the partial correlation between dense and sparse distances further limits the number of such crossings. Many candidate pairs have the same relative order under both the dense and sparse distances. For such pairs, this order is preserved under any convex combination of the two distances. Even among the remaining crossings, those within the selected neighbors or within the unselected candidates change only their internal order. For a per-weight neighbor-set size ( kg ), the neighbor set changes only when a candidate crosses the top-kg bound-ary. Only a relatively small number of pairwise crossings can change the top-kg neighbor set. Between consecutive change points, the neighbor set remains unchanged. Therefore, discrete α sampling can effectively capture neighborhood structures across the continuous weight range. Accordingly, to construct UniGraph, we use a fixed sampling step δ to select a finite set of α values instead of finding all change points explicitly.

C. UniGraph Search 

Given a query q, a hybrid weight α, and an entry-point set Eq , we perform greedy beam search over UniGraph. Let ef s denote the search beam size. Unguided UniGraph search starts from a single randomly selected entry point (Eq = {e0}), whereas guided UniGraph search uses multiple query-dependent entry points retrieved from a guide index, as detailed in §IV-A. The traversal maintains a candidate set C

ordered by the query-specific hybrid distance and an ef s-sized result set R containing the best vertices found so far. At each step, the search selects the closest unexpanded vertex from C,visits its graph neighbors, evaluates promising unseen vertices, and updates C and R. Once |R| = ef s, it uses the standard beam-search termination condition: traversal stops when the closest remaining candidate is farther than the worst vertex in R. During traversal, UniGraph directly uses the query-specific hybrid distance to order candidates, while supporting any query-level hybrid weight α ∈ [0 , 1] without requiring graph reconstruction. Hybrid distance evaluation can dominate traversal cost because every visited candidate may require computing both dense and sparse distances. Computing the sparse inner-product distance is especially costly because it requires match-ing query terms with irregularly stored nonzero entries. Uni-Graph search therefore evaluates the dense component first and combines it with sparse vector norms to obtain an estimated hybrid distance. Based on this estimate, it determines whether exact sparse distance computation is necessary. Base vector norms are query-independent and can be precomputed during index construction and stored with the index; the sparse query norm is computed once and reused for all candidates during the query. Once the dense distance is available, computing the pruning estimate requires only a few scalar operations and no sparse vector matching. We next derive a norm-based lower bound, use it to construct a tunable hybrid-distance estimate, and characterize the resulting pruning guarantee and efficiency–recall tradeoff.

The guided search framework in UniGraph uses query-dependent entry points to initialize traversal of the unified graph. It selects between sparse-guided and dense-guided paths according to the query weight α. We first describe how the two paths obtain their entry points, and then present the α-adaptive routing policy and analyze the benefits of guided initialization. 

A. Guided Entry-Point Search 

Guided UniGraph search uses a guide index to obtain query-dependent entry points, as illustrated by the concrete example in Figure 4. We use either a sparse index or a dense index as the guide index. The sparse- and dense-guided paths retrieve results under Ds and Dd, respectively. The retrieved results serve as the entry-point set Eq for initializing the traversal in Algorithm 2; thereafter, UniGraph ranks and explores vertices using the query-specific hybrid distance Dh. The framework is independent of the specific guide index implementation. Any dense or sparse index that returns results ranked by the corresponding component distance can serve as the guide index. 

B. α-Adaptive Execution 

The guided search framework selects an execution path according to the query-level hybrid weight α: sparse- and dense-dominant queries are routed to the sparse- and dense-guided paths, respectively. After routing, the corresponding sparse or dense guide index is queried, and its results form the entry-point set Eq for UniGraph traversal. C. Analysis 

Guided entry points improve search by reducing the number of hybrid graph traversal steps needed to reach the result region. During UniGraph traversal, visiting a candidate may require evaluating the hybrid distance, which combines both dense and sparse distances. In contrast, the sparse and dense guide indexes perform single-route coarse search using only one component distance. Since dense and sparse vectors are correlated, the top-k results under either component distance are often close in UniGraph to highly ranked hybrid results. Guided UniGraph search can therefore be viewed as a coarse-to-fine process: it first uses Ds or Dd to approach the result region and then uses the query-specific hybrid distance Dh

to refine the search over UniGraph, reducing hybrid distance evaluations and improving search efficiency compared with unguided UniGraph traversal initialized from a random graph entry point. The α-adaptive policy further matches the entry-point strat-egy to the query’s dense-sparse weighting. For smaller α

values, results returned by the sparse guide index are more likely to include or lie near highly ranked hybrid results. For larger α values, results returned by the dense guide index provide analogous guidance for dense-dominant queries. Taken together, guided initialization and α-adaptive routing provide two benefits: they reduce the hybrid distance evaluations needed to reach the result region and improve recall by selecting entry points that match the dense-sparse preference specified by the query. VI. R ELATED WORK 

Fusion-based dense-sparse retrieval. Fusion-based systems typically retrieve dense and sparse candidates separately and then combine their truncated result lists. Weighted score fusion [10] preserves score magnitudes but requires calibra-tion, whereas reciprocal rank fusion (RRF) [10], [28] avoids calibration but discards score magnitudes and is sensitive to its rank constant. They both can lose candidates before fusion. 

Dense and sparse retrieval. Dense vector ANNS methods include locality-sensitive hashing [29], [30], quantization and inverted file methods (e.g, product quantization [31] and IVF-PQ [32]), and graph-based indexes (e.g., HNSW [25], NSG [33], and DiskANN [34]). Empirical evaluations show that graph-based methods offer competitive recall-efficiency trade-offs and often perform particularly well in high-recall regimes [35], [36]. Efficient sparse retrieval is commonly implemented with inverted indexes. Representative approaches accelerate re-trieval through pruning or compact index structures. Clas-sical block-max pruning and BMP skip low-potential doc-ument blocks [37], [38]; Seismic groups inverted lists into geometrically cohesive blocks [39]; Sinnamon uses compact sketches [40]; and SINDI uses optimized inverted lists for approximate sparse maximum inner-product search [26]. 

Unified dense-sparse indexing and dynamic-weight hybrid search. A graph-based ANNS method for dense-sparse hybrid vectors [12] aligns the dense and sparse distance distributions and refines an HNSW-style topology under a predetermined hybrid weight. Its fixed-weight topology may not match queries with different weights. Existing query-dependent hybrid methods face limitations in dense-sparse retrieval. IVF-MIPS [41] reuses IVF partitions for query-side reweighting, but lacks cross-weight neighbor-hood optimization. LADR [27] seeds dense graph explo-ration with lexical results, but is tailored for dense retrieval. While GPU-based Allan-Poe [42] supports dynamic multi-path weighting without index reconstruction, UniGraph builds a CPU-based bounded-degree graph by merging multi-weight sampled neighborhoods. Other multi-metric approaches and DEG [43] support query-specific weights via Pareto frontier neighborhoods or multi-graph traversals [44]–[48]. However, DEG is restricted to fixed-length Euclidean embeddings; its formulation and analy-sis do not cover high-dimensional inner-product sparse vectors, making it inapplicable to our dense-sparse hybrid setting without fundamental redesign. VII. C ONCLUSION 

This paper studies efficient dense-sparse hybrid retrieval with query-specific hybrid weights. We investigate UniGraph, a unified hybrid graph that supports different query weights without index reconstruction. UniGraph uses an α-cover con-struction to merge neighborhoods sampled at multiple weights. We further study α-adaptive graph search with sparse-guided and dense-guided execution paths. We also study dense-first hybrid distance pruning for reducing exact sparse dis-tance computations. Experiments show that, at Recall@100 

≥ 0.95 , UniGraph achieves 27.6% ∼52.3% higher QPS than the fastest baseline on each dataset under mixed weights and
