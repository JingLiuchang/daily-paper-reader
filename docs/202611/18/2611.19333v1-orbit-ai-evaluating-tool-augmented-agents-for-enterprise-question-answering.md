## 摘要
企业信息通常存储于多个平台，而非集中在一个位置。回答有关工作场所活动的问题可能需要来自多个来源的信息，包括项目文档、任务管理系统和团队对话。因此，我们评估 Orbit AI，这是一种基于工具的检索增强生成（RAG）系统，它使用由 LangGraph 实现的 ReAct 智能体，从三个不同的工作区来源检索并整合信息。我们比较三种配置：（1）不进行检索的独立 LLM，（2）基于文档的 RAG，（3）可访问全部三个来源的多工具智能体。留出评估集包含 80 个为 Phase 3 工作区设计的问题；Gemini 3.5 Flash Lite 在完整智能体下达到 86.25% 的准确率。仅基于文档的 RAG 达到 60.00%（完整智能体高出 26.25 个百分点），而普通 LLM 达到 23.13%。对于多源问题，完整智能体回答正确率为 84.38%，而仅基于文档的 RAG 为 40.63%，提高了 43.75 个百分点。在 rubric v2.2 下，采用本地推理的受评估 Llama 3.2 配置达到 5.50% 的总体正确率。Llama 3.2 完整智能体配置的留出准确率为 52.50%，比仅基于文档的 RAG 的准确率高 1.88 个百分点。Gemini 的提升相当于 26.25 个百分点。应谨慎看待这一比较，因为 Gemini 是通过其托管的 API 访问的，而 Llama 是通过 Ollama 在本地运行的，且模型规模不同。因此，在本实验中无法分离性能差距的原因。本文还讨论了评估的局限性，例如人工工作区规模较小，以及 Q53 问题与系统提示中的某个问题相似。

## Abstract
Enterprise information is commonly stored across multiple platforms rather than in one centralized location. Answering questions about workplace activities may require information from several sources, including project documents, task management systems, and team conversations. Therefore, we evaluate Orbit AI, a tool-based retrieval-augmented generation (RAG) system that uses a ReAct agent implemented with LangGraph to retrieve and combine information from three different workspace sources. We compare three configurations: (1) a standalone LLM without retrieval, (2) document-based RAG, and (3) a multi-tool agent with access to all three sources.   The held-out evaluation set contains 80 questions designed for Phase 3 workspace; Gemini 3.5 Flash Lite achieves an accuracy of 86.25% with the complete agent. Document-only RAG achieves 60.00% (26.25 pp higher), and the plain LLM achieves 23.13%. For multi-source questions, the full agent answers 84.38%, while document-only RAG answers 40.63%, a 43.75 pp increase.   The evaluated Llama 3.2 configuration with local inference achieves 5.50% overall correctness under rubric v2.2. The Llama 3.2 full-agent configuration achieves a held-out accuracy of 52.50%, which is 1.88 pp higher than the accuracy of document-only RAG. The gain of Gemini is equivalent to 26.25 pp. The comparison must be taken with a pinch of salt, because Gemini was accessed via an API hosted by them, while Llama was run locally via Ollama and the models are of different size. It is therefore not possible to isolate the cause of the performance gaps in this experiment. The paper also addresses the constraints of the evaluation such as the small artificial workspace and the similarity of the Q53 problem to a problem in the system prompt.
