## 摘要
混合稠密-稀疏向量检索将稠密表示中的语义信号与稀疏表示中的词法信号相结合，通常根据稠密和稀疏向量距离的查询相关加权和对物品排序。现有系统通常分别搜索稠密和稀疏向量索引，并对其候选并集进行重排，这会带来两次检索过程，并可能丢弃仅在语义与词法信号结合后才排名靠前的物品。直接在混合距离下构建基于图的索引可以缓解这种过早的候选丢失。然而，由于改变混合权重会改变底层邻域关系，在固定权重下构建的单一静态图无法适应动态的查询特定权重。因此，我们提出统一混合图（UniGraph），它将多个混合权重下计算得到的邻居集合合并为一个有界度图索引，从而无需重建索引即可支持具有不同查询特定权重的混合向量检索。我们进一步开发了一种自适应权重引导的搜索框架，该框架根据查询权重在稀疏引导和稠密引导的入口点之间进行选择，并结合一种稠密优先的混合距离剪枝策略，以避免不必要的精确稀疏距离计算。大量实验表明，UniGraph 在不同查询权重下提供了良好的 Recall-QPS 权衡。在混合权重设置下，当 Recall@100 大于或等于 0.95 时，UniGraph 在每个数据集上比最快的基线实现了高 27.6%~52.3% 的 QPS。UniGraph 已在蚂蚁集团的生产环境中大规模部署，该环境对具有查询相关权重的混合检索有强烈需求。

## Abstract
Hybrid dense-sparse vector retrieval combines semantic signals from dense representations with lexical signals from sparse representations, typically ranking items by a query-dependent weighted sum of dense and sparse vector distances. Existing systems commonly search separate dense and sparse vector indexes and rerank the union of their candidates, incurring two retrieval passes and potentially discarding items that rank highly only after the semantic and lexical signals are combined. Constructing a graph-based index directly under a hybrid distance can mitigate this premature candidate loss. However, because varying the hybrid weight alters the underlying neighborhood relationships, a single static graph built at a fixed weight cannot accommodate dynamic query-specific weights. Therefore, we propose a Unified Hybrid Graph (UniGraph), which merges neighbor sets computed at multiple hybrid weights into a single bounded-degree graph index, enabling hybrid vector retrieval with different query-specific weights without index reconstruction. We further develop an adaptive weight-guided search framework that chooses between sparse- and dense-guided entry points according to the query weight, together with a dense-first hybrid distance pruning strategy that avoids unnecessary exact sparse distance computations. Extensive experiments show that UniGraph provides a favorable Recall-QPS trade-off across different query weights. In the mixed-weight setting, UniGraph delivers 27.6%~52.3% higher QPS than the fastest baseline on each dataset at Recall@100 greater than or equal to 0.95. UniGraph has been deployed at scale in Ant Group's production environment, where hybrid retrieval with query-dependent weights is in strong demand.

## 1. 核心问题与整体含义

- **研究背景**：混合稠密-稀疏向量检索结合稠密向量的语义信号与稀疏向量的词法信号，常用于 RAG、开放域问答、事实核查、实体检索等场景。查询时通常用权重 \(\alpha\) 对稠密距离和稀疏距离加权：  
  \[
  D_h(q,x;\alpha)=\alpha D_d(q_d,x_d)+(1-\alpha)D_s(q_s,x_s)
  \]
  其中 \(\alpha\) 往往随查询变化。
- **核心问题一：两路检索的候选丢失**。现有系统通常分别搜索稠密索引和稀疏索引，再对候选并集重排。这会带来两次检索开销，并可能漏掉“单模态排名不高、但混合加权后排名很高”的结果。
- **核心问题二：固定权重图索引不适应动态权重**。直接在混合距离下构图可缓解候选丢失，但混合权重变化会改变邻域关系；在固定 \(\alpha\) 下构建的静态图难以适配查询级动态 \(\alpha\)，除非重建索引。
- **整体含义**：论文提出 **UniGraph**，将多个混合权重下采样的邻居集合合并为一个有界度统一图，使单一索引支持不同查询权重而无需重建；并配合权重自适应入口点和稠密优先剪枝，提高混合检索的 Recall-QPS 权衡。论文强调该方法已在蚂蚁集团生产环境规模化部署。

## 2. 方法论

### 2.1 核心思想

- 稠密与稀疏表示是同一对象的互补表示，二者邻域部分相关但非独立。
- 不同 \(\alpha\) 下的混合邻域会变化，但存在大量可复用结构；因此可将多个 \(\alpha\) 下的 top-\(k_g\) 邻居合并，按出现频率保留高价值边，形成统一有界度图。
- 查询时仍使用查询特定的混合距离 \(D_h\) 排序和遍历，因此同一个图可服务不同 \(\alpha\)。

### 2.2 \(\alpha\)-cover 图构建

- 将 \([0,1]\) 按步长 \(\delta\) 离散为采样权重集合  
  \[
  A=\{0,\delta,2\delta,\dots,1\}
  \]
  论文实验采用 \(\delta=0.1\)。
- 对每个中心点 \(x_i\) 和每个采样权重 \(\alpha\in A\)，计算其 top-\(k_g\) 混合邻居集合 \(N_i^\alpha\)。
- 合并所有采样权重下的邻居：
  \[
  U_i=\bigcup_{\alpha\in A}N_i^\alpha
  \]
- 对候选邻居 \(x_j\) 统计出现频率：
  \[
  f_i(x_j)=\sum_{\alpha\in A}\mathbf{1}[x_j\in N_i^\alpha]
  \]
- 最终每个节点保留频率最高的 \(\min\{M,|U_i|\}\) 个邻居，形成最大出度为 \(M\) 的有向图：
  \[
  N_G(x_i)=\arg\max_{S\subseteq U_i, |S|=\min\{M,|U_i|\}}\sum_{x_j\in S}f_i(x_j)
  \]
- 构建时并非全量两两计算距离，而是用稠密索引和稀疏索引生成候选池，再在候选池上计算精确稠密/稀疏距离并执行多权重邻居选择与频率合并。

### 2.3 图搜索与稠密优先剪枝

- 搜索采用 beam search：维护候选集 \(C\) 和大小为 \(ef_s\) 的结果集 \(R\)，用查询特定 \(D_h\) 排序；当 \(R\) 满且最近候选距离大于当前最差结果距离 \(\tau\) 时终止。
- **稠密优先混合距离剪枝**：先计算稠密距离 \(D_d\)，利用 Cauchy-Schwarz 不等式得到稀疏距离下界：
  \[
  L_s(q_s,x_s)=1-\|q_s\|_2\|x_s\|_2\le D_s(q_s,x_s)
  \]
  进而得到混合距离下界：
  \[
  L_h(q,x;\alpha)=\alpha D_d+(1-\alpha)L_s\le D_h
  \]
- 引入剪枝尺度 \(\gamma\in[0,1]\)，构造可调估计：
  \[
  \hat D_h=\alpha D_d+(1-\alpha)(1-\gamma\|q_s\|_2\|x_s\|_2)
  \]
  若 \(R\) 已满且 \(\hat D_h\ge\tau\)，则跳过精确稀疏距离计算。
- \(\gamma=1\) 时具有安全下界保证；\(\gamma<1\) 时更激进，可能提高剪枝率但不再保证下界，存在召回风险。主实验取 \(\gamma=0.3\)。

### 2.4 权重自适应引导入口

- 使用稠密索引或稀疏索引作为 guide index，先做单模态粗检索，将返回结果作为 UniGraph 遍历的入口点集合 \(E_q\)。
- 根据查询权重选择路径：
  \[
  \text{Path}(q,\alpha)=
  \begin{cases}
  \text{sparse-guided}, & \alpha\le \alpha_t\\
  \text{dense-guided}, & \alpha>\alpha_t
  \end{cases}
  \]
  实验设 \(\alpha_t=0.5\)。
- 稀疏主导查询用稀疏引导入口，稠密主导查询用稠密引导入口；之后统一用混合距离在 UniGraph 上细化搜索。

## 6. 主要结果与发现（定性归纳）

- **统一图能缓解候选丢失并减少双路检索开销**：UniGraph 将多个 \(\alpha\) 下的邻居合并到一个有界度图中，查询时用查询特定混合距离遍历，因此不必分别搜索稠密索引和稀疏索引再合并候选。相较 two-route 与固定权重混合图，论文报告其在混合权重场景下取得更优的 Recall-QPS 权衡。
- **动态权重适配是核心收益来源**：固定 \(\alpha=0.5\) 构建的混合图在查询权重偏离构建权重时性能下降；UniGraph 通过 \(\alpha\)-cover 合并多权重邻域，使单一索引覆盖 \([0,1]\) 上的采样权重，尤其适合 mixed-\(\alpha\) 查询流。
- **权重自适应入口点有效**：稀疏主导查询使用稀疏引导入口、稠密主导查询使用稠密引导入口，可避免从与查询语义不匹配的区域启动遍历；入口点消融在 \(\alpha=0.3\) 与 \(\alpha=0.7\) 下验证了该策略对召回和效率的正向作用。
- **稠密优先剪枝带来效率收益但存在召回风险**：利用稀疏距离下界可在不计算精确稀疏距离时跳过候选，\(\gamma=1\) 有安全下界保证，\(\gamma<1\) 更激进。主实验取 \(\gamma=0.3\)，说明论文倾向于以一定召回风险换取更高剪枝率和 QPS；实际部署需根据召回容忍度调节。
- **构建与存储存在额外成本**：多权重邻居采样和合并会增加构图计算量，统一图的有界度设计控制查询存储与遍历成本，但相较单模态索引仍有额外索引开销；论文通过构建时间和存储实验展示该开销与检索收益之间的权衡。

## 7. 局限与风险

- **理论保证不完整**：\(\gamma=1\) 时剪枝具有安全下界，但主实验使用 \(\gamma=0.3\)，此时不再保证精确下界；因此高剪枝率下的召回损失缺乏严格保证，只能依赖经验评估。
- **权重离散化误差**：\(\alpha\)-cover 以 \(\delta=0.1\) 采样权重，查询权重若落在采样点之间，图结构未必完全匹配；减小 \(\delta\) 可降低误差但会增加构图成本，论文未充分展开该权衡。
- **静态图与动态数据**：方法假设索引相对静态；面对文档插入、删除或表示模型更新时，多权重统一图需要维护或重建，在线更新成本未系统评估。
- **表示依赖**：实验固定使用 BGE-M3 的 1024 维稠密向量和加权稀疏向量，结论对其他稠密/稀疏表示、不同稀疏化策略及跨语言场景的泛化性仍需验证。
- **生产声明与公开实验之间存在差距**：论文强调蚂蚁集团生产部署，但公开实验主要是离线单线程评测；在线并发、尾延迟、内存压力和运维复杂度等生产关键指标披露有限。

- **评估建议**：未来工作应补充跨编码器、跨领域、在线更新和并发负载实验，并报告尾延迟、内存占用和索引维护成本，以更全面评估统一混合图的实际收益。

## 10. 总体评价

UniGraph 针对混合稠密-稀疏检索中“双路候选丢失”和“固定图难适配动态权重”两个实际问题，提出了结构清晰、工程可落地的统一图方案。其方法将多权重邻居采样、频率保留、有界度构图、权重自适应入口和稠密优先剪枝整合为完整检索流程；实验覆盖多个 BEIR 数据集、混合与固定权重设置及多类消融，整体证据较强。主要不足在于主实验剪枝不保证安全下界、权重离散化与静态图更新成本讨论不足，以及生产部署指标披露有限。总体而言，该论文对大规模混合检索系统设计具有较高参考价值，尤其适合查询级权重动态变化的 RAG 与开放域检索场景。
