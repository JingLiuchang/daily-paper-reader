# Jetriever: 

# Shifting Agent Memory Retrieval from Similarity to Utility 

Ruizhe Li, Licheng Zhang, Mingxuan Du, Zhendong Mao 

University of Science and Technology of China (USTC) Contact email: imlrz@mail.ustc.edu.cn Project repository: github.com/imlrz/Jetriever Research draft 4 November 2026 

Abstract. A useful memory need not resemble the question it helps answer. Jetriever ranks each stored memory by Jev’s decision score for its usefulness to the current question, replacing similarity search with full-pool utility scoring. On InMind’s 125 indirect-query tasks, it places the gold exchange first in 84.8% of cases; matched BM25 and MiniLM controls reach 1.6% and 0.0% when indexing user turns. A 20-question comparison separates finding evidence from ranking it: Jev and Qwen3.5 9B each find 90% of gold exchanges by rank 50, while Laya finds 30%; at rank one, Jev reaches 85% and Qwen3.5 9B 40%. On a dimension-proportional random sample of 60 MemoryAgentBench questions, Jetriever’s four-dimension score is 55.4%, against 44.3% for ReFind on the same questions. Jev retrieval costs $0.00834 per InMind question and $0.03103 per MAB question on average. These results show the value of world knowledge, scores that rank deci-sive memories first, and affordable full-pool scoring. 

Keywords agent memory utility ranking implicit association decision models 

1 Introduction 

Most memory systems retrieve text that resembles a question. That is often enough: BM25 is strong on established memory benchmarks, and even raw-dialogue RAG can match or beat elaborate memory systems [2, 3, 4, 5]. InMind exposes the case they miss [1]. A stored nut allergy matters to a request for a macaron recipe, although the request need not mention nuts. The connection comes from knowing what macarons contain, not from matching the two texts. An answer-stage LLM cannot use a memory that retrieval has left behind.

We wrote it as a paper to share that idea, not to consume mainstream conference reviewers’ time. arXiv:2611.21478v1 [cs.CL] 16 Nov 2026 Jetriever scores the memories already in the store, one by one, for whether each would help answer the question. This avoids asking an agent to guess every possible hidden association before retrieval. The scorer must know enough about the world to recognize those associations, return scores that distinguish decisive evidence from merely plausible evidence, and be cheap enough to run over the whole pool. Jev is an LLM-derived System One deci-sion model trained to return structured decisions and probabilities rather than free-form answers [8, 9]. We use its utility score directly as the re-trieval score. InMind tests the intended failure mode: on the same 241 exchanges per query, Jetriever places the gold exchange first in 106 of 125 tasks, against two for BM25 and none for MiniLM when they index user turns. A matched 20-question comparison with a BERT-based decision model and Qwen3.5 9B separates world knowledge from score quality: finding the gold memory by rank 50 is not the same as ranking it first [10, 11]. MemoryAgentBench then tests whether the method remains useful beyond implicit-association questions [2]. We report answer scores alongside retrieval cost; full-pool scoring is the method’s advantage at these pool sizes and its scaling prob-lem at larger ones. 

2 From similarity to utility 

For years, agent memory has inherited the search engine’s definition of rel-evance: find text similar to the query. Memory benchmarks have reinforced that choice by asking for explicit facts, state updates, or entity-linked multi-hop answers, where the question itself provides a search cue [1, 2]. On such tasks, even a simple retriever can look excellent. In ReFind’s six-task comparison, single-shot BM25-RAG has a 48.8 macro-average, ahead of every dense-retrieval baseline in the table; agent-controlled BM25 search reaches 58.2 [3]. Pengyu Wang and colleagues likewise find BM25 remark-ably strong in a broader RAG scaling study [4]. Bao et al.’s RAW-RAG indexes raw dialogue without memory extraction, uses dense retrieval and cross-encoder reranking, and leads the compared memory systems in six of seven settings across four benchmarks [5]. Similarity works well when the useful memory shares the query’s words or entities. The harder question is what happens when it does not. InMind changes the target from finding similar text to finding the memory that is useful for the answer [1]. A user’s nut allergy matters when they ask for macarons because macarons commonly contain almond flour. A memory saying there are lilies at home matters when the user asks about getting a cat because lilies can be toxic to cats [6]. The connection lives in world knowledge, not in word overlap. InMind makes this failure visible: across its 125 tasks, a backbone given the decisive memory directly answers 84.0% of indirect queries correctly, while the six tested memory systems reach at most 14.4% end-to-end. The knowledge to answer is often available; the right memory simply never arrives [1]. Putting an LLM in the retrieval loop does not solve this by itself. 3 Why a decision model? 

> THREE THINGS
> Remember these three. We test them one by one in the experiments.

We cannot search every possible association, but we can inspect every mem-ory we actually have. A decision-model scorer reverses the usual order: instead of asking an LLM to invent search terms and hoping a similarity retriever finds the right record, it judges each real memory against the query. This requires three things at once: broad world knowledge, prob-abilities that reflect usefulness accurately enough to rank memories, and scoring cheap enough to cover the whole memory pool. Jev brings those three requirements together. 

World knowledge. TypeSafe builds its decision models on pretrained LLMs and trains them for calibrated decisions with RLCD [8, 9]. This LLM foundation is the essential difference from a BERT-era classifier [14]: modern LLMs carry wide world knowledge, while BERT-based classifiers do not have that breadth. Jev can therefore judge a query–memory pair through an unstated fact, such as the link between macarons and nuts or between lilies and cats. On identical InMind candidate pools, Jev ranks the gold exchange first in 84.8% of tasks, compared with 1.6% for BM25 and 0.0% for MiniLM with user-turn indexing (Table 1). 

Reliable ranking scores. A retriever cannot rank hundreds of memories if it calls nearly everything “useful” or assigns nearly identical scores. A conventional chat LLM asked to make this judgment can be pulled toward agreeable yeses or cautious middle-of-the-road probabilities. RLCD trains Jev for calibrated decisions rather than preferred-sounding text [8]. For retrieval, the important consequence is a score that separates candidates: Jev puts the gold InMind exchange at rank one in 106 of 125 tasks and within five in 115 (Table 1). 

Affordable full-pool scoring. Scoring every candidate removes the need to guess the right search query first: each memory can be judged for what it would contribute to the answer, including memories a similarity filter would never retrieve. This requires hundreds or thousands of decisions per question. Our InMind experiment evaluates all 241 exchanges per ques-tion; the MAB sample averages 1,258.2 conversations per question. Do-ing this with an autoregressive chat LLM would make retrieval expensive and slow. Jev returns structured decisions without free-text decoding, and TypeSafe reports parallel output sampling [9]. In our runs, the retrieval API costs $0.00834 per InMind question and $0.03103 per MAB question on average. A separate batch scores 6,446 pairs in 90.16 seconds at 100-way concurrency (Table 4). Full-pool scoring is practical at these pool sizes.

4 Jetriever 

For query q and a memory candidate mi, Jetriever sends only (q, m i) to Jev and requests a binary Noul judgment. InMind uses the criterion: “Does this memory chunk contain personal information needed to give a correct, personalized response to the user query, including indirectly relevant in-formation? Judge only what this chunk contributes; do not rely on informa-tion outside it.” For the broader MAB tasks, we ask whether the memory contains information needed to answer correctly, including directly stated facts and necessary supporting information. The returned score s(q, m i) is treated as a ranking signal: 

πq = argsort i

( − s(q, m i), id (mi)), Mk(q) = {mπq (1) , . . . , m πq (k)}. (1) The identifier supplies a deterministic order for equal scores, which can occur because Jev’s scores are rounded to two decimals. The answerer sees the top k memories but not Jev’s score or a generated rationale. Thus Jetriever is a complete-reranking design: it makes N independent Jev de-cisions for N candidates, with no approximate nearest-neighbor index. The prompt asks Jev to judge what this candidate memory contributes, not to borrow facts from other personal memories. General world knowledge is precisely what lets it connect that candidate to the query. BM25 and MiniLM rank textual correspondence between q and mi; Jetriever ranks the expected usefulness of mi to the answer. 

5 Experiments and results 

5.1 InMind Memory Bench

> 5.1.1 Benchmark

InMind is both our motivation and our primary test of whether utility scoring retrieves memories that similarity search misses. Its 125 indirect-query tasks each require a world-knowledge bridge from a stored personal fact to a later question that does not name that fact. In the original pro-tocol, the fact is injected into a 47-session dialogue, followed by 38 more sessions before the query. The paper distinguishes whether the target fact reaches the answerer (Target Recall) from whether the final answer applies it (Application) [1]. Our ranking experiment gives each query the same 241 user–assistant ex-changes: the fixed background plus one injected gold exchange. Jetriever scores the complete exchange. For matched similarity controls, BM25 uses lowercased alphanumeric tokenization, k1 = 1 .2, b = 0 .75 [13]; MiniLM uses all-MiniLM-L6-v2 , normalized embeddings, cosine similarity, and its 256-token truncation limit [16]. We index either the user turn alone or the entire exchange. Query, candidate IDs, and gold flags are identical across methods. Gold labels are used only after scoring.

One representative task asks for cold medicine while its gold memory says, “I’ve been diagnosed with hypertension.” With user-turn indexing, the gold ranks first for Jetriever, 54th for MiniLM, and 178th for BM25. Another asks for a family pet while its gold memory states asthma; the ranks are first, 107th, and 241st. The useful connection in each case is knowledge about the world, not a shared word. Changing Jetriever’s candidate unit from 241 exchanges to 47 sessions de-creases R@1 from 84.8% to 49.6% and R@5 from 92.0% to 82.4%. At R@10 the sessions score 96.8% versus 94.4% for exchanges. Short exchanges make the utility of a specific fact easier to see; a long session can bury it among unrelated details.

5.2 MemoryAgentBench 

5.2.1 Benchmark 

MemoryAgentBench (MAB) tests four memory competencies: Accurate Retrieval (AR), Test-Time Learning (TTL), Long-Range Understanding (LRU), and Selective Forgetting (SF) [2]. It therefore broadens the question beyond InMind’s implicit associations. We sample 60 questions from our 3,671-question MAB evaluation set, in proportion to the size of each dimen-sion: 33 AR, 11 TTL, 3 LRU, and 13 SF. Within each dimension, questions are sampled uniformly without replacement (seed 6641975833030951438 ). Jev scores the full candidate pool for each sampled question: 75,491 query– conversation pairs in total, or a mean of 1,258.2 conversations per question (median 100.5; range 2–42,946). Conversations over 60k characters are split with 4k-character overlap, yielding 75,532 scored fragments; we max-pool their scores back to the original conversation. The top five feed the task-specific gpt-4o-mini answer prompt [19], followed by the MAB task met-rics. LongMemEval answers [20] receive an additional gpt-4o-mini judge. We compare against ReFind’s answers on these same 60 questions from an earlier full run [3]. Because ReFind was not rerun with Jetriever’s answer pipeline, this is a system-level comparison, not a retriever-only comparison.

World knowledge. InMind’s gold exchange matters through a fact about the world, not through words shared with the query. Jev and Qwen3.5 9B draw on broad knowledge from large-scale language-model pretraining. Laya does not have that breadth. By rank 50, both Jev and Qwen3.5 9B find the gold exchange in 18 of 20 questions (90%); Laya finds only 6 (30%). The two LLM-based scorers can recognize a memory whose usefulness is implicit, while the BERT-based scorer often misses it even after retrieving 50 of 241 candidates.

Reliable ranking scores. Recognizing the gold exchange is different from putting it first. The background contains many memories that could pos-sibly help. Qwen3.5 9B’s next-token probabilities are not aligned to this utility distinction: it puts the gold first in 8 of 20 questions and in the top five in 14. Jev’s decision score separates the decisive memory from merely plausible ones. Its recall is already 17/20 at rank one and 18/20 at rank five, and remains 18/20 through rank 50. The knowledge is present in both models; the difference is which memory their scores send to the answerer.

6 Discussion 

6.1 Why a decision model works as a retriever 

Section 3 gave three requirements for a utility retriever: broad world knowl-edge, reliable ranking scores, and affordable full-pool scoring. Jev com-bines all three (Table 5). A BERT-based classifier can give a cheap ranking score when trained for the task, but lacks the breadth of world knowledge needed for indirect associations. A conventional LLM has that knowledge, but its answer-token probabilities do not reliably put the decisive memory first, and scoring the full pool is expensive. Jev uses an LLM foundation while returning a decision score cheaply enough to rank every candidate in the pools we tested.

Similarity retrieval asks which memory sounds like the question. Agen-tic query expansion asks which hidden connection the agent can imagine 

before seeing the memory. Jetriever instead scores the actual memory for its effect on the answer. The InMind results show why that distinction matters. 

6.2 Scaling limits 

Full-pool scoring grows with the number and length of stored memories. Our runs cover 241 exchanges per InMind question and a mean of 1,258.2 conversations per MAB question, but a much larger store would require more Jev calls and raise both cost and latency. The unit of indexing also 

> 9

matters: an entire session may preserve context, yet contains more tokens and can make the relevant exchange harder to rank. These experiments establish that full-pool scoring is practical at the tested sizes, not that it is free at any scale. 

6.3 Where to go next 

A cheaper first stage could narrow a large memory pool before Jev scor-ing. Ordinary lexical or embedding retrieval is a risky filter: it may drop precisely the indirectly useful memories Jetriever is meant to find. The use-ful next experiment is therefore a cascade measured by both gold-memory recall and end-to-end cost as the pool grows. A utility-aware index, or a high-recall first stage that keeps indirect candidates, may make full-pool decisions unnecessary without bringing back the similarity bottleneck. We also need per-question latency distributions and direct tests of score cali-bration, rather than only batch throughput and retrieval ranks. 

7 Conclusion 

> ONE LINE
> Find the memory that matters to the answer, not just one that sounds similar.

Jetriever ranks a memory by what it can do for the answer, not by how closely it matches the query. Jev makes that full-pool judgment useful be-cause it combines broad world knowledge, a decision score that separates decisive evidence from plausible background, and low per-decision cost. On InMind, this recovers indirect evidence that BM25 and MiniLM miss; on the sampled MAB questions, it improves the four-dimension score over Re-Find on the same sample. The paired InMind comparison also shows why an ordinary LLM’s world knowledge is not enough: finding the gold mem-ory somewhere in the top 50 does not put it first. Full-pool scoring still grows with the store. The next retriever should reduce the number of deci-sions without filtering out the indirect memories that motivated Jetriever in the first place.
