# Abstract 

An agent that carries memory across tasks is only as good as the entries it keeps. We begin from an observation that is easy to reproduce and uncomfortable for the field: naively accumulating cross-task experience can make an agent worse 

than one with no memory at all. On AgentBoard, a workflow-induction memory solves fewer tasks than a memoryless ReAct agent in seven of eight domains, and a per-step procedural store with no surrounding structure loses half of ReAct’s completions on Jericho. We argue that the missing ingredients are per-action credit assignment and an explicit life cycle for stored entries, and present AdMem, which supplies both. Before each action the actor commits to an expected outcome; a concurrently running critic scores the realized outcome against that expectation and writes a procedural entry carrying a binary reward and a reflection, so credit lands on the action that earned it and no environment reward is required. Each entry then carries a scalar utility, updated online under a noisy-OR reward model, that ranks retrieval jointly with context similarity and drives eviction and merging, giving the store a forgetting and consolidation policy instead of unbounded growth. Across 707 tasks in eight AgentBoard domains AdMem solves 441 against 388 for ReAct and 312 for the workflow-induction baseline — a pooled gain significant under a two-sided Fisher exact test, concentrated in the domains that supply transferable cross-task structure. All memory stays human-readable text, which is what makes the failures above diagnosable — and, as we discuss, also makes the store an auditable but attackable surface. 

# 1 Introduction 

Large Language Models (LLMs) [Brown et al., 2020, Chowdhery et al., 2023, Guo et al., 2025, Touvron et al., 2023] have improved rapidly at reasoning and tool use, yet still struggle with long multi-turn tasks that require remembering, organizing, and applying knowledge across sessions or large inputs [Zhang et al., 2025]. Two research directions have emerged [Wu et al., 2025]: 

architectural memory , built into the network through added layers or modules [Xu et al., 2026], and symbolic or textual memory that the model reads and writes explicitly. This paper is about the second, and specifically about a question the second direction makes it possible to ask: not how much experience an agent can store, but which of it is worth keeping. Parametric memory extends the model’s effective context: End-to-End Memory Networks [Sukhbaatar et al., 2015] introduced differentiable attention over an external memory, and later work [Berges et al., 2025, Behrouz et al., 2025, Munkhdalai et al., 2024] learns long-term memory modules that retain historical context while keeping training parallelizable. These buy speed and differentiability at the cost of inspectability: what has been remembered is distributed over weights or a compressive state, so it cannot be read, attributed, or deleted item by item. That trade-off is decisive here, because the central failure we report is an agent storing the wrong experience and re-using it: diagnosing it required reading the offending entries, and fixing it required a policy that can remove a specific one. We therefore keep every entry as readable text.

Textual stores are inspectable and tool-friendly, but need well-designed policies to be effective and bounded. Prior systems fine-tune models to read and write knowledge triples [Modarressi et al., 2025, 2023], foreground human control over adding, merging, and deleting entries [Huang et al., 2023], page virtual context with explicit CRUD [Packer et al., 2023], consolidate units extracted from running conversations [Chhikara et al., 2025, Zhou et al., 2026], decay episodic histories on a forgetting curve [Zhong et al., 2024], and compress context by learned overwriting or sub-task chunks [Yu et al., 2026, Hu et al., 2025]. As a group they already hold most of the vocabulary a memory life cycle needs — writing, consolidation, decay, deletion — but instantiate it for facts about the world and the user, where an entry’s value is roughly its correctness. Our entries are recommendations about how to act , whose value is whether following them helped, and that is not observable at write time. That gap is the domain of procedural memory: in the classical cognitive division [Tulving, 1985, Cohen et al., 1997, Wu et al., 2025] it holds knowledge of how to do things rather than the semantic and episodic content above. Cast into the language-agent setting [Sumers et al., 2023, Gao et al., 2026], the LLM is the decision maker and the prompt is its control flow, so procedural memory is whatever text conditions the next action. Agent Workflow Memory (AWM) [Wang et al., 2025] induces reusable workflows from past successes in web navigation [Deng et al., 2023, Zhou et al., 2024]; Mem p [Fang et al., 2026] distills experience into granular instructions and higher-level templates [Xie et al., 2024, Shridhar et al., 2021]; Buffer of Thoughts [Yang et al., 2024] stores distilled thought templates; and MIRIX [Wang and Chen, 2025] and Agent KB [Tang et al., 2025] organize structured memory types or strategy–log pairs under a multi-agent controller [Mialon et al., 2024, Jimenez et al., 2024]. A parallel line writes memory from evaluated outcomes rather than successes alone: Reflexion [Shinn et al., 2023] turns task failure into a verbal reflection, ExpeL [Zhao et al., 2024] accumulates insights from successful and failed trajectories, Generative Agents [Park et al., 2023] maintains a reflection hierarchy, and the most recent work — ReasoningBank [Ouyang et al., 2026], Memento [Zhou et al., 2025], and agentic context engineering [Zhang et al., 2026] — makes reusable reasoning strategy the stored unit. AdMem shares its goal with that line and differs in two specific ways that the rest of the paper is about. Where credit is assigned. These systems evaluate a trajectory or a task and write an entry from the verdict, so the reward is task-level and arrives once, after many actions — the credit-assignment problem in its usual form. AdMem instead requires the actor to state, before each action, what it expects that action to accomplish, and has a critic score the realized outcome against that expectation as soon as the relevant observations arrive. Credit lands on the action that earned it, with no environment reward needed. What happens to an entry afterwards. Where these systems do keep post-write bookkeeping — helpfulness counters, deduplication, a value per stored case — it is updated from the task-level verdict and is a separate quantity from the score retrieval ranks by. AdMem gives each procedural entry one scalar utility with an explicit probabilistic meaning — the probability that following it makes the current action succeed — estimated online from the per-action rewards of the paragraph above, and ranks retrieval by that same quantity, with eviction and merging following from the retrieval statistics it drives. The store thus has a life cycle — write, evaluate, consolidate, forget — closed by one estimated number rather than a write path plus side counters. This matters more than it may appear, because unmanaged accumulation is not merely suboptimal. In our experiments a workflow-induction memory ends up below a memoryless ReAct control in seven of eight AgentBoard domains, and an ablation of our own system that keeps the procedural store but removes the planning and scoping structure around it loses half of ReAct’s completions on Jericho. An independent streaming benchmark reports the same for workflow-induction memory in a four-backbone evaluation [Wei et al., 2025]. A memory that cannot be evaluated and cannot be forgotten is a liability whenever the domain supplies less transferable structure than the write policy assumes. # 2 Methodology 

2.1 Setting, notation, and framework 

An agent solves a series of tasks by interacting with an environment in turns; in round t it emits an action at and the environment returns an observation ot. The environment may comprise human users, other agents, or tool-calling infrastructure. Each task is its own environment episode, but the agent’s memory is not reset between tasks — the setting of a deployed assistant, and the reason a single lifelong horizon, rather than a task, is the right unit of analysis. The agent carries a memory st

and acts by conditioning an LLM on a context ct assembled from that memory, at ∼ πLLM (· | ct).Vanilla baselines for multi-turn benchmarks [Ma et al., 2024] take ct = st = [ a1, o 1, . . . , a t, o t], the full trajectory, which stresses long-context reasoning as tasks grow. Prior work responds along two axes: context compaction , keeping st short enough for one window, and retrieval , placing only part of the memory into ct. The critic is a second LLM instance on the memory write path: it caches each action together with the actor’s stated expectation, waits until the relevant observations have arrived, then scores the action and writes the resulting procedural entry. It never emits an environment action. The store holds three kinds of entry, M = MS ⊕ ME ⊕ MP , following the standard cognitive division [Tulving, 1985, Cohen et al., 1997]: MS , semantic — facts and general knowledge about the environment and the tasks, such as what a tool returns or what a field name means; ME , episodic 

3— summaries of past events in the agent’s own interaction history; and MP , procedural — decision-making guidance extracted from past actions, recording for each action taken and outcome observed whether the outcome met the stated expectation and advanced the task, and what a better action would have been. Semantic and episodic entries are comparatively easy to form: an LLM summarizes facts and events as the task runs. Procedural entries are harder for two reasons. First, an action cannot be judged until the observations it was supposed to produce have arrived, possibly many turns later — concluding a sub-goal plan requires everything that happened inside the sub-goal. Second, the environment supplies no per-action reward, and in the lifelong setting may supply none at all. AdMem resolves both at once: the actor must state the expected purpose or result of every action 

before taking it, and the critic buffers the action until its outcomes land and then judges it against that expectation. Within the actor, the two non-procedural memory types are surfaced in different structures, shown in-side the actor box in Figure 1. The semantic heap is an unordered, priority-ranked pool: environment facts have no natural sequence, are read by relevance to the current context, and the highest-scoring ones are surfaced first. The episodic stack is ordered and scoped: event summaries are pushed as the task descends into sub-goals and read most-recent-first, so the actor sees the events of the sub-goal it is currently inside before older ones, and a scope’s episodic entries are compressed together when that scope is concluded (Section 2.3). Both structures draw on one fixed prompt allowance, so what they expose is what the actor gets to reason over. 

2.2 Pipeline and expectation-grounded credit assignment 

Algorithms 1 and 2 in Appendix A give the two loops, and Figure 1 the information flow between them. The actor owns all communication with the environment and consumes what the store returns; besides acting, it can call planning tools that both structure the task and delimit the units the critic will later judge. The critic owns the procedural write path: for each action it receives the pre-action context, the action, the actor’s committed expectation, and the realized outcome, then condenses these, proposes a better alternative, and labels the record with a reward rk ∈ { 0, 1} according to whether the outcome met the expectation and advanced the task. Two properties distinguish this from writing memory from task-level verdicts. First, the reward is per action : an action taken thirty steps in is judged on its own outcomes, so a good action inside a failed task is not penalized and a lucky one inside a successful task is not rewarded. Second, it requires no environment signal , coming instead from a comparison against a commitment made before acting, available in any environment that returns observations. That the standard is fixed before the outcome is known is what makes this more than after-the-fact self-assessment. The planning tools give the critic well-formed units to wait for (full tool specifications in Appendix E). 

Plan for the task is written before the first action and its entry is emitted at the task’s end, once every observation bearing on the plan has arrived; add sub-goal and conclude sub-goal push and pop a scope, and the sub-goal planning action’s entry takes everything between push and pop as its observations; act carries an explicit expectation and its entry is emitted after the immediate observation; think emits reasoning into short-term memory and changes nothing. Pushing and popping thus lets the actor explore the environment as a tree while giving the pending queue a natural closing condition: a record is judgeable exactly when its scope closes. Whenever the critic emits a reward it also forwards the identities of the procedural entries that were retrieved for that action — the only channel by which the store learns whether its own recommendations were any good. 

2.3 Short-term memory: scoping and compaction 

The actor needs to attend to the current goal without re-reading the whole task; the critic needs a delimited execution trace to summarize. Both are served by one structure borrowed from program execution: a running stack. The live frame holds the current sub-goal and the plan the actor made for it; turns outside it are compressed into summaries by the actor’s own LLM, so the actor sees the current scope at full resolution and everything above it compressed, and resumes the parent objective when the frame is popped. Sub-goal and task boundaries are also scope boundaries in the memory-safety sense. Popping a sub-goal compresses its turns, so raw observations from a concluded scope are no longer verbatim in the actor’s context; ending a task clears short-term memory entirely, 4and nothing survives into the next task except what the critic or the semantic/episodic summarizer wrote to the long-term store. Cross-task carryover is therefore mediated by summarization rather than by raw trajectory, which bounds context growth and, as Section 4 discusses, what raw environment text can reach a later task. 

2.4 Long-term memory: retrieval, utility, and life cycle 

The store holds M and owns both retrieval and the entry life cycle. • Retrieval. Semantic and episodic entries are retrieved by dense similarity to the current context. Procedural entries are ranked by a product of their estimated utility and their context similarity, defined below, so that an entry must be both relevant and previously effective in order to be surfaced. Procedural entries are additionally hard-scoped by the action space they were recorded under: an entry is eligible only when the set of legal tools matches, so advice formed in one action space is never surfaced in another. • Consolidation. Two procedural entries are merged into one when the retriever cannot distinguish them: we score a pair by how often they are retrieved together among the rounds in which either one is retrieved, and merge above 1 − ϵm, once at least one of the two has accumulated enough retrievals for that rate to mean something. Scoring on co-retrieval rather than on raw round-by-round agreement is what keeps two merely cold entries from looking mutually indistinguishable. Semantic entries are consolidated differently — an LLM edits the existing entry when a new fact refines or contradicts it, rather than appending a second entry. • Forgetting. Once an entry has been resident long enough for its statistics to be meaningful, it is removed from the retrieval index if its retrieval frequency falls below a threshold ϵe > 0.Because ranking is utility-weighted, an entry whose utility estimate has fallen stops being retrieved and is then evicted; low utility causes forgetting through the retrieval channel rather than by a direct reward threshold. This is the system’s forgetting policy, and its absence is, we argue in Section 3, a large part of why unmanaged procedural memory ends up below a memoryless baseline. • Provenance. Each procedural entry retains its originating context and action, the critic’s reflection, its binary success label, and its current utility, so it is traceable to the action that produced it and inspectable as text — which is how the failure modes in Section 3 were identified. Retrieval is thus the hinge of the life cycle: consolidation and forgetting are both computed from retrieval statistics, so we estimate, rather than assume, how useful each entry is. # 3 Experiments 

3.1 Setup 

We evaluate AdMem under streaming multi-task conditions intended to approximate a deployed task-solving agent: the agent meets a domain’s tasks one after another in a single lifelong episode, and its long-term store is never reset between tasks. We use the eight domains bundled with AgentBoard [Ma et al., 2024], spanning embodied household tasks (AlfWorld), grid-world instruction following (BabyAI), interactive fiction (Jericho), symbolic planning (PDDL), tool calling (Tool-query Academic and Weather), web navigation (WebShop), and scientific experimentation (ScienceWorld). Within a domain every method receives the same system prompt (Appendix E) and the unmodified AgentBoard task instructions, and is run over the full task set. We report AgentBoard’s two native metrics: task completeness C, the fraction of tasks solved, and average progress P , the mean over tasks of a per-task progress score pi ∈ [0 , 1] with pi = 0 for no progress and pi = 1 for completion. Claude Haiku 4.5 is the backbone for the actor, the critic, and the semantic/episodic summarizer in every configuration, including the baselines, so all comparisons hold the backbone fixed; decoding is greedy (temperature 0, top-p 1) and each task is capped at 30 environment steps, as recorded in the run configuration. 3.2 Cross-task memory is not free 

The headline of Table 1 is not only that AdMem leads, but where the cross-task memory baseline ends up. AWM solves fewer tasks than the memoryless ReAct control in seven of the eight domains, and 312 of 707 tasks against ReAct’s 388 — a 10 .7-point drop in pooled completeness, significant under a two-sided Fisher exact test ( p = 7 × 10 −5, Table 2). The same pattern appears inside our own system: the LTP ablation of Table 3, which keeps the procedural store, critic reflections, and reward-based utility but removes planning and scoping, solves 4 of 20 Jericho tasks against ReAct’s 

8.AWM is not mis-ported: it beats ReAct on PDDL in this very table ( 43 .3% versus 33 .3% ), so the mechanism does fire where the domain supplies reusable structure [Zheng et al., 2024, Wang et al., 2024]. Two properties of induction-from-successes explain the rest. First, AWM induces workflows online from its own trajectories, so a wrong induction — a step order that happened to work once, a precondition read as universal — is written with the same confidence as a right one, and a single pass gives no held-out signal that would catch it, a gap self-judgement cannot close [Huang et al., 2024, Stechly et al., 2025]; AdMem’s critic shares that limit, but its entries remain revisable as later outcomes update their utility. Second, AWM has no removal policy: a badly generalizing workflow stays and is re-retrieved for the rest of the run, so one bad induction is a persistent rather than transient cost. Under a coarse success signal such inaccuracies compound, and regulating entry quality rather 7than accumulating more of it recovers the loss [Xiong et al., 2026]; an inapplicable entry distracts rather than sitting inert [Shi et al., 2023]. AWM was validated on web navigation, where consecutive tasks share page structure; most AgentBoard domains lack that regularity. A streaming benchmark of self-evolving memory reports the same pattern for this class of method: AWM falls below a ReAct control on its multi-turn suite for three of four backbones ( 0.49 against 0.57 mean success on Claude 3.7 Sonnet) and below the no-memory baseline on its single-turn suite for all four [Wei et al., 2025]. The design question is therefore not how to store more experience but which to keep — which motivates the per-action credit assignment and entry life cycle of Section 2.4. 

3.3 Main results 

AdMem solves 441 of 707 tasks against 388 for ReAct and 312 for AWM (Table 2), and matches or exceeds ReAct on completeness in six of eight domains while achieving the best average progress in all eight. We treat the pooled comparison over all 707 tasks as the primary endpoint and the eight per-domain tests as a multiplicity-corrected breakdown. We read these as parity on completion with a small edge on partial progress, and note the contrast with AWM, which loses 13 .1 and 27 .8 points on the same task sets: what these columns support is that AdMem’s structure prevents the collapse unmanaged cross-task memory produces where transfer is weak, not that it gains there. These are also the domains where transferable structure is thinnest — each WebShop task targets a different product with a different attribute set, so carryover is closer to distraction than to a reusable recipe, the regime where top-ranked but inapplicable retrievals measurably hurt [Cuconasu et al., 2024]. The three 20-task domains behave as expected but carry little weight on their own — the +25 .0

points on Tool-query Academic ( 19 of 20 against 14 ) reaches only p = 0 .09 . Table 2 gives both the pooled and the equally-weighted domain average rather than the flattering one: they differ ( +7 .5

against +12 .8 points) because WebShop and ScienceWorld hold 48% of the tasks, and the pooled figure is the conservative reading. 

3.4 Which components matter 

Table 3 decomposes the system on Jericho into (i) acting and planning with short-term memory management (STP) and (ii) the long-term procedural store (LTP), and additionally streams the task set for three epochs to test whether accumulation pays off over a longer horizon. The two halves behave asymmetrically. STP raises average progress over ReAct ( 0.4553 against 0.4002 ) at equal completeness, and is single-epoch by construction: nothing crosses task boundaries, so there is no horizon over which it could improve. LTP is the weaker half in isolation — 4, 5, then 6 of 20 tasks across the three epochs, below ReAct’s 8 at every epoch. It improves with accumulation, but the trend does not carry it to the memoryless baseline within three epochs, so the long-term store on its own is net-negative on this domain rather than a transient warm-up cost. Assembled, the two halves reverse that: AdMem improves monotonically, 9 → 10 → 12 of 20 tasks, ending +20 .0 points above ReAct. This is the paper’s clearest claim about the architecture: the 8procedural store is only useful inside the planning and scoping structure, which turns a net-negative store into a net-positive one. It also answers the simpler-baseline question: LTP retains the critic’s reflections and the reward-derived utility, so it is if anything a strengthened reflection-memory agent, and it is the weakest arm in the table. With 20 tasks the per-epoch differences are individually underpowered (LTP versus AdMem at epoch three is 6 against 12 , p = 0 .11 ), and the contrast is between two halves of the system rather than individual mechanisms. 

3.5 Cost 

The design prioritizes long-horizon performance over minimal per-step cost. Multi-threading keeps memory encoding, management, and the critic’s write path off the actor’s critical path, but the pipeline still spends extra planning turns and background LLM calls. As a rough worst case, per-step wall-clock is about 2× the vanilla LLM agent’s with about 3× the LLM calls — a bound set by the easiest domains, where any fixed overhead looks large in ratio. Extra memory-side calls are not the differentiator: AWM and the LTP ablation also pay them, and both land below ReAct. 

# 4 Memory as an attack surface 

Keeping memory in readable text is what makes the diagnosis in Section 3 possible, and the same property makes the store a durable, attacker-reachable channel. The dataflow follows from the architecture: environment text enters the critic prompt as an action’s realized outcome, becomes a procedural entry, and is later retrieved into the actor’s context before it acts — so any text the environment can emit reaches a later task’s action selection, and unlike a payload confined to one context window a written entry persists and is re-retrieved. This is indirect prompt injection [Greshake et al., 2023] applied to a store the agent writes itself, close to demonstrated poisoning of agent memory and RAG stores [Chen et al., 2024]. Two of our own choices bear on this: vm = 1 grants a new entry maximum retrieval priority before any evidence exists, and the utility signal is produced by an LLM reading environment text. The life cycle also supplies the defenses — unhelpful entries are evicted, provenance is retained, tool-set scoping bounds reach, and a readable store can be audited — so eviction is a defense and vm = 1 a vulnerability within one policy. Appendix D gives the full dataflow, defenses, and caveats; we report no adversarial evaluation and make no robustness claim. 

# 5 Limitations 

Our evidence is one run per configuration on one backbone. We compensate where the data allows — completion counts on fixed task sets support Fisher exact tests and Wilson intervals — but this is not a full seed sweep, and the three 20-task domains are underpowered by construction. A caveat specific to the memory arms is that each is one coupled stream, so their binomial intervals are anti-conservative; we therefore report the variance inflation each load-bearing conclusion tolerates before crossing 

α = 0 .05 , a design effect of 4.2 for the negative result and 5.9 for the PDDL gain (Appendix C). The component ablation separates the acting/planning half from the long-term half on one domain, so we do not claim how much of the gain is attributable to expectation-grounded reward, to utility-based eviction, or to context scoping. 

# 6 Conclusion 

We asked which experience a task-solving agent should keep. Procedural memory induced from successes leaves an agent below a memoryless control on seven of eight AgentBoard domains; AdMem answers with per-action credit against a pre-committed expectation and a per-entry utility governing the entry life cycle. The mechanism that lets memory help where transfer exists is the one that keeps it from hurting where it does not.

What the model can and cannot express. Six properties should be stated plainly. First, this is a 

streaming update: one step per observed reward rather than iterating to convergence on a retained dataset, so the monotone-likelihood guarantee of batch EM does not transfer and we do not claim it. The estimator should be read as tracking a non-stationary quantity — an entry’s usefulness genuinely 15 changes as the rest of the store changes around it — rather than as maximizing a fixed likelihood. Second, retrieval only surfaces entries whose score exceeds the inclusion threshold, which bounds 

σi away from zero for exactly the entries that get updated. Third, the similarity σi is supplied by a frozen embedding model and is never itself learned, so the model can only reallocate credit among retrieved entries and cannot discover that its notion of context similarity is wrong. Fourth, vm is bounded below at 0, so the model represents an entry that never helps but not one that actively hurts. This is deliberate rather than an oversight: harm leaves the store through the retrieval channel rather than through a negative score. An entry that keeps co-occurring with failures is driven towards 0, its Equation (1) value falls with it, it stops clearing the inclusion threshold, and the frequency-based eviction of Section 2.4 then deletes it — so a harmful entry and a merely useless one receive the same treatment, which is removal, and a signed utility would only be needed if the system had to rank harmful entries against one another, which it never does. It is also worth being precise about how a failure is charged: by Equation (6) the decrement is η σ i/(1 − qi), which is not 

uniform over the retrieved set — an entry whose stored context closely matches the present one loses more than a marginally similar one, and an entry currently estimated to help loses more than one already near zero. Fifth, the update conditions on retrieval, not on use: an entry the actor ignored is credited or blamed as if it had been followed, a failure with an external cause, such as a broken tool, lowers every entry retrieved for that action, and the noisy-OR treats retrieved entries as independent causes, so overlapping or conflicting entries are not modelled as such. Finally, we read vm as the model’s estimate of the probability that an entry helps here, which is the quantity retrieval ranks by; the causal phrasing is licensed by the generative model rather than measured against an intervention, and we make no calibration claim. 

# C Pairing and clustering robustness of the pooled tests 

Two properties of the design are not captured by a Fisher exact test on a 2 × 2 table, and we bound the effect of both rather than assume them away. 

Pairing. All three methods are run over the same 707 tasks, so the pooled comparison is paired and the appropriate test is McNemar’s on the discordant pairs. We do not log per-task outcomes for the baselines, so the pairing itself is unavailable; instead we take the worst case over every pairing consistent with the observed margins. Given the two margins — 441 solved for AdMem against 

388 for ReAct — write b for the tasks AdMem solves and ReAct fails and c for the converse, so that b − c = 53 is fixed while b + c is not. The exact two-sided McNemar test, a binomial test on b out of b + c at rate 12 , is least significant when the discordant count b + c is largest, so we maximize it subject to b ≤ min(441 , 707 − 388) and c = b − 53 ≥ 0. The extreme admissible pairing is b = 319 , c = 266 , giving p = 0 .031 . The same construction for AWM against ReAct, with c − b = 76 , has extreme point b = 312 , c = 388 and gives p = 4 .6 × 10 −3; for PDDL, b = 40 ,

c = 14 and p = 5 .4 × 10 −4. Every pairing consistent with the reported margins is therefore at least this significant, so neither pooled conclusion nor the PDDL result depends on the unobserved pairing being favorable. Applying the same construction to AlfWorld gives p = 0 .096 , which is one more reason we do not rest a claim on that domain. 

Clustering within a stream. Tasks in a memory arm are not independent trials: they share one evolving store, so a single badly generalizing entry can correlate failures across the tasks that follow it. This inflates the true variance of a pooled rate by a design effect D, equivalently reducing the effective sample size to n/D , and it is precisely the mechanism Section 3 argues is operating. Rather than assume D = 1 , we report the breakdown point: dividing the observed two-proportion z by √D,the negative result for workflow-induction memory ( z = −4.04 ) crosses α = 0 .05 only at D = 4 .2,and the PDDL gain ( z = 4 .77 ) only at D = 5 .9. A design effect above 4 within a single stream of a few hundred tasks would require most of the outcome variance to be attributable to stream position, which the per-domain spread in Table 1 does not support. We note that this is a sensitivity analysis and not a substitute for replicated stream orders, which remains the right experiment. 16 D The memory store as an attack surface: full dataflow 

This expands Section 4. The write path is: environment text → critic prompt (as the realized outcome of a pending action) → procedural entry → retrieval index → actor context at some later step, possibly in a later task, where the actor is instructed to reason over the retrieved entry before choosing an action. Three properties of that path matter. It is persistent : a payload that succeeds once is stored and re-retrieved, so the cost of a single successful injection is amortized over every later retrieval, in contrast to a single-context payload. It is self-authored : no external document has to be trusted, because the agent writes the entry itself from text the environment supplied. And it is reward-coupled :the utility vm that governs retrieval, consolidation, and eviction is produced by an LLM critic reading environment text, so an adversary who can shape observations can in principle shape the signal that decides what the store keeps. Initializing vm = 1 is the choice with the sharpest two-sidedness. It is the exploration policy that lets an untried entry acquire the statistics that will keep or evict it, and it is exactly the property an attacker who can cause one entry to be written would want, since maximum retrieval priority is granted before any evidence exists. A pessimistic initialization would blunt that at the cost of never surfacing genuinely useful new entries; we did not evaluate the trade-off and note it as the obvious knob. The defenses available without adding any new machinery are the life cycle itself. Utility-weighted ranking means an entry that does not help stops being retrieved, and the frequency-based eviction of Section 2.4 then removes it, so a payload that does not produce apparent success decays. Provenance makes every entry traceable to the action, context, and reflection that produced it. Tool-set scoping bounds which later contexts an entry can reach at all: an entry recorded under one action space is ineligible in another, which limits lateral movement across domains. And because the store is human-readable text, an operator can audit and delete, which is not true of a store held in parameters or opaque embeddings. On personal data specifically, the critic prompt (Appendix E) instructs the critic to replace identifying values with placeholders before writing, which limits what crosses a task boundary. This is an instruction-level measure and not a guarantee: it depends on the critic complying, it does not cover what a summarizer writes into semantic or episodic entries, and it does not address the contextual-integrity question of which information is appropriate to carry into which later context [Mireshghallah et al., 2024]. A deployment with real users would need a mechanism rather than an instruction here.
