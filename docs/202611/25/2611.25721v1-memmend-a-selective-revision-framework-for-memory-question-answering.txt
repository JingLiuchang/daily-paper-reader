# MemMend: A Selective Revision Framework for Memory Question Answering 

Sheng Shi Geng Li 

Independent Research 

Abstract 

Revising every answer from a long-term mem-ory can consume substantial inference budget and damage facts that were already correct. We introduce MemMend, a modular selective revision framework that routes potentially in-complete answers to an editor, represents cor-rections as bounded exact-text replacements, and accepts only edits with resolvable source coordinates and valid edit operations. The ed-itor preserves the current answer when no le-gal repair is proposed; accepted edits require no additional semantic-verification call. On 1,986 LoCoMo development questions, Mem-Mend achieves 67.17 conversation-macro F1 and 88.35 mean Judge score, improving over a verified revision chain by 0.82 and 1.24 points while using 62.37% fewer revision calls. Routing uses 54.15% fewer revision calls than ungated local review, with similar F1 but a 0.67-point lower Judge score. Applied directly to native PropMem, Mem0, and Sim-pleMem answers, the editing interface raises F1 by 3.79, 6.44, and 0.42 points. It outper-forms same-gate rewriting and saves 49.85– 83.72% of editing calls relative to ungated editing, which retains higher F1 in this adap-tation. A source-by-editing factorial supports local editing for F1 but leaves an independent quality benefit from source obligations unre-solved. Transfer to 451 LongMemEval-V2 Small questions also favors revision efficiency, while an external PerLTQA dialogue subset re-veals a completeness gap. These results sup-port selective editing as a reusable quality–cost operating point. 

1 Introduction 

Long-term memory helps agents answer questions about accumulated conversations and past inter-actions. Yet retrieving a relevant record does not guarantee that the resulting answer is com-plete or correctly scoped. A response may omit one member of a set, attribute an event to the wrong speaker, or abstain despite available evi-dence. Conversely, an answer may already be adequate, and another unrestricted generation can add unsupported details or overwrite a correct fact. The decision to revise is therefore part of the mem-ory problem. Existing memory systems improve storage, re-trieval, and consolidation (Packer et al., 2023; Xu et al., 2025; Chhikara et al., 2025). Benchmarks such as LoCoMo and LongMemEval expose the difficulty of using long histories accurately (Maha-rana et al., 2024; Wu et al., 2025). After retrieval, however, additional inference still has to be allo-cated: which answers need review, how much of an answer may change, and what checks should a proposed change satisfy? Always rewriting the answer spends calls on easy cases. Independently verifying every candidate adds another cost, while a source identifier by itself cannot prove that the cited record entails the proposed claim. MemMend addresses these decisions through a conservative editing policy. It accepts a memory system’s candidate answer and original evidence, allowing the same revision interface to serve dif-ferent storage and retrieval backends. A determin-istic gate selects abstentions, list questions, and long answers for review. The editor proposes ei-ther no change or a small set of exact replace-ments, accompanied by coordinates into the avail-able original records. A program checks source resolution, anchor uniqueness, operation permis-sions, and issue-specific expansion limits. If these checks fail, the previous answer is retained after at most one corrective proposal. This design makes editing inspectable and bounds its scope without paying for a separate semantic verifier after each edit. Our evaluation distinguishes this editing inter-face from the complete upstream pipeline. 2 Related Work 

Memory organization and evaluation. Mem-ory agents organize histories as streams, hierar-chical stores, linked notes, or consolidated facts (Park et al., 2023; Packer et al., 2023; Xu et al., 2025; Chhikara et al., 2025; Liu et al., 2026). EviMem combines evidence-gap-driven iterative retrieval with hierarchical memory organization (Li et al., 2026). LoCoMo evaluates multi-session conversational memory; LongMemEval separates retrieval, temporal reasoning, updates, and abstention (Maharana et al., 2024; Wu et al., 2025). LongMemEval-V2 adds multimodal in-teraction trajectories and questions about states, changes, procedures, and flawed premises (Wu et al., 2026). PerLTQA supplies synthetic personal histories with heterogeneous memory types (Du et al., 2024). MemMend addresses revision af-ter evidence is available. We evaluate its interface with PropMem from MemEval (ProsusAI, 2026), Mem0, and SimpleMem, keeping each backend’s native answer as the starting candidate. 

Evidence and grounded generation. Retrieval-augmented generation conditions answers on ex-ternal records (Lewis et al., 2020), while retrieval granularity and context position influence which facts the model uses (Chen et al., 2024; Liu et al., 2024). Self-RAG separates retrieval and support judgments, and ALCE evaluates answer quality together with citation quality (Asai et al., 2023; Gao et al., 2023). These distinctions matter for re-vision: locating a citation is a mechanical check, whereas deciding that it supports a correction is semantic. MemMend retains that distinction and tests citation obligations directly, instead of as-suming that traceability guarantees correctness. 2Revision as a resource-allocation problem. 

Self-Refine iteratively revises outputs using model-generated feedback (Madaan et al., 2023). In memory QA, repeated generation can recover omitted information but can also replace an ade-quate answer with an unnecessary elaboration. We compare iterative revision, critique followed by rewriting, and a chain with separate semantic ver-ification under a common additional-call cap. We further compare selective and all-question edit-ing using shared outputs on their common ques-tions. This isolates the cost of reviewing more answers from stochastic differences in identical requests. The generic controls are implemented revision strategies, not reproductions of complete published memory systems. 

3 Method 

3.1 Candidate Answers and Original Evidence 

Let q be a question, a the current answer, and E =

{(si, x i)} the available evidence. A coordinate si

identifies an original conversational turn or a na-tive trajectory span or state; xi contains its text and available metadata or images. A source resolver maps a cited coordinate back to this record. Mem-Mend operates on (q, a, E) and can also use an ear-lier answer retained by the upstream pipeline. It does not require reference answers or benchmark category labels. Our main conversational configuration retrieves raw sessions with BM25, selecting five seed ses-sions and their immediate neighbors within a char-acter budget. A Raw Session Reader produces an answer, followed by conditional List Refinement and Scope Checking (SC), then Premise Guard (PG). PG reviews factual premises and may re-place an answer with an abstention when its source and conflict checks succeed; it does not freely rewrite factual content. The evaluated main con-figuration then permits Answer Restoration (AR): if PG abstains and the saved SC answer is eligi-ble, one independent support check may restore that exact answer. AR generates no new candidate text. This upstream configuration is fixed in the main conversational comparisons. The native-answer adapter instead preserves a backend’s answer and resolves its retrieved memories to their original conversational sources. It applies the gate, edi-tor, and acceptance checks directly, without SC, PG, or AR. The LongMemEval-V2 adapter simi-larly starts from a fresh Reader answer over fixed trajectory messages and images. All adapters pre-serve source coordinates; the upstream stages are configuration choices rather than interface require-ments. 

3.2 Selective Routing 

The gate g(q, a ) uses inexpensive, deterministic cues. It first protects explicit negative answers consisting of “No” with optional periods, excla-mation marks, or whitespace. Otherwise it routes an existing abstention, a list-oriented question, or an answer longer than 20 whitespace-delimited words: 

g(q, a ) = ¬n(a) ∧ u(a) ∨ ℓ(q) ∨ (|a|w > 20) .

(1) Here n recognizes the protected negative form, u

recognizes explicit abstention expressions, and ℓ

applies English surface rules for quantities, sets, and shared attributes. This gate prioritizes likely omission or scope problems; it is not a learned un-certainty estimate. Answers with g = 0 retain the current candidate without an editor call. Ap-pendix A gives the operational rules. 

3.3 Source-Linked Local Corrections 

For a routed answer, the editor returns either KEEP 

or EDIT . A correction specifies an issue, one to three anchor–replacement pairs ∆ = {(uj , v j )},and one to twelve source coordinates. Each nonempty anchor uj must occur exactly once in the original candidate, and the anchor spans must not overlap. The program constructs a′ = ∆( a) by replacing spans from right to left. This represen-tation leaves all text outside the nominated spans unchanged. Permitted issues include omitted qualifiers or set members, temporal precision, speaker attri-bution, incorrect facts, unsupported abstention, language mismatch, and missing preference rea-sons. Some require additional bounds: qualifier, temporal, speaker, and preference-reason repairs may add at most 6, 8, 4, and 8 distinct normal-ized words, respectively. Other issue types re-tain the anchor and operation checks without these word caps. A repair of an existing abstention must explicitly identify that issue; an ordinary edit may not introduce a new refusal. 4 Experiments 

We evaluate whether selective editing improves on the shared candidate and stronger revision con-trols; whether routing allocates work usefully; which effects come from source obligations ver-sus local editing; and whether the policy transfers across memory backends, evidence formats, and dialogue sources. 

4.1 Evaluation Protocol Data and scope. The main study uses all 1,986 questions from ten LoCoMo conversations (Ma-harana et al., 2024). A separate factorial re-generates answers on the same questions. The trajectory study uses all 451 LongMemEval-V2 Small questions, comprising 211 Enterprise and 240 Web questions (Wu et al., 2026). Both collec-tions were previously used for development; they support controlled mechanism and transfer com-parisons, not independent-source generalization. An external evaluation uses a fixed 200-question PerLTQA dialogue subset from 31 character histo-ries, with no prior use found in the available local development records. Its inputs exclude reference-memory pointers and answer anchors. 

Models and metrics. All new Reader and ed-itor calls use gpt-5.6-sol with low reason-ing and a 2,400-token output cap. LoCoMo uses 4conversation-macro word-set F1 and the MemEval Judge rubric (ProsusAI, 2026): separate binary ac-curacy, relevance, and completeness scores, av-eraged over questions, with their mean reported as Judge. Scores are on a 0–100 scale. The Judge is gpt-5.2 with no reasoning; PerLTQA uses the same rubric and character-macro F1. LongMemEval-V2 uses native final-answer ex-traction and native accuracy: 295 rule-graded and 156 model-graded questions, with gpt-5.2 at medium reasoning for the latter. These Judge set-tings and metrics are distinct. Model snapshots and scoring details appear in Appendix B.1. 

Comparators and uncertainty. Within the main and factorial studies, arms share fresh upstream answers and evidence. Controls in-clude the scope-checked answer, PG, a veri-fied abstention/restoration/editing chain, three-step iterative revision, and critique followed by rewriting under the same three-call revision cap. Direct-edit ablations remove AR, routing, or issue-specific added-word bounds. Identical re-quests reuse the same outputs and are charged to each standalone policy. We report success-ful logical Reader calls; Judge and historical retrieval costs are excluded. Paired 95% in-tervals use 50,000 whole-conversation bootstrap draws for LoCoMo and whole-character draws for PerLTQA. LongMemEval-V2 uses question re-sampling within each domain. Intervals condition on fixed outputs, are exploratory, and have no mul-tiplicity adjustment. 

4.2 Conversational Quality and Revision Cost 

Table 1 reports the prespecified main configu-ration. MemMend improves over PG by 3.78 F1 points ( [2 .92 , 4.60] ) and 6.04 Judge points ([4 .86 , 7.11] ). It also improves over the verified chain by 0.82 F1 ( [0 .12 , 1.56] ) and 1.24 Judge ([0 .69 , 1.90] ), using 938 rather than 2,493 revi-sion calls. This is a 62.37% reduction in revi-sion calls; including the shared upstream, the re-duction is 24.46% (4,802 versus 6,357). Both generic revision controls use all 5,958 available additional calls and have lower aggregate F1 and Judge scores. The observed gain thus comes with less revision work than these controls, rather than a larger inference budget. Category results reveal a tradeoff: MemMend improves ordinary-question F1 over PG but re-duces category-5 abstention performance. Iter-ative revision also has higher ordinary-question Judge despite lower F1 (Appendix B.2). 

Component deletion. Removing independent AR gives 67.20 F1 and 88.37 Judge with 909 revi-sion calls. AR changes 35 intermediate candidates but only three final answers; these results do not establish its necessity. The editor still receives the saved SC answer without AR. We retain the pre-specified main row and report this simplification separately. Removing added-word bounds gives 66.83 F1 and 88.18 Judge; both paired differences have intervals crossing zero. 4.3 Revision across Memory Systems 

We evaluate PropMem (ProsusAI, 2026), Mem0 (Chhikara et al., 2025), and SimpleMem (Liu et al., 2026) on the same 1,986 LoCoMo ques-tions. Table 2 compares their saved native an-swers with the registered MemMend full config-uration. MemMend’s 67.17 F1 and 88.35 Judge exceed PropMem’s 62.13 and 80.72; these system-level results use different upstream representations and budgets. To test the editing interface, we preserve ev-ery native answer and expose the same resolved source ancestry to MemMend selective patching, ungated patching, and same-gate rewriting. No conversational preparation or restoration is added. All four arms are complete for all three backends; this study reports full-cohort F1, with Judge scor-ing pending (Appendix C.1). Selective patching improves native F1 by 3.79, 6.44, and 0.42 points, respectively; all three paired 95% intervals are above zero (Table 3). It also exceeds same-gate rewriting by 1.04, 0.85, and 0.42 points. Ungated patching has higher F1, whereas selection saves 54.15%, 49.85%, and 83.72% of editing calls. Thus the interface trans-fers a quality–cost tradeoff across these backends. Native-to-edited gains include rereading original sources; the patch-versus-rewrite control holds source access and routing fixed.

4.5 Source Obligations Versus Local Editing 

A separate fresh generation crosses two editor choices: required source coordinates versus no ci-tation obligation, and local patches versus whole-answer rewriting. The four arms share their up-stream answer, restoration, evidence, and gate; each routes the same 886 questions. Remov-ing the citation obligation leaves the original ev-idence available. The locality intervention jointly changes repair instructions, exact anchors, and ex-pansion bounds. Table 4 reports this cohort sepa-rately from the main experiment. Local editing improves F1 by 0.819 points on average over rewriting; its Judge effect is un-resolved. Requiring coordinates has a −0.183 -point marginal F1 effect and no clear Judge ben-efit. A separate blinded model audit on 250 pre-selected questions finds a −0.205 -point source effect on unsupported additions, with an inter-val of [−0.890 , 0.438] . These results support lo-cal editing for lexical overlap, while leaving in-dependent support gains from source obligations unestablished. Source coordinates remain useful for locating and inspecting proposed repairs. Ap-pendix B.3 reports all factorial contrasts, interac-tions, and the audit protocol.

4.7 External Dialogue Boundary 

On the fixed PerLTQA dialogue subset, Mem-Mend scores 20.65 F1 and 46.83 Judge, above PG’s 18.54 and 41.50. Iterative revision is stronger at 25.92 F1 and 51.50 Judge, including higher completeness (30.50 versus 22.00). MemMend uses 133 revision calls versus 600, or 569 versus 1,036 calls including the shared upstream. This external result supports a cheaper operating point but shows that restrictive editing can leave sub-stantial information unrecovered. Appendix B.5 reports all arms and the subset construction. An additional coverage-planning attempt also failed to improve the selected policy and is retained in the appendix. 

5 Conclusion 

MemMend allocates revision selectively and ex-presses corrections as source-linked exact edits. On matched LoCoMo comparisons, it improves over a verified revision chain while reducing calls. Routing preserves most observed quality at lower cost, and the policy transfers to fixed native trajec-tory evidence with few substantive changes. Ap-plied to native PropMem, Mem0, and SimpleMem answers, the same editing interface improves F1 and outperforms same-gate rewriting, while un-gated editing retains higher F1 at greater call cost. Factorial controls favor local editing for F1 but do not establish independent quality gains from citation obligations. The external dialogue re-sult identifies completeness as a remaining obsta-cle. Limitations 

The decision to revise still has substantial room for improvement. Surface rules can miss short but in-correct answers and over-select long yet adequate ones; calibrated, task-adaptive routing could better balance omission risk and computation. Exact-text patches restrict drift but can be too rigid when an answer requires reorganization or synthesis across many records. Future work should choose edit scope adaptively while preserving already sup-ported content. Source resolution also leaves se-mantic support unresolved: a valid coordinate can-not certify speaker identity, temporal scope, or cross-modal entailment. More reliable support as-sessment and better recovery of missing evidence remain necessary, especially when text and images conflict. Finally, explicit abstentions and negative answers require finer distinctions between missing information and a contradicted premise, so that preserving an answer does not also preserve an avoidable error.

A Implementation Details 

Evidence adapters. Conversational retrieval uses SQLite FTS5 Porter BM25 over raw session text. Five seed sessions are expanded with immediately adjacent sessions, retaining whole sessions within a 240,000-character input bud-get. Retrieval does not use reference answers, extracted answer propositions, or benchmark labels. List Refinement and Scope Checking run conditionally on list-routed questions; other ques-tions retain the preceding answer at these stages. Session/turn coordinates and dialogue identifiers resolve to original speaker, text, and timestamp records. The trajectory adapter instead retains native trajectory/state text and image coordinates; retrieval-agent analysis may provide context but is not treated as a citable original record. 

Gate and proposal contract. The protected negative pattern matches case-insensitive “No” followed only by whitespace, periods, or ex-clamation marks. Abstention patterns include 

None , UNKNOWN , “not stated,” “not mentioned,” “not specified,” “not available,” “insufficient infor-mation/evidence,” and “no evidence/information.” List routing uses surface expressions such as “how many,” “what are,” shared/both/in-common con-structions, and selected plural forms following “what” or “which.” These rules use the question and current answer, never the target or a question category. A valid KEEP has a nonempty reason and re-quires no source coordinates. An EDIT has one to three nonempty original anchors, each unique and changed, with disjoint spans and one to twelve valid source coordinates. Aliases are normalized and duplicate coordinates removed. The con-structed answer must be nonempty and at most 8,000 characters. Added-word caps count distinct lowercase regex words newly introduced relative to the current answer: 6 for a missing qualifier, 8 for temporal precision, 4 for speaker attribu-tion, and 8 for a preference reason. Set comple-tion, wrong-fact repair, unsupported abstention, and language correction have no such word cap, while retaining other edit checks. The original candidate remains the anchor text for a corrective proposal. Failed network requests do not count as successful KEEP decisions. 

Upstream restoration and verification controls. 

PG skips existing abstentions, explicit negative answers, and hypothetical questions. Its factual-premise review can retain the answer, request a local evidence lookup, or propose abstention sub-ject to source, quote, speaker, and conflict checks. AR nominates the exact saved SC answer only when the current PG candidate is None and dif-fers from SC, and the saved SC answer is factu-ally eligible for review. It restores SC only af-ter a successful independent support check. The no-AR ablation removes that call while retaining SC in editor context. The verified-chain compara-tor instead includes Verified Abstention Review (VAR), AR, and Verified Completion and Recov-ery (VCR), whose proposed changes receive se-9mantic verification within the common revision-call cap. The selected direct editor removes VAR and post-edit VCR verification; it does not remove the upstream AR verifier from the registered main configuration.

B.1 Protocols and Cost Accounting 

The conversational experiments use the gpt-5.6-sol Reader (gpt-5.6-sol-2026-07-09 , low rea-soning) with an output limit of 2,400 tokens per call. In the main conversational study, each revision policy has at most three additional Reader calls after the shared upstream pipeline. Direct editing allocates at most one call to Answer Restoration (AR) and two proposal attempts; unused slots are not reassigned. Iterative revision uses three successive revision calls, while critique and rewrite uses the same call cap. The verified revision chain applies Verified Abstention Review (VAR), AR, and Verified Completion and Recov-ery (VCR), including semantic verification. These are implemented controls with shared evidence and budgets. Fresh conversational upstream answers use question-based BM25 session retrieval followed by the Raw Session Reader, List Refinement, Scope Checking, and Premise Guard (PG). Within each experiment, policies share upstream answers and original evidence. The direct-revision study and the source/locality factorial generate separate upstream answers on the same 1,986 LoCoMo questions; their scores are therefore reported sepa-rately. The routing study reuses the direct-revision study’s fixed AR candidates and ungated editing outputs. The blinded audit samples the factorial’s outputs. A separate coverage-planning calibration generates another matched output cohort on 150 questions. All ten LoCoMo conversations were previously used for development. Conversational F1 is word-set overlap, aver-aged within each source group and then equally across groups. The gpt-5.2-2025-12-11 

Judge separately scores accuracy, relevance, and completeness; Judge mean averages these three question-level scores. Conversational scoring uses no reasoning and a 512-token output limit, with the fixed recognized-refusal rule for empty ref-erences. This common rubric is distinct from PerLTQA’s official metrics. Paired intervals use 50,000 whole-source-group bootstrap draws. Lo-CoMo has ten groups and the external PerLTQA subset has 31. Intervals condition on the generated answers and are exploratory, without multiplicity correction. Extra-call counts include successful logical re-vision work, including AR when present. Shared stages are charged to each standalone policy but executed only once when identical requests can be reused. The common LoCoMo upstream uses 3,864 calls in the direct experiment and 3,879 in the factorial; the PerLTQA upstream uses 436. These common-pipeline counts are not the min-imal deployment cost of Scope Checking alone. Token totals sum input and output tokens, with reasoning tokens already included in output. They measure algorithmic resource use, not prices or end-to-end latency.

C.2 Source Expansion with a Common Reader 

The earlier source-expansion experiment replaces the native answer with a fresh common Reader answer over the same original-record ancestry used by both downstream editing arms. Native summaries are omitted from that Reader’s in-put. Source MemMend and source ungated review then apply selective and ungated patching to this new candidate, without conversational restoration stages. All twelve backend–policy combinations have complete F1 and Judge scores (Table 15). Relative to the common Source Reader, selec-tive editing adds 0.59, 0.70, and 0.79 F1 points for PropMem, Mem0, and SimpleMem, and 1.07, 1.21, and 1.28 Judge points. Ungated review has higher Judge scores than selective editing on all three backends. Source expansion itself changes both representation and Reader behavior: Prop-Mem’s F1 drops from 62.13 to 51.06, despite 15 a Judge increase from 80.72 to 84.09. Mem0 and SimpleMem instead improve on both metrics. These differences motivate evaluating the native-answer interface separately, rather than assuming that replacing compressed memories with their sources always helps. The complete MemMend result of 67.17 F1 and 88.35 Judge retains its orig-inal pipeline and saved outputs; it is excluded from these within-backend editing contrasts and has a different total inference budget. 

C.3 Fixed-Output Gate Sensitivity 

This retrospective analysis retains all ten develop-ment conversations and replays the exact shared AR candidate and ungated patch outcome. No new Reader or Judge call is made. We delete each of the gate’s three OR terms separately and vary the strict whitespace-word length threshold to 10, 30, or 40.
