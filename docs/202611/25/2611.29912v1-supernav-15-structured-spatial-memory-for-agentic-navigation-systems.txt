Abstract 

This paper addresses the challenge of scene-level memory design for efficient navigation across sessions and succes-sive object goals. Recent methods commonly represent a scene using scene graphs or image–text records. How-ever, dense scene-graph representations impose substan-tial reasoning and context overhead on multimodal large language models, while image–text records cannot be di-rectly converted into executable geometric routes. To ad-dress these limitations, we propose SuperNav-1.5 , an agen-tic navigation system equipped with a structured spatial memory constructed by the agent. The memory consists of an area-segmented occupancy map annotated with agent-maintained, map-grounded memory nodes. This map guides the agent toward unvisited areas and provides executable routes to known locations. For multi-session navigation, we introduce agent-guided relocalization, whereby the agent infers an area prior from current observations and stored memory records to constrain geometric matching and lo-calize the robot within the stored map. Together, these de-signs enable efficient navigation across session and suc-cessive object goals. Experiments show that our method outperforms baselines on single-object, multi-object, and demand-driven navigation benchmarks, with particularly strong gains in path efficiency. Multi-session evaluation demonstrates that the constructed memory can be reused, while deployment on a real quadruped robot further shows the system’s applicability. 

1. Introduction 

Reliable navigation requires understanding current observa-tions and remembering the environment beyond the robot’s immediate view. For instance, within a single search, a robot should distinguish explored from unexplored areas to avoid redundant exploration [4]. Across successive goals or repeated visits, it should reuse past experience to reach re-membered destinations efficiently [3]. Together, these set-tings require persistent spatial memory that is both easy for 1arXiv:2611.29912v1 [cs.RO] 23 Nov 2026 an agent to query and geometrically grounded for naviga-tion. Existing approaches to spatial memory broadly fall into two categories: graph-based representations and recallable image–text records. Graph-based spatial memories provide explicit structure but can be costly for an agent to process. Scene graphs organize objects and rooms as nodes con-nected by relational edges [27], while observation-based topological memories retain visual features from past ob-servations [7, 13]. As exploration adds nodes and relations, exposing the full accumulated representation can increase context and reasoning costs, motivating selective memory access [7]. The challenge is to expose useful spatial knowl-edge without overwhelming the agent with scene detail. Recallable image–text records provide access to past vi-sual observations and textual summary [14, 15]. Although these systems retain spatial evidence, retrieving an image or textual record does not by itself specify a traversable route to a distant destination. The remaining challenge is there-fore to couple compact semantic recall with a geometric representation that can provide executable navigation route. We introduce SuperNav-1.5 , an agentic navigation sys-tem with structured spatial memory that the agent selec-tively constructs and uses. Our key insight is to use a ge-ometric map as the spatial backbone while letting the agent decide where to retain useful memories. During navigation, a real-time two-dimensional simultaneous localization and mapping (SLAM) system [10] builds an occupancy map partitioned into areas. The agent adaptively creates memory nodes at selected map locations, grounding retained scene information in a shared spatial reference. This design sim-plifies memory access and management, while grounding memory nodes in the map enables efficient navigation to known areas. This structured spatial memory supports both explo-ration and navigation to remembered locations. During ini-tial exploration, the occupancy map distinguishes explored from unexplored areas, guiding the agent toward unvisited regions. To reach an unvisited area or revisit a remembered location, the agent selects the corresponding destination on the map. A map-based geometric tool then plans and ex-ecutes the route, avoiding the need for the agent to infer step-by-step semantic instructions. When reusing memory across navigation sessions, the robot must first determine its location within the stored map. Our agent-guided relocalization combines agent reasoning with geometric relocalization to estimate this location us-ing limited geometric observations from the current session. Once relocalized, the system reuses stored memory nodes and map geometry to navigate to subsequent goals. Experiments evaluate SuperNav-1.5 on single-object, multi-object, demand-driven, and multi-session navigation. On HM3D-OVON [29] val-unseen, our method achieves an 80.00% success rate at the 1 m evaluation threshold, out-performing the reported baselines. On Habitat-GS [24] multi-object tasks, it improves success weighted by path length (SPL) from SuperNav’s 0.1388 to 0.2494. In second-session navigation from a different spawn position, mem-ory reuse raises SPL from 0.4364 to 0.5022 compared with the no-memory setting. These results support the value of geometry-grounded memory for long-horizon navigation and multi-session reuse. Our contributions are threefold: • A structured spatial memory with agent-selected nodes grounded in a persistent two-dimensional occupancy map, linking scene recall to navigable locations. • An agent-guided relocalization method that locates the robot in a stored map using limited geometric observa-tions from the current session. • A unified agentic navigation system integrating map-guided exploration, geometric navigation, and relocaliza-tion for long-horizon navigation and multi-session mem-ory reuse. 

2. Related Work 

2.1. Map-guided Navigation Systems 

Map-guided systems ground exploration decisions in spa-tial representations. SemExp [4] and L3MVN [30] use se-mantic maps for learned or language-guided exploration. InstructNav [16] and VLFM [28] ground decisions in value maps. ApexNav [36] combines adaptive seman-tic and geometric exploration with target-centric fusion, while VoroNav [23] selects waypoints on a reduced Voronoi graph. However, exploration-oriented map states alone do not provide task-independent scene memory or sup-port multi-session reuse. We couple geometry with agent-selected memories and relocalization to support memory reuse beyond the current search. 

2.2. Agentic Navigation Systems 

Agentic navigation systems pair pretrained reasoning mod-els with perception and navigation tools. SuperNav [35] provides navigation skills and a visual-point interface for the reasoning model, while DemandAgent [2] introduces an embodied agent harness for interpreting high-level hu-man demands. AgenticNav [14] and NavProbe [15] ex-pose selective visual or geometric evidence-retrieval tools to the agent. Recent systems further incorporate persistent state and memory [5, 37]. Although these systems establish flexible agent–environment interaction, an agentic interface alone does not determine how long-term spatial informa-tion is managed. 2.3. Spatial Memory for Long-Horizon Navigation 

Spatial memory supports experience reuse across succes-sive goals. GOAT [3], SG-Nav [27], and SysNav [38] use instance-aware memory, scene graphs, or structured room-level representations. MemoNav [13] selects infor-mative topological features, while EvoMemNav [7] com-bines per-visit visual nodes over an occupancy grid with budgeted retrieval and reflection-driven updates. Memory is also central to recent agentic systems. AgenticNav [14] and NavProbe [15] retain visual or geometric evidence for later retrieval. HarnessVLN [5] maintains event memory and a spatiotemporal graph while NavHarness [37] pre-serves maps and task knowledge across sessions. Existing designs therefore span retrieval-oriented records and struc-tured topological or scene graphs. The former do not neces-sarily provide executable geometric route towards destina-tions, whereas the latter require maintaining relational state. In contrast, we represent spatial memory as map-grounded nodes without explicit graph edges and couple them with relocalization and geometric navigation, making selected memories directly actionable across sessions. 

3. Method 

SuperNav-1.5 equips the agentic navigation framework of SuperNav [35] with persistent structured spatial memory for multi-object and multi-session navigation. Given a navigation request and online observations, the agent uses this memory to select unexplored areas or recall previ-ously visited destinations. The key design is to let the oc-cupancy map encode navigable geometry while the agent decides which scene information to retain, connecting se-mantic decisions to executable geometric goals. As shown in Fig. 2, our system separates the memory representation (Sec. 3.1), its construction (Sec. 3.2), and its use for navi-gation (Sec. 3.3). 

3.1. Structured Spatial Memory 

Our structured spatial memory is designed to make se-mantic information manageable for the agent while sup-porting executable geometric routes. It is represented as an occupancy map annotated with agent-maintained, map-grounded memory nodes. The annotated two-dimensional occupancy map provides a unified interface through which the agent accesses spatial memory (Fig. 2a). The map displays color-coded areas, the current robot pose, and two types of markers: automatically generated unvisited-area entries and agent-maintained memory nodes. The unvisited-area entries describe areas observed from nearby but not yet represented by an agent-created memory node, preserving incidental observations as leads for further exploration. Each agent-maintained memory node contains a name , a scene description , factual records , and a SLAM pose (x, y, θ ). The node name supports direct lookup, the 3description and records preserve scene information, and the pose anchors that information to geometric navigation. A dictionary maps each displayed marker identifier to its cor-responding memory-node name or area entry. Together, these annotations let the agent distinguish remembered lo-cations from areas awaiting exploration and select destina-tions in a shared spatial reference. 

3.2. Memory Construction 

The structured spatial memory consists of an underlying geometric map and area annotations. The geometric map is constructed asynchronously as the robot moves. The agent manages memory nodes through tool calls, whereas descriptions of unvisited areas are generated automatically for regions observed in passing but not yet explored. 

Asynchronous geometric mapping. The occupancy map provides a continuously updated geometric foundation in-dependent of the agent’s memory decisions. During navi-gation, Cartographer [10] asynchronously integrates depth or LiDAR observations with odometry to estimate the robot pose and construct an occupancy map. Watershed seg-mentation [21] partitions the map into areas, which are assigned distinct colors for the agent-facing visualization (Fig. 2c). By explicitly encoding spatial relationships, the resulting map frees the agent from managing them directly and guides it toward unvisited areas. Further details of the geometric mapping procedure are provided in the supple-mentary material (Sec. 8.1). 

Agent-maintained memory nodes. The agent controls which observations become persistent memory through node-creation and update tools. It can create a named node with a description and factual records, or revise an existing node as new information becomes available. After either operation, the affected node is automatically bound to the robot’s current SLAM pose. This node-management mech-anism allows the agent to selectively record important se-mantic information while preserving a geometric location for each node. Further details of the memory-node design are provided in the supplementary material (Sec. 8.2). 

Descriptions of unvisited areas. Intermediate observa-tions encountered during movement may contain useful information and should therefore be retained. However, for efficiency, agentic navigation systems commonly re-turn only the final observation from a movement-tool call to the reasoning model [14, 35]. We therefore record keyframe images and their poses during execution and asyn-chronously caption them with Qwen3.5-2B [18] (Fig. 2c). These captions provide textual evidence about areas that the agent has not explicitly visited. For each unvisited area a, we use geometric visibility to select a representative caption. 3.3. Navigation with Memory 

The agent uses spatial memory for navigation through three operations. Agent-guided relocalization localizes the robot within the stored map, enabling memory reuse across ses-sions. Memory lookup retrieves information about remem-bered places and objects by name or keyword. Geometric navigation then executes an efficient route to the selected destination. 

Agent-guided relocalization. Reusing spatial memory across sessions requires aligning the robot’s new local map with the stored scene map. At the start of a session, limited geometric observations can make global matching ambigu-ous when several areas share similar layouts. To reduce this ambiguity, the agent compares current observations with stored memory descriptions and records to infer its likely area in the prior map (Fig. 2b). This semantic area prior is then used to constrain geometric matching. We crop the prior occupancy map to the inferred area and match the current local map against this crop. The re-sulting planar rigid transform bTprior ←new maps the robot’s current pose into the stored map’s coordinate frame, making prior memory locations available for navigation. Restrict-ing the match to the inferred area reduces ambiguity from geometrically similar regions elsewhere in the scene. The detailed relocalization algorithm and acceptance criteria are provided in the supplementary material (Sec. 8.3). 

Memory lookup. The agent retrieves scene information either by node name or through keyword search over stored text. Direct lookup returns the named node’s contents, while keyword lookup returns text-matching entries, as il-lustrated by the grep example in Fig. 2b. This allows the agent to inspect relevant descriptions and factual records be-fore selecting a destination, without loading the full mem-ory into its context.

4.5. Ablation Study 

We conduct three complementary ablation analyses. Us-ing 40 tasks randomly sampled from the Habitat-GS single-object split under the changed-spawn multi-session setting, we first quantify the contributions of the major system com-ponents and assess compatibility across reasoning models (Tab. 6). We then compare our structured spatial memory with an alternative memory design on all 150 Habitat-GS multi-object tasks. 

Main component ablation. For the component ablation, we retain GPT-5.6-terra as the reasoning model. We first assess whether structured memory nodes must be cou-pled with a geometric map. Removing agent-maintaned memory nodes while providing the plain occupancy map reduces SR by 5 points and SPL by 0.0695, providing di-rect evidence that structued semantic information benefits multi-session navigation. Removing the annotated occu-pancy map and the geometric navigation tool for reaching stored locations, while retaining the memory-node tools, re-duces SR from 82.50% to 70.00% and SPL from 0.5329 to 0.3563, demonstrating the importance of explicit geometry for efficient memory reuse. We next assess the contribution of agent-guided relocal-ization. The w/o reloc variant disables both geometric and agent-guided relocalization, leaving the agent with only the static prior map and memory nodes. Its SR and SPL de-crease to 72.50% and 0.3622, respectively, indicating that geometrically localizing the robot within the prior map is necessary for multi-session navigation. The w/o agent-guided reloc variant retains global geometric relocalization but removes agent guidance. Its lower SR and SPL show that the agent-provided area prior further improves multi-session navigation.

4.6. Real-World Demonstrations 

We further deploy SuperNav-1.5 on a Unitree Go2 in in-door environments. Fig. 5 shows three qualitative results. The first two examples demonstrate multi-object navigation and memory-guided returns to previously observed targets over extended trajectories. The third shows demand-driven navigation. The robot can interpret “thirsty,” locate a wa-ter dispenser, and then use memory to return to its starting area. These qualitative results demonstrate the feasibility of structured memory and geometric execution on a physical platform. 

5. Conclusion 

We propose SuperNav-1.5, an agentic navigation system equipped with structured spatial memory for efficient navi-gation across sessions and successive object goals. The an-notated occupancy map provides a unified interface through which the agent accesses spatial memory, while agent-maintained memory nodes selectively retain scene knowl-edge. Experiments on instance-navigation and demand-driven benchmarks, as well as in multi-session settings, show that our method achieves higher success rates and greater path efficiency.

6. Evaluation Protocols 

6.1. Shared Evaluation Controls 

Unless stated otherwise, all navigation experiments use 

GPT-5.6-terra with high reasoning effort. Alternative-model ablations retain high reasoning effort and change only the policy model. Each episode is run once in an iso-lated session. The agent receives only the public task in-struction, RGB observations, and tools enabled for that con-dition. Target coordinates, evaluator geometry, approved viewpoints, reference paths, and success feedback remain hidden from the agent. An episode is complete only when the agent issues an explicit S TOP action. Failed episodes because of infrastruc-ture failures, such as simulator or upstream model provider errors, are retried. 

6.2. Dataset-Specific Evaluation 

InteriorGS single-object navigation. An episode suc-ceeds when the agent issues S TOP and its final saved posi-tion is at a navmesh-geodesic distance strictly below 1.0 m 

from at least one approved viewpoint for the target. Only the final position determines success. Encountering the tar-get earlier does not count if the agent subsequently moves away. We report success rate (SR) and success weighted by path length (SPL), where the per-episode SPL is 

SPL i = Si

max( Li, P i) . (2) Here, Si is the binary success indicator, Li is the frozen shortest-path reference distance, and Pi is the accumulated length of the saved trajectory through S TOP . We compute path length directly from consecutive saved poses without trajectory interpolation. All methods are evaluated with a 3600 s time budget. 

InteriorGS ordered multi-object navigation. Targets must be completed in the specified order. The evalua-tor scans the saved trajectory chronologically and com-pletes the active target at the first recorded position whose navmesh-geodesic distance to an approved target viewpoint is strictly below 1.0 m . A single position may complete multiple consecutive targets when it lies within all corre-sponding acceptance regions. Visiting a later target before it becomes active does not complete that target. Full-task success requires completing every target and then issuing STOP . All methods are evaluated with a 3600 s time bud-get. Besides full-task SR and sequential SPL, we report the ordered completion fraction and prefix metrics SR k and 

SPL k. The k-th prefix cohort includes every episode con-taining at least k targets, rather than only episodes contain-ing exactly k targets. 

Demand-bench. Demand-bench evaluates roles in the se-rialized order of the released goal graph . At every saved pose, including the initial pose, the evaluator considers only the active role and selects its nearest unused admissible object. Exact distance ties are resolved by object iden-tifier. Distance is measured in the horizontal plane from the agent’s (x, z ) position to the nearest point on the ob-ject’s runtime AI2-THOR axis-aligned bounding-box foot-print. The active role is completed when this distance is at most 2.0 m . An object cannot satisfy more than one role, although one pose may complete several consecutive roles using different objects. Acceptance depends only on this geometric rule. Full-task success requires completing every role and issuing STOP . Path length is accumulated in the horizontal plane, and SPL uses the frozen globally optimal route for the com-plete task. All methods are evaluated with a 3600 s time budget. 

HM3D-OVON. Success is determined by the minimum navmesh-geodesic distance from the final saved position to any approved viewpoint of any instance belonging to the target category. We report SR and SPL at the strict navmesh-geodesic threshold d < 1.0 m , requiring an ex-plicit S TOP . For SPL, the reference length is the start-to-goal navmesh-geodesic distance stored in the original HM3D-OVON episode, whereas the executed path length is accumulated over the complete saved trajectory from the initial position to the pose at which S TOP is issued. Three episodes contain targets that are unreachable on the navigation mesh. We count these episodes as successful and assign each an SPL of 1. 

6.3. Multi-session Evaluation Protocols 

We evaluate multi-session performance on all 150 episodes in the Habitat-GS single-object split. Each episode com-prises two sequential sessions. Unless an experimental con-dition explicitly disables memory, Session 2 receives the spatial memory frozen at the end of Session 1, including the occupancy map and associated memory nodes. We consider two Session 2 spawn settings: the unchanged-spawn setting reuses the Session 1 spawn position, whereas the changed-spawn setting uses a different position. For each episode, 1we sample this alternative position once before running any experiments. The sampled position is guaranteed to be navi-gable, not initially reveal the target, and have a ground-truth path length to the target of at least half that from the Session 1 spawn. Once selected, the position remains fixed across all experimental conditions. 

6.4. Ablation Protocols 

We conduct the ablation study on a randomly sampled 40-task subset of the Habitat-GS single-object split. All ex-periments use the changed-spawn multi-session setting: in Session 2, the robot starts from a location different from its Session 1 spawn and receives the prior spatial memory, except when an ablation removes specific memory compo-nents. We evaluate the following configurations: 

Baseline. 

Loads the paired memory nodes, visual and planning SLAM states, caption evidence, and relocalization ma-chinery. This is the reference condition. 

No occupancy map. 

The annotated occupancy map is hidden from the agent, and geometric navigation to known locations is disabled. Visual-point navigation and memory nodes remain available. 

No memory node. 

Memory-node lookup and update are disabled, as is geometric navigation to memory-node locations. The paired SLAM maps and caption evidence remain avail-able, isolating geometric mapping from structured memory. 

No relocalization. 

Static memory nodes and the occupancy map from the first session are retained, but both agent-triggered and geometric relocalization are disabled. No initial pose is inserted into the inherited map. 

No agent-guided relocalization. 

The agent-guided relocalization pathway is disabled. Background geometric-based relocalization remain enabled. This condition isolates the contribution of the semantic prior from automatic geometric relocal-ization. 

Alternative policy models. The model ablation changes only the policy models. The completed comparison cells use KIMI-k3-256k and GLM-5.3-flash .

6.5. HarnessVLN Memory Integration 

To compare memory designs without confounding them with different agent harnesses, we integrate HarnessVLN’s memory [5] into SuperNav and evaluate both memory sys-tems under the same SuperNav runtime. This comparison uses all 150 Habitat-GS multi-object episodes with identical initial poses and ordered target sequences. The two condi-tions also share the reasoning-model settings, four-camera RGB observations, action and time budgets, and objective evaluator. They differ only in the memory representation, update protocol, and retrieved context exposed to the agent. 

Core memory components. We preserve HarnessVLN’s two core memory components. Its event memory main-tains a structured TODO list with stable identifiers, four states ( PENDING , ACTIVE , COMPLETED , and BLOCKED ), at most one active item, incremental updates, and evidence references. Its episode-local spatiotemporal graph retains place, object, failure, and edge records. Places within 

0.75 m are merged, as are objects within 1.0 m . Objects within 0.35 m may also be merged despite having differ-ent labels, with those labels retained as aliases. The im-plementation preserves the NAVIGABLE TO , CONTAINS ,

OBSERVED FROM , and FAILED FOR SUBGOAL relations and adds navigability edges only after an actual traversal. It also records place summaries and the subgoal-specific 

NO PROGRESS and STOP REJECTED failures. 

Memory retrieval. Memory retrieval runs automatically before every high-level decision and uses HarnessVLN’s re-trieval scoring function. It selects the three highest-scoring content-bearing places as seeds, expands one hop from these seeds and the current place, and returns at most five places while excluding the current place itself. The agent then commits its summary of the current place, TODO up-dates, and intended action before execution. 

Navigation capability. To make recalled information actionable while holding navigation capability fixed across experimental conditions, the adapter associates HarnessVLN’s graph places with poses from our Car-tographer state. For a visible target, the agent invokes SuperNav’s point-only visual point navigate 

interface. For a recalled place, it invokes our 

navigate slam occupancy interface, which uses the shared occupancy-map planner. Backtracking retains HarnessVLN’s actionability rule. The agent may select only a waypoint returned by the current retrieval that lies within 6 m . Thus, all experimental conditions share the same Cartographer state, local point-navigation interface, occupancy-based navigation, and low-level execution. The comparison primarily isolates the memory representation and retrieval protocol.

8. Implementation Details 

This section describes the construction of the annotated oc-cupancy map, the persistent memory-node interface, and the geometric navigation executor. 

8.1. Occupancy-Map Construction 

Occupancy map in simulation In simulation, we con-struct two geometrically aligned occupancy maps from the same timestamped simulator odometry and depth observa-tions: a center-band structural map and a projected-depth planning map . The two maps serve different accuracy re-quirements. The structural map favors clean room bound-aries for area segmentation and relocalization, whereas the planning map favors collision-relevant obstacle coverage for path planning and execution. For the structural map, we sample a narrow horizontal band around the image center and convert its depths into angularly spaced planar ranges. This camera-height slice captures walls and other structures intersecting the sampling plane and generally produces clean free-space boundaries. It may, however, miss low furniture and obstacles visible only in the lower image. The planning map therefore back-projects pixels from the lower part of the depth image into 3D, retains points between 0.15 and 1.25 m above the floor, and projects them onto the ground plane. The nearest point in each angular bin becomes the simulated LiDAR return. Keeping the two streams separate avoids contaminating the structural map with dense object boundaries while retaining the obstacle coverage needed for safe planning. The simulator pose is transformed into Cartographer’s planar tracking frame and rebased to the first observa-tion. A patched Cartographer local trajectory builder uses timestamp-matched simulator odometry as the authorita-tive trajectory pose: it bypasses local scan-pose estimation and inserts each range observation at the supplied odome-try pose. Because the two scan streams share timestamps and odometry, their grids remain aligned. Cartographer in-tegrates the scans into submaps and renders both grids at a resolution of ρ = 0 .05 m per cell. 

Occupancy map in real-world deployment. The real-world occupancy map is a world-aligned, terrain-aware two-dimensional costmap constructed from the Unitree Go2’s onboard L1 LiDAR and odometry. It provides the common geometric representation used for map visualiza-tion, area segmentation, and navigation. The robot interface receives LiDAR point arrays and robot odometry over WebRTC. Each LiDAR observa-tion is a 3D point cloud expressed in the Unitree world frame, and odometry provides the corresponding world-to-

base link pose for tracking and displaying the robot. The mapper inserts these already registered world-frame observations directly, without additional local scan match-ing or pose optimization. Mapper follows the implementa-tion in dimos [6]. The world-aligned costmap supplies both the displayed geometry and the planner’s input. Before planning, lethal cells are inflated by 0.15 m , half of the Go2’s nominal 

0.30 m width, and an obstacle-distance cost field encour-ages paths with additional clearance. 

Area segmentation. The structural occupancy grid is par-titioned into human-interpretable areas in four stages. 1. Cell classification and cleanup. We classify grayscale intensities below 80 as occupied, intensities of at least 245 as free, and all remaining values as unknown. We then extract eight-connected free-space components and discard components smaller than Amin = 80 pixels. 2. Conditional subdivision. A component smaller than 

max(4 Amin , 400) pixels is retained as one area. Larger components are candidates for subdivision because they may join several rooms through narrow openings. For each candidate, we compute the Euclidean distance D

from every free cell to the component boundary. If the maximum clearance is below three pixels, we retain the component intact. This avoids fragmenting thin corri-dors that contain no reliable room interior. 3. Watershed growth and stability merging. We smooth 

D with a Gaussian kernel of σ = 1 and detect local-maximum pixels using an adaptive odd window between 15 and 65 pixels. Only maximum pixels with at least three pixels of clearance are retained. Because a flat peak may contain several adjacent maximum pixels, we group the retained pixels into eight-connected compo-nents. Each component becomes one watershed seed and receives a unique integer basin label. We then process the remaining free cells in descending order of smoothed clearance and propagate these basin labels through four-neighbor connections. Thus, every assigned cell carries the identifier of the seed from which its basin grew, and neighboring basins meet near doorways or other narrow boundaries. After this initial partition, we evaluate each basin using its area, maximum clearance, thick-interior support, occupied/unknown boundary ratios, compact-ness, and contact with neighboring basins. A basin that fails the stability test is absorbed into the adjacent basin with which it shares the longest boundary. Final basins smaller than Amin are discarded. 4. Area metadata. For every retained area, we store its 5pixel count, bounding box, centroid, number of free– unknown frontier cells, and boundary size. The result is an area-label grid together with area records. The conditional subdivision preserves simple or narrow spaces, while the stability merge prevents the raw watershed from producing many small regions that would be difficult for the agent to interpret. 

Captioning and geometric evidence association. Suc-cessful robot movements produce a caption keyframe ev-ery two translation steps. Each keyframe stores front, right, back, and left RGB views, which are submitted to an asyn-chronous caption inference queue. We use Qwen3.5-2B [18] as the captioning backend. Be-fore inference, images are resized to at most 768 pixels on the longest side. Captions are generated deterministi-cally with at most 48 new tokens. The prompt requests one short factual description of visible objects, surfaces, open-ings, and spatial layout, while explicitly prohibiting guesses about room category, hidden objects, navigation goals, or actions. This restriction favors concise visual evidence over unsupported semantic inference. We associate captions with segmented areas in two stages. If at least one keyframe pose lies inside an area, we select the keyframe closest to the area centroid and attach all four directional captions. When multiple candidates share the same position, preference is given to current-session and more recent evidence. If no keyframe lies inside the area, we use ray casting to select the view that best depicts the area. For every directional view, nine rays are distributed uniformly across its 90 ◦ horizontal field of view. Each ray advances until it leaves the grid, encounters an occupied cell, or enters the candidate area. We select the view with the most rays entering the area, breaking ties by distance to the area center, and recency, and attach only that view’s caption. These captions remain transient visual evidence and are not automatically promoted to persistent semantic memory. 

8.2. Persistent Memory Nodes 

Data structure. Persistent memory is stored as a JSON document containing a set of node records. Each agent-authored node contains a stable id , a kind (area or 

door ), a short name , a semantic description , a list of textual records , and pano images mapping view directions to panorama references. The system addition-ally maintains a monotonically increasing order id and a 

slam pose containing the Cartographer sequence, planar position, and yaw at which the node was recorded. Up-dating panoramic evidence also refreshes the SLAM pose when a current pose is available. 

Creation and update. Creation requires a complete node and rejects duplicate identifiers. A partial update may modify only name , description , records , and 

pano images . After any mutation, the system repub-lishes the node manifest used to annotate the occupancy map. 

Lookup. The interface provides three complementary ac-cess patterns. Listing returns compact summaries of all nodes containing the name, and description. Text search performs case-insensitive substring matching over names, descriptions, and textual records. Inspection returns a com-plete node information and can omit panorama references when images are not required. A combined context query can execute multiple searches and inspections against the memory. 

Atomic batch mutation. Batch mutation accepts an or-dered, nonempty sequence of create , create , and 

update operations. The system validates and applies all operations to an in-memory copy before performing one persistent write. Its response reports the index, status, and node identifier of every operation, followed by image-free snapshots of the affected nodes. This batch mutation saves agent steps during navigation. 

8.3. Agent-Guided Relocalization 

Agent-guided relocalization aligns geometry observed in the current session (the source ) with the stored occupancy map (the target ). At the beginning of a session, the current trajectory may contain too little geometry for reliable global matching. The agent therefore supplies a semantic spatial prior by recognizing a stored memory node, after which ge-ometric registration estimates and verifies the precise planar transform. The procedure consists of region construction, source-map preparation, candidate search and refinement, conservative acceptance, and frame handoff. 

Agent-guided target region. When the agent recognizes a previously stored node, it reports that node as the relocal-ization prior. We locate the node’s stored SLAM pose in the segmented target occupancy map. The free-space area con-taining the pose becomes the primary target region. If the pose is outside all segmented areas, we use the nearest area. We then include any area whose bounding box lies within 

0.5 m of the reported node and take the union of the selected area bounds. Padding this union by 0.5 m produces the fi-nal metric crop. If no segmentation is available, the fallback region is an 8 × 8 m square centered on the node pose. The crop restricts only the occupied and free cells of the stored target map. We retain the complete recent source tra-jectory so that all currently observed geometry can support alignment. For each candidate transform, we transform the 6current robot pose—the endpoint of the source trajectory— into the target-map frame and require it to lie inside the agent-reported region. 

Current-session source geometry. The source represen-tation uses the most recent 8 m of scan-matched trajectory, measured along the traveled path. We insert its scans into a temporary Cartographer-style probability grid at 0.05 m 

resolution, using both ray hits and misses. Cells with oc-cupancy probability at least 0.65 form the occupied source set, whereas cells with probability at most 0.46 form the confidently free set. 

Candidate generation and refinement. We gener-ate initial source-to-target transforms using multi-scale FPFH/RANSAC registration. Each proposal is expanded by 90 ◦ quadrant rotations and local yaw perturbations, then pre-ranked using both point-cloud fitness and consistency between the transformed source occupancy and the tar-get grid. Correlative scan matching searches around the strongest proposals. A coarse stage covers translations of 

±1.5 m and rotations of ±15 ◦. A fine stage then searches 

±0.10 m and ±2◦. Surviving candidates are refined with planar point-to-point ICP and projected to rigid SE(2) 

transforms. This sequence combines broad hypothesis gen-eration with progressively finer grid and point-cloud align-ment. 

Acceptance gates. A candidate transform is accepted only when it satisfies every gate below. The gates test whether enough geometry is available, whether occupied and free space agree, whether matches cover the trajectory rather than one small patch, whether local refinement is re-liable, and whether the result remains consistent with the agent’s prior. Frame handoff and correction. After acceptance, the es-timated SE(2) transform is applied through a Cartographer trajectory handoff. The system rebases the current odome-try frame at the scan sequence used for matching and ini-tializes a new trajectory against the frozen exploration map. A corrective relocalization report made after an earlier lo-calization passes through the same acceptance gates. The previous trajectory remains active until the new anchor is confirmed, allowing the system to roll back if the correction fails. 

8.4. Geometric Navigation 

Given a memory node or unvisited-area marker, the execu-tor retrieves its map position and produces an executable ac-tion sequence. In realworld deployment on Unitree Go2, we use the path planner implementation in dimos. In simulator, 7the path planner follows three stages: cost-map construc-tion, A* search, and path discretization. The stages delib-erately separate safety constraints from global route search and robot-specific action compilation. 

Cost-map construction. We first convert the planning oc-cupancy grid into a cost map that distinguishes hard safety constraints from soft path preferences. Free cells are ini-tially traversable at zero cost. Occupied cells are blocked, and unknown cells are also blocked by default. When the goal is reached, parent links are reconstructed and converted back into metric SLAM co-ordinates. If the queue is exhausted first, the planner returns an explicit unreachable status. 

Path simplification and action compilation. The raw grid path contains many adjacent cells and cannot be di-rectly executed by a robot with quantized actions. We con-vert it into actions in three stages. 1. Line-of-sight simplification. Starting from the first path cell, we find the farthest later cell connected to the cur-rent anchor by a collision-free Bresenham line. That cell becomes the next waypoint and the new anchor. Repeat-ing this process removes redundant cells while preserv-ing collision-free straight segments. The retained way-points are then converted into metric SLAM coordinates, and the first waypoint is removed because it represents the robot’s current position. 2. Quantized action selection. For each waypoint, we compute the ideal heading and round it to an initial num-ber of 10 ◦ turns. Because independent rounding can make the subsequent 0.25 m forward step unsafe or un-productive, we test nearby integer turn counts in order of remaining heading error. Each candidate is simulated before execution. We reject it if the residual heading er-ror is excessive, its swept forward segment intersects a blocked cell, or the step increases the waypoint distance by more than one map cell. The first valid candidate contributes its individual left/right turns followed by one forward action. 3. Validation and recovery. Every proposed forward sweep is sampled at intervals no larger than 0.025 m .If no candidate is valid, line-of-sight waypoints are re-computed from the current pose. The compiler reports a blocked-sweep failure if the same segment remains in-valid. Execution terminates successfully once the robot lies within rgoal = 0 .45 m of the target. Reaching the end of the compiled route outside this radius yields a partial-route status. During online execution, a colli-sion, blocked motion, or disagreement between the pre-dicted and updated SLAM poses triggers global replan-ning, with at most two replanning attempts by default. This simulate-before-commit procedure preserves the intent of the continuous grid path under a discrete action space and exposes explicit failure states instead of issuing an unsafe forward motion. 8
