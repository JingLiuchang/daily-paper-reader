Abstract —When an embedding model changes, the same col-lection is re-encoded, and its vector index must be adapted to the new embedding space. Because the source and target vectors represent the same objects, suitable connections in the source index can be reused. We propose STARR (Standardized Tolerance for Adaptive Reuse and Repair) to migrate HNSW indexes after an embedding model change. STARR compares standardized edge lengths over the same source neighbor lists in both embedding spaces and uses the correlation between their distance profiles to set the allowable increase in standardized edge length. It reconnects affected vertices by searching the partially migrated graph and shares the resulting candidates with their neighbors. We bound edge rejection under local distance distortion, characterize migration work, and prove that a final repair pass makes every vertex reachable from the entry point at the base layer while respecting degree limits. Single-threaded experiments on MS MARCO, Wikipedia, and CC3M, each with one million objects, show that STARR achieves 5.25–44.54 ×

construction speedups over Fresh and migrates faster than both DGM variants on all 15 selected transitions. Recall@10 remains within one percentage point of Fresh in 10 cases, and query throughput exceeds DGM-Local in 14 cases. Parameter sweeps on three transitions further demonstrate favorable migration-time–recall tradeoffs beyond the default settings. Across all 240 directed transitions among 16 MS MARCO models, STARR achieves a median construction speedup of 16.71 × with a median recall loss of 1.0 percentage point.

I. I NTRODUCTION 

The growing demand for semantic retrieval has spurred extensive research into vector similarity search, which captures semantic similarity through distance-based neighborhood rela-tionships in embedding spaces. Embedding models map multi-modal data, such as text, images, and audio, to dense, high-dimensional vectors, often yielding large vector collections. Efficient indexes are therefore essential for supporting vector similarity search at scale. In particular, graph-based vector indexes have attracted considerable attention for their strong empirical search performance [1], [13], [15]. 

This work was supported by the China Postdoctoral Science Foundation (Grant No. 2025M781464), and the Natural Science Foundation of Hebei Province of China (Grant No. F2026210032). 

Recent research has devoted considerable effort to maintain-ing graph-based vector indexes in dynamic settings [8], [10], [11], primarily focusing on the insertion, deletion, or update of individual vectors [5], [9], [21]. These operations, however, address only one aspect of index maintenance. Because vectors are derived from the underlying multi-modal objects through embedding models, an update to an individual vector must originate from an update to its underlying object. Another important source of change is the change of embedding mod-els , a common occurrence in real-world applications driven by version upgrades, changes in model size, or adaptation to new tasks [16], [20], [22]. Such embedding model changes can transform the entire vector dataset even when the underlying objects remain un-changed [3], [7], [14], requiring the index to adapt to a new similarity structure residing in an entirely new embedding space. This dataset-wide transformation presents a distinct maintenance challenge: techniques designed for individual vector updates do not directly address the problem of adapting the index to an entirely new vector dataset. A straightforward solution is to rebuild the index from scratch on the new vectors, but this is prohibitively expensive, as graph construction is well known to be costly [17], [18]. Rebuilding also overlooks a potential opportunity: although a change of embedding model produces two distinct sets of vectors, each vector in the old dataset has a counterpart in the new dataset derived from the same underlying object. Because embeddings encode semantic relationships among these objects [6], objects whose embeddings are close in the old space are likely to remain close in the new space. Therefore, an edge in the old index may still be useful for linking the corresponding vectors in the new index. This intuition motivates our central hypothesis: reusing suitable parts of the old graph-structured index can reduce the cost of constructing an index for the new vectors. To examine how well an old graph supports search after a model change, we conduct a direct-reuse experiment on one million MS MARCO objects. We fix GTE-large as the target model and use old indexes built with four different embedding models. A. Problem and Challenges 

We now examine the task in greater detail. Let X and Y

be vector datasets generated from the same set of underlying objects O by different embedding models MX and MY ,respectively. Given an existing graph-structured index GX over 

X, our goal is to construct a graph-structured index GY over Y

by reusing suitable connections from GX and repairing those that no longer support effective search in the new embedding space. This task is called index migration [4]. Our preliminary experiments (Table I) suggest that index migration involves two central decisions: which edges of the source index to retain, and how to add new edges so that the target index achieves search performance comparable to that of an index built from scratch. Addressing these decisions presents four key challenges. First, deciding whether to retain an edge (i, j ) from GX

requires determining whether its endpoints remain near neigh-bors in the target embedding space. However, this neighbor-hood information must be obtained before an index over Y

is available, creating a circular dependency between neighbor-hood determination and index construction. Second, the old and new vector datasets may differ in dimension and distance scale, so raw distances cannot be directly compared across the two spaces. Transferring neigh-borhood information therefore requires non-trivial techniques that account for these differences. Third, any practical migration must be remarkably faster than rebuilding the index from scratch. For example, exhaus-tively testing all vector pairs to detect neighborhood changes would cost O(n2) time which defeats the purpose of migration and is prohibitive for large-scale datasets. Fourth, the migrated index must deliver query performance comparable to that of a freshly built index. B. Approach and Contributions 

To address these challenges, we develop the following strategy based on the idea of reuse-and-repair. First, we screen the old index GX using a novel criterion that distinguishes stable edges to retain from unstable edges to modify. This process requires no index over the new vector dataset Y , addressing the first challenge. Second, the criterion is based on standardized distances, computed from the mean and variance of each node’s neighbor distance list. This normalization accounts for differences in dimension and distance scale across embedding spaces, ad-dressing the second challenge. Both criterion evaluation and edge screening operate within local neighbor lists, avoiding exhaustive pairwise comparisons and quadratic cost, thereby addressing the third challenge. Third, after a partial new index is obtained by screening and reusing the old index, we improve the new index through a reconnection stage, a local refinement pass, and a reachability repair stage. Together, these steps improve index quality and query performance, addressing the fourth challenge. In summary, this paper makes the following contributions. 1) We propose a lightweight neighborhood similarity metric that can be evaluated before the target index is built, allowing the identification of reusable edges without quadratic cost. 2) We develop an HNSW migration method that combines local edge screening, selective reconnection, candidate sharing, and reachability repair, which significantly reduces construc-tion overhead compared to rebuilding from scratch. 3) We analyze the time complexity of our method based on the careful inspection of the screening rules and repair process. 4) We evaluate our method on various datasets against recent baseline methods. Across 15 transitions spanning different types of model change, STARR migrates faster than baselines and achieves 5.25–44.54 × construction speedups over Fresh, with Recall@10 within one percentage point of Fresh in 10 cases. We further evaluate all 240 directed model transitions against Fresh to examine performance across embedding-model pairs. Parameter sweeps and recall–throughput curves compare migration and query efficiency at comparable recall, while ablations quantify the effects of individual components on migration cost, recall, and reachability. B. HNSW index 

ANN search is usually supported by index structures. This paper focuses on HNSW index. An HNSW index is a hierarchy of directed graphs {GhA} =(Vh, E hA), h = 0 , . . . , H , where H is the maximum level, and A ∈ { X, Y } denotes the embedding space. Each vertex 

i has a nonnegative integer height hi ≤ H and belongs to layers 0, . . . , h i. The level-0 layer, or the base layer, has 

V0 = V, and Vh = {i : hi ≥ h}. The entry point e ∈ V H

is the designated starting vertex for hierarchical search. The adjacency list N hA(i) contains the outgoing neighbors of i at layer h. The outgoing degree is denoted as |N hA(i)|.HNSW constructs the index incrementally, assigning each new vertex i a random height hi. Starting from e, it descends greedily through layers above hi, repeatedly moving to a closer neighbor and using the closest vertex found as the next layer’s entry point. From layer min {H, h i} to layer 0, it searches for candidates with width efConstruction ,selects up to M neighbors using a diversity heuristic, and adds outgoing and reverse connections. The heuristic can reject a candidate that is closer to an already selected neighbor than to the vertex being connected, avoiding redundant connections. Lists exceeding their capacities are pruned using this heuristic. Higher layers contain exponentially fewer vertices, forming a sparse navigation structure, while the base layer contains all vertices for finer local exploration. The outgoing-list capacities used here are C0 = 2 M and Ch = M for h > 0, with common upper bound C = 2 M ; these limits do not bound incoming degree. Queries exploit this hierarchy by descending greedily from the top-layer entry point to approach the query’s neighborhood. At the base layer, best-first search expands the closest pending vertex and maintains a bounded set of promising candidates, from which the closest k are returned as approximate nearest neighbors. Query width efSearch 

controls the retained candidate set, trading query cost for search accuracy [12]. 

C. The migration task 

We now define the migration task to tackle in this paper. 

Input: source and target vector sets X and Y , together with the source HNSW index GX .

Output: an HNSW index GY for ANN search on Y .

Requirements: Migration should be substantially faster than rebuilding the index from scratch and should yield query performance comparable to that of a freshly built index. III. M ETHOD DESCRIPTION 

Given source and target vectors for the same objects, and a source HNSW index, our method STARR, standing for Standardized Tolerance for Adaptive Reuse and Repair, con-structs the target index in three stages. The overall algorithm is given in Algorithm 1. First, we screen source edges by comparing local distance relationships in the two embedding spaces using the same source neighbor lists. We retain edges for which these rela-tionships change only slightly and mark vertices for repair if they lose any outgoing edges or have empty neighbor lists. Next, we search the current target graph for candidate neighbors and use them to reconnect vertices in the repair set. We also share these candidates with nearby vertices, allowing vertices outside the repair set to gain connections. When the repair set is small, selected reverse connections are added to retained edges before reconnection. Finally, we check base-layer reachability from the entry point and add bridges to unreached portions of the graph to ensure the full graph reachability. By reusing source connections and the search routes of the source index, the method concentrates reconnection searches on affected vertices to reduce construction cost while improv-ing search quality of the migrated target index.

C. Adding Stable Reverse Connections 

Using the sets identified in Section III-B, we add each retained edge i → j, j ∈ Shi , to the target index at layer 

h, without automatically adding its reverse. Vertices that lose an outgoing edge at any layer, or have an empty neighbor list at an occupied layer when n > 1, form the repair set U, with 

u = |U| . It remains fixed throughout subsequent repair. When the repair set is small, reconnection and candidate sharing may update only a limited portion of the base graph. We therefore first supplement retained edges with reverse connections if u(C0 +1) < n . Here, C0 +1 bounds the number of base-layer lists that reconnection and sharing can update per repaired vertex: its own list and at most C0 neighboring lists. The reverse pass operates layer by layer. A retained edge 

i → j proposes j → i only if that direction is missing and was not explicitly rejected during screening. After collecting all proposals for a layer, we merge each recipient’s proposals with its current neighbors. We write the union directly if it fits within Ch; otherwise, we apply diversity pruning once before writing it. This batch update avoids repeated pruning and does not guarantee bidirectional connections. The resulting graph provides the search routes for reconnecting vertices in U.D. Search-Based Connection Repair 

The preceding stages partially establish target index connec-tions, but vertices in U may still lack suitable neighbors. We therefore use each vertex’s target vector as a query to search the current target graph and repair its connections. For each i ∈ U , greedy search starts at e and descends through layers above hi to find an entry close to yi. We process layers hi, . . . , 0 in descending order, so repaired upper-layer connections can guide subsequent searches. Before searching each layer, we use i’s neighbor list N hY (i) in the current target graph and an entry vertex to seed best-first search. At layer hi,the entry comes from the upper-layer greedy traversal; at each lower layer, it comes from neighbor selection at the preceding layer. The repair search width B limits the retained set to at most B candidate neighbors, excluding i. All searches use the graph updated by earlier repairs. We apply the HNSW diversity heuristic [12] to select neigh-bors from the candidate set, update i’s outgoing connections, prune lists exceeding their capacities, and attempt reverse insertion into the selected neighbors’ lists. If the updated neighbor list for i has free slots, we append missing neighbors from the saved list until all are restored or capacity is reached. Thus, restoration uses neighbors already present in the target graph immediately before this layer’s search, including con-nections retained or added by preceding operations. This reconnection process updates an existing vertex’s con-nections while preserving its identifier and height. An edge rejected during screening may be rediscovered and inserted, as long as it is eligible for reconnection. The base-layer search candidates also support the candidate sharing described next.

F. Ensuring Reachability from the Entry Point 

Filtering and pruning can leave some vertices unreachable from the entry point e. After reconnection and candidate sharing, we therefore check base-layer reachability and add bridges where needed. We first perform a breadth-first traversal from e, marking reached vertices and recording the edge that first discovers each vertex. These edges form a traversal tree and are protected during subsequent updates to preserve existing paths from the entry point. For each unreached vertex r, a base-layer best-first search from e with query yr finds reached vertices as candidate bridge sources, or anchors . We try them in increasing distance to r. An anchor with a free slot accepts an edge to r directly; a full anchor instead replaces its farthest outgoing non-tree edge. If none of the search candidates can accept a bridge, we scan the remaining reached vertices for a suitable anchor. After adding a bridge, we include it in the traversal tree and resume traversal from r to mark newly reached vertices. We repeat this process until every vertex is reachable from 

e. All updates respect the base-layer neighbor capacity, while tree-edge protection preserves previously established paths. IV. A NALYSIS

C. Capacity-Preserving Reachability 

Section IV-B bounded how many vertices end up in the repair set U. The next result is a structural guarantee about that procedure’s output: whatever size U turns out to have, repair leaves the base layer connected from the entry point, without ever asking any vertex to hold more outgoing edges than its capacity allows. 

Proposition IV.1 (Rooted reachability) . Let R0 be the base-layer vertices reachable from e before reachability repair. Pro-tecting traversal-tree edges and attaching unreached vertices through free or unprotected slots terminates with every vertex reachable from e, respects outgoing capacities, and adds at most n − |R 0| bridges. Proof. Maintain a protected spanning out-tree T of the reached set R, initially R0. Since protected edges are never removed, all vertices in R remain reachable from e. If R̸ = V,any leaf of T has no protected outgoing edge. Its capacity is at least 1, so it has either a free slot or an unprotected edge that can be replaced by a bridge to an unreached vertex. Thus the fallback scan always finds an eligible anchor if the search does not. Adding and protecting the bridge, then extending T by traversal from its endpoint, preserves capacities and existing protected paths while increasing |R| by at least one. At most 

n − |R 0| bridges suffice to reach every vertex.

B. Dynamic vector indexes. 

Dynamic ANN methods maintain search structures as vec-tors arrive or are removed. GTI combines a tree with a lightweight graph to support efficient insertions and dele-tions [11]. Wolverine repairs monotonic search paths disrupted by deletions [10], and Greator localizes small-batch updates to reduce graph-maintenance I/O and redundant neighbor pruning [21]. CONDA uses connectivity-aware pruning, bidi-rectional link reinforcement, and lazy deletion to preserve search quality under continuous updates [9]. OdinANN di-rectly inserts vectors into an on-disk graph to stabilize search performance during ingestion [5]. These methods share our interest in reusing an existing graph and repairing its con-nections. The migration setting introduces a different reuse decision: the object identifiers remain fixed, but a model change replaces the entire collection’s representations and can change their dimensionality. Processing these changes as individual deletions and insertions does not itself identify which source connections remain useful under target-space distances. Our screening rule makes this decision using paired local distance profiles before a target index is available. 

C. Embedding compatibility and model upgrades. 

Compatible representation learning addresses model changes at the representation level. Continual variants align new and historical gallery features [3], cross-modal variants project embeddings into legacy spaces [7], Drift-Adapter maps new queries into the old space [14], and Embedding-Converter converts embeddings between models [19]. Our setting assumes that target vectors are already available and addresses index construction under target-space distances. Representation conversion and index migration thus address different stages of a model upgrade. 

D. Cross-model graph index migration 

Gu et al. [4] studied the same index migration task and proposed the two DGM variants evaluated here. DGM-Local expands inherited neighborhoods to generate candidates for each vertex, then evaluates and prunes them in the target space. DGM-Search uses hop-bounded beam traversal to discover candidates for each vertex. By contrast, STARR compares standardized edge lengths across the two embedding spaces and uses the correlation of the paired profiles to set the retention threshold. A vertex enters the repair set if screening rejects any of its outgoing edges or if it has an empty list at an occupied layer. This confines reconnection searches to the flagged vertices, while candidate sharing can also update nearby vertices outside the repair set. VII. C ONCLUSION 

Useful neighborhood structure can survive an embedding-model change and reduce the cost of constructing the target index. STARR identifies reusable edges through standardized distance profiles and repairs affected neighborhoods to obtain a reachable HNSW graph. Experiments show substantial con-struction savings across model transitions, with recall close to that of Fresh in many cases. The parameter sweeps show that migration quality depends on the model pair and repair budget. Stricter screening and wider repair search can improve recall on difficult transitions at additional cost.
