## 摘要
大语言模型（LLM）智能体现在能够调优神经网络，但如果没有跨会话记忆，它们就会耗费昂贵的试验来重新发现已知经验。复用之所以困难，是因为生产模型在架构、训练设置和推理预算上各不相同。我们提出 Engram，一种记忆系统，它将过去的试验结果与其背后的假设和理由联系起来，并评估这些证据是否适用于当前模型。在线智能体在需要证据的决策点对证据进行整理：初始指导在开始时提供经过验证的经验，会话检索在生成每批假设之前提供相关的过往会话，试验候选审查则将每个试验候选与匹配的过往试验进行核对。在会话之间，离线智能体提炼经过验证的经验，使记忆能够自我改进。在两个广告模型上，Engram 以少 47% 的试验次数达到无记忆对照组第 32 次试验的结果，并且平均而言最终得到更好的模型。

## Abstract
Large language model (LLM) agents can now tune neural networks, yet without cross-session memory they spend costly trials rediscovering known lessons. Reuse is difficult because production models differ in architecture, training setup and inference budget. We present Engram, a memory system that links past trial outcomes with the hypotheses and rationale behind them and assesses whether this evidence applies to the current model. An online agent curates evidence at the decision points where it is needed: Initial Guidance supplies validated lessons at the start, Session Retrieval supplies related past sessions before each batch of hypotheses is generated, and Trial Candidate Review checks each trial candidate against matching past trials. Between sessions, an offline agent distills validated lessons, making the memory self-improving. On two ads models, Engram reaches the 32-trial result of a no-memory control with 47% fewer trials and also ends with a better model on average.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体已能自主调优神经网络（读取代码与日志 → 提出假设与理由 → 跑训练试验 → 依据结果选下一个实验），在表格类 Kaggle 任务、推荐系统等场景已被验证有效（AIDE 优于 H2O AutoML；推荐系统智能体已上线并缩短 8 倍训练时间）。
- **核心痛点**：这些智能体**没有跨会话记忆**，每次调优都从零开始，反复"重新发现"已知教训，代价是昂贵的训练试验。
- **为何复用困难**：生产模型生态高度异构——在目标、特征、架构、训练设置（数据、训练轮数、优化器 schedule）、训练数据时间跨度、推理预算上都不同。作者基于生产实践归纳出 **五个挑战**：
  - **C1** 历史收益依赖具体模型与训练设置（某模型上有效的改动，换模型未必复现）；
  - **C2** 可用改动受推理预算约束（宽松 FLOPs 下有效的手段在紧预算下不可用）；
  - **C3** 仅有"配置—结果"记录无法解释结果成立的假设前提，因而无法判断能否迁移；
  - **C4** 历史会话的相关性会**随当前会话进展而变化**（初期相似的会话，后期不如"在同一改动上获益"的会话有用）；
  - **C5** 误用证据会**损害搜索**（差异过大的模型的历史会把智能体引向更差配置）。
- **整体含义**：论文主张记忆系统的关键不是"提供更多历史"，而是**判断哪些历史证据适用于当前模型与预算，并在需要它的决策点交付**。

## 2. 方法论

### 2.1 问题形式化

- 会话从基线配置 `x₀` 出发，在固定评测环境下最多提交 `K` 次试验；每次试验评估一个配置 `x_k`（学习率、层宽等搜索参数）。
- 每次试验测质量指标 `q(x)`（越低越好，本文为 **NE，归一化熵** = log loss 除以平均标签率的熵）与推理代价 `c(x)`（**推理 FLOPs**）；若 `c(x) ≤ ρ·c(x₀)` 则可行。
- 目标：`x* = argmin q(x) s.t. c(x) ≤ ρ c(x₀)`，且智能体只能使用"至今已完成试验"的结果。
- Engram 不改变调优智能体的 observe–reason–act 循环，只**补充它原本看不到的跨会话证据**。

### 2.2 双存储：Memory（原始证据）与 Knowledge（已验证经验）

- **Memory**：由每日回填从所有已结束会话导入，逐试验记录配置改动、NE、FLOPs、状态，以及调优智能体写的**假设（hypothesis）、理由（rationale，试验前写，解释为何应改善 NE）与分析（analysis，试验后写，解释实测结果）**。
- **Knowledge**：存放离线提炼并验证过的"经验/教训"。每条经验包含：参数、起始值范围、从该范围施加的改动（三者合称一个 **move**）、关于该 move 对 NE 影响的**claim**，以及界定其适用模型的 **scope**（如某类架构、某量级训练数据）。
- **离线巩固（Consolidation，会话之间）**：
  1. 代码先在同一会话内的试验对之间挖掘候选经验，分别处理**单参数改动**与**联合改动**（联合改动只表述为相关性，因其效应不可归因于单一参数）；
  2. 离线 LLM 智能体结合支持性试验与理由逐条复核：保留 / 收窄 scope / 丢弃，并与默认调优指南关联；
  3. **发布门槛（三条同时满足）**：① 在完整历史与**时间交叉验证**下都比默认调优指南预测更准；② 来自多个不同模型（默认 ≥5）；③ 获得多个独立 LLM 评审认可（默认 2 个）。
- 由此形成**自改进记忆**：调优的模型越多，指导越强。

### 2.3 多阶段在线检索（三阶段，按需交付）

在线 LLM 智能体在每个阶段都执行 **Assess（证据是否适用）→ Revise（证据不足则重检索/调权重）→ Compose（写出给调优智能体读的文本）** 的循环。

- **Initial Guidance（IG，会话开始时一次）**：一条经验适用需满足：① scope 覆盖当前模型；② 模型暴露该参数；③ 基线值落在 move 的起始范围内。在线智能体再对全部适用经验做复核，生成简报：推荐经验支持的 move，**联合改动经验只作为相关性报告而非建议**。
- **Session Retrieval（SR，每批假设生成前）**：按加权元数据匹配 + 假设/结果一致性对历史会话排序：
  `score(c) = Σ_i w_i · Match_i(c) + λ · Agreement(c)`
  其中 `Match_i ∈ [0,1]` 比较架构、规模、已探索参数等某一元数据字段，`w_i` 为其权重；`Agreement(c)` 衡量当前会话迄今的 NE 收益中有多少来自 `c` 也探索并改善过的参数，`λ` 控制其相对重要性。**Agreement 每批后重算**，故排序随结果演化（直接回应 C4）。在线智能体检查召回会话是否覆盖可调参数、是否符合 FLOPs 预算、是否够新，可剔除会话或调整 `w_i`、`λ` 后重检索（默认最多检索 50 个会话、每批最多修订 2 次），再撰写引用其测量与理由的建议；**下一个假设的选择权仍归调优智能体**。
- **Trial Candidate Review（TCR，提交前）**：与 SR 的"整会话"推理不同，TCR 逐条检查候选试验，取 Memory 中做过**同一改动**的历史试验，判断该候选是否可能改善 NE 且不超 FLOPs 上限；被判为"不太可能改善或超预算"的候选，调优智能体必须替换或给出理由（每批检查一次）。

### 2.4 会话流程（Algorithm 1）

1. 生成 IG 简报；2. 在每个批次循环内：跑 SR（基于迄今结果）→ 重复"调优智能体提出/修订试验 → 跑 TCR"直至无被标记项或达审查上限 → 执行试验并记录结果；3. 会话结束写入 Memory 供离线巩固；4. 返回最优可行配置 `x*`。

## 3. 实验设计

- **场景/数据**：两个**真实广告生产模型**（Meta），无公开数据集，无传统 benchmark；以"NE 相对基线的百分比变化"为指标（负值=改善）。
  - **Model 1（主研究，历史丰富）**：历史 227 个会话，其中 59 个来自 **close 模型**（同 production model type：同广告产品、排序阶段、预测事件、归因窗口），共 8 个其他基线。
  - **Model 2（历史贫乏，检验泛化）**：299 个会话**全部来自 distant 模型**（部分与其同架构族）。
  - 两者历史均**不含当前评测基线**。
- **试验设置**：每个 arm 5 个会话，按**每批 8 个试验**同步提交；FLOPs 上限 `ρ = 1.5`；每次试验训练 1 个 epoch（Model 1 约 190M 样本，Model 2 约 144M），一批约 5 小时 / 3 小时。除 batch size、epoch 数、FLOPs 上限外**搜索空间不受限**（智能体主要调 LR、warmup、优化器设置、embedding 与层大小、输入特征）。
- **对比方法/实验组（8 个 arm + 1 个仅 Model 1 的 arm）**：
  1. Control（无记忆）；
  2. NE-sorted journal（按性能增益排序的历史配置日志，作为既有做法的基线）；
  3. IG only；4. SR only；5. IG + SR；6. **Full Engram**；
  7. No curation（去掉在线整理）；8. No agreement（去掉 `Agreement` 反馈项）；
  9. **Distant history only**（仅 Model 1；在 Model 2 上等同 Full Engram）。
- **统计检验**：对两 arm 的 5 个会话结果做**双侧精确 Mann–Whitney U 检验**（理由是 5 个样本不支持正态假设，且结果常呈双峰——要么找到决定性改动、要么停滞）；**未做多重比较校正**。
- **评测点**：8 / 16 / 24 / 32 次试验后的"平均最优可行 NE 变化"，兼顾搜索速度与最终质量（实践中会话中位数 9–10 次试验、90% 在 25 次内结束，故早期收益最重要）。
