## 摘要
磁盘驻留近似最近邻搜索（ANNS）使向量搜索能够扩展到 DRAM 之外，然而即使采用快速 SSD 和复杂的 I/O 执行方式，最先进的系统仍然受限于 I/O。为理解这一瓶颈，我们开展以 I/O 为中心的分析，将每次查询分解为定位查询邻近区域的逼近阶段和确定最终 top-k 的收敛阶段。该分析揭示了互补的 I/O 权衡：基于聚类的搜索通过内存路由规避逼近阶段的 I/O，但在收敛期间读取粗粒度的完整聚类；而基于图的搜索全程采用细粒度的向量级 I/O，从而实现高效收敛，但代价是逼近阶段不可避免的 I/O。为结合两种粒度互补的 I/O 优势，我们提出 TriVS，一种新范式，将磁盘驻留向量搜索重新架构为三部曲：粗粒度逼近、渐进式蒸馏、精确收敛。其关键创新包括两部分。首先，它将逼近阶段和收敛阶段与单一搜索粒度解耦，采用基于聚类的搜索避免逼近阶段的 I/O，并利用向量级 I/O 实现高效收敛。其次，为桥接这两种粒度，它在原有两个阶段之间引入新的内存蒸馏阶段，在磁盘访问之前使用紧凑的量化向量将路由到的聚类逐步缩减为向量级候选短名单。此外，更粗粒度的聚类会缩小质心路由索引，使 TriVS 能够将现有内存重新分配给蒸馏，而无需扩大内存预算。我们在涵盖多种向量类型和规模的五个数据集上的评估表明，在 Recall@10=0.9 时，TriVS 的平均吞吐量达到 PipeANN 的 3.42 倍，延迟降低 51.2%，磁盘 I/O 减少 63.7%，同时使用的内存和存储均少于 PipeANN。

## Abstract
Disk-resident approximate nearest-neighbor search (ANNS) scales vector search beyond DRAM, yet state-of-the-art systems remain I/O-bound, even with fast SSDs and sophisticated I/O execution. To understand this bottleneck, we conduct an I/O-centric analysis that breaks each query down into an approach phase that locates a query-near region and a converge phase that resolves the final top-k. This analysis reveals complementary I/O tradeoffs: cluster-based search circumvents approach-phase I/O through in-memory routing but reads coarse-grained, full clusters during convergence, whereas graph-based search employs fine-grained, vector-level I/O throughout, enabling efficient convergence at the cost of inevitable I/O during the approach phase.   To combine the complementary I/O benefits of the two granularities, we present TriVS, a new paradigm that re-architects disk-resident vector search as a trilogy: approach coarsely, distill progressively, and converge exactly. Its key innovations come in two parts. First, it decouples the approach and converge phases from a single search granularity, employing cluster-based search to avoid approach-phase I/O and leveraging vector-level I/O for efficient convergence. Second, to bridge the two granularities, it introduces a new in-memory distill phase between the original two, progressively reducing routed clusters to a vector-level shortlist using compact quantized vectors before disk access. Moreover, coarser clustering shrinks the centroid-routing index, allowing TriVS to reallocate existing memory to distillation rather than expand its memory budget. Our evaluation on five datasets spanning diverse vector types and scales shows that, at Recall@10=0.9, TriVS achieves on average 3.42X PipeANN's throughput, 51.2% lower latency, and 63.7% less disk I/O, while using less memory and storage than PipeANN.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：向量检索（ANNS）在十亿级规模下已成为事实标准，全精度向量及其索引动辄数百 GB，因此主流方案采用**磁盘驻留 ANNS**（SSD 存数据、DRAM 存紧凑状态）。
- **核心痛点**：即便使用 PCIe 5.0 NVMe SSD，现有系统（SPANN、DiskANN、PipeANN）在查询并发上升时仍**无法线性扩展**，会迅速逼近 SSD I/O 容量上限；在 96 线程满载时，**暴露的 I/O 等待占查询延迟的 87–93%**。PipeANN 的流水线化只能“隐藏”I/O 延迟，无法减少**每查询 I/O 量**。
- **根因洞察**：作者将查询拆成两个分析阶段——
  - **逼近阶段（approach）**：定位可能含最近邻的区域；
  - **收敛阶段（converge）**：在该区域内确定最终 top-k。
  - **基于簇**（SPANN）：用内存质心路由**免除逼近阶段 I/O**，但收敛阶段按簇整块读取，I/O 放大（实测 426 页/查询，为 PipeANN 的 7.8×）。
  - **基于图**（DiskANN/PipeANN）：全程向量级细粒度 I/O，收敛高效，但逼近阶段必须读取邻接表，产生**依赖式 I/O**（DiskANN 59.4 页、PipeANN 25.5 页）。
- **整体含义**：现有系统将两个阶段**绑定在单一搜索粒度**上，各自优化一个阶段却牺牲另一个。TriVS 的核心主张是——**用不同粒度分别服务两个阶段**，并以内存蒸馏作为桥梁，从根本上降低每查询磁盘 I/O。

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想
将磁盘驻留向量搜索重构为**三部曲**：
> **粗粒度逼近（approach coarsely）→ 渐进式蒸馏（distill progressively）→ 精确收敛（converge exactly）**

- **逼近阶段**用簇粒度，避免图遍历 I/O；
- **收敛阶段**用向量粒度，避免整簇读取；
- 中间插入**纯内存的蒸馏阶段**，把“路由到的簇”缩小为“向量级候选短名单”，桥接两种粒度。

### 2.2 索引组织（离线构建）
- **尺寸受限的层次 k-means**：目标簇大小 T=128，递归分裂超过 2T 的簇。
- **刻意采用更粗聚类**：簇数仅约向量数的 0.7–0.8%（SPANN 约 10–12%），从而**缩小质心路由索引**。
- **每个向量只属于一个簇**，不做边界复制（消除存储与内存放大）。
- 质心建 **HNSW 路由索引**；簇内向量以**簇质心为参考**做 **RaBitQ 量化**（降低残差分布、提升估计精度）。
- 内存中按簇连续存放量化码；磁盘上全精度向量按相同簇顺序紧凑排列。

### 2.3 内存重分配（而非扩张）
- 粗聚类 → 质心少 → 路由索引小 → **腾出的 DRAM 用于存放每向量 2-bit RaBitQ 码**，总内存预算不增反降。
- 与 PipeANN 相比不增加新的每向量状态；与 SPANN 相比可扫描更大簇而无需整簇读盘。

### 2.4 TriSearch 算法流程（文字化伪代码）
1. **簇级逼近**：用 HNSW 在内存质心索引上检索，返回最多 P 个近簇，搜索宽度 `ef = 1.2P`；此阶段**零磁盘访问**。
2. **渐进式内存蒸馏**：
   - 对每个路由簇按 32 向量块扫描，先用 **1-bit RaBitQ** 计算低精度距离估计与**置信下界 LB_low**；
   - 维护容量为 **R 的最大堆 H**（按 2-bit 中精度距离排序）；
   - 仅当 `LB_low < 当前堆阈值` 时才读取**额外一个 bit-plane** 做 **2-bit 精化**，精化成功则收紧阈值；
   - **簇级早停**：连续 **W ≈ 0.3P** 个簇未更新 H 即终止扫描。
3. **精确访问选择**：以 H 中近似 top-k 为种子，用其第 k 距离作阈值，保留 `LB_mid ≤ τ_k` 的候选；并**把已选页上的其他候选一并纳入**（零额外 I/O）。
4. **向量级收敛**：对短名单做页 ID 去重与相邻页合并，**批量读取**全精度向量并精确重排，返回 top-k。由于蒸馏已确定全部磁盘访问，读取可**成批发起、消除依赖式 I/O 轮次**。

### 2.5 工程优化
- **AVX-512 FastScan 内核**：1-bit 基码 + 1 个附加 bit-plane 组成嵌套 2-bit 表示，按 32 向量块处理；尾部块在线程本地 scratch 中重建以保持对齐。
- **紧凑内存状态**：质心用 **SQ8**；簇内 RaBitQ 估计字段也用 SQ8 编码，误差项保守取整以保证剪枝下界有效。
- **页高效收敛**：全精度向量按簇序密排，一次页读可覆盖同簇多候选。
- **内联 / 池化重排序**：I/O 仍为瓶颈时用**专用重排序线程池**持续填充 I/O 队列；蒸馏后压力转向计算时用内联模式。
- **通用性**：TriSearch 不绑定 RaBitQ，低/中精度层可用其他量化器；无理论下界时可用估计距离或固定精化比例替代。

## 6. 主要结论与发现

- **性能**：Recall@10=0.9 时，TriVS 平均达 **PipeANN 的 3.42× 吞吐、低 51.2% 延迟、少 63.7% 磁盘 I/O**；对每个工作负载最强基线为 **1.29×–3.94× 吞吐（均值 2.18×）、低 28.5%–68.1% 延迟（均值 44.8%）**。
- **I/O 是增益主因**：相对各工作负载最低 I/O 基线再降 **47.3%–74.7%（均值 57.7%）**；同量化位宽的 PipeANN+R 反而更慢，说明增益来自架构而非量化。
- **内存不增反降**：100M/1B 上比 PipeANN 少 **30%/3%**，且少于除 DiskANN 外所有基线；存储比图基线少约 **46%**、比 SPANN 少 **82%**。
- **渐进缩减极其有效**：候选集在精确 I/O 前缩减 **三个数量级以上**（如 DEEP-100M：66K 低精度 → 766.6 中精度 → 23.4 精确）。
- **三阶段缺一不可**：Low+Exact 短名单过大导致 I/O 多；Mid+Exact 计算开销大；Low+Mid 无全精度重排，Recall 上限仅 0.71/0.78。
- **高并发优势显著**：96 线程时为 PipeANN/DiskANN 的 **2.43×

… 倍 / 3.94 倍（相对 PipeANN / DiskANN 在 96 线程下的吞吐比），且吞吐随线程数近似线性上升直至逼近 SSD 随机读上限；PipeANN 在约 48 线程后即进入平台期，其流水线宽度增加只能延缓、不能消除饱和。

- **延迟分解揭示瓶颈转移**：单线程下 TriVS 的暴露 I/O 占比已明显低于基线，但蒸馏计算使其总延迟略高（约 +10%）；96 线程下基线的暴露 I/O 仍占 87–93%，而 TriVS 将该比例大幅压缩，剩余时间更多落在内存蒸馏与重排计算上——即**瓶颈由 I/O 等待转为可控的 CPU 工作**，这正是其高并发可扩展性的来源。
- **Top-k 鲁棒性**：k 从 1 增至 100 时优势保持，未出现因短名单膨胀而退化；k 增大时“同页多候选”的合并收益反而更明显，抵消了候选数增长带来的额外读取。
- **重排序模式存在明确交叉点**：低并发下内联重排序更优（避免线程池调度开销），高并发下池化重排序更优（持续填满 I/O 队列），二者可按负载切换，说明工程实现已考虑不同压力区间。
- **簇大小敏感性**：T 过小 → 质心与路由索引膨胀、挤占 RaBitQ 码内存；T 过大 → 蒸馏扫描成本上升且页内候选聚集度下降。T=128 附近为实测最优，验证了“粗聚类 + 内存蒸馏”的设计前提。

## 7. 局限性与可讨论之处

- **对量化下界的依赖**：渐进蒸馏的剪枝效力建立在 RaBitQ 能给出有效置信下界之上；论文虽声称可替换为其他量化器，但在无严格下界时只能用估计距离或固定精化比例替代，此时“只对可能入选者读额外 bit-plane”的收益会打折，通用性论证仍以 RaBitQ 为主。
- **静态索引假设**：全文围绕离线构建的静态簇结构展开，**未讨论插入、删除与增量更新**，也未评估分布漂移下的簇质量退化。对真实在线系统而言，这是从论文到产品的关键缺口。
- **单机单盘验证**：实验固定在单机、单块 PCIe 5.0 SSD 上，未涉及多盘并行、NVMe-oF 或存算分离架构；TriVS 的“批量无依赖 I/O”在多盘条带化下预期收益更大，但缺少实证。
- **构建成本缺失**：未报告索引构建时间、峰值内存与逐子树构建的额外开销，而“更粗聚类 + 单归属”虽降低了内存与存储，其对构建期资源的影响未被量化。
- **基线覆盖不完整**：SPANN 在部分大规模/高维数据集上因构建超内存被省略，簇级对比并不完整；Wiki 为自建 RAG 数据集，其代表性依赖生成方式。
- **统计严谨性**：未报告多次运行的方差或置信区间，微基准实验多为单次测量，结论的稳健性缺少统计支撑。

## 8. 总体评价与启示

- **思想层面**：TriVS 的贡献不是某个单点优化，而是一个**结构性观察**——查询的“逼近”与“收敛”天然需要不同搜索粒度，而现有系统把二者绑死在同一粒度上，才导致“省了逼近 I/O 就放大收敛 I/O，反之亦然”。用纯内存蒸馏作为两种粒度之间的桥，是简洁且可复用的设计范式。
- **系统层面**：论文体现了“**减少 I/O 优于隐藏 I/O**”的判断。PipeANN 走的是流水线隐藏路线，TriVS 走的是从源头削减每查询 I/O 量路线；在 SSD 带宽成为共享瓶颈的多核场景下，后者具有更好的扩展上界，这一对比本身对存储系统设计具有普遍意义。
- **工程完成度**：AVX-512 FastScan、SQ8 保守取整保下界、按簇密排以提升页命中、内联/池化双模式等细节，说明作者不仅提出思路，也处理了落地时的对齐、精度与调度问题。
- **实验说服力**：通过 PipeANN+R（同量化位宽）与 DiskANN+C（同内存预算）两组对照，较有效地隔离了“量化方法”和“内存差异”两个混淆因素，并主动报告单线程劣势，整体较为克制、可信。
- **适用边界**：最适合**读多写少、内存可容纳质心与量化码、SSD 随机读为瓶颈**的十亿级检索场景；对强动态更新、内存极度受限或延迟要求极低的场景，需额外机制配合。
- **可延展方向**：将粒度解耦思想推广到多向量/多模态混合检索、GPU–SSD 异构流水线，以及为蒸馏阶段引入学习型或自适应精度分配，都是自然的后续工作。
