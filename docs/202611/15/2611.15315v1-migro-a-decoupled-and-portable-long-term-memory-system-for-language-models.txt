ABSTRACT 

Language models evolve, but the observations, revisions, and context accumulated through user interac-tions should remain usable. Each new model must be able to retrieve past evidence, track revisions, and add new observations. We present MIGRO , a decoupled long-term memory system that treats experience as a persistent state shared across successive language models. MIGRO follows a simple principle: preserve historical evidence exactly, organize it approximately, and decide what to retrieve only when the question is known. We call this asymmetric fidelity with deferred selectivity . A shared semantic index supports retrieval, while exact records retain observations and their historical relationships. Because models differ in vocabulary and tokenization, host-specific interfaces convert selected evidence into inputs the receiving model can use. Reversible encoding reduces archival storage while enabling exact recovery. The shared state and its access interfaces let successive hosts read and extend the accumulated experience. On matched LoCoMo states, MIGRO scores 7.3% higher and uses 99.3% less private memory than the strongest quality baseline. After handoff, continued writing retains 99.9% of full-history rebuilding quality by extending the inherited state. On million-token BEAM histories, MIGRO uses 57.5% less private storage on average than the most compact baseline. MIGRO combines high answer quality, continued memory growth across hosts, and low storage cost (Figure 1). Code is available at https://github.com/zOUMINGXI/MIGRO.

Research on language model memory has advanced along complementary directions. Neural approaches integrate past information through learned representations and model states [3–6]. Retrieval-augmented and agent memory systems retain explicit evidence beyond the active context [7–10], while memory-management frameworks organize evolving records and shared resources [11, 12]. External records can already be shared across models, as illustrated by plugin and text-based memory systems [10, 13]. An earlier revision may be lost when memory is summarized, while surviving evidence may still be difficult for a new host to retrieve or interpret [14]. Preserving history and making it usable are therefore distinct requirements. Successive revisions may share a semantic neighborhood while answering different questions about the past. A durable memory must retain those distinctions before knowing which ones will matter, including their source and historical relationships [15, 16]. This motivates two complementary principles. Asymmetric fidelity preserves historical evidence exactly while allowing approximate semantic addresses that index observations for retrieval [17, 18]. Deferred selectivity 

postpones evidence selection until a question is known. At read time, an evidence packet provides a temporary view of the observations or exact spans selected for that question. Future readers can revisit the retained history with new questions instead of relying on an interpretation fixed at writing time. We introduce MIGRO, a decoupled long-term memory system that realizes this separation through one persistent experience state and host-specific interfaces. Writing retains canonical observations, their provenance, historical order, and available reference links; reading selects relevant evidence and adapts it to the receiving model’s vocabulary and tokenization [19]. Reversible predictive coding stores this state in an archive, its physical persistent form, from which the saved records can be recovered [20, 21]. Changing the host replaces the access interface; subsequent writes extend the inherited state. The experiments examine three consequences of this design across conversational, operational, and long-horizon memory tasks [1, 2, 22–24]. Access ablations reveal how semantic similarity alone can miss complementary evidence. Handoff and continued-writing studies show that inherited history can remain useful and continue growing under new hosts. Matched-state and long-history measurements show that exact preservation can coexist with compact states and low marginal storage cost. Our contributions are organized around three complementary requirements of long-term memory: 1. High-quality memory through fidelity-aware access. We introduce asymmetric fidelity with deferred selec-tivity , separating exact historical evidence from approximate semantic organization and query-conditioned access. Shared semantic anchors, observation-specific innovations, and contextual evidence retrieval realize this principle, supported by a formal characterization of information preservation and semantic ranking stability. 2. Portable memory with continuous experience accumulation. We develop a decoupled experience state that successive language models can access and extend through host-specific interfaces. 2.1 A Fact Revision Across Model Replacements 

A user states that a project’s budget is 17 in version 1, then revises it to 18 and 19 under successive hosts. What is the latest budget? and What was the budget in version 1? require different answers, 19 and 17, from the same evolving history. When the original host returns, both questions should remain answerable. Table 10 in Appendix D.1 expands this illustrative trace. The example separates three ideas. Semantic similarity does not make observations identical: all three statements concern the same budget but record different values. The latest answer does not replace the full history: retaining only 19 erases the evidence for the first version. Model replacement does not change historical identity: a receiving host inherits earlier records and adds its own observations to that history. Semantic addresses organize these related records into a common neighborhood. Independent source bindings retain their content, provenance distinguishes their origins and historical positions, and query-time selection determines which version supports the answer. Local discourse links add contextual access hints within a bounded same-session window; cross-session revisions can remain unlinked while their evidence is still preserved.

2.2 One State, Four Operations 

Writing adds an observation, its address, and its historical relationships to the durable state. Reading leaves that state intact and constructs a temporary, attributed evidence packet for the current question and host. Persistence encodes the saved state so that its records and access structure can be recovered. Handoff attaches a new host interface to this state, allowing the receiver to read inherited observations and continue writing. Algorithm 1 in Appendix D.4 connects these operations. 3 Problem Formulation and Design Principles 

Long-term memory must preserve an evolving history while allowing changing models to use it. The budget example exposes both requirements: the state must retain distinct revisions, and a reader must select the revision relevant to its question. We formalize this separation before deriving the design principles. 

3.1 Experience as a Persistent State 

What must persist when the host changes? MIGRO separates three roles: exact evidence retains source-token bindings, provenance, and history; access structure organizes observations through semantic anchors and address innovations; contextual relationships retain references between records. An accepted observation is oi = ( xi, mi), where xi is its content and mi contains available provenance, including speaker, role, time, session, and source identity. Observations arrive chronologically and may be written by different hosts hi, each with frozen parameters θhi . Shared canonicalization σ normalizes each accepted observation, and a source tokenizer τs yields vi = τs(σ (oi)) . We call this saved content representation canonical evidence . Throughout, 

exact recovery means recovery of these saved source-token IDs and their associated saved state; it does not mean unconditional reconstruction of input forms discarded before canonicalization. After n observations, the persistent state is 

Mn = ( An, Dn, Xn, Pn, Gn, Vn). (1) Here (Xn, Pn, Vn) hold source bindings, provenance, and retained history; (An, Dn) hold anchors and address innovations; and Gn holds reference relations. Shared dependencies B specify how to represent source tokens, reconstruct addresses, and decode archives across hosts. The observations remain user-specific; these dependencies are reusable resources.

3.3 Deferred Selectivity: Why Preservation Precedes Access 

Long-term memory faces an asymmetry in when information becomes relevant. At write time, the questions that will depend on an observation are unknown. At read time, the question is available and evidence can be selected accordingly. Persistence must retain distinctions that future questions may require; reading must expose the relevant distinctions within the current model’s access budget. Let Rn = (( vi, ¯mi, i)) ni=1 denote the accepted canonical history, including source-token sequences, saved historical metadata, and observation order. For a family of future questions Q, let Ans (q, R) be the answer determined by history R. Two histories are equivalent when no question in that family distinguishes them: 

R ∼Q R′ ⇐⇒ Ans (q, R) = Ans (q, R′) for all q ∈ Q. (4) This relation identifies what a memory must preserve for the given family. The encoding–query separation connects information-theoretic compression to communication complexity [25–27]. 

Proposition 1 (Irreversibility of query-distinguishable information loss) . Let F be a query-independent memory encoding. If F(R1) = F(R2) but R1̸ ∼Q R2, no readout using only q and F(R) can guarantee the correct answer to every question in Q for both histories. 

In the running example, irreversibly overwriting the version-1 budget 17 with 19 removes the evidence needed to answer the version-1 question. A stronger future model cannot recover that value from the current state alone. By contrast, a record omitted from today’s evidence packet remains available to another query. Deferred selectivity preserves the possibility of reinterpreting history before choosing what to expose on each read. The binary-fact example in Appendix E.2 develops this distinction. This separation becomes more valuable as future readers acquire new capabilities and information needs. For nested question families, 

Q1 ⊆ Q2, R ∼Q2 R′ =⇒ R ∼Q1 R′. (5) The broader family refines the distinctions that memory must retain. An encoding sufficient for an earlier task can merge histories that a later task separates. Canonical history preserves the opportunity to revisit those observations under new questions and stronger models. 

3.4 Asymmetric Fidelity: Exact Evidence, Approximate Addresses 

A book’s contents must be preserved, but its index need not encode enough information to reconstruct every page. The same distinction applies to memory: source bindings determine which historical record is preserved, while semantic addresses help locate it. Compact access geometry can therefore tolerate approximation without merging record identities. MIGRO assigns different fidelity requirements to these roles. The components (Xn, Pn, Vn) retain canonical evidence and its historical context. The components (An, Dn) organize semantic access through quantized shared representations, while Gn retains explicit reference relations. 4 MIGRO Architecture and Lifecycle 

The architecture must locate preserved observations, deliver them within a host’s input budget, and store the growing history economically. MIGRO uses semantic addresses for lookup, evidence packets for query-specific access, and archives for persistence (Figure 3).

4.2 Budgeted Retrieval and Host Adaptation 

Reading has two tasks: choose the evidence, then deliver it to the receiving model. Retrieval can fail by missing a relevant record or its supporting context. Delivery can fail even with the right records because models use different vocabularies, token boundaries, and embedding spaces. Retrieval constructs a bounded packet from the accumulated state. Reconstructed-address similarity and lexical matching generate candidates, followed by frozen cross-encoder reranking and diversity-aware selection of K

primary relevance seeds [18, 30]. Chronological reserves keep older observations eligible, while local and reference-linked support can supplement the seeds. 4.4 Resource Model and Implementation 

A small user state does not by itself determine deployment cost. MIGRO also relies on reusable representation, retrieval, and decoding assets. The relevant questions are how private bytes grow with experience and how fixed resources are shared across independent memories. Private persistent state contains recoverable evidence, addresses, provenance, references, history, and archival metadata. Shared resources include representation models, tokenizers, retrieval components, host interfaces, and decoding dependencies [34]. Temporary workspace holds decoded records, indexes, reconstructed addresses, transport tensors, and inference caches; it is accounted for separately from persistent storage. 5.3 Model Capacity and Memory Utilization 

When both memory construction and reading move to larger Qwen hosts, MIGRO improves consistently across the evaluated checkpoints, from 54.13 at 4B to 61.83 at 32B (Table 2; Figure 5). Each checkpoint builds a fresh memory and reads it with the same model. This sweep therefore measures scaling of the complete construction-and-read system. Larger hosts do not improve all memory systems proportionally. MIGRO improves at every tier, while LSTMem peaks at 8B under state-only reading. How observations are retained, organized, and presented affects whether greater model capacity translates into better memory answers. These system-level trajectories combine changes in construction and reading; they do not isolate the effect of a stronger reader on a fixed state. Appendix D.3 records the checkpoint-specific reader and refitting settings.

5.5 Storage Efficiency: Fidelity Without Redundant Persistence 

Storage efficiency must explain both why a state is compact and whether it can remain economical as experience grows. We connect representation and coding ablations to matched-state quality, marginal history growth, and deployment-scale sharing. 

Where the byte savings come from. Figure 4c separates the basic gain from lossless coding and the additional gain from archive selection. The uncompressed archive occupies 2.381 MB; existing lossless coding reduces it

to 0.953 MB; full selection reduces it to 0.870 MB. Full selection saves about 63.5% against the uncompressed archive and a further 8.7% against existing lossless coding. Exact recovery is retained in every accepted encoded candidate. Address organization provides a separate saving (Figure 4f). Anchor + Residual reduces address-table bytes by 91.1% relative to float32, with a 0.46-point LoCoMo gap. 5.6 Joint Design Implications 

Evaluating long-term memory requires following experience across reads, writes, and host changes. Memory qual-ity depends on whether an access interface exposes useful relationships among retained observations. Portability includes the ability to extend inherited experience under a new host. Persistent cost has two scales: marginal growth within one history and infrastructure shared across many histories. Evaluating one snapshot or one receiving-host score misses these lifecycle properties. Figure 1a highlights six selected performance strengths. The largest gains are on LongMemEval-S multi-session QA and temporal reasoning, where MIGRO leads the strongest displayed baselines by 15.79 and 18.80 points, respectively. The transfer panel shows quality across receiving hosts, memory continuity and growth, and reuse without historical replay. Its portable-efficiency axis pairs continued-writing quality with the receiver’s private state size. The storage panel connects compact private states with economical growth: MIGRO has the lowest displayed private footprints, marginal costs over the matched half-history windows, and BEAM deployment cost, together with the highest LoCoMo score per private MB. Appendix D.8 defines the profile axes and normalization. The joint frontier in Figure 12 places continued-writing quality, rebuilding-relative quality and paired private cost in one Mistral setting. MIGRO combines the highest inherited-state answer quality with the smallest inherited-state footprint, yielding 2.60 times the best baseline’s answer quality per private MB across all eight methods. 

5.7 What Remains Difficult in Long-Term Memory 

On BEAM-1M, information extraction scores 66.92 and preference following 79.64, compared with 39.64 for contradiction resolution and 37.44 for event ordering (Appendix D.2, Table 12). Preserving facts is different from reconstructing their relationships. The harder questions require the reader to connect versions, recover temporal order, and combine evidence across records. Their scores do not identify one failing stage, but they expose the distance between retained observations and an accessible historical account. 

> 15

## MIGRO 

Exact preservation keeps historical distinctions available. The remaining challenge is to make the relationships among those distinctions accessible when a question demands them. By keeping experience independent of its current reader, MIGRO provides a persistent foundation on which future memory access and reasoning can improve. 

6 Conclusion 

MIGRO organizes long-term memory around the continuity of experience across model changes. By separating preservation from access, it keeps historical evidence exact while allowing semantic organization and query-specific inputs to adapt. The completed evaluations connect this design to competitive question answering, effective state reuse across heterogeneous hosts, and continued writing close to full-history rebuilding, alongside compact persistence and low marginal storage growth. Quality, portability, and storage jointly determine whether accumulated experience remains useful as both the history and its consuming model change. The broader implication is a different relationship between model progress and memory growth. A model upgrade can change how earlier observations are interpreted without erasing the evidence available to future questions. Continued writing extends that history under the receiving host, making portability a continuity of accumulation rather than a one-time transfer. Preserving experience independently of its current reader leaves room for advances in retrieval and historical reasoning to improve how that experience is used. The model can change; the history that supports future reasoning can continue to grow.

A Relationship to Prior Work 

MIGRO connects four research threads: learned access to retained representations, external evidence separated from active context, hybrid representations with explicit preservation criteria, and interfaces that reuse memory across consumers. The distinctions concern what is stored, how it is accessed and which resources remain tied to a model. 

A.1 Neural and latent memory: extending computational state 

Memory Networks make addressable memory participate in inference; the end-to-end formulation learns repeated attention over supporting memories [39, 40]. Compressive Transformers extend the past through compressed activations, while Memorizing Transformers retrieve internal key–value pairs through approximate nearest-neighbor lookup [3, 41]. In both cases, the retained representation extends what the model can use beyond its ordinary active window, under conventions designed with the consuming architecture. Factual model editing changes selected weights to alter stored associations [42]. MemoryLLM, LSTMem and TransMem explore latent pools, online state accumulation or context-derived interventions as further forms of learned memory [36, 37, 43]. Their storage and update rules give retained experience different computational roles. MIGRO uses learned representations for semantic organization and interpretation, while independent source bindings define historical identity. Metis learns native memory procedures through memory-specific mid-training. Its persistent dynamic state is updated by forward computation and accessed through memory attention [4]. MemT-1.0 extends this approach with dynamic local memory, trainable hyper memory, stable token-level Gated DeltaNet-2 updates and Mixture-of-Storage capacity scaling [5]. δ -mem instead adds a compact associative matrix alongside a frozen full-attention backbone, writes with a gated delta rule, and uses the readout for low-rank attention corrections [6]. These designs make compact retained state part of active computation. MIGRO assigns a separate role to its growing canonical history: preserving exact observations that later computations can revisit. MemOS broadens the managed objects to plaintext, activation and parameter memory. Its MemCubes include provenance and versions and support composition, migration and lifecycle management [11]. This system-level view establishes that portable memory can encompass several representation types. MIGRO specifies which observation fields persist, how each host reads and extends them, and how an archive recovers the saved state.

A.2 Explicit and retrieval-augmented memory: separating records from active context 

REALM and RAG couple neural models to externally retrieved documents, and dense passage retrieval provides learned semantic access to that corpus [7, 18, 44]. The corpus can persist independently of the model’s parameters while retrieval constructs a query-specific input. This is an established foundation for memory surviving a model instance. Agent memory extends this separation to evolving interactions. Managed recall, reflections, linked descriptors, extracted knowledge and temporal hierarchies organize an agent’s experience [8–10, 13, 35, 45]. Several such systems already retain original content or pursue model independence. The relevant comparison is therefore how retention, bounded access, continued growth and host replacement are connected, rather than whether a system uses external storage. Recent work exposes the lifecycle structure more directly. Hindsight separates world facts, experiences, entity summaries and evolving beliefs, while EverMemOS connects episodic MemCells, consolidated MemScenes and reconstructive recall [12, 46]. Zep uses time-aware facts, and MemoryLACE retains provenance-bearing textual units linked by merge, supersession and contradiction relations [47, 48]. These structures make historical relationships part of retrieval rather than leaving them implicit in an undifferentiated transcript. Other designs change the granularity or timing of access. H-Mem combines temporal and semantic trees, and HiGMem uses event-summary anchors to reach individual turns [49, 50]. MRAgent explores a Cue–Tag–Content graph during reasoning, while RecMem delays consolidation until recurrent evidence supports it and refines access to finer facts [51, 52]. Such mechanisms determine which retained evidence can be recovered economically. Long-context position effects further distinguish available records from evidence a model can use effectively [31]. MIGRO makes the delivered packet and its source-token cost explicit at this boundary. 

A.3 Hybrid representation and evidence preservation: assigning fidelity 

Product and additive quantization compress vector coordinates for approximate search [17, 28]. An approximate address can locate an exact object, which motivates assigning separate fidelity criteria to search geometry and source evidence. Database provenance and temporal databases provide the corresponding distinction between a current value, its origin and its historical states [15, 16]. MIGRO combines quantized address organization with explicit source attribution, record order and retained content. Mem++ is a close preservation strategy: it keeps complete dated, attributed documents and selects relevant versions at read time [53]. SimpleMem instead synthesizes compact semantic units and plans retrieval by intent; VikingMem evolves an event/entity base with topic-wise temporal compression [54, 55]. The preservation criterion matters to this comparison. MIGRO’s archive recovers the saved source IDs, coordinates and bookkeeping, while its active packet is selective. DeMem, Remember the Decision, Not the Description , measures compression through achievable decision quality under a fixed number of runtime states. Certified conflicts trigger partition refinement [56]. This is complementary to retaining canonical experience for an expanding family of future questions: runtime abstraction limits what one decision process carries, whereas durable preservation determines what future processes can revisit. Information theory distinguishes relevance-preserving abstraction from redundancy removed by a reversible code [20, 21, 25, 26]. Section 3.3 expresses preservation through query-distinguishable histories. The causal archive then exploits statistical regularity without changing that saved history. Semantic quantization changes address coordinates, selection limits the evidence packet, and lossless coding reduces archive bytes while preserving the saved state. 

A.4 Portable interfaces: changing consumers around retained experience 

A persistent record and a model input have different lexical conventions. Token identities, segmentation and normalization depend on the tokenizer [19]. MIGRO separates a canonical source vocabulary from the receiv-ing vocabulary and constructs target embeddings through lexical/subword hypotheses. Exact source recovery establishes what survived. Successful host interpretation establishes whether the receiver can use it. Frozen-memory extraction studies this receiving boundary by attaching an external learned table to another backbone through compatible or adapted readers [29]. Model-upgrade experiments distinguish construction losses from retrieval and interpretation failures, including repair enabled by original histories [14]. Metis also applies

its architecture and mid-training recipe to compatible Llama and Gemma backbones [4]. That comparison tests architectural and training transfer. MIGRO tests a complementary object: the same accumulated user state handed between receivers, with continued writes and exact saved-state restoration. Continuous prefixes and LoRA localize adaptation while keeping pretrained backbone weights frozen [32, 33]. LongMem decouples a frozen backbone from a learned SideNet reader, while TransMem and Doc-to-LoRA derive reusable latent interventions or low-rank adapters from context [37, 38, 57]. D.7 Runtime Complexity and Operating Conditions 

Construction, retrieval and generation can shift resource costs independently of archive size [59]. With a anchors, address assignment scans residual errors in O(a(da − r)) arithmetic. Host-local writing is bounded in record count, with compute still determined by the admitted token lengths. Inputs must fit the host context; an over-context local batch is rejected. Reader construction can traverse all n records to reconstruct addresses and lexical statistics. The reference dense scan costs O(nd a), followed by bounded cross-encoder scoring and greedy seed selection. Transport adds source-vocabulary similarity and target tokenization. Generation then depends on the expanded evidence and answer length. A fixed evidence cap bounds delivered content without eliminating these preparation costs. Causal encoding and decoding process the complete predictor-token stream. Page-local context bounds each predictive window, while total reconstruction work grows with the number of pages. Compact persistence thus trades archive bytes against shared prediction and restoration work. The cold archive and the temporary serving representation serve different roles: one retains recoverable history economically, and the other supports active access.

E.1 Proofs of the Preservation and Stability Propositions 

Proof of Proposition 1. There is a question q⋆ with Ans (q⋆, R1)̸ = Ans (q⋆, R2). Its query and encoded memory are identical in the two cases. A deterministic readout produces the same answer; a randomized readout has the same output distribution. Neither can guarantee both required answers from that same input.

E.2 An Information-Theoretic Illustration of Deferred Selectivity 

Consider a history with Nf independent binary facts and a future question family that can request any individual fact. Every pair of different binary histories differs at some position, and a question about that position distinguishes them. A query-independent, zero-error fixed-length encoding must therefore distinguish all 2Nf histories, requiring at least Nf bits [25, 27]. Once the question supplies the requested position, one bit communicates the corresponding value. Preserving information for a family of possible future questions and delivering information for one question have different in-formation requirements. MIGRO retains a recoverable canonical history and constructs compact query-conditioned evidence packets from it.

E.6 Causal Coding and Exact Archive Selection Exact decoding conditions. Encoding and decoding use matching predictor and coding-tokenizer versions, integer-CDF convention, page framing, numerical precision, attention backend, and batch schedule. Surface and source-ID exceptions retain tokenizer-sensitive distinctions. Each new causal candidate is independently restored and compared with the saved state before admission. MIGRO reduces persistent bytes through reversible causal coding. A frozen predictor assigns probabilities within bounded, same-scope pages, and arithmetic coding converts them into a recoverable bitstream [20, 21].
