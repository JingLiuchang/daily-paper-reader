## 摘要
基于大语言模型的任务导向智能体依赖工具与环境交互，但可能忽视执行反馈、重复无效调用，或坚持无成效策略。这些行为会阻碍智能体自主使用工具并维持任务进展。我们在两个时间粒度上刻画工具使用症状：局部笨拙的工具使用行为，以及跨越多次交互的工具使用绕行。为实现更高程度的工具使用自主性，我们提出 ToolPulse，一种通过线索提示与识别支持自主工具使用的在线中间件。ToolPulse 跟踪执行状态和时间交互模式，在派发前监测拟议调用，并在智能体恢复推理前检查执行反馈。它结合基于状态的规则、语义序列分析和交互特征相似度来识别干预机会，并提供口头提醒、结构化反馈或来自辅助模型的上下文特定建议。我们的面向过程评估区分触发有效性、行为停止和实质性纠正，并结合任务结果与资源成本。使用 SWE-agent 和三个骨干模型，我们在 90 个 Python、C++ 和 Java 缺陷修复任务上评估了 1,350 条轨迹，比较无辅助执行与四种辅助策略。对于工具使用绕行，61.6%–90.9% 的有效触发后会出现实质性响应。简洁提醒取得了观察到的最高总体实质性响应率；更精细的辅助带来依赖症状的收益，且可能效果较差。总体修复结果仍接近基线，在部分设置中节省了 token。这些发现支持面向自主工具使用的主动运行时辅助。行为调整与总体修复收益之间的差距，要求在自主智能体中谨慎决定干预时机与辅助策略。

## Abstract
LLM-based task-oriented agents depend on tools to interact with their environments, but may overlook execution feedback, repeat ineffective calls, or persist with unproductive strategies. These behaviors can hinder agents' ability to use tools autonomously and sustain task progress. We characterize tool-use symptoms at two temporal granularities: local clumsy tool-use behaviors and tool-use detours spanning multiple interactions. Towards greater autonomy in tool use, we present ToolPulse, an online middleware supporting autonomous tool use through cueing and spotting. ToolPulse tracks execution state and temporal interaction patterns, monitoring proposed calls before dispatch and inspecting execution feedback prior to the agent resumes reasoning. It combines state-based rules, semantic sequence analysis, and interaction-feature similarity to identify intervention opportunities and provide verbal reminders, structured feedback, or context-specific advice from auxiliary models. Our process-oriented evaluation distinguishes trigger validity, behavioral cessation, and substantive correction alongside task outcomes and resource costs. Using SWE-agent with three backbone models, we evaluate 1,350 trajectories on 90 Python, C++, and Java bug-fix tasks, comparing unassisted execution with four assistance strategies. Substantive responses follow 61.6-90.9% of valid triggers for tool-use detours. Concise reminders achieve the highest observed aggregate substantive-response rate; more elaborate assistance offers symptom-dependent benefits and can be less effective. Aggregate repair outcomes remain close to baseline, with token savings in selected settings. These findings support proactive runtime assistance for autonomous tool use. The gap between behavioral adjustment and aggregate repair gains calls for careful decisions on intervention timing and assistance strategy in autonomous agents.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：基于 LLM 的任务导向智能体虽然能调用工具，但在长程执行中常出现“笨拙”的工具使用：忽视工具反馈中的诊断信息、重复无效调用、在已有证据表明策略失效时仍持续坚持。现有研究多关注工具调用准确率与最终任务成功率，较少刻画这些问题**如何在执行过程中产生并持续**。
- **两类症状的时间粒度**：
  - **局部笨拙工具使用行为（clumsy tool-use behaviors）**：单个动作或短邻接动作序列中不必要、缺乏依据或明显冗余的调用，如未查看文件就编辑、连续重复同一调用。
  - **工具使用绕行（tool-use detours）**：跨越多次交互的持续性无效模式，单步看可能合理，但整体不推进任务，如功能性循环、策略固着、重复失败却无恢复。
- **背景与缺口**：
  - 工具文档只提供声明性知识，无法覆盖执行中的具体情境；工具输出通常作为临时观察追加到历史中，智能体未必能将其与演化中的执行状态关联。
  - 现有改进路径包括轨迹精炼、经验复用、离线训练，但依赖额外探索、可迁移经验或参数更新，难以在执行中即时补位。
  - 已有在线干预工作（如 Wink 固定间隔异步检查、LivePlan 预定义规则触发）存在检查间隙或难以识别“近似重复”导致的停滞。
- **整体含义**：论文主张把“运行时支持”作为智能体执行基础设施的一部分——环境不仅提供工具和反馈，还应维护交互证据并在适当时机提供选择性辅助，同时保留智能体的决策自主权。软件工程缺陷修复任务因具备检索、编辑、测试验证的长程工具交互，被选为代表性研究场景。

## 2. 方法论：ToolPulse 的核心思想与技术细节

### 2.1 核心思想

- 借鉴健身中的“保护者（spotter）”隐喻：**智能体负责“举重”**（理解任务、选择工具、解释反馈、决定后续动作），ToolPulse 只在检测到症状时提供**线索提示（cueing）与识别辅助（spotting）**，不代替智能体决策。
- 采用**状态流跟踪 + 双检查点 + 多粒度检测 + 选择性干预**：
  - **执行前检查点**：在动作派发前检查拟议调用，可拦截缺乏环境依据的操作。
  - **执行后检查点**：在工具返回后、智能体恢复推理前检查反馈与近期轨迹。
- 形式化地，第 \(t\) 步执行前上下文为 \(H_t^-=(q,\tau_{<t},r_t,a_t)\)，执行后为 \(H_t^+=(H_t^-,o_t)\)；若拦截则 \(o_t=\bot\)。最终观察为：
  - 拦截时 \(\tilde o_t=m_t\)；
  - 正常执行时 \(\tilde o_t=o_t\oplus m_t\)（原始输出与辅助信息联合呈现）；
  - 无触发时 \(m_t=\varnothing,\ \tilde o_t=o_t\)。

### 2.2 六类症状与检测机制

论文沿**探索、进展、依据、恢复**四个维度组织三类局部笨拙行为和三类绕行：

| 维度 | 症状 | 类别 | 检测方式 |
|---|---|---|---|
| 探索 | Wandering Flood | 局部笨拙行为 | 不进行在线检测；任务结束后离线两阶段评估 |
| 进展 | Calling Repetition | 局部笨拙行为 | 基于状态的规则 |
| 进展 | Functional Cycle | 绕行 | 语义序列 + Sequitur |
| 进展 | Strategic Fixation | 绕行 | 交互特征相似度 + Matrix Profile |
| 依据 | Blind Command | 局部笨拙行为 | 基于状态的规则 |
| 恢复 | Failure Inertia | 绕行 | 错误签名 + 规则/语义判断 |

- **Calling Repetition**：连续三次拟议动作的工具名与参数完全相同即触发，即 \(CR_t=\mathbf{1}[t\ge3\land a_{t-2}=a_{t-1}=a_t]\)。相比试点中“两次即触发”，主实验延迟到三次，给智能体自主纠错机会。
- **Blind Command**：若拟议编辑文件 \(f\)，但 \(f\) 不在此前通过查看类动作已观察内容的文件集合 \(V_{t-1}\) 中，则触发，即 \(BC_t=\mathbf{1}[\text{Edit}(a_t,f)\land f\notin V_{t-1}]\)。
- **Failure Inertia**：为失败调用定义错误签名 \(\sigma_t=(u_t,\text{errorType}_t,\text{errorFingerprint}_t)\)。若最近一次失败 \(i\) 与当前失败签名相同，且两步之间没有任何变更类语义动作（\(z_j\in\mathcal{L}_{\text{change}}\)），则触发。回看窗口为 8 步。
- **Functional Cycle**：将每次工具调用映射到缺陷修复导向的语义标签（如检索、浏览、编辑、测试成功/失败/报错等），用 Sequitur 增量文法归纳重复序列；当长度大于 2 的同一标签序列在轨迹末尾连续出现三次时触发。每个不同语义序列在每个任务中最多触发一次，避免重复干预。
- **Strategic Fixation**：将每个交互编码为特征向量（推理长度、工具名与参数哈希、观察长度、执行时间、错误指示），取最近 \(3w\) 步分为三个不重叠窗口 \(W_1,W_2,W_3\)，用 Matrix Profile 计算窗口距离；若三对相邻窗口距离均低于阈值 \(\theta_S\)，则判定为策略固着。
- **Wandering Flood**：因依赖任务上下文、宽泛检索可能合理，故不做在线干预。离线评估分两阶段：先用各语言、各骨干模型下 Retrieve 类动作的观察长度与执行时间第 95 百分位筛选候选步，再由 LLM 判断是否属于“范围明显过宽、存在更聚焦替代方案、信息增益有限”的探索。
