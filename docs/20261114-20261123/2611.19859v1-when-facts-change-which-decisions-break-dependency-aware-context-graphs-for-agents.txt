# When Facts Change, Which Decisions Break? Dependency-Aware Context Graphs for Agents 

Paul Deepakraj Retinraj Scale AI 

paul.retinraj@scale.com 

Abstract 

When an observed fact changes, an agent must identify and repair dependent decisions while preserving unaffected outputs. We study the reliability–cost trade-off of field-level dependency graphs extracted from actual agent read traces. A controlled benchmark spans three executable workflow domains and four successive updates, with separate imperative and expression-based references. Across 120 workflows, two gateway models, and two repeated runs, we compare full recomputation, rolling summary memory, lexical retrieval, trace-extracted dependencies, and verified dependency upper bounds. Trace-derived graphs reduce review work but can omit unvisited alternatives and necessary repair context. Paired ablations examine edge deletion, spurious edges, transitive propagation, and context scope. An exploratory enhancement adds the observable record ID/field directory during extraction without revealing unread values or reference edges. On 60 fresh workflows with two repeats, the enhanced graph matches observed full-context complete-plan correctness for gpt-6.1-sol (100%) with an estimated 4.0% total-cost reduction, but reaches only 84.8% versus 99.6% for gpt-6-luna. The findings motivate evaluating selective repair with executable correctness and full memory-processing cost together. The evidence concerns explicit procedural workflows and does not establish broad real-world agent-memory generalization. 

# 1 Introduction 

Agent decisions can remain in memory after the facts supporting them change. A supplier selected under an earlier delivery estimate may become ineligible; downstream spend, approval, and reminder decisions can then become stale. Revising a fact alone is insufficient, while recomputing every output may incur unnecessary work. Explicit dependencies offer a way to select candidate decisions for review, but their usefulness depends on the completeness of the extracted support structure and the evidence available during repair. We investigate this trade-off with a prototype context graph and a controlled executable workflow benchmark. The central question is not whether reverse reachability identifies graph descendants, but whether a graph extracted from an agent’s actual observations supplies enough information to maintain a correct plan across successive updates. An initially sufficient read trace need not describe every alternative that can become relevant later. This creates a mismatch between initial planning and future repair. Our contribution is an empirical evaluation rather than a claim that dependency tracking or cascading invalidation is new. We provide: (i) sequential workflows with executable reference decisions, (ii) comparisons that include initial planning, memory construction, maintenance, and repair cost, (iii) paired dependency and context ablations, and (iv) fresh-workflow evaluation of a simple observable-directory enhancement. We report failures and limitations alongside successes. 1arXiv:2611.19859v1 [cs.AI] 15 Nov 2026 The results do not support an unconditional replacement of full-context recomputation with extracted graph repair. 

# 2 Related work 

StateGraph explicitly models state dependencies, verifies counterfactual support, handles alternative support, and evaluates selective cascade revision and public-memory tasks [1]. PACMI studies provenance-aware cascading memory invalidation and repair [2]. These are directly overlapping mechanisms. We do not reproduce either system and cannot claim comparative superiority. 

Impact Is Not Invalidation distinguishes a changed artifact’s impact from whether a stored claim actually becomes false, using executable claim ground truth [3]. Our candidate sets are likewise separated from decision correctness: reachability is a conservative review signal rather than proof of invalidity. LongMemEval evaluates long-term interactive memory, including knowledge updates and tempo-ral reasoning [4]; AMA-Bench studies long-horizon memory for agentic applications and causality-graph-based memory [5]. Our external LongMemEval check is evidence-only calibration, not full-history evaluation. The narrow framing here is the reliability and total cost of trace-derived field dependencies for executable workflow repair over repeated updates.

3.2 Initial agent and extraction 

The initial agent receives policies and a record directory containing IDs and field names, but not values. It makes an actual read_records function call, receives the requested observable records, 2and returns a plan with brief public explanations. Each repair method shares that initial plan within a workflow/model/repetition trial. The main extractor receives the policies, plan, and actual tool-read results. It is instructed to enumerate direct field dependencies, including alternatives that may become relevant after changes. It does not receive reference expressions or reference dependencies. Unknown IDs, invalid fields, self-supports, and malformed annotations are rejected by the harness. Extraction quality is measured against conservative static expression references, including alternative branches; these labels are not necessary-active-cause annotations. 

3.3 Repair methods 

Full context. 

Recompute all decisions using all current fact records and the prior plan. 

Rolling summary. 

Create a working memory prompted to at most 1,200 characters, update it with each fact patch, and recompute all outputs from that memory. This is a prompted limit, not hard truncation. 

Lexical retrieval. 

Use a fixed keyword-overlap rule to choose eight decisions and eight fact records. This is a lightweight lexical baseline, not an embedding retriever or a reproduction of a named memory system. 

Extracted graph. 

Select graph candidates, retrieve their recursively required support fields and stored decision values, and ask the model to recompute the requested outputs together. Unselected outputs are retained. 

Verified graph. 

Use reference dependency annotations with the same graph selection and repair machinery. This is a diagnostic upper bound with free oracle annotations, not a deployable method with measured annotation acquisition cost. Missing information can produce null/unknown outputs, which count as incorrect. If the candidate set is empty, no repair call is made. There are no paid SDK retries, deterministic replacement answers, or hidden fallback methods. 

# 4 Experimental design 

4.1 Procedural workflows 

The main set contains 120 workflows, 40 per domain: procurement, scheduling, and resource alloca-tion. Procurement includes supplier eligibility, alternative suppliers, spend, approval, ownership, and dependent reminders. Scheduling includes job ordering, sequential start/finish calculations, deadlines, and downstream coordination. Resource allocation includes ordered demand allocation, remaining capacity, coverage, costs, and ownership. Each workflow includes unrelated fact records and four independent noise decisions. Development and test families differ in numbers of alternatives, reminder chain length, or noise volume. There are only two test families per domain, so parameter instances should not be treated as broad structural diversity. These families are held out from harness development, not model pretraining. Four successive patches introduce a relevant shock, changed eligibility or order, an irrelevant metadata update, and a reversal or late adjustment. Policies define one exact expected answer. The generator cross-checks separate imperative and expression-DAG evaluators at every snapshot. Both evaluators still share the generator and parameters; there is no independent human annotation audit. 34.2 Models, repetitions, and cost 

Two OpenAI-compatible gateway identifiers were used: openai/gpt-6-luna and openai/gpt-6.1-sol ,abbreviated Luna and Sol below. These identifiers and returned served identities are retained, but dated weight snapshots and public availability are not independently established. Responses use low reasoning effort, a 4,096-token output maximum for main study calls, no server-side storage, and disabled retries. Each workflow/model pair has two independent runs. The main study therefore contains 480 initial agent trajectories and 480 × 5 × 4 = 9 ,600 method-update evaluations. 5.3 Exploratory diagnosis 

Failure inspection revealed omitted alternative support and missing repair context. A procurement trace can establish that supplier A is initially eligible without reading suppliers B and C. Later, A may become ineligible; a graph that records only A can lack the fields needed to choose an alternative. A resource-allocation graph can omit the decision selecting which service’s demand applies, leaving an allocation stale after order reversal. Two exploratory arms use the same 30-workflow subset and initial plans. The first retains extracted-graph selection but supplies all current facts during repair. The second adds the complete record ID/field directory to the extraction input without revealing unread values or reference edges. Table 3 reports both. These comparisons were motivated by preliminary main errors, and are not preregistered primary comparisons. Separate model calls introduce sampling variation.

6.2 Graph versus flat-list cost 

We measure 20 queries at each of 100, 1,000, and 10,000 nodes, with the same seven-decision affected chain. The prototype is compared with flat scans and rebuilt adjacency, including edge loading and index construction on every query. All return identical candidate sets. At 10,000 nodes, median query times are 23.55, 19.96, and 19.54 ms, respectively. The prototype loads all 8,750 edges despite the small affected set. Thus this implementation does not demonstrate an inherent speed advantage over equivalent flat dependencies. Persistent reverse indexing is a possible engineering improvement, not a measured result here. The microbenchmark uses local in-memory SQLite under concurrent model activity, not production storage latency. 

# 7 Discussion and limitations 

The main failure mechanism is a distinction between sufficient evidence for an initial decision and sufficient support coverage for future repair. Reverse reachability cannot recover edges or alternative facts that extraction omitted. Correct initial plans can therefore coexist with incomplete repair graphs. A record directory is a simple way to expose possible alternatives without leaking future values, but its benefit is not uniform across the tested models. Total cost changes the efficiency conclusion. The Sol enhancement matches observed correctness on fresh instances, but saves only about 4% over four updates after paying for initial planning and extraction. Low-cost review calls alone would suggest a stronger saving than the full pipeline supports. Conversely, oracle annotations substantially reduce estimated cost in the diagnostic bound, but their acquisition cost is excluded. 8The dataset has explicit rules, modest contexts, one exact answer per output, four updates, and few procedural families. Imperative and expression references agree on generated states, but share a generator and have no independent human audit. The initial agent performs a record-reading action rather than rich long-horizon execution. The lexical baseline is weak and fixed, summaries have prompted limits, and close temporal/dependency methods are not reproduced. Static edge labels include possible alternative supports, not active causal necessity. Graph maintenance, action execution, partial observability recovery through new tool reads, and multiple acceptable repairs are not evaluated. Model aliases and gateway prices are retained, but public dated weight snapshots are not established. Summed call durations under concurrency are not user-facing end-to-end latency. Workflow bootstrap intervals measure variation within this generator, not across organizations or task families. Multiple exploratory comparisons are disclosed without a broad adjusted significance claim. Real workflow traces, human annotation, stronger retrieval, close-baseline reproduction, and additional policy families are needed before broad agent-memory claims.

Rate-based usage is estimated at $34.93; conservative admission accounting with a 25% margin is $43.66. Fifty targeted transport, budget, dependency, and workflow tests pass. No public code-repository availability is claimed in this version. AI tools assisted software implementation, experiment orchestration, analysis, and manuscript drafting. The human author is responsible for the final manuscript and submission. AI-generated annotations are not described as independently human-verified. Generated workflow data contain fictional entities; this study does not involve real procurement, scheduling, or allocation decisions about people. 

# 9 Conclusion 

Trace-derived context graphs reduce review work but can fail when unvisited alternatives or selection-dependent fields are omitted. Directory-aware extraction recovers observed full-context correctness for one tested model on fresh procedural workflows, with a modest total-cost saving, while the other model remains less reliable. Selective repair should therefore be assessed using executable plan correctness, dependency coverage, and full memory-processing cost together. These results support a narrow empirical account of when selective repair fails and succeeds, rather than an unconditional graph-memory advantage.

# A Observable prompts and reference separation 

The initial request provides policies and a record_directory , and requires a read_records 

tool call. The returned records are followed by a request for every decision, value, and brief public explanation; insufficient observations allow null values. Extraction requests direct field-level dependencies and possible alternative supports. The main extraction input has policies, the initial plan, and actual read results. The directory-aware condition adds record IDs and field names, without unread values. Repair requests say: recompute all requested decisions under the latest facts; return exactly the requested IDs; old values may be stale; compute requested dependent decisions together; return null if required information is absent. Inputs contain requested IDs, corresponding policies, latest retrieved context, prior decisions, and the current patch. Reference expression trees, reference outputs, and reference dependency labels are evaluator-only. The verified-graph diagnostic is the explicit exception for edge-based selection and retrieval, not for model answer generation.
