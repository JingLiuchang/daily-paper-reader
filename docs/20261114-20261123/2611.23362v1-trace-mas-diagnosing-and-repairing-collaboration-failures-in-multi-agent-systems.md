## 摘要
基于大语言模型（LLM）的多智能体系统（MAS）不仅依赖单个智能体的行为，还依赖连接智能体的交互，包括消息交换和任务依赖。现有的 MAS 防护机制主要执行智能体级异常检测，当故障源于智能体交互时，这种检测会变得不足，且检测到的异常不一定能揭示其真实来源。为解决这一局限，我们提出 TRACE-MAS，一个用于诊断和修复 MAS 故障的更细粒度框架。TRACE-MAS 从良性轨迹中学习正常的协作执行模式，并检测智能体状态变化、消息转移和任务依赖演化中的偏差。它进一步通过来源感知归因识别负责的执行元素，并选择最小干预来恢复协作，同时保留任务关键能力。在五个 MAS 基准上的实验表明，TRACE-MAS 将根因定位准确率显著提升 60.2%，并在任务恢复方面相较于强 MAS 防护机制取得一致增益。

## Abstract
LLM-based multi-agent systems (MAS) rely on not only individual agent behaviors but also the interactions that connect agents, including message exchanges and task dependencies. Existing MAS safeguards mainly perform agent-level anomaly detection, which becomes insufficient when failures originate from agent interactions and detected anomalies do not necessarily reveal their true sources. To address this limitation, we propose \textbf{TRACE-MAS}, a finer-grained framework for diagnosing and repairing MAS failures. TRACE-MAS learns normal collaborative execution patterns from benign trajectories and detects deviations in agent state changes, message transitions, and task dependency evolutions. It further identifies responsible execution elements through source-aware attribution and selects minimal interventions to restore collaboration while preserving task-critical capabilities. Experiments on five MAS benchmarks demonstrate that TRACE-MAS significantly improves root-cause localization accuracy by \textbf{60.2}\% and achieves consistent gains in task recovery over strong MAS safeguards.

- **整体含义**：论文将 MAS 安全保障从“智能体级异常检测”推进到“执行级协作故障诊断与修复”，统一建模“检测偏差—定位责任执行元素—最小干预恢复协作”。

## 2. 方法论

### 2.1 核心思想

TRACE-MAS 将一次 MAS 执行建模为**部分有序的带类型事件图**，从良性轨迹学习“正常协作执行契约”，并用同一契约完成三件事：

1. 检测智能体状态、消息转移、任务进度变化是否偏离正常协作模式；
2. 通过反事实恢复分析定位真正责任源，而不是最大异常点；
3. 在候选修复算子中选择能最小化残余违规、任务退化和干预成本的最小修复。

### 2.2 执行事件图与上下文编码

- 每个事件表示为  
  \(e_t=(i_t,r_t,q_t,x_t,h_t,m^{in}_t,m^{out}_t,a_t,s_t)\)，分别对应智能体、角色、子任务、上下文、状态、输入/输出消息、可用性和任务进度。
- 执行图 \(G=(V,E_{msg}\cup E_{dep}\cup E_{temp})\)，边分为消息边、任务依赖边、时间顺序边，形成有向无环的部分序图。
- 使用关系感知编码器 ExecFormer 聚合父事件上下文：不同关系类型使用不同投影，并通过注意力聚合，得到事件上下文 \(c_t\)。编码是因果的，不使用未来事件。

### 2.3 执行契约学习与违规检测

- 建模事件转移残差 \(\Delta e_t=(\Delta h_t,\Delta m_t,\Delta s_t)\)，即状态、消息、任务进度的变化。
- 在良性轨迹上学习条件高斯契约：  
  \(p_\theta(\Delta e_t|c_t)=\mathcal N(\mu_t,\Sigma_t)\)，训练目标为负对数似然。
- 违规分数为马氏距离：  
  \(V(e_t)=(\widehat{\Delta e_t}-\mu_t)^\top\Sigma_t^{-1}(\widehat{\Delta e_t}-\mu_t)\)，并对消息和完成通道加权。
- 轨迹在 \(\max_t V(e_t)>\tau\) 时告警；阈值 \(\tau=\alpha\cdot \mathrm{Quantile}_\delta(\{V(e)\}_{e\in D_{val}})\)，仅用良性验证集校准，不需要攻击标签。

### 2.4 源感知归因

- 违规事件集合为 \(\Omega=\{e_t|V(e_t)>\tau\}\)。
- 候选源包括违规事件本身及其 \(H\) 跳祖先，部署中取前 \(C=4\) 个候选。
- 对候选 \(c\)，将其转移替换为契约期望值 \(\mu_c\)，并在契约空间中把恢复传播到后代，得到反事实图 \(G^{res}_c\)。
- 责任分数为跳数折扣后的违规下降：  
  \(R(c)=\sum_{e_j\in\{c\}\cup Desc(c)} \psi^{d(c,e_j)}[V(e_j)-\tilde V_c(e_j)]-\lambda_{pen}P(c)\)，  
  选择 \(c^\star=\arg\max_c R(c)\)。  
  直观上，真正源应能“解释”其后代违规的下降，而症状事件不能因上游违规获得同等信用。

### 2.5 最小修复

- 在 \(c^\star\) 上构造修复空间 \(U(c^\star)\)，包括：
  - 状态恢复：重写智能体状态；
  - 消息纠正：修复或重发消息载荷；
  - 依赖调整：恢复被删除依赖、跳过角色等协调结构。
- 对每个修复算子做 \(K\) 步契约空间 rollout，预测未来执行。
- 选择目标：  
  \(u^\star=\arg\min_{u\in U(c^\star)}[\sum_{i=t}^{t+K}V(\hat e_i^u)+\lambda_1L_{task}(u)+\lambda_2\kappa(u)]\)，  
  即最小化残余违规、任务模板未满足比例和干预成本。
- 默认 \(K=1\)；只有被选中的修复会触发 LLM 重新生成，诊断和排序阶段不调用 LLM。

### 2.6 整体流程

解析执行日志构建事件图 → 逐事件计算违规分数并告警 → 在违规事件及其祖先中做反事实恢复和源归因 → 在责任源上枚举修复算子并 rollout 排序 → 提交最小修复并只重执行受影响分支。

## 3. 实验设计

- **数据集/场景**：五个公开 MAS 基准：
  - GSM8K：多智能体数学推理（Solver/Critic/Verifier）；
  - CSQA：常识问答多智能体辩论；
  - HotPotQA：检索—推理—验证多跳问答；
  - PoisonRAG：检索文档投毒场景；
  - InjecAgent：工具使用型 Planner–Executor–Monitor MAS。
- **攻击设置**：受控 L1–L3 注入：
  - L1 修改智能体状态；
  - L2 修改消息或工具载荷，保持拓扑不变；
  - L3 修改协调结构，如重连依赖、跳过角色、下线智能体。
  每条测试轨迹含一个真实发起事件 \(c_{gt}\)，仅用于评估。
- **评价指标**：
  - 检测：轨迹级 F1、AUROC；
  - 定位：Hit@1、到真实源的平均跳距；
  - 恢复：ASR、任务 ACC、TCR、平均后告警算子成本。
- **对比方法**：BlindGuard、G-Safeguard、AcMAS(-R)、A-Trust、AgentSafe、Oracle Anomaly Ranking；另有 GT-source repair 作为诊断参考。所有方法共享同一骨干 LLM、MAS 模板、攻击注入、数据划分和良性校准预算。
- **实现**：骨干 LLM 为 Qwen2.5-7B-Instruct，GGUF 推理；主实验使用 3 个随机种子，报告均值±标准差；良性训练/验证/攻击测试任务 ID 不相交。
