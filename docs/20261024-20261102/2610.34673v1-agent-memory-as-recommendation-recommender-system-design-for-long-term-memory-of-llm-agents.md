## 摘要
在多次会话中为用户服务的大语言模型（LLM）智能体，必须为每个请求从存储记忆中选出少量记忆送入有限的上下文窗口。这一选择在很大程度上决定智能体能否正确作答，而且要在Web规模下对每个请求执行。该选择面临三个挑战：记忆库庞大且持续增长、单请求成本预算受限，以及需要汇集全部证据的多会话问题。许多记忆系统会为每段历史构建笔记或图，需数百至数千次LLM调用，且各组件独立设计，因此难以明确哪一组件带来准确率。这些挑战与推荐系统的特性相似，因此我们将智能体记忆形式化为带预算的列表推荐（budgeted slate recommendation），其中请求为用户，存储记忆为物品，上下文窗口为列表。该形式化将记忆系统置于推荐级联的统一设计空间中，并将准确率分解为各阶段所控制的完备性。受此启发，我们提出AgentMemRec，它借鉴推荐系统中的候选生成、学习排序和列表构建，在无需任何LLM调用的情况下选择记忆。在LongMemEval的多会话问题上，AgentMemRec相比包括A-Mem、HippoRAG 2、DynamicRAG和T-Mem在内的记忆与上下文选择方法，准确率高出10至31个百分点。它以低3.2倍的服务成本达到与每次查询进行64次调用的LLM重排序器相当的性能；在LoCoMo上，无需在写入时进行任何LLM调用，就优于Mem0和Zep。该分解将增益归因于列表更常包含全部证据，因此推荐系统设计为LLM智能体的长期记忆提供了有效且高效的基础。

## Abstract
Large language model (LLM) agents that serve users across many sessions must choose, for every request, the few stored memories that enter a limited context window. This choice largely decides whether the agent answers correctly, and it runs on every request at Web scale. This selection faces three challenges: a large and growing store, a per-request cost budget, and multi-session questions that need all of their evidence. Many memory systems build notes or graphs with hundreds to thousands of LLM calls per history, and each is designed on its own, so it is unclear which component yields the accuracy. These challenges mirror the properties of recommendation, so we formalize agent memory as budgeted slate recommendation, with the request as the user, stored memories as items and the context window as a slate. The formalization places memory systems in one design space of recommender cascades and factorizes accuracy into the completeness that each stage controls. Guided by it, we propose AgentMemRec, which adapts candidate generation, learning to rank and slate construction from recommender systems and selects memories without any LLM call. On multi-session questions of LongMemEval, AgentMemRec outperforms memory and context-selection methods, including A-Mem, HippoRAG 2, DynamicRAG and T-Mem, by 10 to 31 points of accuracy. It matches an LLM reranker that makes 64 calls per query at 3.2 times lower serving cost, and on LoCoMo it outperforms Mem0 and Zep without any LLM call at write time. The factorization attributes the gains to slates that more often hold all of the evidence, so recommender-system design offers an effective and efficient foundation for the long-term memory of LLM agents.

- **三重困难**：
  - **库规模大且持续增长**：LongMemEval-M 单个问题的历史约 500 个会话、150 万 token，而回答模型最多只读 2,700 token。
  - **单请求预算约束**：选择器在每个请求上运行，若用 LLM 打分，调用成本会随库规模与流量线性增长。
  - **价值在“集合”层面判定**：证据跨多个会话的问题需要全部证据；反馈只针对整个上下文，而非单条记忆。
- **现有方法的混乱**：HippoRAG 2、A-Mem、T-Mem 等系统用每段历史约 440–2,270 次 LLM 调用构建笔记、图、时序层级等结构，但各组件独立设计，无法判断准确率究竟来自哪一环节；且四个基于轮次的对比方法，其上下文仅在 0.50–0.68 的多会话问题上包含全部证据。
- **核心洞察**：上述三点正是推荐系统的典型属性（大目录、每请求延迟预算、以展示集合为单位评估），因此将智能体记忆选择形式化为**带预算的列表推荐（budgeted slate recommendation）**：请求=用户，存储轮次=物品，上下文窗口=列表（slate）。

## 2. 方法论

### 2.1 形式化框架

- **定义 3.1（带预算列表推荐）**：给定请求分布 x、目录 I(x)、单调集合代价 c_x、预算 B、仅对展示列表可观测的奖励 R(S,x)∈[0,1]；策略 π 在代价约束下输出列表，价值为 V(π)=E_x[R(π(x),x)]。
- **记忆选择实例**：请求 x=(q,t_q)，目录为历史 H(q) 中的轮次；代价为渲染列表的 token 数；奖励为评判器接受答案的概率。目标为：
  - max_π E_q[u(π(q),q)]，s.t. tok(render(π(q))) ≤ B。

### 2.2 设计空间

- **定义 3.2**：一个记忆设计是四元组 d=(φ, g, f, h)：
  - **φ 写入时映射**：把历史转成单元目录（可带边信息）；
  - **g 候选生成**：返回候选池 P(q)；
  - **f 排序器**：对池排序；
  - **h 列表构建**：在预算内选出 S_B(q)。
  - LLM 成本 = φ 的每历史调用 + g/f/h 的每请求调用。所有对比系统都是该空间中的一个点，差异主要在“在哪里花 LLM 调用”。

### 2.3 三条理论结果（设计空间的核心结论）

- **命题 3.3（阶段分解）**：Acc(π) = a_i + (a_c − a_i)·r_pool·r_rank。
  - r_pool = Pr[G ⊆ P]（池完备性），r_rank = Pr[G ⊆ S_B | G ⊆ P]（排序完备性），a_c / a_i 为列表完整/不完整时的平均奖励。
  - 含义：候选生成设定上界（r_slate ≤ r_pool），排序决定池内保留率，集合层面的效应通过 a_c、a_i 体现。
- **命题 3.4（归约为逐项排序）**：在奖励不依赖列表组成、单元代价可加、各单元独立以概率 p_v 属于金标集的假设下，预算内最大化期望奖励等价于 0-1 背包，物品价值为 −log(1−p_v)；等代价时最优列表即 p_v 最大的单元。
  - 这是“学习物品相关性 + 填充”适用于集合级目标的依据，也界定了失效条件：奖励依赖列表组成、证据单元相关性相关。
- **命题 3.5（填充优于截断）**：贪心填充包含所有代价不超过 B 的排序前缀；若奖励在“前缀→填充列表”之间不下降，则填充不劣于任何逐问题截断。
  - 这是 AgentMemRec 坚持填满固定预算、不做 per-question cutoff 的理由。

### 2.4 设计问题

- 将三条件合并为：max_{φ,g,f} r_pool(φ,g)·r_rank(f | φ,g)，s.t. LLMcost(d) ≤ L。
- 该式把各阶段耦合成单一优化问题：更宽的池提升 r_pool 但引入更多干扰项；LLM 调用只有在提升乘积时才值得。

### 2.5 AgentMemRec 的具体实现（L=0，全流程无 LLM 调用）

- **候选生成（提升 r_pool）**：
  - 词法通道：BM25（小写词元）；稠密通道：bge-m3 余弦相似度；
  - 用 RRF（k=60）融合两路排序，取前 N=128 轮构成候选池；
  - 池大小由“排序后的列表完备性”乘积在开发集上选定（128 轮 0.912 vs 64 轮 0.879）。
- **学习排序（提升 r_rank）**：
  - LightGBM + LambdaRank 目标，31 叶、学习率 0.05、300 棵树、每叶至少 20 样本、固定随机种子；
  - 每个（问题，池内轮次）对使用 **10 个廉价特征**：
    - 5 个相关性信号：bge-m3 余弦、全局稠密排名与 BM25 排名的对数、融合池中位置、bge-reranker-v2-m3 交叉编码器分数；
    - 5 个轮次上下文特征：是否为用户角色、在会话中的相对位置、天龄对数、长度对数、与问题共享的 spaCy 关键词；
  - 训练标签来自 152 个开发问题的金标，合并 S/M 两种历史，共 19,456 个样本对。
- **列表构建（填充）**：
  - 按排序遍历候选池，若加入某轮后渲染代价（含首次出现的会话头）仍不超过 B=2,700 token 则加入，否则跳过并继续；
  - 渲染时按会话分组、按日期排序，采用 LongMemEval 官方历史格式；不做逐问题截断。
- **可选写入时记录**：
  - 用 Qwen3-32B 每会话读一次，写出带日期、实体、引用轮次的类型化记录；记录通道向 128 轮池中追加最多 32 个被引用轮次，再由冻结排序器统一排序；
  - 相对时间标签把引用记录的日期附着到含相对时间表达的轮次上（只保留不晚于问题参考日期的日期）。该扩展在选择阶段仍无 LLM 调用。

## 3. 实验设计

### 3.1 数据集与 Benchmark

- **LongMemEval-S**（清洗版）：500 个问题，每段历史约 50 个会话、10 万 token、约 490 轮。
- **LongMemEval-M**：同一批问题，历史约 500 个会话、150 万 token、约 4,894 轮，作为更难的第三设置。
- **LoCoMo**：10 段对话（369–689 轮），1,540 个计分问题。
- **划分**：预先固定 152 个开发问题 / 348 个测试问题（其中 328 个可回答）；主分析层为测试集上证据跨 ≥2 会话的 κ≥2（n=209），另报 κ≥3（n=49）。排除 30 个不可回答问题。
- **回答与评判**：LongMemEval 用 Qwen3-32B（FP8/vLLM）与 DeepSeek V4.1 Flash 两个回答模型，温度 0、关闭推理；官方 GPT-4o 评判器 + 按题型 prompt。LoCoMo 沿用 T-Mem 的 GPT-4o-mini 回答与三次评判。
- **稳定性控制**：每个问题/系统构建 K=4 个列表（预算 2,400–2,700），报告平均评判标签；配对百分位 bootstrap（10,000 次抽样，5% 水平）；“持平”定义为不显著且单侧检验下不低于 −3 点（非劣性边界 3 点，约等于同一后端四个近似预算间的波动 2.6/3.3 点）。

### 3.2 对比方法

- **上下文选择器**：Adaptive-k（官方最大间隔规则，作用于全历史的 bge-m3 相似度）、DynamicRAG-8B（在融合前 40 轮上用 8B 选择器）。
- **LLM 构建的记忆系统**：LongMemEval 原生记忆设计、HippoRAG 2、A-Mem、T-Mem（均以 Qwen3-32B 作为构建器，保证构建器一致）。
- **LLM 重排器（Ref）**：Qwen3-8B 对 64 轮融合池逐轮 0–10 打分，每查询 64 次调用。
- **共享协议下的生产系统**：Mem0、Zep、MemOS、TiMem、RecMem、HyperMem（官方代码复现）、T-Mem 复现。
- **其他对照**：蒸馏排序器（无金标）、LoCoMo 域内训练的排序器、128 次调用的 LLM 排序器（8B/32B）、随机填充与“近邻干扰”填充的标签控制实验。
