Abstract 

Dataset search remains a bottleneck in data analysis workflows, as existing systems largely rely on keyword matching or shallow retrieval that fail to capture user intent. To facilitate intent-driven search, we present two retrieval components to equip multi-faceted dataset search interfaces through natural language. First, we propose Hypothetical Schema Em-beddings (HySE) that uses a language model to generate task-aligned hypothetical table schemas which are used for embedding-based retrieval, bridging the gap between intent and table content. We introduce K AGGLE DS, a corpus comprising 6,503 tables and diverse task-queries derived from Kaggle, and show that HySE consistently improves recall over strong keyword and embedding-based base-lines, as well as over a dense table retriever fine-tuned on K AGGLE DS. We also show that HySE generalizes to end-to-end question answer-ing on, for example, the NQ-Tables dataset, a corpus of 169,898 Wikipedia tables with human-written queries, where HySE improves Recall@10 by +6.0 pp over dense retrieval baselines. Second, we introduce FlexPrune, which translates dataset constraints expressed in natural-language into SQL predicates over a customizable metadata index, enabling filtering across arbitrary metadata attributes. Combined with HySE, FlexPrune increases Recall@10 by +6.0 pp over dense retrieval followed by tag-based filtering. Our results show that natural-language-based retrieval supporting task and metadata queries offers a viable alternative to schema-level keyword search in dataset search. 

1 Introduction 

Dataset search is a recurring bottleneck in data analysis (Hulsebos et al., 2024). As data lakes and public repositories grow, analysts spend consider-able effort locating relevant datasets before analysis can begin. Industry surveys report that data scien-tists spend roughly 25% of their time searching for datasets or preparing data for analysis (Grover, 2019), and data preparation remains the most time-consuming stage of the workflow according to a survey of more than 2,000 practitioners (Anaconda, Inc., 2023). These observations highlight the need for more effective dataset search systems. 

In Practice, Dataset Search is Still Primar-ily Keyword-based. In enterprise environments, data catalogs such as Amundsen and DataHub store metadata describing datasets and provide search in-terfaces over these metadata repositories (Grover, 2019; DataHub, 2025). At web scale, systems such as Google Dataset Search index datasets us-ing supplied metadata to support keyword lookup (Brickley et al., 2019; Sostek et al., 2024). In both settings, retrieval is driven primarily by matching query keywords to metadata fields such as dataset ti-tles, descriptions, or column names. This approach is effective when users already know the relevant dataset names or metadata attributes. However, users may have a clear analytical objective but are unfamiliar with the dataset search space, let alone the exact keywords matching the indexed metadata. 

Dataset Search Beyond Data Augmentation. 

Prior research on dataset search has largely focused on identifying structural relationships between ta-bles, such as join discovery, schema matching, and table union search (Nargesian et al., 2018; Zhu et al., 2019, 2016; Castro Fernandez et al., 2018; Srinivas et al., 2023). These approaches retrieve tables that can be combined with a known refer-ence table or schema. However, dataset search in practice typically starts from an analytical objective rather than a known table or schema. User studies suggest that analysts reason in terms of analysis goals during early exploration, rather than in terms of specific table schemas (Paton et al., 2023). And an analyst who wants to “analyze trends in Cali-fornia real estate over the past decade” may not know upfront which data attributes are needed and how relevant datasets are structured. 1arXiv:2610.33936v2 [cs.IR] 28 Oct 2026 Design Requirements from User Research. In this work, we build on a survey of 89 data profes-sionals about their dataset search challenges and requirements (Hulsebos et al., 2024). The survey identified four design desiderata for dataset search systems: (1) task-driven search that starts from ana-lytical objectives rather than dataset specifications, (2) hybrid querying that combines semantic table embeddings with rich metadata filtering, (3) result comprehensibility and diversity to reduce cogni-tive overload in large catalogs, and (4) iterative interfaces that support multi-step refinement. 

Task-Driven Table Retrieval and Flexible Metadata Pruning via Natural Language. We explore how dataset search systems can move be-yond keyword- and schema-bound interfaces to-ward task-driven, open-ended natural-language interaction . Effective retrieval in dataset search builds on dataset semantics as well as metadata (Hearst, 2006; Hulsebos et al., 2024), which we address through two distinct components. First, we introduce Hypothetical Schema Embeddings (HySE) , a semantic retrieval mechanism that uses a language model to translate a user’s analytical task description into one or more task-aligned hypothet-ical table schemas, which are then used as inputs for dense retrieval. Second, we introduce Flex-Prune, an attribute-agnostic metadata filter stage that parses natural-language constraints into struc-tured SQL predicates over a customizable metadata index. Together, these components enable task-driven dataset search in which users can refine their search using natural language. 

Contributions. In this work we make the follow-ing contributions: (1) We propose Hypothetical Schema Embeddings (HySE) , an algorithm that turns a natural-language task into one or more hy-pothetical schemas for dense retrieval, to bridge the intent-dataset gap. (2) We propose FlexPrune ,an attribute-agnostic natural-language mechanism for search over metadata. FlexPrune translates NL constraints into SQL over a hybrid metadata in-dex. (3) We present KAGGLE DS , a new task-based dataset search corpus comprising 6,503 ta-bles from 3,141 real-world Kaggle datasets, with task-oriented queries in natural language for train-ing and evaluation. (4) We present an evaluation 

across key table retrieval paradigms which shows how HySE improves top-k recall—over keyword and dense retrieval baselines as well as a dense ta-ble retriever trained on our corpus—while in combi-nation with FlexPrune yields a significant reduction in result set size. 

2 Related Work 

Keyword-Based Search. Early approaches to dataset discovery relied on keyword search over metadata and content. Early work by Cafarella et al. (2008) introduced WebTables, which extracted 14.1 billion HTML tables from Google’s web crawl and developed schema-aware ranking algorithms that consider table structure and attribute relation-ships. Google Dataset Search (Brickley et al., 2019) later provided the first large-scale commercial im-plementation using schema.org markup for web-scale dataset discovery. Within enterprise envi-ronments, systems like Amundsen (Grover, 2019) and DataHub (DataHub, 2025) focus on metadata search with usage-based ranking and lineage track-ing. Auctus (Castelo et al., 2021) extends tradi-tional keyword search by supporting spatial, tem-poral, and data integration queries that enable users to find join-compatible datasets. 

Semantic and Embedding-Based Search. Sub-sequent work applies pre-trained language models to move beyond lexical matching toward semantic similarity. Recent approaches include CHORUS (Kayali et al., 2024), which unifies multiple data discovery tasks using large language models, and Starmie (Fan et al., 2023), which employs con-trastive learning with pre-trained language mod-els to achieve contextualized column embeddings. TableQA systems like TAPAS (Herzig et al., 2020) extend BERT (Devlin et al., 2019) to encode tabu-lar input, demonstrating that language models can represent table structure. Building on TAPAS, the Dense Table Retriever (DTR) (Herzig et al., 2021) trains a specialized encoder to score a natural-language question against a flattened table. DTR is the closest learned counterpart to our setting, and we therefore adopt it as a trained retrieval base-line. SOLO (Wang and Fernandez, 2023) addresses natural-language table retrieval via self-supervised learning without requiring manual training data. 

Benchmarks for Dataset Search and Retrieval. 

Several datasets have been used to evaluate dataset discovery systems. Early studies relied on large web table collections such as WebTables (Cafarella et al., 2008). Subsequent work constructed data lake benchmarks from open data portals and en-terprise repositories (Khatiwada et al., 2022; Fan et al., 2023; Castro Fernandez et al., 2018), as well as union-search benchmarks over open data and 2data lakes (Nargesian et al., 2018; Srinivas et al., 2023). System-oriented work such as Voyager (Bo-gatu et al., 2022) evaluates discovery over small, domain-specific collections. However, no dataset exists that enables training and evaluating task-based dataset search. To this end, we contribute KAGGLE DS, a new dataset derived from thousands of real-world Kaggle datasets with task-oriented queries. 

3 Components for Bridging Search Intent and Tabular Datasets 

Here, we introduce two core components for task-driven multi-faceted dataset search based on natural language interfaces, covering both over dataset con-tent and metadata. First, HySE (§ 3.1) performs task-based retrieval: given a natural-language task description, it generates hypothetical table schemas and uses their embeddings to retrieve a broad can-didate set via ANN search. Second, FlexPrune 

(§ 3.2) can narrow retrieved results down through NL-based metadata filtering, translating user con-straints into SQL predicates over an extensible metadata index. 

3.1 HySE: Task-based Semantic Search 

To address the task-driven desideratum, we intro-duce Hypothetical Schema Embeddings (HySE) ,a retrieval mechanism that enables dataset search using task-queries which have less semantic resem-blance with the target schemas than user-informed keywords. HySE builds on the classical idea of query expansion (Salton, 1971) and draws direct in-spiration from hypothetical document embeddings (Gao et al., 2022), a framework that embeds LLM-generated hypothetical documents to bridge the semantic gap between input query and documents. In the tabular setting, rather than expanding into free-form text, we prompt an LLM to gen-erate hypothetical table schemas–a table name, col-umn names, and two example rows–aligned with the specified task, as illustrated in Figure 1. We then embed both the task query and the generated schema(s), fuse the embeddings, and perform ap-proximate nearest neighbor (ANN) search over the table representations. This ensures alignment be-tween the input embedding and target representa-tions in the retrieval corpus, while preserving the user’s task specification.

4.1 Dataset Construction Pipeline 

Using the Kaggle CLI 3 in May 2024, we extracted 

5,221 dataset “folders” (hereafter datasets ). Since our goal is to construct a public benchmark for tab-ular dataset retrieval, we filter datasets to comprise only CSV files, have a permissive license, and have a non-empty description to ensure input for query inference and column-level metadata enrichment. 

Dataset Cardinality A single Kaggle “dataset” often contains several CSV files with related ta-bles instead of just a single CSV file, resulting in the following partitions: 1) single-table: 2,349 datasets contain exactly one table, 2) multi-table: 4,154 datasets hold multiple tables, of which 1,459 datasets share an identical schema (e.g., yearly par-titions), while 2,695 exhibit diverse schemas. 

Dataset Splits To support isolated model train-ing and evaluation, we partition the corpus at the 

dataset level to ensure that no test-set schema oc-curs in the training data. Of the 3,141 datasets (6,503 tables) in total, 60% (1,884 datasets; 4,166 tables) are allocated to a training+validation set, with a 2:1 split between training (1,256 datasets; 2,715 tables) and validation (628 datasets; 1,451 tables). The remaining 40% (1,257 datasets; 2,337 tables) are held out as a test set.

The user survey that informs our design cri-teria (Hulsebos et al., 2024) also revealed that analysts value a table’s content granularity —particularly temporal and geographic coverage, which existing dataset search systems seldom ex-pose. 5 Experimental Setup 

Our evaluation is organized by first evaluating the first retrieval step through HySE , followed by a generalization study for open-domain tabular QA. Finally, we assess the end-to-end multi-faceted 

pipeline that chains HySE with FlexPrune for meta-data filtering. Here, we elaborate on the full experi-mental setup.

5.2 Datasets 

We use the validation split (4,353 task queries and 1,451 tables, §4) of the KaggleDS corpus only for model selection, i.e., to select the HySE configuration (Appendix C). After identifying the best-performing configuration, all reported results are computed on the held-out test set (7,011 task queries and 2,337 tables, §4), ensuring an unbiased assessment of end-to-end performance. Moreover, we evaluate the HySE retrieval method also on the NQ-Tables dataset (Herzig et al., 2021), to understand its generalizability (§6.2). NQ-Tables is the table-retrieval benchmark released with DTR: 169,898 Wikipedia tables and 11,628 human-written questions drawn from Nat-ural Questions (Kwiatkowski et al., 2019), split 9,594 / 1,068 / 966 into train, dev, and test. Its queries are factual (e.g., “when was the last time easter was in the month of march” ) rather than analytical task descriptions.

To evaluate the retrieval performance, we adopt the standard metric of recall@ k, i.e. fraction of queries for which the ground-truth table appears in the top-k.

5.5 Baselines 

We compare HySE retrieval against four retrieval baselines spanning syntactic keyword matching, semantic keyword- and task-embedding retriever, and a learned approach, representative of both in-dustry systems and common research abstractions for table retrieval (§ 2). 

Syntactic–Keyword Search (BM25). A classical search method uses fuzzy BM25 match over 

table_name and example_rows_md . This reflects common keyword-based search in data lakes or metadata catalogs, and serves as a lower-bound baseline. Queries are matched against pre-tokenized fields while tolerating minor variations. 

Semantic–Keyword Search. We embed key-words using text-embedding-3-small , and retrieve tables by cosine similarity against their pre-computed table embeddings. This approach extends keyword search to dense retrieval, enabling semantic matching even when syntactic forms differ (e.g., “home price” vs. “housing cost” ). 

Semantic–Task Search. The natural-language task query is embedded using 

text-embedding-3-small . Cosine similar-ity is computed against pre-computed table embeddings. This baseline represents standard dense retrieval without schema augmentation. 

TAPAS Dense Table Retriever (DTR). A learned 

baseline: the TAPAS retriever of Herzig et al. (2021) is fine-tuned on the K AGGLE DS training split (1,256 datasets; 2,715 tables; 8,142 task queries, §4). We initialize from the released ICT-pre-trained dual encoder, encode each table as its title, header, and two example rows to match the corpus representation used by HySE, and train with in-batch negatives following the original recipe. We additionally report DTR +hn , the paper’s best configuration, which adds one mined hard negative per query. 

5.6 Evaluation Procedure 

All results are reported on the hold-out test split (7,011 task queries over 2,337 tables). For each task query, HySE retrieves from a single corpus-wide embedding index. Recall@ k is computed with respect to the ground-truth table. To analyze structural differences, we partition the evaluation results by properties of the ground-truth table. Results are separately reported for: (i) 

normalized tables (tables with explicit relational identifiers and separate entities, n=1 ,041 queries) vs. (ii) denormalized tables (wide tables that col-lapse multiple entities or attributes into a single schema, n=5 ,970 queries), and (iii) single-table datasets (n=2 ,826 queries) vs. (iv) multi-table datasets (n=4 ,185 queries) (§ 4.1). These seg-6ments allow us to assess how schema formulation and dataset cardinality affect retrieval behavior.

6.2 Generalization to Retrieval in Tabular QA 

Evaluating on K AGGLE DS alone leaves three ques-tions open: whether the results generalize beyond a Kaggle-derived corpus where analytical and pre-dictive tasks are dominant, whether the results hold at a larger corpus scale, and whether HySE’s gains are consistent for queries that were not generated. To this end, we evaluate HySE also on NQ-Tables which was introduced for evaluating the TAPAS-based DTR baseline (Herzig et al., 2021). NQ-Tables is a corpus for Open-Domain Tabular Ques-tion Answering comprising 169,898 tables, with real human queries and reference labels. We report its hold-out test split (959 questions over the full corpus). To demonstrate the robust-ness of HySE, it is configured exactly the same 

as on K AGGLE DS (same prompt, schemas N =2 ,

7 Conclusion 

Dataset search systems are expected to enable search by task and required metadata. This is typi-cally approached by embedding the input query and performing dense retrieval directly, or training a specialized model to map queries to table schemas followed by metadata search. Dataset search sys-tems should, however, not simply ignore the se-mantic gap between the user’s intent expressed in queries and the targeted schemas, but learned ap-proaches require retraining to the data at hand. We propose a lightweight generalizable mechanism to bridge user-intent through hypothesizing relevant schemas for a given task (HySE), inspired by hy-pothetical document embeddings. We also intro-duce an attribute-agnostic mechanism (FlexPrune) for metadata-based filtering that parses metadata queries to SQL, executed on the metadata index at hand. We show on a new large task-based dataset search corpus, K AGGLE DS, that HySE substan-tially improves recall over syntactic and seman-tic baselines, as well as over a trained dense ta-ble retriever while HySE does not require train-ing. We also show that HySE generalizes well to tabular question answering datasets, where it main-tains significant performance improvements. When HySE is combined with FlexPrune it increases Re-call@10 by +6.0 pp on a held-out test set com-pared to the traditional approach using direct query embedding and fixed metadata tag search. Alto-gether, this work shows the potential of lightweight natural-language based mechanisms to enable task-informed tabular dataset search, and provides a stepping stone for future research. 8Acknowledgements

Limitations 

Single ground-truth table. Each query in K AG -

> GLE

DS is associated with exactly one gold table, so Recall@ k measures whether that specific table is retrieved. Real analytical tasks are frequently sat-isfiable by several datasets, which means our metric understates the utility of all methods evaluated here, and possibly unevenly across them. Graded rele-vance judgments over a pooled candidate set would give a more faithful picture of ranking quality, par-ticularly at small k; which we consider future work. 

Scale and corpus diversity. Our primary corpus contains 6,503 tables drawn from a single source, Kaggle, whose datasets carry relatively rich author-provided metadata. The NQ-Tables experiment demonstrates that HySE retrieval holds on a corpus of 169,898 tables, but we do not report a scaling curve, nor do we evaluate on noisy, sparsely docu-mented tables typical of enterprise data lakes and web-table collections, where metadata-dependent components such as FlexPrune would face materi-ally harder conditions.
