## 摘要
现有的近似最近邻搜索（ANNS）方法通常假设每个实体只有一个向量。然而，在许多实际应用中，一个实体会关联多个向量，并且查询可能联合考虑两个属性。由于不同查询会为各属性赋予不同权重，基于帕累托前沿的索引通过连接所有可能查询偏好下的近似最近邻，为双向量检索提供了一种有效解决方案。然而，现有的基于帕累托前沿的方法在索引构建和动态更新两方面都存在显著的低效问题，限制了其实际适用性。为解决这些问题，我们提出 ACTIVE，一种基于动态帕累托前沿的 DVQ 索引，它支持高效构建和更新，同时在变化的查询偏好下保持高检索性能。它分别采用角度约束的活动范围计算和连通性损失驱动的自适应修复策略来加速节点插入和删除。大量实验表明，在搜索精度相当（或略低）的情况下，ACTIVE 的插入吞吐量为 DEG 的 1.20–1.43 倍，删除吞吐量为基于邻居重连的修复的 1.64–2.06 倍，为基于重新插入的修复的 22.64–39.51 倍。

## Abstract
Existing approximate nearest neighbor search (ANNS) methods generally assume that each entity has a single vector. In many real-world applications, however, an entity is associated with more than one vector, and queries may jointly consider two attributes. With different queries assigning different weights to each attribute, Pareto-frontier-based indices provide an effective solution for dual-vector retrieval by connecting to approximate nearest neighbors under all possible query preferences. However, existing Pareto-frontier-based approaches suffer from substantial inefficiencies in both index construction and dynamic updates, limiting their practical applicability.   To address these issues, we propose ACTIVE, a dynamic Pareto-frontier-based DVQ index that supports efficient construction and updates while maintaining high retrieval performance under varying query preferences. It employs angle-constrained active-range computation and connectivity-loss-driven adaptive repair strategies to accelerate node insertion and deletion, respectively. Extensive experiments show that, at comparable (or slightly below) search accuracy, ACTIVE improves insertion throughput by $1.20$--$1.43\times$ over DEG, and deletion throughput by $1.64$--$2.06\times$ over neighbor-reconnection-based repair and by $22.64$--$39.51\times$ over reinsertion-based repair.

## 1. 核心问题与整体含义

- **研究背景**：传统 ANNS 通常假设每个实体只有一个向量；但电商图文商品、社交平台空间-文本帖子、短视频视频-文本等场景中，实体常有两个向量属性，查询需联合考虑两个属性。
- **DVQ 问题**：查询 \(q=\langle x,y,\alpha,k\rangle\)，距离定义为  
  \[
  \mathrm{Dist}(q,o)=\alpha\cdot\delta_x(q,o)+(1-\alpha)\cdot\delta_y(q,o)
  \]
  其中 \(\alpha\in[0,1]\) 表示用户对两个属性的偏好权重。目标是支持任意 \(\alpha\) 下高效、准确的 top-\(k\) 近似检索，并支持动态插入/删除。
- **现有方法局限**：
  - **偏好特定多索引（如 MR）**：为每个属性单独建索引，候选生成时难以覆盖任意加权距离下的近邻，任意偏好下召回受限。
  - **偏好无关统一索引（如 DEG）**：用近似 Pareto 前沿连接所有可能偏好下的近邻，检索质量较好，但构建时主动范围（active range）计算开销大，删除修复复杂，动态更新效率低。
- **论文整体含义**：提出 ACTIVE，一个面向 DVQ 的动态 Pareto 前沿统一索引，在保持多偏好检索性能的同时显著提升构建、插入和删除效率，增强 Pareto 前沿索引的实际可用性。

## 2. 方法论：核心思想与关键技术

### 2.1 总体思路

- ACTIVE 仍以**多层近似 Pareto 前沿**作为节点出邻居，使不同 \(\alpha\) 下均能覆盖近似近邻。
- 针对构建/插入瓶颈，提出**角度约束的主动范围计算 ACAR**。
- 针对删除瓶颈，提出**连通性损失驱动的自适应修复 CA-PFR**。
- 辅以**异步反向图维护**定位受影响节点，并存储边上的双向量距离以减少重复计算。

### 2.2 ACAR：角度约束的主动范围计算

- **Pareto 角定义**：对节点 \(v\) 及其邻居 \(c\)，在二维距离空间 \((\delta_x(v,c),\delta_y(v,c))\) 中定义 Pareto 角 \(\phi(v,c)\)，即距离向量与正 \(y\) 轴方向的夹角，范围为 \([0,\pi/2]\)。
- **观察**：真实数据中，检索到的节点在 Pareto 角空间呈局部集中分布，即高频检索节点对应连续角度区间。
- **核心约束**：若两个候选邻居在检索中可能被同时访问，其 Pareto 角差异应较小。因此计算候选 \(p\) 的主动范围时，只与满足  
  \[
  |\phi(v,p)-\phi(v,w)|\le \theta_{th}
  \]
  的已保留邻居 \(w\) 计算剪枝区间，跳过角度差异大的比较。
- **第一层特殊处理**：第一层候选更可能位于精确 Pareto 前沿，且其主动范围会影响后续层。ACAR 对第一层采用**正向 + 反向两阶段扫描**，提高主动范围准确性。
- **剩余层处理**：按两层排序遍历候选；仅对满足角度约束的保留节点计算剪枝区间，得到  
  \[
  ar_p=[0,1]\setminus ar_p^-
  \]
  若 \(|ar_p|\ge\tau\) 则保留，直至达到最大出度 \(R\)。
- **收益**：角度计算所需的 \(\delta_x,\delta_y\) 已在候选构造中保存，角度约束本身成本低；相比 DEG 的 \(O(R\cdot|C|)\) 式全量比较，显著减少距离计算。但若 Pareto 角高度集中，加速可能退化。

### 2.3 CA-PFR：连通性损失驱动的自适应修复

- **观察**：删除后受影响节点的原邻居与重插入修复后的邻居重叠率较高，总体至少 72%；低层邻居约 87% 保留，高层仅约 52% 保留。因此可做局部增量修复，而非全局重插入。
- **连通性损失定义**：
  \[
  CL(v)=\frac{R-|N_{out}(v)|}{R}
  \]
  其中 \(R\) 为最大出度。
- **三级自适应修复**：
  - **轻度损失**：\(0<CL(v)\le CL_1\)，采用**历史 Pareto 前沿修复**，候选集为活跃出邻居与活跃入邻居。入邻居曾作为候选出邻居，且距离已存储，基本无额外距离计算。
  - **中度损失**：\(CL_1<CL(v)\le CL_2\)，采用**受影响层修复**，在轻度候选基础上，扩展包含被删除节点的受影响 Pareto 层中节点的活跃出邻居。
  - **重度损失**：\(CL(v)>CL_2\)，采用**多层修复**，扩展最低受影响层及其以上所有高层的活跃出邻居，以恢复严重连通性损失并弥补构建阶段遗留的连通性不足。
- 修复后的候选集最终再由 ACAR 计算主动范围并选出出邻居。
- **异步反向图维护**：维护轻量反向图 \(G_{in}\) 以快速定位入邻居；反向图只存 ID，在 HM 上约占正向图与双向量数据合计大小的 2.34%，并在后台异步维护以降低同步开销。
- **查询流程**：贪心搜索，候选队列和结果队列按距离排序；仅扩展主动范围包含查询 \(\alpha\) 的边；当候选队首距离大于结果队列尾部距离时终止。

- **指标**：Recall@\(k\)（默认 \(k=10\)）、平均查询延迟、更新吞吐（ops/s）、距离计算次数、更新后召回稳定性、混合读写负载下的 p50/p95/p99 延迟。
