## 摘要
主动式LLM智能体从持续观测和累积历史中预判服务机会。现有方法强调近期上下文或相关记忆检索，难以为验证反复出现的行为规律并评估其当前事件适用性提供充分支持。我们提出主动记忆（Proactive Memory，ProactMem），将历史组织为近期事件、时间轨迹和行为规律。轨迹事实与源事件进行核验，行为规律通过历史回放进行评估，然后再与当前条件匹配。我们还构建了ProactiveStream，一个涵盖三个应用范围的纵向基准；在该基准中，智能体在具备回合感知的机会标签下按时间顺序处理孤立事件流。在ProactiveStream上，ProactMem的总体有效性（F1）达到52.6%，相较五个外部基线中最强基线取得21.4%的相对提升。代码见：https://anonymous.4open.science/r/ProactMem-5351/。

## Abstract
Proactive LLM agents anticipate service opportunities from ongoing observations and accumulated history. Existing approaches emphasize recent context or retrieval of related memories, providing limited support for validating recurring behavioral regularities and assessing their applicability to the current event. We propose Proactive Memory (ProactMem), which organizes history into recent events, temporal trajectories, and behavioral regularities. Trajectory facts are checked against source events, and regularities are assessed through historical replay before being matched to current conditions. We also construct ProactiveStream, a longitudinal benchmark covering three application scopes, where agents process isolated event streams chronologically under episode-aware opportunity labels. On ProactiveStream, ProactMem achieves an overall effectiveness (F1) of 52.6%, a 21.4% relative improvement over the strongest of five external baselines. Code is available at: https://anonymous.4open.science/r/ProactMem-5351/.

## 1. 核心问题与研究背景

- **研究动机**：LLM 智能体正从“被动执行任务”走向“主动服务”，即在体育健康、智能家居、软件协作等场景中，从持续的事件流和累积历史中预判用户何时需要帮助。
- **核心问题**：如何把累积的历史转化为**可靠证据**，用于判断“此刻是否应当主动介入”？
- **现有方法的不足**：
  - 一类方法（如 ProactiveAgent、ContextAgent）依赖**近期上下文**做服务决策；
  - 另一类方法（如 Mem0、A-MEM、Graphiti）侧重**相关记忆的抽取与检索**；
  - 二者都缺少两件关键能力：①验证“反复出现的行为规律”是否真实成立；②判断该规律是否适用于**当前事件**。
- **整体含义**：论文主张主动服务需要多时间尺度的、可核验的历史证据，并需要一个能刻画“机会何时首次可行动、如何持续/重开”的纵向评测基准。

## 2. 方法论：ProactMem

### 2.1 问题形式化
- 每个实体 $u$（参与者/家庭/仓库）拥有隔离的事件流 $E_u=(e_1,\dots,e_{T_u})$，$e_t=(\tau_t,x_t)$ 仅含当时可见的公开字段。
- 策略 $\pi$ 输出 $(\hat y_t,\hat m_t)=\pi(e_t,Z_t)$，$\hat y_t\in\{0,1\}$ 表示介入/不介入，$\hat m_t$ 为带证据的服务消息。
- 状态更新 $Z_{t+1}=U(Z_t,e_t,\hat y_t,\hat m_t)$：**先定决策，后提交事件**，保证因果性（当前事件只与到达时已有的记忆比较）。

### 2.2 三层记忆结构
1. **有界事件记忆（近期证据）**
   - 动机：长上下文下证据利用率会下降（Lost in the Middle）。
   - 以原始粒度保留近期事件，同时受时间窗 $\Delta=72$ 小时与容量 $K=100$ 约束（最多 99 条历史 + 当前事件）；另有“开放本地日缓冲区”保存当天全部已提交事件用于轨迹构建。
2. **事实核验的时间轨迹记忆（日级抽象）**
   - 每个本地日结束时，LLM 将当日事件总结为带区间、类型化事实和来源引用的轨迹段。
   - 校验条件：$F(d)\subseteq\bigcup_{e\in E(d)}F(e)$ 且 $E(d)\subseteq E_u^{\text{completed day}}$，并检查实体、区间、引用可解析性、标量值规范化后的字段路径一致性；不通过则拒收。
   - 目的：防止“未支持的细节”在日记录合并时被放大为虚假规律。
3. **回放评估的行为规律记忆（跨周规律）**
   - 每周整合 7 条已完成日记录；LLM 提出候选规律：触发条件 $g$、期望行为 $p$、时间窗、可选星期限制、来源日标识。
   - 历史回放：触发且可观测的“日”若在窗口内触发后发生 $p$ 记为满足（$n_f$），否则记为违反（$n_v$）；缺失观测做删失，不适用日排除，每日最多计一次。
   - 评分：$\text{conf}_{\text{replay}}=n_f/(n_f+n_v)$，$\text{lift}=\text{conf}_{\text{replay}}/\text{base}(p)$，其中 base rate 为同等时间窗与星期限制下 $p$ 在全部可观测日的频率（用 lift 抑制“高频活动导致高置信但无信息量”的假规律）。
   - 激活门槛：$n_f\ge 3$、conf $\ge 0.5$、lift $\ge 1.0$；否则保持候选或被拒。
   - 生命周期：连续 2 次违反 → weakening（降低检索优先级），连续 4 次 → dormant；满足观测可将 weakening 恢复为 active（conf $\ge 0.5$），dormant 可回到 candidate 重新回放。

### 2.3 检索与选择
- 事件记忆给出有界近期序列 $S_t$，轨迹记忆给出当前周期内全部已完成轨迹 $W_t$。
- 规律检索按同实体、星期、时间适用性匹配（含 30 分钟提前量与宽限区间），排除已满足（fulfilled）与删失（censored）的 occurrence。
- 选择：$R_t=\text{Top3}\{\ell:\text{Eligible}\wedge\text{Match}\wedge s_t(\ell)\notin\{\text{fulfilled},\text{censored}\}\}$，排序依据 occurrence 状态、生命周期、置信度、时间距离。

### 2.4 决策与介入控制
- 决策上下文 $C_t=(e_t,S_t,W_t,R_t,Q_t)$，$Q_t$ 为可观测的机会状态；LLM 输出 $(\tilde y_t,\tilde m_t)$。
- **介入控制器**：与“此前已允许的介入”比对，重复提案转为 abstain；机会状态变化、服务身份变化、规律标识变化、本地日切换可生成新 key 从而重开评估。
- 所有基线方法共享同一控制器策略，仅上下文/记忆表示不同（尽量保证比较公平）。
