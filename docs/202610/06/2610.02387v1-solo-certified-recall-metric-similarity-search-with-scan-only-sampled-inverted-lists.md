## 摘要
我们提出 SOLO，一种用于一般度量空间中近似最近邻搜索的索引，其服务路径不包含任何形式的排序启发式：查询被路由到数据库随机样本的 k_s 个最近点，且被触及的倒排列表中的每个对象都用真实距离进行评估。由于无需让任何对象排序高于其他对象，召回率等于可由所存储索引计算出的覆盖概率：对查询样本进行一遍真值遍历即可一次性认证所有工作点，而无需服务其中任何一个——这是一种召回率证书，而对于可导航图，无论代价如何都不存在类似对象。整个索引就是一条递归规则——对集合采样，将每个对象投递到其 b 个最近样本点，拆分任何超出界限的列表，始终扫描叶节点——其运行曲面遵循等功定律，召回率 ≈ f(b·k_s)，其水平是数据集的一个单标量签名。当路由器本身也按同一规则建立索引后，这种仅扫描结构给出了任何图架构都无法达到的服务下限：Deep-100M 在 1 GB 常驻内存（强制上限，每对象 10.7 字节）下以召回率 0.9977 提供服务，在 256 MB 下达到 0.9964；Deep-1B 在 512 MB 下以召回率 0.9925 提供服务（在深度 3 时从 96 MB 达到），插入只需一次搜索，删除是精确的。在硬件允许的情况下，吞吐量具有竞争力——在双路 32 核服务器上，对于 10^8 规模，最高可达调优后 HNSW 的 1.8 倍，且工作点位于该图饱和点的右侧——表格中报告了其与 HNSW、DiskANN、GRAFT、NAPP、misi 以及 SPANN 的分配规则在相同硬件和真值下的对比。

## Abstract
We present SOLO, an index for approximate nearest-neighbor search in general metric spaces whose serving path contains no ranking heuristic of any kind: a query is routed to the $k_s$ nearest points of a random sample of the database, and every object in the touched posting lists is evaluated with the true distance. Because nothing must outrank anything, recall equals a coverage probability computable from the stored index: one ground-truth pass over a query sample certifies every operating point at once, without serving any of them -- a recall certificate, and for a navigable graph no analogous object exists at any price. The whole index is one recursive rule -- sample the collection, post each object to its $b$ nearest sample points, split any list that outgrows a bound, always scan the leaves -- and its operating surface obeys an equal-work law, recall $\approx f(b \cdot k_s)$, whose level is a one-scalar signature of the dataset. The same scan-only structure gives a serving floor no graph architecture reaches once the router is itself indexed by the same rule: Deep-100M served at recall 0.9977 from 1 GB of resident memory (enforced cap, 10.7 bytes per object) and at 0.9964 from 256 MB, Deep-1B at recall 0.9925 from 512 MB (and from 96 MB at depth 3), inserts that are one search, and deletes that are exact. Throughput is competitive where the hardware allows it -- up to $1.8\times$ a tuned HNSW at $10^8$ on a two-socket 32-core server, with operating points to the right of where that graph saturates -- and the tables report it against HNSW, DiskANN, GRAFT, NAPP, misi, and SPANN's assignment rule on the same hardware and ground truth.

## 1. 核心问题与整体含义（研究动机与背景）

- **现有 ANN 索引的根本痛点**：以 HNSW、DiskANN 为代表的可导航图索引，其召回率是**构建与遍历过程涌现出的性质**，只能事后对照真值测量，无法在线预测或认证。
- **召回拨盘饱和**：在 Deep-100M 上，经过精细调优的 HNSW 在 ef=4000 时停在 recall@10=0.9989，再往上**任何代价都不存在工作点**。
- **服务内存下限沉重**：图索引需要常驻大量导航状态，DiskANN 在 Deep-100M 上需 12 GB，低于 9.6 GB 直接失败。
- **动态更新困难**：图索引删除极其脆弱，更新层本身就是一个独立系统。
- **SOLO 的反向设计哲学**：把服务路径简化到"召回率是索引的定理，而不是搜索启发式的结果"。整个索引只有一条递归规则——采样、投递、分裂、扫描叶子，服务路径中没有任何投票、打分板、beam 或剪枝界。

## 2. 方法论

### 核心思想
- **采样词表**：从数据库 X 中均匀随机抽取 αn 个点构成词表 S（实验统一 α=2%），在 S 上构建任意高召回 ANN 路由器。
- **rank-b 投递**：每个对象 x 通过一次路由器搜索得到其 kb 个最近样本点的**有序签名**（构建时 kb=64），投递到其 b 个最近样本点，b≤kb 是服务期选择，倒排文件是存储签名的前缀截断，**一次构建服务所有 b**。
- **仅扫描服务**：查询路由到 ks 个最近样本点，触及的 ks 个倒排链被**穷举扫描并用真实距离评估**（去重），返回扫描集的精确 top-k。

### 召回恒等式（Proposition 1）
- 定义 Tb(x) 为对象 x 的 b 个最近样本点，Rks(q) 为查询 q 的 ks 个最近样本点，则：
  - **recall@k = cov(b, ks) = Pr[Tb(y) ∩ Rks(q) ≠ ∅]**（y 为 q 的真实 k-NN）
- 证明要点：y 被扫描到 ⟺ y 与 q 共享至少一个词项；服务对所有扫描对象用真实距离精确排序，因此只有"是否被扫描到"这一种失败模式，无其他事件能丢失或恢复真实邻居。边界仅剩 rank-k 处的距离并列。

### 一条递归规则
- 枢纽偏斜导致列表长度不均（GloVe 上 max/mean 达 48×）。**任何超过 τ 的列表被视为一个数据库**，用同一规则再次采样、投递、分裂；叶子永远被扫描。召回跨层乘法组合，复制保险也递归。

### 量化叶子
- 使用最简单的量化器：全局仿射 **8-bit 网格**（两个常数，一遍扫描，无训练）或逐维仿射 **4-bit 网格**（2d 常数，两码一字节）。
- **screen-and-refine**：整数平方距离筛选，保留 R 个最佳不同候选，全精度重排；返回的排序在筛选集上精确。实测 SQ8 在 R=40 即无损，服务用 R=100；SQ4 需 R=200。

### 服务内核与内存模型
- **访问状态必须用位图**：epoch 标记的 32 位 visited 数组在 10⁸ 规模 64 线程下需 25.6 GB；每线程位图仅 12.5 MB 且更快。
- **去重必须在筛选 R 堆之前**（否则堆被副本填满，实测 recall 0.9982→0.8394）。
- **扫描必须流式而非聚集**：代码按倒排序复制（list-major），每条列表为顺序段；聚集每记录 9–25 ns，流式约 1.7 ns。
- **rank-ordered postings**：列表按成员对其赋予的 rank 排序，服务期 b 是前缀，可做锥形前沿 b(t)=⌈b₀(1−t/ks)^p⌉。
- **加载不重建**：路由器序列化为平坦、位置无关、可 mmap 的镜像，加载 43–90 µs。
- **磁盘模式**：叶子块为 [id | code] 倒排序记录，顺序读入有界缓冲，筛选后按 ~R 次行读取精排。

### 等功定律
- **cov(b, ks) ≈ f_X(b·ks)**：覆盖坍塌到被触及投递质量 b·ks 的等值线上，同一等值线内因子分解自由。f_X 的水平是数据集的一标量签名（覆盖 0.99 所需 b·ks：SIFT ~512，Deep-10M ~1–2k，GloVe ≳8k）。

### 递归向上：驻留内存定律
- **resident(n, L, T, op) = αᴸ n cr + T·s(op) + O(page cache)**，其中 cr 为每样本点代价（float32 含图状态约 448 B，8-bit 约 160 B），每层递归将容量上限乘以 1/α=50。

## 6. 主要结论与发现

- **召回 = 覆盖**：恒等式在 10⁶–10⁹ 三个数据集上成立到 5×10⁻⁴ 以内；在 MS MARCO @10⁸（最不利场景）证书与实测召回匹配到 0.0001。
- **等功定律**：覆盖是被触及投递质量 b·ks 的函数，因子分解自由；其水平是数据集的单标量签名。固定召回下距离评估数随 n 仅以 n⁰·⁴–⁰·⁶ 增长，扫描比例逐十年下降（3.060%→0.070%）。
- **服务下限**：Deep-100M 在 1 GB 常驻内存（10.7 B/对象）下 recall 0.9977，256 MB 下 0.9964；Deep-1B 在 512 MB 下 0.9925（depth 3 从 96 MB），比 10⁸ 同上限的每对象字节少 10×。
- **吞吐**：在 Deep-100M 上用 list-major 4-bit 流 + rank-ordered postings，在 0.9974 以上所有召回点比调优 HNSW 快 1.1–1.8×，并继续到 0.9990（HNSW 已无工作点）；SIFT-1M 上 1.4–2.1×。
- **递归有效**：一条规则递归在召回和吞吐上同时击败"每列表附加图索引"的混合方案，构建便宜 25×。
- **量化必须 screen 不能 score**：SPANN 原生 Int8 打分在 Deep-100M 饱和于 0.9561，而同一网格作筛选 + 精确精排无损。
- **MS MARCO 上不 competitive**：最佳仅 0.8987 @235 qps，原因是高维 OOD 下覆盖水平随 n 每十年下降 0.055（Deep 仅 0.0012）。

## 7. 优点

- **召回可认证**：Proposition 1 是恒等式而非界或相关；一次真值遍历即可认证全部 (b, ks) 工作面，包括从未部署的配置。
- **服务路径零启发式**：只有"哪些列表被触及"一个近似源，失败模式是存储数据的成员资格问题，而非搜索动力学。
- **极致内存效率**：递归向上将路由器容量上限每层 ×50，实现 10⁸ 从 1 GB、10⁹ 从 512 MB（甚至 96 MB）服务。
- **动态更新优雅**：插入是一次搜索 + b 次列表追加；删除是精确移除，无墓碑、无图修复。
- **可复现性**：所有数字由运行写入带版本清单（代码提交、机器、参数、种子、原始计时）；实现、驱动、清单全部开源。
- **公平对比**：基线同机同真值、扫描到饱和；主动披露并修正前一稿的内存记账错误。
- **诚实的边界声明**：明确区分"测量"与"投影/算术"，并坦承 MS MARCO 上的失败。
