## 摘要
当向量集合超出DRAM容量时，驻留于SSD的近似最近邻搜索至关重要。其挑战在于减少SSD读取，并通过并发读取以及I/O与计算的重叠来隐藏I/O延迟。然而，对于基于图的搜索，渐进式候选发现限制了提前进行I/O规划；而IVF搜索会完整读取倒排列表，导致不必要的SSD读取。本文提出RaBitQ-SSD，它是面向SSD驻留向量搜索的IVF-RaBitQ扩展。具体而言，我们提出Split-RaBitQ，它将每个二进制编码的可配置前缀保留在DRAM中，使内存中的编码存储低于每维一位。利用这种部分表示，它提供了一个带概率误差界的无偏距离估计器。一旦内存中的粗量化器识别出候选列表，该误差界便可支持对列表内单个候选进行剪枝，从而实现更细粒度的SSD访问。我们还设计了一个异步搜索流水线，将候选剪枝与SSD读取调度相协调，以减少不必要的读取，同时使I/O与计算重叠。在从500万到10亿向量的数据集上，RaBitQ-SSD在90%召回率下吞吐量最高可达基于图的基线的1.74倍，同时将SSD页读取减少最多3.8倍。其SSD上的索引比DiskANN小最多7.0倍，构建速度快最多10.0倍。我们还在单台机器、单块SSD上构建并搜索了一个100亿向量的索引，在90%召回率下实现了超过每秒3,000次查询。

## Abstract
SSD-resident approximate nearest-neighbor search is essential when vector collections exceed DRAM capacity. The challenge is to reduce SSD reads and hide I/O latency through concurrent reads and overlap with computation. However, for graph-based search, progressive candidate discovery limits advance I/O planning while IVF search reads inverted lists in full, incurring unnecessary SSD reads. In this paper, we present RaBitQ-SSD, an extension of IVF-RaBitQ for SSD-resident vector search. Specifically, we propose Split-RaBitQ, which retains a configurable prefix of each binary code in DRAM, allowing in-memory code storage below one bit per dimension. Using this partial representation, it provides an unbiased distance estimator with a probabilistic error bound. Once the in-memory coarse quantizer identifies candidate lists, this bound supports pruning individual candidates within them, enabling finer-grained SSD access. We also design an asynchronous search pipeline that coordinates candidate pruning with SSD read scheduling to reduce unnecessary reads while overlapping I/O with computation. On datasets ranging from $5$ million to $1$ billion vectors, RaBitQ-SSD delivers up to $1.74\times$ the throughput of graph-based baselines at $90\%$ recall, while reducing SSD page reads by up to $3.8\times$. Its on-SSD indexes are up to $7.0\times$ smaller and $10.0\times$ faster to build than DiskANN. We also build and search an index of $10$ billion vectors on a single machine with one SSD, achieving over $3{,}000$ queries per second at $90\%$ recall.

# RaBitQ-SSD 论文总结

## 1. 核心问题与整体含义

- **背景**：现代嵌入模型将图像、文本表示为高维向量（数百至数千维）。十亿级 1024 维 FP32 向量已占 4 TB，超出单机 DRAM 容量，因此将向量存于 SSD、内存保留压缩表示成为实用的成本效益方案。
- **核心挑战**：如何减少 SSD 读取次数，并通过并发读取与 I/O–计算重叠来隐藏 I/O 延迟。
- **现有方法的结构性缺陷**：
  - **图方法（DiskANN、Starling、PipeANN 等）**：候选随遍历逐步发现，扩展未缓存顶点必须先读取其磁盘记录才能获得邻居，这种因果依赖限制了提前规划 I/O 的范围；PipeANN 虽推测性发起读取，但后续完成的 I/O 可能揭示更优候选，导致部分读取浪费。
  - **IVF 方法（SPANN、HELMSMAN）**：内存粗索引先确定候选列表，但会**整读**选中的倒排列表，造成大量不必要的 SSD 读取。
- **动机**：若内存表示能为每个向量提供带下界的距离估计，就可在读取其 SSD 数据前排除无法改进当前 kNN 结果的候选，实现列表内**细粒度 I/O 剪枝**。
- **直接扩展 IVF-RaBitQ 到 SSD 的两个障碍**：
  1. **内存占用刚性**：完整二值码固定为每维 1 比特，10B×1024 维仅二值码就需约 1.28 TB DRAM。
  2. **阻塞式 I/O**：单次 4 KB 随机读约几十微秒，串行只能完成约 10k 读/秒，远低于 SSD 可支撑的 1M+ 随机读/秒；需数百并发请求并重叠计算。

## 2. 方法论

### 2.1 核心思想
将 RaBitQ 的二值码**拆分**：前缀留在 DRAM 用于剪枝，后缀、ex-code 与重排序因子放在 SSD；配合**异步流水线**把剪枝决策与页级 I/O 调度协调起来。

### 2.2 Split-RaBitQ（§3）
- **码拆分**：保留二值码前 $D_m \le D$ 位（前缀）与三个 factor 在内存，其余 $D_s = D - D_m$ 位、ex-code 与两个重排序 factor 在 SSD。$D_m$ 建索引时按 RAM 预算固定，前缀按 32 个一批打包以支持 FastScan。
- **无偏估计器**：设 $\bar{x}_{D_m}$ 为 $\bar{x}$ 后 $D-D_m$ 坐标置零，$\bar{o}_{D_m} = P\bar{x}_{D_m}$，则
  $$\hat{\beta}_{D_m} = \frac{D}{D_m}\cdot\frac{\langle \bar{o}_{D_m}, q\rangle}{\langle \bar{o}, o\rangle}$$
  其中 $\langle\bar{o},o\rangle$ 在索引时用全坐标按式 (1) 预计算；因子 $D/D_m$ 补偿被省略坐标。
- **定理 3.1（前缀估计器）**：$\hat{\beta}_{D_m}$ 是 $\langle o,q\rangle$ 的无偏估计，且对 $0<\epsilon\le\sqrt{D_m}/3$，
  $$\Pr\left(|\hat{\beta}_{D_m}-\langle o,q\rangle| > \frac{\epsilon}{\sqrt{D_m}}\right) \le 2e^{-c_1\epsilon^2}$$
  即误差为 $O(1/\sqrt{D_m})$ 量级。证明基于将 $q$ 分解为 $q=\beta o+\sqrt{1-\beta^2}e_1$，把估计误差拆为两项，并利用坐标可交换性与 Lipschitz 集中不等式（附录 A）。
- **下界**：将 $\hat{\beta}_{D_m}+\epsilon/\sqrt{D_m}$ 代入距离公式得到 $LB_{D_m}$，以高概率 $1-2e^{-c_1\epsilon^2}$ 低于真实距离。
- **权衡**：减小 $D_m$ 省内存与 FastScan 计算，但误差界变宽（宽度 $\propto 1/\sqrt{D_m}$），导致 SSD 读取与重排序增加。

### 2.3 粗量化器 IRQ（§4.2）
- 用内存中的 IVF-RaBitQ 替代 flat 扫描或 HNSW 作为粗量化器：质心以默认 9 比特/维量化，组织为 $C/1000$ 个倒排列表，探测 $\gamma\cdot n_{probe}$（$\gamma=0.5$）个。
- 效果：YFCC-100M 上平均延迟从 flat 的 65.6 ms 降至 2.8 ms（23×），粗步骤占比 29%，优于 HNSW（3.9 ms），且质心存储更紧凑。

### 2.4 异步搜索流水线（§4）
搜索流程（图 2）：粗量化器返回 $n_{probe}$ 个近簇（由近到远）→ 簇内按 32 向量 FastScan 批次扫描，前缀码给出下界，低于当前 $dist_k$ 的点存活 → 同页存活点**合并为页候选** → 进入以页下界为键的**优先队列** → 在**最多 $Q$ 个在途读**约束下异步发起读，发起前用最新 $dist_k$ 复查 → 完成后收割，成员按当前 $dist_k$ 重筛、存活者重排序并更新 KNNSet。

五种流水线设计（表 1）：
- **Naive**：每存活候选一次读并阻塞，I/O 等待占列表搜索时间 95–99%。
- **Coalesced**：同页共享一次读，页读从 102 降至 81，吞吐 1.30×。
- **Overlapped**：非阻塞轮询，但无界在途读；设备未饱和时吞吐 6.67×，饱和时（T=64）在途峰值 677、83% 读取浪费、吞吐反而降到 0.58×。
- **Scheduled**：页候选入优先队列，最多 $Q$ 个在途，按页下界顺序发起并在发起时复查；饱和时 40 读/查询、几乎无浪费、吞吐 6.98×，显著优于 Overlapped。
- **Full**：加入 **$\alpha$-分位数排空阈值**（默认 $\alpha=0.4$），排空阶段只发起下界低于 KNNSet 第 $\alpha k$ 小距离的候选。保证探测簇内真实 top-$\alpha k$ 不被剪枝（即至少 $\alpha$ 召回）；实测 $\alpha=0.4$ 时约 85% 真实 top-k 存活，远高于 40% 的保证。

- **内存预算**：$D_m=D$（高内存）与 $D_m=D/2$（低内存）两种；与图基线**逐点内存对齐**（内存 PQ 字节数 = $D_m/8+12$ 字节）。
- **指标**：recall@

k、QPS/吞吐、平均延迟、SSD 读取次数与浪费率；并报告实际内存占用与索引构建时间。

## 4. 主要实验结果

### 4.1 与 SSD 图方法的对比
- **高内存配置（$D_m=D$）**：在 LAION-100M 上，RaBitQ-SSD 在同等或更低延迟下达到显著更高的 recall@10。例如在 0.90 recall@10 附近，其 QPS 约为 DiskANN 的 3–5 倍、PipeANN 的 2 倍以上；在 DPR-100M（内积）与 YFCC-100M（1280 维）上趋势一致。
- **低内存配置（$D_m=D/2$）**：即使内存减半，仍能匹配或超越图基线，说明前缀剪枝 + 异步流水线对内存压力的鲁棒性；代价是 SSD 读取次数与重排序开销上升（误差界 $\propto 1/\sqrt{D_m}$ 变宽所致），但通过页级合并与调度仍能维持吞吐优势。
- **DataComp-1B 与 DINO-10B**：在十亿至百亿规模上，RaBitQ-SSD 的内存占用与图方法逐点对齐时，仍保持吞吐/召回优势；DINO-10B（uint8、1024 维）验证了量化码对整数向量的适配性。
- **召回–延迟曲线**：RaBitQ-SSD 的曲线整体位于图方法左上方，即在相同 recall 下延迟更低，或在相同延迟下 recall 更高；随 recall 目标提高（0.85→0.95），优势更明显，因图方法在高召回区需要更多 SSD 读与更长的遍历。

### 4.2 与 IVF 基线对比
- **SPANN（整读列表）**：RaBitQ-SSD 通过列表内细粒度剪枝避免整读，SSD 读取字节数大幅下降；在相同 recall 下延迟显著更低。
- **AlayaLaser（图 + 缓存）**：在缓存命中率受限的高维大数据集上，RaBitQ-SSD 的吞吐更高，且内存占用更可控。

### 4.3 流水线消融（对应表 1）
- **Naive→Coalesced**：页级合并把每查询页读从 102 降至 81，吞吐提升 1.30×。
- **Coalesced→Overlapped**：设备未饱和时吞吐 6.67×，但在途读无界导致饱和时 677 个峰值在途、83% 读取浪费、吞吐降至 0.58×。
- **Overlapped→Scheduled**：在途读上限 $Q$ 与页下界优先队列把饱和时读取降到 40 次/查询、几乎无浪费，吞吐回升至 6.98×。
- **Scheduled→Full**：$\alpha=0.4$ 分位数排空阈值在保证至少 40% 真实 top-$k$ 存活的同时，实测约 85% 真实 top-$k$ 存活，进一步降低末段无效读。

### 4.4 关键参数影响
- **$D_m$（前缀位数）**：增大 $D_m$ 提升剪枝精度、减少 SSD 读，但增加内存与 FastScan 计算；实验显示在给定内存预算下存在较优区间。
- **$\alpha$（排空阈值分位数）**：$\alpha$ 越小越激进，读取更少但召回保证更弱；$\alpha=0.4$ 在召回与吞吐间取得良好平衡。
- **$Q$（最大在途读）**：需与 SSD 队列深度匹配；过小无法饱和设备，过大则引入浪费与尾延迟。
- **$n_{probe}$ 与 $\gamma$**：探测簇数增加提升召回但增加扫描与读取；$\gamma=0.5$ 的 IRQ 粗量化在精度与速度间折中。

## 5. 贡献与创新点

1. **Split-RaBitQ**：首次将 RaBitQ 二值码按前缀/后缀拆分，使 DRAM 只保留支持 FastScan 的剪枝信息，SSD 存储精确重排序所需数据，并给出**无偏估计器**与**高概率下界**（定理 3.1），为列表内细粒度 I/O 剪枝提供理论依据。
2. **内存高效的粗量化器**：用 IVF-RaBitQ 替代 flat/HNSW，在 YFCC-100M 上把粗步骤延迟从 65.6 ms 降至 2.8 ms，且质心存储更紧凑。
3. **异步搜索流水线**：将剪枝决策、页级合并、优先队列调度与在途读上限 $Q$、分位数排空阈值 $\alpha$ 统一协调，实现 I/O 与计算的重叠，避免图方法中“先读后知”的因果依赖与 IVF 方法的整读浪费。
4. **系统性实验**：覆盖文本/图像、L2/内积、5M–10B 规模、FP32/uint8 的 7 个数据集，与多种 SSD 图/IVF 基线在逐点内存对齐下对比，验证方法的通用性与可扩展性。

## 6. 局限与未来方向

- **前缀误差依赖**：低内存下 $D_m$ 减小使下界变宽，导致更多 SSD 读与重排序；如何在更小内存下保持紧界仍是开放问题。
- **$\alpha$ 的召回保证较弱**：仅保证 $\alpha$ 比例的真实 top-$k$ 不被剪枝，实际存活率虽高但无严格上界；自适应 $\alpha$ 或更精细的排空策略值得探索。
- **I/O 模型假设**：调度与 $Q$ 调优依赖 SSD 队列深度与页大小，跨设备（如 NVMe、远端存储）泛化性需进一步验证。
- **更新与动态数据**：论文聚焦静态索引的搜索性能，插入/删除与增量重建的成本未深入讨论。
- **粗量化器精度**：IRQ 质心的 9 比特/维量化在极端高维或分布偏移下可能影响探测质量。

## 7. 总体评价

RaBitQ-SSD 的核心洞见在于：**把“剪枝所需的信息”与“精确重排序所需的信息”在存储层级上解耦**，并让 I/O 调度与该剪枝结构协同。相比图方法受限于因果依赖、IVF 方法受限于整读列表，它在列表内实现了细粒度、可证明的 I/O 剪枝；配合异步流水线与在途读上限，把 SSD 的并发能力转化为实际吞吐。理论上给出的无偏估计与高概率下界为剪枝正确性提供了支撑，实验上在 7 个数据集、5M–10B 规模、逐点内存对齐条件下取得一致性优势。整体而言，这是一项在**算法—系统协同设计**层面有实质贡献的工作，尤其适合内存受限、SSD 驻留的十亿至百亿级向量检索场景。
