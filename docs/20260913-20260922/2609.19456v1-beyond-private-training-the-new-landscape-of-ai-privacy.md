## 摘要
检索增强系统日益依赖向量索引，而这些索引可能在其搜索图中保留已删除项。现有删除接口可以阻止已删除标识符出现在返回结果中，但在图遍历过程中仍会计算到其嵌入的距离。我们将这一区别形式化为输出安全性与遍历安全性，并引入 TSD-AUDIT，一个用于在基于图的近似最近邻检索中审计并强制执行遍历安全删除的框架。在 Faiss IndexHNSWFlat 上，原生过滤使距离计算次数相对于未过滤搜索保持不变；在 70% 的删除率下，轨迹忠实重放会在所有 100 个被审计查询中检测到对已删除向量的评分。对 hnswlib 的 mark_deleted 路径进行代码检查，揭示了同样的“先评分、后判存活”模式。TSD-AUDIT 强制实施“先存活、后评分”不变量，仅使用存活候选修复连通性，并为每个查询生成评分轨迹证书，独立验证者可对照删除快照对其进行检查。在区域定向删除下，TSD-AUDIT 在删除比例从 0.5 到 0.9 时将 Recall@10 相对于原生过滤提升 4.3 至 42.2 个百分点，而在随机删除下保持相当。这些结果表明，仅关注输出的删除审计可能会遗漏过程层面的暴露：在向量检索中审计删除，需要考虑搜索期间被评分的向量，而不仅仅是返回的标识符。

## Abstract
Retrieval-augmented systems increasingly rely on vector indexes that may retain deleted items in their search graph. Existing deletion interfaces can prevent deleted identifiers from appearing in returned results while still computing distances to their embeddings during graph traversal. We formalize this distinction as output safety versus traversal safety, and introduce TSD-AUDIT, a framework for auditing and enforcing traversal-safe deletion in graph-based approximate nearest-neighbor retrieval. On Faiss IndexHNSWFlat, native filtering leaves the number of distance computations unchanged relative to unfiltered search; at a 70% deletion rate, trace-faithful replay detects deleted-vector scoring in all 100 audited queries. Code inspection of hnswlib's mark_deleted path reveals the same scoring-before-liveness pattern. TSD-AUDIT enforces an alive-before-scoring invariant, repairs connectivity using only live candidates, and emits per-query scored-trace certificates that an independent verifier can check against the deletion snapshot. Under region-targeted deletion, TSD-AUDIT improves Recall@10 over native filtering by 4.3--42.2 percentage points across deletion fractions from 0.5 to 0.9, while remaining comparable under random deletion. These results show that output-only deletion audits can miss process-level exposure: auditing deletion in vector retrieval requires accounting for the vectors scored during search, not only the identifiers returned.

## 1. 核心问题与整体含义

- **背景迁移**：隐私研究长期聚焦训练阶段（如 DP-SGD），但当前 RAG、自主智能体、上下文学习等推理时范式，使大量敏感数据并不进入模型权重，而是存放在向量索引等“检索记忆”中，在推理时被读取。
- **核心问题**：生产向量库通常用 soft-delete/tombstone 实现删除，只保证被删 id 不出现在返回的 top-k 中；但 HNSW 等图索引在遍历时仍会访问并计算已删 embedding 的距离。
- **关键区分**：论文形式化提出 **输出安全（output safety） vs 遍历安全（traversal safety）**。
  - 输出安全：返回结果中无已删标识。
  - 遍历安全：搜索过程中从未对已删向量计分。
- **整体含义**：仅审计输出结果会遗漏过程级隐私暴露。删除义务应从“返回结果约束”升级为“检索过程可审计保证”。论文提出 TSD-AUDIT，目标是审计并强制执行遍历安全删除，并生成可外部验证的证书。
- **定位**：论文明确为 **audit-not-algorithm**。alive 过滤机制借鉴 predicate-aware ANN，recall 修复现象属于已知 churn 行为，at-rest 可恢复性由 Ghost Vectors 研究；其剩余贡献是“检索过程从未计分已删项”的可验证审计属性。

## 2. 方法论：核心思想与关键技术

- **形式化定义**：
  - 令 \(Visited(q,t)\) 为搜索中计算过 query–node 距离的所有节点。
  - 返回泄漏：已删 id 出现在 top-k 的比率。
  - 访问泄漏：任一已删节点被计分的比率。
  - **遍历安全**：两者均为零。
- **alive-before-scoring 不变量**：
  - 内存维护 alive bitset，在计分前三个点检查：
    1. 入口点只从存活节点中选取；
    2. 前沿中的已删邻居在计分前被丢弃；
    3. pop 时再次检查，跳过入队后才被删除的节点。
  - 因此已删节点从不进入候选池，保证 \(Visited(q,t) \cap D_t = \emptyset\)。
- **遍历安全修复**：
  - 直接剪掉死边会破坏删除节点曾提供的连通性，高删除率下存活子图可能碎片化。
  - 离线修复通过“曾经过已删节点的路径”重连存活节点，且只在存活候选之间计算距离，从而保持遍历安全保证。
- **可外部验证证书**：
  - 每个 checkpoint 发出：删除集哈希、采样扩展轨迹哈希、\(Visited \cap D_t\) 判定结果。
  - 独立验证者重算哈希并断言无交集，将遍历安全删除转化为可检查的 artifact。
- **威胁模型**：
  - 假设 **诚实但可能有 bug 的运营者**。
  - 不防恶意运营者伪造证书；不涉及模型权重的参数级 unlearning。
